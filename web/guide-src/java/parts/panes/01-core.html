JAVA 01

자바를 실행하는 법

“설치했는데 안 돌아가요”의 90%는 JDK 버전과 빌드 도구 이야기입니다. 여기만 정리하고 넘어가면 나머지는 편합니다.

JDK · JRE · JVM — 헷갈리는 3형제

JDK
개발자가 설치하는 것컴파일러(javac) + 도구 + JRE. 이것만 깔면 됩니다.
▼ 포함
JRE
실행에 필요한 것표준 라이브러리 + JVM. 요즘은 따로 배포하지 않습니다.
▼ 포함
JVM
실제로 코드를 돌리는 기계.class 바이트코드를 읽어 OS에 맞게 실행합니다.

“한 번 작성하면 어디서나 돈다”가 여기서 나옵니다. 내 코드는 OS가 아니라 JVM을 향해 컴파일되고, JVM이 각 OS별로 따로 존재합니다.

JAVA 02

변수 · 타입 · var

자바의 타입은 딱 두 종류로 나뉩니다 — 기본형과 참조형. 이 구분만 잡으면 나머지는 쉽습니다.

기본형 8가지 — 값 자체를 담는다

타입크기범위 · 쓰임
byte1B-128 ~ 127 · 바이너리 데이터
short2B±3만 · 거의 안 씁니다
int4B±21억 · 정수의 기본값
long8B±922경 · 돈·ID·시간 100L
float4B실수 7자리 1.5f
double8B실수 15자리 · 실수의 기본값
boolean1byte*true / false (0/1 아님!) — *크기는 명세에 없고 JVM 구현상 보통 1바이트
char2B문자 하나 '가' (작은따옴표)
돈 계산에 double 쓰면 안 됩니다 — 0.1 + 0.2 != 0.3 입니다(부동소수점 오차). 금액은 BigDecimal 또는 정수(원 단위 long)로 다루세요.

참조형 — 값이 있는 '주소'를 담는다

// 기본형: 상자 안에 값이 직접 들어 있다
int a = 10;
int b = a;        // 값이 복사됨
b = 20;           // a 는 그대로 10

// 참조형: 상자 안에 '어디 있는지'가 들어 있다
int[] x = {1, 2, 3};
int[] y = x;      // 주소가 복사됨 (같은 배열을 가리킴)
y[0] = 99;        // x[0] 도 99 가 된다!

// null 은 참조형에만 존재한다
String s = null;         // OK
// int n = null;         // 컴파일 에러

// 박싱 타입 — 기본형을 객체로 감싼 것
Integer boxed = 10;      // int  -> Integer (오토박싱)
int unboxed = boxed;     // Integer -> int  (언박싱)

// ⚠️ 박싱 타입 비교는 == 이 아니라 equals
Integer p = 1000, q = 1000;
System.out.println(p == q);        // false! (다른 객체)
System.out.println(p.equals(q));   // true
언제 박싱 타입을 쓰나 — 컬렉션에 담을 때(List<Integer>)와 “값이 없음(null)”을 표현해야 할 때입니다. DB 컬럼이 nullable 이면 엔티티 필드는 Long·Integer로 두세요.

문자열과 텍스트 블록

실무 코드의 절반은 문자열을 만들고 자르고 붙이는 일입니다. 자바의 String 은 불변(immutable)이라는 점 하나가 성능과 안전성을 모두 좌우합니다.

s = s.toUpperCase();        // ✅ 다시 담아야 한다

String result = "";
for (int i = 0; i < 10000; i++) {

// ✅ StringBuilder 를 쓴다

for (int i = 0; i < 10000; i++) {

클래스 · 객체 · 생성자

자바는 모든 코드가 클래스 안에 있습니다. 클래스는 “데이터 + 그 데이터를 다루는 기능”을 한 덩어리로 묶는 도구입니다.

기본 구조

public class Order {

    // 1) 필드 — 객체가 가지는 데이터
    private final Long id;              // final = 생성 후 안 바뀜
    private final String customerName;
    private int amount;
    private OrderStatus status = OrderStatus.CREATED;   // 기본값

    // 2) 생성자 — 객체를 만들 때 필요한 것을 받는다
    public Order(Long id, String customerName, int amount) {
        if (amount < 0) {
            throw new IllegalArgumentException("금액은 0 이상이어야 합니다");
        }
        this.id = id;                   // this = "지금 만들고 있는 이 객체"
        this.customerName = customerName;
        this.amount = amount;
    }

    // 3) 메서드 — 객체가 할 수 있는 일
    public void pay() {
        if (status != OrderStatus.CREATED) {
            throw new IllegalStateException("이미 처리된 주문입니다");
        }
        this.status = OrderStatus.PAID;
    }

    public boolean isPaid() {
        return status == OrderStatus.PAID;
    }

    // 4) getter — 밖에서 읽기만 허용
    public Long getId() { return id; }
    public int getAmount() { return amount; }

    // 5) 객체를 문자열로 (로그·디버깅에서 매우 중요)
    @Override
    public String toString() {
        return "Order{id=%d, amount=%d, status=%s}"
                .formatted(id, amount, status);
    }
}

// 사용
Order order = new Order(1L, "김현우", 50000);

System.out.println(order);   // Order{id=1, amount=50000, status=PAID}

public abstract class Payment {          // abstract = 직접 만들 수 없음

    private void validate() {

    private void log() { System.out.println(amount + "원 결제"); }
}

    public CardPayment(int amount) {

    protected void doPay() {

}

함수형 인터페이스란 정확히 무엇인가

한 줄로 “추상 메서드가 정확히 하나뿐인 인터페이스” 입니다. 그게 전부입니다. 특별한 종류가 따로 있는 게 아니라, 조건을 만족하면 그냥 함수형 인터페이스가 됩니다. Runnable, Comparator, Callable 처럼 자바 1.0~5 시절부터 있던 인터페이스들도 전부 여기에 해당합니다.

람다에는 타입이 없습니다 — 받는 쪽 타입이 곧 람다의 타입입니다.

왜 이런 게 필요한가

자바에는 “함수”라는 타입이 없습니다. JS 의 const f = x => x + 1 처럼 함수 자체를 변수에 담을 수 없습니다. 그래서 자바는 메서드 하나짜리 인터페이스로 함수를 흉내 냅니다. 

// 이 인터페이스가 곧 "String 을 받아 int 를 주는 함수" 타입
@FunctionalInterface
interface StringToInt {
    int apply(String s);          // 추상 메서드 딱 하나
}

// ① 예전 방식 — 익명 클래스로 구현체를 만든다
StringToInt f1 = new StringToInt() {
    @Override public int apply(String s) { return s.length(); }
};

// ② 람다 — 위와 완전히 같은 뜻

public <T> T withRetry(int max, Supplier<T> action) {
    RuntimeException last = null;
    for (int i = 0; i < max; i++) {
        try { return action.get(); }
        catch (RuntimeException e) { last = e; sleep(200L * (i + 1)); }
    }
    throw last;
}

NullPointerException은 자바에서 가장 많이 만나는 예외입니다. Optional 은 “값이 없을 수도 있다”를 타입으로 드러내는 도구입니다.

기본 사용

user.orElseThrow();                    // 없으면 NoSuchElementException
user.orElseThrow(() -> new UserNotFoundException(id));   // ✅ 실무에서 가장 많이

// 있을 때만 실행
user.ifPresent(u -> log.info("찾음: {}", u.getName()));
user.ifPresentOrElse(
        u -> log.info("찾음"),
        () -> log.warn("없음"));

  • ❌ 메서드 파라미터로 받지 마세요 — 오버로딩이나 null 허용이 낫습니다
  • ❌ Optional<List> — 빈 리스트를 돌려주면 됩니다
  • ✅ 반환 타입에만 쓰세요 — “못 찾을 수도 있음”을 알리는 용도
