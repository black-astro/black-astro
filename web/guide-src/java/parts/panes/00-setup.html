어떤 JDK 를 깔아야 하나 — 배포판과 버전 고르기

파이썬은 “파이썬을 깐다”가 끝이지만, 자바는 같은 자바를 만드는 회사가 예닐곱 곳입니다. Oracle · Temurin · Corretto · Zulu · Liberica · Microsoft · GraalVM — 이름만 보면 다른 언어 같지만 안에 든 것은 거의 같습니다. 여기서 5분만 정리하면 “뭘 받아야 하죠?”가 영원히 끝납니다.

SETUP 02

윈도우 설치 — Temurin 25 LTS 를 끝까지 따라 깔기

화면에 무엇이 뜨고 어디를 눌러야 하는지 전부 적었습니다. 체크박스 두 개만 제대로 켜면 뒤에 나올 환경 변수 삽질(st03)을 통째로 건너뛸 수 있습니다. 그 두 개가 무엇인지가 이 섹션의 핵심입니다.

SETUP 03

JAVA_HOME 과 PATH — 손으로 잡는 법을 완전히

설치 마법사가 안 잡아 줬거나, zip 으로 풀었거나, 버전을 바꿔야 할 때는 직접 넣어야 합니다. 화면 경로부터 값 하나하나까지 적었습니다. 이 두 변수가 무엇을 하는지만 이해하면 자바 설치 문제의 8할이 사라집니다.

PATH 에 실제 경로 대신 %JAVA_HOME%\bin 을 넣는 이유가 이것입니다 — 고칠 곳이 한 군데가 됩니다.

열리는 창은 위아래 두 칸입니다
  ┌ 사용자 변수 ─ 나만 적용 · 관리자 권한 불필요
  └ 시스템 변수 ─ 이 PC 전체 · 관리자 권한 필요
어느 칸에 넣나 — 개인 PC 라면 사용자 변수로 충분하고, 권한 문제도 없어 편합니다. 여러 계정이 쓰는 PC 나 서비스로 도는 프로그램(윈도우 서비스, 스케줄러)이 자바를 써야 하면 시스템 변수에 넣어야 합니다. 양쪽에 다 넣지는 마세요 — 나중에 어느 쪽을 고쳤는지 헷갈립니다.

넣을 값 두 개 — 그대로 복사

① 새로 만들기 [새로 만들기(N)...] 버튼

   변수 이름 : JAVA_HOME
   변수 값   : C:\Program Files\Eclipse Adoptium\jdk-25.0.2.12-hotspot

   ※ 값은 탐색기에서 그 폴더로 들어가
      주소창을 클릭해 복사하는 것이 가장 정확합니다.
      그 폴더 안에 bin · conf · lib 가 보이면 맞습니다.
   ※ 끝에 \ 를 붙이지 않습니다.
   ※ bin 을 붙이지 않습니다.  ← 최대 빈출 실수 ★

② PATH 편집 — 목록에서 Path 를 고르고 [편집(E)...]

   [새로 만들기] → 아래 한 줄을 그대로
     %JAVA_HOME%\bin

   그리고 [위로 이동] 을 눌러 맨 위로 올립니다 ★
     (Oracle javapath, 옛 JDK, cmder 등보다 앞에)

③ [확인] 을 세 번 눌러 창을 전부 닫습니다
   ※ X 로 닫으면 저장되지 않습니다
PATH 순서가 곧 우선순위입니다 — 윈도우는 PATH 를 위에서 아래로 훑다가 처음 만난 java.exe 를 씁니다. 그래서 %JAVA_HOME%\bin 이 밑에 있으면 옛날 자바가 계속 이깁니다. 다음 그림이 그 이야기입니다.
where.exe java 가 여러 줄을 뱉으면 이미 섞인 것입니다 — 맨 윗줄이 실제로 도는 자바입니다.

임시 전환이 안전합니다 — 시스템 전체 값을 계속 고치면 어느 프로젝트가 어느 자바로 돌고 있는지 알 수 없게 됩니다. 기본값은 하나로 고정해 두고, 예외가 필요한 창에서만 바꾸세요. 이걸 자동으로 해 주는 도구가 st05 입니다.
PATH 를 편집할 때 절대 하면 안 되는 것 — Path 항목 전체를 한 줄로 복사해 메모장에서 고치는 것입니다. 윈도우 10 이후로는 PATH 편집 창이 한 줄에 하나씩 보여 주는 목록 형태인데, 옛날처럼 “텍스트 편집” 버튼으로 열어 잘못 붙여 넣으면 PATH 전체가 날아가 다른 프로그램까지 전부 못 찾게 됩니다. 고치기 전에 $env:Path > C:\path-backup.txt 로 한 번 백업해 두세요.
정리 — JAVA_HOME 은 bin 의 부모 폴더, PATH 에는 %JAVA_HOME%\bin 을 맨 앞에. 고친 뒤에는 터미널을 새로 열고 where.exe java 로 맨 윗줄을 확인합니다. 이 세 가지면 윈도우 자바 환경 문제는 거의 끝납니다.

macOS · Linux — 한 줄로 끝나는 대신 알아야 할 것

맥과 리눅스는 패키지 매니저가 있어 설치 자체는 훨씬 쉽습니다. 대신 “어느 JDK 가 기본인가”를 정하는 방식이 OS 마다 다릅니다 — 맥은 java_home, 우분투는 update-alternatives 입니다. 그 둘만 익히면 됩니다.

macOS — Homebrew 로

# Homebrew 가 없다면 먼저 (공식 한 줄)
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

# Temurin 설치 — cask 입니다 (앱 형태로 /Library 아래 설치)
brew install --cask temurin@25
brew install --cask temurin@21     # 나란히 깔아도 충돌하지 않습니다

# 어디에 깔렸나
ls /Library/Java/JavaVirtualMachines/
# temurin-21.jdk  temurin-25.jdk

# 설치된 JDK 목록 보기 — 맥의 핵심 명령
/usr/libexec/java_home -V
# Matching Java Virtual Machines (2):
#   25.0.2 (arm64) "Eclipse Adoptium" - "OpenJDK 25.0.2" /Library/.../temurin-25.jdk/Contents/Home
#   21.0.6 (arm64) "Eclipse Adoptium" - "OpenJDK 21.0.6" /Library/.../temurin-21.jdk/Contents/Home

# 특정 버전의 경로만 뽑기 — 이 출력을 JAVA_HOME 에 넣습니다
/usr/libexec/java_home -v 25
# /Library/Java/JavaVirtualMachines/temurin-25.jdk/Contents/Home
맥에서 JAVA_HOME 은 Contents/Home 까지입니다. .jdk 폴더까지만 적으면 안에 bin 이 없어서 실패합니다. 직접 경로를 외우지 말고 아래처럼 java_home 명령의 출력을 쓰는 것이 정석입니다.

셸 설정 파일에 넣기 (zsh 기준)

# 맥은 2019년부터 기본 셸이 zsh 입니다 → ~/.zshrc
# (bash 를 쓴다면 ~/.bash_profile)

# 지금 셸이 뭔지
echo $SHELL          # /bin/zsh

# 편집
open -e ~/.zshrc     # 또는 nano ~/.zshrc

# ── 아래 두 줄을 파일 끝에 추가 ─────────────────
export JAVA_HOME=$(/usr/libexec/java_home -v 25)
export PATH="$JAVA_HOME/bin:$PATH"
# ────────────────────────────────────────────

# 저장 후 지금 창에 즉시 반영
source ~/.zshrc

# 확인
echo $JAVA_HOME
java -version
which -a java        # 여러 줄이면 섞인 것 (맨 윗줄이 이깁니다)

# 버전을 바꾸고 싶으면 -v 숫자만 고치면 됩니다
export JAVA_HOME=$(/usr/libexec/java_home -v 21)
맥의 함정 — /usr/bin/java. 이 파일은 진짜 자바가 아니라 “설치된 자바를 찾아 주는 껍데기” 입니다. JDK 가 하나도 없으면 “자바를 설치하겠습니까” 안내창을 띄웁니다. which java 결과가 /usr/bin/java 라고 해서 “깔려 있다”는 뜻이 아닙니다 — java -version 으로 확인하세요.

Ubuntu · Debian — Adoptium 저장소를 등록해서 🟢 기초

Temurin 을 apt 로 받기

# ① 저장소 서명 키 등록
sudo apt update && sudo apt install -y wget apt-transport-https gpg
wget -qO - https://packages.adoptium.net/artifactory/api/gpg/key/public \
  | gpg --dearmor | sudo tee /etc/apt/keyrings/adoptium.gpg > /dev/null

# ② 저장소 주소 추가 (VERSION_CODENAME 은 noble · jammy 등으로 자동 치환)
echo "deb [signed-by=/etc/apt/keyrings/adoptium.gpg] https://packages.adoptium.net/artifactory/deb \
$(awk -F= '/^VERSION_CODENAME/{print$2}' /etc/os-release) main" \
  | sudo tee /etc/apt/sources.list.d/adoptium.list

# ③ 설치
sudo apt update
sudo apt install -y temurin-25-jdk
sudo apt install -y temurin-21-jdk     # 함께 깔아도 됩니다

# 배포판 기본 저장소의 OpenJDK 로도 충분합니다 (버전이 조금 늦습니다)
sudo apt install -y openjdk-21-jdk

# 페도라 · 로키 계열
sudo dnf install -y java-21-openjdk-devel     # -devel 이 javac 를 포함합니다 ★
리눅스에서 가장 흔한 사고 — openjdk-21-jre 나 java-21-openjdk(-devel 없이) 만 깔고 나서 javac: command not found 를 만나는 것입니다. 개발용은 반드시 -jdk / -devel 패키지입니다.

기본 자바 고르기 — update-alternatives

# 여러 개가 깔렸을 때 "기본"을 대화형으로 고릅니다
sudo update-alternatives --config java
#   선택   경로                                          우선순위  상태
# * 0      /usr/lib/jvm/temurin-25-jdk-amd64/bin/java    2500     자동 모드
#   1      /usr/lib/jvm/temurin-21-jdk-amd64/bin/java    2100     수동 모드
# 유지하려면 <엔터>, 아니면 선택 번호를 누르세요:

# javac 도 따로 골라야 합니다 ★ (java 만 바꾸면 짝이 어긋납니다)
sudo update-alternatives --config javac

# 지금 무엇이 잡혀 있나
update-alternatives --display java
readlink -f "$(which java)"
# /usr/lib/jvm/temurin-25-jdk-amd64/bin/java

# JAVA_HOME 은 bin 을 두 번 거슬러 올라간 폴더입니다
export JAVA_HOME=$(dirname $(dirname $(readlink -f $(which java))))
echo $JAVA_HOME
# /usr/lib/jvm/temurin-25-jdk-amd64
영구 적용은 ~/.bashrc(또는 ~/.profile)에 위의 export 두 줄을 넣고 source ~/.bashrc. 서버라면 사용자 셸이 아니라 systemd 유닛 파일의 Environment=JAVA_HOME=… 에 넣어야 서비스가 읽습니다 — “내 계정에선 되는데 서비스로 띄우면 안 된다”의 원인이 대개 이것입니다.

WSL 을 쓴다면 — 두 개의 자바가 생깁니다 🟡 중급

윈도우 쪽과 WSL 쪽은 완전히 별개

which -a java
# /usr/bin/java                                  ← 리눅스에 깐 것
# /mnt/c/Program Files/Eclipse Adoptium/.../java  ← 윈도우 PATH 가 넘어온 것 (!)

# WSL 은 기본적으로 윈도우 PATH 를 이어받습니다.
# 그래서 리눅스에 자바를 안 깔았는데도 java 명령이 "되는" 것처럼 보입니다.
# 하지만 그 java 는 윈도우용 exe 라서 리눅스 경로(/home/...)를 못 읽습니다.

# 해결 ① 리눅스 쪽에 제대로 깔고 PATH 앞에 두기 (위 apt 방법)
# 해결 ② 윈도우 PATH 상속을 끄기
sudo tee /etc/wsl.conf <<'EOF'
[interop]

SETUP 05

여러 JDK 를 함께 두고 갈아 끼우기

실무에서는 JDK 하나로 끝나지 않습니다. 회사 서비스는 17, 새로 만드는 것은 25, 오픈소스 기여는 21 — 이런 상황이 곧 옵니다. 환경 변수를 매번 손으로 고치는 대신, 도구에 맡기고 프로젝트가 스스로 버전을 말하게 만듭니다.

버전 관리 도구의 정체는 “가리키는 링크를 바꿔 주는 것” — 마법이 아닙니다.

SDKMAN! — 맥 · 리눅스 · WSL 의 정답

curl -s "https://get.sdkman.io" | bash
source "$HOME/.sdkman/bin/sdkman-init.sh"

#  Temurin     25.0.2       25.0.2-tem

# 설치 · 기본값 지정

sdk use java 21.0.6-tem           # 지금 이 터미널에서만 21

cat .sdkmanrc

import java.time.*;
import java.time.format.*;
import java.util.Locale;

public class LocaleCheck {
    public static void main(String[] args) {
        System.out.println("기본 로케일 : " + Locale.getDefault());
        System.out.println("기본 시간대 : " + ZoneId.systemDefault());
        System.out.println("파일 인코딩 : " + System.getProperty("file.encoding"));
        System.out.println("콘솔 인코딩 : " + System.getProperty("stdout.encoding"));

        var now = LocalDateTime.now();
        // 로케일을 명시하지 않으면 서버마다 결과가 달라집니다
        System.out.println(now.format(
            DateTimeFormatter.ofPattern("yyyy년 M월 d일 (E) a h시", Locale.KOREA)));
        // 2026년 8월 26일 (수) 오후 3시

        System.out.printf(Locale.KOREA, "%,d 원%n", 1234567);   // 1,234,567 원
    }
}
