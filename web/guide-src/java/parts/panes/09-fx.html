어떤 버전을 쓸까 — JavaFX 도 LTS 라인이 있습니다. LTS 는 17 · 21 · 25 이고, 그 사이 버전(22·23·24·26)은 6개월짜리 단기 릴리스입니다. 데스크탑 프로그램은 한 번 배포하면 오래 도니 ★ LTS 인 25 를 고르는 편이 안전합니다.
현행 최신은 JavaFX 26(2026-03)인데 --release 24 로 컴파일돼 있어 실행에 JDK 24 이상이 필요합니다 — JDK 21 에 묶여 있는 프로젝트라면 26 으로는 못 올라갑니다. JavaFX 버전은 JDK 버전과 같거나 낮게 맞추면 실수가 없습니다.

FX 02

첫 창 만들기

JavaFX 앱의 뼈대는 항상 같습니다 — Stage(창) → Scene(장면) → Node(요소).

public class MainApp extends Application {

    @Override
    public void start(Stage stage) {           // 창 하나가 Stage
        Label label = new Label("안녕하세요");
        label.setStyle("-fx-font-size: 20px;");

        Button button = new Button("클릭");
        button.setOnAction(e -> label.setText("클릭했습니다!"));

        VBox root = new VBox(12, label, button);   // 세로 배치, 간격 12
        root.setAlignment(Pos.CENTER);
        root.setPadding(new Insets(20));

        Scene scene = new Scene(root, 400, 300);   // 장면 + 크기
        scene.getStylesheets().add(
                getClass().getResource("/style.css").toExternalForm());

        stage.setTitle("내 첫 프로그램");
        stage.setScene(scene);
        stage.setMinWidth(320);
        stage.getIcons().add(new Image(
                getClass().getResourceAsStream("/icon.png")));
        stage.show();
    }

    @Override
    public void stop() {                        // 종료 시 정리
        // 스레드 종료, 설정 저장 등
    }

    public static void main(String[] args) {
        launch(args);
    }
}

바인딩을 쓰면 “값 바뀔 때마다 화면 갱신 코드”가 사라집니다. 모델의 값만 바꾸면 UI 는 알아서 따라옵니다. JavaFX 를 쓸 거라면 이 개념을 꼭 익히세요.
WPF·SwiftUI·React 가 각자의 방식으로 하는 일과 같은 발상입니다 — 상태를 선언하면 화면이 따라온다.

바인딩 실전 — 폼 하나를 통째로 묶기

모델을 프로퍼티로 만들면

public class OrderForm {
    private final StringProperty  customer = new SimpleStringProperty("");
    private final IntegerProperty qty      = new SimpleIntegerProperty(1);
    private final IntegerProperty price    = new SimpleIntegerProperty(0);
    private final BooleanProperty saving   = new SimpleBooleanProperty(false);

    // 계산된 값 — 수량이나 단가가 바뀌면 자동으로 다시 계산됩니다
    public final IntegerBinding total =
            Bindings.createIntegerBinding(
                    () -> qty.get() * price.get(), qty, price);

    // 유효성도 바인딩으로
    public final BooleanBinding invalid =
            customer.isEmpty()
                .or(qty.lessThanOrEqualTo(0))
                .or(price.lessThanOrEqualTo(0));

    public StringProperty  customerProperty() { return customer; }
    public IntegerProperty qtyProperty()      { return qty; }
    public IntegerProperty priceProperty()    { return price; }
    public BooleanProperty savingProperty()   { return saving; }
}
// 화면과 묶기 — 이게 전부입니다

FX 09

백그라운드 작업

여기가 JavaFX 에서 가장 많이 실수하는 곳입니다. 화면이 얼어붙는 원인이 전부 여기에 있습니다.

절대 규칙 — 모든 UI 조작은 JavaFX 애플리케이션 스레드에서만 해야 합니다.
· UI 스레드에서 오래 걸리는 작업(DB·파일·API)을 하면 화면이 멈춥니다.
· 반대로 다른 스레드에서 UI 를 건드리면 IllegalStateException: Not on FX application thread 가 납니다.
❌ 화면이 얼어붙습니다
button.setOnAction(e -> {
    List<Order> orders = api.fetchAll();   // 5초 걸림
    table.setItems(FXCollections.observableArrayList(orders));
});
// 5초 동안 창이 하얗게 되고 "응답 없음"
✅ Task 로 분리
Task<List<Order>> task = new Task<>() {
    @Override
    protected List<Order> call() {          // 백그라운드에서 실행
        return api.fetchAll();               // UI 를 건드리지 않는다
    }
};

task.setOnSucceeded(e ->                    // UI 스레드에서 자동 실행 ✅
        table.setItems(FXCollections.observableArrayList(task.getValue())));
task.setOnFailed(e -> showError(task.getException()));

new Thread(task).start();

진행률까지 표시하기

Task<Void> task = new Task<>() {
    @Override
    protected Void call() throws Exception {
        int total = files.size();
        for (int i = 0; i < total; i++) {
            if (isCancelled()) break;              // 취소 지원
            process(files.get(i));
            updateProgress(i + 1, total);          // 진행률
            updateMessage("처리 중: " + files.get(i).getName());
        }
        return null;
    }
};

progressBar.progressProperty().bind(task.progressProperty());
statusLabel.textProperty().bind(task.messageProperty());
cancelButton.setOnAction(e -> task.cancel());

task.setOnSucceeded(e -> {
    progressBar.progressProperty().unbind();       // ★ 바인딩 해제
    statusLabel.textProperty().unbind();
    statusLabel.setText("완료");
});

// 스레드 풀로 관리 (가상 스레드도 가능)
ExecutorService pool = Executors.newVirtualThreadPerTaskExecutor();
pool.submit(task);

JAVAFX 11

대용량 화면 — 수십만 행을 끊김 없이

사내 도구가 느려지는 이유는 대부분 “조회 결과를 전부 화면에 올려서” 입니다. TableView 는 이미 가상화를 하고 있지만, 쓰는 쪽이 망가뜨리기 쉽습니다.

셀 팩토리 — 매번 새로 만들지 않는다

스크롤할 때마다 노드 생성
col.setCellFactory(c -> new TableCell<>() {
  @Override protected void updateItem(Money v, boolean empty) {
    super.updateItem(v, empty);
    Label l = new Label();          // ★ 매 호출마다 새 노드
    l.setText(fmt(v));
    setGraphic(l);
  }
});
노드는 한 번, 값만 갱신
col.setCellFactory(c -> new TableCell<>() {
  private final Label l = new Label();   // 셀당 하나
  @Override protected void updateItem(Money v, boolean empty) {
    super.updateItem(v, empty);
    if (empty || v == null) { setGraphic(null); return; }
    l.setText(fmt(v));
    setGraphic(l);
  }
});
updateItem 은 스크롤 중 초당 수백 번 불립니다. 여기서 DB 조회·파일 읽기·포맷터 생성을 하면 즉시 버벅입니다. DateTimeFormatter·NumberFormat 은 static final 로 밖에 빼세요.

화면에 다 올리지 않는다 — 페이지 로딩

// 정렬·필터는 DB 에 맡기고, 화면에는 필요한 만큼만 올린다
public class LazyRows extends AbstractList<Row> {
    private final Map<Integer, List<Row>> pages = new LinkedHashMap<>() {
        protected boolean removeEldestEntry(Map.Entry<Integer, List<Row>> e) {
            return size() > 20;                   // 최근 20페이지만 보관
        }
    };
    private final int total, pageSize = 200;

    @Override public Row get(int i) {
        List<Row> page = pages.computeIfAbsent(i / pageSize, repo::loadPage);
        return page.get(i % pageSize);
    }
    @Override public int size() { return total; }
}

table.setItems(FXCollections.observableList(new LazyRows(repo.count())));
  • SortedList·FilteredList 는 전체를 메모리에 둘 때만 유효합니다. 수십만 행이면 정렬·필터를 DB 로 내리세요

배포한 뒤 — 자동 업데이트 · 운영

사내 PC 50대에 깔린 앱의 버전이 제각각이 되는 순간 “재현이 안 되는 버그”가 시작됩니다. 배포는 설치가 아니라 운영입니다.

jpackage — JRE 를 품은 설치본

# 1) 필요한 모듈만 담은 런타임을 만든다 (용량 절반 이하)
jlink --add-modules java.base,java.logging,java.sql,\
javafx.controls,javafx.fxml \
      --strip-debug --no-header-files --no-man-pages --compress=zip-6 \
      --output build/runtime

# 2) 설치 파일 생성
jpackage --type msi \
  --name "사내도구" --app-version 3.4.0 \
  --runtime-image build/runtime \
  --input build/libs --main-jar app.jar \
  --main-class com.acme.App \
  --icon app.ico \
  --win-dir-chooser --win-menu --win-shortcut \
  --win-upgrade-uuid 0f6c1d5e-....   # ★ 버전 올릴 때 덮어쓰기 되는 열쇠
--win-upgrade-uuid 를 매번 바꾸면 새 버전이 기존 앱을 덮지 않고 따로 설치됩니다. 제어판에 같은 앱이 여러 개 쌓이는 사고가 여기서 납니다 — 이 값은 앱의 수명 동안 고정입니다.

업데이트 확인 · 강제 버전

// 시작 시 조용히 확인하고, 필요할 때만 알린다
public void checkUpdate() {
    CompletableFuture.supplyAsync(() -> http.get(UPDATE_URL, Manifest.class))
        .thenAccept(m -> Platform.runLater(() -> {
            if (!isNewer(m.version(), APP_VERSION)) return;

            if (m.minSupported() != null && isOlder(APP_VERSION, m.minSupported())) {
                // 서버 API 가 깨지는 변경 — 업데이트 전엔 못 쓰게 막는다
                blockingUpdateDialog(m);
            } else {
                updateBanner(m);          // 배너만 띄우고 작업은 방해하지 않는다
            }
        }))
        .exceptionally(e -> { log.warn("update check failed", e); return null; });
}
  • 강제 업데이트 스위치를 처음부터 만들어 두세요 — 서버 API 를 바꿔야 할 때 유일한 탈출구입니다
  • 서명하세요. 서명 없는 msi 는 SmartScreen·백신에 막힙니다
  • 크래시 로그를 남기세요 — Thread.setDefaultUncaughtExceptionHandler 로 파일에 쓰고, 사용자가 버튼 하나로 보낼 수 있게 하세요
  • 로그는 %LOCALAPPDATA%·~/Library/Logs 에 — 설치 폴더에 쓰면 권한 오류가 납니다
