임베디드 디버깅 지도 — LED 한 개부터 오실로스코프까지

펌웨어 디버깅 도구는 사다리처럼 늘어서 있습니다. LED 하나 깜빡이기는 공짜지만 1비트밖에 못 보고, 온칩 디버거는 모든 변수를 보지만 CPU 를 멈추는 순간 시간이 망가집니다. 도구마다 무엇을 보여 주는지와 무엇을 대가로 치르는지를 알아야 증상에 맞는 도구를 첫 번째로 꺼낼 수 있습니다.

디버깅 도구 매트릭스 — 많이 보는 도구일수록 시간을 더 망가뜨립니다. 타이밍 버그엔 아래쪽, 논리 버그엔 ⑤.

① 디버그 핀 — 가장 싸고 가장 정확한 스톱워치

/* debug_pin.h — PA5(Nucleo LD2) 나 남는 핀 하나를 "측정 전용"으로 */
#include "stm32f4xx.h"

/* BSRR: 아래 16비트 = set, 위 16비트 = reset.
   한 번의 32비트 쓰기라 읽기-수정-쓰기(RMW) 가 없어
   ISR 안에서 써도 다른 핀과 경쟁하지 않습니다. */
#define DBG_PIN_HI()  (GPIOA->BSRR = GPIO_BSRR_BS5)
#define DBG_PIN_LO()  (GPIOA->BSRR = GPIO_BSRR_BR5)

void TIM2_IRQHandler(void)
{
    DBG_PIN_HI();                  /* ← 스코프 상승 엣지 = ISR 진입 */
    TIM2->SR = ~TIM_SR_UIF;        /* 플래그 지우기 (rc_w0 비트) */
    control_loop_step();
    DBG_PIN_LO();                  /* ← 하강 엣지 = ISR 끝          */
}
/* 스코프에서 보이는 것:
   · 펄스 폭      = ISR 실행 시간 (최악값을 무한 지속 모드로)
   · 펄스 간격    = 실제 주기 (지터 포함)
   · 펄스가 빠짐  = 인터럽트를 놓쳤다는 증거 */
서버 개발에 빗대면 — APM 의 "구간 타이머"를 하드웨어로 만든 것입니다. 핀 쓰기 한 번은 수십 ns 라 측정 자체가 결과를 거의 바꾸지 않습니다. 핀이 모자라면 핀 두 개로 상태 4가지를 인코딩하는 요령도 씁니다.

관찰자 효과 — 도구가 버그를 숨기는 세 가지 방식 🟡 중급

물리학의 "관찰하면 결과가 바뀐다"가 펌웨어에선 일상입니다. 이런 버그를 현장에선 하이젠버그(Heisenbug) 라고 부릅니다. 도구를 고를 때 그 도구가 시스템의 무엇을 바꾸는지 알아야 "버그가 사라졌다"를 "고쳐졌다"로 착각하지 않습니다.

도구무엇을 바꾸나그래서 숨는 버그
printf (UART 폴링)호출마다 수 ms 지연 · 코드 크기 · 스택 수백 바이트레이스 · 타이밍 의존 버그 · 스택이 아슬아슬한 태스크(오히려 터짐)
브레이크포인트CPU 만 멈추고 주변장치는 계속 돎UART 수신 오버런 · 타이머 만료 · 워치독 리셋이 디버깅 중에만 생김
-O0 디버그 빌드변수가 전부 메모리에 · 인라인 없음 · 코드 2~3배volatile 누락 · 미정의 동작 · 최적화가 지운 지연 루프(t13)
디버거 연결 자체저전력 모드에서도 디버그 클럭 유지 · DHCSR.C_DEBUGENStop 모드 진입 실패 · BKPT 명령이 디버거 없을 땐 HardFault

DWT 사이클 카운터 — 코드 안의 스톱워치

/* Cortex-M3/M4/M7 의 DWT->CYCCNT: CPU 클럭마다 1 증가하는 32비트 카운터.
   180 MHz 면 2^32 / 180e6 ≈ 23.8 초마다 한 바퀴 돕니다. */
static inline void cyc_init(void)
{
    CoreDebug->DEMCR |= CoreDebug_DEMCR_TRCENA_Msk; /* DWT 전원 켜기 */
    DWT->CYCCNT = 0;
    DWT->CTRL  |= DWT_CTRL_CYCCNTENA_Msk;
}
static inline uint32_t cyc_now(void) { return DWT->CYCCNT; }

void measure(void)
{
    uint32_t t0 = cyc_now();
    fir_filter(buf, 256);
    uint32_t dt = cyc_now() - t0;   /* 부호 없는 뺄셈 → 한 바퀴 넘쳐도 맞음 */
    /* dt = 9000 이면 9000 / 180 = 50 µs */
    LOG_INF("fir: %lu cyc (%lu us)", (unsigned long)dt,
            (unsigned long)(dt / (SystemCoreClock / 1000000u)));
}
M7(F7 · H7) 는 잠금이 있습니다 — DWT->LAR = 0xC5ACCE55 로 풀어야 CYCCNT 가 켜지는 칩이 있습니다. M0/M0+ 에는 DWT 사이클 카운터가 아예 없어 SysTick 이나 타이머로 대신합니다.

디버깅 중에 주변장치 멈추기 — DBGMCU

/* 브레이크포인트에 걸린 동안 타이머 · 워치독도 같이 멈추게.
   #ifdef DEBUG 로 감싸 양산 빌드에는 넣지 않습니다. */
void debug_freeze_setup(void)
{
#ifdef DEBUG
    __HAL_DBGMCU_FREEZE_IWDG();   /* 멈춘 동안 독립 워치독 정지 */
    __HAL_DBGMCU_FREEZE_WWDG();
    __HAL_DBGMCU_FREEZE_TIM2();   /* 제어 루프 타이머 */
    HAL_DBGMCU_EnableDBGSleepMode();  /* WFI 중에도 SWD 유지 */
    HAL_DBGMCU_EnableDBGStopMode();   /* Stop 모드에서도 디버거 연결 유지 */
#endif
}
UART 수신은 멈출 수 없습니다 — 상대 장치는 계속 보내므로 멈춘 사이 ORE(오버런) 가 쌓입니다. 디버깅 뒤 "수신이 영영 안 된다"면 HAL 이 ORE 를 지우지 않아 생긴 일입니다(통신 탭 참고). 통신 경로는 멈추지 말고 RTT 로그(t04)로 보세요.

개발 보드에 미리 준비해 둘 것

  • SWD + SWO + NRST 를 커넥터로 뺀다 — 양산 보드에서도 테스트 패드로 남깁니다(SET 탭 u09).
  • 디버그 핀 2개를 헤더로 — ISR · 태스크 측정용. 보드 설계 때 안 빼 두면 나중엔 납땜입니다.
  • UART 콘솔 1개 — 디버거 없이도 현장에서 덤프를 꺼내는 마지막 통로.
  • 리셋 원인 출력 — 부팅 첫 줄에 RCC->CSR 를 찍게 (t13).

-g 는 .hex · .bin 크기에 영향이 없습니다 — 디버그 정보는 .elf 에만 들어가고 칩에는 안 올라갑니다. 그러니 양산 빌드도 -g 로 만들어 .elf 를 보관하세요. 현장 덤프의 주소를 줄 번호로 바꿀 유일한 열쇠입니다.
정리 — 많이 보는 도구일수록 시간을 망가뜨립니다. 논리 버그는 GDB · 호스트 테스트로, 타이밍 버그는 GPIO 토글 · RTT · 트레이스로, 현장 버그는 리셋 뒤에도 남는 덤프로 — 증상에 맞춰 첫 도구를 고르는 것이 디버깅 시간의 절반을 줄입니다.

GDB 실전 — 멈추고, 들여다보고, 감시하기

명령 열 개짜리 기초는 C 실전 탭 c24 에 있습니다. 여기서는 그 위에서 펌웨어를 GDB 로 디버깅할 때만 생기는 일을 다룹니다 — 조건부 브레이크포인트가 실시간 루프를 망가뜨리는 이유, HAL 안으로 빨려 들어가지 않는 단계 실행, 매크로로 된 레지스터(GPIOA->ODR)를 출력하는 법, 하드웨어 와치포인트의 개수 한계, 그리고 최적화가 디버거 화면을 어떻게 속이는지.

bt 해부 — 주소의 앞자리만 봐도 어디인지 압니다: 0x08 은 Flash(코드), 0x2000 은 전역, 0x2001F 는 스택.

브레이크포인트 — 조건 · 횟수 · 자동 명령

(gdb) tbreak main                       # 한 번 걸리면 사라짐

조건부 · dprintf 도 매번 CPU 를 멈춥니다 — 칩은 "조건"을 모릅니다. 걸릴 때마다 정지 → USB 로 GDB 에 알림 → GDB 가 조건 평가 → 재개 순서라 한 번에 수 ms가 듭니다. 1 kHz 제어 루프에 걸면 루프가 무너집니다. 자주 지나가는 곳은 코드에 조건을 넣고(if (raw > 4000) __NOP(); 줄에 BP) 거기에 거세요.

온칩 디버깅 — GDB 와 칩 사이에서 일어나는 일

프로브 배선 · OpenOCD 설치 · 기본 launch.json 은 설치 탭 u09 · u04 에서 끝냈습니다. 이 절은 그 연결이 실제로 어떻게 동작하는지를 봅니다. 브레이크포인트를 걸면 칩 안의 무엇이 바뀌는지 알면 "BP 가 안 걸린다 · 6개 넘게 못 건다 · 붙이면 칩이 멈춘다" 같은 증상이 전부 설명됩니다. 그리고 SVD 로 주변장치 레지스터를 이름으로 보는 법, 돌고 있는 장치에 리셋 없이 붙는 법까지 다룹니다.

GDB 원격 프로토콜(RSP) 시퀀스 — Z1 = 하드웨어 브레이크포인트. 칩 안의 FPB 비교기가 PC 를 감시합니다.

플래시에서 도는 코드에 소프트웨어 BP 가 안 되는 이유

PC 프로그램의 GDB 는 브레이크포인트 자리의 명령을 BKPT 명령으로 덮어써서 겁니다(소프트웨어 BP, 개수 무제한). 펌웨어는 Flash 에서 직접 실행되는데, Flash 는 섹터 단위로 지워야만 다시 쓸 수 있습니다.

2바이트를 바꾸려고 128 KB 섹터를 지우고 다시 쓰면 수 초가 걸리고, Flash 수명(섹터당 1만 회)도 깎입니다. 그래서 OpenOCD 는 GDB 에 "이 영역은 Flash" 라는 메모리 지도를 넘기고, GDB 는 그 영역에 자동으로 하드웨어 BP(Z1)를 씁니다.

RAM 에 올려 실행하는 함수(__attribute__((section(".RamFunc"))))에는 소프트웨어 BP 가 걸립니다. SEGGER J-Link 의 "Flash Breakpoints" 는 Flash 를 영리하게 다시 써서 무제한 BP 를 흉내 내는 유료 기능입니다.

로그 출력 방식 — UART printf · SWO · RTT · 바이너리 로그

로그는 멈추지 않는 디버거입니다. 하지만 펌웨어에선 로그 한 줄이 제어 루프 한 주기보다 길 수 있습니다. 같은 80글자를 내보내는 데 UART 폴링은 7 ms, RTT 는 몇 µs 입니다. 어떤 통로로 내보내는지, 무엇을 칩 안에서 하고 무엇을 PC 로 미룰지가 로그 설계의 전부입니다. 레벨별로 컴파일 시점에 통째로 지우는 매크로까지 만듭니다.

로그 비용 — UART 폴링 한 줄 = 1 kHz 루프 7주기. 같은 정보를 바이너리로 보내면 만 배 넘게 싸집니다.

① UART printf — 비용을 직접 계산해 보기

/* newlib 의 printf → _write() 로 내려옴. 이걸 재정의 */
#include <errno.h>
extern UART_HandleTypeDef huart2;     /* Nucleo: ST-LINK 가상 COM */

int _write(int fd, char *ptr, int len)
{
    if (fd != 1 && fd != 2) { errno = EBADF; return -1; }
    HAL_UART_Transmit(&huart2, (uint8_t *)ptr, (uint16_t)len, HAL_MAX_DELAY);
    return len;                       /* ★ 끝날 때까지 블로킹 */
}

/* 115200 bps, 8N1 → 바이트당 10비트(시작 1 + 데이터 8 + 정지 1)
     1 바이트 = 10 / 115200      = 86.8 µs
    80 바이트 = 80 × 86.8 µs     = 6.94 ms
   180 MHz 에서 6.94 ms         = 약 125만 사이클을 기다림 */
ISR 안에서 printf 금지 — 7 ms 동안 같거나 낮은 우선순위 인터럽트가 전부 밀리고, newlib 의 printf 는 재진입 안전하지 않으며 malloc 을 부를 수도 있습니다. DMA + 링 버퍼로 바꾸면 블로킹은 사라지지만 대역폭(11.5 KB/s)은 그대로라 로그가 많으면 결국 버퍼가 넘칩니다.

② ITM / SWO — 디버그 핀 하나로 나가는 printf

/* PB3 = TRACESWO. Nucleo-F446RE 는 내장 ST-LINK 에 이어져 있음.
   TPIU 속도 · ITM 채널 켜기는 디버거(OpenOCD · Cortex-Debug)가 설정 */
#include "stm32f4xx.h"

{
    (void)fd;
    for (int i = 0; i < len; i++)
        ITM_SendChar((uint32_t)ptr[i]);   /* core_cm4.h — 채널 0 */
    return len;

// launch.json 에 추가 — Cortex-Debug 가 TPIU 를 설정하고 출력 창에 표시
"swoConfig": {

③ SEGGER RTT — RAM 의 링 버퍼를 디버거가 몰래 읽습니다 🟡 중급

RTT 링 버퍼 — 쓰는 쪽과 읽는 쪽이 각자 자기 오프셋만 고치므로 잠금이 필요 없습니다(서버의 SPSC 큐와 같은 원리).

HardFault 깊이 — 스택 프레임 복원부터 리셋 뒤에 남는 크래시 덤프까지

naked 핸들러로 프레임을 잡고 addr2line 에 PC 를 넣는 첫 대응은 STM32 탭 m12 에 있습니다. 이 절은 그다음 단계입니다 — FPU 확장 프레임과 정렬 패딩까지 정확히 복원하고, 스택이 터져서 난 폴트에서도 핸들러가 살아남게 하고, 프레임 밖 스택을 훑어 호출 경로를 추정하고, 무엇보다 디버거가 없는 현장 장비에서 난 폴트를 리셋 뒤에 꺼내 보는 법입니다.

예외 프레임 배치 — FPU 확장 · 정렬 패딩을 셈하지 않으면 "폴트 직전 SP"가 틀리고, 그 위의 호출 경로를 잘못 읽습니다.

/* 스택 오버플로로 난 폴트(STKERR · MSTKERR)라면 MSP 가 이미 RAM 밖이거나
   가드 영역에 있습니다. 거기서 C 함수를 부르면 또 폴트 → lockup.
   그래서 C 로 가기 전에 MSP 를 전용 스택으로 옮깁니다. */
__attribute__((used, aligned(8))) uint32_t g_fault_stack[128];   /* 512 B */

void hardfault_c(const uint32_t *sf, uint32_t exc_return,
                 const uint32_t *r4_r11) __attribute__((used, noreturn));

__attribute__((naked)) void HardFault_Handler(void)
{
    __asm volatile(
        "tst   lr, #4                 \n"  /* 비트2: 0=MSP, 1=PSP       */
        "ite   eq                     \n"
        "mrseq r0, msp                \n"  /* r0 = 프레임 주소           */
        "mrsne r0, psp                \n"
        "mov   r1, lr                 \n"  /* r1 = EXC_RETURN            */
        "ldr   r2, =g_fault_stack+512 \n"
        "msr   msp, r2                \n"  /* ★ 이제 SP 는 안전한 곳    */
        "push  {r4-r11}               \n"  /* 프레임에 없는 레지스터 보존 */
        "mov   r2, sp                 \n"  /* r2 = &r4 ~ r11            */
        "b     hardfault_c            \n");
}
/* UsageFault · BusFault · MemManage 핸들러도 같은 본문으로 —
   SHCSR 로 개별 폴트를 켰다면(m12) 그쪽으로 먼저 옵니다. */

프레임 밖까지 — 호출 경로 추정 · addr2line 일괄 🟡 중급

"가난한 자의 백트레이스" — 스택에서 코드 주소 줍기

/* 폴트 직전 SP 위쪽에는 호출자들이 push 한 LR 이 흩어져 있습니다.
   Flash 범위 + 최하위 비트 1(Thumb) 인 워드를 모으면 호출 경로 후보가 됩니다.
   (프레임 포인터가 없는 -O2 빌드에서 쓰는 근사법 — 오탐 가능) */
#define FLASH_LO 0x08000000u
#define FLASH_HI 0x08080000u   /* F446RE: 512 KB */

static uint32_t collect_ret_addrs(const uint32_t *sp, const uint32_t *top,
                                  uint32_t *out, uint32_t max)
{
    uint32_t n = 0;
    for (const uint32_t *p = sp; p < top && n < max; p++) {
        uint32_t v = *p;
        if (v >= FLASH_LO && v < FLASH_HI && (v & 1u))
            out[n++] = v & ~1u;     /* Thumb 비트 떼고 저장 */
    }
    return n;
}
/* top: MSP 면 링커의 _estack, PSP 면 그 태스크 스택의 끝
        (FreeRTOS: pxStack + 스택 크기) */

#define CRASH_MAGIC 0xC0DEFA17u
typedef struct {

    uint32_t build_id;          /* git 해시 앞 8자리 (빌드 시 -D 로 주입) */
    uint32_t r0, r1, r2, r3, r12, lr, pc, xpsr;   /* 프레임 (없으면 0) */
    uint32_t r4_r11[8];
    uint32_t cfsr, hfsr, mmfar, bfar, exc_return, sp_before;
    uint32_t ret[8];            /* 스택에서 주운 주소 후보 */
    uint32_t sum;               /* ★ 맨 끝 — 앞 전체의 체크섬 */
} crash_dump_t;

extern crash_dump_t g_crash;

/* crash.c */
__attribute__((section(".noinit"))) crash_dump_t g_crash;

static uint32_t chk32(const uint32_t *w, uint32_t n)
{
    uint32_t s = 0x5A5A5A5Au;
    while (n--) s = (s << 5 | s >> 27) ^ *w++;   /* 회전 + XOR */
    return s;
}
#define CRASH_WORDS ((uint32_t)(offsetof(crash_dump_t, sum) / 4u))

폴트 때 쓰고, 부팅 때 읽기

void hardfault_c(const uint32_t *sf, uint32_t exc_return,
                 const uint32_t *r4_r11)
{
    crash_dump_t *d = &g_crash;
    int ok = ((uint32_t)sf & 3u) == 0 &&
             (uint32_t)sf >= 0x20000000u && (uint32_t)sf <= 0x2001FFE0u;
    if (ok) {                       /* 범위가 맞을 때만 프레임 복사 */
        d->r0 = sf[0]; d->r1 = sf[1]; d->r2 = sf[2]; d->r3 = sf[3];
        d->r12 = sf[4]; d->lr = sf[5]; d->pc = sf[6]; d->xpsr = sf[7];
        uint32_t sz = (exc_return & 0x10u) ? 0x20u : 0x68u;
        if (d->xpsr & (1u << 9)) sz += 4u;          /* 정렬 패딩 */
        d->sp_before = (uint32_t)sf + sz;
    } else {
        d->pc = d->lr = d->sp_before = 0;
    }
    for (int i = 0; i < 8; i++) d->r4_r11[i] = r4_r11[i];
    d->cfsr = SCB->CFSR;  d->hfsr = SCB->HFSR;
    d->mmfar = SCB->MMFAR; d->bfar = SCB->BFAR;
    d->exc_return = exc_return;
    d->build_id = BUILD_ID;
    d->magic = CRASH_MAGIC;
    d->sum = chk32((const uint32_t *)d, CRASH_WORDS);   /* 마지막에 */

    if (CoreDebug->DHCSR & CoreDebug_DHCSR_C_DEBUGEN_Msk) __BKPT(0);
    NVIC_SystemReset();
}

/* main() 앞부분 — 클럭 · UART 초기화 직후 */
void crash_check_at_boot(void)
{
    crash_dump_t *d = &g_crash;
    if (d->magic == CRASH_MAGIC &&
        d->sum == chk32((const uint32_t *)d, CRASH_WORDS)) {
        LOG_ERR("CRASH build=%08lx pc=%08lx lr=%08lx cfsr=%08lx bfar=%08lx",
                (unsigned long)d->build_id, (unsigned long)d->pc,
                (unsigned long)d->lr, (unsigned long)d->cfsr,
                (unsigned long)d->bfar);
        persist_to_flash(d, sizeof *d);   /* 다음 통신 때 서버로 (양산 탭) */
    }
    d->magic = 0;                          /* ★ 같은 덤프를 두 번 보고하지 않게 */
}
생략한 ret[] 는 앞의 collect_ret_addrs(sp_before, _estack, ...) 로 채웁니다(MSP 일 때). RAM 보다 오래 남겨야 하면 F446 의 백업 SRAM 4 KB(VBAT 로 유지)나 RTC 백업 레지스터를 씁니다. 폴트 핸들러에서 Flash 를 직접 쓰는 건 피하세요 — 지우기에 수백 ms~초가 걸리고 그 사이 또 폴트가 나면 Flash 가 반쯤 지워집니다.
정리 — 프레임 크기는 EXC_RETURN 비트4(FPU)와 xPSR 비트9(정렬 패딩)로 정해지고, 이걸 알아야 폴트 직전 SP 와 그 위의 호출 경로를 읽습니다. 핸들러는 전용 스택으로 갈아탄 뒤 C 로 넘어가고, 덤프는 매직 + 체크섬과 함께 .noinit 에 남겨 리셋 뒤 부팅 코드가 보고합니다. 빌드 ID 로 맞는 .elf 를 찾으면 현장 크래시도 줄 번호까지 내려갑니다.

스택 · 메모리 문제 — 추측하지 말고 재고, 넘치면 바로 죽게

MCU 에는 MMU 가 없습니다. 스택이 넘치면 세그폴트 대신 옆 변수를 조용히 덮어씁니다 — 증상은 엉뚱한 곳에서, 한참 뒤에 나타납니다. 그래서 펌웨어의 메모리 디버깅은 두 갈래입니다: 얼마나 쓰는지 숫자로 재기(스택 페인팅 · -fstack-usage · .map)와 넘치는 순간 즉시 폴트 나게 만들기(MPU 가드). 힙 단편화가 왜 "남는데 못 받는" 상황을 만드는지도 봅니다.

RAM 배치 — 스택과 힙이 마주 보고 자라는 빈 곳이 유일한 완충지대입니다. 가드는 그 경계에 세우는 울타리입니다.

① 스택 페인팅 — 0xA5 로 칠하고 얼마나 지워졌나 보기

/* CubeMX 링커 스크립트가 주는 심볼 — "주소"가 곧 값입니다 */
extern uint32_t _estack;           /* 스택 꼭대기 = RAM 끝     */
extern uint32_t _Min_Stack_Size;   /* 예약 크기 (0x800 등)     */
#define STACK_TOP    ((uint32_t)&_estack)
#define STACK_SIZE   ((uint32_t)&_Min_Stack_Size)
#define STACK_BOTTOM (STACK_TOP - STACK_SIZE)
#define PAINT        0xA5A5A5A5u

/* main() 맨 처음에 한 번 — 지금 SP 아래 64 B 는 남겨 둠 */
void stack_paint(void)
{
    uint32_t *p  = (uint32_t *)STACK_BOTTOM;
    uint32_t *sp = (uint32_t *)__get_MSP();
    while (p < sp - 16) *p++ = PAINT;
}

/* 바닥부터 올라가며 칠이 남은 곳을 셈 → 최대 사용량 */
uint32_t stack_high_water(void)
{
    const uint32_t *p = (const uint32_t *)STACK_BOTTOM;
    while (p < (const uint32_t *)STACK_TOP && *p == PAINT) p++;
    return STACK_TOP - (uint32_t)p;     /* 바이트 */
}
/* 1분마다 / 시험 끝에: LOG_INF("msp max %lu / %lu", hw, STACK_SIZE); */
측정은 최악 경로를 지나간 뒤에만 의미가 있습니다 — 오류 처리 경로 · 모든 인터럽트가 겹친 순간 · 로그 레벨 DEBUG. HIL 시험(t12) 마지막에 high-water 를 읽어 기록하면 버전마다 추이가 보입니다. FreeRTOS 태스크는 커널이 같은 방식(0xA5)으로 칠해 두니 uxTaskGetStackHighWaterMark() 를 쓰세요(r 탭).

② MPU 스택 가드 — 넘치면 그 자리에서 폴트

/* core_cm4.h 가 mpu_armv7.h 를 포함합니다(__MPU_PRESENT = 1).
   F446 MPU: 영역 8개, 크기는 2의 거듭제곱(최소 32 B), 시작 주소는 크기의 배수 */
#define GUARD_SIZE 256u

void mpu_stack_guard(void)
{
    uint32_t base = (STACK_BOTTOM + GUARD_SIZE - 1u) & ~(GUARD_SIZE - 1u);

    ARM_MPU_Disable();
    ARM_MPU_SetRegion(
        ARM_MPU_RBAR(0u, base),                    /* 영역 0 */
        ARM_MPU_RASR(1u,                           /* 실행 금지 */
                     ARM_MPU_AP_NONE,              /* 읽기 · 쓰기 금지 */
                     0u, 0u, 0u, 0u,               /* TEX · S · C · B */
                     0x00u,                        /* 서브영역 전부 사용 */
                     ARM_MPU_REGION_SIZE_256B));
    /* PRIVDEFENA: 영역 밖은 기본 메모리 맵 그대로 → 가드만 막힘 */
    ARM_MPU_Enable(MPU_CTRL_PRIVDEFENA_Msk);
    SCB->SHCSR |= SCB_SHCSR_MEMFAULTENA_Msk;     /* MemManage 개별 핸들러 */
}
/* ★ 가드를 켠 뒤에는 stack_paint · stack_high_water 도 base + GUARD_SIZE 부터
     훑어야 합니다 — 측정 코드가 가드를 읽는 순간 그 자체가 MemManage 폴트 */
가드보다 큰 지역 배열은 가드를 건너뜁니다 — uint8_t buf[512]; 처럼 SP 를 한 번에 512 B 내리면 가드(256 B)를 밟지 않고 그 아래 힙에 바로 씁니다. 가드는 가장 큰 스택 프레임보다 크게 잡거나, 큰 배열을 스택에 두지 마세요. Cortex-M33(STM32U5 · L5)부터는 MSPLIM · PSPLIM 레지스터가 이 일을 하드웨어로 합니다.

정적 분석으로 재기 — -fstack-usage · -Wstack-usage · 최악 경로 🟡 중급

(블록 헤더 · 정렬 바이트는 생략한 그림입니다.) 실무 규칙은 단순합니다 — 초기화 때만 malloc, 운영 중엔 금지. 운영 중 할당이 꼭 필요하면 크기별 고정 블록 풀을 씁니다.

고정 블록 풀 — 단편화가 원리적으로 불가능

/* 같은 크기 블록만 주고받으니 "빈 곳은 있는데 못 받는" 일이 없음 */
#define BLK_SIZE  64u
#define BLK_COUNT 32u

typedef union blk { union blk *next; uint8_t data[BLK_SIZE]; } blk_t;
static blk_t  s_pool[BLK_COUNT];
static blk_t *s_free;
static uint32_t s_used, s_peak;

void pool_init(void)
{
    s_free = NULL;
    for (uint32_t i = 0; i < BLK_COUNT; i++) {
        s_pool[i].next = s_free;
        s_free = &s_pool[i];
    }
    s_used = s_peak = 0;
}

void *pool_alloc(void)                /* O(1) · ISR 에서 쓰려면 임계 구역 */
{
    blk_t *b = s_free;
    if (b) {
        s_free = b->next;
        if (++s_used > s_peak) s_peak = s_used;   /* 최대 사용 기록 */
    }
    return b;
}

void pool_free(void *p)
{
    blk_t *b = p;
    b->next = s_free;
    s_free = b;
    s_used--;
}
/* s_peak 를 HIL 시험 끝에 읽어 BLK_COUNT 를 정합니다 — 스택 페인팅과 같은 발상 */
정리 — 스택은 0xA5 페인팅으로 실측하고 -fstack-usage 로 함수별 숫자를 받아 최악 체인 + 중첩 ISR 로 합산합니다. MPU 가드(가장 큰 프레임보다 크게)를 세우면 넘치는 순간 폴트가 나 범인이 드러납니다. Flash · RAM 은 --print-memory-usage 와 .map 의 --cref 로 추적하고, 운영 중 malloc 은 고정 블록 풀로 바꿉니다.

호스트에서 단위 테스트 — 보드 없이 펌웨어 로직을 1초 안에

보드에 구워서 확인하는 한 바퀴는 빌드 · 플래시 · 리셋 · 눈으로 확인까지 30초가 넘고, 자동화도 어렵습니다. 그런데 펌웨어 코드의 대부분 — 프로토콜 파서, 링 버퍼, 상태 머신, 필터, 단위 변환 — 은 레지스터를 한 번도 만지지 않습니다. 그 부분을 PC 의 GCC 로 컴파일해 돌리면 수천 개 테스트가 1초 안에 끝납니다. Unity 의 기본 사용법은 C 실전 탭 c24 에 있으니, 여기서는 펌웨어를 호스트에서 테스트할 때만 생기는 문제와 프로젝트 구성에 집중합니다.

테스트 피라미드 — 로직의 70% 이상을 호스트에서. 칩이 꼭 필요한 것(타이밍 · 주변장치)만 위층으로 올립니다.

테스트 대상 — 링 버퍼 (ISR 과 메인이 공유)

/* ringbuf.h — 크기는 2의 거듭제곱, head/tail 은 계속 증가(자연 오버플로) */
#include <stdbool.h>
#include <stdint.h>
typedef struct {
    uint8_t *buf;
    uint16_t mask;                 /* size - 1 */
    volatile uint16_t head, tail;  /* 쓰는 쪽 head, 읽는 쪽 tail */
} ringbuf_t;

bool     rb_init(ringbuf_t *rb, uint8_t *mem, uint16_t size);
bool     rb_put(ringbuf_t *rb, uint8_t b);
bool     rb_get(ringbuf_t *rb, uint8_t *out);
uint16_t rb_count(const ringbuf_t *rb);

/* ringbuf.c */
bool rb_init(ringbuf_t *rb, uint8_t *mem, uint16_t size)
{
    if (size == 0 || (size & (size - 1u)) != 0 || size > 32768u) return false;
    rb->buf = mem; rb->mask = (uint16_t)(size - 1u);
    rb->head = rb->tail = 0;
    return true;
}
uint16_t rb_count(const ringbuf_t *rb)
{
    return (uint16_t)(rb->head - rb->tail);   /* ★ 캐스트: int 승격 후 음수 방지 */
}
bool rb_put(ringbuf_t *rb, uint8_t b)
{
    if (rb_count(rb) > rb->mask) return false;   /* 가득 참 */
    rb->buf[rb->head & rb->mask] = b;
    rb->head++;
    return true;
}
bool rb_get(ringbuf_t *rb, uint8_t *out)
{
    if (rb->head == rb->tail) return false;      /* 비었음 */
    *out = rb->buf[rb->tail & rb->mask];
    rb->tail++;
    return true;
}

시간을 인자로 — HAL_GetTick() 을 부르지 않는 디바운스

/* debounce.c — "지금 시각"을 받기만 하므로 테스트가 시간을 조종 */
#define DEBOUNCE_MS 20u            /* 이 줄과 typedef 는 debounce.h 에 */
typedef struct { uint8_t stable, last_raw; uint32_t since_ms; } debounce_t;

bool debounce_update(debounce_t *d, uint8_t raw, uint32_t now_ms)
{
    if (raw != d->last_raw) {            /* 바뀌었으면 시계 다시 시작 */
        d->last_raw = raw;
        d->since_ms = now_ms;
        return false;
    }
    if (raw != d->stable && (uint32_t)(now_ms - d->since_ms) >= DEBOUNCE_MS) {
        d->stable = raw;
        return true;                     /* 안정된 상태가 바뀜 = 이벤트 */
    }
    return false;
}
/* test_debounce.c — include 와 main 은 앞 파일과 같은 모양 */
static debounce_t d;
void setUp(void)    { d = (debounce_t){ 0 }; }
void tearDown(void) { }

void test_bounce_then_stable_20ms(void)

#include <stddef.h>
#include <stdint.h>
int i2c_read_reg(uint8_t addr7, uint8_t reg, uint8_t *buf, size_t len);

/* tmp117.c — TI TMP117: 온도 레지스터 0x00 (16비트 2의 보수),
   1 LSB = 7.8125 m°C = 125/16 m°C, 장치 ID 레지스터 0x0F = 0x0117 */
#include <errno.h>
#include "i2c_port.h"
#define TMP117_ADDR  0x48u          /* ADD0 = GND */
#define REG_TEMP     0x00u
#define REG_DEV_ID   0x0Fu

int tmp117_probe(void)
{
    uint8_t b[2];
    if (i2c_read_reg(TMP117_ADDR, REG_DEV_ID, b, 2) != 0) return -EIO;
    uint16_t id = (uint16_t)((b[0] << 8) | b[1]);    /* MSB 먼저 */
    return ((id & 0x0FFFu) == 0x0117u) ? 0 : -ENODEV;
}

int tmp117_read_mc(int32_t *out_mc)             /* 밀리 °C */
{
    uint8_t b[2];
    int rc = i2c_read_reg(TMP117_ADDR, REG_TEMP, b, 2);
    if (rc != 0) return rc;
    int16_t raw = (int16_t)((b[0] << 8) | b[1]);  /* 0xFF80 → -128 (GCC: 모듈로) */
    *out_mc = (int32_t)raw * 125 / 16;           /* 0x0C80=3200 → 25000 */
    return 0;
}

t08 은 포트 위의 코드를 시험했습니다. 그럼 포트 아래, 레지스터를 직접 쓰는 드라이버는 보드 없이 시험할 수 없을까요? 할 수 있습니다. CMSIS 의 USART_TypeDef 는 그냥 C 구조체이고, USART2 는 그 구조체를 가리키는 주소 상수일 뿐입니다. 드라이버가 주소를 상수로 박지 않고 포인터로 받게 하면, 테스트는 RAM 에 만든 같은 모양의 구조체를 넘겨 드라이버가 어느 레지스터에 무엇을 썼는지 그대로 읽을 수 있습니다. 이걸로 TDD 한 바퀴를 돌려 봅니다.

레지스터 페이크 — 오프셋과 타입이 같으니 드라이버는 진짜인지 모릅니다. 테스트는 쓰인 값을 그냥 읽으면 됩니다.

    USART2 같은 주소 매크로를 쓰지 않으면 호스트에서도 문제 없음) */

#include "reg_access.h"

                                    아래 TDD 한 바퀴에서 생김 */

/* uart_drv.c */
void uart_init(uart_t *u, USART_TypeDef *regs, uint32_t pclk_hz, uint32_t baud)
{
    u->regs = regs;
    REG_WRITE(regs->CR1, 0u);                        /* UE=0 에서 설정 */
    /* OVER8=0: BRR = USARTDIV × 16 = pclk / baud (반올림)
       45 000 000 / 115 200 = 390.6 → 391 = 0x187 (가수 24 · 소수 7/16) */
    REG_WRITE(regs->BRR, (pclk_hz + baud / 2u) / baud);
    REG_WRITE(regs->CR2, 0u);                        /* 정지 비트 1 */
    REG_WRITE(regs->CR3, 0u);                        /* 흐름 제어 없음 */
    REG_WRITE(regs->CR1, USART_CR1_TE | USART_CR1_RE);
    REG_WRITE(regs->CR1, regs->CR1 | USART_CR1_UE);  /* ★ 마지막에 켬 */
}

/* main.c (양산) — 여기서만 진짜 주소가 등장 */

/* main() 안에서 */

{

        if (spin_limit-- == 0u) return -1;

/* 프레임: 0x7E | LEN | PAYLOAD[LEN] | CRC_H | CRC_L
   CRC-16/CCITT-FALSE (초깃값 0xFFFF, 다항식 0x1021) — LEN 과 PAYLOAD 에 대해
   예: 7E 03 01 02 03 7E 2D   ← CRC 가 0x7E2D. 0x7E 가 본문에도 나올 수 있어
       길이로 끝을 아는 방식입니다 */
#define PROTO_SOF 0x7Eu
#define PROTO_MAX 32u
typedef enum { ST_SOF, ST_LEN, ST_DATA, ST_CRC_H, ST_CRC_L } pstate_t;
typedef enum { P_NONE, P_FRAME, P_ERR } presult_t;
typedef struct {
    pstate_t st;
    uint8_t  len, idx;
    uint8_t  buf[PROTO_MAX];
    uint16_t crc_rx;
} parser_t;

presult_t parser_feed(parser_t *p, uint8_t b)
{
    switch (p->st) {
    case ST_SOF:
        if (b == PROTO_SOF) p->st = ST_LEN;
        return P_NONE;
    case ST_LEN:
        /* ✗ 처음 버전엔 이 검사가 없었습니다 — 퍼저가 3초 만에 찾음 */
        if (b == 0u || b > PROTO_MAX) { p->st = ST_SOF; return P_ERR; }
        p->len = b; p->idx = 0; p->st = ST_DATA;
        return P_NONE;
    case ST_DATA:
        p->buf[p->idx++] = b;
        if (p->idx == p->len) p->st = ST_CRC_H;
        return P_NONE;
    case ST_CRC_H:
        p->crc_rx = (uint16_t)(b << 8); p->st = ST_CRC_L;
        return P_NONE;
    case ST_CRC_L: {
        p->crc_rx |= b; p->st = ST_SOF;
        uint16_t c = crc16_ccitt(&p->len, 1u, 0xFFFFu);
        c = crc16_ccitt(p->buf, p->len, c);
        return (c == p->crc_rx) ? P_FRAME : P_ERR;
    }
    }
    p->st = ST_SOF;
    return P_ERR;
}

CI 는 그것을 PR 마다 자동으로 돌리고 결과로 머지를 막습니다. 펌웨어 CI 에는 서버 CI 에 없는 항목이 둘 있습니다 — 크로스 컴파일(ARM 툴체인으로 실제 이미지 빌드)과 크기 감시(Flash 512 KB 는 늘릴 수 없습니다). 그리고 양산 이미지의 .elf · .map 보관은 t05 의 현장 덤프를 읽는 유일한 열쇠입니다. 정적 분석 규칙(MISRA · clang-tidy 검사 목록)은 대규모 C 구조 탭 k12 에 있고, 여기서는 그것을 CI 에 붙이는 실무만 다룹니다.

tools/size_diff.sh — 기준과 비교해 표 + 실패

#!/usr/bin/env bash
# 사용: size_diff.sh <기준.elf> <새.elf> <Flash 허용 증가 바이트>
set -euo pipefail
sz() { arm-none-eabi-size -B "$1" | awk 'NR==2 {print $1, $2, $3}'; }
read -r bt bd bb < <(sz "$1")
read -r nt nd nb < <(sz "$2")
bflash=$((bt + bd)); nflash=$((nt + nd))     # Flash = text + data
bram=$((bd + bb));   nram=$((nd + nb))       # RAM   = data + bss
dflash=$((nflash - bflash)); dram=$((nram - bram))

out="${GITHUB_STEP_SUMMARY:-/dev/stdout}"    # Actions 요약 페이지에 표
{
  echo "### 펌웨어 크기 (기준 → PR)"
  echo "| 영역 | 기준 | PR | 차이 |"
  echo "|---|---:|---:|---:|"
  echo "| Flash | $bflash | $nflash | $(printf '%+d' "$dflash") |"
  echo "| RAM | $bram | $nram | $(printf '%+d' "$dram") |"
} >> "$out"

if (( dflash > $3 )); then
  # ::error:: 는 stdout 으로 — 요약 파일이 아니라 로그에 써야 주석이 됨
  echo "::error title=Flash 크기::Flash 가 ${dflash} B 늘었습니다 (허용 $3 B)"
  exit 1
fi
### 펌웨어 크기 (기준 → PR)        ← 실제 출력 예
| 영역  | 기준  | PR    | 차이  |
| Flash | 25224 | 26560 | +1336 |
| RAM   | 10984 | 10992 | +8    |
::error title=Flash 크기::Flash 가 1336 B 늘었습니다 (허용 1024 B)
허용치는 0 이 아니라 "리뷰가 필요한 크기"로 — 기능을 넣으면 커지는 게 정상입니다. 실패는 "막는다"보다 "설명하라"는 신호입니다. 의도한 증가면 PR 라벨(size-ok)로 넘기는 조건을 둬도 됩니다.

# hil/conftest.py — 보드 하나를 pytest 픽스처로
import os
import subprocess
import time

import pytest
import serial
from serial.tools import list_ports

FW_ELF = os.environ.get("FW_ELF", "build-fw/fw.elf")
DUT_SERIAL = os.environ["DUT_SERIAL"]          # ST-LINK 일련번호 (보드 식별)
HUB_LOC, HUB_PORT = os.environ.get("HUB", "1-1:3").split(":")


def find_port(timeout=10.0):
    """ST-LINK 가상 COM 을 일련번호로 찾음 — 전원 사이클 뒤 재열거를 기다림"""
    end = time.monotonic() + timeout
    while time.monotonic() < end:
        for p in list_ports.comports():
            if p.vid == 0x0483 and p.serial_number == DUT_SERIAL:
                return p.device
        time.sleep(0.2)
    raise RuntimeError(f"DUT {DUT_SERIAL} 의 COM 포트가 안 보임")


class Dut:
    def __init__(self):
        self.ser = None

    def open(self):
        self.ser = serial.Serial(find_port(), 115200, timeout=0.5)
        self.ser.reset_input_buffer()             # 이전 실행의 찌꺼기 버림

    def close(self):
        if self.ser:
            self.ser.close()
            self.ser = None

    def wait_for(self, prefix, timeout=3.0):
        """prefix 로 시작하는 줄이 올 때까지 — sleep 으로 때우지 않음"""
        end = time.monotonic() + timeout
        while time.monotonic() < end:
            line = self.ser.readline().decode(errors="replace").strip()
            if line.startswith(prefix):
                return line
        raise TimeoutError(f"'{prefix}' 를 {timeout}s 안에 못 받음")

    def cmd(self, text, expect="", timeout=1.0):
        self.ser.reset_input_buffer()
        self.ser.write((text + "\n").encode())
        return self.wait_for(expect, timeout)

    def power_cycle(self):
        self.close()                              # 포트가 사라지기 전에 닫음
        subprocess.run(["uhubctl", "-l", HUB_LOC, "-p", HUB_PORT,
                        "-a", "cycle", "-d", "2"], check=True)
        self.open()                               # find_port 가 재열거를 기다림

/* F4 의 RCC_CSR 리셋 플래그. 읽고 나서 RMVF 로 지움.

static uint32_t s_csr;              /* 부팅 때 한 번 읽어 보관 */

void reset_cause_capture(void)
{
    s_csr = RCC->CSR;
    RCC->CSR |= RCC_CSR_RMVF;
}

const char *reset_cause_str(void)
{
    if (s_csr & RCC_CSR_LPWRRSTF) return "LPWR";
    if (s_csr & RCC_CSR_WWDGRSTF) return "WWDG";
    if (s_csr & RCC_CSR_IWDGRSTF) return "IWDG";
    if (s_csr & RCC_CSR_SFTRSTF)  return "SW";    /* NVIC_SystemReset */
    if (s_csr & RCC_CSR_PORRSTF)  return "POR";   /* 전원 켬 (BOR 도 같이 섬) */
    if (s_csr & RCC_CSR_BORRSTF)  return "BOR";   /* 전압 강하 */
    if (s_csr & RCC_CSR_PINRSTF)  return "PIN";   /* 리셋 버튼 · 디버거 */
