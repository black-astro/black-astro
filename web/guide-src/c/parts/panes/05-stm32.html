현업 STM32 펌웨어의 대부분은 STM32CubeMX 가 생성한 코드 + HAL 위에서 시작합니다. 클릭 몇 번이면 UART 가 돌고 DMA 가 붙습니다. 문제는 그다음입니다 — 재생성했더니 코드가 사라지고, ISR 에서 HAL_Delay 를 불렀더니 멈추고, DMA 버퍼가 깨지고, HardFault 가 납니다. 이 탭은 Nucleo-F446RE(Cortex-M4F, 180 MHz, Flash 512 KB, SRAM 128 KB) 하나를 기준으로 CubeMX 프로젝트를 실무 구조로 짜는 법, 클럭·GPIO·NVIC·UART·타이머·ADC·DMA·Flash 를 HAL 로 다루는 법, 그리고 HAL 아래(LL · CMSIS · 레지스터)에서 실제로 무슨 일이 일어나는지를 함께 봅니다. 이 탭을 마치면 CubeMX 프로젝트를 받아 구조를 읽고, 주변장치를 붙이고, HardFault 를 스스로 추적할 수 있게 됩니다.

STM32 와 Cortex-M — 시리즈 지도와 보드 고르기

"STM32" 는 칩 하나가 아니라 수천 개 품번의 가족입니다. 모두 ARM 의 Cortex-M 코어를 쓰고, ST 가 그 둘레에 주변장치(UART · 타이머 · ADC …)를 붙여 시리즈별로 성격을 나눴습니다. 서버로 치면 EC2 인스턴스 패밀리를 고르는 일과 같습니다 — 계산형(c), 메모리형(r), 범용(m)처럼 STM32 도 고성능(H7) · 저전력(L4/U5) · 모터 제어(G4) · 범용(F4/G0)으로 나뉩니다.

시리즈는 코어 + 주변장치 성격으로 나뉩니다 — 이 탭의 기준은 범용 고성능 F4 (F446RE) 입니다.

소프트웨어 계층 — 레지스터 · CMSIS · LL · HAL, 같은 LED 를 네 번 켭니다

STM32 코드는 네 가지 높이에서 쓸 수 있습니다. 맨 아래는 메모리 주소에 직접 값을 쓰는 것이고, 맨 위는 HAL 이라는 ST 의 공식 드라이버 라이브러리입니다. 서버로 치면 소켓을 직접 여는 것과 HTTP 클라이언트 라이브러리를 쓰는 것의 차이 — 위로 갈수록 편하고 이식성이 높지만 크고 느립니다. 실무 펌웨어는 대부분 HAL 로 시작하고, 시간이 빠듯한 곳만 LL 이나 레지스터로 내려갑니다.

레이어 스택 — 내려갈수록 작고 빠르고 칩에 묶입니다. 앱 층만큼은 칩을 모르게 짭니다.

① 레지스터 — 헤더 없이 주소에 직접

#include <stdint.h>
/* RM0390(F446 레퍼런스 매뉴얼)의 메모리 맵에서 주소를 직접 옮겨 적습니다 */
#define RCC_AHB1ENR (*(volatile uint32_t *)0x40023830u)  /* RCC 0x40023800 + 0x30 */
#define GPIOA_MODER (*(volatile uint32_t *)0x40020000u)  /* GPIOA + 0x00 */
#define GPIOA_ODR   (*(volatile uint32_t *)0x40020014u)  /* GPIOA + 0x14 */

int main(void)
{
    RCC_AHB1ENR |= (1u << 0);            /* bit0 GPIOAEN — 클럭부터 켠다 */
    (void)RCC_AHB1ENR;                   /* 한 번 읽어 클럭이 실제로 켜질 시간을 번다 */
    GPIOA_MODER = (GPIOA_MODER & ~(3u << (5 * 2)))
                |  (1u << (5 * 2));      /* PA5 의 2비트 = 01 (출력) */
    for (;;) {
        GPIOA_ODR ^= (1u << 5);          /* 읽고-바꾸고-쓰기 (원자적이지 않음) */
        for (volatile uint32_t i = 0; i < 500000u; i++) { }   /* 대충 기다리기 */
    }
}
volatile 이 빠지면 컴파일러가 "같은 주소에 두 번 쓰네?" 하고 앞의 쓰기를 지웁니다. 하드웨어 레지스터 포인터에는 반드시 붙입니다(volatile 자체는 C 실전 탭 c22 참고).

② CMSIS — 주소에 이름이 붙었을 뿐

#include "stm32f4xx.h"        /* -DSTM32F446xx 로 stm32f446xx.h 를 고름 */

int main(void)
{
    RCC->AHB1ENR |= RCC_AHB1ENR_GPIOAEN;
    __DSB();                                      /* 쓰기가 끝날 때까지 대기 */
    GPIOA->MODER = (GPIOA->MODER & ~GPIO_MODER_MODER5)
                 | GPIO_MODER_MODER5_0;           /* 01 = 출력 */
    for (;;) {
        GPIOA->BSRR = GPIO_BSRR_BS5;              /* 켜기 — 원자적 */
        for (volatile uint32_t i = 0; i < 500000u; i++) { }
        GPIOA->BSRR = GPIO_BSRR_BR5;              /* 끄기 — 원자적 */
        for (volatile uint32_t i = 0; i < 500000u; i++) { }
    }
}

GPIOA 는 ((GPIO_TypeDef *)GPIOA_BASE) 매크로이고, GPIO_TypeDef 는 MODER · OTYPER · OSPEEDR · PUPDR · IDR · ODR · BSRR · LCKR · AFR[2] 를 주소 순서대로 늘어놓은 구조체입니다. ①과 기계어가 사실상 같습니다. BSRR 은 아래 16비트에 1을 쓰면 켜지고 위 16비트에 1을 쓰면 꺼지는 레지스터라, 다른 핀을 건드리지 않고 한 번의 쓰기로 끝납니다(m05).

③ LL — 레지스터 한 줄을 인라인 함수 한 줄로

#include "stm32f4xx_ll_bus.h"
#include "stm32f4xx_ll_gpio.h"
#include "stm32f4xx_ll_utils.h"

int main(void)
{
    LL_Init1msTick(SystemCoreClock);     /* SysTick 을 1 ms 로 (인터럽트 없이 폴링용) */
    LL_AHB1_GRP1_EnableClock(LL_AHB1_GRP1_PERIPH_GPIOA);
    LL_GPIO_SetPinMode(GPIOA, LL_GPIO_PIN_5, LL_GPIO_MODE_OUTPUT);
    LL_GPIO_SetPinOutputType(GPIOA, LL_GPIO_PIN_5, LL_GPIO_OUTPUT_PUSHPULL);
    for (;;) {
        LL_GPIO_TogglePin(GPIOA, LL_GPIO_PIN_5);   /* 내부: ODR 읽고 BSRR 한 번 쓰기 */
        LL_mDelay(500);
    }
}

#include "main.h"                    /* stm32f4xx_hal.h 를 끌고 옴 */

int main(void)
{
    HAL_Init();                         /* SysTick 1 ms 인터럽트 · NVIC 그룹 설정 */
    SystemClock_Config();               /* 180 MHz (m04) */

    __HAL_RCC_GPIOA_CLK_ENABLE();

    g.Pin   = GPIO_PIN_5;
    g.Mode  = GPIO_MODE_OUTPUT_PP;
    g.Pull  = GPIO_NOPULL;
    g.Speed = GPIO_SPEED_FREQ_LOW;

        HAL_Delay(500);                 /* SysTick 이 올려 주는 uwTick 을 기다림 */

HAL_GPIO_TogglePin 의 실제 구현

/* STM32CubeF4 HAL (요즘 버전) — 요약 */
void HAL_GPIO_TogglePin(GPIO_TypeDef *GPIOx, uint16_t GPIO_Pin)
{
    uint32_t odr;
    assert_param(IS_GPIO_PIN(GPIO_Pin));      /* USE_FULL_ASSERT 일 때만 검사 */
    odr = GPIOx->ODR;
    /* 켜진 핀은 위 16비트(리셋)로, 꺼진 핀은 아래 16비트(셋)로 */
    GPIOx->BSRR = ((odr & GPIO_Pin) << GPIO_NUMBER) | (~odr & GPIO_Pin);
}
HAL 은 마법이 아닙니다 — 열어 보면 대부분 레지스터 몇 줄 + 검사입니다. Drivers/STM32F4xx_HAL_Driver/Src 의 소스를 읽는 습관이 HAL 함정(m13)을 피하는 가장 빠른 길입니다. 예전 버전은 ODR ^= Pin 이었는데, ISR 과 겹치면 다른 핀이 되돌아가는 문제가 있어 BSRR 방식으로 바뀌었습니다.

실무에선 이렇게 — 읽고-바꾸고-쓰기 경쟁 🔴 실무

❌ ODR 을 main 과 ISR 이 함께 고침
/* main */
GPIOA->ODR |= (1u << 5);   /* ① ODR 읽음 ── 여기서 인터럽트 ──┐  */
                            /* ③ 옛 값 | bit5 를 씀 → bit6 꺼짐!  */
/* ISR */
GPIOA->ODR |= (1u << 6);   /* ② bit6 켬                         */
✅ BSRR 한 번 쓰기 — 다른 비트는 안 건드림
/* main */

/* ISR */
GPIOA->BSRR = GPIO_BSRR_BS6;
같은 함정이 다른 레지스터에도 있습니다 — TIMx->DIER |= … 처럼 main 과 ISR 이 같은 레지스터를 읽고-바꾸고-쓰면 똑같이 깨집니다. BSRR 같은 "셋/리셋 전용" 레지스터가 없는 곳은 __disable_irq() / __enable_irq() 로 짧게 감싸거나, 한쪽에서만 쓰도록 설계합니다.
정리 — 레지스터 → CMSIS → LL → HAL 은 같은 레지스터 쓰기를 점점 두껍게 포장한 것입니다. 초기화와 일반 경로는 HAL, 마이크로초가 아까운 ISR 만 LL·레지스터로 내려가는 것이 실무의 기본 배합입니다.

CubeMX 프로젝트 해부 — 무엇이 생성되고, 무엇이 내 것인가

STM32CubeMX 는 핀 · 클럭 · 주변장치를 그림으로 고르면 초기화 코드를 생성해 주는 도구입니다. 스프링 이니셜라이저처럼 프로젝트 뼈대를 만들어 주는데, 결정적인 차이가 하나 있습니다 — 설정을 바꿀 때마다 다시 생성하고, 그때 정해진 영역 밖에 쓴 코드는 지워집니다. 그래서 "어느 파일이 누구 것인가"를 먼저 알아야 합니다.

트리 — 내 코드는 초록 자리(App/) 에 두고, 생성 파일에는 호출 한 줄만 남깁니다.

{

클럭 트리 — 16 MHz 를 180 MHz 로 만드는 법

칩 안의 모든 회로는 클럭(일정한 간격으로 0/1 을 반복하는 박자 신호)에 맞춰 움직입니다. 리셋 직후 F446 은 내부 발진기 HSI 16 MHz 로 돌고, 180 MHz 를 쓰려면 PLL(주파수를 곱해 주는 회로)을 거쳐야 합니다. UART 보레이트 · 타이머 주기 · ADC 속도가 전부 이 트리에서 갈라져 나오므로, 클럭을 모르면 m07~m09 의 계산이 하나도 맞지 않습니다.

트리 — 8 ÷ 4 × 180 ÷ 2 = 180 MHz. 버스마다 상한(APB1 45 · APB2 90)이 있어 다시 나눕니다.

계산을 손으로 확인하기

f_VCO_in  = f_HSE / PLLM       = 8 MHz / 4    = 2 MHz    (1~2 MHz, 2 권장)
f_VCO     = f_VCO_in × PLLN    = 2 × 180      = 360 MHz  (100~432 MHz)
f_SYSCLK  = f_VCO / PLLP       = 360 / 2      = 180 MHz  (PLLP = 2,4,6,8)
f_PLLQ    = f_VCO / PLLQ       = 360 / Q      → 48 MHz 를 만들 정수 Q 가 없음 (7.5)

HCLK  = SYSCLK / 1 = 180 MHz
PCLK1 = HCLK / 4   =  45 MHz   (APB1 상한 45)  → 타이머 ×2 = 90 MHz
PCLK2 = HCLK / 2   =  90 MHz   (APB2 상한 90)  → 타이머 ×2 = 180 MHz

HSI 로 시작한다면 PLLM = 8 (16 / 8 = 2 MHz), 나머지 동일
USB 가 필요하면 48 MHz 가 정확해야 합니다. 180 MHz 에서는 PLLQ 로 못 만들어서 F446 은 PLLSAI 로 48 MHz 를 따로 만듭니다(CubeMX 클럭 탭이 자동 계산). PLLQ 하나로 끝내고 싶다면 168 MHz(N=168 → VCO 336, P=2, Q=7 → 48 MHz)가 깔끔한 선택입니다.

RCC_HSE_BYPASS 와 RCC_HSE_ON 의 차이 — ON 은 칩이 크리스털을 직접 발진시키고, BYPASS 는 이미 만들어진 클럭 신호를 받기만 합니다. Nucleo 는 ST-LINK 가 8 MHz 를 만들어 주므로 BYPASS 입니다. 자체 보드에 크리스털을 달았는데 BYPASS 로 두면 HSE 가 안 떠서 HAL_RCC_OscConfig() 가 타임아웃으로 HAL_TIMEOUT 을 돌려줍니다.

SystemClock_Config — 한 줄씩 읽기 🟡 중급

CubeMX 가 생성하는 180 MHz 설정 (HSE 바이패스)

void SystemClock_Config(void)
{
  RCC_OscInitTypeDef RCC_OscInitStruct = {0};
  RCC_ClkInitTypeDef RCC_ClkInitStruct = {0};

  __HAL_RCC_PWR_CLK_ENABLE();                                  /* ① */
  __HAL_PWR_VOLTAGESCALING_CONFIG(PWR_REGULATOR_VOLTAGE_SCALE1);

  RCC_OscInitStruct.OscillatorType = RCC_OSCILLATORTYPE_HSE;   /* ② */
  RCC_OscInitStruct.HSEState       = RCC_HSE_BYPASS;
  RCC_OscInitStruct.PLL.PLLState   = RCC_PLL_ON;
  RCC_OscInitStruct.PLL.PLLSource  = RCC_PLLSOURCE_HSE;
  RCC_OscInitStruct.PLL.PLLM = 4;
  RCC_OscInitStruct.PLL.PLLN = 180;
  RCC_OscInitStruct.PLL.PLLP = RCC_PLLP_DIV2;
  RCC_OscInitStruct.PLL.PLLQ = 2;
  RCC_OscInitStruct.PLL.PLLR = 2;
  if (HAL_RCC_OscConfig(&RCC_OscInitStruct) != HAL_OK) Error_Handler();

  if (HAL_PWREx_EnableOverDrive() != HAL_OK) Error_Handler();  /* ③ */

  RCC_ClkInitStruct.ClockType = RCC_CLOCKTYPE_HCLK | RCC_CLOCKTYPE_SYSCLK
                              | RCC_CLOCKTYPE_PCLK1 | RCC_CLOCKTYPE_PCLK2;
  RCC_ClkInitStruct.SYSCLKSource   = RCC_SYSCLKSOURCE_PLLCLK; /* ④ */
  RCC_ClkInitStruct.AHBCLKDivider  = RCC_SYSCLK_DIV1;
  RCC_ClkInitStruct.APB1CLKDivider = RCC_HCLK_DIV4;
  RCC_ClkInitStruct.APB2CLKDivider = RCC_HCLK_DIV2;
  if (HAL_RCC_ClockConfig(&RCC_ClkInitStruct, FLASH_LATENCY_5) != HAL_OK)
    Error_Handler();                                           /* ⑤ */
}

번호별 해설

#무엇을 하나
①PWR 주변장치 클럭을 켜고 전압 스케일 1(가장 높은 코어 전압)로. 168 MHz 를 넘기려면 필수
②HSE 를 켜고 PLL 을 설정 · 기동. 내부에서 HSERDY · PLLRDY 플래그가 설 때까지 타임아웃을 두고 기다립니다
③오버드라이브 — 코어 전압을 한 단계 더 올리는 모드. 168 → 180 MHz 구간에 필요. 소비 전류가 늘어납니다
④SYSCLK 를 PLL 로 전환하고 버스 분주 설정
⑤Flash 대기 상태를 먼저 올리고 클럭을 올립니다(내릴 땐 반대 순서). 끝에 SystemCoreClock 갱신 + HAL_InitTick() 으로 SysTick 재설정
Error_Handler() 는 기본적으로 무한 루프입니다(__disable_irq(); while (1) {}). 보드가 "아무 반응이 없다"면 여기서 멈춰 있는 경우가 많습니다. USER CODE 영역에 LED 를 빠르게 깜빡이거나 __BKPT(0) 을 넣어 두면 디버거가 바로 그 자리에서 멈춥니다.

GPIO · EXTI — 핀 하나를 설정하는 레지스터 일곱 개와 외부 인터럽트

GPIO(범용 입출력)는 핀을 0 V / 3.3 V 로 내보내거나 읽는 가장 기본 주변장치입니다. F446 의 핀 하나는 입력 · 출력 · 대체 기능(UART 같은 주변장치에 넘김) · 아날로그 네 모드 중 하나이고, 이 선택이 레지스터 몇 개의 비트로 저장됩니다. 그 위에 EXTI 가 핀의 변화를 인터럽트로 바꿔 줍니다 — 폴링 대신 이벤트 리스너를 다는 것과 같습니다.

❌ 펜딩 레지스터에 |= — 다른 라인까지 지움

ISR 맨 끝에서 플래그를 지우면 두 번 들어옵니다 — 펜딩 비트를 지우는 쓰기가 주변장치 버스를 지나 실제로 반영되기 전에 ISR 이 끝나면, NVIC 가 아직 남은 펜딩을 보고 같은 인터럽트에 한 번 더 들어옵니다. HAL 처럼 ISR 앞쪽에서 지우거나, 끝에서 지웠다면 __DSB() 를 붙입니다.

정리 — GPIO 설정은 MODER · OTYPER · OSPEEDR · PUPDR 의 비트이고, 출력은 BSRR 로 원자적으로 씁니다. EXTI 는 핀 번호 = 라인 번호이며 10~15 는 IRQ 하나를 나눠 쓰고, 기계식 버튼은 반드시 디바운스합니다.
STM 06

NVIC · SysTick · HAL 콜백 — 누가 누구를 끊고 들어오는가

인터럽트는 "지금 하던 일을 잠깐 멈추고 이 함수를 실행하라"는 하드웨어의 요청입니다. NVIC(Nested Vectored Interrupt Controller)는 그 요청들의 우선순위를 매기고 끼어들기(선점)를 결정하는 교통정리 담당입니다. HAL 의 모든 비동기 기능(_IT · _DMA · 콜백 · HAL_Delay)이 이 위에서 돌기 때문에, 여기를 모르면 "가끔 멈춘다" 같은 버그를 영영 못 잡습니다.

타임라인 — 높은 우선순위는 낮은 것을 끊고 들어오고, 같거나 낮은 것은 끝날 때까지 기다립니다.

우선순위 숫자 — 4비트, 작을수록 높음

/* HAL_Init() 안에서 */
HAL_NVIC_SetPriorityGrouping(NVIC_PRIORITYGROUP_4);
/* 4비트 전부를 '선점 우선순위'로 → 0~15 단계, 서브 우선순위 없음 */

HAL_NVIC_SetPriority(TIM6_DAC_IRQn, 1, 0);    /* (IRQ, 선점, 서브) */
HAL_NVIC_SetPriority(EXTI15_10_IRQn, 5, 0);
HAL_NVIC_SetPriority(USART2_IRQn,    6, 0);
HAL_NVIC_EnableIRQ(TIM6_DAC_IRQn);

/* 레지스터로 보면 — IPR 은 8비트 칸인데 F4 는 위 4비트만 구현 */
/* NVIC 의 IP[EXTI15_10_IRQn] 칸에 실제로 들어간 값 = 0x50  (5 << (8 - __NVIC_PRIO_BITS)) */
"높은 우선순위 = 작은 숫자" 입니다. 리눅스 nice 값과 같은 방향이고, 직관과 반대라 실수가 잦습니다. Reset(-3) · NMI(-2) · HardFault(-1)는 고정이라 어떤 IRQ 보다 높습니다.

선점 · 서브 · 펜딩 — 용어 정리

용어뜻
선점 우선순위이 값이 더 작아야 실행 중인 ISR 을 끊을 수 있음
서브 우선순위선점이 같은 둘이 동시에 대기 중일 때 누가 먼저냐만 결정. 끊지는 못함
펜딩요청은 왔지만 아직 실행 못 함. 같은 IRQ 가 또 와도 1번으로 합쳐짐
꼬리 물기ISR 이 끝날 때 펜딩이 있으면 스레드로 돌아가지 않고 바로 다음 ISR 로 (레지스터 복원 생략)
지연 도착스택에 쌓는 중에 더 높은 것이 오면 그쪽을 먼저 실행
펜딩이 합쳐진다는 것이 중요합니다 — 같은 인터럽트가 처리 전에 세 번 오면 ISR 은 한 번만 돕니다. 그래서 "인터럽트 횟수 = 이벤트 횟수"로 세면 빠뜨립니다. UART 는 수신 레지스터가 1바이트라 늦으면 오버런(ORE) 이 납니다.

SysTick 과 HAL_Delay — ISR 에서 멈추는 이유 🟡 중급

시퀀스 — HAL_Delay 는 SysTick 이 uwTick 을 올려 줘야 끝나는 바쁜 대기입니다. 그 SysTick 을 막고 있으면 영원히 끝나지 않습니다.

HAL 의 시간 — 실제 구현

/* stm32f4xx_hal.c (요약) */
__IO uint32_t uwTick;

__weak void HAL_IncTick(void)  { uwTick += uwTickFreq; }  /* SysTick_Handler 가 1 ms 마다 */
__weak uint32_t HAL_GetTick(void) { return uwTick; }

__weak void HAL_Delay(uint32_t Delay)
{
  uint32_t tickstart = HAL_GetTick();
  uint32_t wait = Delay;
  if (wait < HAL_MAX_DELAY) {
    wait += (uint32_t)(uwTickFreq);      /* 최소 Delay ms 를 보장하려고 1 틱 더함 */
  }
  while ((HAL_GetTick() - tickstart) < wait) { }    /* 바쁜 대기 */
}
HAL_Delay(1) 은 1~2 ms 입니다 — 호출 시점이 틱 경계의 어디냐에 따라 달라서, 최소 1 ms 를 보장하려고 1 을 더합니다. 마이크로초 지연이 필요하면 DWT 사이클 카운터(DWT->CYCCNT, 180 MHz 에서 1 µs = 180 사이클)를 씁니다.

STM 07

UART + DMA + IDLE — 길이를 모르는 메시지를 놓치지 않고 받기

UART 는 선 두 개(TX · RX)로 바이트를 하나씩 보내는 가장 흔한 통신입니다(프로토콜 자체는 통신 탭에서 깊게). HAL 로 보내는 것은 쉽습니다. 어려운 것은 받기입니다 — 상대가 언제 몇 바이트를 보낼지 모르기 때문입니다. 이 절은 블로킹 → 인터럽트 → DMA 순서로 올라가서, 현업 표준인 순환 DMA + IDLE 감지 (HAL_UARTEx_ReceiveToIdle_DMA)로 끝납니다. 서버로 치면 소켓 recv 를 비동기 이벤트 루프로 바꾸는 과정입니다.

파형 — 바이트 사이가 한 프레임 이상 비면 IDLE. 이 하드웨어 신호가 가변 길이 수신의 열쇠입니다.

보내기 세 단계 — 블로킹 · IT · DMA

static const char hello[] = "hello\r\n";

/* ① 블로킹 — 다 보낼 때까지 CPU 가 기다림 (100 = 타임아웃 ms) */
HAL_UART_Transmit(&huart2, (const uint8_t *)hello, sizeof hello - 1, 100);

/* ② 인터럽트 — 즉시 리턴. 바이트마다 TXE 인터럽트로 한 바이트씩 */
HAL_UART_Transmit_IT(&huart2, (const uint8_t *)hello, sizeof hello - 1);

/* ③ DMA — 즉시 리턴. DMA 가 메모리 → USART2->DR 로 옮김, 끝나면 콜백 1번 */
HAL_UART_Transmit_DMA(&huart2, (const uint8_t *)hello, sizeof hello - 1);

void HAL_UART_TxCpltCallback(UART_HandleTypeDef *huart) { /* ②③ 완료 */ }

/* ②③ 은 이전 전송이 안 끝났으면 HAL_BUSY 를 돌려줌 — 반환값 확인 필수 */
if (HAL_UART_Transmit_DMA(&huart2, buf, n) == HAL_BUSY) { /* 큐에 쌓기 */ }
②③ 의 버퍼는 콜백이 올 때까지 살아 있어야 합니다. 함수 안 지역 배열을 넘기고 리턴하면 스택이 덮여 엉뚱한 바이트가 나갑니다(m10). 상수 문자열 · static · 전역 버퍼만 넘기세요.

#define RX_DMA_SZ 256u
static uint8_t  rx_dma[RX_DMA_SZ];   /* DMA 가 쓰는 곳 (전역 수명) */
static uint16_t rx_old;               /* 지난번 처리 끝 위치 */
static UART_HandleTypeDef *rx_uart;

extern void rx_push(const uint8_t *p, uint16_t n);   /* 앱 링 버퍼로 복사 */

void uart_rx_start(UART_HandleTypeDef *huart)
{
    rx_uart = huart;
    rx_old  = 0;
    HAL_UARTEx_ReceiveToIdle_DMA(huart, rx_dma, RX_DMA_SZ);
}

void HAL_UARTEx_RxEventCallback(UART_HandleTypeDef *huart, uint16_t Size)
{
    if (huart != rx_uart) return;
    uint16_t pos = Size;                         /* 1 .. RX_DMA_SZ */
    if (pos != rx_old) {
        if (pos > rx_old) {
            rx_push(&rx_dma[rx_old], pos - rx_old);
        } else {                                 /* 한 바퀴 돎 */
            rx_push(&rx_dma[rx_old], RX_DMA_SZ - rx_old);
            rx_push(&rx_dma[0], pos);
        }
        rx_old = pos;
    }
    if (rx_old == RX_DMA_SZ) rx_old = 0;         /* TC 로 끝까지 왔으면 처음으로 */
}

void HAL_UART_ErrorCallback(UART_HandleTypeDef *huart)
{
    if (huart != rx_uart) return;
    /* ORE 등으로 HAL 이 DMA 수신을 멈췄으면 다시 건다 */
    if (huart->RxState == HAL_UART_STATE_READY) uart_rx_start(huart);
}

타이머 — PWM · 입력 캡처 · 엔코더, 숫자 세 개로 시간을 만든다

STM32 타이머의 본질은 클럭을 세는 카운터입니다. 이 카운터 하나에 "몇 클럭마다 한 번 셀지(PSC)", "어디까지 세고 0 으로 돌아갈지(ARR)", "어느 값에서 무엇을 할지(CCR)" 세 숫자를 붙이면 LED 밝기 조절(PWM), 신호 주파수 측정(입력 캡처), 모터 회전 위치 읽기(엔코더)가 전부 됩니다. F446 에는 타이머가 14개 있고 기본 · 범용 · 고급(TIM1/TIM8) 세 등급으로 나뉩니다.

파형 — ARR 이 주기, CCR 이 켜진 길이입니다. CCR 만 바꾸면 주파수는 그대로 두고 밝기만 바뀝니다.

계산 — TIM2 (APB1 타이머 클럭 90 MHz)

f_PWM = f_TIM / ((PSC + 1) × (ARR + 1))
duty  = CCR / (ARR + 1)

LED 밝기   PSC 89 · ARR 999   → 90e6 / (90 × 1000)   = 1 kHz,  해상도 1000 단계
서보 모터  PSC 89 · ARR 19999 → 90e6 / (90 × 20000)  = 50 Hz,  CCR 1000~2000 = 1~2 ms
모터 구동  PSC 0  · ARR 4499  → 90e6 / (1 × 4500)    = 20 kHz, 해상도 4500 단계(≈12비트)

TIM1 · TIM8 (APB2 타이머 180 MHz) 로 20 kHz 면 ARR 8999 → 해상도 9000 단계
PSC 를 작게, ARR 을 크게 잡을수록 듀티 해상도가 좋아집니다. 같은 1 kHz 라도 PSC 899 · ARR 99 면 100 단계뿐입니다. 모터는 사람 귀에 들리지 않도록 20 kHz 이상으로 돌리는 게 보통입니다.

        for (int c = 0; c < NCH; c++) sum[c] += p[i * NCH + c];   /* [A0,A1,A2, A0,A1,A2, …] */
    for (int c = 0; c < NCH; c++) adc_mv[c] = (sum[c] / NSMP) * 3300u / 4095u;
}
포인터를 main 에서 읽는 시간도 마감 안에 있어야 합니다 — 50 ms 안에 adc_poll() 이 돌지 못하면 DMA 가 그 반쪽을 다시 덮어씁니다. 마감이 빠듯하면 콜백 안에서 합계만 계산해 두고 main 은 결과만 가져갑니다. HAL_ADC_Start_DMA 의 버퍼 인자가 uint32_t * 인 것은 HAL 의 역사적 시그니처일 뿐, DMA 폭은 CubeMX 의 Half Word 설정을 따릅니다.

/* ✅ 수명이 긴 버퍼 + 사용 중 표시 */

{

왜 32바이트 정렬인가 · 다른 해법

상황무슨 일이
버퍼가 줄 중간에서 시작Invalidate 가 같은 줄의 옆 변수까지 버려서, CPU 가 방금 쓴 그 변수 값이 사라짐
크기가 32 배수 아님끝 줄에서 같은 문제
MPU 로 비캐시 영역 지정DMA 버퍼 전용 구역을 캐시 안 되게 — Clean/Invalidate 불필요, 대신 CPU 접근이 느림
D-Cache 를 아예 끔문제는 사라지지만 M7 성능의 상당 부분을 버림
이 버그가 고약한 이유 — 디버거로 메모리를 보면 SRAM 의 값이 보여서 "정상"으로 보이고, printf 를 넣으면 캐시가 밀려나 증상이 사라집니다. F4 에서 잘 돌던 코드를 H7 으로 옮겼더니 "가끔" 깨진다면 1순위로 의심합니다.
F4 에서도 지킬 것 — 캐시가 없어도 컴파일러는 버퍼 값을 레지스터에 들고 있을 수 있습니다. 완료 플래그는 volatile 로, 플래그를 본 뒤 버퍼를 읽기 전에는 __DMB() 를 두면 순서가 보장됩니다.
정리 — DMA 버퍼는 전역 수명 · DMA 가 닿는 RAM · (M7 이면) 32 B 정렬 + Clean/Invalidate 세 조건을 지켜야 합니다. F4 는 요청별 스트림 표를 보고 충돌을 피해 배정하고, F446 에는 CCM 이 없어 RAM 위치 걱정은 덜합니다.

{
    HAL_StatusTypeDef st;
    uint32_t sector_err = 0;
    FLASH_EraseInitTypeDef er = {0};
    er.TypeErase    = FLASH_TYPEERASE_SECTORS;
    er.Sector       = FLASH_SECTOR_7;
    er.NbSectors    = 1;
    er.VoltageRange = FLASH_VOLTAGE_RANGE_3;   /* 2.7~3.6 V → 32비트 단위 */

    HAL_FLASH_Unlock();                         /* KEYR 에 키 두 개를 써서 잠금 해제 */
    __HAL_FLASH_CLEAR_FLAG(FLASH_FLAG_EOP | FLASH_FLAG_OPERR | FLASH_FLAG_WRPERR |
                           FLASH_FLAG_PGAERR | FLASH_FLAG_PGPERR | FLASH_FLAG_PGSERR);

    st = HAL_FLASHEx_Erase(&er, &sector_err);   /* 약 1 s — 그동안 CPU 멈춤 */
    for (uint32_t i = 0; st == HAL_OK && i < nwords; i++) {
        st = HAL_FLASH_Program(FLASH_TYPEPROGRAM_WORD, CFG_ADDR + 4u * i, data[i]);
    }
    HAL_FLASH_Lock();                           /* 반드시 다시 잠금 */
    return st;    /* 지우기 실패면 sector_err 에 실패 섹터 번호, 성공이면 0xFFFFFFFF */
}

    HAL_FLASH_Lock();
}
RDP 레벨 2 는 되돌릴 수 없습니다 — 디버그 포트가 영구히 닫혀 칩을 다시 굽지 못합니다. 레벨 1 → 0 으로 내리면 Flash 전체가 지워집니다. 실습 보드에서 RDP 를 건드리기 전에 양산 탭을 먼저 읽으세요.
정리 — F446 의 설정 저장은 섹터 지우기 → 워드 쓰기이고, 지우는 동안 CPU 가 멈춘다는 걸 설계에 넣어야 합니다. 저장 섹터는 링커에서 반드시 빼고, 두 섹터 교대 + CRC 로 정전에 대비합니다. 옵션 바이트의 RDP 는 양산 탭의 몫입니다.
STM 12

HardFault 첫 대응 — 무한 루프 대신 범인의 주소를 남긴다

HardFault 는 Cortex-M 의 "프로세스가 죽었다"입니다. 서버라면 코어 덤프와 스택 트레이스가 남지만, CubeMX 가 생성한 HardFault_Handler 는 그냥 무한 루프라 아무것도 남지 않습니다. 다행히 CPU 는 폴트 순간 레지스터 여덟 개를 스택에 쌓아 두고, 폴트 원인을 상태 레지스터(CFSR · HFSR)에 기록합니다. 이 절은 그 둘을 읽어 "어느 줄에서 왜"까지 가는 첫 대응을 다룹니다. 더 깊은 디버깅(GDB · 트레이스)은 디버깅 · 테스트 탭에서 이어집니다.

메모리 배치 — SP + 0x18 의 PC 하나만 꺼내도 범인 줄을 찾는 경우가 절반입니다.

덤프를 남기는 HardFault 핸들러

/* CubeMX: System Core → NVIC → Code generation 탭에서
   "Hard fault interrupt" 의 Generate IRQ handler 체크 해제 → 직접 정의 */
#include "main.h"

typedef struct { uint32_t r0, r1, r2, r3, r12, lr, pc, xpsr; } exc_frame_t;

typedef struct {
    exc_frame_t f;
    uint32_t cfsr, hfsr, mmfar, bfar, exc_return;
} fault_dump_t;

volatile fault_dump_t g_fault;    /* .noinit 에 두면 리셋 후에도 남김 (양산 탭) */

void hardfault_c(exc_frame_t *sf, uint32_t exc_return) __attribute__((used));

__attribute__((naked)) void HardFault_Handler(void)
{
    __asm volatile(
        "tst   lr, #4      \n"   /* EXC_RETURN 비트2: 0 = MSP, 1 = PSP */
        "ite   eq          \n"
        "mrseq r0, msp     \n"
        "mrsne r0, psp     \n"
        "mov   r1, lr      \n"
        "b     hardfault_c \n");
}

void hardfault_c(exc_frame_t *sf, uint32_t exc_return)
{
    g_fault.f          = *sf;
    g_fault.cfsr       = SCB->CFSR;
    g_fault.hfsr       = SCB->HFSR;
    g_fault.mmfar      = SCB->MMFAR;
    g_fault.bfar       = SCB->BFAR;
    g_fault.exc_return = exc_return;

    if (CoreDebug->DHCSR & CoreDebug_DHCSR_C_DEBUGEN_Msk) {
        __BKPT(0);               /* 디버거가 붙어 있을 때만 — 없으면 BKPT 가 또 폴트 */
    }
    NVIC_SystemReset();
}

IMPRECISERR — PC 가 거짓말을 하는 경우

Cortex-M4 는 쓰기를 버퍼에 맡기고 다음 명령으로 넘어갑니다. 그 쓰기가 나중에 실패하면 폴트가 몇 명령 뒤에 나서, 프레임의 PC 는 범인이 아니라 범인 근처를 가리킵니다. BFAR 도 유효하지 않습니다. 위 코드처럼 쓰기 버퍼를 끄고 재현하면 정확한 위치가 나옵니다.

디버거 없이도 정보를 남기려면 — 덤프 구조체를 링커의 .noinit 영역에 두고, 리셋 후 부팅 때 매직 값을 보고 UART 로 출력하거나 Flash 에 기록합니다. 현장 장비의 "가끔 리셋된다"를 잡는 유일한 방법입니다(양산 탭 · 디버깅 탭).
폴트 핸들러 안에서 HAL 을 부르지 마세요 — HAL_Delay 는 SysTick 이 못 돌아 멈추고(m06), HAL_UART_Transmit 의 타임아웃도 같은 SysTick 기반이라 작동하지 않습니다. 레지스터로 직접 한 바이트씩 내보내거나, 기록만 하고 리셋합니다.
정리 — HardFault 를 무한 루프로 두지 말고 스택 프레임 + CFSR · HFSR · BFAR · MMFAR 를 남기게 바꿉니다. PC 를 addr2line 에 넣고, CFSR 의 바이트로 종류를 좁히면 대부분의 원인은 표 안에 있습니다.
STM 13

저전력 · HAL 함정 모음 — 잠들 줄 알고, 멈추지 않는 펌웨어

펌웨어의 대부분 시간은 아무 일도 하지 않는 시간입니다. 그 시간에 CPU 를 재우면 배터리 수명이 몇 달에서 몇 년으로 바뀝니다. F446 은 Sleep · Stop · Standby 세 단계 잠을 지원하고, 깊이 잘수록 덜 먹지만 깨어나는 비용이 큽니다. 절의 뒷부분은 이 탭 전체에서 나온 HAL 함정을 실무 체크리스트로 묶습니다.

막대 — Run 과 Standby 는 만 배 차이입니다. 배터리 수명은 "얼마나 빨리 도나"보다 "얼마나 오래 자나"가 정합니다.
상태 기계 — Sleep · Stop 은 그 자리에서 이어서, Standby 는 리셋으로 다시 시작합니다. 깊을수록 깨는 조건이 좁아집니다.

/* Stop — 버튼(EXTI)이나 RTC 깨우기 타이머로 깨어남 */
void enter_stop(void)
{
    HAL_SuspendTick();
    HAL_PWREx_EnableFlashPowerDown();          /* Stop 중 Flash 도 끔 (깨기 약간 느려짐) */
    HAL_PWR_EnterSTOPMode(PWR_LOWPOWERREGULATOR_ON, PWR_STOPENTRY_WFI);
    /* ← 깨어나면 여기부터. 이때 SYSCLK = HSI 16 MHz! */
    SystemClock_Config();                      /* 180 MHz 로 복구 — 빠뜨리면 UART 가 깨짐 */
    HAL_ResumeTick();
}

/* Standby — 깨면 리셋. 부팅 때 원인 확인 */
void enter_standby(void)
{
    HAL_PWR_DisableWakeUpPin(PWR_WAKEUP_PIN1);
    __HAL_PWR_CLEAR_FLAG(PWR_FLAG_WU);         /* 남아 있으면 즉시 깨어남 */
    HAL_PWR_EnableWakeUpPin(PWR_WAKEUP_PIN1);  /* PA0 상승 엣지 */
    HAL_PWR_EnterSTANDBYMode();                /* 돌아오지 않음 */
}

/* main 초기화 직후 */
if (__HAL_PWR_GET_FLAG(PWR_FLAG_SB) != RESET) {
    __HAL_PWR_CLEAR_FLAG(PWR_FLAG_SB);         /* Standby 에서 깨어난 부팅 */
}

{
