전기 최소한 — 전압 · 전류 · 저항과 옴의 법칙

펌웨어 버그의 상당수는 코드가 아니라 전기에서 납니다. LED 가 안 켜지는 이유, 핀이 타 버리는 이유, 3.3 V 칩에 5 V 센서를 꽂으면 안 되는 이유 — 전부 이 섹션의 공식 세 개로 설명됩니다. 회로 이론을 배우자는 게 아니라 "이 핀에 무엇을 연결해도 되는가"를 스스로 판단할 수 있는 만큼만 다룹니다.

LED 저항 계산은 (전원 − LED 전압) ÷ 원하는 전류 한 줄입니다 — 계산값보다 큰 표준값을 고릅니다.

세 단어를 물에 빗대면

양단위물 비유펌웨어에서 만나는 곳

단위 감각 (이 세 개만 외우면 됩니다)
  1 mA  = 0.001 A        LED 하나 · 핀 하나는 mA 단위

서버 개발에 빗대면 — 전압은 요청을 보내는 압력, 전류는 초당 처리량, 저항은 레이트 리미터입니다. 리미터(저항) 없이 LED 를 핀에 바로 물리면, 처리량(전류)이 폭주해 서버(핀)와 클라이언트(LED)가 같이 죽습니다.

LED 저항 계산 — PC 에서 돌려 보는 정수 계산기

#include <stdio.h>
#include <stdint.h>

/* E12 표준 저항값의 가수 — 실제로 살 수 있는 값은 이것 × 10ⁿ 뿐 */
static const uint8_t E12[12] = {10,12,15,18,22,27,33,39,47,56,68,82};

/* ohm 이상인 가장 작은 표준값 — 전류가 목표를 '넘지 않게' 위로 올림 */
static uint32_t e12_ceil(uint32_t ohm) {
    for (uint32_t dec = 1; dec <= 100000u; dec *= 10u)
        for (int i = 0; i < 12; i++)
            if ((uint32_t)E12[i] * dec >= ohm) return (uint32_t)E12[i] * dec;
    return 0;                                   /* 10 MΩ 초과 — 범위 밖 */
}

/* mV 와 µA 로 받아 정수로만 계산: mV ÷ µA = kΩ 이므로 ×1000 */
static uint32_t led_r(uint32_t vcc_mv, uint32_t vf_mv, uint32_t i_ua) {
    if (vcc_mv <= vf_mv || i_ua == 0) return 0; /* 전원이 Vf 보다 낮으면 안 켜짐 */
    return (vcc_mv - vf_mv) * 1000u / i_ua;
}

int main(void) {
    uint32_t r  = led_r(5000, 2000, 10000);     /* 5 V · 적색 · 10 mA */
    uint32_t rs = e12_ceil(r);
    printf("계산 %lu Ω → 표준 %lu Ω, 실제 %lu µA\n",
           (unsigned long)r, (unsigned long)rs,
           (unsigned long)((5000u - 2000u) * 1000u / rs));
    return 0;   /* 출력: 계산 300 Ω → 표준 330 Ω, 실제 9090 µA */
}
표준값은 반드시 "위로" — 300 Ω 이 안 팔린다고 270 Ω 을 쓰면 전류가 11.1 mA 로 목표를 넘습니다. 330 Ω 이면 9.1 mA 로 살짝 어두워질 뿐 아무도 다치지 않습니다. 밝기 차이는 눈으로 거의 구분되지 않습니다.

전력 — 저항이 타는지, 배터리가 얼마나 가는지

저항이 먹는 전력  P = I² × R
  330 Ω, 9.1 mA  →  0.0091² × 330 ≈ 0.027 W = 27 mW
  흔한 저항 정격 1/4 W = 250 mW  →  9배 여유, 문제 없음

LED 가 먹는 전력  P = Vf × I = 2 × 0.0091 ≈ 18 mW

보드 전체 대략 (5 V 로 50 mA 를 쓴다면)
  P = 5 × 0.05 = 0.25 W

배터리 수명 감 잡기 (조정기 손실은 무시한 거친 추정)
  2000 mAh ÷ 50 mA = 40 시간
  2000 mAh ÷ 0.05 mA(슬립 50 µA) = 40,000 시간 ≈ 4.5 년
  → 펌웨어가 "얼마나 자주 잠드는가"가 수명을 1000배 바꿉니다
펌웨어 개발자에게 전력이 중요한 이유 — 배터리 제품에서 전류의 대부분은 CPU 가 깨어 있는 시간에 씁니다. 인터럽트(HW 08)로 깨어나 일하고 다시 자는 구조가 곧 배터리 수명입니다. 저전력 설계는 🚀 양산 탭에서 계산까지 다룹니다.

바운스는 버그가 아니라 물리입니다 — 엣지를 세지 말고 일정 시간 안정된 값을 세세요(코드는 HW 13).

플로팅 입력과 풀업 — 두 칩에서 같은 일을 하는 코드

/* 아무것도 안 꽂은 입력 핀 = '플로팅(떠 있음)'
   주변 전기 잡음·손가락만 대도 0 과 1 을 오락가락합니다.
   → 저항으로 한쪽에 '살짝' 묶어 둡니다 = 풀업(HIGH 쪽) / 풀다운(LOW 쪽) */

/* ── ATmega328P : Uno D2 = PD2, 버튼은 PD2 ↔ GND ── */
#include <avr/io.h>
DDRD  &= ~(1 << DDD2);     /* 방향 = 입력 */
PORTD |=  (1 << PORTD2);   /* 입력일 때 PORT 에 1 = 내부 풀업 켬 (20~50 kΩ) */
uint8_t pressed = !(PIND & (1 << PIND2));   /* 눌리면 GND 에 붙어 0 */

/* ── STM32F446RE : PB4 를 같은 용도로 (CMSIS 헤더) ── */
#include "stm32f446xx.h"
RCC->AHB1ENR |= RCC_AHB1ENR_GPIOBEN;                 /* 클럭 먼저 (HW 07) */
GPIOB->MODER &= ~(3u << (4 * 2));                    /* 00 = 입력 */
GPIOB->PUPDR  = (GPIOB->PUPDR & ~(3u << (4 * 2)))
              | (1u << (4 * 2));                     /* 01 = 풀업 (약 40 kΩ) */
uint32_t pressed2 = !(GPIOB->IDR & (1u << 4));
버튼은 왜 GND 쪽에 다나 — 풀업 + "누르면 GND" 구성이 업계 기본입니다. 선이 끊기거나 버튼이 빠져도 안전한 HIGH(안 눌림)로 읽히고, 모든 칩이 내부 풀업은 갖고 있지만 내부 풀다운은 없는 경우(AVR)가 많기 때문입니다. 대신 눌림 = 0 이라 논리가 뒤집힙니다(active-low).

"절대 최대"는 설계 목표가 아닙니다 — 그 값에서 칩이 즉시 죽지 않는다는 뜻일 뿐, 수명과 출력 전압은 보장되지 않습니다. 실무 기준은 "전기적 특성(Electrical Characteristics)" 표의 시험 조건(위 20 mA·8 mA)입니다. 그보다 많이 끌면 HIGH 가 3.3 V 가 아니라 2.6 V 로 처집니다.

5 V 톨러런트(FT)와 레벨 시프트

STM32 데이터시트의 핀 표(Pinouts and pin description)에 'I/O 구조' 열이 있습니다
  FT   5 V 를 견디는 핀 (5V tolerant)        ← 대부분의 GPIO
  TT   3.3 V 까지만 (아날로그 겸용 등)       ← 예: PA4 · PA5 는 DAC 겸용이라 TTa
  주의: FT 라도 '아날로그 모드'로 설정하면 5 V 를 견디지 못합니다
        FT 는 '입력으로 받을 수 있다'일 뿐, 5 V 를 '출력'하지는 못합니다

레벨이 다른 두 칩을 잇는 방법
  ① 3.3 V → 5 V 입력        AVR 은 3.0 V 이상을 HIGH 로 봄 → 직결해도 대개 동작
  ② 5 V → 3.3 V (FT 아님)    저항 분배 (예 1.8k / 3.3k) — 단방향·저속만
  ③ 양방향 (I²C 등)          MOSFET 레벨 시프터 (BSS138 모듈)
  ④ 빠른 단방향 다채널       74LVC 계열 버퍼 / 전용 레벨 변환 IC
Nucleo 의 LD2 가 PA5 인 이유를 생각해 보면 — PA5 는 5 V 를 못 견디는 핀이지만 LED 출력에는 상관없습니다. 입력으로 5 V 를 받을 핀은 반드시 표에서 FT 를 확인하세요. "옆 핀은 됐는데 이 핀만 죽었다"의 원인이 이것입니다.

}
/* 문제: 손을 '뗄 때'의 바운스도 하강 엣지를 만들 수 있고,
   노이즈 한 번에도 반응합니다 — 확정이 아니라 '첫 엣지'를 믿는 방식 */
✅ 주기적 샘플링 + 연속 N 회 일치
/* 1 ms 마다 호출 (타이머 ISR 이나 메인 루프의 1 ms 틱에서) */
#include <stdbool.h>
#include <stdint.h>

bool button_pressed_event(bool raw_pressed) {
    static bool    stable = false;   /* 확정된 상태 */
    static uint8_t cnt    = 0;

    if (raw_pressed == stable) { cnt = 0; return false; }
    if (++cnt < 20) return false;    /* 20 ms 연속으로 달라야 인정 */
    stable = raw_pressed;
    cnt = 0;
    return stable;                   /* '안 눌림 → 눌림' 순간만 true */
}
왜 이게 표준인가 — 노이즈 한 번은 카운터를 0 으로 되돌릴 뿐이고, 누를 때와 뗄 때를 똑같이 처리하며, 인터럽트가 필요 없습니다. 하드웨어로 막으려면 버튼에 RC 필터(10 kΩ + 100 nF ≈ 1 ms) 를 달고 슈미트 트리거 입력을 씁니다 — 둘 다 하는 제품도 많습니다.
정리 — 입력은 풀업으로 묶어 두고(누르면 0), 출력은 신호용(수 mA)으로만 쓰며, 5 V 를 받을 3.3 V 칩 핀은 FT 인지 확인합니다. 버튼은 반드시 튀므로 "N ms 동안 같은 값"일 때만 믿습니다.
HW 03

MCU 안을 들여다보기 — 코어 · 메모리 · 버스 · 주변장치

마이크로컨트롤러(MCU)는 CPU · 메모리 · 입출력 장치를 칩 하나에 몰아넣은 작은 컴퓨터입니다. PC 와 같은 부품 목록인데 크기가 1/100,000 이고, 운영체제가 대신 해 주던 일이 전부 빠져 있습니다. 그 빈자리가 곧 펌웨어 개발자의 일입니다.

MCU 는 코어 + 메모리 + 주변장치이고, 코어 입장에서 주변장치는 "특별한 주소의 메모리"일 뿐입니다 — 이것이 HW 04 의 출발점.

   에러 메시지 없이 '가끔 값이 이상해지는' 버그가 됩니다 (HW 12). */
Flash 는 읽기 전용이 아니라 "쓰기가 느리고 횟수 제한이 있는" 메모리입니다. 페이지/섹터 단위로 지우고 다시 써야 하고 수명은 1만~10만 회 정도라, 설정값 저장은 🚀 양산 탭에서 따로 다룹니다.

PC 와 무엇이 다른가 — 없는 것들의 목록 🟡 중급

MCU 에는 세그폴트가 없습니다 — 잘못된 쓰기는 멈추지 않고 다른 무언가를 조용히 바꿉니다. 그래서 정적 할당과 경계 검사가 기본입니다.

하버드 vs 폰 노이만 — AVR 에서 실제로 문제가 되는 곳

/* AVR 은 '하버드' — Flash 와 SRAM 이 서로 다른 주소 공간입니다.
   주소 0x0100 이 Flash 의 0x0100 인지 SRAM 의 0x0100 인지 포인터만 봐서는 모름.
   그래서 const 문자열도 기본으로는 시작할 때 SRAM 으로 '복사'됩니다. */

const char help[] = "usage: led on|off|blink <ms>\r\n";  /* SRAM 31 바이트 소모! */

/* 해결: Flash 에 두고 전용 명령으로 읽기 */
#include <avr/pgmspace.h>
const char help_P[] PROGMEM = "usage: led on|off|blink <ms>\r\n";

void uart_puts_P(const char *s) {          /* s 는 'Flash 주소' */
    char c;
    while ((c = (char)pgm_read_byte(s++)) != '\0')
        uart_putc(c);
}

/* STM32(Cortex-M)는 주소 공간이 하나라 const 면 그냥 Flash 에 남고
   보통 포인터로 바로 읽힙니다 — PROGMEM 같은 것이 필요 없습니다. */
Cortex-M 은 "수정된 하버드"입니다 — 명령과 데이터를 다른 버스(I-Code · D-Code · System)로 동시에 가져와 속도를 얻되, 주소는 4 GB 하나로 통일했습니다. 프로그래머는 폰 노이만처럼 쓰고, 하드웨어는 하버드처럼 달립니다.

칩이 스스로를 소개하게 하기 (STM32F446)

#include <stdint.h>

/* 칩마다 정해진 주소에 정보가 박혀 있습니다 (레퍼런스 매뉴얼 기재) */
#define DBGMCU_IDCODE  (*(volatile const uint32_t *)0xE0042000u)
#define FLASH_SIZE_KB  (*(volatile const uint16_t *)0x1FFF7A22u)
#define UID_BASE_ADDR  ((volatile const uint32_t *)0x1FFF7A10u)

void chip_info(void) {
    uint32_t dev_id = DBGMCU_IDCODE & 0x0FFFu;   /* F446 은 0x421 */
    uint32_t rev_id = DBGMCU_IDCODE >> 16;       /* 실리콘 리비전 */
    uint16_t kb     = FLASH_SIZE_KB;             /* RE 면 512 */
    uint32_t uid0   = UID_BASE_ADDR[0];          /* 칩마다 다른 96비트 ID */
    (void)dev_id; (void)rev_id; (void)kb; (void)uid0;
}
고유 ID(UID)는 양산에서 시리얼 번호·암호 키 파생에 그대로 씁니다. 리비전 ID 는 에라타(HW 06)에서 "이 버그는 Rev A 에만"을 확인할 때 봅니다. AVR 은 시그니처 바이트 3개(0x1E 0x95 0x0F)를 프로그래머(avrdude)가 읽어 칩을 확인합니다.

HW 04

메모리 맵과 레지스터 — 주소에 값을 쓰면 핀이 움직인다

임베디드 C 의 가장 큰 깨달음은 이것 하나입니다: 주변장치를 조작하는 특별한 명령은 없습니다. 칩 설계자가 어떤 주소들을 메모리 대신 하드웨어 스위치에 연결해 두었고, 우리는 포인터로 그 주소에 숫자를 쓸 뿐입니다. 이 연결표가 메모리 맵이고, 스위치 한 묶음(보통 32비트)이 레지스터입니다.

주변장치는 메모리 맵 위의 한 구간이고, 레지스터는 그 안의 "베이스 주소 + 오프셋"입니다 — 주소는 전부 레퍼런스 매뉴얼에 있습니다.

방법 ① 주소를 직접 — 원리가 그대로 보이는 형태

#include <stdint.h>

/* "0x40020014 번지를 32비트 부호 없는 정수로 보고, 거기에 써라" */
#define GPIOA_ODR  (*(volatile uint32_t *)0x40020014u)

void led_on(void) {
    GPIOA_ODR |= (1u << 5);       /* PA5 = HIGH → Nucleo 의 LD2 켜짐 */
}

/* 한 겹씩 벗겨 보면
   0x40020014u                     그냥 정수
   (volatile uint32_t *)0x40020014u 그 정수를 '포인터'로 해석
   *(…)                            그 포인터가 가리키는 곳 = 레지스터 자체
   → 변수처럼 읽고 쓸 수 있는 lvalue 가 됩니다 */

/* ATmega328P 도 똑같습니다 — avr/io.h 가 이렇게 정의해 둡니다 */
#define MY_PORTB  (*(volatile uint8_t *)0x25)   /* I/O 주소 0x05 + 0x20 */
/* MY_PORTB |= (1 << 5);  → Uno 의 D13(PB5) LED 켜짐 */
AVR 주소에 0x20 이 더해지는 이유 — AVR 데이터 공간은 0x00~0x1F 가 CPU 레지스터 r0~r31 이라, I/O 레지스터는 그 뒤 0x20 부터 놓입니다. 데이터시트 표는 I/O 주소(0x05)와 메모리 주소(0x25)를 둘 다 적어 둡니다.

방법 ② 구조체로 덮어씌우기 — CMSIS 가 쓰는 방식

#include <stdint.h>
#include <stddef.h>

/* 레지스터 순서와 간격(4바이트)을 구조체 멤버로 그대로 옮김 */
typedef struct {
    volatile uint32_t MODER;    /* 0x00 */
    volatile uint32_t OTYPER;   /* 0x04 */
    volatile uint32_t OSPEEDR;  /* 0x08 */
    volatile uint32_t PUPDR;    /* 0x0C */
    volatile uint32_t IDR;      /* 0x10 */
    volatile uint32_t ODR;      /* 0x14 */
    volatile uint32_t BSRR;     /* 0x18 */
    volatile uint32_t LCKR;     /* 0x1C */
    volatile uint32_t AFR[2];   /* 0x20 · 0x24 — 대체 기능 선택 */

실무에서는 직접 만들지 않습니다 — ST 가 배포하는 stm32f446xx.h(CMSIS 디바이스 헤더)에 GPIO_TypeDef · GPIOA · RCC_AHB1ENR_GPIOAEN 같은 이름이 수천 개 정의돼 있습니다. 거기서 volatile 은 __IO 라는 매크로로 보입니다.

volatile 이 왜 필수인가 — 최적화가 지워 버리는 코드 🟡 중급

volatile 의 정의와 "원자성은 아니다"라는 점은 C 실전 탭 c22 에 있습니다. 여기서는 레지스터에서 실제로 무엇이 사라지는지를 기계어 수준에서 봅니다.

❌ volatile 을 빠뜨린 대기 루프

void wait_tx_empty(void) {

  #define PINB   _SFR_IO8(0x03)     → 0x23
디버거에서 이 숫자들이 그대로 보입니다 — 메모리 창에 0x40020014 를 치면 ODR 값이 뜨고, 거기에 0x20 을 써 넣으면 코드 없이 LED 가 켜집니다. "레지스터 = 주소"를 몸으로 확인하는 가장 빠른 실험입니다(🐞 디버깅 탭).
정리 — 레지스터 접근은 *(volatile uint32_t *)주소 가 전부이고, CMSIS 의 GPIOA->ODR 은 같은 것을 구조체로 예쁘게 쓴 것입니다. volatile 을 빠뜨리면 -O2 에서 대기 루프가 멈추고 지연 루프가 사라집니다 — 레지스터와 ISR 공유 변수에는 예외 없이 붙입니다.
HW 05

비트 조작 — 마스크 · 시프트 · 원자적 쓰기

레지스터 하나에는 서로 다른 스위치가 수십 개 들어 있습니다. 그중 하나만 바꾸고 나머지는 그대로 두는 것이 펌웨어 코드의 절반입니다. 기본 매크로는 C 실전 탭 c22 에 있으니, 여기서는 여러 비트짜리 필드, 읽기-수정-쓰기가 인터럽트와 부딪히는 순간, 그리고 그것을 하드웨어가 해결해 주는 레지스터를 봅니다.

여러 비트 필드는 OR 만으로는 못 씁니다 — 10 에 01 을 OR 하면 11 이 됩니다. 반드시 마스크로 지우고 → 넣기.

필드 쓰기를 함수 하나로

#include <stdint.h>

/* reg 의 [shift, shift+width) 구간에 val 을 넣는다 */
static inline void reg_field(volatile uint32_t *reg,
                             uint32_t shift, uint32_t width, uint32_t val) {
    uint32_t mask = ((width >= 32u) ? 0xFFFFFFFFu : ((1u << width) - 1u)) << shift;
    *reg = (*reg & ~mask) | ((val << shift) & mask);    /* 읽기 → 지우기 → 넣기 → 쓰기 */
}

/* 사용 — 숫자로 말하면 레퍼런스 매뉴얼과 1:1 로 대조됩니다 */
reg_field(&GPIOA->MODER,  5 * 2, 2, 0x1);   /* PA5  = 출력        */
reg_field(&GPIOA->MODER,  2 * 2, 2, 0x2);   /* PA2  = 대체 기능    */
reg_field(&GPIOA->AFR[0], 2 * 4, 4, 7);     /* PA2  = AF7 (USART2_TX) */

/* CMSIS 헤더의 같은 일 — 이름이 붙은 _Msk / _Pos 와 MODIFY_REG 매크로 */
MODIFY_REG(GPIOA->MODER, GPIO_MODER_MODER5_Msk, 1u << GPIO_MODER_MODER5_Pos);
1u 의 u 가 중요합니다 — 1 << 31 은 부호 있는 int 를 넘쳐 미정의 동작이고, AVR 에서는 int 가 16비트라 1 << 15 는 음수, 1 << 16 은 미정의 동작입니다. AVR 의 32비트 레지스터 값은 1UL << n 으로 씁니다.

★ ATmega328P 의 숨은 기능 — 입력 레지스터 PINx 에 1 을 쓰면 그 비트의 출력이 뒤집힙니다. 읽기-수정-쓰기 없이 한 번의 쓰기라 원자적입니다. STM32 의 BSRR 은 아래 16비트가 "켜기", 위 16비트가 "끄기"이고 0 을 쓴 비트는 아무 일도 하지 않습니다 — 그래서 다른 핀을 건드릴 걱정이 없습니다.

읽기-수정-쓰기와 인터럽트 — 비트 하나가 사라지는 순간 🔴 고급

레이스는 스레드가 없어도 생깁니다 — main 과 ISR 이 같은 레지스터를 RMW 하면 가끔 비트가 사라집니다.

고치는 세 가지 방법

/* ① 원자적 레지스터를 쓴다 (가장 좋음) */
GPIOA->BSRR = (1u << 5);            /* PA5 켜기 — 쓰기 한 번 */
GPIOA->BSRR = (1u << (5 + 16));     /* PA5 끄기 */

/* ② 잠깐 인터럽트를 막는다 — 이전 상태를 저장했다가 되돌림 (CMSIS) */
uint32_t primask = __get_PRIMASK();
__disable_irq();
GPIOA->ODR ^= (1u << 5);            /* 이 사이엔 ISR 이 끼지 못함 */
__set_PRIMASK(primask);             /* 원래 꺼져 있었다면 꺼진 채로 */

/* ③ AVR — avr-libc 의 원자 블록 */
#include <util/atomic.h>
ATOMIC_BLOCK(ATOMIC_RESTORESTATE) {
    TIMSK1 |= (1 << OCIE1A);        /* 아래 표 참고 — 이건 RMW 가 맞음 */
}
__enable_irq() 로 무조건 켜지 마세요 — 호출한 쪽이 이미 인터럽트를 꺼 둔 상태였다면 그 의도를 깨뜨립니다. "저장 → 끄기 → 되돌리기"가 표준 형태이고, 막는 구간은 수 마이크로초 이내로 짧게 둡니다.

AVR 은 어디까지 원자적인가

C 코드기계어원자적?
PORTB |= (1<<5)sbi 0x05,5예 — 명령 1개
PORTB |= 0x30 (비트 2개)in · ori · out아니오
TIMSK1 |= (1<<OCIE1A)lds · ori · sts아니오 — 주소 0x6F
PINB = (1<<5)ldi · out예 — 쓰기뿐
uint16_t 변수 읽기lds · lds아니오 — 8비트 CPU
sbi/cbi(비트 하나 세트/클리어) 명령은 I/O 주소 0x00~0x1F 레지스터에만 쓸 수 있습니다. 그 밖의 레지스터나 비트 여러 개는 컴파일러가 세 명령으로 풀어 RMW 가 됩니다. "AVR 은 한 줄이면 원자적"이라고 일반화하면 안 됩니다.

한 단계 더 — 비트밴딩과 "쓰면 지워지는" 비트 🧬 전문가

Cortex-M4 비트밴딩 — 비트 하나를 워드 하나로

/* 주변장치 영역 0x4000 0000~0x400F FFFF 의 비트마다
   0x4200 0000 부터 '별칭 워드'가 하나씩 있습니다.
   별칭 주소 = 0x42000000 + (바이트 오프셋 × 32) + (비트 번호 × 4) */
#define BITBAND_PERI(addr, bit) \
    (*(volatile uint32_t *)(0x42000000u + (((uint32_t)(addr) - 0x40000000u) * 32u) + ((bit) * 4u)))

/* GPIOA->ODR(0x40020014) 의 5번 비트 → 0x42400294 */
BITBAND_PERI(&GPIOA->ODR, 5) = 1;    /* 하드웨어가 원자적으로 그 비트만 바꿈 */
Cortex-M3/M4 의 선택 기능이라 M0+·M7·M33 에는 없습니다. 이식성이 떨어져 요즘은 BSRR 같은 전용 레지스터나 짧은 임계 구역을 더 많이 씁니다.

"1 을 써서 지우는" 플래그를 |= 로 다루면

/* EXTI->PR 은 rc_w1: 읽으면 '대기 중'인 비트가 1, 1 을 쓰면 그 비트가 지워짐 */

EXTI->PR |= EXTI_PR_PR13;   /* ❌ 읽은 값에 1 인 다른 비트(PR0 등)까지 다시 써서 */
                            /*    아직 처리 안 한 다른 인터럽트까지 지워 버림 */
EXTI->PR  = EXTI_PR_PR13;   /* ✅ 13번만 지움 — 0 을 쓴 비트는 그대로 */

/* AVR 의 인터럽트 플래그도 같은 규칙 (1 을 써서 지움) */
TIFR1 = (1 << OCF1A);       /* ✅ */

/* 반대로 TIMx->SR 은 rc_w0: 0 을 써야 지워지고 1 은 무시 */
TIM2->SR = ~TIM_SR_UIF;     /* ✅ UIF 만 0 으로, 나머지는 1(=무시) */
정리 — 한 비트는 |= · &= ~ · ^= · &, 여러 비트 필드는 지우고 → 넣기. main 과 ISR 이 같은 레지스터를 고치면 RMW 레이스가 나므로 BSRR 같은 원자적 레지스터를 먼저 찾고, 없으면 짧은 임계 구역으로 감쌉니다. "1 을 써서 지우는" 플래그는 |= 가 아니라 =.

클럭 — 모든 것의 박자, 그리고 초보 1순위 버그

MCU 안의 모든 블록은 클럭(일정한 박자의 사각파)에 맞춰 움직입니다. 클럭은 속도를 정하고, 타이머·UART 보레이트의 기준이 되며, 무엇보다 켜지 않은 장치는 아예 동작하지 않습니다. "레지스터에 썼는데 읽어 보면 0" — 처음 STM32 를 만지는 사람의 첫 사흘을 잡아먹는 버그가 여기 있습니다.

클럭 트리는 원천 → PLL → 버스별 분주이고, 장치마다 게이트 스위치가 하나씩 있습니다 — 기본은 전부 꺼짐(STM32).

PLL 계산 — 식 하나

f_VCO_in = f_src ÷ M        1~2 MHz 여야 함 (2 MHz 권장 — 지터 적음)
f_VCO    = f_VCO_in × N      100~432 MHz 범위
SYSCLK   = f_VCO ÷ P         P ∈ {2, 4, 6, 8}

HSI 16 MHz 로 180 MHz 만들기
  M = 8    → 16 ÷ 8   = 2 MHz      ✓
  N = 180  → 2 × 180  = 360 MHz    ✓ (100~432)
  P = 2    → 360 ÷ 2  = 180 MHz    ✓ (F446 최대)

버스
  AHB  ÷1 → 180 MHz
  APB1 ÷4 →  45 MHz  (최대 45)    APB1 타이머 = 2 × 45 = 90 MHz
  APB2 ÷2 →  90 MHz  (최대 90)    APB2 타이머 = 2 × 90 = 180 MHz

레지스터로 180 MHz 올리기 — 순서가 전부입니다 🔴 고급

#include "stm32f446xx.h"

void clock_180mhz_from_hsi(void) {
    /* ① 전원부: 전압 스케일 1 (PLL 을 켜기 전에) */
    RCC->APB1ENR |= RCC_APB1ENR_PWREN;
    (void)RCC->APB1ENR;
    PWR->CR |= PWR_CR_VOS;                          /* VOS = 11 */

    /* ② PLL: 원천 HSI, M=8, N=180, P=2 (PLLP 비트 00) — 다른 필드(Q·R)는 유지 */
    RCC->PLLCFGR = (RCC->PLLCFGR & ~(RCC_PLLCFGR_PLLM | RCC_PLLCFGR_PLLN |
                                     RCC_PLLCFGR_PLLP | RCC_PLLCFGR_PLLSRC))
                 | (8u   << RCC_PLLCFGR_PLLM_Pos)
                 | (180u << RCC_PLLCFGR_PLLN_Pos);
    RCC->CR |= RCC_CR_PLLON;
    while (!(RCC->CR & RCC_CR_PLLRDY)) { }          /* PLL 이 잠길 때까지 */

    /* ③ 180 MHz 는 오버드라이브가 있어야 허용 */
    PWR->CR |= PWR_CR_ODEN;
    while (!(PWR->CSR & PWR_CSR_ODRDY)) { }
    PWR->CR |= PWR_CR_ODSWEN;
    while (!(PWR->CSR & PWR_CSR_ODSWRDY)) { }

    /* ④ Flash 가 180 MHz 를 못 따라오므로 대기 5 클럭 + 가속기 켬 — 클럭 올리기 '전에' ★ */
    FLASH->ACR = FLASH_ACR_LATENCY_5WS | FLASH_ACR_PRFTEN | FLASH_ACR_ICEN | FLASH_ACR_DCEN;

    /* ⑤ 버스 분주: AHB ÷1, APB1 ÷4, APB2 ÷2 */
    RCC->CFGR = (RCC->CFGR & ~(RCC_CFGR_HPRE | RCC_CFGR_PPRE1 | RCC_CFGR_PPRE2))
              | RCC_CFGR_PPRE1_DIV4 | RCC_CFGR_PPRE2_DIV2;

    /* ⑥ 시스템 클럭을 PLL 로 전환하고 실제로 바뀌었는지 확인 */
    RCC->CFGR = (RCC->CFGR & ~RCC_CFGR_SW) | RCC_CFGR_SW_PLL;
    while ((RCC->CFGR & RCC_CFGR_SWS) != RCC_CFGR_SWS_PLL) { }

    SystemCoreClock = 180000000u;                   /* CMSIS 전역 — SysTick 계산이 이걸 봄 */
}
④ 와 ⑥ 의 순서를 바꾸면 — 180 MHz 로 먼저 올라간 CPU 가 대기 0 클럭으로 Flash 를 읽다가 엉뚱한 명령을 실행하고 HardFault 로 갑니다. 실무에서는 CubeMX 가 이 코드를 SystemClock_Config() 로 만들어 주지만, 클럭이 이상할 때 무엇을 의심할지는 이 여섯 단계로 압니다.
정리 — 리셋 직후 STM32F446 은 HSI 16 MHz, Uno 는 외부 16 MHz로 돕니다. STM32 는 주변장치 클럭이 기본으로 꺼져 있어 RCC 의 ENR 비트를 켜지 않으면 레지스터 쓰기가 조용히 무시되고, AVR 은 반대로 PRR 로 끄는 방식입니다. PLL 로 올릴 때는 Flash 대기 → 클럭 전환 순서를 지킵니다.

인터럽트 — 하드웨어가 CPU 의 어깨를 두드리는 법

버튼이 눌렸는지 알려면 두 가지 방법이 있습니다. CPU 가 계속 물어보거나(폴링), 버튼이 CPU 를 부르게 하거나(인터럽트). 서버로 치면 폴링은 1초마다 DB 를 조회하는 배치이고, 인터럽트는 웹훅입니다. 펌웨어의 구조 — 반응 속도, 전력, 버그의 종류 — 가 이 선택에서 갈립니다.

인터럽트의 이득은 반응 시간과 잠들 수 있는 시간입니다 — 대신 언제든 끼어든다는 대가로 공유 변수 문제가 생깁니다.

ISR 의 규칙 — 짧게 · 막지 말고 · 공유는 조심 🟡 중급

ISR 철칙 네 가지(짧게, malloc·printf 금지, volatile, 임계 구역)의 기본은 C 실전 탭 c22 에 있습니다. 여기서는 각 규칙을 어기면 실제로 무엇이 깨지는지를 봅니다.

찢어진 읽기 — volatile 로는 안 막히는 것

/* AVR: 16비트 변수는 8비트 CPU 에게 '두 번' 읽어야 하는 값 */
volatile uint16_t g_ticks;              /* 타이머 ISR 이 1 ms 마다 ++ */
ISR(TIMER1_COMPA_vect) { g_ticks++; }

uint16_t now_bad(void) {
    return g_ticks;     /* 하위 바이트 읽고 → (ISR: 0x00FF→0x0100) → 상위 바이트 읽기
                           → 0x01FF 같은 '존재한 적 없는 값' */
}

#include <util/atomic.h>
uint16_t now_ok(void) {
    uint16_t t;
    ATOMIC_BLOCK(ATOMIC_RESTORESTATE) { t = g_ticks; }   /* 읽는 동안만 차단 */
    return t;
}

우선순위 · 중첩 · 지연 처리 — NVIC 의 상태 기계 🔴 고급

우선순위 설정 — 숫자가 작을수록 높다

/* STM32F4 는 우선순위 비트 4개 → 0(최고) ~ 15(최저) */
NVIC_SetPriorityGrouping(3);              /* 4비트 전부 '선점' 단계로 (그룹 4) */

NVIC_SetPriority(USART2_IRQn,   2);       /* 바이트 유실이 치명적 → 높게 */
NVIC_SetPriority(TIM2_IRQn,     4);       /* 제어 주기 */
NVIC_SetPriority(EXTI15_10_IRQn,6);       /* 버튼 — 사람은 느리다 */

/* 우선순위 4 이상(숫자 ≥ 4)만 잠깐 막고, 0~3 은 계속 받기 — BASEPRI */
__set_BASEPRI(4u << (8u - __NVIC_PRIO_BITS));  /* 상위 4비트에 정렬해서 씀 */

Cortex-M 의 우선순위는 레지스터의 상위 비트에 놓입니다 — 4비트 칩에서 "5"는 실제로 0x50 으로 저장됩니다. CMSIS 함수는 이 정렬을 대신 해 주지만 BASEPRI 를 직접 쓸 때는 위처럼 시프트가 필요합니다. FreeRTOS 설정에서 다시 만납니다(⏱️ FreeRTOS 탭).

지연 처리 패턴 — ISR 은 표시, 일은 main 이

#include <stdint.h>
#include <stdbool.h>

/* 사건별 비트 — ISR 이 켜고 main 이 끔 */
enum { EV_BTN = 1u << 0, EV_TICK = 1u << 1, EV_RX = 1u << 2 };
static volatile uint32_t g_events;

void EXTI15_10_IRQHandler(void) { EXTI->PR = EXTI_PR_PR13; g_events |= EV_BTN; }
void SysTick_Handler(void)      { g_events |= EV_TICK; }

static uint32_t take_events(void) {          /* 읽고 비우기를 원자적으로 */
    uint32_t pm = __get_PRIMASK();
    __disable_irq();
    uint32_t ev = g_events;
    g_events = 0;
    __set_PRIMASK(pm);
    return ev;
}

int main(void) {
    /* … 초기화 … */
    for (;;) {
        uint32_t ev = take_events();
        if (ev & EV_BTN)  on_button();        /* 무거운 일은 전부 여기서 */
        if (ev & EV_TICK) on_tick();
        if (ev == 0) __WFI();                 /* 할 일 없으면 다음 인터럽트까지 잠 */
    }
}
"확인하고 잠들기" 사이의 틈 — ev == 0 을 본 직후 인터럽트가 와서 플래그를 세우면, 그 인터럽트가 이미 CPU 를 깨운 뒤라 __WFI() 가 다음 인터럽트까지 잠들어 처리가 한 틱 늦습니다. SysTick 이 1 ms 마다 깨워 주면 최대 1 ms 지연으로 끝나지만, 엄밀히 막으려면 PRIMASK=1 상태에서 확인하고 WFI(깨어나되 ISR 은 PRIMASK 를 푼 뒤 실행) 패턴을 씁니다. 그리고 ISR 의 하드웨어 플래그는 앞부분에서 지우세요 — 마지막 줄에서 지우면 쓰기가 반영되기 전에 ISR 이 끝나 한 번 더 들어올 수 있습니다.
정리 — 인터럽트는 벡터 테이블의 주소록대로 ISR 을 부르고, ISR 은 플래그를 지우고 표시만 한 뒤 끝냅니다. 공유 변수는 volatile + 원자적 접근(AVR 16비트·STM32 의 ++ 는 임계 구역), 우선순위는 숫자가 작을수록 높고, 같은 인터럽트는 횟수가 아니라 표시 하나입니다.
HW 09

타이머 · PWM — 세는 하드웨어로 시간과 밝기를 만든다

타이머는 클럭을 세는 카운터입니다. 그런데 이 단순한 카운터 하나로 정확한 주기 인터럽트, LED 밝기 조절, 서보 모터 각도, 신호의 주파수 측정까지 합니다. CPU 는 설정만 해 두고 손을 떼며, 하드웨어가 클럭 단위로 정확하게 일합니다. 코드로 만든 지연과는 정확도의 차원이 다릅니다.

PWM 은 빠르게 켰다 껐다를 반복해 평균 전력을 조절합니다 — 1 kHz 면 눈에는 깜빡임이 아니라 밝기로 보입니다.

주기 계산 — 두 칩의 식

STM32 (업카운트)
  f_update = f_TIM ÷ ((PSC + 1) × (ARR + 1))
  TIM2 는 APB1 타이머 클럭 — 리셋 기본(HSI, 분주 없음)이면 16 MHz
    PSC = 15   → 16 MHz ÷ 16 = 1 MHz  (1 틱 = 1 µs)
    ARR = 999  → 1 MHz ÷ 1000 = 1 kHz (1 ms 주기)
    CCR1 = 250 → HIGH 250 틱 → 듀티 = CCR ÷ (ARR+1) = 25 %
  180 MHz 설정이면 APB1 타이머 = 90 MHz → PSC = 89 로 같은 1 µs

ATmega328P Timer1 (16비트)
  CTC 모드:      f = f_clk ÷ (N × (1 + OCR1A))
    N = 64, OCR1A = 249 → 16 MHz ÷ (64 × 250) = 1000 Hz
  Fast PWM(TOP=ICR1): f = f_clk ÷ (N × (1 + ICR1))
    N = 8, ICR1 = 1999  → 16 MHz ÷ (8 × 2000) = 1 kHz
    OCR1A = 499 → 듀티 = (OCR1A + 1) ÷ (ICR1 + 1) = 25 %
    ※ 비반전 Fast PWM 은 OCR+1 틱 동안 HIGH — STM32 와 '+1' 위치가 다름
"+1" 을 빼먹으면 1 kHz 를 원했는데 1.001 kHz 가 됩니다. 시계·통신처럼 오차가 쌓이는 곳에서는 하루 86초 차이입니다. PSC 와 ARR 은 "값 + 1" 로 나눈다를 주석에 적어 두세요.

    TIM2->ARR   = 999;                 /* 1 kHz */
    TIM2->CCR1  = 250;                 /* 25 % */
    TIM2->CCMR1 = (6u << TIM_CCMR1_OC1M_Pos)   /* 110 = PWM 모드 1 */

    TIM2->CR1  |= TIM_CR1_CEN;         /* 카운터 시작 */
}

/* 서보: 20 ms 주기, 펄스 1.0 ms(0°) ~ 1.5 ms(90°) ~ 2.0 ms(180°)

void servo_init(void) {
    DDRB  |= (1 << DDB1);                          /* OC1A 핀을 출력으로 */

           | (1 << WGM11);                         /* 모드 14 = WGM13:10 = 1110 */
    TCCR1B = (1 << WGM13) | (1 << WGM12)
           | (1 << CS11);                          /* 분주 8 */
    ICR1   = 39999;                                /* TOP */
    OCR1A  = 2999;                                 /* (2999+1) × 0.5 µs = 1.5 ms */
}

void servo_set_us(uint16_t us) {                   /* 1000 ~ 2000 µs */
    if (us < 1000) us = 1000;
    if (us > 2000) us = 2000;
    OCR1A = (uint16_t)(us * 2u - 1u);              /* µs → 0.5 µs 틱, +1 보정 */
}

ADC — 전압을 숫자로 바꾸는 법과 그 숫자를 믿는 법

세상은 아날로그입니다. 온도·빛·배터리 잔량·조이스틱 위치가 전부 연속적인 전압으로 들어오고, ADC(아날로그-디지털 변환기)가 그걸 0~1023 이나 0~4095 같은 정수로 바꿉니다. 변환식은 한 줄이지만, 그 숫자가 얼마나 정확하고 얼마나 흔들리는지를 모르면 "센서 값이 튀어요"라는 이슈가 끝나지 않습니다.

ADC 결과는 "기준 전압의 몇 분의 몇"입니다 — 그래서 기준 전압이 흔들리면 모든 값이 같이 흔들립니다.

/* ── ATmega328P: A0 ── */
#include <avr/io.h>
void adc_init_avr(void) {
    ADMUX  = (1 << REFS0);                           /* 기준 AVcc, 채널 0 */
    ADCSRA = (1 << ADEN)
           | (1 << ADPS2) | (1 << ADPS1) | (1 << ADPS0);  /* ÷128 → 125 kHz */
}
uint16_t adc_read_avr(uint8_t ch) {
    ADMUX   = (uint8_t)((ADMUX & 0xF0) | (ch & 0x0F));
    ADCSRA |= (1 << ADSC);                           /* 변환 시작 */
    while (ADCSRA & (1 << ADSC)) { }                 /* 끝나면 하드웨어가 0 으로 */
    return ADC;                                      /* ADCL→ADCH 순서는 매크로가 보장 */
}

/* ── STM32F446: PA0 = ADC1_IN0 (Nucleo A0) ── */
void adc_init_stm32(void) {
    RCC->AHB1ENR |= RCC_AHB1ENR_GPIOAEN;
    RCC->APB2ENR |= RCC_APB2ENR_ADC1EN;
    (void)RCC->APB2ENR;
    GPIOA->MODER |= (3u << (0 * 2));                 /* 11 = 아날로그 모드 */
    ADC123_COMMON->CCR &= ~ADC_CCR_ADCPRE;           /* 00 = PCLK2 ÷ 2 (16 → 8 MHz) */
    ADC1->SMPR2 = (ADC1->SMPR2 & ~ADC_SMPR2_SMP0)
                | (7u << ADC_SMPR2_SMP0_Pos);        /* 111 = 480 사이클 — 가장 느리고 안정 */
    ADC1->SQR1 = 0;                                  /* 변환 개수 1 */
    ADC1->SQR3 = 0;                                  /* 1번째 = 채널 0 */
    ADC1->CR2  = ADC_CR2_ADON;                       /* 켜기 — 수 µs 안정화 시간 필요 */
}
uint16_t adc_read_stm32(void) {
    ADC1->CR2 |= ADC_CR2_SWSTART;
    while (!(ADC1->SR & ADC_SR_EOC)) { }
    return (uint16_t)ADC1->DR;                       /* DR 을 읽으면 EOC 가 지워짐 */
}

노이즈 줄이기 — 평균 두 가지

#include <stdint.h>

/* ① 이동 평균 8개 — 합을 들고 다녀 매번 8개를 더하지 않음 */
#define MA_N 8u                                /* 2의 거듭제곱 */
static uint16_t ma_buf[MA_N];
static uint8_t  ma_idx;
static uint32_t ma_sum;

uint16_t ma_push(uint16_t x) {
    ma_sum = ma_sum - ma_buf[ma_idx] + x;      /* 빠지는 값 빼고, 새 값 더하고 */
    ma_buf[ma_idx] = x;
    ma_idx = (uint8_t)((ma_idx + 1u) & (MA_N - 1u));
    return (uint16_t)(ma_sum / MA_N);
}   /* 처음 7개는 0 이 섞여 낮게 나옴 — 시작 때 버퍼를 첫 값으로 채우면 해결 */

/* ② 지수 이동 평균 — 배열 없이 변수 하나 (acc ≈ 평균 × 8) */
static uint32_t ema_acc;
uint16_t ema_push(uint16_t x) {
    ema_acc = ema_acc - (ema_acc >> 3) + x;    /* 새 값 1/8, 이전 7/8 */
    return (uint16_t)(ema_acc >> 3);
}   /* 일정한 입력이면 약 20 샘플에 93 %, 40 샘플에 99 % 따라감 */

    uint32_t raw = sum / 16u;                 /* 0~4095 */
    uint32_t pin_mv = raw * 3300u / 4095u;    /* 핀 전압 */
    return pin_mv * DIV_NUM / DIV_DEN;        /* 배터리 전압 */
}
/* 예: raw 3723 → 핀 3000 mV → 배터리 12000 mV
   최대 중간값: 4095 × 3300 = 13,513,500 — uint32_t 로 충분 */

/* 저항 오차 ±1% 두 개면 배율 오차가 최대 ±1.5% 안팎 —
   양산에서는 기준 전압으로 한 번 재서 보정값을 Flash 에 저장 */

HW 11

부팅의 진실 — main 보다 먼저 도는 것들

PC 의 C 프로그램은 운영체제가 메모리를 준비하고 main 을 불러 줍니다. MCU 에는 그 운영체제가 없으니 누군가는 전원이 들어온 첫 클럭부터 main 까지를 직접 해야 합니다. 그 "누군가"는 하드웨어 몇 단계와 스타트업 코드 수십 줄이고, 이걸 알면 전역 변수가 0 이 아닌 버그, main 전에 죽는 버그, HardFault 의 위치가 읽힙니다.

Cortex-M 은 벡터 테이블의 처음 두 워드만으로 C 함수를 부를 수 있게 설계됐습니다 — 스택과 시작 주소가 거기 있습니다.

벡터 테이블을 C 로 쓰면 — 실제 구조가 보입니다

Reset_Handler 를 C 로 — 스타트업이 하는 일 전부

#include <stdint.h>

extern uint32_t _sidata, _sdata, _edata, _sbss, _ebss;  /* 링커 심볼 (HW 12) */
extern void SystemInit(void);
extern void __libc_init_array(void);
extern int  main(void);

void Reset_Handler(void) {
    /* SP 는 이미 하드웨어가 [0] 에서 넣어 두었습니다 */

    uint32_t *src = &_sidata, *dst = &_sdata;
    while (dst < &_edata) *dst++ = *src++;      /* ① .data: Flash 사본 → RAM */

    for (dst = &_sbss; dst < &_ebss; ) *dst++ = 0;   /* ② .bss: 0 으로 */

    SystemInit();                               /* ③ FPU 접근 허용 등 */
    __libc_init_array();                        /* ④ 생성자 · init 함수 (newlib) */
    (void)main();                               /* ⑤ 드디어 */
    for (;;) { }                                /* ⑥ 돌아오면 여기서 멈춤 */
}
/* 이 함수가 끝나기 전까지는 '전역 변수의 초기값'을 믿으면 안 됩니다 */

/* STM32F4: RCC->CSR 의 플래그는 리셋해도 남음 → 읽고 지우기 */
const char *reset_cause_stm32(void) {
    uint32_t csr = RCC->CSR;
    RCC->CSR |= RCC_CSR_RMVF;                 /* 다음 부팅을 위해 지움 */
    if (csr & RCC_CSR_IWDGRSTF) return "watchdog";      /* 펌웨어가 멈췄었다 ★ */
    if (csr & RCC_CSR_SFTRSTF)  return "software";      /* NVIC_SystemReset() */
    if (csr & RCC_CSR_PORRSTF)  return "power-on";      /* 이때 BOR·PIN 도 같이 섬 */
    if (csr & RCC_CSR_BORRSTF)  return "brown-out";     /* POR 없이 BOR 만 → 전원이 처졌다 */
    if (csr & RCC_CSR_PINRSTF)  return "reset pin";
    return "unknown";
}

/* ATmega328P: MCUSR — 부트로더가 지워 버리는 경우가 있어 일찍 읽기 */
uint8_t reset_flags_avr(void) {
    uint8_t f = MCUSR;          /* PORF · EXTRF · BORF · WDRF */
    MCUSR = 0;
    return f;
}
순서에 주의 — STM32F4 는 전원 투입 때 PORRSTF 와 함께 BORRSTF · PINRSTF 도 같이 켜집니다. 그래서 위처럼 더 구체적인 원인부터 검사해야 "켤 때마다 brown-out" 같은 오판이 없습니다. 현장 장비가 "가끔 재부팅된다"면 이 값을 로그에 남기는 것만으로 원인의 절반이 드러납니다(🚀 양산 탭).
정리 — 리셋되면 Cortex-M 하드웨어가 [0] 을 SP 로, [4] 를 PC 로 읽고, 스타트업 코드가 .data 복사 · .bss 0 · SystemInit · 생성자를 끝낸 뒤 main 을 부릅니다. main 은 절대 돌아오지 않게 쓰고, 핸들러 이름은 벡터 테이블과 정확히 맞춥니다. 재부팅 이슈는 리셋 원인 레지스터부터 읽습니다.
HW 12

링커 스크립트 · 메모리 섹션 — 무엇이 어디에 놓이나

PC 에서는 실행 파일의 각 부분을 어느 주소에 올릴지 운영체제가 정합니다. MCU 에서는 링커 스크립트(.ld) 한 파일이 그 역할입니다 — 코드는 Flash 몇 번지부터, 변수는 RAM 몇 번지부터, 스택은 어디서 시작하는지. 기본 문법은 C 실전 탭 c22 에 맛보기가 있으니, 여기서는 Flash 와 RAM 에 실제로 펼쳐진 모습과 빌드 결과물에서 메모리 사용량을 읽는 법을 다룹니다.

.data 는 두 번 존재합니다 — Flash 에 초기값 사본(LMA), RAM 에 실제 변수(VMA). 이 둘을 잇는 것이 HW 11 의 복사 루프입니다.

STM32F446RE 링커 스크립트 — 뼈대만 남긴 것

ENTRY(Reset_Handler)                     /* 디버거·ELF 의 시작점 표시 */

_estack = ORIGIN(RAM) + LENGTH(RAM);     /* 0x2002 0000 — 벡터 [0] 에 들어감 */
_Min_Heap_Size  = 0x200;                 /* 이만큼 남지 않으면 링크 실패 */
_Min_Stack_Size = 0x400;                 /* 1 KB — '최소 확인용', 제한이 아님 */

MEMORY
{
  RAM   (xrw) : ORIGIN = 0x20000000, LENGTH = 128K
  FLASH (rx)  : ORIGIN = 0x08000000, LENGTH = 512K
}

SECTIONS
{
  .isr_vector : { . = ALIGN(4); KEEP(*(.isr_vector)) . = ALIGN(4); } >FLASH

  .text : {
    . = ALIGN(4);
    *(.text) *(.text*)                   /* 모든 .o 의 코드 */
    KEEP(*(.init)) KEEP(*(.fini))
    . = ALIGN(4);
    _etext = .;
  } >FLASH

  .rodata : { . = ALIGN(4); *(.rodata) *(.rodata*) . = ALIGN(4); } >FLASH

  .init_array : {                        /* 생성자 목록 — __libc_init_array 가 돎 */
    PROVIDE_HIDDEN(__init_array_start = .);
    KEEP(*(SORT(.init_array.*))) KEEP(*(.init_array*))
    PROVIDE_HIDDEN(__init_array_end = .);
  } >FLASH

  _sidata = LOADADDR(.data);             /* Flash 쪽 사본의 주소 */
  .data : {
    . = ALIGN(4);
    _sdata = .;  *(.data) *(.data*)  . = ALIGN(4);  _edata = .;
  } >RAM AT> FLASH                       /* ★ 실행은 RAM, 보관은 FLASH */

  .bss : {
    . = ALIGN(4);
    _sbss = .;  *(.bss) *(.bss*) *(COMMON)  . = ALIGN(4);  _ebss = .;
  } >RAM

  ._user_heap_stack : {                  /* 공간 확인용 가짜 섹션 */
    . = ALIGN(8);
    PROVIDE(end = .);                    /* newlib 의 _sbrk 가 힙 시작으로 씀 */
    . = . + _Min_Heap_Size;
    . = . + _Min_Stack_Size;
    . = ALIGN(8);
  } >RAM
}

스택 칠하기 — 높이 물의 흔적 찾기

#include <stdint.h>
#include "stm32f446xx.h"

extern uint32_t _ebss;                  /* .bss 끝 = 스택이 내려올 수 있는 한계 (malloc 안 쓸 때) */
#define PAINT 0xA5A5A5A5u

/* main 맨 앞에서 한 번 — 현재 SP 아래(아직 안 쓴 곳)를 무늬로 칠함 */
void stack_paint(void) {
    uint32_t *p   = &_ebss;
    uint32_t *top = (uint32_t *)__get_MSP() - 16;   /* 지금 쓰는 프레임은 건드리지 않게 */
    while (p < top) *p++ = PAINT;
}

/* 아무 때나 — 무늬가 남아 있는 바이트 수 = 한 번도 안 쓴 여유 */
uint32_t stack_unused_bytes(void) {
    const uint32_t *p = &_ebss;
    while (*p == PAINT) p++;
    return (uint32_t)((const uint8_t *)p - (const uint8_t *)&_ebss);
}
정적 분석도 같이 — GCC 의 -fstack-usage 는 함수마다 스택 크기를 .su 파일로 남깁니다. 재귀와 함수 포인터는 계산이 안 되므로 임베디드에서 재귀를 피하는 이유가 여기 있습니다. RTOS 를 쓰면 태스크마다 스택이 따로라 같은 측정을 태스크별로 합니다(⏱️ FreeRTOS 탭).

HW 13

베어메탈 Blinky 전 과정 — 레지스터만으로 LED 와 버튼

지금까지의 열두 섹션을 한 프로그램에 모읍니다. HAL 도 Arduino 도 없이 STM32F446RE 의 레지스터만으로 Nucleo 의 LD2(PA5)를 깜빡이고, SysTick 으로 1 ms 를 세고, B1 버튼(PC13)을 디바운스해 깜빡임 속도를 바꿉니다. 코드는 90 줄이 안 되지만 클럭 게이트 · 필드 쓰기 · 원자적 레지스터 · 인터럽트 · 공유 변수 · 슬립이 전부 들어 있습니다.

초기화는 클럭 → 핀 모드 → 시간원 → 루프 순서입니다 — 어떤 MCU, 어떤 주변장치든 이 순서는 바뀌지 않습니다.

main.c — 전체 (STM32F446RE · HSI 16 MHz · CMSIS 헤더만 사용)

/* main.c — Nucleo-F446RE 베어메탈 Blinky + 버튼
 *  LD2 = PA5 (HIGH 면 켜짐) · B1 = PC13 (누르면 LOW, 보드에 풀업)
 *  클럭: 리셋 기본값 HSI 16 MHz 그대로 — PLL 을 쓰지 않으므로 SystemInit 외 설정 없음 */
#include <stdint.h>
#include <stdbool.h>
#include "stm32f446xx.h"           /* CMSIS 디바이스 헤더 (core_cm4.h 포함) */

#define LED_PIN   5u
#define BTN_PIN   13u
#define DEBOUNCE_MS 20u

static volatile uint32_t g_ms;     /* SysTick 만 쓰고 main 은 읽기만 — 32비트라 읽기는 원자적 */

void SysTick_Handler(void) { g_ms++; }   /* 이름이 벡터 테이블과 글자 하나까지 같아야 함 */

static inline void led_on(void)  { GPIOA->BSRR = 1u << LED_PIN; }
static inline void led_off(void) { GPIOA->BSRR = 1u << (LED_PIN + 16u); }
static inline bool btn_raw_pressed(void) { return (GPIOC->IDR & (1u << BTN_PIN)) == 0u; }

/* 1 ms 마다 한 번 호출 — DEBOUNCE_MS 연속으로 다른 값이어야 상태를 바꿈 (HW 02) */
static bool button_pressed_event(void) {
    static bool    stable = false;      /* 확정된 상태: 눌림? */
    static uint8_t cnt    = 0;
    bool raw = btn_raw_pressed();
    if (raw == stable) { cnt = 0; return false; }
    if (++cnt < DEBOUNCE_MS) return false;
    stable = raw;
    cnt = 0;
    return stable;                      /* 떼짐 → 눌림 순간에만 true */
}

int main(void) {
    /* ① 클럭 게이트 */
    RCC->AHB1ENR |= RCC_AHB1ENR_GPIOAEN | RCC_AHB1ENR_GPIOCEN;
    (void)RCC->AHB1ENR;                 /* 켜진 뒤 2 클럭 — 에라타 우회용 더미 읽기 */

    /* ② PA5 출력 (MODER5 = 01). OTYPER(푸시풀) · OSPEEDR(저속)은 리셋값 그대로 */
    GPIOA->MODER = (GPIOA->MODER & ~(3u << (LED_PIN * 2u))) | (1u << (LED_PIN * 2u));

    /* ③ PC13 입력 (MODER13 = 00), 내부 풀업·풀다운 끔 (보드 저항 사용) */
    GPIOC->MODER &= ~(3u << (BTN_PIN * 2u));
    GPIOC->PUPDR &= ~(3u << (BTN_PIN * 2u));

    /* ④ SysTick: LOAD = 16000 - 1, 코어 클럭, 인터럽트 켬, 시작 — 실패하면 1 반환 */
    if (SysTick_Config(16000u) != 0u) { for (;;) { } }

    uint32_t period_ms   = 500u;        /* 반주기 — 500 이면 1 Hz 깜빡임 */
    uint32_t last_toggle = g_ms;
    uint32_t last_seen   = g_ms;
    bool     on = false;

    /* ⑤ 슈퍼 루프 */
    for (;;) {
        __WFI();                                    /* 다음 인터럽트(≤ 1 ms)까지 잠 */
        uint32_t now = g_ms;
        if (now == last_seen) continue;             /* 다른 인터럽트로 깼으면 건너뜀 */
        last_seen = now;

        if (button_pressed_event())                 /* 누를 때마다 500 ↔ 100 ms */
            period_ms = (period_ms == 500u) ? 100u : 500u;

        if ((uint32_t)(now - last_toggle) >= period_ms) {   /* 뺄셈 비교 — 49.7일 뒤 넘쳐도 안전 */
            last_toggle = now;
            on = !on;
            if (on) led_on(); else led_off();
        }
    }
}
읽어 볼 곳 세 군데 — ① now - last_toggle 처럼 뺄셈으로 비교하면 g_ms 가 2³² ms(약 49.7일) 뒤 0 으로 돌아가도 맞게 동작합니다(now >= last + period 는 틀림). ② LED 는 BSRR 로만 건드려 RMW 레이스가 없습니다. ③ __WFI() 덕분에 CPU 는 대부분 시간 잠들어 있습니다 — 같은 일을 바쁜 대기로 하면 전류가 몇 배입니다.

증상가장 흔한 원인확인법
LED 가 전혀 안 켜짐클럭 게이트 누락 · MODER 필드를 OR 만 함 · 다른 핀디버거로 GPIOA->MODER 가 0xA8000400 인지

깜빡임이 11배 빠름/느림클럭을 바꿨는데 SysTick 값은 16 MHz 기준SysTick_Config(SystemCoreClock / 1000) 로
버튼 한 번에 여러 번 반응디바운스 없이 엣지를 셈DEBOUNCE_MS 를 늘려 보기

main 전에 HardFault링커 스크립트 RAM 크기 오류 · 벡터 테이블 미포함.map 에서 .isr_vector 가 0x0800 0000 인지 (HW 12)
다음은 어디로 — 같은 원리를 칩별로 깊게: 🔷 AVR · ATmega 탭(타이머·UART·EEPROM·저전력을 데이터시트 순서로) → 🟦 STM32 · Cortex-M 탭(CubeMX · HAL/LL · DMA · NVIC 심화) → 📡 통신 · 드라이버 탭(UART · I²C · SPI 를 드라이버로). 막히면 🐞 디버깅 · 테스트 탭의 SWD 디버거·HardFault 해석을 먼저 보세요.
정리 — 베어메탈 Blinky 는 클럭 켜기 → MODER 필드 쓰기 → SysTick 1 ms → WFI 루프에서 BSRR 다섯 줄기이고, 버튼은 1 ms 샘플링 + 20회 연속으로 디바운스합니다. 이 90 줄을 설명할 수 있으면 HAL 이 내부에서 무엇을 하는지 전부 읽을 수 있습니다.
