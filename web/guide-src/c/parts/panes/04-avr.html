AVR 과 ATmega328P — Uno 보드의 실체

"Arduino" 는 칩 이름이 아니라 보드 + 부트로더 + 라이브러리 + IDE 를 묶은 브랜드입니다. Uno R3 에서 실제로 코드를 돌리는 것은 Microchip(옛 Atmel) 의 8비트 MCU ATmega328P 하나입니다. 이 칩이 어떤 구조인지, 보드의 핀 번호가 칩의 어느 다리인지부터 맞춰 둡니다.

핀맵 — Arduino 의 D13 은 칩의 PB5, 즉 "포트 B 의 5번 비트"입니다. 이 탭의 모든 코드는 오른쪽 이름이 아니라 안쪽 이름으로 씁니다.

RISC = 명령을 단순하게 만들고 대부분을 한 클럭에 끝내는 설계. 8비트 = 한 번에 계산하는 단위가 1바이트라는 뜻입니다. uint32_t 덧셈은 내부적으로 명령 4개로 쪼개집니다 — 그래서 AVR 코드는 uint8_t 를 기본으로 씁니다.

하버드 구조 — 코드와 데이터가 다른 길로 다닙니다

PC·서버의 CPU 는 코드와 데이터를 같은 메모리 공간(폰 노이만)에 둡니다. AVR 은 하버드 구조라서 명령은 Flash 에서 16비트 프로그램 버스로, 데이터는 SRAM 에서 8비트 데이터 버스로 따로 가져옵니다. 덕분에 명령을 읽는 동안 데이터를 동시에 읽을 수 있어 대부분 명령이 1클럭에 끝납니다.

대가는 주소 공간이 둘이라는 점입니다. Flash 의 0x0100 번지와 SRAM 의 0x0100 번지는 전혀 다른 곳이고, C 의 포인터 하나로는 둘을 구별하지 못합니다. 그래서 Flash 에 둔 문자열은 pgm_read_byte() 같은 전용 명령(LPM)으로만 읽습니다 — a10 에서 이걸 제대로 다룹니다.

하버드 구조 — Flash 와 SRAM 은 서로 다른 주소 공간이고, 주변장치는 SRAM 쪽 주소에 붙은 특수한 변수입니다.

헷갈리기 쉬운 것들

Uno R4 는 완전히 다른 칩입니다. R4 Minima/WiFi 는 Renesas RA4M1(32비트 Cortex-M4)이라 이 탭의 레지스터 코드가 하나도 돌지 않습니다. 이 탭은 Uno R3(및 같은 칩을 쓴 Nano · Pro Mini) 기준입니다. Cortex-M 은 STM32 탭에서 다룹니다.
호환 보드(클론)는 16U2 대신 CH340 같은 USB 칩을 쓰기도 합니다 — 윈도우에서 드라이버가 따로 필요할 수 있습니다. 옛 Nano 클론은 부트로더 속도가 57600 이라 업로드 명령의 -b 값이 다릅니다(a02).
핀 하나의 전류 한계는 절대 최대 40 mA, 권장 20 mA 이하입니다. LED 는 반드시 저항(220 Ω~1 kΩ)과 함께 — 저항값 계산과 회로 기초는 하드웨어 기초 탭에서 다룹니다.

레지스터 이름은 어디서 오나 🟡 중급

<avr/io.h> 가 주는 것

#include <avr/io.h>   // -mmcu=atmega328p 를 보고 iom328p.h 를 골라 줍니다

// iom328p.h 안에는 이런 정의가 수백 줄 들어 있습니다 (발췌 · 개념)
//   #define PINB   _SFR_IO8(0x03)   // I/O 주소 0x03 = 데이터 주소 0x23
//   #define DDRB   _SFR_IO8(0x04)
//   #define PORTB  _SFR_IO8(0x05)
//   #define PORTB5 5                 // 비트 번호
//   #define TCCR0A _SFR_IO8(0x24)
//   #define UDR0   _SFR_MEM8(0xC6)   // 확장 I/O — sbi/cbi 불가 영역
//
// _SFR_IO8(x) 는 결국 (*(volatile uint8_t *)((x) + 0x20)) 입니다
// → "volatile 포인터를 역참조한 변수" — C 실전 탭 c22 의 그 패턴

int main(void) {
    DDRB  |= _BV(DDB5);     // _BV(n) = (1 << n) — avr-libc 매크로
    PORTB |= _BV(PORTB5);   // PB5 = HIGH → D13 LED 켜짐
    for (;;) { }            // main 에서 돌아오면 안 됩니다 (돌아갈 OS 가 없음)
}

Arduino 없이 첫 프로그램 — avr-gcc · avrdude · Makefile

Arduino IDE 의 "업로드" 버튼은 사실 avr-gcc → avr-objcopy → avrdude 를 차례로 부르는 단축키입니다. 그 세 명령을 직접 치면 무엇이 어떻게 칩에 들어가는지 보이고, 빌드 옵션도 마음대로 바꿀 수 있습니다. 툴체인 설치 자체는 설치 · 툴체인 탭에서 다루고, 여기서는 명령과 그 의미에 집중합니다.

빌드 파이프라인 — elf 까지는 컴파일러의 일, hex 부터는 칩의 일입니다. 업로드 실패는 거의 항상 오른쪽 두 칸에서 납니다.

blink.c — 라이브러리 없는 Blink

// blink.c — ATmega328P @16MHz (Arduino Uno R3), D13 LED 깜빡이기
#ifndef F_CPU
#define F_CPU 16000000UL      // util/delay.h 가 지연 계산에 씁니다
#endif

#include <avr/io.h>
#include <util/delay.h>

int main(void)
{
    DDRB |= _BV(DDB5);         // PB5(D13) 를 출력으로

    for (;;) {
        PINB = _BV(PINB5);     // PINx 에 1 쓰기 = 그 핀 토글 (a03)
        _delay_ms(500);        // 컴파일 시간 상수만 허용 · -O 필수
    }
}
F_CPU 는 칩 속도를 바꾸는 설정이 아닙니다. "이 칩은 16 MHz 로 돈다"고 컴파일러에게 알려 주는 숫자일 뿐입니다. 실제 클럭은 퓨즈와 크리스털이 정합니다(a11). 둘이 다르면 _delay_ms(500) 가 1초가 되거나 UART 가 깨집니다.

명령 세 줄로 빌드 → 업로드

# 1) 컴파일 + 링크 (-mmcu 가 레지스터 정의와 링커 스크립트를 고릅니다)
avr-gcc -mmcu=atmega328p -DF_CPU=16000000UL -Os -std=gnu11 \
        -Wall -Wextra -o blink.elf blink.c

# 2) 크기 확인 — Flash 사용량 = text + data, SRAM 사용량 = data + bss
avr-size blink.elf
#   text(코드+상수) · data(초기값 있는 전역) · bss(0 으로 시작하는 전역)
#   이 Blink 는 text 가 200 바이트 안쪽, data·bss 는 0 입니다 (툴체인 버전마다 조금 다름)

# 3) Flash 영역만 Intel HEX 로 뽑기 (EEPROM·퓨즈 섹션 제외)
avr-objcopy -O ihex -R .eeprom -R .fuse -R .lock blink.elf blink.hex

# 4) 업로드 — Uno 의 Optiboot 부트로더에게 보냅니다
avrdude -c arduino -p m328p -P COM3 -b 115200 -U flash:w:blink.hex:i
#   리눅스: -P /dev/ttyACM0 (Uno) · /dev/ttyUSB0 (CH340 클론)
#   옛 Nano 클론: -b 57600
같은 Blink 를 Arduino IDE 로 빌드하면 약 900 바이트대가 나옵니다. 차이는 Arduino 코어가 미리 켜 두는 타이머 0 인터럽트(millis), PWM 설정, 핀 번호 테이블입니다 — a13 에서 하나씩 뜯어봅니다.

Makefile — 매번 치지 않도록 🟡 중급

Makefile (여러 .c 파일 지원)

# Makefile — ATmega328P / Arduino Uno R3 (레시피 줄 앞은 반드시 탭)
MCU     = atmega328p
F_CPU   = 16000000UL
PORT   ?= COM3
BAUD   ?= 115200
TARGET  = app
SRC     = $(wildcard *.c)
OBJ     = $(SRC:.c=.o)

CC      = avr-gcc
OBJCOPY = avr-objcopy
CFLAGS  = -mmcu=$(MCU) -DF_CPU=$(F_CPU) -Os -std=gnu11 -g \
          -Wall -Wextra -ffunction-sections -fdata-sections
LDFLAGS = -mmcu=$(MCU) -Wl,--gc-sections -Wl,-Map=$(TARGET).map

all: $(TARGET).hex size

%.o: %.c
	$(CC) $(CFLAGS) -c $< -o $@

$(TARGET).elf: $(OBJ)
	$(CC) $(LDFLAGS) $^ -o $@

$(TARGET).hex: $(TARGET).elf
	$(OBJCOPY) -O ihex -R .eeprom -R .fuse -R .lock $< $@

size: $(TARGET).elf
	avr-size $<

flash: $(TARGET).hex
	avrdude -c arduino -p m328p -P $(PORT) -b $(BAUD) -U flash:w:$<:i

clean:
	rm -f *.o *.elf *.hex *.map

.PHONY: all size flash clean

Makefile 의 레시피 줄은 공백이 아니라 탭이어야 합니다. 에디터가 탭을 공백으로 바꾸면 missing separator 오류가 납니다. CMake 를 쓰고 싶다면 툴체인 파일만 만들면 되지만, AVR 프로젝트는 대부분 이 정도 Makefile 로 충분합니다.
Arduino IDE 가 쓰는 툴체인을 그대로 빌려 쓰기 — IDE 를 설치했다면 이미 avr-gcc 와 avrdude 가 들어 있습니다 (Windows 는 보통 %LOCALAPPDATA%\Arduino15\packages\arduino\tools\ 아래). 다만 IDE 가 묶어 둔 avr-gcc 는 버전이 오래된 경우가 많아서, 새 프로젝트는 독립 설치한 최신 안정 avr-gcc 를 권합니다.
정리 — avr-gcc -mmcu -DF_CPU -Os 로 elf 를 만들고, avr-objcopy 로 hex 를 뽑고, avrdude -c arduino -b 115200 로 부트로더에게 보내면 끝입니다. 이 셋을 Makefile 에 묶어 두면 IDE 가 필요 없습니다.
AVR 03

GPIO — DDRx · PORTx · PINx 세 레지스터로 끝납니다

핀 하나를 켜고 끄고 읽는 일(GPIO, 범용 입출력)은 포트마다 레지스터 세 개가 전부입니다. 방향(DDR), 출력 값 또는 풀업(PORT), 입력 읽기(PIN). 이 셋의 조합 네 가지와 "PINx 에 1 을 쓰면 토글" 같은 AVR 고유의 요령, 그리고 기계식 버튼의 채터링을 타이머로 거르는 법까지 봅니다.

GPIO 매트릭스 — 입력일 때 PORT 비트는 풀업 스위치가 되고, 출력일 때는 출력 값이 됩니다. 같은 비트가 두 가지 일을 합니다.

버튼(D2)으로 LED(D13) 켜기 — 폴링

// button_led.c — ATmega328P @16MHz (Uno R3)
// 배선: D2(PD2) ── 버튼 ── GND   (외부 저항 없음, 내부 풀업 사용)
#define F_CPU 16000000UL
#include <avr/io.h>
#include <stdint.h>

int main(void)
{
    DDRB  |=  _BV(DDB5);      // PB5(D13) 출력
    DDRD  &= ~_BV(DDD2);      // PD2(D2) 입력 (리셋 값이 이미 0 이지만 명시)
    PORTD |=  _BV(PORTD2);    // PD2 풀업 켜기 → 안 누르면 1

    for (;;) {
        uint8_t pressed = !(PIND & _BV(PIND2));  // 누르면 GND → 0 → 반전
        if (pressed) PORTB |=  _BV(PORTB5);
        else         PORTB &= ~_BV(PORTB5);
    }
}
풀업 + 버튼을 GND 로가 표준인 이유 — 외부 부품이 필요 없고, 선이 끊어져도 "안 눌림(1)"으로 안전하게 읽힙니다. 대신 논리가 뒤집힙니다(눌림 = 0). 이걸 잊는 것이 초보의 첫 버그입니다.

{

디바운스 파형 — 판단 기준은 "바뀌었나"가 아니라 "바뀐 값이 N 번 연속 유지됐나"입니다. _delay_ms 로 기다리는 방식은 그동안 CPU 를 잡아 둡니다.

타이머 기반 디바운스 — 완전한 코드

// debounce.c — 1 ms 타이머 인터럽트에서 버튼 상태를 걸러 냄
#define F_CPU 16000000UL
#include <avr/io.h>
#include <avr/interrupt.h>
#include <util/atomic.h>
#include <stdint.h>

#define DEBOUNCE_MS 20

static volatile uint8_t g_press_events;   // ISR 이 올리고 main 이 가져감

ISR(TIMER0_COMPA_vect)                    // 1 ms 마다 (설정은 a05)
{
    static uint8_t stable = 1;            // 확정된 상태 (1 = 떼어짐)
    static uint8_t count  = 0;
    uint8_t raw = (PIND & _BV(PIND2)) ? 1 : 0;

    if (raw == stable) { count = 0; return; }
    if (++count >= DEBOUNCE_MS) {         // 바뀐 값이 20 번 연속
        stable = raw;
        count  = 0;
        if (stable == 0 && g_press_events < 255) g_press_events++;
    }
}

int main(void)
{
    DDRB  |= _BV(DDB5);
    PORTD |= _BV(PORTD2);                 // 풀업
    TCCR0A = _BV(WGM01);                  // CTC
    TCCR0B = _BV(CS01) | _BV(CS00);       // 분주 64 → 250 kHz
    OCR0A  = 249;                         // 250 카운트 = 1 ms
    TIMSK0 = _BV(OCIE0A);
    sei();

    for (;;) {
        uint8_t n;
        ATOMIC_BLOCK(ATOMIC_RESTORESTATE) {   // 읽기와 지우기를 한 덩어리로
            n = g_press_events;
            g_press_events = 0;
        }
        while (n--) PINB = _BV(PINB5);    // 누를 때마다 LED 토글
    }
}

결정이유

이벤트 '개수'메인이 바빠서 늦게 와도 누른 횟수를 잃지 않음
static 지역 변수ISR 만 쓰는 상태 — volatile 불필요

버튼에 인터럽트(INT0)를 바로 거는 것은 디바운스가 아닙니다. 튈 때마다 ISR 이 불려 한 번 누름이 3~10번으로 셉니다. INT0 은 "잠든 칩을 깨우는 용도"로 쓰고(a12), 판정은 이렇게 주기 샘플링으로 하세요.
서버 개발에 빗대면 디바운스 = 이벤트 디바운싱/스로틀링입니다. 검색창 자동완성이 "타이핑이 300 ms 멈추면 요청"하는 것과 같은 생각을 하드웨어 신호에 적용한 것입니다.
정리 — DDR 은 방향, PORT 는 출력값 또는 풀업, PIN 은 읽기(그리고 1 쓰면 토글). 한 비트씩 바꾸면 sbi/cbi 로 원자적이고, 버튼은 풀업 + GND 배선에 1 ms 주기 샘플링으로 디바운스합니다.
AVR 04

인터럽트 — 하드웨어가 함수를 부릅니다

인터럽트는 "어떤 일이 생기면 지금 하던 것을 멈추고 이 함수를 불러라"를 하드웨어에 맡기는 장치입니다. 서버로 치면 이벤트 콜백이지만, 결정적인 차이가 있습니다 — 메인 코드의 명령과 명령 사이 어디에서든 끼어듭니다. 그래서 ISR 과 공유하는 변수는 volatile 과 원자적 접근이 필수이고, 8비트 칩에서는 16비트 변수 하나도 위험합니다.

인터럽트 타임라인 — ISR 이 도는 동안 I 비트가 꺼져 있어 다른 인터럽트는 기다립니다. ISR 이 길면 그만큼 다른 인터럽트(UART 수신 등)가 밀리고, 결국 데이터를 잃습니다.

외부 인터럽트 INT0 — 하강 에지에서

// int0.c — D2(PD2)가 HIGH→LOW 로 떨어질 때마다 ISR 호출
#define F_CPU 16000000UL
#include <avr/io.h>
#include <avr/interrupt.h>

ISR(INT0_vect)
{

{
    DDRB  |= _BV(DDB5);
    PORTD |= _BV(PORTD2);        // 풀업

    EIFR   = _BV(INTF0);         // ★ 이미 세워진 플래그 지우기 (1 을 써서 지움)
    EIMSK  = _BV(INT0);          // INT0 허용
    sei();                       // 전역 인터럽트 허용 (SREG 의 I 비트)

        /* 메인은 다른 일을 해도 됩니다 */

16비트 변수 하나가 찢어지는 순간 🔴 고급

찢어진 읽기 — volatile 은 "매번 메모리에서 읽어라"일 뿐 "한 번에 읽어라"가 아닙니다. 8비트 AVR 에서는 2바이트 이상이면 전부 이 문제가 있습니다.

ATOMIC_BLOCK — 정답 패턴

#include <avr/interrupt.h>
#include <util/atomic.h>
#include <stdint.h>

static volatile uint16_t g_ms;      // ISR 이 증가 — volatile 필수

uint16_t ms_now(void)
{
    uint16_t v;
    ATOMIC_BLOCK(ATOMIC_RESTORESTATE) {
        v = g_ms;                   // cli → 두 바이트 읽기 → SREG 복원
    }
    return v;
}

//   RESTORESTATE : 들어오기 전 I 비트를 저장했다가 그대로 되돌림
//                  → 이미 인터럽트가 꺼진 곳(다른 ISR 안)에서 불러도 안전
//   FORCEON      : 끝날 때 무조건 sei() — 조금 빠르지만
//                  인터럽트가 꺼져 있어야 하는 곳에서 부르면 사고

// 1바이트 변수는 lds 한 번이라 읽기 자체는 원자적입니다.

CTC = Clear Timer on Compare match. 카운터가 OCR0A 와 같아지면 0 으로 되돌아갑니다. Normal 모드(256 고정)로는 1 ms 를 정확히 만들 수 없어서 Arduino 의 millis 는 1.024 ms 마다 인터럽트를 받고 분수 보정을 따로 합니다. CTC 는 그럴 필요가 없습니다.
CTC 파형 — 비교 일치가 톱니의 꼭대기를 잘라 주기를 정합니다. 0 부터 249 까지라 250 칸이고, 그래서 OCR0A 는 250 이 아니라 249 입니다.

계산 — OCR0A = 249 는 어디서 나왔나 🟢 기초

식 하나로 끝납니다

CTC 주파수     f = F_CPU / ( N × (1 + OCR) )
→ 거꾸로       OCR = F_CPU / ( N × f ) − 1

목표: f = 1000 Hz (1 ms),  F_CPU = 16 000 000

N = 1    → 16 000 000 / 1000      − 1 = 15 999   8비트(255) 초과
N = 8    →  2 000 000 / 1000      − 1 =  1 999   8비트 초과
N = 64   →    250 000 / 1000      − 1 =    249   ✓ 정수 · 255 이하
N = 256  →     62 500 / 1000      − 1 =   61.5   정수 아님 → 오차
N = 1024 →     15 625 / 1000      − 1 = 14.625   정수 아님

검산: 16 000 000 / (64 × (1 + 249)) = 16 000 000 / 16 000 = 1000 Hz  ✓
고르는 규칙: ① 결과가 정수이고 ② 타이머 폭(8비트면 255, 16비트면 65535) 이하인 분주 중 가장 작은 N. N 이 작을수록 해상도(1 틱의 길이)가 좋습니다.

millis.c — Arduino 없이 millis()

// millis.c — Timer0 CTC 1 ms 틱 · ATmega328P @16MHz
#define F_CPU 16000000UL
#include <avr/io.h>
#include <avr/interrupt.h>
#include <util/atomic.h>
#include <stdint.h>

static volatile uint32_t g_ms;            // 49.7 일 후 0 으로 돌아감

ISR(TIMER0_COMPA_vect) { g_ms++; }

static void tick_init(void)
{
    TCCR0A = _BV(WGM01);                  // WGM02:0 = 010 → CTC, TOP = OCR0A
    TCCR0B = _BV(CS01) | _BV(CS00);       // CS02:0 = 011 → 분주 64 (여기서 시작)
    OCR0A  = 249;                         // 16 MHz / 64 / 250 = 1000 Hz
    TCNT0  = 0;
    TIFR0  = _BV(OCF0A);                  // 남아 있던 플래그 지우기
    TIMSK0 = _BV(OCIE0A);                 // 비교 일치 A 인터럽트 허용
}

uint32_t millis(void)
{
    uint32_t m;
    ATOMIC_BLOCK(ATOMIC_RESTORESTATE) { m = g_ms; }   // 4바이트 → 원자적으로
    return m;
}

int main(void)
{
    DDRB |= _BV(DDB5);
    tick_init();
    sei();

    uint32_t last = millis();
    for (;;) {
        if ((uint32_t)(millis() - last) >= 500) {   // 뺄셈 비교 = 넘침에도 안전
            last += 500;                           // 주기가 밀리지 않게 누적
            PINB = _BV(PINB5);
        }
        /* 여기서 다른 일을 해도 깜빡임은 정확합니다 — delay 가 없으니까 */
    }
}

micros() — 카운터 값까지 읽기

// 위 millis.c 에 추가 — 해상도 4 µs
uint32_t micros(void)
{
    uint32_t m;
    uint8_t  t;
    ATOMIC_BLOCK(ATOMIC_RESTORESTATE) {
        m = g_ms;
        t = TCNT0;
        // 방금 249 → 0 으로 넘어갔는데 ISR 이 아직 못 돈 경우(인터럽트가 꺼져 있으니까)
        if ((TIFR0 & _BV(OCF0A)) && t < 249) m++;
    }
    return m * 1000UL + (uint32_t)t * 4U;   // 약 71.6 분마다 0 으로 돌아감
}
대기 중 플래그 확인을 빼면 아주 드물게 micros 가 1000 µs 뒤로 가는 값이 나옵니다. 하루에 몇 번 생기는 버그라 테스트로는 안 잡히고 현장에서 "가끔 튀는 측정값"으로 나타납니다. Arduino 코어의 micros 도 똑같은 처리를 합니다(TOV0 기준).

16비트 타이머 레지스터(TCNT1 · OCR1A · ICR1)는 내부 TEMP 레지스터로 상·하위 바이트를 한 번에 옮깁니다. 컴파일러가 순서를 맞춰 주지만, ISR 에서도 같은 16비트 타이머 레지스터를 만지면 TEMP 를 공유하므로 메인 쪽 접근을 ATOMIC_BLOCK 으로 감싸야 합니다.
정리 — OCR = F_CPU ÷ (N × f) − 1 이 정수이고 타이머 폭 안에 들어가는 가장 작은 분주를 고릅니다. 1 ms 는 분주 64 · OCR0A 249, ISR 에서 카운터를 올리고 메인에서는 ATOMIC_BLOCK 으로 읽고 뺄셈으로 비교합니다.
AVR 06

PWM — 켜짐 비율로 아날로그 흉내

ATmega328P 에는 진짜 아날로그 출력(DAC)이 없습니다. 대신 핀을 아주 빨리 켰다 껐다 하면서 켜져 있는 비율(듀티)을 바꿉니다. LED 는 눈의 잔상 때문에, 모터는 관성 때문에 평균값처럼 반응합니다. Arduino 의 analogWrite() 가 이것이고, 서보 모터는 반대로 펄스의 폭 자체를 명령으로 읽습니다.

PWM 파형 — Fast PWM 은 톱니라 주파수가 2배, Phase Correct 는 삼각파라 펄스가 대칭입니다. 모터 제어처럼 위상이 중요하면 아래쪽을 씁니다.

LED 밝기 — Timer2 Fast PWM (D11)

// pwm_led.c — D11(PB3, OC2A) LED 페이드 · ATmega328P @16MHz
#define F_CPU 16000000UL
#include <avr/io.h>
#include <util/delay.h>
#include <stdint.h>

static void pwm2_init(void)
{
    DDRB  |= _BV(DDB3);                         // OC2A 핀을 출력으로 (필수)
    TCCR2A = _BV(COM2A1)                        // 비반전: 일치 시 LOW, 바닥에서 HIGH
           | _BV(WGM21) | _BV(WGM20);           // 모드 3: Fast PWM, TOP = 0xFF
    TCCR2B = _BV(CS22);                         // Timer2 의 100 = 분주 64 → 976.6 Hz
    OCR2A  = 0;
}

// 사람 눈은 밝기를 로그로 느낌 → 제곱으로 펴 주면 페이드가 고르게 보임
static uint8_t gamma2(uint8_t v)
{
    return (uint8_t)(((uint16_t)v * v + 255) >> 8);   // 0→0, 255→255
}

int main(void)
{
    pwm2_init();
    for (;;) {
        for (uint16_t i = 0; i <= 255; i++) { OCR2A = gamma2((uint8_t)i); _delay_ms(4); }
        for (int16_t  i = 255; i >= 0;  i--) { OCR2A = gamma2((uint8_t)i); _delay_ms(4); }
    }
}
Fast PWM 에서 OCR = 0 은 완전히 꺼지지 않습니다. 매 주기 바닥에서 한 틱짜리 가는 펄스가 남습니다(데이터시트에 명시된 동작). 완전히 끄려면 TCCR2A &= ~_BV(COM2A1) 로 핀을 타이머에서 떼고 PORT 로 LOW 를 쓰세요 — Arduino 의 analogWrite(pin, 0) 도 내부에서 그렇게 합니다.

#include <util/delay.h>
#include <stdint.h>

#define SERVO_MIN 2000u     // 1.0 ms
#define SERVO_MAX 4000u     // 2.0 ms

static void servo_init(void)
{
    DDRB  |= _BV(DDB1);                          // OC1A 출력
    TCCR1A = _BV(COM1A1) | _BV(WGM11);           // 비반전 · WGM13:0 = 1110 (모드 14)
    TCCR1B = _BV(WGM13) | _BV(WGM12) | _BV(CS11);// 분주 8
    ICR1   = 39999;                              // TOP → 50 Hz
    OCR1A  = 3000;                               // 가운데
}

static void servo_write(uint8_t deg)             // 0 ~ 180
{
    if (deg > 180) deg = 180;
    // 180 × 2000 = 360 000 → 16비트를 넘으므로 32비트로 계산
    OCR1A = (uint16_t)(SERVO_MIN + (uint32_t)deg * (SERVO_MAX - SERVO_MIN) / 180u);
}

int main(void)
{
    servo_init();
    for (;;) {
        servo_write(0);   _delay_ms(1000);
        servo_write(90);  _delay_ms(1000);
        servo_write(180); _delay_ms(1000);
    }
}

AVR 07

UART — Serial.print 를 직접 만듭니다

UART 는 선 두 개(TX · RX)로 바이트를 한 비트씩 보내는 가장 오래되고 가장 흔한 통신입니다. Uno 의 D0/D1 은 보드의 USB 칩에 연결돼 있어서, UART 로 보낸 글자가 그대로 PC 의 시리얼 모니터에 찍힙니다. 여기서는 보레이트 레지스터 계산과 오차, 폴링 송수신, 인터럽트 + 링 버퍼, 그리고 printf 연결까지 만듭니다. UART 프로토콜 일반론(패리티 · 흐름 제어 · RS-485)은 통신 · 드라이버 탭에서 다룹니다.

UART 프레임 — 클럭 선이 없어서 양쪽이 같은 속도라고 믿고 시간을 잽니다. 그래서 보레이트 오차가 통신 성패를 가릅니다.

폴링 송수신 — 가장 단순한 형태

// uart_poll.c — 에코: 받은 글자를 그대로 돌려줌 · 9600 8N1
#define F_CPU 16000000UL
#define BAUD  9600
#include <avr/io.h>
#include <util/setbaud.h>      // F_CPU 와 BAUD 로 UBRRH_VALUE · USE_2X 계산
#include <stdint.h>

static void uart_init(void)
{
    UBRR0H = UBRRH_VALUE;
    UBRR0L = UBRRL_VALUE;
#if USE_2X
    UCSR0A |= _BV(U2X0);
#else
    UCSR0A &= ~_BV(U2X0);
#endif
    UCSR0B = _BV(RXEN0) | _BV(TXEN0);        // 수신 · 송신 켜기
    UCSR0C = _BV(UCSZ01) | _BV(UCSZ00);      // 8비트 · 패리티 없음 · 정지 1 (8N1)
}

static void uart_putc(uint8_t c)
{
    while (!(UCSR0A & _BV(UDRE0))) { }       // 송신 버퍼가 빌 때까지
    UDR0 = c;
}

static uint8_t uart_getc(void)
{
    while (!(UCSR0A & _BV(RXC0))) { }        // 1바이트 들어올 때까지
    return UDR0;
}

static void uart_puts(const char *s) { while (*s) uart_putc((uint8_t)*s++); }

int main(void)
{
    uart_init();
    uart_puts("ready\r\n");
    for (;;) uart_putc(uart_getc());
}

인터럽트 + 링 버퍼 — 하나도 안 잃게 🟡 중급

링 버퍼 — 쓰는 쪽과 읽는 쪽이 서로 다른 변수만 고치므로 락이 필요 없습니다. 일반 원리는 C 실전 탭 c22, 여기서는 AVR UART 에 붙이는 법입니다.

uart_irq.c — 수신 · 송신 모두 인터럽트

// uart_irq.c — 링 버퍼 UART · 115200 (U2X) · ATmega328P @16MHz
#define F_CPU 16000000UL
#include <avr/io.h>
#include <avr/interrupt.h>
#include <stdint.h>

#define RX_SIZE 64u                   // 2 의 거듭제곱
#define TX_SIZE 64u
#define RX_MASK (RX_SIZE - 1u)
#define TX_MASK (TX_SIZE - 1u)

// 버퍼까지 volatile — 메인의 "데이터 쓰기 → head 갱신" 순서를
// 컴파일러가 뒤바꾸지 못하게 (volatile 접근끼리는 순서가 유지됨)
static volatile uint8_t rx_buf[RX_SIZE], tx_buf[TX_SIZE];
static volatile uint8_t rx_head, rx_tail, tx_head, tx_tail;
static volatile uint8_t rx_overflow;

ISR(USART_RX_vect)
{
    uint8_t c    = UDR0;              // 읽어야 RXC0 가 내려감
    uint8_t next = (uint8_t)((rx_head + 1u) & RX_MASK);
    if (next != rx_tail) { rx_buf[rx_head] = c; rx_head = next; }
    else if (rx_overflow < 255) rx_overflow++;   // 가득 참 — 버리고 셈
}

ISR(USART_UDRE_vect)
{
    if (tx_head == tx_tail) {         // 보낼 것 없음 → 이 인터럽트 끄기
        UCSR0B &= ~_BV(UDRIE0);
        return;
    }
    UDR0    = tx_buf[tx_tail];
    tx_tail = (uint8_t)((tx_tail + 1u) & TX_MASK);
}

void uart_init(void)
{
    UBRR0  = 16;                      // 115200 · U2X → +2.12%
    UCSR0A = _BV(U2X0);
    UCSR0C = _BV(UCSZ01) | _BV(UCSZ00);
    UCSR0B = _BV(RXEN0) | _BV(TXEN0) | _BV(RXCIE0);
}

int uart_getc(void)                   // 없으면 -1 (블로킹하지 않음)
{
    if (rx_head == rx_tail) return -1;
    uint8_t c = rx_buf[rx_tail];
    rx_tail = (uint8_t)((rx_tail + 1u) & RX_MASK);
    return c;
}

void uart_putc(uint8_t c)             // ★ ISR 안에서 부르지 말 것 (가득 차면 영원히 대기)
{
    uint8_t next = (uint8_t)((tx_head + 1u) & TX_MASK);
    while (next == tx_tail) { }       // 가득 참 → UDRE ISR 이 비워 줄 때까지
    tx_buf[tx_head] = c;
    tx_head = next;
    UCSR0B |= _BV(UDRIE0);            // "보낼 게 있다" — 빈 즉시 ISR 이 불림
}

int main(void)
{
    uart_init();
    sei();
    for (;;) {
        int c = uart_getc();
        if (c >= 0) uart_putc((uint8_t)c);   // 에코
        /* 메인이 바빠도 63 바이트까지는 ISR 이 받아 둡니다 */
    }
}

// 위 uart_irq.c 의 main 을 이것으로 바꾸면 printf 가 UART 로 나갑니다
#include <stdio.h>
#include <avr/pgmspace.h>

static int uart_putchar(char c, FILE *stream)
{
    (void)stream;
    if (c == '\n') uart_putc('\r');   // 터미널용 CR LF
    uart_putc((uint8_t)c);
    return 0;
}

// C 전용 정적 초기화 매크로 (C++ 에서는 fdev_setup_stream() 함수를 씀)
static FILE uart_out = FDEV_SETUP_STREAM(uart_putchar, NULL, _FDEV_SETUP_WRITE);

int main(void)
{
    uart_init();
    stdout = &uart_out;
    sei();

    printf("boot ok, ticks=%u\n", 42u);
    printf_P(PSTR("서식 문자열도 Flash 에 (a10)\n"));
    for (;;) { }
}

printf 는 공짜가 아닙니다. 정수 printf 만으로도 Flash 가 1.5 KB 안팎 늘고, 호출마다 스택을 수십 바이트 씁니다. 2 KB SRAM 에서 깊은 호출 안의 printf 는 스택 넘침의 단골 원인입니다. 온도처럼 소수가 필요하면 %f 대신 정수 ×10 으로 계산해 "%d.%d" 로 찍는 것이 정석입니다(a13).
Arduino 의 HardwareSerial 과 같은 구조입니다. Arduino 도 수신 64 · 송신 64 바이트 링 버퍼 + RX/UDRE 인터럽트로 되어 있고 (그래서 Serial 을 쓰는 순간 SRAM 이 백수십 바이트 사라집니다), 57600 에서는 옛 부트로더 호환 때문에 일부러 U2X 를 끈 설정을 쓰는 예외 처리까지 들어 있습니다.
정리 — UBRR 은 직접 계산하고 U2X0 두 경우의 오차를 비교한 뒤 고릅니다. 수신은 RX 인터럽트로 링 버퍼에, 송신은 UDRE 인터럽트로 링 버퍼에서 — 그리고 FDEV_SETUP_STREAM 한 줄로 printf 를 연결합니다.

ADC — 전압을 숫자로

ADC(Analog-to-Digital Converter)는 핀의 전압을 0~1023 의 정수로 바꿉니다. 가변저항 · 조도 센서 · 아날로그 온도 센서 같은 대부분의 센서가 결국 "전압"을 내놓으므로 ADC 는 센서 세계로 들어가는 문입니다. 기준 전압 고르기, 125 kHz 클럭, 한 번 변환과 자유 실행, 그리고 칩 안의 온도 센서까지 다룹니다.

양자화 계단 — 정밀도는 비트 수와 기준 전압이 정합니다. 작은 전압을 재면 기준을 1.1 V 로 내려 같은 1024 계단을 촘촘하게 씁니다.

가변저항(A0) → LED 밝기(D11)

// adc_pot.c — 배선: 가변저항 양끝 5V·GND, 가운데 → A0(PC0)
#define F_CPU 16000000UL
#include <avr/io.h>
#include <stdint.h>

static void adc_init(void)
{
    ADMUX  = _BV(REFS0);              // REFS1:0 = 01 → 기준 = AVcc(5 V), 오른쪽 정렬
    ADCSRA = _BV(ADEN)                // ADC 켜기
           | _BV(ADPS2) | _BV(ADPS1) | _BV(ADPS0);   // 분주 128 → 125 kHz
    DIDR0  = _BV(ADC0D);              // A0 의 디지털 입력 버퍼 끄기 (전류·노이즈 감소)
}

static uint16_t adc_read(uint8_t ch)  // 단일 변환 · 약 104 µs
{
    ADMUX   = (uint8_t)((ADMUX & 0xF0) | (ch & 0x0F));   // 기준 비트는 유지
    ADCSRA |= _BV(ADSC);              // 변환 시작
    while (ADCSRA & _BV(ADSC)) { }    // 끝나면 하드웨어가 0 으로
    return ADC;                       // ADCL 먼저, ADCH 나중 — 매크로가 순서 보장
}

static uint16_t adc_to_mv(uint16_t raw)
{
    return (uint16_t)((uint32_t)raw * 5000u / 1024u);   // 1023×5000 → 32비트 필요
}

int main(void)
{
    adc_init();
    DDRB  |= _BV(DDB3);                                  // OC2A (a06 과 같은 설정)
    TCCR2A = _BV(COM2A1) | _BV(WGM21) | _BV(WGM20);
    TCCR2B = _BV(CS22);

    for (;;) {
        uint16_t raw = adc_read(0);
        OCR2A = (uint8_t)(raw >> 2);                     // 10비트 → 8비트
        (void)adc_to_mv(raw);                            // 디버깅 출력용 (a07 printf)
    }
}

설정값 고르기

REFS1:0기준 전압언제
00AREF 핀 (외부)정밀 기준 칩을 따로 달 때
01AVcc (Uno 는 5 V)가변저항 · 5 V 센서 — 기본
11내부 1.1 V작은 전압 · 칩 온도 센서
ADC 클럭은 50 ~ 200 kHz 여야 10비트 정밀도를 보장
16 MHz / 64  = 250 kHz   ✕ 너무 빠름
16 MHz / 128 = 125 kHz   ✓ → 유일한 선택
변환 1회 = 13 ADC 클럭 = 13 / 125 kHz = 104 µs  (최대 약 9.6 kSPS)
첫 변환(ADEN 직후) = 25 클럭 = 200 µs
AREF 핀에 외부 전압을 넣은 채로 AVcc/1.1 V 기준을 고르면 칩 안에서 두 전압이 맞붙어 칩이 상할 수 있습니다. Uno 의 AREF 핀은 커패시터만 달려 있으니 아무것도 연결하지 않는 것이 기본입니다.
변환 타이밍 — 첫 변환은 두 배 가까이 길고, 자유 실행은 끝나자마자 다음 변환을 시작해 약 9.6 kSPS 로 끊김 없이 측정합니다.

자유 실행 + 인터럽트

// adc_free.c — A0 를 끊임없이 측정, 최신값만 보관
#define F_CPU 16000000UL
#include <avr/io.h>
#include <avr/interrupt.h>
#include <util/atomic.h>
#include <stdint.h>

static volatile uint16_t g_adc;

ISR(ADC_vect) { g_adc = ADC; }       // 104 µs 마다

int main(void)
{
    ADMUX  = _BV(REFS0);                       // AVcc · ADC0
    ADCSRB = 0;                                // ADTS2:0 = 000 → 자유 실행
    ADCSRA = _BV(ADEN) | _BV(ADATE) | _BV(ADIE)
           | _BV(ADPS2) | _BV(ADPS1) | _BV(ADPS0);
    sei();
    ADCSRA |= _BV(ADSC);                       // 첫 변환만 시작해 주면 계속 돔

    DDRB |= _BV(DDB5);
    for (;;) {
        uint16_t v;
        ATOMIC_BLOCK(ATOMIC_RESTORESTATE) { v = g_adc; }   // 16비트 공유 → 원자적으로
        if (v > 512) PORTB |= _BV(PORTB5); else PORTB &= ~_BV(PORTB5);
    }
}
자유 실행 중에 채널(MUX)을 바꾸면 이미 시작된 변환은 옛 채널로 끝나고, 그다음 변환부터 새 채널입니다. 여러 채널을 돌아가며 재려면 ISR 에서 MUX 를 바꾸고 결과를 한 칸 늦게 해석해야 합니다 — 헷갈리면 단일 변환을 쓰세요.

칩 내부 온도 센서 (ADC8)

// chip_temp.c — 칩 온도가 50 °C 를 넘으면 D13 LED 경고
#define F_CPU 16000000UL
#include <avr/io.h>
#include <util/delay.h>
#include <stdint.h>

// ★ 두 상수는 '내 칩'으로 직접 보정해야 합니다
#define TS_RAW_AT_25C   352   // 25 °C 에서 잰 원시값 (칩마다 수십 LSB 차이)
#define TS_LSB_PER_C100 100   // 기울기 × 100 (약 1 LSB/°C 안팎 — 두 온도에서 재서 구함)

int16_t chip_temp_c(void)
{
    ADMUX = _BV(REFS1) | _BV(REFS0) | _BV(MUX3);  // 내부 1.1 V 기준 · MUX3:0 = 1000 (온도)
    _delay_ms(2);                                 // 기준 전압이 자리 잡을 시간
    ADCSRA |= _BV(ADSC);                          // 기준을 바꾼 뒤 첫 결과는 버림
    while (ADCSRA & _BV(ADSC)) { }

    uint32_t sum = 0;
    for (uint8_t i = 0; i < 16; i++) {           // 16회 평균 → 노이즈 감소
        ADCSRA |= _BV(ADSC);
        while (ADCSRA & _BV(ADSC)) { }
        sum += ADC;
    }
    int32_t raw = (int32_t)(sum / 16u);
    return (int16_t)((raw - TS_RAW_AT_25C) * 100 / TS_LSB_PER_C100 + 25);
}

int main(void)
{
    ADCSRA = _BV(ADEN) | _BV(ADPS2) | _BV(ADPS1) | _BV(ADPS0);   // ÷128
    DDRB  |= _BV(DDB5);
    for (;;) {
        if (chip_temp_c() > 50) PORTB |= _BV(PORTB5);
        else                    PORTB &= ~_BV(PORTB5);
        _delay_ms(1000);
    }
}
내부 온도 센서는 '칩 온도'이고 정확도는 보정 전 ±10 °C 수준입니다. 내부 1.1 V 기준 자체가 칩마다 1.0~1.2 V 로 흩어지기 때문입니다. 실내 온도 측정용이 아니라 과열 감지 · 온도 보상용으로 쓰고, 실내 온도는 LM35 같은 외부 센서를 씁니다(a13).
정리 — ADC 는 REFS 로 기준 전압, 분주 128 로 125 kHz, ADSC 로 시작합니다. 결과 × Vref / 1024 를 계산할 때는 32비트로 곱한 뒤 나누고, 공유되는 16비트 결과는 ATOMIC_BLOCK 으로 읽습니다.
AVR 09

I2C(TWI) · SPI — 레지스터로 버스 다루기

센서 · RTC · EEPROM · 디스플레이는 대부분 I2C(선 2개, 주소로 여러 장치) 나 SPI(선 4개, 빠름) 로 붙습니다. ATmega328P 는 둘 다 하드웨어로 가지고 있습니다(Atmel 은 I2C 를 상표 문제로 TWI, Two-Wire Interface 라고 부릅니다). 여기서는 레지스터로 한 바이트를 주고받는 최소 드라이버까지만 만듭니다. 프로토콜의 전기적 세부 · 클럭 스트레칭 · 버스 복구 · DMA 는 통신 · 드라이버 탭에서 깊게 다룹니다.

I2C 시퀀스 — 매 단계 끝에 TWSR 상태 코드를 확인합니다. "레지스터 번호 쓰기 → 반복 START → 읽기"는 거의 모든 I2C 센서에서 똑같은 모양입니다.

TWBR 계산 — 100 kHz

SCL = F_CPU / ( 16 + 2 × TWBR × 4^TWPS )      (TWPS = 0 → 4^0 = 1)

TWBR = ( F_CPU / SCL − 16 ) / 2
100 kHz : (16 000 000 / 100 000 − 16) / 2 = (160 − 16) / 2 = 72
400 kHz : (16 000 000 / 400 000 − 16) / 2 = ( 40 − 16) / 2 = 12

검산: 16 000 000 / (16 + 2 × 72) = 16 000 000 / 160 = 100 000 Hz ✓
상수 (util/twi.h)값뜻
TW_START0x08START 보냄
TW_REP_START0x10반복 START 보냄
TW_MT_SLA_ACK0x18주소+W 에 ACK
TW_MT_SLA_NACK0x20주소+W 에 NACK — 장치 없음
TW_MT_DATA_ACK0x28데이터에 ACK
TW_MR_SLA_ACK0x40주소+R 에 ACK
TW_MR_DATA_ACK0x50받음 · ACK 보냄 (더 줘)
TW_MR_DATA_NACK0x58받음 · NACK 보냄 (끝)
I2C 는 풀업 저항이 필수입니다(선을 HIGH 로 끌어올리는 저항, 보통 4.7 kΩ). 칩 내부 풀업(20~50 kΩ)은 너무 약해 100 kHz 에서도 파형이 무너집니다. 대부분의 센서 모듈 기판에는 이미 달려 있으니 모듈을 여러 개 달면 병렬로 너무 세지는 것도 확인하세요.

twi.c — DS3231 초 읽기 (완전한 코드)

// twi_rtc.c — A4=SDA(PC4), A5=SCL(PC5) · ATmega328P @16MHz
#define F_CPU 16000000UL
#include <avr/io.h>
#include <util/twi.h>        // TW_STATUS, TW_START ...
#include <stdint.h>

#define DS3231_ADDR 0x68

static void twi_init(void)
{
    TWSR = 0;                                 // TWPS = 0 (분주 1)
    TWBR = 72;                                // 100 kHz
    TWCR = _BV(TWEN);
}
static void twi_wait(void) { while (!(TWCR & _BV(TWINT))) { } }

static uint8_t twi_start(uint8_t sla_rw)     // 0 = 성공
{
    TWCR = _BV(TWINT) | _BV(TWSTA) | _BV(TWEN);
    twi_wait();
    if (TW_STATUS != TW_START && TW_STATUS != TW_REP_START) return 1;
    TWDR = sla_rw;
    TWCR = _BV(TWINT) | _BV(TWEN);
    twi_wait();
    return (TW_STATUS == TW_MT_SLA_ACK || TW_STATUS == TW_MR_SLA_ACK) ? 0 : 2;
}
static uint8_t twi_write(uint8_t b)
{
    TWDR = b;
    TWCR = _BV(TWINT) | _BV(TWEN);
    twi_wait();
    return TW_STATUS == TW_MT_DATA_ACK ? 0 : 1;
}
static uint8_t twi_read(uint8_t ack)        // ack=1: 더 읽음, 0: 마지막
{
    TWCR = _BV(TWINT) | _BV(TWEN) | (ack ? _BV(TWEA) : 0);
    twi_wait();
    return TWDR;
}
static void twi_stop(void)
{
    TWCR = _BV(TWINT) | _BV(TWSTO) | _BV(TWEN);
    while (TWCR & _BV(TWSTO)) { }            // STOP 이 나갈 때까지
}

static int16_t rtc_seconds(void)             // 실패하면 -1
{
    int16_t r = -1;
    uint8_t bcd;
    if (twi_start((DS3231_ADDR << 1) | TW_WRITE)) goto out;
    if (twi_write(0x00))                      goto out;   // 초 레지스터
    if (twi_start((DS3231_ADDR << 1) | TW_READ))  goto out;
    bcd = twi_read(0);                                     // 1바이트만 → NACK
    r = (int16_t)((bcd >> 4) * 10 + (bcd & 0x0F));         // BCD → 10진
out:
    twi_stop();
    return r;
}

int main(void)
{
    twi_init();
    DDRB |= _BV(DDB5);
    int16_t last = -1;
    for (;;) {
        int16_t s = rtc_seconds();
        if (s < 0) { PORTB |= _BV(PORTB5); continue; }   // 장치 없음 → LED 켜진 채
        if (s != last) { last = s; PINB = _BV(PINB5); }   // 초가 바뀔 때마다 토글
    }
}
이 드라이버의 약점 — 무한 대기. twi_wait() 는 버스가 고장 나면(선이 빠지거나 슬레이브가 SDA 를 LOW 로 잡고 멈추면) 영원히 돌아오지 않습니다. 양산 코드는 a05 의 millis() 로 타임아웃을 두고, 실패하면 SCL 을 GPIO 로 9번 흔들어 버스를 푸는 버스 복구 절차를 넣습니다 — 통신 · 드라이버 탭의 주제입니다.

spi.c — 1바이트 보내고 1바이트 받기

// spi_master.c — D13=SCK(PB5), D12=MISO(PB4), D11=MOSI(PB3), D10=SS(PB2)
#define F_CPU 16000000UL
#include <avr/io.h>
#include <stdint.h>

#define CS_LOW()  (PORTB &= ~_BV(PORTB2))
#define CS_HIGH() (PORTB |=  _BV(PORTB2))

static void spi_init(void)
{
    // ★ SS(PB2)를 반드시 출력으로 — 입력인 채 LOW 가 되면 슬레이브 모드로 떨어짐
    DDRB |= _BV(DDB5) | _BV(DDB3) | _BV(DDB2);
    CS_HIGH();
    SPCR  = _BV(SPE) | _BV(MSTR) | _BV(SPR0);   // 켜기 · 마스터 · 모드 0 · f/16 = 1 MHz
    SPSR &= ~_BV(SPI2X);
}

static uint8_t spi_xfer(uint8_t out)            // SPI 는 보내는 동시에 받습니다
{
    SPDR = out;
    while (!(SPSR & _BV(SPIF))) { }
    return SPDR;
}

int main(void)
{
    spi_init();
    for (;;) {
        CS_LOW();
        uint8_t id = spi_xfer(0x9F);           // 예: SPI 플래시의 JEDEC ID 명령
        id = spi_xfer(0x00);                   // 더미를 보내야 응답이 들어옴
        CS_HIGH();
        (void)id;
    }
}

2 KB SRAM 아끼기 — PROGMEM 과 스택-힙 충돌

서버에서는 메모리가 GB 단위라 문자열 상수가 어디 놓이는지 신경 쓸 일이 없습니다. ATmega328P 의 SRAM 은 2048 바이트 — 이 문단의 글자 수보다 적습니다. 게다가 하버드 구조라 상수 문자열도 기본적으로 SRAM 에 복사됩니다. 어디에 무엇이 놓이는지, 스택과 힙이 어떻게 부딪히는지, Arduino 의 F() 가 무엇을 하는지 정확히 봅니다.

SRAM 배치 — 힙은 위로, 스택은 아래로 자랍니다. MMU 도 보호 페이지도 없어서 둘이 만나도 아무 경고 없이 서로의 값을 조용히 덮어씁니다.
좌우 대조 — AVR 에서 const 만으로는 SRAM 을 못 아낍니다. Flash 에 남기려면 PROGMEM 으로 자리를 지정하고 전용 함수로 읽어야 합니다.

PROGMEM 실전 — 문자열 · 표 · 문자열 표

// progmem_demo.c — a07 의 uart_putc 와 함께 링크
#define F_CPU 16000000UL
#include <avr/io.h>
#include <avr/pgmspace.h>
#include <stdint.h>

void uart_putc(uint8_t c);                 // a07 uart_irq.c

// ① 문자열 하나
static const char banner[] PROGMEM = "Temperature logger v1\r\n";

// ② 숫자 표 — 큰 룩업 테이블일수록 효과가 큽니다
static const uint8_t gamma8[16] PROGMEM = {
    0, 1, 2, 4, 7, 11, 16, 22, 29, 37, 46, 56, 67, 80, 93, 110
};

// ③ 문자열들의 표 — 표 자체도, 각 문자열도 Flash 에
static const char s_ok[]  PROGMEM = "OK";
static const char s_err[] PROGMEM = "ERROR";
static const char *const s_msgs[] PROGMEM = { s_ok, s_err };

static void uart_puts_P(const char *p)     // _P = "Flash 주소를 받는다"는 관례
{
    char c;
    while ((c = (char)pgm_read_byte(p++)) != '\0') uart_putc((uint8_t)c);
}

void demo(uint8_t i)
{
    uart_puts_P(banner);
    uint8_t g = pgm_read_byte(&gamma8[i & 15]);
    (void)g;
    const char *m = (const char *)pgm_read_word(&s_msgs[i & 1]);  // 포인터도 Flash 에서 읽기
    uart_puts_P(m);
    uart_puts_P(PSTR("\r\n"));             // PSTR = 그 자리에서 PROGMEM 문자열 리터럴
}
가장 흔한 버그: PROGMEM 데이터를 그냥 읽기. banner[0] 처럼 일반 접근을 하면 컴파일 오류 없이 같은 번호의 SRAM 주소를 읽어 엉뚱한 값이 나옵니다. GNU C 의 const __flash char msg[] 를 쓰면 컴파일러가 알아서 LPM 으로 읽어 주지만(C 전용, C++ 불가), 이식성 때문에 PROGMEM 이 더 흔합니다.

① 지금 이 순간의 여유 — free_ram()

#include <stdint.h>

extern char  __heap_start;      // 링커 심볼: 힙이 시작하는 곳 (.bss 끝)
extern char *__brkval;          // avr-libc malloc: 지금 힙의 끝 (안 썼으면 0)

int free_ram(void)
{
    char top;                   // 이 지역 변수의 주소 ≈ 현재 스택 끝
    return (int)(&top - (__brkval ? __brkval : &__heap_start));
}

// 겹친 순간의 최악값은 놓칩니다 → ② 스택 칠하기

② 최악의 여유 — 스택 칠하기

#include <stdint.h>

extern uint8_t _end;            // 링커 심볼: .bss/.noinit 의 끝
extern uint8_t __stack;         // 스택 꼭대기 (기본값 RAMEND = 0x08FF)

// .init3 = 스택 포인터와 r1(=0) 설정이 끝난 직후, main 이전에 실행되는 구간
void stack_paint(void) __attribute__((naked, used, section(".init3")));
void stack_paint(void)
{
    uint8_t *p = &_end;
    while (p <= &__stack) *p++ = 0xC5;   // 아직 스택에 아무것도 없을 때 칠함
}

uint16_t stack_never_used(void)          // 한 번도 덮이지 않은 바이트 수
{
    const uint8_t *p = &_end;
    uint16_t n = 0;
    while (p <= &__stack && *p == 0xC5) { p++; n++; }
    return n;                            // 힙(malloc)을 안 쓰는 프로그램 기준
}

스택 넘침의 증상은 '이상한 동작'입니다. 전역 변수가 저절로 바뀌거나, 함수가 엉뚱한 곳으로 돌아가 리셋되거나, 특정 메뉴에서만 멈춥니다. 서버라면 StackOverflowError 가 났을 자리에서 아무 오류 없이 다른 데이터가 망가집니다. avr-size 의 data + bss 가 1.5 KB 를 넘으면 위험 신호로 보세요. avr-libc 의 malloc 은 스택과 __malloc_margin(기본 32 바이트)만큼만 거리를 둡니다.

EEPROM · 퓨즈 · 부트로더 — 칩의 설정과 생애

전원이 꺼져도 남는 작은 저장소 EEPROM, 칩의 클럭과 부팅 방식을 정하는 퓨즈, 그리고 USB 케이블 하나로 업로드를 가능하게 하는 부트로더. 셋 다 "한 번 잘못 쓰면 오래 간다"는 공통점이 있습니다. 특히 퓨즈는 잘못 쓰면 칩이 응답하지 않는 상태(벽돌)가 되므로, 무엇이 위험한지부터 정확히 압니다.

EEPROM — 설정 저장 (완전한 코드)

// eeprom_cfg.c — 부팅 횟수와 설정을 EEPROM 에 · ATmega328P @16MHz
#define F_CPU 16000000UL
#include <avr/io.h>
#include <avr/eeprom.h>
#include <stdint.h>

typedef struct {
    uint8_t  version;          // 구조가 바뀌면 올림 → 옛 데이터 무시
    uint8_t  brightness;
    uint16_t log_interval_s;
    uint8_t  checksum;         // 나머지 바이트의 합의 보수
} Config;

// EEMEM = EEPROM 주소 공간에 배치 (.eeprom 섹션 → app.eep 파일)
static Config   EEMEM ee_cfg;
static uint16_t EEMEM ee_boot_count;

static uint8_t cfg_sum(const Config *c)
{
    const uint8_t *p = (const uint8_t *)c;
    uint8_t s = 0;
    for (uint8_t i = 0; i < sizeof(Config) - 1; i++) s += p[i];
    return (uint8_t)~s;
}

static void cfg_load(Config *c)
{
    eeprom_read_block(c, &ee_cfg, sizeof *c);
    if (c->version != 1 || c->checksum != cfg_sum(c)) {   // 처음이거나 깨짐
        c->version = 1; c->brightness = 128; c->log_interval_s = 60;
    }
}

static void cfg_save(Config *c)
{
    c->checksum = cfg_sum(c);
    eeprom_update_block(c, &ee_cfg, sizeof *c);  // ★ 바뀐 바이트만 실제로 씀
}

int main(void)
{
    Config cfg;
    cfg_load(&cfg);

    uint16_t boots = eeprom_read_word(&ee_boot_count);
    if (boots == 0xFFFF) boots = 0;               // 지워진 EEPROM 은 0xFF
    eeprom_update_word(&ee_boot_count, (uint16_t)(boots + 1));

    cfg.brightness = 200;
    cfg_save(&cfg);
    for (;;) { }
}

sleepy.c — 8 초마다 깨어 5 ms 일하기

// sleepy.c — 워치독 인터럽트로 주기 기상 · ATmega328P @16MHz
#define F_CPU 16000000UL
#include <avr/io.h>
#include <avr/interrupt.h>
#include <avr/sleep.h>
#include <avr/wdt.h>
#include <avr/power.h>
#include <util/delay.h>

ISR(WDT_vect) { }                       // 깨우기만 하면 됨 (비어 있어도 필수)

static void wdt_interrupt_8s(void)
{
    cli();
    wdt_reset();
    MCUSR  &= ~_BV(WDRF);               // WDRF 가 1 이면 WDE 를 끌 수 없음
    WDTCSR  =  _BV(WDCE) | _BV(WDE);     // 변경 허가 — 4 클럭 안에 다음 쓰기 (-Os 에서 성립)
    WDTCSR  =  _BV(WDIE) | _BV(WDP3) | _BV(WDP0);   // 인터럽트 모드만, 약 8 s
    sei();
}

static void sleep_power_down(void)      // avr-libc 문서의 권장 순서
{
    set_sleep_mode(SLEEP_MODE_PWR_DOWN);
    cli();
    sleep_enable();
    sleep_bod_disable();                // 잠든 동안 BOD 끄기 (약 20 µA 절약)
    sei();                              // sei 직후 한 명령은 인터럽트 없이 실행
    sleep_cpu();                        // → 여기서 잠듦 · WDT ISR 후 다음 줄부터
    sleep_disable();
}

int main(void)
{
    ADCSRA &= ~_BV(ADEN);               // ADC 먼저 끄고 (PRR 보다 앞에)
    ACSR   |=  _BV(ACD);                // 아날로그 비교기 끄기
    power_all_disable();                // PRR: TWI·타이머·SPI·USART·ADC 클럭 차단

    DDRB  |= _BV(DDB5);
    PORTC |= 0x3F;                      // 안 쓰는 입력은 풀업 — 떠 있는 입력은 전류를 먹음
    PORTD |= 0xFF;

    wdt_interrupt_8s();
    for (;;) {
        PORTB |=  _BV(PORTB5);          // (일하는 척) 5 ms
        _delay_ms(5);
        PORTB &= ~_BV(PORTB5);
        sleep_power_down();
    }
}

지금까지 만든 부품 — 1 ms 틱(a05) · UART 링 버퍼와 printf(a07) · ADC(a08) · EEPROM(a11) — 을 한 파일에 모아 1분마다 온도를 재서 EEPROM 에 쌓고, 시리얼로 명령을 받아 내보내는 로거를 만듭니다. 그리고 마지막으로 Arduino 의 digitalWrite 를 뜯어서, 우리가 직접 쓴 한 줄과 무엇이 다른지 클럭 단위로 비교합니다.

스윔레인 — 실시간성이 필요한 일(틱 · 수신)만 ISR 에, 3.3 ms 씩 걸리는 EEPROM 쓰기 같은 느린 일은 main 에 둡니다. 그래도 수신은 링 버퍼가 받아 두므로 하나도 잃지 않습니다.

logger.c — 한 파일로 된 완전한 로거 (LM35 → A0, 시리얼 57600)

// logger.c — 온도 로거 · ATmega328P @16MHz (Arduino Uno R3)
// 배선: LM35 +Vs → 5V, GND → GND, Vout → A0(PC0)
// 빌드: avr-gcc -mmcu=atmega328p -DF_CPU=16000000UL -Os -std=gnu11 -Wall -Wextra -o logger.elf logger.c
#ifndef F_CPU
#define F_CPU 16000000UL
#endif
#include <avr/io.h>
#include <avr/interrupt.h>
#include <avr/eeprom.h>
#include <avr/pgmspace.h>
#include <util/atomic.h>
#include <stdint.h>
#include <stdio.h>

#define LOG_PERIOD_MS 60000UL
#define SLOTS  512u              // 1024 B ÷ 2 B
#define EMPTY  0xFFFFu           // 지워진 EEPROM
#define HEAD   0xFFFEu           // "다음에 쓸 칸" 표시
#define BIAS   2000              // 저장값 = 온도×10 + 2000 (음수도 담기 위해)

/* ───────── 1 ms 틱 (a05) ───────── */
static volatile uint32_t g_ms;
ISR(TIMER0_COMPA_vect) { g_ms++; }

static void tick_init(void)
{
    TCCR0A = _BV(WGM01);                    // CTC
    TCCR0B = _BV(CS01) | _BV(CS00);         // ÷64
    OCR0A  = 249;                           // 1 ms
    TIMSK0 = _BV(OCIE0A);
}
static uint32_t millis(void)
{
    uint32_t m;
    ATOMIC_BLOCK(ATOMIC_RESTORESTATE) { m = g_ms; }
    return m;
}

/* ───────── UART + 링 버퍼 + printf (a07) ───────── */
#define RB 64u
static volatile uint8_t rx_buf[RB], tx_buf[RB];
static volatile uint8_t rx_h, rx_t, tx_h, tx_t;

ISR(USART_RX_vect)
{
    uint8_t c = UDR0;
    uint8_t n = (uint8_t)((rx_h + 1u) & (RB - 1u));
    if (n != rx_t) { rx_buf[rx_h] = c; rx_h = n; }
}
ISR(USART_UDRE_vect)
{
    if (tx_h == tx_t) { UCSR0B &= ~_BV(UDRIE0); return; }
    UDR0 = tx_buf[tx_t];
    tx_t = (uint8_t)((tx_t + 1u) & (RB - 1u));
}
static void uart_init(void)                 // 57600 · U2X → UBRR 34, 오차 −0.79%
{
    UBRR0  = 34;
    UCSR0A = _BV(U2X0);
    UCSR0C = _BV(UCSZ01) | _BV(UCSZ00);
    UCSR0B = _BV(RXEN0) | _BV(TXEN0) | _BV(RXCIE0);
}
static void uart_putc(uint8_t c)
{
    uint8_t n = (uint8_t)((tx_h + 1u) & (RB - 1u));
    while (n == tx_t) { }
    tx_buf[tx_h] = c;
    tx_h = n;
    UCSR0B |= _BV(UDRIE0);
}
static int uart_getc(void)
{
    if (rx_h == rx_t) return -1;
    uint8_t c = rx_buf[rx_t];
    rx_t = (uint8_t)((rx_t + 1u) & (RB - 1u));
    return c;
}
static int put(char c, FILE *f) { (void)f; if (c == '\n') uart_putc('\r'); uart_putc((uint8_t)c); return 0; }
static FILE uart_out = FDEV_SETUP_STREAM(put, NULL, _FDEV_SETUP_WRITE);

/* ───────── ADC + LM35 (a08) ───────── */
static uint16_t adc_read(void)
{
    ADCSRA |= _BV(ADSC);
    while (ADCSRA & _BV(ADSC)) { }
    return ADC;
}
static void adc_init(void)
{
    ADMUX  = _BV(REFS1) | _BV(REFS0);       // 내부 1.1 V 기준 · ADC0 → 1 LSB ≈ 1.07 mV
    ADCSRA = _BV(ADEN) | _BV(ADPS2) | _BV(ADPS1) | _BV(ADPS0);
    DIDR0  = _BV(ADC0D);
    (void)adc_read();                       // 기준을 바꾼 뒤 첫 결과는 버림
}
static int16_t read_temp_x10(void)          // 0.1 °C 단위 (LM35 기본 회로: 0 ~ 110 °C)
{
    uint32_t sum = 0;
    for (uint8_t i = 0; i < 16; i++) sum += adc_read();
    uint16_t raw = (uint16_t)(sum / 16u);
    // LM35 = 10 mV/°C → mV 값이 곧 '°C × 10'.  mV = raw × 1100 / 1024
    return (int16_t)((uint32_t)raw * 1100u / 1024u);   // 1023×1100 은 16비트를 넘음
}
static void print_t(int16_t t)              // %f 없이 소수 한 자리
{
    if (t < 0) { putchar('-'); t = (int16_t)-t; }
    printf("%d.%d", t / 10, t % 10);
}

/* ───────── EEPROM 순환 기록 (a11) ───────── */
static uint16_t g_head;                     // HEAD 표시가 있는 칸 번호

static uint16_t *slot(uint16_t i) { return (uint16_t *)(uintptr_t)(i * 2u); }  // EEPROM 주소

static void log_find_head(void)             // 부팅 때 한 번: 어디까지 썼나 찾기
{
    uint16_t first_empty = SLOTS;
    for (uint16_t i = 0; i < SLOTS; i++) {
        uint16_t v = eeprom_read_word(slot(i));
        if (v == HEAD) { g_head = i; return; }          // 표시가 둘이면 낮은 번호
        if (v == EMPTY && first_empty == SLOTS) first_empty = i;
    }
    g_head = (first_empty == SLOTS) ? 0 : first_empty;  // 새 칩이면 0 번부터
    eeprom_update_word(slot(g_head), HEAD);
}
static void log_append(int16_t t_x10)
{
    uint16_t next = (uint16_t)((g_head + 1u) % SLOTS);
    eeprom_update_word(slot(next), HEAD);                       // ① 다음 칸에 표시 먼저
    eeprom_update_word(slot(g_head), (uint16_t)(t_x10 + BIAS)); // ② 그다음 데이터
    g_head = next;                          // ①과 ② 사이에 전원이 나가도 복구됨 (본문)
}
static void log_dump(void)                  // 오래된 것부터
{
    uint16_t n = 0;
    for (uint16_t k = 1; k < SLOTS; k++) {
        uint16_t v = eeprom_read_word(slot((uint16_t)((g_head + k) % SLOTS)));
        if (v == EMPTY || v == HEAD) continue;
        printf("%u,", n++);
        print_t((int16_t)((int32_t)v - BIAS));
        putchar('\n');
    }
    printf_P(PSTR("# %u records\n"), n);
}
static void log_clear(void)                 // 약 3.5 초 걸림 (512 × 2 바이트 쓰기)
{
    for (uint16_t i = 0; i < SLOTS; i++) eeprom_update_word(slot(i), EMPTY);
    g_head = 0;
    eeprom_update_word(slot(0), HEAD);
}

int main(void)
{
    tick_init();
    uart_init();
    adc_init();
    stdout = &uart_out;
    sei();

    log_find_head();
    printf_P(PSTR("\nlogger ready (d=dump n=now c=clear)\n"));

    uint32_t last = millis();
    for (;;) {
        if ((uint32_t)(millis() - last) >= LOG_PERIOD_MS) {
            last += LOG_PERIOD_MS;
            log_append(read_temp_x10());
        }
        switch (uart_getc()) {
            case 'n': print_t(read_temp_x10()); printf_P(PSTR(" C\n")); break;
            case 'd': log_dump();  break;
            case 'c': log_clear(); printf_P(PSTR("cleared\n")); break;
            default:  break;                // -1(없음) 포함
        }
    }
}

결정근거 (계산)
1.1 V 내부 기준LM35 는 25 °C 에서 250 mV. 5 V 기준이면 1 LSB = 0.49 °C, 1.1 V 면 0.107 °C
16회 평균16 × 104 µs ≈ 1.7 ms — 노이즈 감소, 시간은 무시할 수준
정수 ×10%f 를 쓰면 printf_flt 로 Flash 수 KB 증가
57600 · U2X오차 −0.79% (115200 은 +2.12%) — a07 표
칸 512 개 순환칸마다 한 바퀴에 2번 씀 → 100 000 ÷ 2 × 512 분 ≈ 48.7 년
(비교) 고정 칸에 위치 저장1분마다 같은 칸 → 100 000 분 ≈ 69 일
계산 검산 예 — 25.0 °C → 250 mV → raw = 250 × 1024 / 1100 = 232(내림) → 232 × 1100 / 1024 = 249(내림) → "24.9". 두 번 내림해서 0.1 °C 가 깎이는 것은 양자화 오차(±0.107 °C) 안입니다. 순환 기록의 동작(덮어쓰기 · 전원 차단 복구)은 같은 알고리즘을 PC 에서 시뮬레이션해 확인했습니다.

전원이 쓰기 중간에 나가면

log_append 는 ① 다음 칸에 HEAD 표시 → ② 지금 칸에 데이터 순서로 씁니다. ①과 ② 사이에 전원이 나가면 HEAD 표시가 두 개 남습니다. 부팅 때 log_find_head 는 번호가 낮은 쪽을 고르므로, 보통은 "② 를 안 한 칸"이 다시 HEAD 가 되어 그 기록 하나만 없던 일이 됩니다.

끝 칸(511)에서 0 번으로 넘어가는 순간이라면 0 번이 HEAD 로 뽑히고, 511 번에 남은 낡은 표시는 덤프에서 건너뛰다가 다음 바퀴에 자연히 덮입니다. 어느 경우에도 깨진 값이 데이터로 읽히는 일은 없습니다.

순서를 반대로(② → ①) 하면 사이에서 전원이 나갔을 때 HEAD 표시가 하나도 없어 기록 위치를 잃습니다. EEPROM · Flash 에 쓰는 코드는 언제나 "어느 줄 다음에 전원이 나가도 되는가"를 한 줄씩 물어야 합니다.

    if (port == NOT_A_PIN) return;              // ④ 잘못된 핀 번호 방어

    // PWM 이 걸린 핀이면 타이머에서 떼어 냄
    if (timer != NOT_ON_TIMER) turnOffPWM(timer);   // ⑤ switch 문

    out = portOutputRegister(port);             // ⑥ 포트 → 레지스터 주소 표 조회

    uint8_t oldSREG = SREG;                     // ⑦ 인터럽트 끄기
    cli();
    if (val == LOW) *out &= ~bit;               // ⑧ 포인터로 읽고-고치고-쓰기
    else            *out |=  bit;
    SREG = oldSREG;                             //    인터럽트 상태 복원
}

핀 번호가 실행 중에 정해지는 변수라는 가정 위에서 쓰여 있습니다. 그래서 매번 "13 번 핀은 어느 포트의 몇 번 비트인가"를 Flash 의 표(pins_arduino.h 의 PROGMEM 배열)에서 찾고, 그 결과 주소가 상수가 아니니 sbi 를 못 쓰고 포인터 읽기-쓰기가 되며, 그 3단계가 ISR 과 엉키지 않도록 cli 까지 합니다.

for (;;) {
    PORTB |=  _BV(PORTB5);   // sbi   2 클럭
    PORTB &= ~_BV(PORTB5);   // cbi   2 클럭
}                            // rjmp  2 클럭 → 6 클럭 = 2.67 MHz

// C — PINx 토글 (한 번 쓰기가 반 주기)
for (;;) PINB = _BV(PINB5);  // out 1 + rjmp 2 = 3 클럭마다 반전
                             // → 6 클럭 주기 = 2.67 MHz, 듀티 50%
