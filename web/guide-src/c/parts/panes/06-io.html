통신 지도 — UART · RS-485 · I²C · SPI · CAN · USB · 1-Wire, 무엇을 언제 쓰나

MCU 의 통신 방식은 일곱 가지 정도면 현업의 95% 를 덮습니다. 모두 "바이트를 옮긴다"는 점은 같고, 다른 것은 선 몇 가닥 · 얼마나 빠르게 · 얼마나 멀리 · 몇 대를 · 누가 말을 시작하나 다섯 가지뿐입니다. 서버로 치면 프로세스 간 통신 수단을 고르는 일과 같습니다 — 같은 머신이면 공유 메모리(SPI), 같은 랙이면 유닉스 소켓(I²C), 건물 반대편이면 TCP(RS-485 · CAN), 사람 PC 와 연결이면 HTTP(USB)처럼 거리와 규모가 답을 정합니다.

매트릭스 — 속도와 거리는 맞바꾸는 관계입니다. 멀리 가려면 차동 신호(RS-485 · CAN), 빠르려면 짧은 배선(SPI).

UART 깊이 — 프레임 · 오차 허용 · 흐름 제어, 그리고 RS-485 방향 전환

UART 의 기초(시작 비트 · 데이터 · 정지 비트, 보레이트 레지스터)는 AVR 탭 a07 과 STM32 탭 m07 에서 다뤘습니다. 여기서는 현장에서 실제로 부딪히는 것들을 봅니다 — 보레이트가 몇 % 틀려도 되나, 패리티를 켜면 왜 HAL 설정이 9비트가 되나, RTS/CTS 는 누가 누구에게 거는 신호인가, RS-232 포트를 핀에 꽂으면 왜 안 되나, 그리고 RS-485 에서 송신을 끝낸 뒤 언제 수신으로 돌아서야 하나. 마지막 것은 산업 현장 통신 장애의 단골 원인입니다.

파형 · 샘플 위치 — 수신기는 시작 에지 하나로만 박자를 맞춥니다. 그래서 오차가 프레임 끝으로 갈수록 커집니다.

보레이트 오차 — 얼마까지 괜찮나

오차 예산 = 송신 측 오차 + 수신 측 오차 (방향이 반대면 더해짐)

이론: 시작 에지 기준, 마지막(정지) 비트 가운데까지 N − 0.5 비트
      그 사이 누적 오차가 반 비트를 넘으면 안 됨
      10비트(8N1) : 0.5 / 9.5  = 5.26 %
      11비트(8E1) : 0.5 / 10.5 = 4.76 %

실제(RM0390, 16배 오버샘플링 · 8비트 · 분주 소수부 0): 수신 허용 3.75 %
      (ONEBIT=1 이면 4.375 %, 소수부가 있으면 약 3.3 %)
      — 샘플 3번 다수결 · 에지 검출 지연 몫을 뺀 값

F446 USART2 (APB1 45 MHz) 115200 → BRR 0x187, 오차 −0.096 %
F446 USART1 (APB2 90 MHz) 115200 → BRR 0x30D, 오차 +0.032 %
HSI(내부 RC, ±1 % 공장 보정)만 쓰면 온도에 따라 수 % 까지 → 외부 크리스털
실무 기준은 양쪽 합 ±2 % 이내입니다. 상대가 USB-UART 브리지면 그쪽 오차는 거의 0 이지만, 상대도 MCU 내부 RC 면 각자 1~2 % 가 겹칩니다. 높은 보레이트(921600 · 1 M)일수록 정수 분주가 어려워 오차가 커지니 쓰려는 보레이트마다 BRR 오차를 계산해 두세요(m07 의 식).

RS-485 반이중 — 말이 끝난 순간을 정확히 알기 🔴 실무

RS-485 는 두 선(A/B)을 여러 장치가 공유하는 차동 버스입니다. 한 번에 한 장치만 선을 구동할 수 있어서, MCU 는 MAX3485 같은 트랜시버의 DE(Driver Enable) 핀을 올려 "지금 내가 말한다"를 알리고, 다 말하면 내려서 듣는 모드로 돌아갑니다. 문제는 언제 내리느냐입니다. HAL 의 "송신 완료"가 정확히 무엇을 뜻하는지 알아야 합니다.

타임라인 — TXE = 레지스터가 비었다, TC = 선이 비었다. 방향 전환은 언제나 뒤의 것입니다.

rs485.c — DMA 송신 + TC 콜백에서 DE 내리기

#include "main.h"

extern UART_HandleTypeDef huart1;       /* PA9 TX · PA10 RX · 8E1 */
#define DE_PORT GPIOA
#define DE_PIN  GPIO_PIN_8              /* 트랜시버 DE 와 /RE 를 묶음 */

static volatile uint8_t tx_busy;

HAL_StatusTypeDef rs485_send(const uint8_t *p, uint16_t n)
{
    if (tx_busy) return HAL_BUSY;
    tx_busy = 1;
    HAL_GPIO_WritePin(DE_PORT, DE_PIN, GPIO_PIN_SET);      /* 말하기 시작 */
    HAL_StatusTypeDef st = HAL_UART_Transmit_DMA(&huart1, p, n);
    if (st != HAL_OK) {                                     /* 실패하면 원상복구 */
        HAL_GPIO_WritePin(DE_PORT, DE_PIN, GPIO_PIN_RESET);
        tx_busy = 0;
    }
    return st;
}

/* F4 HAL: DMA 가 마지막 바이트를 DR 에 넣으면 TCIE 를 켜고,
   TC(정지 비트까지 끝)에서 이 콜백을 부릅니다. _IT 송신도 같습니다. */
void HAL_UART_TxCpltCallback(UART_HandleTypeDef *huart)
{
    if (huart == &huart1) {
        HAL_GPIO_WritePin(DE_PORT, DE_PIN, GPIO_PIN_RESET);  /* 듣기로 */
        tx_busy = 0;
    }
}
버퍼 수명 — p 는 콜백이 올 때까지 살아 있어야 합니다(m07). 그리고 DE 를 내리기 전에 상대가 응답을 시작하면 첫 바이트를 놓치므로, Modbus 같은 프로토콜은 응답 전 최소 대기(p12 의 3.5 문자 시간)를 규정해 둡니다.

트랜시버3.3 V: MAX3485 · SP3485 · THVD 계열 / 5 V: MAX485
/RE 핀DE 와 묶으면 송신 중 수신 꺼짐. 따로 두고 켜 두면 내 송신이 에코로 들어옴 → 충돌 감지에 활용

정리 — 오차 예산은 양쪽 합 ±2 % 이내, 패리티를 켜면 WordLength 를 9B 로, RS-232 는 반드시 트랜시버를 거칩니다. RS-485 의 DE 는 TC(선이 빔)에서 내리고 — F4 HAL 에선 HAL_UART_TxCpltCallback 이 그 시점입니다.
IO 03

프레이밍 · 프로토콜 설계 — 바이트 스트림을 메시지로 자르기, COBS 와 CRC-16

UART 는 TCP 처럼 경계 없는 바이트 스트림입니다. "온도=25" 를 보냈다고 상대가 한 번에 받는다는 보장이 없고, 잡음 한 번이면 비트가 뒤집히며, 전원이 켜지는 순간 메시지 한가운데부터 듣기 시작할 수도 있습니다. 그래서 모든 통신 프로토콜은 세 가지를 정합니다 — 어디서 시작해 어디서 끝나나(프레이밍), 깨졌는지 어떻게 아나(CRC), 엇갈렸을 때 어떻게 다시 맞추나(재동기화). 서버에서 길이 접두 + 체크섬을 붙인 TCP 프로토콜을 직접 짜 본 적이 있다면 같은 문제입니다.

SLIP — 가장 짧은 바이트 스터핑

#define SLIP_END     0xC0
#define SLIP_ESC     0xDB
#define SLIP_ESC_END 0xDC
#define SLIP_ESC_ESC 0xDD

/* put() 은 한 바이트를 UART 송신 큐에 넣는 함수 */
void slip_send(const uint8_t *p, size_t n, void (*put)(uint8_t))
{
    put(SLIP_END);                    /* 앞에도 END — 앞선 쓰레기를 끊음 */
    for (size_t i = 0; i < n; i++) {
        if (p[i] == SLIP_END)      { put(SLIP_ESC); put(SLIP_ESC_END); }
        else if (p[i] == SLIP_ESC) { put(SLIP_ESC); put(SLIP_ESC_ESC); }
        else                       put(p[i]);
    }
    put(SLIP_END);
}
/* 예: 11 C0 22  →  C0 11 DB DC 22 C0 */
수신 측은 END 를 만나면 프레임을 닫고, ESC 다음 바이트를 원래 값으로 되돌립니다. 데이터에 0xC0 이 많으면 크기가 들쭉날쭉해져 버퍼 크기를 최악(2배)으로 잡아야 한다는 것이 COBS 가 나온 이유입니다.

COBS — 0 을 지우고 "다음 0 까지 거리"를 적는다 🟡 중급

메모리 변환 — 코드 바이트가 사슬처럼 다음 0 을 가리킵니다. 그래서 수신 측은 0x00 하나로 경계를 찾습니다.

cobs.c — 인코더 · 디코더 (표준 COBS)

#include <stddef.h>
#include <stdint.h>

/* dst 는 n + n/254 + 2 바이트 이상. 반환 = 인코딩 길이(끝 0x00 미포함) */
size_t cobs_encode(const uint8_t *src, size_t n, uint8_t *dst)
{
    size_t  w = 1, code_i = 0;          /* code_i: 코드 바이트를 적을 자리 */
    uint8_t code = 1;
    for (size_t r = 0; r < n; r++) {
        if (src[r] != 0) { dst[w++] = src[r]; code++; }
        if (src[r] == 0 || code == 0xFF) {   /* 0 을 만났거나 254개 꽉 참 */
            dst[code_i] = code;
            code   = 1;
            code_i = w;
            if (src[r] == 0 || r + 1 < n) w++;  /* 마지막 꽉 찬 블록 뒤엔 자리 안 만듦 */
        }
    }
    dst[code_i] = code;
    return w;
}

/* src = 끝 0x00 을 뺀 프레임. 반환 = 디코딩 길이, 형식 오류면 -1 */
int cobs_decode(const uint8_t *src, size_t n, uint8_t *dst)
{
    size_t r = 0, w = 0;
    while (r < n) {
        uint8_t code = src[r++];
        if (code == 0) return -1;             /* 프레임 안의 0 은 있을 수 없음 */
        for (uint8_t i = 1; i < code; i++) {
            if (r >= n || src[r] == 0) return -1;
            dst[w++] = src[r++];
        }
        if (code != 0xFF && r < n) dst[w++] = 0;
    }
    return (int)w;
}

CRC-16/CCITT — 표 한 장으로 바이트당 한 번 🟡 중급

crc16.c — 비트 방식 · 표 방식 (같은 결과)

/* CRC-16/CCITT-FALSE: 다항식 0x1021, 초깃값 0xFFFF, 반사 없음, 최종 XOR 없음 */
uint16_t crc16_bitwise(const uint8_t *p, size_t n)
{
    uint16_t crc = 0xFFFF;
    while (n--) {
        crc ^= (uint16_t)(*p++ << 8);
        for (int k = 0; k < 8; k++)
            crc = (crc & 0x8000u) ? (uint16_t)((crc << 1) ^ 0x1021u)
                                  : (uint16_t)(crc << 1);
    }
    return crc;
}

static uint16_t crc_tab[256];          /* 512 B — const 로 만들면 Flash 에 */

void crc16_init(void)
{
    for (uint16_t i = 0; i < 256; i++) {
        uint16_t c = (uint16_t)(i << 8);
        for (int k = 0; k < 8; k++)
            c = (c & 0x8000u) ? (uint16_t)((c << 1) ^ 0x1021u) : (uint16_t)(c << 1);
        crc_tab[i] = c;               /* tab[0..3] = 0000 1021 2042 3063 */
    }
}

/* 스트리밍용 — 파서가 바이트 하나 받을 때마다 부름 */
static inline uint16_t crc16_update(uint16_t crc, uint8_t b)
{
    return (uint16_t)((crc << 8) ^ crc_tab[((crc >> 8) ^ b) & 0xFFu]);
}

/* 자가 시험 — 부팅 때 한 번 돌려 두면 표가 깨진 것도 잡힘 */
int crc16_selftest(void)
{
    static const uint8_t v[] = "123456789";
    uint16_t c = 0xFFFF;
    for (size_t i = 0; i < 9; i++) c = crc16_update(c, v[i]);
    return c == 0x29B1 && crc16_bitwise(v, 9) == 0x29B1;
}

"CRC-16" 은 하나가 아닙니다 — 테스트 벡터로 구분

이름다항식 · 초깃값 · 반사"123456789"

XMODEM0x1021 · 0x0000 · 없음0x31C3

상대 문서에 "CRC-16" 이라고만 적혀 있으면 반드시 이 벡터 값을 물어보세요. 다항식이 같아도 초깃값 · 반사 · 최종 XOR 이 다르면 전혀 다른 값이 나옵니다. 위 세 값은 모두 node 로 계산해 확인했습니다(비트 방식 = 표 방식). 
왜 CRC 인가 (체크섬 합계 대비)
· 합계: 바이트 두 개가 서로 바뀌면 못 잡음 (01 02 ↔ 02 01)
· CRC-16: 16비트 이하 연속 오류(burst) 전부 · 홀수 비트 오류 전부
          그 밖은 1/65536 확률로만 놓침
· 속도: 표 방식은 바이트당 시프트 1 + 표 조회 1 + XOR 2
        STM32F4 의 내장 CRC 장치는 CRC-32(0x04C11DB7) 고정 — 16비트는 소프트웨어로

상태 머신 파서 — 길이 접두 프레임 + 타임아웃 재동기화 🔴 실무

상태 기계 — 타임아웃이 재동기화의 안전망입니다. 없으면 잘린 프레임 하나가 다음 정상 프레임까지 깨뜨립니다.

frame_parser.c

#define SOF          0xAAu
#define MAX_PAYLOAD  64u
#define GAP_MS       5u

typedef enum { ST_SOF, ST_LEN, ST_CMD, ST_DATA, ST_CRC_HI, ST_CRC_LO } pstate_t;

typedef struct {
    pstate_t st;
    uint8_t  len, cmd, n;
    uint8_t  buf[MAX_PAYLOAD];
    uint16_t crc, rx_crc;
    uint32_t last_ms;
    uint32_t err_crc, err_len, err_timeout;   /* 진단 카운터 — 꼭 남기세요 */
} parser_t;

extern void on_frame(uint8_t cmd, const uint8_t *p, uint8_t len);

void parser_feed(parser_t *p, uint8_t b, uint32_t now_ms)
{
    if (p->st != ST_SOF && (uint32_t)(now_ms - p->last_ms) > GAP_MS) {
        p->err_timeout++;
        p->st = ST_SOF;                       /* 끊긴 프레임 버림 */
    }
    p->last_ms = now_ms;

    switch (p->st) {
    case ST_SOF:
        if (b == SOF) p->st = ST_LEN;
        break;
    case ST_LEN:
        if (b > MAX_PAYLOAD) { p->err_len++; p->st = (b == SOF) ? ST_LEN : ST_SOF; break; }
        p->len = b; p->n = 0;
        p->crc = crc16_update(0xFFFF, b);     /* CRC 범위 = LEN..DATA */
        p->st  = ST_CMD;
        break;
    case ST_CMD:
        p->cmd = b;
        p->crc = crc16_update(p->crc, b);
        p->st  = p->len ? ST_DATA : ST_CRC_HI;
        break;
    case ST_DATA:
        p->buf[p->n++] = b;
        p->crc = crc16_update(p->crc, b);
        if (p->n == p->len) p->st = ST_CRC_HI;
        break;
    case ST_CRC_HI:
        p->rx_crc = (uint16_t)(b << 8);
        p->st = ST_CRC_LO;
        break;
    case ST_CRC_LO:
        p->rx_crc |= b;
        if (p->rx_crc == p->crc) on_frame(p->cmd, p->buf, p->len);
        else                     p->err_crc++;
        p->st = ST_SOF;
        break;
    }
}
/* 예: AA 03 10 01 02 03 85 48  → cmd 0x10, payload 01 02 03 */

같은 로직을 node 로 옮겨 30만 프레임 주입

· 5 % 는 앞에 쓰레기 3바이트 (간격 없이)
· 프레임 사이 간격 6 ms (> GAP_MS)

결과: 정상 프레임 270 009 중 269 982 수신 (99.99 %)
      깨진 프레임이 통과한 경우 0
      놓친 27개 = 쓰레기 속 0xAA 가 정상 프레임 앞부분을 삼킨 경우

마지막 줄이 이 절의 핵심입니다. 길이 접두 방식은 잘린 프레임 뒤에 곧바로 다음 프레임이 오면, 파서가 다음 프레임의 바이트를 앞 프레임의 데이터로 먹어 버립니다. 막는 방법은 셋 — ① 송신 측이 프레임 사이에 간격을 둔다(Modbus 방식) ② 타임아웃 ③ CRC 실패 시 버퍼를 한 바이트 뒤부터 다시 훑는다(가장 견고하지만 버퍼 필요). COBS 는 구조적으로 이 문제가 없습니다.
프로토콜에 꼭 넣을 것 — 버전 바이트(나중에 형식을 바꿀 수 있게) · 시퀀스 번호(유실 · 중복 탐지) · 응답에 요청 번호 되돌려 주기 · 최대 길이 명시. 서버 API 를 버전 없이 냈다가 고생한 경험과 똑같습니다.
정리 — 바이너리 메시지는 COBS + CRC-16(가장 견고) 또는 길이 접두 + CRC + 타임아웃(가장 흔함)으로 자릅니다. CRC 는 이름이 아니라 "123456789" 테스트 벡터로 맞추고, 파서는 상태 머신 + 진단 카운터로 짭니다.
IO 04

수신 버퍼 전략 — ISR 링 · DMA 순환 · 오버런 정책, 그리고 크기 계산

바이트는 하드웨어의 박자로 도착하고, 해석은 내 코드의 박자로 일어납니다. 둘 사이에 완충지대가 없으면 하나라도 늦는 순간 데이터가 사라집니다. 서버로 치면 소켓 수신 버퍼와 애플리케이션 사이의 큐입니다. 링 버퍼 자체의 원리(가득 참 판정 · 단일 생산자-단일 소비자)는 🥞 스택 · 큐 · 덱 탭과 C 실전 탭 c22 에서 다루고, 여기서는 통신 드라이버에 붙일 때의 결정 — 누가 채우나(ISR 인가 DMA 인가), 넘치면 무엇을 버리나, 몇 바이트면 충분한가 — 를 봅니다.

uart_rx_isr.c — 바이트 인터럽트 + 링 (LL 없이 레지스터로)

#include "main.h"

#define RX_SZ 512u                         /* 2의 거듭제곱 → % 대신 & */
static uint8_t           rx_buf[RX_SZ];
static volatile uint16_t rx_head;          /* ISR 만 씀 (생산자) */
static volatile uint16_t rx_tail;          /* main 만 씀 (소비자) */
volatile uint32_t rx_drop, rx_ore, rx_fe;  /* 진단 카운터 */

void USART2_IRQHandler(void)               /* RXNEIE 만 켠 상태 */
{
    uint32_t sr = USART2->SR;
    if (sr & (USART_SR_RXNE | USART_SR_ORE)) {
        uint8_t b = (uint8_t)USART2->DR;   /* SR 다음 DR 읽기 = RXNE·ORE·FE·NE 해제 */
        if (sr & USART_SR_ORE) rx_ore++;   /* 이 바이트 앞에서 최소 1바이트 잃음 */
        if (sr & (USART_SR_FE | USART_SR_NE)) { rx_fe++; return; }  /* 믿을 수 없는 바이트 */

        uint16_t h    = rx_head;
        uint16_t next = (uint16_t)((h + 1u) & (RX_SZ - 1u));
        if (next == rx_tail) { rx_drop++; return; }  /* 가득 참 → 새 것 버림 */
        rx_buf[h] = b;
        __COMPILER_BARRIER();              /* 데이터를 쓴 뒤에 head 를 공개 */
        rx_head = next;
    }
}

int rx_pop(uint8_t *out)                   /* main 루프 · 태스크에서 */
{
    uint16_t t = rx_tail;
    if (t == rx_head) return 0;
    *out = rx_buf[t];
    __COMPILER_BARRIER();                  /* 읽은 뒤에 tail 을 넘김 */
    rx_tail = (uint16_t)((t + 1u) & (RX_SZ - 1u));
    return 1;
}
head 는 ISR 만, tail 은 main 만 쓰므로 잠금이 필요 없습니다. Cortex-M4 에서 정렬된 16비트 읽기 · 쓰기는 한 명령이라 찢어지지 않고, __COMPILER_BARRIER()(CMSIS)는 컴파일러가 "버퍼 쓰기"와 "head 갱신" 순서를 바꾸지 못하게 막습니다. 한 칸을 비워 두는 방식이라 실제 용량은 RX_SZ − 1 = 511 바이트입니다.

수신 오류 플래그 — 무엇을 뜻하고 어떻게 지우나 (F4 USART)

플래그뜻흔한 원인
ORE오버런 — DR 을 안 읽었는데 다음 바이트가 다 들어옴ISR 지연 · 인터럽트 꺼진 구간이 1 프레임(86.8 µs) 초과
FE프레이밍 — 정지 비트 자리에 0보레이트 불일치 · 선 끊김 · 브레이크 신호
NE잡음 — 한 비트 안 세 샘플이 서로 다름긴 배선 · GND 불량

/* F4: 네 플래그 모두 "SR 읽고 → DR 읽기" 순서로 지워집니다.
   ORE 를 안 지우면 RXNEIE 인터럽트가 계속 들어와 main 이 멈춥니다.
   (ORE 인터럽트는 RXNEIE 로 함께 켜짐) */
__HAL_UART_CLEAR_OREFLAG(&huart2);   /* 같은 순서를 매크로로 */

/* HAL 의 _IT · _DMA 수신은 ORE 가 나면 수신을 "중단"하고
   HAL_UART_ErrorCallback 을 부릅니다 → 거기서 다시 걸어야 함 (m07) */
void HAL_UART_ErrorCallback(UART_HandleTypeDef *h)
{
    if (h->ErrorCode & HAL_UART_ERROR_ORE) rx_ore++;
    if (h->RxState == HAL_UART_STATE_READY)
        uart_rx_start(h);                  /* m07 의 재시작 함수 */
}
ORE 는 링이 가득 찬 것과 다릅니다. ORE 는 ISR 이 제때 못 돈 것(하드웨어 한 칸 버퍼가 넘침)이고, rx_drop 은 main 이 제때 못 비운 것입니다. 카운터를 나눠 두면 원인이 우선순위 문제인지 처리 속도 문제인지 바로 보입니다.

DMA 순환 버퍼 — 에러 없이 조용히 덮어쓴다 🟡 중급

115200 보 이상 · 연속 스트림이면 바이트마다 인터럽트를 받는 대신 DMA 순환 모드 + IDLE(STM32 탭 m07 의 HAL_UARTEx_ReceiveToIdle_DMA)가 표준입니다. CPU 부담은 거의 0 이 되지만 대가가 있습니다 — DMA 는 소비자가 어디까지 읽었는지 모르므로 처리가 밀리면 경고 없이 덮어씁니다. ORE 같은 플래그도 서지 않습니다. 아래 그림은 그 순간을 누적 바이트로 그린 것입니다.

라인 차트 — 두 선의 간격 = 미처리 데이터. 간격이 버퍼 크기를 넘는 순간이 오버런이고, DMA 는 그걸 알려 주지 않습니다.

DMA 오버런을 "보이게" 만드는 세 가지

/* ① 콜백 사이 간격을 재서 한계(22 ms)에 가까우면 경고 */
static uint32_t last_evt_cyc, worst_gap_cyc;
void HAL_UARTEx_RxEventCallback(UART_HandleTypeDef *h, uint16_t Size)
{
    uint32_t now = DWT->CYCCNT;                 /* 180 MHz 사이클 카운터 */
    uint32_t gap = now - last_evt_cyc;
    if (gap > worst_gap_cyc) worst_gap_cyc = gap;   /* 최악값을 로그로 */
    last_evt_cyc = now;
    /* … m07 의 [old, pos) 복사 … */
}

/* ② 프로토콜에 시퀀스 번호 — 1, 2, 4 처럼 건너뛰면 유실 */
if ((uint8_t)(seq - last_seq) != 1u) seq_gap++;
last_seq = seq;

/* ③ 앱 링이 넘치면 그 사실을 파서에게 알림 → 진행 중 프레임 폐기 */
if (ring_free(&app_rx) < n) { app_rx_overflow = 1; return; }
DMA 버퍼 → 앱 링으로 한 번 더 복사하는 구조(m07)에서는 넘침이 두 곳에서 생깁니다 — DMA 버퍼(콜백이 못 돎)와 앱 링(main 이 못 비움). 앞의 것은 ①로, 뒤의 것은 ③으로 잡습니다.

플래그 + 폐기 — 파서와 연결

volatile uint8_t rx_overflow;     /* ISR 에서 drop 시 1 로 */

void comm_poll(parser_t *p)
{
    uint8_t b;
    if (rx_overflow) {
        rx_overflow = 0;
        p->st = ST_SOF;               /* 진행 중이던 프레임은 믿을 수 없음 */
        p->err_len++;                 /* 별도 카운터를 두어도 좋음 */
    }
    while (rx_pop(&b))
        parser_feed(p, b, HAL_GetTick());
}

/* 주의 — rx_pop 으로 꺼낸 바이트의 "도착 시각"은 HAL_GetTick() 이 아니라
   꺼낸 시각입니다. main 이 10 ms 늦게 돌면 정상 프레임도 GAP_MS 를
   넘은 것처럼 보입니다 → 타임아웃 파서를 쓰려면 ISR 에서 시각도 함께 저장하거나,
   GAP_MS 를 main 루프 최악 주기보다 크게 잡습니다. */

버퍼 크기 계산 — 보레이트 × 최악 지연 × 여유 🟡 중급

필요 크기 ≥ (보레이트 / 프레임 비트) × 최악 처리 지연 × 여유(2)
             + 가장 긴 메시지 1개 (해석 전에 통째로 모일 수 있으므로)

예) 115200 8N1, main 루프 최악 20 ms, 최대 메시지 64 B
    11 520 B/s × 0.020 s = 230.4 B
    × 2 = 461 → + 64 = 525 → 2의 거듭제곱으로 올림 → 1024
    (최대 메시지가 작으면 512 로도 충분)

예) 921600 8N1, 같은 20 ms
    92 160 × 0.020 = 1 843 B → × 2 → 4096

예) 9600 8E1 Modbus, 50 ms
    9600 / 11 = 873 B/s × 0.050 = 44 B → 최대 프레임 256 B 가 지배 → 512
"최악 지연"에 들어가는 것잴 방법
main 루프 한 바퀴의 최악루프 시작마다 DWT 사이클 차이의 최댓값 기록
Flash 지우기 · 쓰기 (CPU 정지)F4 섹터 지우기는 수백 ms~초 — 이것만으로 링이 넘침
긴 크리티컬 섹션 · 인터럽트 금지금지 구간 진입 · 해제에 GPIO 토글 → 로직 분석기(p13)
RTOS 라면 소비 태스크보다 높은 태스크트레이스(RTOS 탭) · 태스크 우선순위 표
내부 Flash 를 지우는 동안 같은 뱅크에서 코드를 실행하면 CPU 가 멈춥니다(F446 은 단일 뱅크). 설정 저장 버튼을 누를 때마다 UART 가 깨진다면 링이 아니라 이것이 원인입니다 — 지우기 전에 상대에게 "잠깐 멈춤"을 알리거나, 외부 Flash(p11)로 옮깁니다.
정리 — 저속 · 요청-응답은 ISR + SPSC 링 + "새 것 버리기", 고속 스트림은 DMA 순환 + IDLE 에 넘침 감지를 직접 붙입니다. 크기는 보레이트 × 최악 지연 × 2 + 최대 메시지 — 그리고 ORE 와 drop 을 따로 세어 원인을 가릅니다.
IO 05

I²C — 풀업 저항 계산 · 리피티드 스타트 · 버스 락업 복구

I²C 는 선 두 개(SDA 데이터 · SCL 클럭)에 센서 수십 개를 매달 수 있는 버스입니다. 레지스터로 한 바이트를 주고받는 최소 드라이버는 AVR 탭 a09 에서 만들었고, 여기서는 양산에서 문제가 되는 세 가지를 다룹니다 — 풀업 저항을 얼마로 할지(감이 아니라 계산으로), 레지스터를 읽을 때 버스에서 실제로 무슨 일이 일어나는지, 그리고 슬레이브가 SDA 를 붙잡고 멈춰 버스 전체가 죽는 "락업"을 어떻게 푸는지. 마지막 것은 리셋 버튼으로만 고쳐지던 현장 장애의 주범입니다.

파형 + 해석 — 주소 바이트의 마지막 비트가 방향(R/W), 9번째 클럭이 ACK. HAL 의 7비트 주소를 왼쪽으로 한 칸 미는 이유가 이것입니다.

오픈드레인 — 누구도 HIGH 를 "밀지" 않습니다

I²C 의 모든 장치는 선을 LOW 로 당기거나 놓기만 할 수 있습니다(오픈드레인 — 하드웨어 기초 탭 h02). HIGH 는 풀업 저항이 끌어올려서 만듭니다. 그래서 두 장치가 동시에 말해도 쇼트가 나지 않고(LOW 가 이김), 슬레이브가 SCL 을 붙잡아 마스터를 기다리게 하는 클럭 스트레칭도 가능합니다. 대가는 속도입니다 — 올라가는 에지는 저항 × 버스 정전용량이라는 RC 곡선을 따라 천천히 올라갑니다. 

최소 저항 — 장치가 LOW 로 당길 수 있는 전류 한계 (3 mA 에서 0.4 V)
  Rp(min) = (VDD − VOL) / IOL = (3.3 − 0.4) / 0.003 = 967 Ω

최대 저항 — 상승 시간 tr(30 %→70 %) = 0.8473 × Rp × Cb 가 규격 이내
  표준 모드 100 kHz : tr ≤ 1000 ns
  고속 모드 400 kHz : tr ≤  300 ns
  Rp(max) = tr / (0.8473 × Cb)

  Cb = 100 pF : 표준 11.8 kΩ · 고속 3.54 kΩ
  Cb = 200 pF : 표준  5.9 kΩ · 고속 1.77 kΩ
  Cb = 400 pF : 표준  2.95 kΩ · 고속 0.89 kΩ (최소 저항 근처 → 버스가 너무 큼)

Cb 어림 = 장치당 핀 용량 ~10 pF × 장치 수 + 배선 ~50~100 pF/m

모듈을 여러 개 꽂았을 때 — 병렬 풀업

대부분의 센서 모듈은 기판에 풀업(4.7 k ~ 10 k)을 달고 나옵니다.
모듈 세 개를 한 버스에 꽂으면 풀업 세 개가 병렬:

  4.7 k × 3 병렬 = 1.57 kΩ  → 싱크 전류 3.3 / 1567 = 2.1 mA (OK)
  10 k  × 4 병렬 = 2.5 kΩ   → 문제없음
  2.2 k × 4 병렬 = 550 Ω    → 6 mA, 최소 저항(967 Ω) 미만 ✕
                               LOW 가 0.4 V 아래로 안 내려감
STM32 내부 풀업(약 40 kΩ)으로 I²C 를 돌리지 마세요. 100 pF 에서 tr ≈ 3.4 µs — 표준 모드 규격(1 µs)의 세 배입니다. 책상 위 짧은 배선에선 "되는 것처럼" 보이다가 선을 늘리거나 장치를 더하면 무너집니다.
스코프로 확인하는 법 — SCL 상승 에지를 확대해 30 %(1.0 V)에서 70 %(2.3 V)까지 걸린 시간을 잽니다. 사각파가 아니라 상어 지느러미 모양이면 풀업이 너무 크거나 버스 용량이 너무 큰 것입니다(p13).
RC 곡선 — "4.7 kΩ 이 표준값"은 100 kHz 에서만 맞습니다. 400 kHz 로 올리면 저항도 같이 내려야 합니다.

HAL 로 레지스터 읽기 — Mem_Read 한 줄 아래에서 일어나는 일 🟡 중급

/* ① 버스 스캔 — 처음 보드를 받으면 무조건 이것부터 */
void i2c_scan(void)
{
    for (uint8_t a = 0x08; a < 0x78; a++)          /* 0x00~07, 0x78~7F 는 예약 */
        if (HAL_I2C_IsDeviceReady(&hi2c1, (uint16_t)(a << 1), 2, 5) == HAL_OK)
            printf("found 0x%02X\r\n", a);         /* BME280 → 0x76 또는 0x77 */
}

/* ② 칩 ID — S 0x76W A 0xD0 A Sr 0x76R A [0x60] N P 를 HAL 이 만들어 줌 */
uint8_t id = 0;
HAL_StatusTypeDef st = HAL_I2C_Mem_Read(&hi2c1,
        0x76 << 1,               /* ★ 7비트 주소를 왼쪽으로 한 칸 */

if (st != HAL_OK) {
    uint32_t e = HAL_I2C_GetError(&hi2c1);   /* HAL_I2C_ERROR_AF = NACK */
}

/* ③ 연속 레지스터 버스트 — 주소 자동 증가 (BME280 0xF7~0xFE 8바이트) */
uint8_t raw[8];
HAL_I2C_Mem_Read(&hi2c1, 0x76 << 1, 0xF7, I2C_MEMADD_SIZE_8BIT, raw, 8, 10);

버스 락업 — SCL 9펄스로 슬레이브를 풀어 주기 🔴 실무

시나리오: 마스터가 센서에서 바이트를 읽는 도중 MCU 만 리셋됩니다(워치독 · 디버거 리셋 · 브라운아웃). 센서는 리셋되지 않았으니 아직 "바이트를 보내는 중"이고, 마침 보내던 비트가 0 이라 SDA 를 LOW 로 붙잡은 채 다음 SCL 을 기다립니다. 다시 깨어난 마스터는 SDA 가 LOW 라서 버스가 바쁘다고(BUSY) 보고 START 를 못 겁니다. 서로가 서로를 기다리는 교착 상태입니다. 해법은 마스터가 SCL 을 직접 흔들어 슬레이브가 남은 비트를 다 내보내게 하는 것 — 최악이 8비트 + ACK 이므로 최대 9펄스입니다.

i2c_recover.c — I2C1 (PB8 SCL · PB9 SDA)

/* delay_us() 는 DWT 사이클 카운터로 만든 µs 지연 (STM32 탭) */
static void scl(GPIO_PinState s) { HAL_GPIO_WritePin(GPIOB, GPIO_PIN_8, s); delay_us(5); }
static void sda(GPIO_PinState s) { HAL_GPIO_WritePin(GPIOB, GPIO_PIN_9, s); delay_us(5); }

void i2c1_bus_recover(void)
{
    GPIO_InitTypeDef g = {0};
    HAL_I2C_DeInit(&hi2c1);                    /* 주변장치 끄고 핀 해제 */

    HAL_GPIO_WritePin(GPIOB, GPIO_PIN_8 | GPIO_PIN_9, GPIO_PIN_SET);  /* 먼저 놓아 둠 */
    g.Pin   = GPIO_PIN_8 | GPIO_PIN_9;
    g.Mode  = GPIO_MODE_OUTPUT_OD;             /* 오픈드레인 — 외부 풀업이 HIGH 를 만듦 */
    g.Pull  = GPIO_NOPULL;
    g.Speed = GPIO_SPEED_FREQ_LOW;
    HAL_GPIO_Init(GPIOB, &g);                   /* OD 출력에 1 = 놓음 → 읽기도 가능 */

    /* ① SDA 가 풀릴 때까지 최대 9번 클럭 (약 100 kHz) */
    for (int i = 0; i < 9 && HAL_GPIO_ReadPin(GPIOB, GPIO_PIN_9) == GPIO_PIN_RESET; i++) {
        scl(GPIO_PIN_RESET);
        scl(GPIO_PIN_SET);
    }
    /* ② STOP 만들기 — SCL HIGH 인 동안 SDA LOW → HIGH */
    scl(GPIO_PIN_RESET);
    sda(GPIO_PIN_RESET);
    scl(GPIO_PIN_SET);
    sda(GPIO_PIN_SET);

    /* ③ 주변장치 자체도 리셋 (BUSY 플래그 고착 대비) 후 재초기화 */
    __HAL_RCC_I2C1_FORCE_RESET();
    __HAL_RCC_I2C1_RELEASE_RESET();
    HAL_I2C_Init(&hi2c1);                      /* MspInit 이 핀을 다시 AF4 로 */
}

{
    HAL_StatusTypeDef st = HAL_I2C_Mem_Read(&hi2c1, (uint16_t)(a7 << 1), reg,
                                            I2C_MEMADD_SIZE_8BIT, p, n, 10);
    if (st == HAL_OK) { fail_streak = 0; return st; }

F4 의 I²C 는 정오표(errata)에 "BUSY 플래그가 풀리지 않는" 항목이 있습니다. 아날로그 필터가 잡음을 잘못 걸러 주변장치가 버스가 바쁘다고 믿어 버리는 경우로, 공식 회피책이 바로 위 ③ — GPIO 로 핀을 흔들고 주변장치를 리셋하는 절차입니다. 쓰는 칩의 정오표를 한 번은 읽어 두세요.
근본 대책은 회로에 있습니다 — 센서 전원을 MCU 가 GPIO(또는 로드 스위치)로 끊었다 켤 수 있게 설계하면 어떤 락업도 전원 재투입으로 풀립니다. 양산 보드라면 이 핀 하나를 꼭 남기세요.
정리 — 풀업은 tr = 0.8473 RC 로 계산해 400 kHz 면 2.2 kΩ 근처, HAL 주소는 7비트 << 1. 레지스터 읽기는 리피티드 스타트로 이어지고, 락업은 SCL 9펄스 + STOP + 주변장치 리셋을 부팅 때와 연속 실패 때 부릅니다.
IO 06

SPI — 모드 0~3 · CS 관리 · DMA, 그리고 빠른 버스의 배선 한계

SPI 는 가장 단순하고 가장 빠른 버스입니다. 마스터가 클럭(SCK)을 내보내면 한 클럭마다 한 비트씩 양쪽이 동시에 맞바꿉니다(MOSI 로 나가고 MISO 로 들어옴). 주소도 ACK 도 없고, 대신 장치마다 CS(칩 선택) 선 하나로 "지금 너" 를 지목합니다. 규칙이 적은 만큼 맞춰야 할 것은 클럭의 극성과 위상(모드), CS 를 언제 올리고 내리나, 선이 얼마나 길어도 되나 세 가지입니다.

파형 — 모드 = 쉴 때 클럭 레벨 × 몇 번째 에지에서 읽나. 데이터시트 타이밍 그림에서 "SCK 가 쉴 때 어디 있나"부터 보면 됩니다.

spi_dev.c — 장치 하나 = (SPI 핸들, CS 핀)

typedef struct {
    SPI_HandleTypeDef *hspi;
    GPIO_TypeDef      *cs_port;
    uint16_t           cs_pin;
} spi_dev_t;

static inline void cs_low(const spi_dev_t *d)  { HAL_GPIO_WritePin(d->cs_port, d->cs_pin, GPIO_PIN_RESET); }
static inline void cs_high(const spi_dev_t *d) { HAL_GPIO_WritePin(d->cs_port, d->cs_pin, GPIO_PIN_SET); }

/* 레지스터 읽기 — 첫 바이트(주소)를 보내는 동안 들어오는 값은 버림 */
HAL_StatusTypeDef bme_spi_read(const spi_dev_t *d, uint8_t reg, uint8_t *p, uint16_t n)
{
    uint8_t cmd = reg | 0x80u;              /* bit7 = 1 → 읽기 */
    cs_low(d);
    HAL_StatusTypeDef st = HAL_SPI_Transmit(d->hspi, &cmd, 1, 10);
    if (st == HAL_OK) st = HAL_SPI_Receive(d->hspi, p, n, 10);  /* p 의 기존 내용을 더미로 내보내며 받음 */
    cs_high(d);                              /* 오류여도 반드시 올림 */
    return st;
}

/* W25Q JEDEC ID — 한 번에 4바이트 맞바꾸기 */
uint32_t w25q_jedec_id(const spi_dev_t *d)
{
    uint8_t tx[4] = { 0x9F, 0, 0, 0 }, rx[4] = { 0 };
    cs_low(d);
    HAL_SPI_TransmitReceive(d->hspi, tx, rx, 4, 10);
    cs_high(d);
    return ((uint32_t)rx[1] << 16) | ((uint32_t)rx[2] << 8) | rx[3];  /* W25Q128JV → 0xEF4018 */
}

/* 부팅 직후: 모든 CS 를 먼저 HIGH 로 — 초기화 순서 때문에 잠깐 LOW 면
   장치들이 동시에 MISO 를 구동해 첫 거래가 깨집니다 */

IO 07

CAN · CAN-FD — 충돌해도 깨지지 않는 버스, 비트 중재와 bus-off

CAN 은 자동차 한 대에 수십 개의 ECU 를 두 가닥 선으로 묶으려고 만든 버스입니다. 마스터가 없고 누구나 아무 때나 말을 시작할 수 있습니다. 두 노드가 동시에 말하면? 이더넷은 충돌로 둘 다 깨지고 재시도하지만, CAN 은 ID 가 작은 쪽이 한 비트도 손상 없이 이기고 진 쪽은 조용히 물러납니다. 그리고 고장 난 노드가 버스를 망치지 않도록 스스로 빠지는(bus-off) 규칙이 하드웨어에 들어 있습니다. 서버로 치면 우선순위 큐가 내장된 메시지 버스 + 서킷 브레이커입니다.

파형 · 중재 — ID 가 곧 우선순위입니다. 브레이크 메시지에 작은 ID 를 주는 이유가 이것입니다.

물리 계층 — 우성과 열성

상태CANHCANL차이논리
열성≈ 2.5 V≈ 2.5 V≈ 0 V1 (아무도 안 당김)

I²C 의 오픈드레인과 같은 원리입니다 — 0(우성)은 적극적으로 구동하고 1(열성)은 놓아 두기만 하므로, 여럿이 동시에 말해도 0 이 이기고 아무것도 타지 않습니다. 송신하는 노드는 자기가 보낸 비트를 버스에서 다시 읽어 비교하고, 다르면 중재에 진 것으로 알고 물러납니다.

종단 저항 120 Ω 을 양 끝에. 전원을 끈 채 CANH–CANL 을 재서 약 60 Ω(120 ∥ 120)이면 정상, 120 Ω 이면 한쪽이 빠졌고, 40 Ω 이면 세 개가 달린 것입니다. Nucleo 두 대를 책상 위에서 이을 때도 종단이 없으면 ACK 에러만 쌓입니다.

비트 스터핑: 같은 값이 5번 연속되면 반대 비트 1개 삽입 → 최악 약 +20 %

F446 bxCAN 설정 — 비트 타이밍 · 필터 · 송수신 🟡 중급

500 kbit/s 비트 타이밍 계산 (APB1 45 MHz)

한 비트 = Sync(1 tq) + BS1 + BS2      (tq = 시간 양자)
tq = Prescaler / 45 MHz

Prescaler 5 → tq = 111.1 ns → 500 kbit/s 면 한 비트 = 2 µs = 18 tq
  18 = 1 + BS1 15 + BS2 2   → 샘플 지점 (1+15)/18 = 88.9 %

USB 디바이스 기초 — 엔드포인트 · 디스크립터 · 열거, 그리고 CDC 가상 COM

USB-UART 브리지 칩 없이 MCU 가 직접 USB 장치가 되면, PC 에는 COM 포트(또는 키보드 · 저장 장치)가 나타납니다. 그런데 USB 는 UART 와 완전히 다른 세계입니다 — 호스트(PC)만 말을 걸 수 있고, 장치는 꽂히는 순간 자기소개서(디스크립터)를 정확한 형식으로 내놓아야 하며, 그 과정(열거)을 수십 ms 안에 끝내야 합니다. 서버로 치면 장치는 HTTP 서버이고 PC 가 폴링하는 클라이언트입니다. 장치는 "보낼 게 있다"고 먼저 연락할 수 없고, 호스트가 물어볼 때만 응답합니다.

엔드포인트와 전송 종류

엔드포인트(EP)는 장치 안의 우편함입니다. 번호(0~15)와 방향(IN = 장치 → 호스트, OUT = 호스트 → 장치)으로 구분하고, EP0 은 모든 장치에 있는 제어용입니다. 나머지는 클래스가 정합니다.

"인터럽트 전송"도 결국 폴링입니다 — 호스트가 1 ms 마다 물어보겠다고 약속하는 것일 뿐, 장치가 호스트를 깨우는 게 아닙니다. USB FS 는 1 ms 프레임 단위로 움직이고, 벌크는 한 프레임에 64 B 패킷 최대 19개 → 이론상 약 1.2 MB/s 입니다.

#include "bme280.h"

#define RD(d, r, b, n) ((d)->bus.read((d)->bus.ctx, (r), (b), (n)))
#define WR(d, r, v)    ((d)->bus.write((d)->bus.ctx, (r), (v)))
#define DLY(d, ms)     ((d)->bus.delay_ms((d)->bus.ctx, (ms)))

static uint16_t u16le(const uint8_t *p) { return (uint16_t)(p[0] | (p[1] << 8)); }
static int16_t  s16le(const uint8_t *p) { return (int16_t)u16le(p); }
static int32_t  comp_t(bme280_t *d, int32_t adc_T);   /* ④ 에 정의 */
static uint32_t comp_p(bme280_t *d, int32_t adc_P);

bme280_err_t bme280_init(bme280_t *dev)
{
    uint8_t id, st, c[26], e[7];
    int i;
    if (!dev || !dev->bus.read || !dev->bus.write || !dev->bus.delay_ms)
        return BME280_E_PARAM;

    if (RD(dev, 0xD0, &id, 1)) return BME280_E_BUS;
    if (id != 0x60)            return BME280_E_CHIP_ID;

    if (WR(dev, 0xE0, 0xB6))   return BME280_E_BUS;     /* 소프트 리셋 */
    DLY(dev, 2);
    for (i = 0; i < 10; i++) {                         /* NVM → 보정 레지스터 복사 대기 */
        if (RD(dev, 0xF3, &st, 1)) return BME280_E_BUS;
        if (!(st & 0x01)) break;                        /* im_update = 0 이면 끝 */
        DLY(dev, 1);
    }
    if (i == 10) return BME280_E_TIMEOUT;

    if (RD(dev, 0x88, c, 26) || RD(dev, 0xE1, e, 7)) return BME280_E_BUS;
    bme280_calib_t *k = &dev->cal;
    k->T1 = u16le(&c[0]);  k->T2 = s16le(&c[2]);  k->T3 = s16le(&c[4]);
    k->P1 = u16le(&c[6]);  k->P2 = s16le(&c[8]);  k->P3 = s16le(&c[10]);
    k->P4 = s16le(&c[12]); k->P5 = s16le(&c[14]); k->P6 = s16le(&c[16]);
    k->P7 = s16le(&c[18]); k->P8 = s16le(&c[20]); k->P9 = s16le(&c[22]);
    k->H1 = c[25];                                      /* 0xA1 (0xA0 은 비어 있음) */
    k->H2 = s16le(&e[0]);
    k->H3 = e[2];
    k->H4 = (int16_t)(((int16_t)(int8_t)e[3] * 16) | (e[4] & 0x0F));   /* 0xE4[7:0] 0xE5[3:0] */
    k->H5 = (int16_t)(((int16_t)(int8_t)e[5] * 16) | (e[4] >> 4));     /* 0xE6[7:0] 0xE5[7:4] */
    k->H6 = (int8_t)e[6];

    if (WR(dev, 0xF2, 0x01)) return BME280_E_BUS;       /* 습도 ×1 (다음 F4 쓰기에서 반영) */
    return BME280_OK;
}

bme280_err_t bme280_measure(bme280_t *dev, bme280_meas_t *m)
{
    uint8_t d[8], st;
    if (!dev || !m) return BME280_E_PARAM;
    if (WR(dev, 0xF4, 0x25)) return BME280_E_BUS;       /* 001 001 01 = T×1 P×1 강제 모드 */
    DLY(dev, 10);                                        /* ×1 셋이면 최대 약 9.3 ms */
    for (int i = 0; ; i++) {
        if (RD(dev, 0xF3, &st, 1)) return BME280_E_BUS;
        if (!(st & 0x08)) break;                         /* measuring = 0 */
        if (i >= 5) return BME280_E_TIMEOUT;
        DLY(dev, 1);
    }
    if (RD(dev, 0xF7, d, 8)) return BME280_E_BUS;        /* 한 번의 버스트 */
    int32_t adc_p = (int32_t)(((uint32_t)d[0] << 12) | ((uint32_t)d[1] << 4) | (d[2] >> 4));
    int32_t adc_t = (int32_t)(((uint32_t)d[3] << 12) | ((uint32_t)d[4] << 4) | (d[5] >> 4));
    m->adc_h  = (int32_t)(((uint32_t)d[6] << 8) | d[7]);
    m->t_c100 = comp_t(dev, adc_t);                      /* t_fine 을 먼저 채움 */
    m->p_q24_8 = comp_p(dev, adc_p);
    return BME280_OK;
}

④ 보정식 — 데이터시트의 정수 버전 그대로

/* 데이터시트 4.2.3 — 결과 0.01 ℃. t_fine 은 기압 · 습도에 다시 쓰임 */
static int32_t comp_t(bme280_t *d, int32_t adc_T)
{
    const bme280_calib_t *k = &d->cal;
    int32_t var1 = ((((adc_T >> 3) - ((int32_t)k->T1 << 1))) * ((int32_t)k->T2)) >> 11;
    int32_t var2 = (((((adc_T >> 4) - ((int32_t)k->T1)) *
                      ((adc_T >> 4) - ((int32_t)k->T1))) >> 12) *
                    ((int32_t)k->T3)) >> 14;
    d->t_fine = var1 + var2;
    return (d->t_fine * 5 + 128) >> 8;
}

/* 결과 Pa × 256 (Q24.8) — 64비트 정수 버전 */
static uint32_t comp_p(bme280_t *d, int32_t adc_P)
{
    const bme280_calib_t *k = &d->cal;
    int64_t var1, var2, p;
    var1 = ((int64_t)d->t_fine) - 128000;
    var2 = var1 * var1 * (int64_t)k->P6;
    var2 = var2 + ((var1 * (int64_t)k->P5) << 17);
    var2 = var2 + (((int64_t)k->P4) << 35);
    var1 = ((var1 * var1 * (int64_t)k->P3) >> 8) + ((var1 * (int64_t)k->P2) << 12);
    var1 = (((((int64_t)1) << 47) + var1)) * ((int64_t)k->P1) >> 33;
    if (var1 == 0) return 0;                       /* 0 으로 나누기 방지 */
    p = 1048576 - adc_P;
    p = (((p << 31) - var2) * 3125) / var1;
    var1 = (((int64_t)k->P9) * (p >> 13) * (p >> 13)) >> 25;
    var2 = (((int64_t)k->P8) * p) >> 19;
    p = ((p + var1 + var2) >> 8) + (((int64_t)k->P7) << 4);
    return (uint32_t)p;
}

주소 0x3C (모듈에 따라 0x3D) — HAL 에는 0x78 (= 0x3C << 1)

[S] [0x78] [제어 바이트] [바이트들 …] [P]

   제어 0x40 → 뒤따르는 바이트는 전부 "그림 데이터" (GDDRAM)

#define OLED_ADDR (0x3C << 1)
extern I2C_HandleTypeDef hi2c1;

static uint8_t fb[8][128];          /* [페이지][열] — 메모리 순서 = 화면 RAM 순서 */
static uint8_t dirty;               /* bit p = 페이지 p 가 바뀜 */

static HAL_StatusTypeDef oled_cmd(const uint8_t *c, uint16_t n)
{
    return HAL_I2C_Mem_Write(&hi2c1, OLED_ADDR, 0x00, I2C_MEMADD_SIZE_8BIT,
                             (uint8_t *)c, n, 50);
}

static const uint8_t init_seq[] = {
    0xAE,            /* 화면 끔 */
    0xD5, 0x80,      /* 내부 클럭 분주 */
    0xA8, 0x3F,      /* MUX = 64 행 */
    0xD3, 0x00,      /* 세로 오프셋 0 */
    0x40,            /* 시작 행 0 */
    0x8D, 0x14,      /* 차지 펌프 켬 — 대부분의 모듈은 내부 승압 */
    0x20, 0x00,      /* 수평 주소 모드 (페이지 끝에서 다음 페이지로) */
    0xA1, 0xC8,      /* 좌우 · 상하 뒤집기 (모듈 방향에 맞춤) */
    0xDA, 0x12,      /* COM 핀 배치 — 128×64 */
    0x81, 0xCF,      /* 대비 */
    0xD9, 0xF1,      /* 프리차지 */
    0xDB, 0x40,      /* VCOMH */
    0xA4, 0xA6,      /* RAM 내용 표시 · 반전 아님 */
    0xAF             /* 화면 켬 */
};

HAL_StatusTypeDef oled_init(void)
{
    HAL_Delay(100);                    /* 전원 안정 대기 — 모듈 리셋 회로 */
    return oled_cmd(init_seq, sizeof init_seq);
}

void oled_pixel(int x, int y, int on)
{
    if ((unsigned)x >= 128u || (unsigned)y >= 64u) return;   /* 음수도 한 번에 거름 */
    uint8_t m = (uint8_t)(1u << (y & 7));
    if (on) fb[y >> 3][x] |= m;
    else    fb[y >> 3][x] &= (uint8_t)~m;
    dirty |= (uint8_t)(1u << (y >> 3));
}

/* 5×7 글꼴 — 한 글자 = 열 5개, 각 열이 세로 바이트 (bit0 = 맨 위)
   화면 메모리와 같은 모양이라 복사만 하면 됨 */
static const uint8_t glyph_A[5] = { 0x7C, 0x12, 0x11, 0x12, 0x7C };
static const uint8_t glyph_0[5] = { 0x3E, 0x51, 0x49, 0x45, 0x3E };

/* y 가 8 의 배수가 아니어도 되는 버전 — 두 페이지에 걸쳐 쪼갬 */
void oled_glyph(int x, int y, const uint8_t g[5])
{
    int page = y >> 3, sh = y & 7;
    for (int i = 0; i < 5 && x + i < 128; i++) {
        if (page < 8) {
            fb[page][x + i] |= (uint8_t)(g[i] << sh);
            dirty |= (uint8_t)(1u << page);
        }
        if (sh && page + 1 < 8) {
            fb[page + 1][x + i] |= (uint8_t)(g[i] >> (8 - sh));
            dirty |= (uint8_t)(1u << (page + 1));
        }
    }
}

/* 바뀐 페이지만 보냄 — 페이지 하나 ≈ 3 ms (400 kHz) */
void oled_flush(void)
{
    for (uint8_t p = 0; p < 8; p++) {
        if (!(dirty & (1u << p))) continue;
        const uint8_t win[] = { 0x21, 0, 127, 0x22, p, p };   /* 열 0~127, 페이지 p */
        oled_cmd(win, sizeof win);
        HAL_I2C_Mem_Write(&hi2c1, OLED_ADDR, 0x40, I2C_MEMADD_SIZE_8BIT,
                          fb[p], 128, 20);
    }
    dirty = 0;
}
oled_glyph 는 OR 로 그리므로 지우려면 해당 영역을 먼저 0 으로 채웁니다. 글꼴 데이터는 const 라 Flash 에 놓이고 RAM 을 쓰지 않습니다. 한글은 글자당 16×16 = 32 B · 2,350자 기준 약 75 KB 라, 쓰는 글자만 뽑아 넣는 것이 보통입니다.

외부 Flash · EEPROM — W25Q 명령 · 256 B 페이지 · 4 KB 지우기, 마모와 littlefs

로그 · 설정 · 펌웨어 업데이트 이미지를 저장하려면 MCU 내부 Flash(512 KB)로는 부족하거나 위험합니다(지우는 동안 CPU 가 멈춤 — p04). 그래서 몇백 원짜리 SPI NOR Flash(Winbond W25Q 계열이 사실상 표준)를 붙입니다. 규칙은 RAM 과 전혀 다릅니다 — 쓰기는 1 을 0 으로만 바꿀 수 있고, 0 을 1 로 되돌리려면 4 KB 단위로 통째로 지워야 하며, 한 번에 쓸 수 있는 건 256 B 페이지 안뿐이고, 한 섹터는 약 10만 번 지우면 닳습니다. 서버로 치면 SSD 의 FTL(플래시 변환 계층)이 하던 일을 펌웨어가 직접 해야 합니다.

메모리 계층 — 지우기는 4 KB, 쓰기는 256 B 페이지 안. 경계를 넘는 쓰기는 오류 없이 엉뚱한 곳을 덮습니다.

NOR Flash 의 세 가지 법칙

① 지우면 전부 1 (0xFF)
② 쓰기(program)는 1 → 0 만 가능 — 이미 0 인 비트는 그대로
   0xFF 에 0xA5 쓰기 → 0xA5
   0xA5 에 0x5A 쓰기 → 0xA5 & 0x5A = 0x00   (덮어쓰기가 아니라 AND)
③ 0 을 1 로 되돌리는 유일한 방법 = 그 비트가 든 섹터 4 KB 전체 지우기

그래서 "설정 4바이트 바꾸기" =
   섹터 4 KB 를 RAM 으로 읽기 → RAM 에서 수정 → 섹터 지우기 → 16 페이지 다시 쓰기
   (도중에 전원이 나가면 4 KB 가 통째로 사라짐!)
EEPROM(24C256 등 I²C)은 바이트 단위로 덮어쓸 수 있고 지우기가 따로 없어 설정값 몇 개에는 더 간단합니다. 대신 쓰기가 페이지(64 B) 단위로 5 ms 씩 걸리고 용량이 KB 단위입니다. 수 MB 의 로그 · 펌웨어 이미지는 NOR, 몇 바이트 설정은 EEPROM 이나 아래 littlefs.

/* spi_dev_t · cs_low · cs_high 는 p06 의 것 */
static int w25q_wait(const spi_dev_t *d, uint32_t timeout_ms)
{
    uint8_t  cmd = 0x05, sr = 0;
    uint32_t t0  = HAL_GetTick();
    do {
        cs_low(d);
        HAL_SPI_Transmit(d->hspi, &cmd, 1, 10);
        HAL_SPI_Receive(d->hspi, &sr, 1, 10);
        cs_high(d);
        if (!(sr & 0x01)) return 0;                   /* BUSY = 0 → 끝 */
    } while (HAL_GetTick() - t0 < timeout_ms);
    return -1;
}

static void w25q_wren(const spi_dev_t *d)
{
    uint8_t c = 0x06;
    cs_low(d); HAL_SPI_Transmit(d->hspi, &c, 1, 10); cs_high(d);
}

int w25q_read(const spi_dev_t *d, uint32_t addr, uint8_t *p, uint16_t n)
{
    uint8_t h[4] = { 0x03, (uint8_t)(addr >> 16), (uint8_t)(addr >> 8), (uint8_t)addr };
    cs_low(d);
    HAL_StatusTypeDef st = HAL_SPI_Transmit(d->hspi, h, 4, 10);
    if (st == HAL_OK) st = HAL_SPI_Receive(d->hspi, p, n, 100);
    cs_high(d);
    return st == HAL_OK ? 0 : -1;
}
/* 임의 길이 쓰기 — 페이지 경계마다 잘라 Page Program 반복
   (대상 영역은 미리 지워져 있어야 함) */
int w25q_write(const spi_dev_t *d, uint32_t addr, const uint8_t *p, uint32_t n)
{
    while (n) {
        uint32_t room  = 256u - (addr & 0xFFu);        /* 이 페이지에 남은 칸 */
        uint32_t chunk = n < room ? n : room;
        uint8_t  h[4]  = { 0x02, (uint8_t)(addr >> 16), (uint8_t)(addr >> 8), (uint8_t)addr };

        w25q_wren(d);
        cs_low(d);
        HAL_StatusTypeDef st = HAL_SPI_Transmit(d->hspi, h, 4, 10);
        if (st == HAL_OK)
            st = HAL_SPI_Transmit(d->hspi, (uint8_t *)p, (uint16_t)chunk, 100);
        cs_high(d);                                    /* CS 가 올라가는 순간 굽기 시작 */
        if (st != HAL_OK || w25q_wait(d, 5)) return -1;   /* tPP 최대 3 ms */

        addr += chunk; p += chunk; n -= chunk;
    }
    return 0;
}
/* 0xF0 에 100 B → 16 B (0xF0~0xFF) + 84 B (0x100~0x153) 두 번 */

int w25q_erase_4k(const spi_dev_t *d, uint32_t addr)  /* addr 의 하위 12비트는 무시됨 */
{
    uint8_t h[4] = { 0x20, (uint8_t)(addr >> 16), (uint8_t)(addr >> 8), (uint8_t)addr };
    w25q_wren(d);
    cs_low(d); HAL_SPI_Transmit(d->hspi, h, 4, 10); cs_high(d);
    return w25q_wait(d, 500);                          /* tSE 최대 400 ms */
}

    .context = &flash,
    .read = f_read, .prog = f_prog, .erase = f_erase, .sync = f_sync,
    .read_size = 16, .prog_size = 256,
    .block_size = 4096, .block_count = 4096,       /* 4 KB × 4096 = 16 MB */
    .cache_size = 256, .lookahead_size = 32, .block_cycles = 500,

uint32_t boot_count(void)
{
    static lfs_t lfs;
    lfs_file_t f;
    uint32_t cnt = 0;
    if (lfs_mount(&lfs, &cfg)) {                     /* 첫 부팅이면 포맷 */
        lfs_format(&lfs, &cfg);
        lfs_mount(&lfs, &cfg);
    }
    lfs_file_open(&lfs, &f, "boot_count", LFS_O_RDWR | LFS_O_CREAT);
    lfs_file_read(&lfs, &f, &cnt, sizeof cnt);
    cnt++;
    lfs_file_rewind(&lfs, &f);
    lfs_file_write(&lfs, &f, &cnt, sizeof cnt);
    lfs_file_close(&lfs, &f);                         /* 닫아야(또는 sync) 확정 */
    lfs_unmount(&lfs);
    return cnt;
}
"마운트 실패 → 포맷"은 첫 부팅에만 맞는 처리입니다. 양산품에서 일시적 SPI 오류로 마운트가 실패했는데 포맷하면 사용자 데이터가 전부 사라집니다. 공장 출하 때 포맷하고, 현장에서는 재시도 · 오류 보고를 먼저 하세요. block_cycles 는 몇 번 지운 블록을 다른 곳으로 옮길지(웨어 레벨링 주기)입니다.
정리 — NOR Flash 는 지우면 1, 쓰기는 1→0, 지우기는 4 KB, 쓰기는 256 B 페이지 안. 드라이버는 WREN → 명령 → BUSY 대기와 페이지 경계 자르기가 전부이고, 마모 · 전원 차단은 직접 짜기보다 littlefs 에 맡깁니다.

Modbus RTU — 산업 현장의 공용어, 프레임 · 3.5 문자 침묵 · 03/06/16

인버터 · 전력계 · 온도 조절기 · PLC 를 MCU 와 이어야 한다면 거의 확실히 Modbus RTU over RS-485 입니다. 1979년에 나온 단순한 프로토콜이지만 지금도 공장의 표준이고, 사양이 공개되어 있어 누구나 구현할 수 있습니다. 구조는 p03 에서 설계한 것과 같습니다 — 주소 · 명령 · 데이터 · CRC. 다른 점은 프레임 경계를 "침묵 시간"으로 정한다는 것 하나입니다. 서버로 치면 마스터가 묻고 슬레이브가 답하는 동기 RPC이고, 슬레이브는 절대 먼저 말하지 않습니다.

F446 에서 t3.5 재기 — TIM6 원샷

/* F4 의 USART 에는 수신 타임아웃(RTO) 기능이 없습니다(F7 · L4 · G0 · H7 엔 있음).
   IDLE 은 "1 문자" 침묵이라 3.5 를 직접 재야 합니다 → 기본 타이머 TIM6 */

/* TIM6: 타이머 클럭 90 MHz, PSC 89 → 1 µs 단위, ARR = t3.5 − 1 (19200 → 2004)
   CubeMX 가 HAL 타임베이스로 TIM6 을 쓰고 있으면(FreeRTOS 프로젝트에 흔함) TIM7 로 */
void mb_timer_init(void)
{
    htim6.Instance->CR1 |= TIM_CR1_OPM;               /* 한 번 넘치면 스스로 멈춤 */
    __HAL_TIM_CLEAR_FLAG(&htim6, TIM_FLAG_UPDATE);   /* Init 의 UG 가 남긴 플래그 */
    __HAL_TIM_ENABLE_IT(&htim6, TIM_IT_UPDATE);
}

static uint8_t           fr[256];
static volatile uint16_t fr_len;
static volatile uint8_t  fr_ready;

void mb_rx_byte(uint8_t b)          /* USART1 수신 ISR 에서 바이트마다 */
{
    if (fr_ready) return;           /* 앞 프레임 처리 전 — 마스터는 응답 전에 안 보냄 */
    if (fr_len < sizeof fr) fr[fr_len++] = b;
    htim6.Instance->CNT = 0;        /* 바이트가 올 때마다 침묵 시계를 0 으로 */
    htim6.Instance->CR1 |= TIM_CR1_CEN;
}

void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *h)
{
    if (h->Instance == TIM6) fr_ready = 1;   /* t3.5 동안 아무것도 안 옴 = 프레임 끝 */
}

void mb_poll(void)                  /* main 루프 */
{
    static uint8_t rsp[256];        /* DMA 송신 중에도 살아 있게 static */
    if (!fr_ready) return;
    size_t n = mb_handle(fr, fr_len, rsp);
    fr_len = 0;
    fr_ready = 0;
    if (n) rs485_send(rsp, (uint16_t)n);      /* p02 — DE 제어 포함 */
}

mb_handle — 03 · 06 · 16 슬레이브

#define MB_ADDR 1
#define NREG    64
static uint16_t hreg[NREG];                       /* 보유 레지스터 */

uint16_t mb_crc(const uint8_t *p, size_t n)
{
    uint16_t c = 0xFFFF;
    while (n--) {
        c ^= *p++;
        for (int k = 0; k < 8; k++)
            c = (c & 1u) ? (uint16_t)((c >> 1) ^ 0xA001u) : (uint16_t)(c >> 1);
    }
    return c;
}
static size_t exc(uint8_t *r, uint8_t a, uint8_t fc, uint8_t code)
{ r[0] = a; r[1] = (uint8_t)(fc | 0x80u); r[2] = code; return 3; }

#define U16(p) ((uint16_t)(((p)[0] << 8) | (p)[1]))

size_t mb_handle(const uint8_t *q, size_t n, uint8_t *r)
{
    if (n < 4 || mb_crc(q, n - 2) != (uint16_t)(q[n - 2] | (q[n - 1] << 8)))
        return 0;                                    /* CRC 틀림 → 침묵 (마스터가 재시도) */
    uint8_t a = q[0], fc = q[1];
    if (a != MB_ADDR && a != 0) return 0;           /* 0 = 브로드캐스트 */
    size_t len;
    switch (fc) {
    case 0x03: {
        if (n != 8) { len = exc(r, a, fc, 3); break; }
        uint16_t start = U16(&q[2]), cnt = U16(&q[4]);
        if (cnt < 1 || cnt > 125)          { len = exc(r, a, fc, 3); break; }
        if ((uint32_t)start + cnt > NREG)  { len = exc(r, a, fc, 2); break; }
        r[0] = a; r[1] = fc; r[2] = (uint8_t)(cnt * 2); len = 3;
        for (uint16_t i = 0; i < cnt; i++) {
            r[len++] = (uint8_t)(hreg[start + i] >> 8);   /* 큰 바이트 먼저 */
            r[len++] = (uint8_t)hreg[start + i];
        }
        break; }
    case 0x06: {
        if (n != 8) { len = exc(r, a, fc, 3); break; }
        uint16_t reg = U16(&q[2]);
        if (reg >= NREG) { len = exc(r, a, fc, 2); break; }
        hreg[reg] = U16(&q[4]);
        memcpy(r, q, 6); len = 6;                    /* 요청 그대로 되돌림 */
        break; }
    case 0x10: {
        if (n < 9) { len = exc(r, a, fc, 3); break; }
        uint16_t start = U16(&q[2]), cnt = U16(&q[4]);
        uint8_t  bc = q[6];
        if (cnt < 1 || cnt > 123 || bc != cnt * 2 || n != 9u + bc)
            { len = exc(r, a, fc, 3); break; }
        if ((uint32_t)start + cnt > NREG) { len = exc(r, a, fc, 2); break; }
        for (uint16_t i = 0; i < cnt; i++) hreg[start + i] = U16(&q[7 + 2 * i]);
        memcpy(r, q, 6); len = 6;                    /* 시작 주소 · 개수만 */
        break; }
    default:
        len = exc(r, a, fc, 1);
    }
    if (a == 0) return 0;                            /* 브로드캐스트엔 응답 안 함 */
    uint16_t c = mb_crc(r, len);
    r[len++] = (uint8_t)c;                           /* CRC 는 작은 바이트 먼저 */
    r[len++] = (uint8_t)(c >> 8);
    return len;
}

32비트 값 — 워드 순서는 장비마다 다릅니다

/* 레지스터 두 개로 float 25.5 (0x41CC0000) 를 보낼 때
   ABCD (큰 워드 먼저) : reg n = 0x41CC, reg n+1 = 0x0000
   CDAB (작은 워드 먼저): reg n = 0x0000, reg n+1 = 0x41CC
   레지스터 안의 바이트는 항상 큰 바이트 먼저 — 바뀌는 건 "워드 순서" */
float mb_float_abcd(const uint16_t r[2])
{
    uint32_t u = ((uint32_t)r[0] << 16) | r[1];
    float f;
    memcpy(&f, &u, sizeof f);            /* 포인터 캐스팅 대신 memcpy (엄격한 별칭 규칙) */
    return f;
}
장비를 처음 붙일 때는 PC 에서 USB-RS485 동글 + 마스터 툴(QModMaster · mbpoll 등)로 먼저 읽어 보고, 같은 요청을 MCU 로 옮기세요. 값이 이상하면 ① 주소 오프셋(40001) ② 워드 순서 ③ 배율(값 × 0.1) 순서로 의심하면 대부분 풀립니다.
정리 — Modbus RTU 는 주소 · 함수 · 데이터 · CRC(작은 바이트 먼저) 이고, 프레임 경계는 3.5 문자 침묵(19200 보 초과면 1.75 ms)입니다. F446 은 RTO 가 없으니 TIM 원샷으로 재고, 슬레이브는 CRC 가 틀리면 침묵, 범위 밖이면 예외 응답을 돌려줍니다.
