WINDOWS · 사내 공개 · 공유기 포트포워딩까지

윈도우 PC 하나로
사내에 서비스
띄우기

Nginx 도 Apache 도 없이, 만든 프로그램을 그냥 IP 와 포트로 여는 방법만 다룹니다. 사내 직원들이 http://192.168.0.50:8080 으로 들어오게 만드는 것이 1차 목표, IPTIME 공유기에서 포트포워딩해 집이나 외근지에서도 열리게 만드는 것이 2차 목표입니다. 마지막으로 외부에 열었을 때 최소한으로 해야 할 보안을 정리합니다. 명령은 전부 윈도우 기준으로, 복사해 붙이면 되게 적었습니다.

SECTION 01

무엇을 만드는가 — 전체 그림

우리가 하려는 일은 "내 PC 에서 돌아가는 프로그램을 다른 사람 브라우저에서 열리게 하는 것" 하나입니다. 여기에 필요한 것은 세 가지뿐입니다 — 프로그램이 떠 있을 것 · 방화벽이 열려 있을 것 · 상대가 주소를 알 것.

사내 공개는 ①②만으로 끝나고, 외부 공개는 ③④가 더 붙습니다.

웹서버(Nginx·Apache)를 안 써도 되나요

사내에서 수십 명이 보는 도구라면 됩니다. Spring Boot · Node · Django · .NET 은 모두 자체 서버 기능을 갖고 있어 그 자체로 요청을 받습니다. 앞단 웹서버는 정적 파일 처리 · HTTPS · 여러 앱 분배가 필요할 때 붙이는 것이고, 지금 목표에는 없어도 됩니다.

이럴 때이렇게
사내 도구 · 사내 대시보드지금 이 탭 그대로 — 앱만 띄우고 방화벽만 엽니다
외부 공개 + 도메인 + HTTPSv11 의 Caddy 방식 또는 Caddy 탭으로 — 인증서가 자동입니다
동시 접속 수백 이상 · 여러 앱Nginx 탭으로 — 리버스 프록시 구조가 필요합니다
회사 규정상 서버실 밖 공개 금지사내망까지만(v05). 외부 공개는 VPN 으로 — v10 에 씁니다
이 탭에서 쓰는 예시
· 서버 PC 사설 IP 192.168.0.50 · 서비스 포트 8080 · 공유기 IPTIME(192.168.0.1)
· 프로그램은 Spring Boot jar · Node · Python 중 무엇이든 상관없습니다 — 포트만 같으면 절차가 동일합니다
SECTION 02

내 서버의 IP 와 포트 확인하기

먼저 내 PC 의 주소를 알아야 합니다. 여기서 나오는 192.168.x.x 는 사무실 안에서만 통하는 주소이고, 바깥에서 보이는 주소는 따로 있습니다(v06). 이 둘을 헷갈리는 것이 첫 번째 함정입니다.

사내 공개에는 사설 IP, 외부 공개에는 공인 IP + 포트포워딩이 필요합니다.

① 사설 IP 확인 — 명령 프롬프트

# 시작 → cmd 입력 → 명령 프롬프트 실행
ipconfig

# 출력에서 "이더넷 어댑터" 또는 "Wi-Fi" 아래를 봅니다
#   IPv4 주소 . . . . . . . . . : 192.168.0.50   ← 이것이 내 사설 IP
#   서브넷 마스크 . . . . . . . : 255.255.255.0
#   기본 게이트웨이 . . . . . . : 192.168.0.1    ← 이것이 공유기 주소
기본 게이트웨이 = 공유기 주소입니다. 나중에 IPTIME 관리 화면에 들어갈 때 브라우저 주소창에 이 값을 칩니다. 대부분 192.168.0.1 이고, 통신사 장비를 함께 쓰면 172.30.1.254 처럼 나오기도 합니다.

② 포트가 비어 있는지 확인

포트는 한 번에 한 프로그램만 쓸 수 있습니다. 이미 다른 프로그램이 쓰고 있으면 내 앱이 뜨지 않습니다. 

# 8080 을 누가 쓰고 있는지
netstat -ano | findstr :8080

# 결과가 아무것도 없으면 → 비어 있습니다. 그대로 쓰면 됩니다.
# 결과가 나오면 맨 오른쪽 숫자가 PID(프로그램 번호)입니다
#   TCP    0.0.0.0:8080     0.0.0.0:0     LISTENING      12345
#                                                        ^^^^^ PID

# 그 PID 가 어떤 프로그램인지 확인
tasklist | findstr 12345
포트쓰기 전에 알아 둘 것
80 · 443웹 표준 포트. 관리자 권한이 필요하고, 통신사가 가정용 회선에서 막아 두는 경우가 많습니다
8080 · 8443가장 무난한 선택. 권한 문제도 없고 대개 열립니다 — 이 탭은 8080 기준입니다
3389원격 데스크톱. 절대 외부로 열지 마세요 — 자동 공격이 가장 많이 노리는 포트입니다
1~1023시스템 예약 구간. 특별한 이유가 없으면 피합니다
SECTION 03

앱 띄우기 — 창을 닫아도 살아 있게

명령 프롬프트에서 실행하면 그 창을 닫는 순간 서비스가 죽습니다. 로그아웃해도, 재부팅해도 알아서 다시 뜨게 하려면 윈도우 서비스로 등록해야 합니다. 여기까지 해야 "띄웠다"고 할 수 있습니다.

사내에 공유하는 순간부터는 서비스 등록이 선택이 아니라 필수입니다.

0단계 — 반드시 확인할 한 줄: 어느 주소로 대기하는가

가장 많이 막히는 지점입니다. 프로그램이 127.0.0.1:8080 으로 떠 있으면 그 PC 안에서만 열리고 다른 PC 에서는 절대 접속되지 않습니다. 방화벽을 아무리 열어도 소용없습니다.
반드시 0.0.0.0(모든 주소에서 받기)으로 떠야 합니다. 
# 확인 — 왼쪽 주소가 0.0.0.0 이어야 합니다
netstat -ano | findstr :8080
#  TCP    0.0.0.0:8080     0.0.0.0:0    LISTENING   → 좋습니다
#  TCP    127.0.0.1:8080   0.0.0.0:0    LISTENING   → 밖에서 못 들어옵니다
프레임워크모든 주소에서 받게 하는 설정
Spring Bootserver.address=0.0.0.0 (기본값이 이미 전체이므로 대개 손댈 필요 없음) · server.port=8080
Node · Expressapp.listen(8080, '0.0.0.0') — 호스트를 안 적으면 환경에 따라 로컬만 열립니다
Python · FastAPIuvicorn main:app --host 0.0.0.0 --port 8080
Python · Djangopython manage.py runserver 0.0.0.0:8080 + ALLOWED_HOSTS 에 IP 추가
.NET--urls http://0.0.0.0:8080 또는 ASPNETCORE_URLS 환경 변수

방법 A — NSSM 으로 서비스 등록 (가장 쉬움)

NSSM 은 아무 실행 파일이나 윈도우 서비스로 만들어 주는 작은 도구입니다. 설치도 필요 없고 파일 하나면 됩니다. 초보자에게 가장 권합니다. 

:: 1) nssm.exe 를 내려받아 C:\tools\nssm.exe 에 둡니다 (공식 사이트: nssm.cc)
:: 2) 관리자 권한 명령 프롬프트를 엽니다 (시작 → cmd 우클릭 → 관리자 권한으로 실행)

:: 3) 설치 창 열기 — 빈칸을 채우는 방식이라 편합니다
C:\tools\nssm.exe install MyApp

::    Application 탭
::      Path             : C:\Program Files\Java\jdk-21\bin\java.exe
::      Startup directory: C:\apps\myapp
::      Arguments        : -jar myapp.jar --server.port=8080
::    I/O 탭 (로그를 파일로 남깁니다 — 나중에 문제 볼 때 꼭 필요합니다)
::      Output (stdout)  : C:\apps\myapp\logs\out.log
::      Error  (stderr)  : C:\apps\myapp\logs\err.log
::    Exit actions 탭
::      Restart          : 죽으면 자동 재시작 (기본값 그대로 두면 됩니다)

:: 4) 시작 · 상태 확인 · 중지
net start MyApp
sc query MyApp
net stop MyApp

:: 5) 서비스 삭제가 필요하면
C:\tools\nssm.exe remove MyApp confirm

방법 B — 윈도우 기본 명령(sc.exe)만 쓰기

:: 실행 파일이 .exe 하나로 끝나는 경우에만 간단합니다 (.NET 게시물 · Go 빌드 등)
sc create MyApp binPath= "C:\apps\myapp\myapp.exe" start= auto DisplayName= "사내 도구"
::  ↑ 등호(=) 뒤에 반드시 공백이 한 칸 있어야 합니다. 이것이 안 되는 이유 1위입니다.

sc description MyApp "사내 재고 조회 도구 (8080)"
sc failure MyApp reset= 86400 actions= restart/5000/restart/5000/restart/10000
net start MyApp
java -jar 처럼 인자가 붙는 명령은 sc.exe 로 바로 안 됩니다. binPath 에는 실행 파일 하나만 들어가야 하므로, 이런 경우 NSSM(방법 A) 을 쓰거나 .bat 로 감싼 뒤 그 배치를 서비스로 만들어야 합니다. 초보자라면 NSSM 이 훨씬 안전합니다.

방법 C — 작업 스케줄러 (서비스가 부담스러울 때)

:: 시작 → "작업 스케줄러" → 작업 만들기
::   일반   : "사용자의 로그온 여부에 관계없이 실행" 체크 + "가장 높은 수준의 권한으로 실행" 체크
::   트리거 : 시작할 때
::   동작   : 프로그램 시작 → C:\apps\myapp\start.bat
::   설정   : "작업이 실패하면 다시 시작" 체크

:: start.bat 예시
@echo off
cd /d C:\apps\myapp
java -jar myapp.jar --server.port=8080 >> logs\out.log 2>&1
어느 방법이든 확인은 같습니다. 서버 PC 브라우저에서 http://localhost:8080 이 열리고, netstat -ano | findstr :8080 에 0.0.0.0:8080 LISTENING 이 보이면 이 단계는 끝입니다.
SECTION 04

윈도우 방화벽 — 그 포트만 열기

프로그램은 떠 있는데 다른 PC 에서 안 열린다면 열에 아홉은 방화벽입니다. 방화벽을 통째로 끄는 것은 위험하니, 필요한 포트 하나만 여는 규칙을 만듭니다.

방화벽 차단은 거절이 아니라 침묵이라, 증상만으로는 원인을 알기 어렵습니다.

명령 한 줄로 여는 법 (권장)

:: 관리자 권한 PowerShell 에서
New-NetFirewallRule -DisplayName "사내도구 8080" -Direction Inbound -Protocol TCP -LocalPort 8080 -Action Allow -Profile Domain,Private

:: 명령 프롬프트를 쓴다면 (netsh)
netsh advfirewall firewall add rule name="사내도구 8080" dir=in action=allow protocol=TCP localport=8080

:: 잘 들어갔는지 확인
netsh advfirewall firewall show rule name="사내도구 8080"

:: 나중에 지울 때
netsh advfirewall firewall delete rule name="사내도구 8080"
위 PowerShell 명령에서 -Profile Domain,Private 를 붙인 이유는 사내망에서만 열고 공용 네트워크에서는 막기 위해서입니다. 카페 와이파이에 노트북을 물렸을 때 자동으로 닫히므로 훨씬 안전합니다. 외부 공개(포트포워딩)를 할 때는 공유기를 거쳐 들어오는 접속도 사내망에서 오는 것처럼 보이므로 이 설정 그대로 동작합니다.

화면에서 클릭으로 하는 법

순서할 일
1시작 → "고급 보안이 포함된 Windows Defender 방화벽" 실행 (또는 wf.msc)
2왼쪽에서 인바운드 규칙 → 오른쪽 새 규칙
3포트 선택 → 다음 → TCP · 특정 로컬 포트에 8080
4연결 허용 → 프로필은 도메인 · 개인만 체크(공용은 해제)
5이름을 "사내도구 8080" 처럼 알아볼 수 있게 — 나중에 정리할 때 필요합니다
방화벽을 끄지 마세요. "일단 꺼 보고 되면 켠다"는 흔한 방법이지만, 끈 채로 잊어버리는 일이 자주 생깁니다. 확인이 목적이라면 규칙을 만들어 켠 상태로 테스트하고, 정 안 되면 잠깐 끄고 확인한 즉시 다시 켜세요.
SECTION 05

사내망에서 접속 확인

여기까지 왔으면 같은 사무실의 다른 PC 에서 열려야 합니다. 안 열린다면 어디가 막혔는지 순서대로 좁히면 됩니다 — 감으로 찍지 마세요.

직원에게 알려 줄 주소

http://192.168.0.50:8080

· http:// 를 빼면 브라우저가 검색어로 인식합니다 — 반드시 붙여서 알려 주세요
· 포트(:8080)를 빼면 80 번으로 가서 안 열립니다
· 사내 어디서나 같은 주소입니다 (같은 공유기·같은 대역일 때)

막혔을 때 — 이 순서로 3분이면 찾습니다

단계확인 명령 (직원 PC 에서)결과가 나쁘면
1 ping 192.168.0.50 응답 없으면 네트워크 문제 — 같은 공유기인지, 유선/무선이 분리돼 있지 않은지 확인. 서버 PC 방화벽이 ping 을 막기도 하니 2단계도 해 보세요
2 Test-NetConnection 192.168.0.50 -Port 8080
(PowerShell)		 TcpTestSucceeded : False 면 포트가 막힌 것 — 방화벽(v04) 또는 앱이 안 떠 있음(v03)
3 서버 PC 에서 http://localhost:8080 여기서도 안 열리면 앱 문제입니다 — 로그 파일부터 보세요
4 서버 PC 에서 netstat -ano | findstr :8080 127.0.0.1:8080 으로 떠 있으면 0.0.0.0 으로 바꿔야 합니다(v03 0단계)
IP 대신 컴퓨터 이름으로도 됩니다. 서버 PC 이름이 SRV-TOOL 이라면 사내에서 http://srv-tool:8080 으로 접속됩니다. IP 가 바뀌어도 주소가 유지돼 편하지만, 회사 네트워크 구성에 따라 안 될 수도 있으니 IP 방식을 기본으로 안내하고 이름은 보조로 알려 주세요.
서버 PC 의 IP 는 언젠가 바뀝니다. 공유기가 자동으로 나눠 주는 주소이기 때문입니다. 바뀌면 직원들이 쓰던 주소가 전부 깨집니다 — 다음 섹션에서 IP 를 고정합니다. 사내 공개만 할 계획이어도 이 작업은 하세요.
SECTION 06

공유기 구조 — 왜 포트포워딩이 필요한가

사무실 전체가 공인 IP 하나를 나눠 쓰고 있습니다. 밖에서 그 주소로 들어오면 공유기는 "이 요청을 안쪽 어느 PC 에게 줘야 하지?" 를 알 수 없습니다. 그 답을 미리 적어 두는 것이 포트포워딩입니다.

포트포워딩은 공유기에게 배달지를 알려 주는 일입니다 — 그 이상도 이하도 아닙니다.

먼저 할 일 — 서버 PC 의 사설 IP 고정

두 가지 방법이 있고, 공유기에서 예약하는 쪽(A)이 더 안전합니다. PC 설정을 잘못 건드려 인터넷이 끊기는 사고가 없기 때문입니다.

A. 공유기에서 예약 (권장)
IPTIME 관리 화면
→ 고급 설정
→ 네트워크 관리
→ 내부 네트워크 설정
→ "수동 IP 할당" 또는 "DHCP 예약"

MAC 주소  : 서버 PC 의 랜카드 주소
할당 IP   : 192.168.0.50

· PC 설정은 자동(DHCP) 그대로 둡니다
· 공유기가 늘 같은 주소를 줍니다
· 되돌리기 쉽습니다
B. PC 에서 직접 고정
설정 → 네트워크 → 어댑터 옵션
→ 이더넷 속성 → IPv4 → 속성

IP 주소   : 192.168.0.50
서브넷    : 255.255.255.0
게이트웨이: 192.168.0.1
DNS       : 168.126.63.1 (또는 8.8.8.8)

· 게이트웨이·DNS 를 빼먹으면 인터넷이 끊깁니다
· 다른 기기와 IP 가 겹치면 둘 다 이상해집니다
· DHCP 범위 밖의 번호를 골라야 안전합니다
:: 서버 PC 의 MAC 주소 확인 (A 방법에서 필요합니다)
ipconfig /all
::   물리적 주소 . . . . . . . . : 1C-1B-0D-XX-XX-XX   ← 이 값

:: 고정한 뒤 확인 — 재부팅해도 같은 주소가 나와야 합니다
ipconfig | findstr IPv4
SECTION 07

IPTIME 포트포워딩 설정

화면을 따라가며 규칙 한 줄만 넣으면 됩니다. 넣을 값은 네 개 — 규칙 이름 · 내부 IP · 외부 포트 · 내부 포트 입니다.

외부 포트와 내부 포트는 달라도 됩니다 — 이 점이 간단한 보안 장치가 됩니다.

화면 순서 (IPTIME 공통)

순서할 일
1브라우저에 192.168.0.1 입력 → 관리자 로그인 (초기값 admin / admin — 반드시 바꿉니다, v10)
2왼쪽 위 관리도구 클릭 → 고급 설정
3NAT/라우터 관리 → 포트포워드 설정
4새 규칙 추가 — 규칙이름 사내도구 / 내부 IP 192.168.0.50 / 프로토콜 TCP
5외부 포트 8080 ~ 8080 · 내부 포트 8080 ~ 8080 입력 → 적용
6목록에 규칙이 보이면 끝. 공유기 재부팅은 필요 없습니다
"현재 접속된 IP 주소" 버튼이 있는 모델이 많습니다. 누르면 지금 붙어 있는 기기 목록이 나오고, 서버 PC 를 고르면 내부 IP 가 자동으로 채워집니다 — 오타를 막는 가장 쉬운 방법입니다.
DMZ 는 쓰지 마세요. "포트포워딩이 귀찮으니 DMZ 로 다 열자"는 안내가 인터넷에 많지만, DMZ 는 그 PC 의 모든 포트를 인터넷에 여는 설정입니다. 원격 데스크톱·파일 공유까지 전부 노출됩니다. 필요한 포트 하나만 여는 것이 원칙입니다.

UPnP 로 자동 등록하는 방법도 있지만

프로그램이 공유기에 스스로 포트를 여는 기능(UPnP)이 있습니다. 편하지만 어떤 프로그램이든 마음대로 포트를 열 수 있다는 뜻이라 회사 환경에서는 권하지 않습니다. 손으로 규칙을 넣고, 어떤 포트가 열려 있는지 문서로 남기는 편이 안전합니다.

SECTION 08

외부 접속 확인 — 안 될 때 원인 사전

포트포워딩을 넣었는데도 안 열리는 경우가 많습니다. 원인은 거의 다섯 가지 안에 있습니다. 하나씩 지워 나가면 됩니다.

먼저 — 공인 IP 확인하고 밖에서 접속

1) IPTIME 관리 화면 첫 페이지에서 "외부 IP 주소" 확인
   또는 서버 PC 브라우저에서 검색창에 "내 아이피" 검색

2) 휴대폰에서 Wi-Fi 를 끄고 (반드시 LTE·5G 로) 접속
   http://203.0.113.45:8080

   ※ 사무실 Wi-Fi 에 붙은 채로 공인 IP 로 접속하면
     공유기 모델에 따라 안 열립니다(헤어핀 NAT). 이것은 정상이며 고장이 아닙니다.
     반드시 외부 회선에서 테스트하세요.
증상 · 원인확인 방법해결
① 이중 NAT
공유기가 두 대		 IPTIME 첫 화면의 외부 IP 가 192.168.·172.·10. 으로 시작하면 이중 NAT 입니다 앞단 통신사 장비에도 같은 포트포워딩을 넣거나, IPTIME 을 브리지 모드로 바꿉니다 — 통신사에 문의가 빠릅니다
② ISP 포트 차단 80 · 443 · 21 · 25 로 열었을 때만 안 되고 8080 은 되면 이 경우 가정용 회선은 80·443 을 막는 곳이 많습니다 — 8080 등 다른 포트를 쓰세요
③ 방화벽 프로필 사내에서는 되는데 밖에서만 안 됨 방화벽 규칙 프로필을 확인합니다. 공유기를 거친 접속도 사설 대역에서 오지만, 공용으로 잡힌 네트워크라면 규칙이 적용되지 않습니다(v04)
④ 내부 IP 가 바뀜 어제까지 되다가 오늘 안 됨 ipconfig 로 지금 IP 를 보고 포트포워딩 규칙과 같은지 확인 — 다르면 IP 고정(v06)을 안 한 것입니다
⑤ 공인 IP 가 바뀜 주소를 다시 확인하니 예전과 다름 대부분의 회선은 재부팅하면 공인 IP 가 바뀝니다 — DDNS(v09) 로 고정된 이름을 만듭니다
외부에서 포트가 열렸는지 빠르게 보는 법
휴대폰(LTE)에서 Test-NetConnection 을 쓸 수는 없으니, 브라우저로 열어 보는 것이 가장 간단합니다. "포트 열림 확인" 사이트도 있지만 회사 IP 를 외부 사이트에 입력하는 셈이므로, 가능하면 직접 접속으로 확인하세요.
여기서부터는 인터넷 전체에 열린 상태입니다. 포트를 연 순간부터 몇 분 안에 자동 스캔이 붙습니다. 로그를 보면 낯선 주소에서 /admin, /.env, /wp-login.php 를 찔러 보는 기록이 쌓입니다. v10 · v11 의 보안 조치를 같은 날 안에 끝내세요.
SECTION 09

DDNS — 바뀌는 IP 대신 이름

공인 IP 는 대개 고정이 아닙니다. 공유기를 재부팅하거나 통신사 사정으로 바뀌면 어제 알려 준 주소가 죽습니다. IPTIME 은 무료 DDNS 를 제공하므로, 우리회사도구.iptime.org 같은 이름을 만들어 쓰면 됩니다.

설정 순서

순서할 일
1IPTIME 관리도구 → 고급 설정 → 특수기능 → DDNS 설정
2호스트 이름에 회사이름도구.iptime.org 입력 (원하는 앞부분만 정하면 됩니다)
3사용자 ID 에 본인 이메일 입력 → 추가
4접속 상태가 "정상 등록" 으로 바뀌는지 확인 (몇 초 걸립니다)
5이제 주소는 http://회사이름도구.iptime.org:8080 — IP 가 바뀌어도 따라갑니다
회사 도메인이 이미 있다면 DNS 에 A 레코드를 추가하는 편이 더 낫습니다. 다만 공인 IP 가 바뀌는 회선이라면 A 레코드를 자동 갱신해 주는 서비스(Cloudflare API 등)를 함께 써야 합니다. 고정 IP 회선이라면 이 고민이 사라지므로, 상시 서비스라면 통신사에 고정 IP 를 신청하는 편이 결국 편합니다.
이름이 생기면 검색·스캔에도 잘 걸립니다. *.iptime.org 대역은 자동 스캐너가 늘 훑는 곳입니다. DDNS 를 켜는 것과 보안 조치(v10·v11) 는 반드시 같이 갑니다.
SECTION 10

최소 보안 ① — 열린 문을 줄입니다

외부 공개에서 가장 중요한 것은 화려한 보안 장비가 아니라 "필요 없는 문을 닫아 두는 것" 입니다. 아래 여섯 가지는 초보자도 30분이면 할 수 있고, 실제 사고의 대부분을 막습니다.

완벽한 방어가 아니라 "쉬운 표적이 되지 않는 것"이 목표입니다.

① 공유기부터 잠급니다 — 5분

설정이유
관리자 비밀번호 변경
기본 설정 → 시스템 관리 → 관리자 설정		admin/admin 그대로면 공유기 자체가 먼저 뚫립니다 — 가장 먼저 하세요
원격 관리 포트 끄기
고급 설정 → 보안 기능 → 공유기 접속·관리 제한		공유기 관리 화면이 인터넷에 열려 있으면 모든 규칙을 남이 바꿀 수 있습니다
DMZ · UPnP 끄기의도치 않게 다른 포트가 열려 있을 수 있습니다 — 목록을 열어 지금 있는 규칙 전부를 확인하세요
공유기 펌웨어 업데이트공개된 취약점이 그대로 남아 있는 구형 펌웨어가 많습니다

② 절대 열면 안 되는 포트

3389(원격 데스크톱) · 445(파일 공유) · 1433·3306·5432(데이터베이스) · 22(SSH, 비밀번호 로그인 상태)
이 포트들을 포트포워딩하면 며칠 안에 무차별 로그인 시도가 시작됩니다. 실제 랜섬웨어 감염 경로 1위가 열린 원격 데스크톱입니다. 원격 접속이 필요하면 포트포워딩이 아니라 VPN 을 쓰세요 — IPTIME 에도 VPN 서버 기능이 있습니다.

③ 접속 가능한 IP 를 좁힙니다 — 가능하면 가장 강력합니다

:: 특정 IP·대역에서만 8080 을 허용 (관리자 PowerShell)
New-NetFirewallRule -DisplayName "사내도구 8080 (제한)" -Direction Inbound -Protocol TCP `
  -LocalPort 8080 -Action Allow `
  -RemoteAddress 192.168.0.0/24, 203.0.113.99, 210.100.50.0/24

::   192.168.0.0/24  → 사내망 전체
::   203.0.113.99    → 지사 고정 IP 하나
::   210.100.50.0/24 → 협력사 대역

:: 기존의 '전체 허용' 규칙은 반드시 삭제하세요 — 남아 있으면 제한이 무의미합니다
netsh advfirewall firewall delete rule name="사내도구 8080"
직원들이 집에서도 봐야 한다면 IP 제한을 쓸 수 없습니다. 그때는 로그인 요구(v11) 가 최소선이 되고, 더 안전하게 하려면 공유기 VPN 을 켜서 "VPN 붙은 사람만 사내망처럼 접속"하게 만듭니다 — 이 방식이면 포트포워딩 자체가 필요 없어집니다.

④ 서버 PC 자체를 정리합니다

항목할 일
계정사용하지 않는 계정 비활성화 · 관리자 비밀번호를 길게(12자 이상) · 자동 로그인 해제
업데이트윈도우 업데이트를 켜 두되 재부팅 시간대를 업무 외 시간으로 지정 (서비스는 자동 시작되므로 안전합니다 — v03)
불필요한 공유net share 로 열린 공유 폴더 확인 → 필요 없는 것 제거
백업앱 폴더와 데이터(DB 파일 등)를 다른 디스크나 NAS 로 매일 복사 — 이것만 있어도 최악은 면합니다
전원 설정절전으로 잠들면 서비스가 멈춥니다 — 전원 옵션에서 절전·최대 절전 해제
SECTION 11

최소 보안 ② — 로그인 · HTTPS · 기록

문을 줄였으면 다음은 들어온 사람을 확인하는 일과 오간 내용을 가리는 일입니다. 둘 다 생각보다 간단하게 붙일 수 있습니다.

① 로그인 — 앱에 없다면 앞에 붙입니다

앱에 자체 로그인이 있으면 그것으로 충분합니다. 없다면 Caddy 를 앞에 두고 기본 인증을 거는 방법이 가장 빠릅니다. Caddy 는 실행 파일 하나로 동작하고 설정도 몇 줄입니다. 

# Caddyfile — 서버 PC 의 C:\caddy\Caddyfile
# 밖에서는 8443 으로 들어오고, 뒤쪽 내 앱(8080)으로 넘깁니다

회사이름도구.iptime.org {
    # 로그인 요구 (아이디: staff)
    basic_auth {
        staff $2a$14$해시값을여기에
    }

    reverse_proxy 127.0.0.1:8080

    # 접속 기록 남기기
    log {
        output file C:\caddy\logs\access.log
        roll_size 10MiB
    }
}
:: 비밀번호 해시 만들기
caddy hash-password --plaintext "여기에실제비밀번호"
::   → $2a$14$... 로 시작하는 문자열이 나옵니다. 이것을 Caddyfile 에 붙여 넣습니다

:: 실행 (테스트)
caddy run --config C:\caddy\Caddyfile

:: 서비스로 등록해 두면 재부팅해도 뜹니다 (v03 의 NSSM 방식 그대로)
이 구성으로 바뀌는 것 — 포트포워딩은 8443 → 192.168.0.50:8443 로 바꾸고, 앱의 8080 은 더 이상 외부에 열지 않습니다(방화벽 규칙 삭제). 밖에서 오는 길이 Caddy 하나로 좁아집니다.

② HTTPS — DDNS 이름이 있으면 자동입니다

위 Caddyfile 의 첫 줄에 도메인 이름을 적어 두면, Caddy 가 인증서를 알아서 발급·갱신합니다. 다만 발급 과정에서 인증 기관이 그 도메인으로 접속해 확인하므로 조건이 있습니다.

상황되는지 · 방법
80·443 을 열 수 있다가장 쉽습니다. 포트포워딩에 80·443 을 추가하면 Caddy 가 자동으로 인증서를 받습니다
ISP 가 80·443 을 막았다HTTP 방식 인증이 안 됩니다 → DNS 챌린지가 필요합니다(도메인 관리 권한 필요). iptime.org 로는 어렵습니다
사내망 전용이다공인 인증서를 받을 수 없습니다 → 사설 인증서를 만들고 각 PC 에 신뢰 등록하거나, HTTP 로 두되 IP 제한 + 로그인으로 갑니다
회사 도메인이 있다서브도메인 하나를 서버로 연결하면 Caddy 자동 HTTPS 가 그대로 동작합니다 — 가장 권하는 형태입니다
HTTP 로 로그인을 받으면 비밀번호가 그대로 흘러갑니다. 사내망이라면 위험이 낮지만, 외부에 공개하면서 HTTPS 가 없다면 그 서비스에는 회사 계정과 같은 비밀번호를 쓰지 않도록 안내해야 합니다.

③ 기록을 남기고 가끔 봅니다

:: 지금 누가 붙어 있는지 (서버 PC 에서)
netstat -an | findstr :8080 | findstr ESTABLISHED

:: 방화벽이 막은 기록을 남기고 싶다면 (로그 파일 위치와 함께 켜기)
netsh advfirewall set allprofiles logging droppedconnections enable
::   기본 위치: C:\Windows\System32\LogFiles\Firewall\pfirewall.log

:: 윈도우 로그인 실패 기록 확인 (이벤트 ID 4625)
wevtutil qe Security /q:"*[System[(EventID=4625)]]" /c:20 /rd:true /f:text
무엇을 봐야 하나요
· 접속 로그에 모르는 IP 가 /admin, /.env, /wp-login.php 를 찔러 보는 기록 — 자동 스캔입니다. 로그인이 걸려 있으면 그냥 실패하고 끝납니다
· 로그인 실패가 짧은 시간에 수십 번 — 무차별 대입입니다. 해당 IP 를 방화벽에서 차단하거나 IP 제한(v10)으로 전환하세요
· 일주일에 한 번, 5분만 보면 충분합니다. 안 보는 로그는 없는 것과 같습니다
