SECTION 01

MPM — 세 가지 처리 방식

Apache 는 요청을 어떻게 나눠 처리할지 골라 쓸 수 있습니다. 이 선택이 메모리 사용량과 동시 처리 능력을 결정합니다.

MPM구조메모리동시성쓰는 곳
prefork요청당 프로세스 1개많음낮음 스레드 안전하지 않은 모듈(옛 mod_php)이 있을 때
worker프로세스 × 스레드중간중간 prefork 와 event 의 중간
eventworker + 유휴 연결 분리적음높음 ★ 2.4 기본값 — 특별한 이유가 없으면 이것
event MPM 이 개선한 것 — prefork·worker 는 keepalive 로 놀고 있는 연결도 프로세스·스레드를 붙잡고 있었습니다. event MPM 은 유휴 연결을 전담 스레드에 넘겨 작업 스레드를 풀어 줍니다. Nginx 의 이벤트 모델에 한 걸음 다가간 구조입니다.
다만 PHP 를 모듈(mod_php)로 쓰면 prefork 가 강제되므로, PHP-FPM 으로 분리해야 event 를 쓸 수 있습니다. 
# 현재 MPM 확인
apachectl -V | grep MPM
# Server MPM:     event

# Ubuntu 계열에서 전환
sudo a2dismod mpm_prefork
sudo a2enmod mpm_event
sudo systemctl restart apache2

# ※ mod_php 가 켜져 있으면 event 로 전환되지 않습니다
sudo a2dismod php8.3
sudo a2enmod proxy_fcgi setenvif
sudo a2enconf php8.3-fpm
# mpm_event.conf — 동시 처리 설정
<IfModule mpm_event_module>
    StartServers             4
    MinSpareThreads         25
    MaxSpareThreads         75
    ThreadsPerChild         25
    MaxRequestWorkers      400      # ★ 동시에 처리할 최대 요청 수
    MaxConnectionsPerChild   0      # 0 = 무제한 (메모리 누수가 있으면 10000 등으로)
</IfModule>
MaxRequestWorkers 를 무작정 올리지 마세요. 각 워커가 메모리를 쓰므로 (워커 수 × 워커당 메모리) 가 물리 메모리를 넘으면 스왑이 발생해 서버가 통째로 느려집니다.
계산법 — ps 로 워커 하나의 실제 메모리를 재고, (가용 메모리 × 0.8) ÷ 워커당 메모리 를 상한으로 잡으세요.

설정 구조 · 모듈

Apache 의 기능은 대부분 모듈로 되어 있습니다. 필요한 것만 켜세요.

# apache2.conf 의 뼈대
ServerRoot "/etc/apache2"
Listen 80

IncludeOptional mods-enabled/*.load
IncludeOptional mods-enabled/*.conf
IncludeOptional conf-enabled/*.conf
IncludeOptional sites-enabled/*.conf      # ← 사이트 설정을 여기서 읽습니다

User  ${APACHE_RUN_USER}
Group ${APACHE_RUN_GROUP}

ServerTokens Prod                         # 응답에 버전을 노출하지 않음
ServerSignature Off
Timeout 60
KeepAlive On
MaxKeepAliveRequests 100
KeepAliveTimeout 5

<Directory />
    Options FollowSymLinks
    AllowOverride None
    Require all denied                    # 기본은 전부 차단 (안전한 기본값)
</Directory>

<Directory /var/www/>
    Options Indexes FollowSymLinks
    AllowOverride None
    Require all granted
</Directory>

# Ubuntu 계열
sudo a2enmod rewrite proxy proxy_http headers deflate expires ssl remoteip
sudo a2dismod autoindex status
sudo systemctl restart apache2

# RHEL 계열 — /etc/httpd/conf.modules.d/*.conf 에서 LoadModule 을 주석 처리·해제
# LoadModule rewrite_module modules/mod_rewrite.so
안 쓰는 모듈은 끄세요. 모듈마다 메모리를 차지하고, 공격 표면이 늘어납니다. 특히 mod_autoindex(디렉터리 목록 노출)와 mod_info·mod_status(설정·상태 노출)는 인터넷에 열려 있으면 심각한 정보 유출이 됩니다.
SECTION 04

VirtualHost

Nginx 의 server 블록과 같은 역할입니다.

# /etc/apache2/sites-available/example.com.conf
<VirtualHost *:80>
    ServerName  example.com
    ServerAlias www.example.com
    DocumentRoot /var/www/example

    <Directory /var/www/example>
        Options -Indexes +FollowSymLinks
        AllowOverride None
        Require all granted
    </Directory>

    ErrorLog  ${APACHE_LOG_DIR}/example-error.log
    CustomLog ${APACHE_LOG_DIR}/example-access.log combined

    # HTTPS 로 리다이렉트
    RewriteEngine On
    RewriteCond %{HTTPS} off
    RewriteRule ^(.*)$ https://%{HTTP_HOST}$1 [R=301,L]
</VirtualHost>

<VirtualHost *:443>
    ServerName example.com
    DocumentRoot /var/www/example

    SSLEngine on
    SSLCertificateFile    /etc/letsencrypt/live/example.com/fullchain.pem
    SSLCertificateKeyFile /etc/letsencrypt/live/example.com/privkey.pem

    Header always set Strict-Transport-Security "max-age=31536000; includeSubDomains"
</VirtualHost>
sudo a2ensite example.com          # 활성화
sudo a2dissite 000-default         # 기본 사이트 비활성화
sudo apachectl configtest
sudo systemctl reload apache2

sudo apachectl -S                  # 어떤 VirtualHost 가 어떤 순서인지 확인
매칭 규칙 — 요청의 Host 헤더와 ServerName·ServerAlias 를 비교하고, 어디에도 안 맞으면 첫 번째 VirtualHost 가 처리합니다. Nginx 의 default_server 같은 명시적 지정이 없으므로, 파일 이름 순서(000-default)로 기본을 정하는 관례가 있습니다.
알 수 없는 Host 를 거부하려면 맨 앞 순서에 오는 VirtualHost 를 하나 두고 Redirect 404 / 또는 빈 응답을 주도록 설정하세요. 봇 스캔이 엉뚱한 사이트에 접근하는 것을 막습니다.
SECTION 05

Directory · Location · Files

셋 다 "어디에 적용할지" 정하지만 기준이 다릅니다. 이 구분이 Apache 설정의 핵심입니다.

지시어기준예
<Directory>파일 시스템 경로<Directory /var/www/app>
<Location>URL 경로<Location /admin>
<Files>파일 이름<Files ".env">
<FilesMatch>파일 이름 (정규식)<FilesMatch "\.(env|log)$">
<LocationMatch>URL (정규식)<LocationMatch "^/api/v[0-9]+">
# 파일 시스템 기준 — 실제 폴더에 적용
<Directory /var/www/example>
    Options -Indexes +FollowSymLinks      # 디렉터리 목록 금지
    AllowOverride None                    # .htaccess 무시 (성능·보안)
    Require all granted
</Directory>

# URL 기준 — 프록시 경로처럼 실제 파일이 없는 곳에도 적용됩니다
<Location /admin>
    Require ip 10.0.0.0/8
    Require ip 203.0.113.5
</Location>

# 민감한 파일 접근 차단 (반드시 넣으세요)
<FilesMatch "^\.|\.(env|git|sql|bak|log|ini|conf)$">
    Require all denied
</FilesMatch>

# 업로드 폴더에서 스크립트 실행 금지 (치명적 취약점 방지)
<Directory /var/www/example/uploads>
    php_admin_flag engine off
    Options -ExecCGI
    AddType text/plain .php .phtml .php3 .php5 .pl .py .cgi
</Directory>
적용 순서 — <Directory>(경로가 짧은 것부터) → <Files> → <Location> 순서로 적용되며, 뒤에 적용된 것이 앞을 덮어씁니다. <Location> 이 가장 마지막이라 가장 강력합니다.

Options 지시어

옵션의미
Indexesindex 파일이 없으면 디렉터리 목록을 보여 줍니다 — 운영에서는 반드시 -Indexes
FollowSymLinks심볼릭 링크를 따라감 (성능상 권장)
SymLinksIfOwnerMatch소유자가 같을 때만 따라감 (더 안전하지만 느림)
ExecCGICGI 실행 허용 — 필요한 곳에만
MultiViews확장자 없이 접근 시 추측 — 예상 밖 동작의 원인이 되므로 끄는 편이 낫습니다
SECTION 06

.htaccess — 쓸 것인가

Apache 만의 특징입니다. 폴더마다 두는 설정 파일로, 서버 설정을 못 건드리는 환경에서 유용합니다.

장점
· 서버 재시작 없이 즉시 반영
· 서버 설정 접근 권한 없이 사용 가능
  (공유 호스팅의 핵심)
· 애플리케이션과 함께 배포 가능
  (워드프레스·라라벨이 기본 제공)
· 폴더 단위로 권한 위임
단점
· ★ 요청마다 파일을 읽습니다
  (상위 폴더 전부를 거슬러 올라가며!)
· 설정이 여러 곳에 흩어져 추적이 어려움
· 문법 오류 시 500 오류 (검증 단계 없음)
· 사용자가 보안 설정을 무력화할 수 있음
성능 비용이 생각보다 큽니다. /var/www/app/a/b/c/file.php 요청이 오면 Apache 는 / → /var → /var/www → … → /c 까지 모든 폴더에서 .htaccess 를 찾습니다. 요청 하나에 디스크 접근이 수 회 발생합니다.
서버 설정을 직접 고칠 수 있다면 AllowOverride None 으로 끄고 VirtualHost 에 직접 쓰세요. 
# 완전히 끄기 (권장 · 성능 향상)
<Directory /var/www/>
    AllowOverride None
</Directory>

# 필요한 것만 허용
<Directory /var/www/app/>
    AllowOverride FileInfo Options=Indexes
</Directory>

전형적인 .htaccess (워드프레스·라라벨)

# 프런트 컨트롤러 패턴 — 실제 파일이 없으면 index.php 로
<IfModule mod_rewrite.c>
    RewriteEngine On
    RewriteBase /

    RewriteCond %{REQUEST_FILENAME} !-f
    RewriteCond %{REQUEST_FILENAME} !-d
    RewriteRule ^ index.php [L]
</IfModule>

# 민감 파일 차단
<FilesMatch "^\.|composer\.(json|lock)$">
    Require all denied
</FilesMatch>

# 디렉터리 목록 금지
Options -Indexes
이 설정을 VirtualHost 로 옮기는 법 — .htaccess 의 내용을 <Directory /var/www/app> 블록 안에 그대로 복사하고 AllowOverride None 으로 바꾸면 됩니다. RewriteBase 만 상황에 맞게 조정하세요. 성능이 개선되고 설정이 한 곳에 모입니다.
SECTION 07

mod_rewrite

Apache 의 가장 강력한 기능이자 가장 어려운 부분입니다. 레거시 시스템 유지보수에서 반드시 만나게 됩니다. 

RewriteEngine On

# ── 기본 형태
# RewriteCond  조건 (여러 개 가능 · AND 로 묶임)
# RewriteRule  패턴  대체  [플래그]

# HTTPS 강제
RewriteCond %{HTTPS} off
RewriteRule ^(.*)$ https://%{HTTP_HOST}%{REQUEST_URI} [R=301,L]

# www 제거
RewriteCond %{HTTP_HOST} ^www\.(.+)$ [NC]
RewriteRule ^(.*)$ https://%1/$1 [R=301,L]

# 실제 파일이 없으면 index.php 로 (프런트 컨트롤러)
RewriteCond %{REQUEST_FILENAME} !-f
RewriteCond %{REQUEST_FILENAME} !-d
RewriteRule ^ index.php [L]

# 옛 URL 을 새 URL 로
RewriteRule ^article/([0-9]+)$ /posts/$1 [R=301,L]

# 내부 재작성 (주소는 그대로, 처리만 다른 곳에서)
RewriteRule ^api/(.*)$ /backend/api.php?path=$1 [QSA,L]
플래그의미
LLast — 여기서 규칙 처리를 멈춥니다 (거의 항상 붙입니다)
R=301브라우저에 리다이렉트 응답 (301 영구 · 302 임시)
QSAQuery String Append — 원래 쿼리스트링을 유지
NC대소문자 무시
P프록시로 전달 (mod_proxy 필요)
F403 Forbidden 응답
E=VAR:val환경 변수 설정

디버깅 — 규칙이 왜 안 먹는지

# 2.4 부터는 LogLevel 로 rewrite 추적을 켭니다
LogLevel warn rewrite:trace3

# error.log 에 각 단계가 기록됩니다
# trace1(간단) ~ trace8(매우 상세) · 운영에서는 반드시 끄세요 (로그 폭증)
[rewrite:trace3] applying pattern '^(.*)$' to uri '/article/123' [rewrite:trace2] rewrite '/article/123' -> '/posts/123' [rewrite:trace1] escaping /posts/123 for redirect
mod_rewrite 의 흔한 함정
· 무한 루프 — 재작성 결과가 다시 같은 규칙에 걸립니다. RewriteCond 로 탈출 조건을 넣으세요
· .htaccess 에서는 경로 앞의 / 가 제거됩니다 — VirtualHost 와 패턴이 달라집니다
· L 플래그가 .htaccess 에서는 완전히 끝내지 않습니다 — 재작성 후 다시 처음부터 돕니다. 확실히 끝내려면 END 플래그(2.3.9+)를 쓰세요
· 조건이 여러 개면 AND 입니다. OR 를 원하면 [OR] 플래그를 붙이세요
단순한 리다이렉트에는 mod_rewrite 를 쓰지 마세요. Redirect 301 /old /new 나 RedirectMatch 가 훨씬 빠르고 읽기 쉽습니다. mod_rewrite 는 조건이 필요한 복잡한 경우에만 씁니다.
SECTION 08

리버스 프록시 mod_proxy

Apache 도 프록시가 됩니다. Tomcat 앞단으로 쓰는 구성이 특히 흔합니다.

# 모듈 활성화
# sudo a2enmod proxy proxy_http proxy_balancer lbmethod_byrequests headers

<VirtualHost *:80>
    ServerName example.com

    ProxyPreserveHost On                  # 원래 Host 헤더를 유지
    ProxyRequests Off                     # ★ 정방향 프록시 금지 (켜면 오픈 프록시가 됩니다)

    ProxyPass        /api/ http://127.0.0.1:8080/api/
    ProxyPassReverse /api/ http://127.0.0.1:8080/api/

    # 실제 IP 전달
    RequestHeader set X-Forwarded-Proto "http"
    RequestHeader set X-Real-IP %{REMOTE_ADDR}s

    # 정적 파일은 프록시하지 않음
    ProxyPass /static/ !
    Alias /static/ /var/www/static/

    ProxyTimeout 60
</VirtualHost>
ProxyRequests Off 를 반드시 확인하세요. 이것이 On 이면 정방향 프록시가 되어 누구나 우리 서버를 거쳐 아무 사이트에나 접속할 수 있습니다. 스팸·불법 트래픽의 경유지가 되어 IP 가 차단됩니다. (기본값은 Off 이지만 잘못 켜 두는 사례가 있습니다)

로드 밸런싱

<Proxy balancer://mycluster>
    BalancerMember http://10.0.1.11:8080 loadfactor=3
    BalancerMember http://10.0.1.12:8080
    BalancerMember http://10.0.1.13:8080 status=+H      # H = 대기(핫 스탠바이)

    ProxySet lbmethod=byrequests                        # bytraffic · bybusyness 도 있음
</Proxy>

ProxyPass        / balancer://mycluster/
ProxyPassReverse / balancer://mycluster/

# 관리 화면 (내부에서만 접근 가능하게)
<Location /balancer-manager>
    SetHandler balancer-manager
    Require ip 10.0.0.0/8
</Location>

AJP — Tomcat 전용 프로토콜

# sudo a2enmod proxy_ajp
ProxyPass        /app/ ajp://127.0.0.1:8009/app/
ProxyPassReverse /app/ ajp://127.0.0.1:8009/app/
AJP 는 신중하게 쓰세요. 2020년 Ghostcat(CVE-2020-1938) 취약점 이후 Tomcat 은 AJP 커넥터를 기본 비활성화했고, 활성화하더라도 secretRequired 와 address="127.0.0.1" 이 필요합니다. 특별한 이유가 없으면 그냥 HTTP 프록시를 쓰세요 — 성능 차이는 미미합니다.
SECTION 09

HTTPS 설정

개념은 Nginx 와 같고 지시어 이름만 다릅니다.

<VirtualHost *:443>
    ServerName example.com
    DocumentRoot /var/www/example

    SSLEngine on
    SSLCertificateFile      /etc/letsencrypt/live/example.com/fullchain.pem
    SSLCertificateKeyFile   /etc/letsencrypt/live/example.com/privkey.pem
    # 2.4.8 미만에서는 체인을 따로 지정했습니다
    # SSLCertificateChainFile /etc/letsencrypt/live/example.com/chain.pem

    SSLProtocol             -all +TLSv1.2 +TLSv1.3
    SSLHonorCipherOrder     off
    SSLCipherSuite          ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-RSA-AES128-GCM-SHA256:ECDHE-ECDSA-AES256-GCM-SHA384:ECDHE-RSA-AES256-GCM-SHA384

    SSLUseStapling on
    SSLStaplingCache "shmcb:logs/ssl_stapling(32768)"

    Header always set Strict-Transport-Security "max-age=31536000; includeSubDomains"
</VirtualHost>

# HTTP → HTTPS
<VirtualHost *:80>
    ServerName example.com
    Redirect permanent / https://example.com/
</VirtualHost>
# certbot 이 Apache 설정까지 자동으로 해 줍니다
sudo apt install -y certbot python3-certbot-apache
sudo certbot --apache -d example.com -d www.example.com

# 인증서만 받고 설정은 직접
sudo certbot certonly --apache -d example.com
HTTP/2 를 쓰려면 — sudo a2enmod http2 후 VirtualHost 에 Protocols h2 http/1.1 을 추가합니다. 다만 prefork MPM 에서는 HTTP/2 가 동작하지 않습니다 — event MPM 이 필요합니다.
인증서 발급·갱신·진단은 🔐 HTTPS 탭에서 자세히 다룹니다.
SECTION 10

인증 · 접근 제어

Apache 는 이 부분이 특히 강합니다. 관리자 페이지 보호에 그대로 씁니다.

# 비밀번호 파일 만들기 (문서 루트 밖에 두세요)
sudo htpasswd -c /etc/apache2/.htpasswd admin      # -c 는 최초 1회만
sudo htpasswd /etc/apache2/.htpasswd user2         # 추가
<Location /admin>
    AuthType Basic
    AuthName "Restricted Area"
    AuthUserFile /etc/apache2/.htpasswd
    Require valid-user
</Location>

# IP 제한
<Location /internal>
    Require ip 10.0.0.0/8
    Require ip 203.0.113.5
</Location>

# IP 또는 인증 (둘 중 하나만 통과하면 됨)
<Location /admin>
    <RequireAny>
        Require ip 10.0.0.0/8
        Require valid-user
    </RequireAny>
</Location>

# IP 이면서 인증 (둘 다 필요)
<Location /danger>
    <RequireAll>
        Require ip 10.0.0.0/8
        Require valid-user
    </RequireAll>
</Location>
Basic 인증은 HTTPS 에서만 쓰세요. 비밀번호가 Base64 인코딩될 뿐 암호화되지 않습니다. HTTP 로 쓰면 네트워크에서 그대로 읽힙니다.
또 2.2 문법(Order·Allow from)은 2.4 에서 폐기됐습니다. 옛 설정을 옮길 때는 Require 문법으로 바꿔야 합니다.

2.2 → 2.4 접근 제어 문법 변환

2.2 (폐기)2.4
Order allow,deny
Allow from all		Require all granted
Order deny,allow
Deny from all		Require all denied
Allow from 10.0.0.0/8Require ip 10.0.0.0/8
Allow from example.comRequire host example.com
SECTION 11

압축 · 캐시 헤더

모듈을 켜고 설정하면 정적 자원 성능이 크게 달라집니다.

# sudo a2enmod deflate expires headers

# ── 압축
<IfModule mod_deflate.c>
    AddOutputFilterByType DEFLATE text/html text/plain text/xml text/css
    AddOutputFilterByType DEFLATE application/javascript application/json
    AddOutputFilterByType DEFLATE application/xml image/svg+xml

    DeflateCompressionLevel 5

    # 이미 압축된 것은 제외
    SetEnvIfNoCase Request_URI \.(?:gif|jpe?g|png|webp|zip|gz|mp4)$ no-gzip dont-vary
</IfModule>

# ── 캐시 헤더
<IfModule mod_expires.c>
    ExpiresActive On
    ExpiresByType image/jpeg      "access plus 1 month"
    ExpiresByType image/png       "access plus 1 month"
    ExpiresByType image/svg+xml   "access plus 1 month"
    ExpiresByType text/css        "access plus 1 year"
    ExpiresByType application/javascript "access plus 1 year"
    ExpiresByType text/html       "access plus 0 seconds"
</IfModule>

# 해시가 붙은 파일은 영구 캐시
<FilesMatch "\.[0-9a-f]{8,}\.(js|css)$">
    Header set Cache-Control "public, max-age=31536000, immutable"
</FilesMatch>

# index.html 은 캐시 금지
<Files "index.html">
    Header set Cache-Control "no-store, must-revalidate"
</Files>

보안 헤더도 여기서

<IfModule mod_headers.c>
    Header always set X-Content-Type-Options "nosniff"
    Header always set X-Frame-Options "SAMEORIGIN"
    Header always set Referrer-Policy "strict-origin-when-cross-origin"
    Header always set Permissions-Policy "geolocation=(), microphone=(), camera=()"
    Header always set Strict-Transport-Security "max-age=31536000; includeSubDomains"

    # 서버 정보 제거
    Header unset X-Powered-By
    Header unset Server
</IfModule>
always 키워드를 붙이세요. 없으면 2xx·3xx 응답에만 헤더가 붙고 4xx·5xx 오류 응답에는 빠집니다. 보안 헤더는 오류 페이지에도 적용돼야 의미가 있습니다.
SECTION 12

로그와 진단

Apache 의 error 로그는 정보량이 많습니다. 레벨만 조절할 줄 알면 됩니다.

# 로그 포맷 정의
LogFormat "%h %l %u %t \"%r\" %>s %b \"%{Referer}i\" \"%{User-Agent}i\" %D" combined_time
# %D = 처리 시간(마이크로초) ← 성능 분석에 필수

CustomLog ${APACHE_LOG_DIR}/access.log combined_time
ErrorLog  ${APACHE_LOG_DIR}/error.log

LogLevel warn                     # 평상시
# LogLevel info rewrite:trace3    # rewrite 디버깅 시 (운영에서는 끄세요)
# LogLevel debug proxy:trace5     # 프록시 디버깅

# 특정 요청은 로그에서 제외
SetEnvIf Request_URI "^/health$" dontlog
SetEnvIf Request_URI "\.(css|js|png|jpg|svg)$" dontlog
CustomLog ${APACHE_LOG_DIR}/access.log combined_time env=!dontlog
기호의미
%h클라이언트 IP
%t시각
%r요청 첫 줄 (GET /path HTTP/1.1)
%>s최종 상태 코드
%b응답 크기
%D처리 시간 (마이크로초)
%T처리 시간 (초)
%{X-Forwarded-For}i임의 요청 헤더
# 상태 코드 집계
awk '{print $9}' /var/log/apache2/access.log | sort | uniq -c | sort -rn

# 가장 느린 요청 (마지막 필드가 %D 일 때)
awk '{print $NF, $7}' /var/log/apache2/access.log | sort -rn | head -20

# 실시간 오류만
sudo tail -f /var/log/apache2/error.log | grep -E '\[(error|crit|alert|emerg)\]'

감정적인 논쟁이 많은 주제입니다. 사실만 정리합니다.

언제 무엇을

🟢 Nginx 를 쓰세요
  • 신규 구축
  • 리버스 프록시·로드밸런서
  • 정적 파일·SPA 서빙
  • 동시 접속이 많은 서비스
  • 컨테이너·쿠버네티스 환경
🔵 Apache 가 나은 경우
  • 이미 Apache 로 돌아가는 시스템
  • .htaccess 가 필요한 공유 호스팅
  • 특정 Apache 모듈에 의존
  • 워드프레스 등 기본 지원이 Apache 인 솔루션
  • 팀이 Apache 에 익숙할 때
🟣 둘 다 쓰는 구성
  • Nginx(앞) + Apache(뒤)
  • Nginx 가 정적·TLS·캐시를 처리
  • Apache 가 .htaccess 와 PHP 를 처리
  • 레거시를 유지하며 점진적 이관
솔직한 결론 — 순수 성능 차이는 예전만큼 크지 않습니다. event MPM + PHP-FPM 조합의 Apache 는 상당히 좋은 성능을 냅니다.
실무에서 Nginx 를 고르는 진짜 이유는 설정의 간결함·최신 자료의 양· 컨테이너 생태계와의 궁합입니다. 이미 잘 돌아가는 Apache 를 바꿀 이유는 대개 없습니다.
