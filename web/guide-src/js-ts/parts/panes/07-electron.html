ELECTRON 01

메인 · 렌더러 구조

이 구분 하나만 이해하면 Electron 의 80%는 끝납니다.

두 개의 세계

Main
메인 프로세스 — Node.js 환경 앱당 하나. 창을 만들고, 파일·DB·OS 기능에 접근합니다. fs·child_process 를 쓸 수 있습니다.
▲ IPC ▼
Renderer
렌더러 프로세스 — 브라우저 환경 창마다 하나씩. React·Vue 로 화면을 그립니다. 기본적으로 Node 를 쓸 수 없습니다(그래야 안전합니다).
▲
Preload
프리로드 — 둘 사이의 다리 렌더러가 로드되기 전에 실행되며, 허용된 기능만 화면에 노출합니다.
규칙 하나 — 화면(렌더러)은 파일을 직접 읽을 수 없습니다. “메인에게 부탁 → 메인이 처리 → 결과를 돌려받기”가 모든 기능의 기본 흐름입니다(e03 IPC).

ELECTRON 02

첫 창 띄우기

최소 코드와 운영에 필요한 설정을 함께 봅니다.

메인 프로세스

import { app, BrowserWindow, shell } from "electron";
import path from "node:path";

let mainWindow: BrowserWindow | null = null;

function createWindow() {
  mainWindow = new BrowserWindow({
    width: 1200, height: 800,
    minWidth: 940, minHeight: 600,
    show: false,                              // ★ 준비될 때까지 숨김
    titleBarStyle: process.platform === "darwin" ? "hiddenInset" : "default",
    webPreferences: {
      preload: path.join(__dirname, "../preload/index.js"),
      contextIsolation: true,                 // ★ 반드시 true (e04)
      nodeIntegration: false,                 // ★ 반드시 false
      sandbox: true,
    },
  });

  // ★ 흰 화면 깜빡임 방지
  mainWindow.once("ready-to-show", () => mainWindow?.show());

  // 외부 링크는 기본 브라우저로 (앱 안에서 열면 보안 위험)
  mainWindow.webContents.setWindowOpenHandler(({ url }) => {
    shell.openExternal(url);
    return { action: "deny" };
  });

  if (process.env.NODE_ENV === "development") {
    mainWindow.loadURL("http://localhost:5173");
    mainWindow.webContents.openDevTools();
  } else {
    mainWindow.loadFile(path.join(__dirname, "../renderer/index.html"));
  }
}

앱 생명주기 — OS 마다 다릅니다

app.whenReady().then(() => {
  createWindow();

  // ★ macOS — 독 아이콘 클릭 시 창이 없으면 다시 만듭니다
  app.on("activate", () => {
    if (BrowserWindow.getAllWindows().length === 0) createWindow();
  });
});

// ★ macOS 는 창을 닫아도 앱이 살아 있는 것이 관례입니다
app.on("window-all-closed", () => {
  if (process.platform !== "darwin") app.quit();
});

// 단일 인스턴스 — 두 번 실행되지 않게 (거의 항상 필요합니다)
if (!app.requestSingleInstanceLock()) {
  app.quit();
} else {
  app.on("second-instance", () => {
    if (mainWindow) {
      if (mainWindow.isMinimized()) mainWindow.restore();
      mainWindow.focus();
    }
  });
}

// 종료 전 정리
app.on("before-quit", async (e) => {
  if (hasUnsavedWork) {
    e.preventDefault();
    const ok = await confirmQuit();
    if (ok) { hasUnsavedWork = false; app.quit(); }
  }
});
창 크기·위치를 기억하게 하세요. 데스크탑 앱에서 사용자가 가장 먼저 불편해하는 부분입니다. electron-window-state 라이브러리 한 줄이면 해결됩니다.
ELECTRON 03

IPC 통신

화면과 메인이 대화하는 유일한 통로입니다.

요청-응답 (가장 많이 씁니다)

// ① 메인 — 핸들러 등록
import { ipcMain, dialog } from "electron";

ipcMain.handle("file:read", async (event, filePath: string) => {
  // ★ 반드시 검증하세요 (e04)
  const safe = path.resolve(DATA_DIR, filePath);
  if (!safe.startsWith(path.resolve(DATA_DIR) + path.sep)) {
    throw new Error("잘못된 경로입니다");
  }
  return fs.readFile(safe, "utf8");
});

ipcMain.handle("dialog:openFile", async () => {
  const { canceled, filePaths } = await dialog.showOpenDialog({
    properties: ["openFile"],
    filters: [{ name: "엑셀", extensions: ["xlsx", "csv"] }],
  });
  return canceled ? null : filePaths[0];
});
// ② 프리로드 — 화면에 노출할 API 만 정의
import { contextBridge, ipcRenderer } from "electron";

const api = {
  readFile: (p: string) => ipcRenderer.invoke("file:read", p),
  openFile: () => ipcRenderer.invoke("dialog:openFile"),
};
contextBridge.exposeInMainWorld("api", api);
export type Api = typeof api;                 // ★ 타입을 렌더러에서 재사용

// ③ 렌더러 — 그냥 함수처럼 씁니다
const path = await window.api.openFile();
if (path) {
  const text = await window.api.readFile(path);
}

메인 → 렌더러 (진행률·알림)

// 메인에서 보내기
mainWindow.webContents.send("job:progress", { done: 30, total: 100 });

// 프리로드 — 구독 API 를 만들어 줍니다
const api = {
  onProgress: (cb: (p: Progress) => void) => {
    const listener = (_e: unknown, p: Progress) => cb(p);
    ipcRenderer.on("job:progress", listener);
    return () => ipcRenderer.off("job:progress", listener);   // ★ 해제 함수 반환
  },
};

// 렌더러 (React)
useEffect(() => {
  const off = window.api.onProgress(setProgress);
  return off;                                  // ★ 언마운트 시 해제 (누수 방지)
}, []);

ELECTRON 04

preload · 보안

이 절을 대충 넘기면 사용자 PC 를 공격자에게 내주게 됩니다.

왜 위험한가

nodeIntegration: true 로 두면
  화면(웹 페이지)에서 require("child_process") 가 됩니다.
  → 표시하는 콘텐츠에 XSS 가 하나라도 있으면
  → 공격자가 사용자 PC 에서 "무슨 명령이든" 실행합니다

위험이 들어오는 경로
  · 외부 웹사이트를 iframe·webview 로 표시
  · 서버에서 받은 HTML 을 innerHTML 로 넣기
  · 사용자가 입력한 마크다운 렌더링
  · 취약한 npm 패키지 (🧬 초고급 d13)
// ★ 안전한 기본 설정 — 이대로 두세요
webPreferences: {
  contextIsolation: true,       // 프리로드와 페이지의 컨텍스트 분리
  nodeIntegration: false,       // 페이지에서 Node 사용 불가
  sandbox: true,                // 렌더러를 샌드박스에
  webSecurity: true,            // ★ 개발 편의로도 끄지 마세요
  allowRunningInsecureContent: false,
  preload: path.join(__dirname, "preload.js"),
}
인터넷에서 “해결책”으로 nodeIntegration: true 를 권하는 글이 많습니다. 대부분 오래된 튜토리얼입니다. 지금은 contextBridge 로 필요한 기능만 노출하는 것이 유일한 정답입니다.

안전한 API 노출

❌ 통째로 노출
contextBridge
 .exposeInMainWorld("api", {
   fs: require("fs"),
   exec: require("child_process")
          .exec,
   ipc: ipcRenderer,   // 무엇이든
 });                   // 호출 가능
✅ 기능 단위로
contextBridge
 .exposeInMainWorld("api", {
   readConfig: () =>
     ipcRenderer.invoke("config:read"),
   saveReport: (data) =>
     ipcRenderer.invoke("report:save",
                        data),
 });   // 정해진 동작만
// 메인 쪽에서도 반드시 검증합니다 (프리로드는 우회될 수 있습니다)
ipcMain.handle("report:save", async (event, data: unknown) => {
  // ① 발신자 확인
  if (event.senderFrame?.url !== expectedUrl) throw new Error("거부");

  // ② 입력 검증 (Zod)
  const parsed = ReportSchema.parse(data);

  // ③ 경로·권한 검증
  const target = path.join(app.getPath("documents"), parsed.filename);
  if (!target.startsWith(app.getPath("documents"))) throw new Error("거부");

  await fs.writeFile(target, JSON.stringify(parsed));
});

보안 체크리스트

  • ☐ contextIsolation: true · nodeIntegration: false
  • ☐ CSP 헤더 설정 (인라인 스크립트 차단)
  • ☐ 외부 링크는 shell.openExternal 로만
  • ☐ will-navigate 로 예상 밖 이동 차단
  • ☐ 원격 콘텐츠를 로드한다면 반드시 HTTPS
  • ☐ DB 접속 정보·API 키를 앱에 넣지 않기 — 디컴파일하면 다 보입니다
  • ☐ npm audit · Electron 최신 버전 유지 (Chromium 취약점 패치)
Electron 버전을 오래 방치하지 마세요. Chromium 취약점이 그대로 남아 있게 됩니다. 보안 패치를 받으려면 최신 3개 메이저 버전 안에 머물러야 합니다.

트레이 · 컨텍스트 메뉴 · 단축키

import { Tray, Menu, nativeImage, globalShortcut } from "electron";

// 트레이 (백그라운드 상주 앱에 필수)
const tray = new Tray(nativeImage.createFromPath(iconPath));
tray.setToolTip("내 앱");
tray.setContextMenu(Menu.buildFromTemplate([
  { label: "창 열기", click: () => mainWindow?.show() },
  { label: "동기화", click: sync },
  { type: "separator" },
  { label: "종료", click: () => app.quit() },
]));
tray.on("click", () => mainWindow?.isVisible()
  ? mainWindow.hide() : mainWindow?.show());

// 전역 단축키 — 앱이 배경에 있어도 동작합니다
app.whenReady().then(() => {
  const ok = globalShortcut.register("CmdOrCtrl+Shift+K", () => {
    mainWindow?.show();
    mainWindow?.webContents.send("shortcut:quickOpen");
  });
  if (!ok) log.warn("단축키 등록 실패 — 다른 앱이 사용 중");
});

app.on("will-quit", () => globalShortcut.unregisterAll());   // ★ 정리 필수
// 창을 닫아도 트레이에 남기기 (백그라운드 앱 패턴)
let isQuitting = false;
app.on("before-quit", () => { isQuitting = true; });

mainWindow.on("close", (e) => {
  if (!isQuitting) {
    e.preventDefault();
    mainWindow?.hide();
    return false;
  }
});
전역 단축키는 다른 앱과 충돌합니다. 등록 실패를 조용히 무시하지 말고 사용자에게 알리거나 설정에서 바꿀 수 있게 만드세요. 흔한 조합(Ctrl+Shift+S 등)은 피하는 편이 좋습니다.

ELECTRON 07

데이터 저장

설정은 가볍게, 데이터가 많으면 SQLite.

설정 — electron-store

npm i electron-store
import Store from "electron-store";

type Config = {
  theme: "light" | "dark";
  serverUrl: string;
  recentFiles: string[];
};

const store = new Store<Config>({
  defaults: { theme: "light", serverUrl: "", recentFiles: [] },
  schema: {                                  // ★ 검증 스키마
    theme: { type: "string", enum: ["light", "dark"] },
    serverUrl: { type: "string", format: "uri" },
  },
  encryptionKey: "obfuscation-only",         // ⚠️ 난독화 수준일 뿐입니다
  migrations: {                              // 버전 업 시 데이터 이전
    "1.1.0": (s) => s.set("recentFiles", []),
  },
});

store.get("theme");
store.set("theme", "dark");
store.onDidChange("theme", (newV) => applyTheme(newV));
encryptionKey 는 진짜 암호화가 아닙니다. 키가 앱 안에 들어 있으므로 마음먹으면 풀 수 있습니다. 비밀번호·토큰은 OS 키체인(Electron 내장 safeStorage)에 저장하세요 (keytar 는 개발이 중단되어 권장하지 않습니다). 
// OS 수준 암호화 (Electron 내장)
import { safeStorage } from "electron";

if (safeStorage.isEncryptionAvailable()) {
  const enc = safeStorage.encryptString(token);
  store.set("token", enc.toString("base64"));
  // 복호화
  const dec = safeStorage.decryptString(Buffer.from(store.get("token"), "base64"));
}

    created_at TEXT DEFAULT CURRENT_TIMESTAMP

const windows = new Map<string, BrowserWindow>();

function openDetailWindow(id: string) {
  const existing = windows.get(id);
  if (existing) { existing.focus(); return existing; }   // ★ 중복 방지

  const win = new BrowserWindow({
    width: 800, height: 600,
    parent: mainWindow!,          // 부모 지정 (항상 위에 뜸)
    modal: false,
    webPreferences: { preload, contextIsolation: true, nodeIntegration: false },
  });

  win.loadURL(`${baseUrl}#/detail/${id}`);
  win.on("closed", () => windows.delete(id));            // ★ 정리
  windows.set(id, win);
  return win;
}

// 모든 창에 브로드캐스트
function broadcast(channel: string, payload: unknown) {
  for (const w of BrowserWindow.getAllWindows()) {
    w.webContents.send(channel, payload);
  }
}
창 하나 = 크로미움 렌더러 프로세스 하나입니다. 창 10개면 메모리가 10배가 됩니다. 가벼운 보조 화면은 별도 창 대신 모달·사이드 패널로 만드는 편이 훨씬 낫습니다.

창 간 상태 공유

// ★ 상태의 원본은 "메인 프로세스"에 두세요
class AppState {
  private data: State = initialState;

  update(patch: Partial<State>) {
    this.data = { ...this.data, ...patch };
    broadcast("state:changed", this.data);     // 모든 창에 알림
  }
  get() { return this.data; }
}

ipcMain.handle("state:get", () => appState.get());
ipcMain.handle("state:update", (_e, patch) => appState.update(patch));
// 렌더러 — 훅으로 감싸면 편합니다
function useAppState() {
  const [state, setState] = useState<State | null>(null);

  useEffect(() => {
    window.api.getState().then(setState);
    return window.api.onStateChanged(setState);   // 구독 + 해제
  }, []);

  return [state, window.api.updateState] as const;
}

});

ELECTRON 12

사내 도구 체크리스트

실제로 만들어 배포할 때 놓치기 쉬운 것들을 모았습니다.

설계 단계

  • ☐ 정말 데스크탑 앱이어야 하는가? 웹으로 되는 일이면 웹이 배포·유지보수가 훨씬 쉽습니다. 로컬 파일·프린터·시리얼 포트·오프라인이 필요할 때만 가치가 있습니다
  • ☐ DB 에 직접 붙지 않기 — 접속 정보가 앱에 들어가면 사용자 PC 에서 DB 전체가 열립니다. 반드시 서버 API 를 거치세요
  • ☐ 인증은 서버에서 — 앱 안의 검사는 우회됩니다
  • ☐ 지원할 OS·버전 범위 확정 (Windows 10 이상? 맥 인텔도?)
  • ☐ 코드 서명 인증서 확보 계획 (e09)

개발 단계

  • ☐ contextIsolation: true · nodeIntegration: false (e04)
  • ☐ IPC 채널마다 입력 검증
  • ☐ 설정·DB 는 userData 에 (설치 폴더 X)
  • ☐ 단일 인스턴스 잠금
  • ☐ 창 크기·위치 기억
  • ☐ 로그를 파일로 — 사용자 PC 에서 무슨 일이 났는지 알 유일한 방법

배포 · 운영
