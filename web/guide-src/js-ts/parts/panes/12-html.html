HTML · 화면의 뼈대

태그를
외우는 게
아니라
의미를 고른다

HTML 은 배우기 쉬운데 잘 쓰기는 어려운 언어입니다. <div> 만으로도 화면은 나오기 때문입니다. 이 탭은 왜 그 태그여야 하는가를 기준으로 정리했습니다 — 올바른 태그는 검색 · 접근성 · 키보드 조작 · 폼 검증을 공짜로 얻는 방법입니다. 여기까지 마치면 스크린리더와 검색 엔진이 함께 읽을 수 있는 문서를 짤 수 있습니다.

HTML 01

HTML 은 디자인이 아니라 의미

브라우저는 태그를 보고 역할을 판단합니다. 모양은 CSS 가 따로 정합니다.

같은 화면, 다른 결과

<!-- ✗ 모양만 버튼 -->
<div class="btn" onclick="save()">저장</div>

<!-- ✓ 진짜 버튼 -->
<button type="button" onclick="save()">저장</button>
얻는 것divbutton
Tab 으로 이동✗✓
Enter · Space 로 실행✗✓
낭독기가 "버튼"이라 읽음✗✓
:focus-visible 테두리✗✓
비활성화(disabled)✗✓
div 로 만들면 위 다섯 가지를 전부 직접 구현해야 합니다. tabindex, 키 핸들러, role, aria-disabled… 올바른 태그 하나가 그걸 전부 대신합니다.

태그를 고르는 한 줄 기준

누른다        → button   (페이지 안에서 무언가 실행)
이동한다      → a href    (주소가 바뀐다)
제목이다      → h1 ~ h6
목록이다      → ul / ol / li
입력받는다    → input / textarea / select + label
표다          → table (수치 데이터. 레이아웃 용도 ✗)
그 외 묶음    → div (의미 없는 상자)
글 묶음       → p, section, article
a 와 button 을 바꿔 쓰지 마세요. <a> 는 주소가 있는 이동입니다 — 새 탭으로 열기·주소 복사가 됩니다. 주소가 없는데 <a href="#"> 를 쓰면 키보드 사용자가 링크인 줄 알고 눌렀다가 페이지 맨 위로 튑니다.
시맨틱 HTML 은 취향이 아니라 화면 없이 읽는 세 독자를 위한 API 설계입니다.
HTML 02

문서의 기본 골격

복붙해서 쓰는 뼈대입니다. 줄마다 이유가 있습니다.

<!doctype html>
<html lang="ko">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>페이지 제목 — 사이트 이름</title>
  <meta name="description" content="검색 결과에 뜨는 두 줄 설명">
  <link rel="stylesheet" href="/style.css">
</head>
<body>
  <a class="skip" href="#main">본문 바로가기</a>
  <header>…</header>
  <main id="main">…</main>
  <footer>…</footer>
  <script src="/app.js" defer></script>
</body>
</html>
줄없으면 생기는 일
<!doctype html>브라우저가 호환 모드로 떨어져 CSS 계산이 옛날 방식이 됩니다
lang="ko"낭독기가 영어 발음으로 한글을 읽습니다. 번역 도구도 오작동
charset="utf-8"한글이 깨집니다. head 의 첫 줄에 두세요
viewport모바일에서 PC 화면을 축소해 보여 줍니다 (글씨가 개미만 해짐)
title브라우저 탭·북마크·검색 결과 제목이 비어 버립니다
본문 바로가기(skip link) 는 키보드 사용자를 위한 것입니다. 메뉴가 20개면 Tab 을 20번 눌러야 본문에 닿습니다. 평소엔 화면 밖에 숨겨 두고 포커스를 받을 때만 보이게 합니다 — .skip{position:absolute;left:-9999px} .skip:focus{left:8px;top:8px}
HTML 03

제목 · 문단 · 목록

제목 태그는 글자 크기가 아니라 문서의 목차입니다.

제목은 건너뛰지 않는다

<!-- ✓ 계단처럼 -->
<h1>가이드</h1>
  <h2>설치</h2>
    <h3>윈도우</h3>
    <h3>맥</h3>
  <h2>사용법</h2>

<!-- ✗ h1 다음에 바로 h4 (작아 보여서) -->
<h1>가이드</h1>
<h4>설치</h4>
낭독기 사용자는 제목만 훑어 목차처럼 이동합니다. 단계를 건너뛰면 "여기가 어디의 하위인지" 알 수 없습니다. 작아 보이게 하려면 CSS 로 하세요 — h2{font-size:1rem} 는 아무 문제가 없습니다.

목록 · 인용 · 강조

<ul>                    <!-- 순서 없음 -->
  <li>사과</li>
</ul>

<ol>                    <!-- 순서 있음 (1,2,3) -->
  <li>물을 끓인다</li>
</ol>

<dl>                    <!-- 용어 : 설명 -->
  <dt>HTML</dt>
  <dd>문서의 구조를 적는 언어</dd>
</dl>

<strong>중요</strong>      <!-- 의미상 중요 (낭독기가 강조) -->
<b>굵게</b>              <!-- 그냥 시각적 굵기 -->
<em>강조</em>            <!-- 의미상 강조 -->
<i>기울임</i>            <!-- 그냥 시각적 -->
낭독기는 목록에 들어가면 "항목 5개"라고 먼저 알려 줍니다. <div> 를 줄줄이 세우면 그 정보가 사라집니다.

제목은 크기가 아니라 목차입니다

크기로 고른 제목
h1  사이트 이름
h3  오늘의 특가   ← "h2는 너무 커서"
h1  인기 상품     ← "눈에 띄게"
h4  공지사항

낭독기의 목차 기능이
뒤죽박죽 — 건너뛰며
탐색할 수 없습니다
구조로 고른 제목
h1  여름 세일          (페이지에 하나)
 h2  오늘의 특가
  h3  가전
  h3  패션
 h2  인기 상품
 h2  공지사항

책의 목차처럼 단계가
빠짐없이 이어집니다
크기는 CSS 로 따로!
낭독기 사용자의 대다수가 제목 건너뛰기(H 키)로 페이지를 탐색합니다 — 제목 구조가 곧 그들의 내비게이션입니다. 단계를 건너뛰지 마세요 (h2 다음은 h3, h4 로 점프 ✗).
HTML 04

링크와 이미지

alt 는 장식이 아니라 그 이미지가 하는 말입니다.

링크

<a href="/price">요금제</a>

<!-- 새 탭 — rel 을 반드시 함께 -->
<a href="https://example.com" target="_blank"
   rel="noopener noreferrer">외부 사이트 (새 탭)</a>

<!-- 파일 내려받기 -->
<a href="/guide.pdf" download>PDF 내려받기</a>

<!-- 전화 · 메일 -->
<a href="tel:01012345678">010-1234-5678</a>
<a href="mailto:me@example.com">메일 보내기</a>
"여기를 클릭"은 링크 이름으로 쓰지 마세요. 낭독기 사용자는 링크만 모아서 목록으로 봅니다 — "여기를 클릭"이 열 개면 아무것도 구분되지 않습니다. 링크 글자만 읽어도 어디로 가는지 알 수 있어야 합니다.

이미지

<!-- 내용이 있는 이미지 -->
<img src="chart.png" width="800" height="400"
     alt="2026년 분기별 매출 — 3분기에 40% 상승">

<!-- 장식용(옆에 같은 설명이 이미 있음) -->
<img src="deco.svg" alt="" aria-hidden="true">

<!-- 화면 크기별로 다른 파일 -->
<img src="s.jpg" alt="…"
     srcset="s.jpg 480w, m.jpg 960w, l.jpg 1920w"
     sizes="(max-width:600px) 100vw, 50vw">

<!-- 첫 화면 밖 이미지는 늦게 -->
<img src="below.jpg" alt="…" loading="lazy" decoding="async">
width·height 를 꼭 적으세요. 브라우저가 자리를 미리 잡아 두므로 이미지가 늦게 떠도 글이 아래로 밀리지 않습니다(레이아웃 이동 방지). CSS 로 크기를 바꿔도 비율 계산에만 쓰이니 안전합니다.
HTML 05

폼 — label 이 절반

입력칸에는 반드시 이름표가 붙어야 합니다. placeholder 는 이름표가 아닙니다.

<form action="/signup" method="post">
  <!-- ✓ for ↔ id 로 연결 -->
  <label for="email">이메일</label>
  <input id="email" name="email" type="email"
         autocomplete="email" required>

  <label for="pw">비밀번호</label>
  <input id="pw" name="pw" type="password"
         autocomplete="new-password" minlength="8" required>

  <!-- 라디오·체크박스는 fieldset 으로 묶는다 -->
  <fieldset>
    <legend>알림 받기</legend>
    <label><input type="radio" name="noti" value="y"> 받음</label>
    <label><input type="radio" name="noti" value="n"> 안 받음</label>
  </fieldset>

  <button type="submit">가입</button>
</form>
속성하는 일
name서버로 보내는 키. 없으면 그 값은 전송되지 않습니다
type모바일 키보드 모양이 바뀝니다 (email → @ 키, tel → 숫자판)
autocomplete브라우저 자동완성. 주소·카드 입력에서 이탈률을 크게 줄입니다
required·minlengthJS 없이 브라우저가 검사하고 메시지를 띄웁니다
inputmode키보드만 바꾸고 싶을 때 (numeric 등)
placeholder 를 label 대신 쓰지 마세요. 글자를 입력하는 순간 사라져서 무엇을 넣는 칸인지 알 수 없게 되고, 회색 글씨라 대비가 낮아 잘 보이지 않습니다. 자리가 없으면 label 을 화면에서만 숨기고(.sr-only) 남겨 두세요.

그대로 쓰는 회원가입 폼 — 태그만으로 여기까지 됩니다

<form method="post" action="/signup">
  <div class="field">
    <label for="email">이메일</label>
    <input id="email" name="email" type="email" required
           autocomplete="email" inputmode="email"
           aria-describedby="email-hint">
    <p id="email-hint" class="hint">로그인에 사용됩니다</p>
  </div>

  <div class="field">
    <label for="pw">비밀번호</label>
    <input id="pw" name="pw" type="password" required
           minlength="8" autocomplete="new-password">
  </div>

  <fieldset>                            <!-- 라디오·체크박스 묶음 -->
    <legend>수신 동의</legend>
    <label><input type="checkbox" name="agree" value="mail"> 메일</label>
    <label><input type="checkbox" name="agree" value="sms"> 문자</label>
  </fieldset>

  <button>가입하기</button>   <!-- form 안 기본 type 은 submit -->
</form>
이 폼이 공짜로 얻은 것어떤 속성 덕분에
모바일에서 이메일 키보드type="email" · inputmode
브라우저 자동완성 · 비밀번호 제안autocomplete — 가입 이탈률을 실제로 줄입니다
빈 채로 제출하면 브라우저가 막고 안내required · minlength
낭독기가 힌트까지 함께 읽음aria-describedby
라벨을 눌러도 체크박스 토글label 로 감싸기
HTML 06

폼 검증과 전송

브라우저 검증은 편의일 뿐입니다. 서버 검증은 없어선 안 됩니다.

기본 검증 + 내 메시지

<input id="nick" name="nick" required
       pattern="[a-zA-Z0-9]{3,12}"
       title="영문·숫자 3~12자">
const f = document.querySelector("form");
const nick = document.getElementById("nick");

nick.addEventListener("input", () => {
  nick.setCustomValidity(
    nick.validity.patternMismatch ? "영문·숫자 3~12자로 적어 주세요" : ""
  );
});

f.addEventListener("submit", (e) => {
  if (!f.checkValidity()) {          // 하나라도 통과 못 하면
    e.preventDefault();
    f.reportValidity();              // 브라우저 기본 말풍선 표시
  }
});
novalidate 를 form 에 붙이면 기본 말풍선을 끄고 직접 만든 에러 UI만 쓸 수 있습니다. 이때도 checkValidity() 로 판정은 그대로 활용하세요.

JS 로 보내기 (FormData)

f.addEventListener("submit", async (e) => {
  e.preventDefault();
  const data = new FormData(f);          // name 속성 기준으로 수집

  // 객체로 바꾸고 싶다면
  const body = Object.fromEntries(data);

  const res = await fetch("/api/signup", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(body),
  });

  if (!res.ok) { /* 서버가 준 에러를 화면에 */ }
});

// 파일 업로드는 FormData 를 그대로 보낸다
// (Content-Type 을 직접 넣지 말 것 — 경계 문자열이 필요)
await fetch("/api/upload", { method:"POST", body: new FormData(f) });
클라이언트 검증은 우회됩니다. 개발자 도구로 속성을 지우면 그만입니다. required 는 사용자를 돕는 장치이지 보안 장치가 아닙니다 — 같은 규칙을 서버에서 반드시 다시 확인하세요.
HTML 07

시맨틱 레이아웃

낭독기에는 "영역 목록"이 있습니다. 여기에 잡히도록 짜는 게 시맨틱입니다.

뼈대

<body>
  <header>                <!-- 사이트 머리 -->
    <nav aria-label="주 메뉴">…</nav>
  </header>

  <main id="main">         <!-- ★ 페이지에 하나. 본문 -->
    <h1>페이지 제목</h1>

    <article>              <!-- 떼어 놔도 말이 되는 덩어리 -->
      <h2>글 제목</h2>
      <section>            <!-- 그 안의 절 -->
        <h3>소제목</h3>
      </section>
    </article>

    <aside>…</aside>       <!-- 곁다리 (관련 글, 광고) -->
  </main>

  <footer>…</footer>
</body>

헷갈리는 지점

질문답
section vs div제목(h2~h6)이 붙는가로 정합니다. 제목이 없으면 그냥 div
article vs section잘라서 다른 곳에 붙여도 말이 되면 article (글·상품·댓글)
nav 는 몇 개?여러 개 가능. 대신 aria-label 로 구분하세요
main 은?페이지에 하나. 반복되는 머리·꼬리는 빼고 그 페이지 고유 내용만
figure그림 + 설명을 묶을 때. 설명은 figcaption
확인법 — 크롬 개발자도구 Elements → Accessibility 패널이나 낭독기의 랜드마크 목록을 열어 보세요. header · nav · main · footer 가 목록에 뜨면 제대로 짠 것입니다.
div 로 지으면 이 목록이 텅 빕니다 — 낭독기 사용자는 Tab 을 수십 번 눌러 본문을 찾아야 합니다.
HTML 08

접근성 — 역할 · 이름 · 상태

ARIA 의 첫 규칙은 "ARIA 를 쓰지 않는 것"입니다.

세 가지만 맞추면 된다

<!-- 역할(role) — 이게 무엇인가 -->
<button>            → 버튼 (태그가 이미 알려 줌)

<!-- 이름(name) — 뭐라고 부르는가 -->
<button aria-label="닫기">✕</button>
<!-- 아이콘만 있는 버튼은 이름이 비어 "버튼"이라고만 읽힙니다 -->

<!-- 상태(state) — 지금 어떤가 -->
<button aria-expanded="false" aria-controls="menu">메뉴</button>
<ul id="menu" hidden>…</ul>
// 상태는 '바꿀 때마다' 같이 갱신해야 의미가 있습니다
btn.addEventListener("click", () => {
  const open = menu.hidden;              // 지금 닫혀 있으면 연다
  menu.hidden = !open;
  btn.setAttribute("aria-expanded", String(open));
});

자주 하는 실수

이렇게 쓰면이렇게
<div role="button"><button> — 키보드까지 공짜
display:none 으로 숨긴 뒤 낭독 기대숨기면 안 읽힙니다. 시각만 숨기려면 .sr-only
aria-label 을 아무 div 에역할 없는 요소의 label 은 무시됩니다
tabindex="5" 처럼 양수순서가 꼬입니다. 0(포함) / -1(JS 로만) 만 쓰세요
포커스 테두리 제거(outline:none)키보드 사용자가 길을 잃습니다. 대체 스타일을 꼭 주세요
/* 화면에서만 숨기고 낭독기에는 남기는 표준 패턴 */
.sr-only{
  position:absolute; width:1px; height:1px;
  padding:0; margin:-1px; overflow:hidden;
  clip-path:inset(50%); white-space:nowrap; border:0;
}
HTML 09

표 제대로 쓰기

표는 수치 데이터에 씁니다. 레이아웃용 표는 낭독기에서 재앙입니다.

<table>
  <caption>2026년 분기별 매출 (단위: 백만원)</caption>
  <thead>
    <tr>
      <th scope="col">분기</th>
      <th scope="col">매출</th>
      <th scope="col">증감</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <th scope="row">1분기</th>   <!-- 행 제목도 th -->
      <td>120</td>
      <td>+8%</td>
    </tr>
  </tbody>
</table>
scope 가 핵심입니다. 낭독기는 셀을 읽을 때 "1분기, 매출, 120" 처럼 그 셀이 어느 행·열에 속하는지 함께 읽어 줍니다. scope 가 없으면 숫자만 줄줄이 읽혀 아무 의미가 없습니다.
넓은 표는 모바일에서 가로로 넘칩니다. 표를 overflow-x:auto 상자로 감싸고 그 상자에 tabindex="0" 과 role="region", aria-label 을 주면 키보드로도 스크롤할 수 있습니다.

완성형 표 — 이 골격을 복사해 쓰세요

<div class="tw" tabindex="0" role="region" aria-label="분기별 매출표">
  <table>
    <caption>2026년 분기별 매출 (단위: 백만 원)</caption>
    <thead>
      <tr>
        <th scope="col">분기</th>
        <th scope="col">매출</th>
        <th scope="col">전년 대비</th>
      </tr>
    </thead>
    <tbody>
      <tr>
        <th scope="row">1분기</th>
        <td>120</td><td>+8%</td>
      </tr>
      <tr>
        <th scope="row">2분기</th>
        <td>135</td><td>+12%</td>
      </tr>
    </tbody>
    <tfoot>
      <tr><th scope="row">합계</th><td>255</td><td>—</td></tr>
    </tfoot>
  </table>
</div>
부품왜 필요한가
caption표의 제목 — 낭독기가 표에 들어가기 전에 읽어 줍니다. 시각적으로 숨겨도 됩니다
thead/tbody/tfoot구획 — 인쇄 시 매 페이지에 머리행 반복, 스타일 걸기도 쉬워집니다
행 머리도 th scope="row""2분기, 매출, 135" 처럼 행 맥락까지 읽힙니다
숫자 셀 정렬CSS 로 td{text-align:right; font-variant-numeric:tabular-nums} — 자릿수가 맞아 비교가 쉬워집니다
HTML 10

스크립트 · 스타일 로딩 순서

어디에 두느냐가 첫 화면이 뜨는 속도를 좌우합니다.

script 세 가지

<script src="a.js"></script>
<!-- 만나는 순간 파싱을 멈추고 받아서 실행 (가장 느림) -->

<script src="a.js" defer></script>
<!-- ✓ 기본 선택. 받는 동안 파싱 계속,
     HTML 을 다 읽은 뒤 '적힌 순서대로' 실행 -->

<script src="a.js" async></script>
<!-- 받자마자 실행. 순서 보장 ✗
     다른 코드와 무관한 것에만 (예: 애널리틱스) -->

<script type="module" src="a.js"></script>
<!-- 모듈은 기본이 defer 와 같음 -->
고민되면 defer 입니다. DOM 이 다 준비된 뒤 순서대로 도니 DOMContentLoaded 를 기다릴 필요도 없습니다.

미리 받기 · 늦게 받기

<!-- 첫 화면에 꼭 필요한 것: 미리 -->
<link rel="preload" href="/hero.webp" as="image">
<link rel="preload" href="/font.woff2" as="font"
      type="font/woff2" crossorigin>

<!-- 곧 갈 페이지: 미리 연결만 -->
<link rel="preconnect" href="https://api.example.com">

<!-- 화면 밖 이미지: 늦게 -->
<img loading="lazy" …>

<!-- 인쇄용 CSS 처럼 당장 필요 없는 것 -->
<link rel="stylesheet" href="print.css" media="print">
preload 를 남발하면 오히려 느려집니다. 전부 "1순위"면 1순위가 없는 것과 같습니다 — 첫 화면에 실제로 보이는 것(히어로 이미지, 본문 폰트) 정도로 제한하세요.
HTML 11

메타 태그와 공유 카드

링크를 채팅방에 붙였을 때 뜨는 그 미리보기를 만드는 부분입니다.

<!-- 검색 -->
<title>가격 안내 — 서비스명</title>
<meta name="description" content="검색 결과에 두 줄로 뜨는 설명. 120자 안팎.">
<link rel="canonical" href="https://example.com/price">

<!-- 공유 미리보기 (카카오·슬랙·페북 공통) -->
<meta property="og:title"       content="가격 안내">
<meta property="og:description" content="플랜별 가격을 한눈에">
<meta property="og:image"       content="https://example.com/og.png">
<meta property="og:url"         content="https://example.com/price">
<meta property="og:type"        content="website">

<!-- 트위터(X) 큰 이미지 -->
<meta name="twitter:card" content="summary_large_image">

<!-- 색상 테마 -->
<meta name="theme-color" content="#0b0b0d">
항목주의
og:image절대 주소여야 합니다. 권장 1200×630. 상대경로는 대부분 무시됩니다
canonical같은 내용이 여러 주소로 있을 때 대표 주소를 지정 (중복 색인 방지)
description검색 순위에 직접 쓰이진 않지만 클릭률을 좌우합니다
키워드 meta이제 아무 효과 없습니다. 넣지 마세요
SPA(리액트·Vue)는 HTML 이 비어 있어 크롤러가 못 읽는 경우가 있습니다. 공유·검색이 중요하면 SSR·정적 생성(Next.js·Nuxt)을 쓰거나 최소한 메타 태그만이라도 서버에서 박아 주세요.

아코디언 · 모달 · 팝오버는 이제 태그만으로 됩니다.

접기 · 모달

<!-- 아코디언 -->
<details>
  <summary>환불 규정 보기</summary>

dlg.showModal();                    // 뒤 배경 클릭 차단 + 포커스 가둠
dlg.addEventListener("close", () => {
  console.log(dlg.returnValue);     // "ok" | "no"
});
<dialog> 는 포커스 가둠·ESC 닫기·배경 비활성화를 브라우저가 해 줍니다. 직접 만들면 가장 자주 틀리는 부분입니다.

</datalist>

<!-- 진행률 · 수치 -->
<progress value="70" max="100">70%</progress>
<meter value="0.6">60%</meter>

<!-- 이미지 크기별 교체 (art direction) -->

  <source media="(max-width:600px)" srcset="mobile.webp">
  <img src="desktop.webp" alt="…">
</picture>
<details> 안의 내용은 검색에 잡힙니다(닫혀 있어도). 반대로 display:none 으로 감춘 내용은 낭독기·검색 모두에서 없는 것이 됩니다.
