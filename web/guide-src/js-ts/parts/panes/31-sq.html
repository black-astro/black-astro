SQ 01

한 장 지도 — JS 에서 무엇으로 쓰나

자바스크립트의 표준 라이브러리에는 Array · Map · Set · TypedArray 정도만 있습니다. 스택은 Array 로 끝나지만, 큐 · 덱 · 우선순위 큐 · 비동기 큐는 직접 만들거나 패키지를 고르는 것이 일입니다. 먼저 상황별 정답표부터 봅니다.

JS 의 기본기는 "스택 = Array, 큐 = 덱(직접 · 패키지), 우선순위 = 힙, 기다림 = 채널" 네 줄입니다.

왜 표준에 Deque 가 없나

자바스크립트 표준(ECMAScript)은 언어 자체만 정하고, 자료구조 라이브러리는 아주 작게 유지해 왔습니다. Array 에 shift · unshift 가 이미 있어서 "큐도 되는 것처럼" 보였던 것도 한몫했습니다. 2026년 현재도 TC39 에 표준 Deque · PriorityQueue 는 들어와 있지 않습니다.

그래서 생태계는 이렇게 갈렸습니다.

  • 작은 큐 — 그냥 Array. 수백 개면 차이가 없습니다.
  • 라이브러리 내부 — 직접 만든 원형 버퍼나 연결 리스트. Node 의 process.nextTick 큐도 내부(lib/internal/fixed_queue.js)에서 고정 크기 원형 버퍼를 이어 붙인 구조를 씁니다(공개 API 는 아님).
  • 앱 코드 — 검증된 패키지(denque, p-limit 등) 또는 이 탭 같은 100줄짜리 직접 구현.
분산 큐와 헷갈리지 마세요. 이 탭의 큐는 한 프로세스의 메모리 안에 있습니다. 서버가 재시작되면 사라집니다. 주문 · 메일처럼 잃으면 안 되는 일은 Redis 기반 BullMQ 같은 바깥 큐로 — 🐈 NestJS 탭 s13 · ⚡ 대규모 트래픽 탭 k07 에서 다룹니다.
Java · Python 개발자에게 — 자바의 Stack 이 ArrayDeque 로 대체된 것처럼, JS 에서는 "Array.shift 큐"가 원형 버퍼 덱으로 대체되는 중입니다. 차이는 자바는 표준이 답을 줬고, JS 는 개발자가 직접 골라야 한다는 점입니다. 이 탭의 Deque<T> · BinaryHeap<T> 는 tsc --strict 를 통과하고 Node 24 의 타입 지우기 실행(node file.ts)으로 그대로 돕니다.
정리 — 스택은 Array, 큰 큐 · 덱은 원형 버퍼, 순서가 우선순위면 힙, 기다려야 하면 채널. "Array 로 다 된다"는 말은 스택까지만 맞습니다.
SQ 02

스택 — Array 의 끝이 top 입니다

JS 의 스택은 새 타입이 아니라 사용 규칙입니다. 끝(length - 1)을 top 으로 정하고 push · pop · at(-1) 만 쓰면 됩니다. 앞쪽을 top 으로 쓰는 순간 느려집니다.

스택 = 배열의 끝 한 칸만 건드리는 규칙. 아래쪽 칸이 움직이지 않는 것이 성능의 전부입니다.

기본 — 배열 그대로 (실행 결과 포함)

// stack-basic.mjs — node stack-basic.mjs
const st = [];
st.push("a", "b");       // 여러 개도 한 번에
st.push("c");
console.log(st.at(-1), st.pop(), st.length);   // c c 2
//          peek(ES2022)  pop

console.log([].pop(), [].at(-1));               // undefined undefined
// ★ 빈 스택에서 예외가 안 납니다 — 자바의 EmptyStackException 같은 것 없음

// undefined 를 "값"으로 넣는 스택이면 pop() 결과가 모호합니다
const maybe = [undefined];
console.log(maybe.length > 0 ? "값이 있음" : "비었음", maybe.pop());
// 값이 있음 undefined   → 꺼내기 전에 length 로 확인하세요
at(-1) 이 ES2022 부터의 peek 입니다. 예전 코드의 st[st.length - 1] 와 같은 뜻이고, TypeScript 에서는 반환 타입이 T | undefined 라 빈 경우를 처리하라고 컴파일러가 알려 줍니다 (st[st.length-1] 은 기본 설정에서 T 로 잡혀 이 검사를 놓칩니다 — noUncheckedIndexedAccess 를 켜면 둘 다 T | undefined).

타입 래퍼 — 빈 스택 정책을 API 로

// stack.ts
export class Stack<T> implements Iterable<T> {
  #a: T[] = [];                          // # = 진짜 private (밖에서 배열을 못 건드림)
  get size() { return this.#a.length; }
  push(x: T): this { this.#a.push(x); return this; }

  /** 비었으면 던진다 — "비어 있을 리 없다"는 불변식이 있을 때 */
  pop(): T {
    if (this.#a.length === 0) throw new RangeError("pop from empty stack");
    return this.#a.pop()!;
  }
  /** 비었을 수 있으면 — 결과 객체로 (undefined 를 값으로 넣어도 안전) */
  tryPop(): { ok: true; value: T } | { ok: false } {
    return this.#a.length ? { ok: true, value: this.#a.pop()! } : { ok: false };
  }
  peek(): T | undefined { return this.#a.at(-1); }

  /** 순회는 top → bottom (꺼낼 순서와 같게) */
  *[Symbol.iterator]() {
    for (let i = this.#a.length - 1; i >= 0; i--) yield this.#a[i];
  }
}

const s = new Stack<number>().push(1).push(2).push(3);
console.log([...s]);                 // [ 3, 2, 1 ]
console.log(s.tryPop());             // { ok: true, value: 3 }
console.log(new Stack().tryPop());   // { ok: false }
try { new Stack().pop(); } catch (e) { console.log((e as Error).name); }  // RangeError

자바 Stack 같은 "레거시"가 JS 에도 있나

JS 에는 버려진 Stack 클래스는 없지만, 버려진 관용구는 있습니다.

  • arr[arr.length - 1] → arr.at(-1) (ES2022, 의도가 바로 보임)
  • arr.unshift(x) / arr.shift() 로 앞을 top 으로 → 끝을 top 으로
  • Array.prototype.push.apply(a, b) → a.push(...b) (단, 아주 크면 아래)
  • { 0: x, 1: y, length: 2 } 같은 유사 배열 스택 → 진짜 Array (엔진 최적화가 안 붙음)
push(...big) 는 인자를 스택에 펼칩니다. 이 PC(Node 24)에서 12만 개는 됐고 13만 개부터 RangeError: Maximum call stack size exceeded 가 났습니다. 크기를 모르는 배열은 for...of 로 하나씩 넣거나 a = a.concat(b) 를 쓰세요.

재귀를 스택으로 — 깊은 트리에서 터지지 않게

type Node = { name: string; children: Node[] };

// 재귀: 깊이 1만 단계짜리 트리면 콜스택이 넘칩니다
function namesRec(n: Node, out: string[] = []): string[] {
  out.push(n.name);
  for (const c of n.children) namesRec(c, out);
  return out;
}

// 명시적 스택: 깊이와 무관 — 힙 메모리만 씁니다
function names(root: Node): string[] {
  const out: string[] = [];
  const st: Node[] = [root];
  while (st.length) {
    const n = st.pop()!;
    out.push(n.name);
    // 자식을 거꾸로 넣어야 원래 순서(왼쪽 먼저)로 나옵니다
    for (let i = n.children.length - 1; i >= 0; i--) st.push(n.children[i]);
  }
  return out;
}
JSON 파서 · 폴더 순회 · DOM 순회처럼 입력이 깊이를 정하는 코드는 명시적 스택이 안전합니다. V8 은 꼬리 호출 최적화(TCO)를 하지 않으므로 "꼬리 재귀라 괜찮다"도 JS 에선 통하지 않습니다.
정리 — JS 의 스택은 push · pop · at(-1) 세 메서드의 약속입니다. 빈 스택은 예외 대신 undefined 를 주므로, 그게 싫으면 얇은 Stack<T> 래퍼로 정책을 정하세요.
SQ 03

큐(FIFO) — shift() 의 함정과 세 가지 대안

queue.push(x) 로 넣고 queue.shift() 로 빼는 코드는 어디에나 있습니다. 작을 때는 아무 문제가 없다가 요소가 수만 개를 넘는 순간 갑자기 느려집니다. 이 PC 에서 직접 재 봤습니다.

작을 때는 다 비슷하지만 10만 개에서 shift 만 포인터 방식의 240배로 느려집니다. 수치는 이 PC 측정 예시이며 기계 · 버전마다 다릅니다.

왜 이런 절벽이 생기나

shift() 는 명세상 0번을 꺼내고 나머지를 한 칸씩 앞으로 당기는 연산입니다 — 그 자체로 O(n). 그런데 1만 개에서는 빨랐습니다. V8 이 배열의 시작 위치를 한 칸 뒤로 옮기는(left-trim) 꼼수로 복사를 피할 수 있는 경우가 있기 때문입니다.

이 꼼수가 언제 통하는지는 엔진 내부 사정(배열이 놓인 힙 영역, 크기 등)에 달려 있어 코드에서 보장받을 수 없습니다. 이 PC 에서는 1만 개 근처까지 빠르고, 1.6만 개에서 이미 8배로 뛰었습니다.

// node bench-shift.mjs  (Deque 는 SQ 04 의 클래스)
function viaShift(n) {            // ① 흔한 실수
  const q = [];
  for (let i = 0; i < n; i++) q.push(i);
  let sum = 0;
  while (q.length) sum += q.shift();
  return sum;
}
function viaPointer(n) {          // ② 인덱스 포인터
  const q = []; let head = 0;
  for (let i = 0; i < n; i++) q.push(i);
  let sum = 0;
  while (head < q.length) sum += q[head++];
  return sum;
}
function viaDeque(n) {            // ③ 원형 버퍼
  const q = new Deque();
  for (let i = 0; i < n; i++) q.pushBack(i);
  let sum = 0;
  while (q.size) sum += q.popFront();
  return sum;
}
for (const n of [10_000, 100_000]) {
  for (const fn of [viaShift, viaPointer, viaDeque]) {
    fn(1000);                                 // 워밍업
    const t = performance.now();
    fn(n);
    console.log(n, fn.name, (performance.now() - t).toFixed(1) + "ms");
  }
}

대안 ① ② — 인덱스 포인터 큐 · 두 스택 큐 🟡 중급

인덱스 포인터 + 주기적 정리

export class ArrayQueue<T> {
  #a: (T | undefined)[] = [];
  #head = 0;                                // 다음에 꺼낼 칸
  get size() { return this.#a.length - this.#head; }
  enqueue(x: T) { this.#a.push(x); }
  dequeue(): T | undefined {
    if (this.#head === this.#a.length) return undefined;
    const x = this.#a[this.#head];
    this.#a[this.#head++] = undefined;      // 참조 끊기 — 안 하면 GC 가 못 가져감
    // 앞쪽 빈칸이 절반을 넘으면 한 번 잘라 냄 → 분할 상환 O(1)
    if (this.#head > 1024 && this.#head * 2 > this.#a.length) {
      this.#a = this.#a.slice(this.#head);
      this.#head = 0;
    }
    return x;
  }
  peek() { return this.#a[this.#head]; }
}

const q = new ArrayQueue<number>();
for (let i = 0; i < 5000; i++) q.enqueue(i);
let last;
for (let i = 0; i < 4000; i++) last = q.dequeue();
console.log(last, q.size, q.peek());       // 3999 1000 4000
가장 짧은 해결책이라 BFS · 한 번 쓰고 버리는 큐에 좋습니다. 다만 뒤에서 넣고 앞에서 빼기만 됩니다(덱 아님). 정리 조건이 없으면 앞쪽 빈칸이 영원히 메모리를 잡습니다.

두 스택 큐 — in 에 쌓고 out 에서 꺼냄

export class TwoStackQueue<T> {
  #in: T[] = [];
  #out: T[] = [];
  enqueue(x: T) { this.#in.push(x); }
  dequeue(): T | undefined {
    if (this.#out.length === 0) {
      // out 이 비었을 때만 한 번에 뒤집어 옮김
      while (this.#in.length) this.#out.push(this.#in.pop()!);
    }
    return this.#out.pop();
  }
  get size() { return this.#in.length + this.#out.length; }
}

const tq = new TwoStackQueue<number>();
tq.enqueue(1); tq.enqueue(2); tq.enqueue(3);
const a = tq.dequeue();                    // 1  (이때 3,2 가 out 으로)
tq.enqueue(4);                             // in 에 들어감
console.log(a, tq.dequeue(), tq.dequeue(), tq.dequeue(), tq.dequeue());
// 1 2 3 4 undefined
각 요소는 in 에 한 번, out 으로 한 번만 옮겨지므로 분할 상환 O(1) 입니다. 단, 옮기는 순간 한 번은 O(n) 이라 지연이 튀는 것이 싫은 실시간 코드에는 원형 버퍼가 낫습니다. 함수형 · 불변 자료구조(영속 큐)의 기본 아이디어이기도 합니다.

SQ 04

덱 — 원형 버퍼를 TypeScript 제네릭으로

자바 ArrayDeque, 파이썬 deque(블록 연결), denque 가 공통으로 기대는 생각은 배열을 고리처럼 쓰는 것입니다. 요소를 옮기지 않고 head 번호만 움직이니 앞 · 뒤 모두 O(1) 입니다. 100줄이면 만들 수 있고, 한 번 만들어 두면 이 탭의 큐 · 채널 · BFS 전부에 씁니다.

원형 버퍼 — head 와 size 두 숫자가 덱의 전부입니다. 감김은 & mask, 늘어남은 드문 O(n) 복사.

deque.ts — 완전한 구현 (tsc --strict 통과)

// deque.ts — 원형 버퍼 덱
export class Deque<T> implements Iterable<T> {
  #buf: (T | undefined)[];   // 길이는 항상 2의 거듭제곱
  #head = 0;                 // 맨 앞 요소의 칸 번호
  #size = 0;                 // 들어 있는 개수
  #mask: number;             // cap - 1  →  (i & mask) === i % cap

  constructor(capacity = 16) {
    let cap = 16;
    while (cap < capacity) cap <<= 1;            // 2의 거듭제곱으로 올림
    this.#buf = new Array<T | undefined>(cap);
    this.#mask = cap - 1;
  }

  get size(): number { return this.#size; }
  get capacity(): number { return this.#buf.length; }
  isEmpty(): boolean { return this.#size === 0; }

  pushBack(x: T): void {
    if (this.#size === this.#buf.length) this.#grow();
    this.#buf[(this.#head + this.#size) & this.#mask] = x;
    this.#size++;
  }
  pushFront(x: T): void {
    if (this.#size === this.#buf.length) this.#grow();
    this.#head = (this.#head - 1) & this.#mask;  // -1 & 15 === 15 : 뒤로 감김
    this.#buf[this.#head] = x;
    this.#size++;
  }
  popFront(): T | undefined {
    if (this.#size === 0) return undefined;
    const x = this.#buf[this.#head];
    this.#buf[this.#head] = undefined;           // ★ 참조를 끊어야 GC 가 회수
    this.#head = (this.#head + 1) & this.#mask;
    this.#size--;
    return x;
  }
  popBack(): T | undefined {
    if (this.#size === 0) return undefined;
    const i = (this.#head + this.#size - 1) & this.#mask;
    const x = this.#buf[i];
    this.#buf[i] = undefined;
    this.#size--;
    return x;
  }
  peekFront(): T | undefined { return this.#size ? this.#buf[this.#head] : undefined; }
  peekBack(): T | undefined {
    return this.#size ? this.#buf[(this.#head + this.#size - 1) & this.#mask] : undefined;
  }
  at(i: number): T | undefined {                 // 음수 인덱스도 Array.at 처럼
    if (i < 0) i += this.#size;
    if (i < 0 || i >= this.#size) return undefined;
    return this.#buf[(this.#head + i) & this.#mask];
  }
  clear(): void {
    this.#buf = new Array<T | undefined>(16);
    this.#mask = 15; this.#head = 0; this.#size = 0;
  }
  *[Symbol.iterator](): Iterator<T> {            // 앞 → 뒤
    for (let i = 0; i < this.#size; i++) yield this.#buf[(this.#head + i) & this.#mask] as T;
  }
  toArray(): T[] { return [...this]; }

  #grow(): void {
    // 감긴 상태 [E F G H | A B C D] (head=4) → 새 배열에 [A B C D E F G H] 로 펴서 옮긴다
    const old = this.#buf, n = old.length;
    const next = new Array<T | undefined>(n << 1);
    for (let i = 0; i < n; i++) next[i] = old[(this.#head + i) & this.#mask];
    this.#buf = next;
    this.#head = 0;
    this.#mask = (n << 1) - 1;
  }
}

SQ 05

우선순위 큐 — 이진 힙을 comparator 로

"가장 급한 것부터", "가장 가까운 것부터" 꺼내야 할 때마다 arr.sort() 를 다시 부르는 코드를 자주 봅니다. 매번 O(n log n) 입니다. 이진 힙은 넣기 · 빼기 모두 O(log n) 이고, 배열 하나로 됩니다.

힙 = 층 순서로 편 완전 이진 트리. 인덱스 계산만으로 부모 · 자식을 찾아 배열 하나에 담깁니다.

heap.ts — comparator 주입형 (tsc --strict 통과)

// heap.ts
export type Comparator<T> = (a: T, b: T) => number;   // 음수면 a 가 먼저 나온다

export class BinaryHeap<T> {
  #a: T[] = [];
  readonly #cmp: Comparator<T>;

  constructor(cmp: Comparator<T>, items: Iterable<T> = []) {
    this.#cmp = cmp;
    for (const x of items) this.#a.push(x);
    for (let i = (this.#a.length >> 1) - 1; i >= 0; i--) this.#down(i);  // O(n) heapify
  }
  get size(): number { return this.#a.length; }
  peek(): T | undefined { return this.#a[0]; }

  push(x: T): void {
    this.#a.push(x);
    this.#up(this.#a.length - 1);
  }
  pop(): T | undefined {
    const a = this.#a;
    if (a.length === 0) return undefined;
    const top = a[0];
    const last = a.pop()!;
    if (a.length > 0) { a[0] = last; this.#down(0); }
    return top;
  }

  #up(i: number): void {
    const a = this.#a, x = a[i];
    while (i > 0) {
      const p = (i - 1) >> 1;
      if (this.#cmp(x, a[p]) >= 0) break;
      a[i] = a[p]; i = p;               // 부모를 내리고 자리를 올라감 (swap 보다 쓰기 절반)
    }
    a[i] = x;
  }
  #down(i: number): void {
    const a = this.#a, n = a.length, x = a[i];
    for (;;) {
      let c = 2 * i + 1;
      if (c >= n) break;
      if (c + 1 < n && this.#cmp(a[c + 1], a[c]) < 0) c++;   // 더 앞서는 자식
      if (this.#cmp(a[c], x) >= 0) break;
      a[i] = a[c]; i = c;
    }
    a[i] = x;
  }
  raw(): readonly T[] { return [...this.#a]; }               // 디버깅용
}

top-k — 크기 k 의 최소 힙

// 큰 것 k 개를 남기려면 "최소" 힙: 맨 위가 지금까지의 k 등
function topK(nums: Iterable<number>, k: number): number[] {
  const h = new BinaryHeap<number>((a, b) => a - b);
  for (const x of nums) {
    if (h.size < k) h.push(x);
    else if (x > h.peek()!) { h.pop(); h.push(x); }   // k 등보다 크면 교체
  }
  const r: number[] = [];
  while (h.size) r.push(h.pop()!);
  return r.reverse();
}
console.log(topK([7, 2, 19, 4, 11, 3, 15, 8], 3));   // [ 19, 15, 11 ]
// O(n log k) · 메모리 O(k) — 스트림(끝을 모르는 입력)에도 그대로

다익스트라 — 낡은 항목은 꺼낼 때 버린다

type Graph = Record<string, [to: string, w: number][]>;

function dijkstra(graph: Graph, src: string): Record<string, number> {
  const dist = new Map<string, number>([[src, 0]]);
  const pq = new BinaryHeap<[number, string]>((a, b) => a[0] - b[0], [[0, src]]);
  while (pq.size) {
    const [d, u] = pq.pop()!;
    if (d > (dist.get(u) ?? Infinity)) continue;   // ★ 이미 더 짧은 길을 찾음 (lazy deletion)
    for (const [v, w] of graph[u] ?? []) {
      const nd = d + w;
      if (nd < (dist.get(v) ?? Infinity)) { dist.set(v, nd); pq.push([nd, v]); }
    }
  }
  return Object.fromEntries(dist);
}
const g: Graph = { A: [["B", 4], ["C", 1]], C: [["B", 2], ["D", 7]], B: [["D", 1]] };
console.log(dijkstra(g, "A"));   // { A: 0, B: 3, C: 1, D: 4 }
힙에는 "우선순위 낮추기(decrease-key)"가 없습니다. 그래서 거리가 줄면 새 항목을 하나 더 넣고, 나중에 꺼낸 낡은 항목은 continue 로 버립니다. 실무 구현 대부분이 이 방식입니다.

스레드 사이의 큐 — Worker · MessageChannel · Atomics

SharedArrayBuffer + Atomics — SPSC 링 버퍼 🔴 고급

SPSC 링 — 각 번호를 한쪽만 쓰고, 값 쓰기 → Atomics.store 순서를 지키면 락 없이 안전합니다.

spsc.mjs — 10만 개를 두 워커 사이로

import { Worker, isMainThread, workerData, parentPort } from "node:worker_threads";

const HEAD = 0, TAIL = 1;          // 계속 증가하는 번호 (칸 = 번호 & MASK)
const CAP = 8, MASK = CAP - 1;
const N = 100_000;

if (isMainThread) {
  const sab = new SharedArrayBuffer(4 * (2 + CAP));     // ctrl 2칸 + data 8칸
  const run = (role) => new Promise((ok, fail) => {
    const w = new Worker(new URL(import.meta.url), { workerData: { sab, role } });
    w.once("message", ok).once("error", fail);
  });
  const [, sum] = await Promise.all([run("producer"), run("consumer")]);
  console.log("합계", sum, "기대", (N * (N + 1)) / 2);
  // 합계 5000050000 기대 5000050000
} else {
  const ctrl = new Int32Array(workerData.sab, 0, 2);
  const data = new Int32Array(workerData.sab, 8, CAP);

  if (workerData.role === "producer") {
    let tail = 0;
    for (let v = 1; v <= N; v++) {
      for (;;) {
        const head = Atomics.load(ctrl, HEAD);
        if (tail - head < CAP) break;               // 빈칸 있음
        Atomics.wait(ctrl, HEAD, head);             // 꽉 참 → head 가 바뀔 때까지 잠
      }
      data[tail & MASK] = v;                        // ① 값을 먼저
      Atomics.store(ctrl, TAIL, ++tail);            // ② 그다음 공개
      Atomics.notify(ctrl, TAIL);
    }
    parentPort.postMessage(0);
  } else {
    let head = 0, sum = 0;
    for (let got = 0; got < N; ) {
      if (Atomics.load(ctrl, TAIL) === head) {      // 비어 있음
        Atomics.wait(ctrl, TAIL, head);
        continue;
      }
      sum += data[head & MASK];
      Atomics.store(ctrl, HEAD, ++head);            // 칸을 돌려줌
      Atomics.notify(ctrl, HEAD);
      got++;
    }
    parentPort.postMessage(sum);
  }
}

정확히 알아야 할 것

  • 왜 안전한가 — Atomics.* 연산은 순차 일관(sequentially consistent)입니다. ①의 일반 쓰기는 ②의 Atomics.store 보다 먼저 일어나고, 소비자가 ④ Atomics.load 로 새 tail 을 보면 ①도 보입니다. ①과 ②의 순서를 바꾸면 이 보장이 깨집니다.
  • Atomics.wait(arr, i, v) 는 "arr[i] 가 아직 v 면 잠든다"입니다. 확인과 잠들기가 한 번에 일어나므로 notify 를 놓치는 일이 없습니다.
  • 번호가 계속 증가 — tail - head 로 개수를 구합니다. Int32 라 약 21억 개를 넘기면 넘칩니다 (오래 도는 서비스면 주기적으로 0 으로 되돌리거나 칸 번호만 저장).
  • 값은 숫자만 — SAB 에는 바이트만 들어갑니다. 객체를 보내려면 직렬화하거나 MessagePort 를 쓰세요.
  • 브라우저 — SharedArrayBuffer 는 교차 출처 격리(COOP: same-origin + COEP: require-corp) 페이지에서만 쓸 수 있고, 메인 스레드에서는 Atomics.wait 대신 Atomics.waitAsync 를 씁니다.
대부분의 앱에는 MessagePort 로 충분합니다. SAB 링은 오디오 처리 · 고빈도 센서 데이터처럼 복사 비용과 지연이 문제로 측정된 경우에만 쓰세요. 이 PC 에서 10만 개를 8칸 링으로 넘기는 데 약 50~70ms 가 걸렸습니다.
정리 — JS 의 스레드 간 큐는 MessagePort(복사 · 전송)가 기본이고, 배압은 "빈 워커에게만 준다"로 겁니다. 한 스레드 안에서도 await 를 넘는 확인-후-행동은 경쟁 상태입니다.

// limit.ts — p-limit 과 같은 생각
import { Deque } from "./deque.ts";

export function createLimit(concurrency: number) {
  if (!Number.isInteger(concurrency) || concurrency < 1) throw new RangeError("concurrency >= 1");
  const waiting = new Deque<() => void>();   // 차례를 기다리는 "출발 신호" (FIFO)
  let active = 0;

  const next = () => {
    if (active >= concurrency) return;
    waiting.popFront()?.();
  };

  return function limit<R>(task: () => R | PromiseLike<R>): Promise<R> {
    return new Promise<R>((resolve, reject) => {
      waiting.pushBack(() => {
        active++;
        // task() 가 동기로 throw 해도 reject 로 바뀌게 then 안에서 부른다
        Promise.resolve()
          .then(task)
          .then(resolve, reject)
          .finally(() => { active--; next(); });   // ★ 성공 · 실패 모두 슬롯 반납
      });
      next();
    });
  };
}
ES2025 의 Promise.try(task) 를 쓰면 Promise.resolve().then(task) 대신 task 를 동기로 바로 시작하면서 throw 를 reject 로 바꿉니다(Node 24 에서 사용 가능). 한 틱 늦게 시작해도 괜찮다면 지금 코드 그대로도 됩니다.

channel.ts — 유한 비동기 큐 (tsc --strict 통과)

import { Deque } from "./deque.ts";

export class ClosedError extends Error { override name = "ClosedError"; }

type Waiter<T> = { resolve: (r: IteratorResult<T, undefined>) => void; reject: (e: unknown) => void };
type Sender<T> = { value: T; resolve: () => void; reject: (e: unknown) => void };

export class Channel<T> implements AsyncIterable<T> {
  #buf = new Deque<T>();
  #receivers = new Deque<Waiter<T>>();    // 값을 기다리는 소비자
  #senders = new Deque<Sender<T>>();      // 자리를 기다리는 생산자
  #closed = false;
  readonly #cap: number;

  constructor(capacity = 1) { this.#cap = capacity; }

  /** 꽉 차 있으면 자리가 날 때까지 기다린다 — 이것이 배압 */
  send(value: T): Promise<void> {
    if (this.#closed) return Promise.reject(new ClosedError("send on closed channel"));
    const r = this.#receivers.popFront();
    if (r) { r.resolve({ value, done: false }); return Promise.resolve(); }   // 소비자에게 직행
    if (this.#buf.size < this.#cap) { this.#buf.pushBack(value); return Promise.resolve(); }
    return new Promise((resolve, reject) => this.#senders.pushBack({ value, resolve, reject }));
  }

  receive(signal?: AbortSignal): Promise<IteratorResult<T, undefined>> {
    if (this.#buf.size) {
      const value = this.#buf.popFront() as T;
      const s = this.#senders.popFront();             // 자리가 났으니 생산자 하나를 들인다
      if (s) { this.#buf.pushBack(s.value); s.resolve(); }
      return Promise.resolve({ value, done: false });
    }
    const s = this.#senders.popFront();               // 용량 0(랑데부)일 때
    if (s) { s.resolve(); return Promise.resolve({ value: s.value, done: false }); }
    if (this.#closed) return Promise.resolve({ value: undefined, done: true });
    if (signal?.aborted) return Promise.reject(signal.reason);

    return new Promise((resolve, reject) => {
      const onAbort = () => {
        // 대기열에서 빼고 거절 — 안 빼면 나중 값이 떠난 소비자에게 가서 사라진다
        const keep = [...this.#receivers].filter((w) => w !== waiter);
        this.#receivers = new Deque();
        keep.forEach((w) => this.#receivers.pushBack(w));
        reject(signal!.reason);
      };
      const waiter: Waiter<T> = {
        resolve: (v) => { signal?.removeEventListener("abort", onAbort); resolve(v); },
        reject,
      };
      this.#receivers.pushBack(waiter);
      signal?.addEventListener("abort", onAbort, { once: true });
    });
  }

  close(): void {
    if (this.#closed) return;
    this.#closed = true;
    for (let r; (r = this.#receivers.popFront()); ) r.resolve({ value: undefined, done: true });
    for (let s; (s = this.#senders.popFront()); ) s.reject(new ClosedError("channel closed"));
  }

  /** for await (const x of ch) — 닫히고 버퍼가 비면 끝난다 */
  async *[Symbol.asyncIterator](): AsyncIterator<T> {
    for (;;) {
      const r = await this.receive();
      if (r.done) return;
      yield r.value;

// ① 괄호 검사 — 여는 괄호를 쌓고 닫는 괄호에서 짝 확인
const PAIR: Record<string, string> = { ")": "(", "]": "[", "}": "{" };
function balanced(s: string): boolean {
  const st: string[] = [];
  for (const ch of s) {
    if (ch === "(" || ch === "[" || ch === "{") st.push(ch);
    else if (ch in PAIR) {
      if (st.pop() !== PAIR[ch]) return false;   // 빈 스택 pop 은 undefined → false
    }
  }
  return st.length === 0;
}

function nextGreater(a: number[]): number[] {
  const res = new Array<number>(a.length).fill(-1);
  const st: number[] = [];                  // 인덱스를 담는다 (값은 감소 순)
  for (let i = 0; i < a.length; i++) {
    while (st.length && a[st.at(-1)!] < a[i]) res[st.pop()!] = a[i];
    st.push(i);
  }
  return res;
}

function bfs(grid: string[][], [sr, sc]: [number, number], [tr, tc]: [number, number]): number {
  const R = grid.length, C = grid[0].length;
  const dist = Array.from({ length: R }, () => new Array<number>(C).fill(-1));
  const q = new Deque<[number, number]>();
  q.pushBack([sr, sc]); dist[sr][sc] = 0;
  while (!q.isEmpty()) {
    const [r, c] = q.popFront()!;
    if (r === tr && c === tc) return dist[r][c];
    for (const [dr, dc] of [[1, 0], [-1, 0], [0, 1], [0, -1]]) {
      const nr = r + dr, nc = c + dc;
      if (nr < 0 || nc < 0 || nr >= R || nc >= C) continue;
      if (grid[nr][nc] === "#" || dist[nr][nc] !== -1) continue;
      dist[nr][nc] = dist[r][c] + 1;     // ★ 넣을 때 방문 표시 (꺼낼 때 하면 중복 삽입)
      q.pushBack([nr, nc]);
    }
  }
  return -1;
}

// ③ 위 그림 그대로
function windowMax(a: number[], k: number): number[] {
  const dq = new Deque<number>(), out: number[] = [];   // 인덱스를 담는다
  for (let i = 0; i < a.length; i++) {
    if (!dq.isEmpty() && dq.peekFront()! <= i - k) dq.popFront();        // 창 밖
    while (!dq.isEmpty() && a[dq.peekBack()!] <= a[i]) dq.popBack();     // 나보다 작은 뒤쪽
    dq.pushBack(i);
    if (i >= k - 1) out.push(a[dq.peekFront()!]);
  }
  return out;
}

// ④ 0-1 BFS — 가중치가 0 이면 앞에, 1 이면 뒤에 → 다익스트라 없이 O(V + E)
function zeroOneBfs(n: number, edges: [number, number, 0 | 1][], src: number): number[] {
  const adj: [number, 0 | 1][][] = Array.from({ length: n }, () => []);
  for (const [u, v, w] of edges) adj[u].push([v, w]);
  const dist = new Array<number>(n).fill(Infinity);
  dist[src] = 0;
  const dq = new Deque<number>();
  dq.pushBack(src);
  while (!dq.isEmpty()) {
    const u = dq.popFront()!;
    for (const [v, w] of adj[u]) {
      if (dist[u] + w < dist[v]) {
        dist[v] = dist[u] + w;
        w === 0 ? dq.pushFront(v) : dq.pushBack(v);
      }
    }
  }
  return dist;
}

// history.ts — 순수 함수라 React 없이 테스트 가능
type History<T> = { past: T[]; present: T; future: T[] };
type Action<T> = { type: "edit"; value: T } | { type: "undo" } | { type: "redo" };
const MAX_HISTORY = 50;

export function historyReducer<T>(s: History<T>, a: Action<T>): History<T> {
  switch (a.type) {
    case "edit":
      if (Object.is(a.value, s.present)) return s;            // 같은 값이면 기록 안 함
      return {
        past: [...s.past, s.present].slice(-MAX_HISTORY),     // ★ 상한
        present: a.value,
        future: [],                                           // 새 편집은 redo 를 지운다
      };
    case "undo":
      if (s.past.length === 0) return s;
      return { past: s.past.slice(0, -1), present: s.past.at(-1)!, future: [s.present, ...s.future] };
    case "redo":
      if (s.future.length === 0) return s;
      return { past: [...s.past, s.present], present: s.future[0], future: s.future.slice(1) };
  }
}

시간만 보면 JS 에서는 연결 리스트도 크게 지지 않습니다. 짧게 사는 노드는 V8 의 젊은 세대 GC 가 싸게 치우기 때문으로 보입니다. 하지만 이 결과는 실행마다 흔들렸고, 지는 쪽은 분명히 메모리입니다.

  • 노드마다 객체 하나 → 요소당 40 B(배열 칸은 약 10 B). 큐에 100만 개가 쌓이면 40 MB 대 10 MB.
  • 노드가 힙 여기저기 흩어져 캐시 지역성이 나쁘고, 큐가 오래 살면 노드가 오래된 세대로 넘어가 GC 비용이 커집니다.
  • 임의 접근(at(i))이 O(n).
그래도 연결 리스트가 맞는 자리 — 큐가 작고 생성 · 폐기가 잦은 곳(yocto-queue 를 쓰는 p-limit 처럼), 중간 노드를 O(1) 로 떼어 내야 하는 LRU 캐시(Map + 이중 연결 리스트).

다른 언어에서 온 사람이 JS 에서 놀라는 것

  • 빈 컬렉션에서 꺼내도 예외가 없다 — [].pop() 은 undefined. 파이썬의 IndexError, 자바의 NoSuchElementException 같은 안전망이 없습니다. TS 의 T | undefined 반환 타입이 그 자리를 대신합니다.

import { Deque } from "./deque.ts";

// ① 꽉 차면 가장 오래된 것을 덮어쓰는 링 버퍼
export class RecentN<T> {
  #buf: (T | undefined)[];
  #next = 0;
  #count = 0;
  constructor(n: number) { this.#buf = new Array<T | undefined>(n); }
  add(x: T): void {
    this.#buf[this.#next] = x;
    this.#next = (this.#next + 1) % this.#buf.length;   // n 이 2의 거듭제곱이 아니어도 되게 %
    this.#count = Math.min(this.#count + 1, this.#buf.length);
  }
  toArray(): T[] {                                       // 오래된 것 → 최근 것
    const n = this.#buf.length, start = (this.#next - this.#count + n) % n;
    return Array.from({ length: this.#count }, (_, i) => this.#buf[(start + i) % n] as T);
  }
}
const recent = new RecentN<string>(3);
for (const e of ["login", "view", "cart", "pay", "logout"]) recent.add(e);
console.log(recent.toArray());           // [ 'cart', 'pay', 'logout' ]

export class SlidingWindowLimiter {
  #hits = new Deque<number>();
  readonly limit: number;
  readonly windowMs: number;
  constructor(limit: number, windowMs: number) { this.limit = limit; this.windowMs = windowMs; }
  tryAcquire(now = Date.now()): boolean {
    while (!this.#hits.isEmpty() && this.#hits.peekFront()! <= now - this.windowMs) this.#hits.popFront();
    if (this.#hits.size >= this.limit) return false;
    this.#hits.pushBack(now);
    return true;
  }
}

③ 재시도 스케줄러 — 최소 힙 + 지수 백오프

import { BinaryHeap } from "./heap.ts";

type Job = { name: string; attempt: number };
type Scheduled = Job & { at: number; seq: number };

export class RetryScheduler {
  #heap = new BinaryHeap<Scheduled>((a, b) => a.at - b.at || a.seq - b.seq);
  #seq = 0;
  schedule(job: Job, at: number) { this.#heap.push({ ...job, at, seq: this.#seq++ }); }

  // now 까지 도래한 작업을 실행, 실패하면 100ms · 2^attempt 뒤로 다시 넣는다
  tick(now: number, run: (j: Job) => boolean, log: string[]) {
    while (this.#heap.size && this.#heap.peek()!.at <= now) {
      const job = this.#heap.pop()!;
      if (run(job)) { log.push(`${now} ${job.name} 성공`); continue; }
      if (job.attempt + 1 >= 4) { log.push(`${now} ${job.name} 포기 → DLQ`); continue; }
      const delay = 100 * 2 ** job.attempt;
      this.schedule({ name: job.name, attempt: job.attempt + 1 }, now + delay);
      log.push(`${now} ${job.name} 실패 → ${now + delay}`);
    }
  }
}

const sch = new RetryScheduler(), log: string[] = [];
sch.schedule({ name: "메일", attempt: 0 }, 0);
sch.schedule({ name: "웹훅", attempt: 0 }, 0);
const flaky = (j: Job) => (j.name === "메일" ? j.attempt >= 2 : false);  // 메일은 세 번째에 성공
for (let now = 0; now <= 1000; now += 100) sch.tick(now, flaky, log);
console.log(log.join("\n"));
// 0 메일 실패 → 100
// 0 웹훅 실패 → 100
// 100 메일 실패 → 300
// 100 웹훅 실패 → 300
// 300 메일 성공
// 300 웹훅 실패 → 700
// 700 웹훅 포기 → DLQ

④ 이벤트 배치 버퍼 — "N 개 또는 T 초"

export type BatchOptions<T> = { maxSize: number; maxWaitMs: number; flush: (batch: T[]) => Promise<void> };

export class BatchBuffer<T> {
  #items: T[] = [];
  #timer: ReturnType<typeof setTimeout> | null = null;
  #flushing: Promise<void> = Promise.resolve();
  readonly #opts: BatchOptions<T>;
  constructor(opts: BatchOptions<T>) { this.#opts = opts; }

  add(item: T): Promise<void> {
    this.#items.push(item);
    if (this.#items.length >= this.#opts.maxSize) return this.flush();
    this.#timer ??= setTimeout(() => void this.flush(), this.#opts.maxWaitMs);
    return this.#flushing;
  }
  flush(): Promise<void> {
    if (this.#timer) clearTimeout(this.#timer);
    this.#timer = null;
    if (this.#items.length === 0) return this.#flushing;
    const batch = this.#items;     // ★ 배열째 넘기고 새 배열로 교체 (length = 0 금지 — SQ 10)
    this.#items = [];
    // 앞 flush 가 끝난 뒤 보낸다 — 순서 보장, 실패해도 다음 배치는 진행
    this.#flushing = this.#flushing
      .then(() => this.#opts.flush(batch))
      .catch((e) => console.error("flush 실패", e));
    return this.#flushing;
  }
}

⑤ 외부 API 대량 호출 — 동시 4개 · 실패 격리

import { createLimit } from "./limit.ts";

const limit = createLimit(4);                   // 상대 서버가 허용하는 동시 수

async function syncAll(ids: string[], signal: AbortSignal) {
  const results = await Promise.allSettled(
    ids.map((id) =>
      limit(async () => {
        signal.throwIfAborted();                // 취소되면 대기 중이던 것도 시작하지 않음
        const res = await fetch(`https://api.example.com/items/${id}`, { signal });
        if (!res.ok) throw new Error(`${id}: HTTP ${res.status}`);
        return res.json();
      }),
    ),
  );
  const failed = results.filter((r) => r.status === "rejected");
  console.log(`성공 ${results.length - failed.length} · 실패 ${failed.length}`);
  return results;
}
왜 allSettled 인가 — Promise.all 은 하나만 실패해도 즉시 reject 하지만, 이미 limit 큐에 들어간 나머지는 계속 돕니다. 결과를 버리면서 일만 하는 셈이라, 대량 호출은 allSettled 로 전부 받고 실패만 재시도 큐(③)로 넘기는 것이 깔끔합니다.
체크리스트 — 큐에는 상한(무한히 쌓이지 않게) · 배압(가득 차면 생산자를 기다리게) · 종료 처리(남은 것 flush · 독약 · AbortSignal) · 관측(길이 · 대기 시간 지표) 네 가지가 있어야 운영에서 버팁니다.
정리 — 최근 N 개는 링 버퍼, 리미터는 시각 덱, 재시도는 시각 힙, 배치는 배열 교체, 대량 호출은 동시성 제한 큐. 잃으면 안 되는 일만 바깥 큐(BullMQ 등)로 보냅니다.
