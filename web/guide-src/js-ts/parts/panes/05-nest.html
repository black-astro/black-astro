NestJS 는 Spring 의 구조를 노드로 옮겨 온 프레임워크입니다. 모듈 · DI · 컨트롤러 · 서비스 · 인터셉터 · 가드가 거의 1:1 로 대응됩니다. Express 가 자유를 준다면 Nest 는 일관성을 줍니다 — 팀이 커질수록 후자가 이깁니다. 여기까지 마치면 여러 명이 함께 고치는 백엔드 서비스를 Nest 구조로 설계하고 운영할 수 있습니다.

NEST 01

Nest 가 필요한 순간

항상 Nest 가 정답은 아닙니다. 기준을 먼저 세웁시다.

Express 와의 비교

항목Express / NestJS
구조자유 (팀마다 제각각) / 강제 (어디 가나 같은 모양)
DI없음 (직접 import) / 내장
학습 곡선낮음 / 높음 (데코레이터·모듈 개념)
보일러플레이트적음 / 많음
테스트직접 구성 / 테스트 모듈 제공
적합한 규모~중형 / 중형 이상 · 장기 유지보수
이럴 때 Nest 를 고르세요 — ① 팀이 3명 이상, ② 서비스가 1년 이상 갈 예정, ③ 자바 개발자가 팀에 있음(학습 비용이 거의 0), ④ 트랜잭션·권한·이벤트 같은 횡단 관심사가 많음.
이럴 때는 과합니다 — 엔드포인트가 10개 미만인 사내 도구, 람다·서버리스(콜드 스타트가 느려집니다), 빠르게 검증하고 버릴 프로토타입.

main.ts — 실무 기본형

import { NestFactory } from "@nestjs/core";
import { ValidationPipe, VersioningType } from "@nestjs/common";
import helmet from "helmet";

async function bootstrap() {
  const app = await NestFactory.create(AppModule, {
    bufferLogs: true,                       // 로거 준비 전 로그를 모아 둠
  });

  app.use(helmet());
  app.enableCors({ origin: process.env.ALLOWED_ORIGINS?.split(",") });
  app.setGlobalPrefix("api");
  app.enableVersioning({ type: VersioningType.URI });   // /api/v1/...

  // ★ 전역 검증 파이프 — 이 설정이 핵심입니다 (s06)
  app.useGlobalPipes(new ValidationPipe({
    whitelist: true,                 // DTO 에 없는 속성 제거
    forbidNonWhitelisted: true,      // 있으면 에러
    transform: true,                 // 문자열 → 숫자 자동 변환
    transformOptions: { enableImplicitConversion: true },
  }));

  app.enableShutdownHooks();         // ★ SIGTERM 처리 (s16)

  await app.listen(process.env.PORT ?? 3000);
}
bootstrap();
whitelist: true 를 반드시 켜세요. DTO 에 정의하지 않은 필드를 자동으로 제거합니다. 이것이 없으면 { role: "admin" } 을 몰래 넣는 Mass Assignment 공격에 노출됩니다.

모듈 · 의존성 주입

Nest 의 뼈대입니다. 이 절만 이해하면 나머지는 문법입니다.

모듈 — 기능의 경계

@Module({
  imports: [                      // 이 모듈이 쓸 다른 모듈
    TypeOrmModule.forFeature([User]),
    forwardRef(() => OrdersModule),      // 순환 참조 해결
  ],
  controllers: [UsersController], // HTTP 진입점

    UsersService,
    UsersRepository,

    {                                                // 팩토리
      provide: "REDIS",
      useFactory: (cfg: ConfigService) => createClient({ url: cfg.get("REDIS_URL") }),
      inject: [ConfigService],
    },
  ],
  exports: [UsersService],        // ★ 다른 모듈에 공개할 것 (안 적으면 못 씁니다)
})
export class UsersModule {}
가장 흔한 에러 — Nest can't resolve dependencies of X. 원인은 셋 중 하나입니다: ① 프로바이더를 providers 에 안 넣음, ② 다른 모듈 것인데 그쪽에서 exports 를 안 함, ③ 그 모듈을 imports 에 안 넣음.

컨트롤러 · 라우팅

URL 과 함수를 잇는 얇은 층. 로직을 여기 두지 마세요.

기본형

@Controller("users")            // → /api/users
export class UsersController {
  constructor(private readonly service: UsersService) {}

  @Get()
  findAll(@Query() query: ListUsersDto) {
    return this.service.findAll(query);      // ★ Promise 를 그냥 반환하면 됩니다
  }

  @Get(":id")
  findOne(@Param("id", ParseIntPipe) id: number) {   // ★ 변환+검증
    return this.service.findOne(id);
  }

  @Post()
  @HttpCode(201)
  create(@Body() dto: CreateUserDto) {
    return this.service.create(dto);
  }

  @Patch(":id")
  update(@Param("id", ParseIntPipe) id: number,
         @Body() dto: UpdateUserDto) {
    return this.service.update(id, dto);
  }

  @Delete(":id")
  @HttpCode(204)
  remove(@Param("id", ParseIntPipe) id: number) {
    return this.service.remove(id);
  }
}

NEST 05

프로바이더 · 서비스

실제 일을 하는 곳. HTTP 를 몰라야 좋은 서비스입니다.

서비스 작성

@Injectable()
export class UsersService {
  private readonly logger = new Logger(UsersService.name);

  constructor(
    private readonly repo: UsersRepository,
    private readonly events: EventEmitter2,
  ) {}

  async create(dto: CreateUserDto): Promise<User> {
    const exists = await this.repo.findByEmail(dto.email);
    if (exists) throw new ConflictException("이미 가입된 이메일입니다");

    const user = await this.repo.save({
      ...dto,
      passwordHash: await bcrypt.hash(dto.password, 12),
    });

    this.logger.log(`사용자 생성 id=${user.id}`);
    this.events.emit("user.created", new UserCreatedEvent(user.id));
    return user;
  }

  async findOne(id: number): Promise<User> {
    const user = await this.repo.findById(id);
    if (!user) throw new NotFoundException(`사용자 ${id} 를 찾을 수 없습니다`);
    return user;
  }
}
내장 HTTP 예외를 그대로 쓰세요. NotFoundException·ConflictException· BadRequestException·ForbiddenException 등을 던지면 Nest 가 알맞은 상태 코드로 변환합니다. 도메인 규칙이 복잡해지면 커스텀 예외 + 필터로 확장하세요(s07).

// class-validator 대신 Zod 로 통일하는 팀도 많습니다
@Injectable()
export class ZodValidationPipe implements PipeTransform {
  constructor(private schema: ZodSchema) {}
  transform(value: unknown) {
    const r = this.schema.safeParse(value);
    if (!r.success) {
      throw new BadRequestException({
        message: "입력값이 올바르지 않습니다",
        errors: r.error.issues.map(i => ({ field: i.path.join("."), message: i.message })),
      });
    }
    return r.data;
  }
}

NEST 07

예외 필터

스프링의 @ControllerAdvice 와 같은 역할입니다.

전역 예외 필터

@Catch()                               // 모든 예외
export class AllExceptionsFilter implements ExceptionFilter {
  private readonly logger = new Logger("Exception");

  catch(exception: unknown, host: ArgumentsHost) {
    const ctx = host.switchToHttp();
    const res = ctx.getResponse<Response>();
    const req = ctx.getRequest<Request>();
    const requestId = req.headers["x-request-id"];

    // ① Nest 내장 예외
    if (exception instanceof HttpException) {
      const status = exception.getStatus();
      const body = exception.getResponse();
      if (status >= 500) this.logger.error({ exception, requestId });
      return res.status(status).json({ ...normalize(body), requestId });
    }

    // ② 라이브러리 예외 변환
    if (exception instanceof Prisma.PrismaClientKnownRequestError) {
      if (exception.code === "P2002")
        return res.status(409).json({ code: "DUPLICATE", requestId });
      if (exception.code === "P2025")
        return res.status(404).json({ code: "NOT_FOUND", requestId });
    }

    // ③ 예상치 못한 것 — 내부 정보를 감춥니다
    this.logger.error({ exception, path: req.url, requestId }, "처리되지 않은 예외");
    res.status(500).json({
      code: "INTERNAL_ERROR", message: "서버 오류가 발생했습니다", requestId,
    });
  }
}

// main.ts
app.useGlobalFilters(new AllExceptionsFilter());

도메인 예외 설계

// 비즈니스 규칙 위반은 HTTP 를 몰라도 되게
export class DomainError extends Error {
  constructor(message: string, public readonly code: string) {
    super(message);
    this.name = this.constructor.name;
  }
}
export class InsufficientStockError extends DomainError {
  constructor(productId: number) {
    super(`상품 ${productId} 의 재고가 부족합니다`, "INSUFFICIENT_STOCK");
  }
}

// 필터에서 HTTP 로 매핑
const DOMAIN_STATUS: Record<string, number> = {
  INSUFFICIENT_STOCK: 409,
  PAYMENT_DECLINED: 402,
  LIMIT_EXCEEDED: 429,
};

@Catch(DomainError)
export class DomainExceptionFilter implements ExceptionFilter {
  catch(err: DomainError, host: ArgumentsHost) {
    const res = host.switchToHttp().getResponse();
    res.status(DOMAIN_STATUS[err.code] ?? 400)
       .json({ code: err.code, message: err.message });
  }
}
왜 이렇게 나누나 — 서비스 계층이 NotFoundException(HTTP 개념)을 던지면 같은 서비스를 큐 워커나 배치에서 재사용할 때 어색해집니다. 도메인 예외로 던지고 변환은 필터에서 하면 계층이 깔끔하게 유지됩니다.

export const Roles = (...roles: Role[]) => SetMetadata("roles", roles);

@Injectable()
export class RolesGuard implements CanActivate {
  constructor(private reflector: Reflector) {}
  canActivate(ctx: ExecutionContext): boolean {
    const required = this.reflector.getAllAndOverride<Role[]>("roles", [
      ctx.getHandler(), ctx.getClass(),
    ]);
    if (!required?.length) return true;
    const { user } = ctx.switchToHttp().getRequest();
    if (!required.includes(user?.role))
      throw new ForbiddenException("권한이 없습니다");
    return true;
  }
}

// ① 응답 형태 통일
@Injectable()
export class TransformInterceptor<T> implements NestInterceptor<T, ApiResponse<T>> {
  intercept(ctx: ExecutionContext, next: CallHandler) {
    return next.handle().pipe(
      map(data => ({ success: true, data, timestamp: new Date().toISOString() })),
    );
  }
}

// ② 소요 시간 로깅
@Injectable()
export class LoggingInterceptor implements NestInterceptor {
  private readonly logger = new Logger("HTTP");
  intercept(ctx: ExecutionContext, next: CallHandler) {
    const req = ctx.switchToHttp().getRequest();
    const start = Date.now();
    return next.handle().pipe(
      tap(() => this.logger.log(
        `${req.method} ${req.url} ${Date.now() - start}ms`)),
    );
  }
}

// ③ 타임아웃 — 오래 걸리는 요청 끊기
@Injectable()
export class TimeoutInterceptor implements NestInterceptor {
  intercept(ctx: ExecutionContext, next: CallHandler) {
    return next.handle().pipe(
      timeout(10_000),
      catchError(e => e instanceof TimeoutError
        ? throwError(() => new RequestTimeoutException())
        : throwError(() => e)),
    );
  }
}
인터셉터는 RxJS 를 씁니다. map·tap·catchError 세 개만 알면 실무의 90%는 커버됩니다. RxJS 를 깊게 배울 필요는 없습니다.

@Injectable()
export class RequestIdMiddleware implements NestMiddleware {
  use(req: Request, res: Response, next: NextFunction) {
    const id = (req.headers["x-request-id"] as string) ?? randomUUID();
    req.headers["x-request-id"] = id;
    res.setHeader("x-request-id", id);
    next();
  }
}

export class AppModule implements NestModule {
  configure(consumer: MiddlewareConsumer) {
    consumer.apply(RequestIdMiddleware).forRoutes("*");   // ★ Nest 11(Express 5)은 "{*splat}"
    consumer.apply(RawBodyMiddleware)
            .forRoutes({ path: "webhooks/*", method: RequestMethod.POST });
    // ★ Nest 11 부터 와일드카드 문법이 path-to-regexp v8 기준으로 바뀌었습니다
    //   "*" → "{*splat}" · "webhooks/*" → "webhooks/{*splat}"
  }
}
미들웨어 vs 인터셉터 — 미들웨어는 Express 레벨(라우팅 전, 원본 req/res), 인터셉터는 Nest 레벨(응답 값에 접근 가능). 응답을 만지고 싶으면 인터셉터, 요청 전처리는 미들웨어입니다.
Nest 를 배우는 일의 절반은 이 일곱 칸의 이름을 익히는 것입니다.

Nest 에는 스프링 같은 @Transactional 이 기본으로 없습니다.

방법 ① 명시적 트랜잭션 (가장 확실)

// Prisma
async createOrder(dto: CreateOrderDto) {
  return this.prisma.$transaction(async (tx) => {
    const order = await tx.order.create({ data: { ...dto } });

    const r = await tx.stock.updateMany({
      where: { productId: dto.productId, quantity: { gte: dto.qty } },
      data: { quantity: { decrement: dto.qty } },
    });
    if (r.count === 0) throw new InsufficientStockError(dto.productId);
    //  ★ 던지면 자동 롤백됩니다

    await tx.pointHistory.create({ data: { userId: dto.userId, amount: -dto.qty } });
    return order;
  }, { timeout: 5000, isolationLevel: "ReadCommitted" });
}

// TypeORM
await this.dataSource.transaction(async (manager) => {
  await manager.save(order);
  await manager.decrement(Stock, { productId }, "quantity", qty);
});

계층 규칙 — 이것만 지키면 됩니다

Controller
HTTP 만 안다 검증된 DTO 를 서비스에 넘기고 결과를 반환. 여기 로직 금지
▼
Service

@WebSocketGateway({ cors: true, namespace: "/chat" })
export class ChatGateway implements OnGatewayConnection {
  @WebSocketServer() server: Server;

  async handleConnection(client: Socket) {
    const token = client.handshake.auth.token;
    try {
      client.data.user = this.jwt.verify(token);     // ★ 연결 시 인증
    } catch {
      client.disconnect();
    }
  }

  @SubscribeMessage("message")
  async onMessage(@MessageBody() dto: MessageDto,
                  @ConnectedSocket() client: Socket) {
    const saved = await this.chatService.save(dto, client.data.user.id);
    this.server.to(dto.roomId).emit("message", saved);
    return { ok: true };                              // ack
  }
}
서버가 여러 대면 소켓이 갈라집니다. A 서버에 붙은 사용자와 B 서버에 붙은 사용자가 서로 메시지를 못 받습니다. Redis 어댑터(@socket.io/redis-adapter)를 반드시 붙이세요 (🚀 대규모 트래픽 k11).

// 명령 — 상태를 바꿉니다
export class CreateOrderCommand {
  constructor(readonly userId: number, readonly items: OrderItem[]) {}

@CommandHandler(CreateOrderCommand)
export class CreateOrderHandler implements ICommandHandler<CreateOrderCommand> {
  constructor(private readonly repo: OrderRepository,
              private readonly publisher: EventPublisher) {}

  async execute(cmd: CreateOrderCommand) {
    const order = this.publisher.mergeObjectContext(Order.create(cmd));
    await this.repo.save(order);
    order.commit();                    // ★ 쌓인 도메인 이벤트를 한 번에 발행
    return order.id;
  }
}

import { ClsModule, ClsService } from "nestjs-cls";

ClsModule.forRoot({
  global: true,
  middleware: {
    mount: true,
    setup: (cls, req) => {
      cls.set("requestId", req.headers["x-request-id"] ?? randomUUID());
      cls.set("userId", req.user?.id);
    },
  },
});

// 어디서든 꺼내 씁니다 (매개변수로 안 넘겨도 됩니다)
constructor(private readonly cls: ClsService) {}
this.logger.log({ requestId: this.cls.get("requestId") }, "주문 생성");

// ★ 트랜잭션 전파(s12)도 같은 원리입니다
Scope.REQUEST 를 피해야 하는 이유 — 요청마다 의존성 트리 전체를 새로 만듭니다. 그 프로바이더를 주입받는 상위 프로바이더도 전부 요청 스코프가 되어 성능이 눈에 띄게 떨어집니다. 요청 정보가 필요하면 CLS(AsyncLocalStorage) 를 쓰세요.
