CSS 가 어려운 이유는 문법이 아니라 "왜 이 값이 이겼는가"가 안 보이기 때문입니다. 이 탭은 값이 정해지는 순서 → 상자 계산 → 배치(Flex·Grid) → 반응형 순서로, 안 먹힐 때 어디를 봐야 하는지를 기준으로 정리했습니다. 여기까지 마치면 !important 없이 레이아웃을 짜고 고칠 수 있습니다.

CSS 01

값이 정해지는 순서

"CSS 가 안 먹혀요"의 90%가 이 순서를 몰라서 생깁니다.

CSS 디버깅은 "왜 안 먹지?"가 아니라 "몇 번 심판에서 누구에게 졌지?"로 물으면 끝납니다.

위에서부터 이긴다

1. !important            ← 최후의 수단 (쓰지 마세요)
2. 인라인 style="…"       ← 명시도 1000
3. #id                   ← 100
4. .class · [속성] · :hover ← 10
5. 태그 · ::before        ← 1
6. * (전체 선택자)         ← 0

같은 점수면 → 나중에 적힌 것이 이깁니다
/* 점수 계산 예 */
#app .btn span   { }   /* 100 + 10 + 1 = 111  ← 이김 */
.page .btn span  { }   /*  10 + 10 + 1 =  21 */
확인법 — 개발자도구에서 요소를 찍으면 Styles 패널에 진 규칙에 취소선이 그어져 있습니다. 무엇에 졌는지 바로 보이니 추측하지 말고 여기를 보세요.

!important 대신 @layer

/* 순서를 '미리' 정해 둔다 — 뒤 레이어가 이깁니다 */
@layer reset, base, components, utilities;

@layer base {
  a { color: blue; }              /* 명시도 1 */
}
@layer utilities {
  .text-red { color: red; }       /* 명시도 10 이지만 */
}
/* → 레이어 순서가 우선이라 utilities 가 이깁니다.
      명시도 싸움을 할 필요가 없어집니다. */
!important 는 빚입니다. 한 번 쓰면 그걸 이기려고 또 쓰게 되고, 결국 전부 important 가 됩니다. 급하면 선택자를 한 단계 구체적으로 하거나 @layer 로 순서를 정하세요.
CSS 02

선택자 — 필요한 만큼만

깊게 쓸수록 고치기 어려워집니다. 짧을수록 좋습니다.

/* 기본 */
.card            { }        /* class */
.card > .title   { }        /* 바로 아래 자식만 */
.card .title     { }        /* 몇 단계 아래든 */
h2 + p           { }        /* h2 바로 다음 형제 */
h2 ~ p           { }        /* h2 뒤의 모든 형제 p */

/* 상태 */
a:hover, a:focus-visible { }   /* 마우스 / 키보드 포커스 */
input:disabled           { }
input:checked + label    { }   /* 체크된 것의 label */
li:nth-child(2n)         { }   /* 짝수 번째 */
li:not(.done)            { }

/* 요즘 많이 쓰는 것 */
.card:has(img)           { }   /* ★ 이미지를 가진 카드 (부모 선택) */
:is(h1, h2, h3) + p      { }   /* 묶어서 짧게 */
:where(h1, h2) a         { }   /* :is 와 같지만 명시도 0 */
선택자쓰임새
:has()부모를 선택. "이미지가 있는 카드만 패딩 다르게" 같은 게 JS 없이 됩니다
:is()여러 선택자를 묶어 짧게. 명시도는 그중 가장 높은 것을 따릅니다
:where()명시도가 항상 0. 라이브러리 기본값에 쓰면 사용자가 쉽게 덮어씁니다
:focus-visible키보드로 왔을 때만 테두리. 마우스 클릭엔 안 뜹니다
div > ul > li > a > span 처럼 길게 쓰지 마세요. HTML 구조를 조금만 바꿔도 깨지고, 명시도가 올라가 나중에 못 덮습니다. 필요한 요소에 class 하나를 주는 편이 거의 항상 낫습니다.

:has() 실전 — JS 로 하던 일이 사라집니다

/* 입력이 틀리면 라벨까지 빨갛게 — 클래스 토글 JS 불필요 */
.field:has(input:invalid:not(:placeholder-shown)) label{ color: crimson; }

/* 체크된 항목이 하나라도 있으면 삭제 버튼 표시 */
.toolbar:has(~ .list input:checked) .btn-delete{ display: inline-flex; }

/* 이미지가 있는 카드와 없는 카드의 레이아웃 분기 */
.card:has(> img){ grid-template-rows: 160px 1fr; }

/* 다음 요소에 따라 내 여백 조절 — "제목 뒤가 표면 붙이기" */
h2:has(+ table){ margin-bottom: 4px; }

/* 모달이 열려 있으면 body 스크롤 잠금 */
body:has(dialog[open]){ overflow: hidden; }
:has() 는 "상태를 클래스로 복사해 두는 JS"를 지우는 도구입니다. 상태가 이미 DOM 에 있다면(checked · invalid · open · 자식 유무) 스타일은 CSS 가 직접 읽게 하세요.
CSS 03

박스 모델과 box-sizing

"width 를 300 으로 줬는데 320 이에요" — 여기서 시작합니다.

첫 CSS 파일의 첫 줄이 *{box-sizing:border-box} 인 이유 — 계산 없는 세계로 시작하기 위해서입니다.

기본값의 함정

/* 기본: content-box */
.box{
  width: 300px;
  padding: 10px;      /* 좌우 20 */
  border: 1px solid;  /* 좌우 2 */
}
/* → 실제 차지하는 너비 = 300 + 20 + 2 = 322px */

/* ✓ 거의 모든 프로젝트가 이걸 깝니다 */
*, *::before, *::after { box-sizing: border-box; }

.box{ width:300px; padding:10px; border:1px solid; }
/* → 실제 너비 = 300px (패딩·테두리가 안쪽으로) */
border-box 는 사실상 표준입니다. "적은 값이 곧 보이는 값"이 되어 계산이 사라집니다.

margin 이 겹치는 현상

/* 위아래 margin 은 '합쳐지지 않고 큰 쪽만' 남습니다 */
.a{ margin-bottom: 20px; }
.b{ margin-top: 30px; }
/* → 사이 간격은 50 이 아니라 30 */

/* 겹침을 막는 법 */
.parent{ display: flex; }        /* flex·grid 안에서는 안 겹침 */
.parent{ padding-top: 1px; }     /* 경계가 생기면 안 겹침 */
.parent{ overflow: hidden; }

/* ✓ 요즘 방식 — 간격은 부모가 gap 으로 */
.list{ display: flex; flex-direction: column; gap: 16px; }
자식에 margin 을 주는 대신 부모에 gap 을 주세요. "마지막 항목만 margin 빼기"(:last-child) 같은 예외 처리가 통째로 사라집니다.
CSS 04

단위 고르기

px 로만 짜면 글씨 크기를 키운 사용자에게 화면이 깨집니다.

단위기준쓰는 곳
px고정테두리, 그림자, 아주 작은 간격
rem루트 글꼴(보통 16px)글자·여백의 기본. 사용자 설정을 따라갑니다
em그 요소의 글꼴버튼 안쪽 여백처럼 글자에 비례해야 할 때
%부모너비
vw·vh화면전체 화면 섹션
dvh실제 보이는 높이모바일 주소창이 접히는 것까지 반영
ch글자 0 의 너비글줄 길이 제한 (max-width:65ch)
/* 화면 크기에 따라 부드럽게 — 미디어 쿼리 없이 */
h1{ font-size: clamp(1.5rem, 4vw, 3rem); }
/*                  최소     선호   최대  */

.container{ width: min(100% - 32px, 1200px); }   /* 좌우 16 여백 + 최대 1200 */
.side{ width: max(240px, 20%); }

/* 모바일 100vh 문제 — 주소창 때문에 잘립니다 */
.full{ height: 100dvh; }         /* ✓ */
글자 크기에 px 을 쓰면 브라우저 글꼴 크기 설정을 바꿔도 그대로입니다. 저시력 사용자가 글씨를 키울 수 없게 됩니다 — 본문·제목은 rem 으로 잡으세요.
CSS 05

변수 — 커스텀 프로퍼티

색·간격을 한 곳에서 정하면 테마 교체가 한 줄이 됩니다.

기본

:root{
  --brand: #6a5cff;
  --text: #1a1a1a;
  --bg: #ffffff;
  --radius: 12px;
  --gap: 16px;
}

.btn{
  background: var(--brand);
  border-radius: var(--radius);
  color: var(--fg, white);      /* 두 번째 값 = 기본값 */
}

/* 부분만 덮어쓰기 — 이 안에서만 적용됩니다 */
.panel{ --brand: #00b894; }
SCSS 변수와 다릅니다. 커스텀 프로퍼티는 브라우저에서 살아 있어 JS 로 바꾸거나 미디어 쿼리 안에서 다시 정할 수 있습니다.

JS 로 바꾸기 · 계산에 쓰기

// 읽기
const c = getComputedStyle(document.documentElement)
            .getPropertyValue("--brand").trim();

// 쓰기 (테마 교체·슬라이더 연동)
document.documentElement.style.setProperty("--brand", "#ff6b6b");
/* 계산에 그대로 씁니다 */
.card{ padding: calc(var(--gap) * 1.5); }

/* 색 하나로 변형 만들기 (요즘 문법) */
.btn:hover{ background: color-mix(in oklab, var(--brand), black 12%); }

/* 값에 타입을 알려 주면 애니메이션도 됩니다 */
@property --ang{ syntax:"<angle>"; inherits:false; initial-value:0deg; }

이름을 어떻게 지을까 — 이 두 층이면 충분합니다

원시값 → 의미값 2단 구조

:root{
  /* ① 원시값(palette) — 색 그 자체. 여기서만 실제 색을 씁니다 */
  --gray-0:#ffffff; --gray-1:#f5f6f8; --gray-8:#23262d; --gray-9:#0f1115;
  --violet-5:#6a5cff; --red-5:#e5484d; --green-5:#30a46c;

  /* ② 의미값(semantic) — 화면에서는 이것만 씁니다 */
  --bg:        var(--gray-0);
  --bg-subtle: var(--gray-1);
  --fg:        var(--gray-9);
  --fg-muted:  #666;
  --line:      #e5e5e5;
  --accent:    var(--violet-5);
  --danger:    var(--red-5);

  /* 간격·모서리·그림자도 같은 방식 */
  --space-1:4px; --space-2:8px; --space-3:16px; --space-4:24px;
  --radius:12px; --radius-sm:8px;
  --shadow-1:0 1px 2px rgb(0 0 0 / .06);
}

/* 다크 모드는 ②만 바꿉니다 — 컴포넌트 CSS 는 한 줄도 안 고칩니다 */
:root[data-theme="dark"]{
  --bg: var(--gray-9);
  --bg-subtle: var(--gray-8);
  --fg: #e8e8ea;
  --line: #23262d;
}

/* 컴포넌트는 의미값만 참조합니다 */
.card{
  background: var(--bg-subtle);
  border: 1px solid var(--line);
  border-radius: var(--radius);
  padding: var(--space-3);
}
--white 가 아니라 --bg 로 이름을 지으세요. 다크 모드를 넣는 순간 --white: #0f1115; 같은 말이 안 되는 코드가 됩니다. "무슨 색인가"가 아니라 "무슨 역할인가"로 이름을 지으면 테마 추가가 변수 몇 줄 교체로 끝납니다.

알아 두면 쓰임새가 넓어지는 것

/* ① 컴포넌트에 '조절 손잡이'를 만들어 두기 */
.btn{
  --btn-bg: var(--accent);
  --btn-fg: white;
  --btn-pad: var(--space-2) var(--space-3);

  background: var(--btn-bg);
  color: var(--btn-fg);
  padding: var(--btn-pad);
}
/* 쓰는 쪽에서 변형 — 새 클래스를 만들 필요가 없습니다 */
.btn.danger{ --btn-bg: var(--danger); }
.btn.ghost { --btn-bg: transparent; --btn-fg: var(--accent); }

/* ② 상속을 이용한 지역 테마 — 이 안의 모든 자식에 적용됩니다 */
.promo{ --accent:#ff6b6b; --line:#ffd9d9; }

/* ③ 미디어 쿼리 안에서 값만 바꾸기 (선택자 중복이 사라집니다) */
:root{ --gap:16px; --col:3; }
@media (max-width:900px){ :root{ --gap:12px; --col:2; } }
@media (max-width:600px){ :root{ --gap:8px;  --col:1; } }
.grid{
  display:grid;
  gap: var(--gap);
  grid-template-columns: repeat(var(--col), 1fr);
}

/* ④ 폴백은 쉼표 뒤에 — 변수가 없을 때만 쓰입니다 */
color: var(--fg, #1a1a1a);
/* 중첩도 됩니다 */
color: var(--fg-strong, var(--fg, #1a1a1a));
커스텀 프로퍼티는 상속됩니다 — 이게 장점이자 함정입니다. .promo{ --accent: red } 를 걸면 그 안의 모든 자식이 영향을 받습니다. 의도한 것이면 강력하지만, 모르고 쓰면 “왜 여기만 색이 다르지”를 한참 찾게 됩니다.
또 값이 유효한지 검사하지 않습니다 — --gap: 16(단위 누락)처럼 잘못된 값을 넣으면 조용히 무시되고 기본값이 적용됩니다. @property 로 타입을 선언해 두면 이 실수를 막을 수 있습니다.
CSS 06

Flexbox — 한 줄 배치

가로 또는 세로 한 방향으로 늘어놓을 때 씁니다.

외우지 말고 이렇게 — justify 는 흐르는 방향, align 은 그 수직. 방향이 돌면 둘 다 함께 돕니다.

부모에 주는 것

.row{
  display: flex;
  flex-direction: row;        /* row | column */
  justify-content: space-between;  /* 주축(가로) 정렬 */
  align-items: center;             /* 교차축(세로) 정렬 */
  gap: 16px;
  flex-wrap: wrap;            /* 넘치면 줄바꿈 */
}

/* 가장 많이 쓰는 세 가지 */
.center{ display:flex; justify-content:center; align-items:center; }
.between{ display:flex; justify-content:space-between; align-items:center; }
.stack{ display:flex; flex-direction:column; gap:12px; }
축이 헷갈릴 때 — justify-* 는 방향(direction)을 따라, align-* 은 그 수직입니다. flex-direction:column 이면 둘의 의미가 뒤바뀝니다.

자식에 주는 것

.item{
  flex: 1;              /* = 1 1 0  남은 공간을 똑같이 나눔 */
  flex: 0 0 200px;      /* 늘지도 줄지도 않는 200px 고정 */
  flex: 1 1 auto;       /* 내용 크기에서 시작해 늘고 줆 */
}

.push{ margin-left: auto; }   /* ★ 이것만 오른쪽 끝으로 */

/* 줄어들다 글자가 삐져나오는 문제 */
.ellipsis{
  min-width: 0;               /* ★ flex 자식의 기본은 min-width:auto */
  overflow: hidden;
  text-overflow: ellipsis;
  white-space: nowrap;
}
말줄임(…)이 안 될 때는 min-width:0 을 의심하세요. flex 자식은 기본적으로 내용보다 작아지지 않으려 해서 overflow:hidden 이 무시된 것처럼 보입니다.
CSS 07

Grid — 두 방향 배치

행과 열을 동시에 다뤄야 하면 Grid 가 훨씬 짧습니다.

가장 많이 쓰는 형태

/* ★ 미디어 쿼리 없는 반응형 카드 그리드 */
.cards{
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(260px, 1fr));
  gap: 20px;
}
/* 화면이 좁아지면 자동으로 열 수가 줄어듭니다 */

/* 고정 + 가변 */
.layout{
  display: grid;
  grid-template-columns: 240px 1fr;   /* 사이드바 + 본문 */
  gap: 24px;
}

/* 12칸 시스템 */
.g{ display:grid; grid-template-columns: repeat(12, 1fr); }
.wide{ grid-column: span 8; }

이름으로 배치하기

.page{
  display: grid;
  grid-template-areas:
    "head head"
    "side main"
    "foot foot";
  grid-template-columns: 240px 1fr;
  grid-template-rows: auto 1fr auto;
  min-height: 100dvh;
}
.page > header{ grid-area: head; }
.page > nav   { grid-area: side; }
.page > main  { grid-area: main; }
.page > footer{ grid-area: foot; }

/* 모바일에선 한 줄로 */
@media (max-width: 720px){
  .page{
    grid-template-areas: "head" "main" "side" "foot";
    grid-template-columns: 1fr;
  }
}
Flex vs Grid — 한 방향이면 Flex, 격자면 Grid. 내용 크기에 맞춰 흐르게 두려면 Flex, 칸을 먼저 정하고 채우려면 Grid 입니다.

복붙해서 쓰는 레이아웃 다섯

① 반응형 카드 · ② 성지 레이아웃

/* ① 미디어 쿼리 없이 반응하는 카드 목록 */
.cards{
  display:grid;
  grid-template-columns: repeat(auto-fill, minmax(min(260px, 100%), 1fr));
  gap:20px;
}
/* min(260px, 100%) — 화면이 260px 보다 좁아도 넘치지 않습니다 */

/* auto-fit vs auto-fill 차이 */
/*  auto-fit  : 남는 칸을 접어 카드가 늘어납니다 (카드가 2개면 화면을 꽉 채움) */
/*  auto-fill : 빈 칸을 그대로 둡니다 (카드 크기가 일정하게 유지됨) */

/* ② 화면 전체를 쓰는 기본 골격 — 푸터가 항상 바닥에 */
body{
  display:grid;
  grid-template-rows: auto 1fr auto;
  min-height:100dvh;              /* ★ vh 가 아니라 dvh — 모바일 주소창 대응 */
  margin:0;
}

/* ③ 본문은 가운데, 특정 요소만 화면 폭 전체로 */
.prose{
  display:grid;
  grid-template-columns:
    1fr min(68ch, 100% - 2rem) 1fr;   /* 좌여백 | 본문 | 우여백 */
}
.prose > *{ grid-column:2; }          /* 기본은 가운데 칸 */
.prose > .full{ grid-column:1 / -1; } /* 이것만 전체 폭 */

③ 겹치기 · ④ 표 · ⑤ 자동 높이 맞춤

/* ④ 요소를 겹쳐 놓기 — position:absolute 없이 */
.stack{ display:grid; }
.stack > *{ grid-area: 1 / 1; }       /* 전부 같은 칸에 = 겹칩니다 */
.stack > .overlay{ place-self:end center; }
/* 이미지 위 캡션·로딩 스피너·배지에 유용합니다.
   부모 높이를 가장 큰 자식이 정해 주는 것이 장점입니다. */

/* ⑤ 카드 안 요소 높이를 줄마다 맞추기 (서브그리드) */
.cards{ display:grid; grid-template-columns:repeat(3,1fr); gap:16px; }
.card{
  display:grid;
  grid-row: span 3;
  grid-template-rows: subgrid;        /* ★ 부모 행을 그대로 물려받습니다 */
}
/* → 제목·본문·버튼이 카드마다 같은 높이에 정렬됩니다 */

/* 버튼을 항상 카드 바닥에 (서브그리드를 못 쓸 때) */
.card{ display:flex; flex-direction:column; }
.card .actions{ margin-top:auto; }

/* 그리드 안에서 정렬 */
.box{
  display:grid;
  place-items:center;                 /* 가로·세로 가운데 — 가장 짧은 방법 */
}
min-height:100vh 는 모바일에서 잘립니다. 주소창이 차지하는 높이가 스크롤에 따라 변하기 때문입니다. 100dvh(동적 뷰포트 높이)를 쓰면 실제 보이는 영역에 맞춰집니다. 구형 브라우저까지 챙기려면 min-height:100vh; min-height:100dvh; 로 두 줄 나란히 두세요 — 지원하지 않는 브라우저는 뒤 줄을 무시합니다.

Grid 에서 자주 막히는 것

증상원인해결
내용이 칸 밖으로 넘침그리드 항목의 기본 min-width 가 autominmax(0, 1fr) 또는 자식에 min-width:0
긴 텍스트가 열을 밀어냄같은 이유overflow-wrap:anywhere 함께
화면보다 넓어져 가로 스크롤고정 minmax(260px,...)minmax(min(260px,100%),1fr)
gap 이 안 먹음구형 브라우저 · display:blockdisplay:grid·flex 확인
행 높이가 제각각기본이 내용 높이grid-auto-rows:1fr 또는 subgrid
순서를 바꾸니 접근성 경고order·grid-area 는 보이는 순서만 바꿉니다키보드·스크린리더는 HTML 순서를 따릅니다 — DOM 을 고치세요
넘침 문제의 원인은 거의 항상 min-width:auto 입니다. 그리드·플렉스 항목은 “내용보다 작아지지 않는다”가 기본값이라, 안에 긴 URL 이나 넓은 표가 있으면 칸이 늘어나 레이아웃이 깨집니다. 1fr 대신 minmax(0, 1fr) 을 쓰는 습관 하나로 이 부류의 버그가 통째로 사라집니다.
Flex 와 Grid 는 경쟁 관계가 아닙니다 — 바깥 틀은 Grid, 안쪽 줄은 Flex 가 흔한 조합입니다.
CSS 08

position 과 z-index

"z-index 9999 인데 안 올라와요" — 쌓임 맥락 때문입니다.

position 다섯 가지

값기준
static기본. top/left 안 먹습니다
relative원래 자리 기준으로 이동. 자리는 그대로 차지
absolute가장 가까운 position≠static 조상 기준. 자리를 비웁니다
fixed화면 기준. 스크롤해도 고정
sticky스크롤하다 정해진 위치에서 붙습니다
/* sticky 헤더 — 부모에 overflow 가 있으면 안 붙습니다 */
.thead{ position: sticky; top: 0; z-index: 2; background: white; }

/* 부모에 기준점 주기 */
.card{ position: relative; }
.badge{ position: absolute; top: 8px; right: 8px; }

z-index 가 안 먹는 이유

/* 아래 속성들은 '새 쌓임 맥락'을 만듭니다.
   그 안의 z-index 는 아무리 커도 '그 상자 안에서만' 유효합니다. */
transform / filter / opacity(1 미만) / will-change
position:fixed / isolation:isolate / contain:paint

/* ✗ 안 되는 상황 */
.parent{ transform: translateZ(0); }   /* ← 여기서 갇힘 */
.child { z-index: 9999; }              /* parent 밖으로 못 나감 */

/* ✓ 해결 — 모달은 최상위로 옮긴다 */
document.body.appendChild(modal);
/* 또는 아예 top-layer 를 쓰는 <dialog> / popover 사용 */
z-index 를 999999 로 올리기 전에 개발자도구에서 조상 중에 transform·opacity·filter 가 있는지 보세요. 거의 항상 그것 때문입니다.
z-index 는 전역 순위가 아니라 같은 유리 상자 안에서의 순위입니다 — 상자가 다르면 숫자 비교 자체가 일어나지 않습니다.

미디어 쿼리

/* 기본 = 모바일 */

컨테이너 쿼리

/* 화면이 아니라 '부모 상자' 크기로 판단합니다.

@container (min-width: 400px){
  .card{ display:grid; grid-template-columns:120px 1fr; }

미디어 쿼리로는 이걸 못 합니다. 화면은 넓은데 카드가 좁은 사이드바에 들어가 있으면 미디어 쿼리는 "넓다"고 판단해 깨진 레이아웃을 만듭니다. 재사용하는 컴포넌트일수록 컨테이너 쿼리가 맞습니다.

반응형 점검 목록 — 어디를 확인해야 하나

확인깨질 때의 처방
360px (작은 폰)에서 가로 스크롤이 없는가고정 width 를 max-width:100% 로 · 긴 단어 overflow-wrap
이미지·영상이 상자를 넘지 않는가img{max-width:100%;height:auto} — 리셋에 포함시키세요

}

.clamp2{

한글 웹폰트는 무겁습니다(전체 글자를 담으면 수 MB). unicode-range 로 쪼개거나 서브셋 폰트를 쓰고, 본문은 시스템 폰트로 두는 것도 충분히 좋은 선택입니다.

  --fs-base: 1rem;       /* 16 — 본문 */
  --fs-lg:   1.25rem;    /* 20 — 소제목 */
  --fs-xl:   1.625rem;   /* 26 — 섹션 제목 */

h1{ font-size: var(--fs-2xl); line-height: 1.2; }

규칙은 하나 — 제목일수록 line-height 를 좁게(1.1~1.3), 본문은 넉넉하게(1.6~1.8). 큰 글자에 1.7을 주면 줄 사이가 벌어져 어색해집니다.

색을 직접 쓰지 않고 변수로 두면 테마는 저절로 됩니다.

/* 1) 의미로 이름을 짓습니다 — --white 가 아니라 --bg */
:root{
  --bg:#ffffff; --fg:#1a1a1a; --muted:#666; --line:#e5e5e5;
  color-scheme: light;              /* 스크롤바·기본 폼도 함께 밝게 */
}

/* 2) 시스템 설정을 따름 */
@media (prefers-color-scheme: dark){

    --bg:#0f1115; --fg:#e8e8ea; --muted:#9aa0a6; --line:#23262d;
    color-scheme: dark;
  }
}

/* 3) 사용자가 직접 고른 값이 이깁니다 */
:root[data-theme="dark"]{
  --bg:#0f1115; --fg:#e8e8ea; --line:#23262d; color-scheme: dark;
}

body{ background: var(--bg); color: var(--fg); }
// 토글 — 고른 값을 기억해 둡니다
const set = (t) => {
  document.documentElement.dataset.theme = t;
  try{ localStorage.setItem("theme", t); }catch(e){}

// 첫 로드에 '깜빡임'을 막으려면 이 코드를 <head> 안에서 먼저 실행
다크 모드에서 순백(#fff) 글자는 눈이 아픕니다. #e8e8ea 정도로 낮추고, 배경도 순흑 대신 #0f1115 처럼 살짝 띄우세요. 대비는 4.5:1 이상을 지켜야 읽힙니다.

첫 로드 깜빡임(FOUC) 없애기

head 안에서 먼저 결정합니다

<head>
  <!-- ★ CSS 보다 먼저, 인라인으로. 외부 파일이면 이미 늦습니다 -->
  <script>
    (function () {
      try {
        var saved = localStorage.getItem("theme");           // "light" | "dark" | null
        var prefersDark = matchMedia("(prefers-color-scheme: dark)").matches;
        var theme = saved || (prefersDark ? "dark" : "light");
        document.documentElement.dataset.theme = theme;
        document.documentElement.style.colorScheme = theme;  // 스크롤바·기본 폼도
      } catch (e) { /* 사생활 보호 모드 등 — 기본값으로 진행 */ }
    })();
  </script>
  <link rel="stylesheet" href="/style.css">
</head>
// 토글 — 시스템 설정으로 되돌리는 선택지도 주세요
const root = document.documentElement;

function setTheme(t) {                 // "light" | "dark" | "system"
  if (t === "system") {
    localStorage.removeItem("theme");
    t = matchMedia("(prefers-color-scheme: dark)").matches ? "dark" : "light";
  } else {
    localStorage.setItem("theme", t);
  }
  root.dataset.theme = t;
  root.style.colorScheme = t;
}

// 사용자가 직접 고르지 않았을 때만 시스템 변경을 따라갑니다
matchMedia("(prefers-color-scheme: dark)").addEventListener("change", (e) => {
  if (!localStorage.getItem("theme")) setTheme("system");
});
이 스크립트를 <body> 끝이나 외부 파일에 두면 깜빡입니다. 브라우저가 밝은 화면을 먼저 그린 뒤 어둡게 바꾸기 때문입니다. <head> 안에 인라인으로 두어야 첫 페인트 전에 결정됩니다. SSR 프레임워크(Next·Nuxt)에도 이 목적의 전용 슬롯이 있습니다.

다크 모드에서 놓치기 쉬운 것

대상흔한 문제해결
이미지·로고흰 배경 PNG 가 그대로테마별 이미지 · SVG 에 currentColor
그림자어두운 배경에서 안 보임밝은 테두리(--line)로 대체

코드 하이라이트대비가 무너짐테마별 색 세트를 따로
차트·지도배경이 흰색라이브러리 테마 옵션 연동
iframe·임베드제어 불가가능하면 파라미터로 테마 전달
순백 텍스트눈부심·번짐#e8e8ea 수준으로
 
/* 이미지 — 테마에 따라 다른 파일 (JS 없이) */
.logo{ content: url("/logo-light.svg"); }
:root[data-theme="dark"] .logo{ content: url("/logo-dark.svg"); }

/* SVG 아이콘은 색을 상속하게 만들어 두면 테마가 저절로 따라옵니다 */
.icon{ fill: currentColor; }

/* 그림자 대신 테두리 — 다크에서 훨씬 깔끔합니다 */
.card{ box-shadow: var(--shadow-1); border:1px solid var(--line); }
:root[data-theme="dark"] .card{ --shadow-1: none; }

/* 사용자가 움직임을 줄이도록 설정했다면 존중하세요 */
@media (prefers-reduced-motion: reduce){
  *, *::before, *::after{
    animation-duration:.01ms !important;
    transition-duration:.01ms !important;
    scroll-behavior:auto !important;
  }
}

/* 테마 전환에 트랜지션을 걸면 오히려 번져 보입니다 — 색만 짧게 */
:root{ transition: background-color .15s, color .15s; }
대비를 눈으로 판단하지 마세요. 브라우저 개발자 도구의 색상 선택기가 대비율을 바로 보여 주고, Lighthouse 접근성 검사도 잡아 줍니다. 본문은 4.5:1, 큰 글자(18px+ 굵게)는 3:1 이 기준입니다 — 다크 모드에서 회색 본문이 이 선을 넘기지 못하는 경우가 특히 많습니다.

CSS 14

어떻게 관리할 것인가

규모가 커지면 문법보다 규칙이 중요해집니다.

방식성격맞는 곳
일반 CSS + BEM.card__title--big 처럼 이름으로 범위를 표시작은 팀, 정적 사이트
CSS Modules빌드가 클래스명을 고유하게 바꿔 충돌 원천 차단React·Vue 컴포넌트
Tailwind미리 만든 유틸 클래스 조합. 이름 짓기가 사라집니다빠른 개발, 디자인 시스템이 정해진 곳
Vue <style scoped>그 컴포넌트에만 적용Vue SFC (기본값처럼 씀)
CSS-in-JS런타임 비용이 있어 예전만큼 권하지 않습니다기존 프로젝트 유지보수
무엇을 쓰든 공통으로 지킬 것 — ① 색·간격은 변수로 ② 선택자는 얕게 ③ !important 는 0개를 목표로 ④ 컴포넌트 밖으로 새는 스타일 금지.
초기화(reset) 는 필요한 만큼만. 요즘은 box-sizing, 기본 margin 제거, img{max-width:100%;display:block}, :focus-visible 유지 정도면 충분합니다 — 과한 reset 은 기본 접근성까지 지워 오히려 손해입니다.

그대로 시작해도 되는 기본 골격

/* styles/base.css — 이 순서로 레이어를 깝니다 */
@layer reset, tokens, base, components, utilities;

@layer reset{
  *,*::before,*::after{ box-sizing:border-box; margin:0; }
  img,video{ max-width:100%; height:auto; display:block; }
  button,input,select{ font:inherit; color:inherit; }
}
@layer tokens{
  :root{
    --bg:#fff; --fg:#1a1a1a; --line:#e5e5e5; --brand:#6a5cff;
    --gap:16px; --radius:10px;
    --fs-base:1rem; --fs-lg:1.25rem;
  }
}
@layer base{
  body{
    background:var(--bg); color:var(--fg);
    font-family:system-ui, "Malgun Gothic", sans-serif;
    line-height:1.7; word-break:keep-all;
  }
}
