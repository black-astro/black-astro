VUE 01

Vue 가 하는 일

리액트와 목표는 같고 방법이 다릅니다.

가장 작은 예

<script setup>
import { ref } from "vue";
const count = ref(0);
</script>

<template>
  <button @click="count++">{{ count }}번</button>
</template>

<style scoped>
button{ padding: 8px 14px; }
</style>
세 덩어리가 한 파일에 있습니다 — 로직(script) · 화면(template) · 스타일(style). scoped 를 붙이면 그 컴포넌트에만 스타일이 적용됩니다.

리액트와의 차이

항목ReactVue
다시 그리는 단위컴포넌트 함수 전체 재실행바뀐 값이 쓰인 곳만
값 바꾸기setState(새 값)count.value++ (직접)
화면 문법JSX (JS 안에 마크업)템플릿 (HTML + 디렉티브)
최적화memo 등 수동(19부터 자동)추적으로 대체로 자동
Vue 는 "함수가 다시 실행되지 않습니다". <script setup> 은 한 번만 돕니다 — 리액트처럼 "렌더마다 새로 만들어지는 변수" 개념이 없어 useCallback 같은 장치도 필요 없습니다.
Vue 를 배운다는 것은 이 장부(의존 추적)가 언제 끊기는지를 배우는 것입니다 — 02번의 함정이 전부 그 이야기입니다.
VUE 02

ref 와 reactive

둘 중 ref 하나만 써도 됩니다. 그게 헷갈리지 않습니다.

기본

import { ref, reactive } from "vue";

const n = ref(0);                    // 아무 타입이나
const user = ref({ name: "현우" });

n.value++;                           // ★ JS 에서는 .value
user.value.name = "민수";
user.value = { name: "새 객체" };     // 통째 교체도 됨

const state = reactive({ n: 0 });    // 객체 전용
state.n++;                           // .value 없이

// 템플릿 안에서는 .value 를 안 붙입니다 (자동으로 풀림)
// {{ n }}  ← 이렇게

reactive 의 함정

const state = reactive({ n: 0 });

// ✗ 통째로 바꾸면 반응성이 끊깁니다
state = reactive({ n: 10 });        // 아예 불가 (const)
Object.assign(state, { n: 10 });    // ✓ 이렇게 해야 함

// ✗ 구조 분해하면 연결이 끊깁니다
const { n } = state;                // 그냥 숫자 복사본
n++;                                // 화면 안 바뀜

// ✓ 꺼내 쓰려면
import { toRefs } from "vue";
const { n } = toRefs(state);        // n 은 ref 가 됨

// ✗ 원시값은 못 담습니다
const bad = reactive(0);            // 경고
권장 — ref 로 통일하세요. .value 를 붙이는 게 번거로워 보여도 "이건 반응형 값"이라는 표시가 되고, 위의 함정을 전부 피할 수 있습니다.
Vue 디버깅의 절반은 이 질문입니다 — "지금 내 손에 있는 것이 상자인가, 꺼낸 값인가?"
VUE 03

템플릿 문법

HTML 에 속성 몇 개를 더한 형태입니다.

<template>
  <!-- 값 넣기 -->
  <p>{{ name }}님, {{ count * 2 }}개</p>

  <!-- 속성 바인딩 — : 는 v-bind: 의 줄임 -->
  <img :src="url" :alt="name">
  <button :disabled="loading">저장</button>

  <!-- 이벤트 — @ 는 v-on: 의 줄임 -->
  <button @click="save">저장</button>
  <button @click="count++">증가</button>
  <form @submit.prevent="onSubmit">…</form>   <!-- preventDefault 자동 -->
  <input @keyup.enter="search">

  <!-- 조건 -->
  <p v-if="err">에러</p>
  <p v-else-if="loading">불러오는 중</p>
  <p v-else>완료</p>
  <p v-show="open">자주 껐다 켜는 것</p>  <!-- display 만 토글 -->

  <!-- 반복 — key 필수 -->
  <li v-for="item in items" :key="item.id">{{ item.name }}</li>
  <li v-for="(v, i) in items" :key="v.id">{{ i }} · {{ v.name }}</li>

  <!-- 클래스 · 스타일 -->
  <div :class="{ on: isOn, big: size === 'l' }">…</div>
  <div :class="['card', theme]">…</div>
  <div :style="{ marginTop: gap + 'px' }">…</div>

  <!-- 양방향 -->
  <input v-model="q" placeholder="검색">
  <input v-model.number="age" type="number">
  <input v-model.trim="name">
</template>
헷갈리는 것구분
v-if vs v-showv-if 는 DOM 에서 제거(초기 비용 ↓), v-show 는 숨기기만(토글 비용 ↓)
v-if + v-for 같이쓰지 마세요. <template v-for> 안에 v-if 를 넣거나 미리 걸러 두세요
{{ }} 안식만 가능. if 문·선언은 안 됩니다
VUE 04

computed — 계산된 값

계산 결과를 따로 저장하지 마세요. computed 가 알아서 갱신합니다.

기본

import { ref, computed } from "vue";

const items = ref([{ price: 1000, n: 2 }]);

// 의존하는 값이 바뀔 때만 다시 계산 (그 외엔 캐시)
const total = computed(() =>
  items.value.reduce((s, v) => s + v.price * v.n, 0)
);

const isEmpty = computed(() => items.value.length === 0);

// 쓰기도 가능한 computed
const fullName = computed({
  get: () => `${first.value} ${last.value}`,
  set: (v) => { [first.value, last.value] = v.split(" "); },
});
메서드와의 차이 — 템플릿에서 {{ getTotal() }} 는 매 렌더 다시 계산하지만, computed 는 의존 값이 바뀔 때만 계산합니다.

watch — 값이 바뀔 때 무언가 하기

import { watch, watchEffect } from "vue";

// 특정 값 감시
watch(q, async (nv, ov) => {
  if (!nv) return;
  results.value = await search(nv);
});

// 여러 개 · 즉시 실행 · 깊은 감시
watch([a, b], ([na, nb]) => { … }, { immediate: true });
watch(obj, () => { … }, { deep: true });

// 쓰인 값을 자동으로 추적
watchEffect(() => {
  console.log(`${user.value.name} / ${count.value}`);
});

// 정리 — 요청 취소 등
watch(id, (nv, ov, onCleanup) => {
  const c = new AbortController();
  onCleanup(() => c.abort());
  fetch(`/api/${nv}`, { signal: c.signal });
});
계산으로 될 일에 watch 를 쓰지 마세요. watch(a, () => { b.value = a.value * 2 }) 는 computed 로 한 줄이면 되고 버그도 없습니다. watch 는 바깥 세계에 영향을 줄 때(요청·저장·로그) 씁니다.

실전 조합 — 검색 · 필터 · 페이징은 전부 computed

const rows    = ref([]);        // 원본 (서버에서 받음)
const q       = ref("");        // 검색어
const sortKey = ref("name");
const page    = ref(1);

// 파이프라인처럼 쌓습니다 — 원본은 절대 안 건드립니다
const filtered = computed(() =>
  rows.value.filter((r) => r.name.includes(q.value)));

const sorted = computed(() =>
  [...filtered.value].sort(              // ★ 복사 후 정렬
    (a, b) => String(a[sortKey.value])
      .localeCompare(String(b[sortKey.value]))));

const paged = computed(() =>
  sorted.value.slice((page.value - 1) * 20, page.value * 20));

const pageCount = computed(() =>
  Math.ceil(filtered.value.length / 20));
검색어를 지우면? 아무것도 안 해도 됩니다. 원본이 그대로니 filtered 가 전체로 돌아옵니다 — "필터 풀기" 코드가 존재하지 않는 것이 이 구조의 힘입니다.

computed 에서 하면 안 되는 것

// ✗ 부수 효과 — computed 는 '계산'만
const total = computed(() => {
  saveToServer(items.value);        // 절대 금지
  return items.value.length;
});

// ✗ 안에서 다른 상태 변경
const bad = computed(() => {
  page.value = 1;                   // 무한 루프의 씨앗
  return filtered.value;
});

// ✓ "검색어가 바뀌면 1페이지로" 는 watch 의 일
watch(q, () => { page.value = 1; });

// ✗ 정렬이 원본을 바꿈 — sort 는 제자리 연산!
const sorted = computed(() => rows.value.sort(…));  // 원본 오염
// ✓ [...rows.value].sort(…) 로 복사 후에
computed 는 "언제 몇 번 실행될지 보장이 없습니다." 그래서 실행 횟수에 의존하는 코드(카운트 증가·API 호출)를 넣으면 예측 불가능한 버그가 됩니다. 순수 계산만 두세요.
VUE 05

props 와 emit

데이터는 아래로, 사건은 위로 흐릅니다.

자식

<script setup>
// 타입과 기본값
const props = defineProps({
  title: { type: String, required: true },
  tone:  { type: String, default: "info" },
  items: { type: Array, default: () => [] },   // ★ 함수로
});

const emit = defineEmits(["close", "pick"]);

function onPick(id){
  emit("pick", id);          // 부모에게 알림
}
</script>

<template>
  <h3>{{ title }}</h3>
  <button @click="emit('close')">닫기</button>
</template>
props 를 직접 바꾸면 경고가 납니다. 바꿔야 하면 emit 으로 부모에게 알리거나, 초기값으로만 쓸 거면 ref(props.x) 로 복사하세요.

부모 · TypeScript

<template>
  <Panel
    title="공지"
    :items="rows"
    @close="open = false"
    @pick="onPick"
  />
</template>
// TS 라면 타입으로 선언하는 편이 깔끔합니다
const props = withDefaults(defineProps<{
  title: string;
  tone?: "info" | "warn";
  items?: string[];
}>(), { tone: "info", items: () => [] });

const emit = defineEmits<{
  close: [];
  pick: [id: number];
}>();
자식은 값을 바꾸지 않고 "바꿔 달라고 올려보냅니다" — 이 규칙 하나가 컴포넌트 수십 개짜리 앱의 질서를 지킵니다.
VUE 06

v-model 직접 만들기

입력 컴포넌트를 만들면 부모가 v-model 로 쓸 수 있게 하세요.

<!-- 자식: MoneyInput.vue (Vue 3.4+) -->
<script setup>
const model = defineModel({ type: Number, default: 0 });
// 읽고 쓰면 부모의 값이 함께 바뀝니다
</script>

<template>
  <input
    :value="model"
    @input="model = Number($event.target.value)"
    inputmode="numeric"
  >
  <button @click="model = 0">비우기</button>
</template>
<!-- 부모 -->
<MoneyInput v-model="price" />

<!-- 이름 붙은 모델 여러 개 -->
<Range v-model:min="from" v-model:max="to" />
v-model 은 사실 :modelValue + @update:modelValue 의 줄임입니다. defineModel() 이 그 두 개를 한 줄로 만들어 줍니다 — 예전의 장황한 props/emit 짝은 이제 필요 없습니다.

실전 — 검증까지 품은 입력 컴포넌트

<!-- LabeledInput.vue — 폼마다 반복되는 것을 전부 흡수 -->
<script setup>
const model = defineModel({ type: String, default: "" });
const props = defineProps({
  label: String,
  error: String,          // 부모가 검증 결과를 내려준다
  required: Boolean,
});
const id = `f-${Math.random().toString(36).slice(2, 8)}`;
</script>

<template>
  <div class="field">
    <label :for="id">{{ label }}
      <em v-if="required">*</em></label>
    <input :id="id" v-model="model"
           :aria-invalid="!!error" v-bind="$attrs">
    <p v-if="error" class="err" role="alert">{{ error }}</p>
  </div>
</template>
<!-- 부모 — 폼이 짧아집니다 -->
<LabeledInput v-model="form.email" label="이메일"
              type="email" required :error="errors.email" />
<LabeledInput v-model="form.name" label="이름" required />

수식어와 폼 요소별 v-model

<!-- 내장 수식어 -->
<input v-model.lazy="q">     <!-- input 대신 change 때 반영 -->
<input v-model.number="n">   <!-- 숫자로 형변환 -->
<input v-model.trim="s">     <!-- 앞뒤 공백 제거 -->

<!-- 체크박스 여러 개 → 배열 -->
<label v-for="t in tags" :key="t">
  <input type="checkbox" :value="t" v-model="picked"> {{ t }}
</label>

<!-- 라디오 · 셀렉트 -->
<input type="radio" value="s" v-model="size"> Small
<select v-model="city">
  <option disabled value="">도시 선택</option>
  <option v-for="c in cities" :key="c" :value="c">{{ c }}</option>
</select>
검증 로직 자체는 부모(또는 컴포저블)에 두세요. 입력 컴포넌트는 표시만 맡아야 어느 폼에서든 재사용됩니다. 규모가 커지면 VeeValidate + zod 조합이 실무 표준입니다.
VUE 07

slot — 구멍 뚫어 두기

컴포넌트 안에 부모가 내용을 끼워 넣는 자리입니다.

기본 · 이름 있는 슬롯

<!-- Card.vue -->
<template>
  <div class="card">
    <header><slot name="head">기본 제목</slot></header>
    <div><slot /></div>               <!-- 이름 없는 기본 슬롯 -->
    <footer><slot name="foot" /></footer>
  </div>
</template>
<!-- 사용 -->
<Card>
  <template #head><h3>공지</h3></template>
  <p>본문입니다</p>
  <template #foot><button>확인</button></template>
</Card>

스코프 슬롯 — 자식의 값을 넘겨준다

<!-- List.vue : 반복은 내가, 생김새는 네가 -->
<template>
  <ul>
    <li v-for="(item, i) in items" :key="item.id">
      <slot :item="item" :index="i" />
    </li>
  </ul>
</template>
<List :items="rows">
  <template #default="{ item, index }">
    <b>{{ index + 1 }}.</b> {{ item.name }}
  </template>
</List>
표·목록 컴포넌트의 핵심 기법입니다. 데이터 처리·페이징은 컴포넌트가 맡고 각 칸을 어떻게 그릴지는 쓰는 쪽이 정합니다.

props 로 줄 것 vs 슬롯으로 뚫을 것

신호선택
넘기는 것이 데이터다 (문자열·숫자·배열)props — title="공지"
넘기는 것이 마크업이다 (아이콘+굵은 글씨+링크)슬롯 — props 로 HTML 문자열을 넘기기 시작하면 신호입니다
모양 종류가 몇 가지로 정해져 있다variant props — 쓰는 쪽 자유도를 일부러 줄입니다
"내용은 뭐가 올지 모른다" (모달 본문 · 카드 내용)기본 슬롯
자식이 가진 데이터로 부모가 그려야 한다스코프 슬롯 — 표의 셀 렌더링
<!-- 판단 예 — 버튼 안에 아이콘을 넣고 싶다 -->
<!-- ✗ props 가 늘어나는 길: icon · iconPos · iconSize … -->
<BaseButton icon="save" icon-pos="left" label="저장" />

<!-- ✓ 슬롯이면 끝: 내용은 쓰는 쪽 마음 -->
<BaseButton><SaveIcon /> 저장</BaseButton>
망설여지면 슬롯이 안전합니다 — props 는 나중에 추가할 수 있지만, props 로 굳은 API 를 슬롯으로 바꾸는 것은 쓰는 곳 전부를 고치는 일입니다.
VUE 08

생명주기와 DOM 접근

DOM 이 준비된 시점을 알아야 바깥 라이브러리를 붙일 수 있습니다.

<script setup>
import { ref, onMounted, onUnmounted, nextTick } from "vue";

// 템플릿의 ref="box" 와 이름이 같으면 연결됩니다
const box = ref(null);
const chart = ref(null);

onMounted(() => {
  chart.value = new Chart(box.value, options);   // 화면에 붙은 뒤
  addEventListener("resize", onResize);
});

onUnmounted(() => {                              // ★ 반드시 정리
  chart.value?.destroy();
  removeEventListener("resize", onResize);
});

// 값 변경이 화면에 반영된 뒤에 무언가 해야 할 때
async function addAndScroll(){
  items.value.push(newItem);
  await nextTick();                              // DOM 갱신 대기
  box.value.scrollTop = box.value.scrollHeight;
}
</script>

<template>
  <div ref="box">…</div>
</template>
훅시점
onMountedDOM 에 붙은 직후. DOM 접근·라이브러리 초기화
onUnmounted사라질 때. 타이머·구독·인스턴스 정리
onUpdated다시 그려진 뒤 (자주 쓸 일 없음)
nextTick()지금 바꾼 값이 화면에 반영된 뒤
정리를 빠뜨리면 페이지를 옮겨도 타이머가 돌고 차트 인스턴스가 남아 메모리를 계속 먹습니다. onMounted 를 적을 때 onUnmounted 를 같이 적는 습관을 들이세요.
생명주기를 외울 필요는 없습니다 — "DOM 은 mounted 부터, 정리는 unmounted 에서" 두 가지면 실무의 90%입니다.
VUE 09

컴포저블 — 로직 재사용

리액트의 커스텀 훅에 해당합니다. 규칙이 더 느슨해서 편합니다.

// composables/useFetch.js
import { ref, watchEffect, onUnmounted } from "vue";

export function useFetch(urlRef){
  const data = ref(null);
  const error = ref(null);
  const loading = ref(false);
  let ctrl;

  watchEffect(async () => {
    const url = typeof urlRef === "function" ? urlRef() : urlRef.value;
    if (!url) return;

    ctrl?.abort();
    ctrl = new AbortController();
    loading.value = true; error.value = null;

    try{
      const r = await fetch(url, { signal: ctrl.signal });
      if (!r.ok) throw new Error(`HTTP ${r.status}`);
      data.value = await r.json();
    }catch(e){
      if (e.name !== "AbortError") error.value = e;
    }finally{
      loading.value = false;
    }
  });

  onUnmounted(() => ctrl?.abort());
  return { data, error, loading };
}
<script setup>
const id = ref(1);
const { data, loading } = useFetch(() => `/api/user/${id.value}`);
// id 가 바뀌면 자동으로 다시 부르고 이전 요청은 취소됩니다
</script>
리액트 훅과 다른 점 — 조건문·반복문 안에서 불러도 되고 호출 순서도 상관없습니다. <script setup> 이 한 번만 실행되기 때문입니다. 다만 onMounted 같은 생명주기 훅은 setup 실행 중에 등록해야 합니다.

// composables/useStorage.js
import { ref, watch } from "vue";

export function useStorage(key, init){
  const v = ref(init);
  try {
    const saved = localStorage.getItem(key);
    if (saved !== null) v.value = JSON.parse(saved);
  } catch {}

  watch(v, (nv) => {
    try { localStorage.setItem(key, JSON.stringify(nv)); }
    catch {}
  }, { deep: true });     // 객체 내부 변경까지

  return v;
}

Pinia — 전역 상태

여러 화면이 같은 데이터를 봐야 할 때 씁니다.

스토어 정의

// stores/cart.js
import { defineStore } from "pinia";
import { ref, computed } from "vue";

export const useCart = defineStore("cart", () => {
  const items = ref([]);                               // state

  const count = computed(() =>                          // getter
    items.value.reduce((s, v) => s + v.n, 0));
  const total = computed(() =>
    items.value.reduce((s, v) => s + v.price * v.n, 0));

  function add(p){                                      // action
    const hit = items.value.find((v) => v.id === p.id);
    if (hit) hit.n++;
    else items.value.push({ ...p, n: 1 });
  }
  function clear(){ items.value = []; }

  return { items, count, total, add, clear };
});

사용

자주 하는 실수 모음

증상원인
값을 바꿔도 화면이 그대로JS 에서 .value 를 빠뜨림 (count++ ✗ → count.value++)
구조 분해했더니 반응성 끊김toRefs·storeToRefs 를 쓰세요
화면에 [object Object]객체를 그대로 출력. 속성을 꺼내거나 JSON.stringify
목록 순서 바꾸면 입력값이 섞임:key 를 index 로 줌 → 고유 id 로
props 를 바꾸면 경고자식은 못 바꿉니다. emit 으로 부모에게
ref 가 nullonMounted 이전에 접근. DOM 이 아직 없습니다
값 바꾸고 바로 DOM 을 읽었더니 이전 값await nextTick() 후에 읽으세요
모달이 다른 요소에 가림조상의 transform·overflow. <Teleport to="body">
v-if 와 v-for 를 같이 썼더니 이상우선순위 문제. <template v-for> 로 감싸세요
watch 가 안 걸림객체 내부 변경은 { deep: true } 필요
도구 — Vue DevTools 로 컴포넌트 트리·상태·Pinia 스토어를 직접 볼 수 있습니다. "값이 진짜 바뀌었는가"를 추측하지 말고 여기서 확인하세요.
