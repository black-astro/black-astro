EDGE 01

왜 다시 경량인가 — Express 가 못 가는 자리

Express 가 나쁜 게 아닙니다. Express 가 서 있는 땅이 Node 하나뿐이라는 것이 문제입니다. 2026년의 배포 자리는 컨테이너 말고도 다섯 군데가 더 생겼고, 그 다섯 곳에는 node:http 가 없습니다.

문제는 성능이 아니라 이식성입니다 — 코드가 갈 수 있는 자리의 개수가 다릅니다.

Express 의 req·res 는 무엇인가

// Express 핸들러의 진짜 정체
import type { IncomingMessage, ServerResponse } from "node:http";

app.get("/hi", (req, res) => {
  //  req 는 node:http 의 IncomingMessage 를 확장한 것
  //  res 는 node:http 의 ServerResponse 를 확장한 것
  //  → 둘 다 Node 런타임이 있어야만 존재합니다
  req.socket.remoteAddress;      // TCP 소켓을 직접 만짐
  res.writeHead(200);            // 헤더를 스트림에 밀어 넣는 방식
  res.end("hi");
});

//  Cloudflare Workers 에 그대로 올리면
//  Error: Could not resolve "node:http"
//  또는 실행 중 TypeError: res.writeHead is not a function
“nodejs_compat 를 켜면 되지 않나요” — Workers 에도 Node 호환 층이 있지만 node:http 의 서버 부분은 대상이 아닙니다. 아이솔레이트는 포트를 열어 소켓을 받는 구조가 아니기 때문입니다. 요청은 플랫폼이 이미 받아서 객체 하나로 넘겨 줍니다.

Web 표준 모델 — 함수 하나가 전부

// 브라우저의 fetch 가 쓰던 그 Request · Response 입니다
export default {
  async fetch(request: Request): Promise<Response> {
    const url = new URL(request.url);              // 표준 URL
    if (url.pathname === "/hi") {
      return new Response(JSON.stringify({ ok: true }), {
        headers: { "content-type": "application/json" },
      });
    }
    return new Response("not found", { status: 404 });
  },
};

//  ★ 핵심 — "요청 객체를 받아 응답 객체를 돌려주는 순수 함수"
//     소켓도, 스트림 쓰기도, next() 도 없습니다.
//     그래서 어느 런타임이든 이 모양만 지원하면 코드가 돕니다.
이미 알고 있는 API 입니다 — 브라우저에서 fetch() 를 쓸 때 받았던 그 Response 이고, res.json() 이 아니라 await request.json() 입니다. 클라이언트에서 쓰던 지식이 서버로 그대로 옵니다.

EDGE 02

Hono 시작 — Express 를 아는 사람이 가장 빨리 배웁니다

개념이 새로 생기지 않습니다. app · 라우트 · 미들웨어 세 가지가 그대로 있고, (req, res, next) 가 (c, next) 하나로 합쳐졌을 뿐입니다. 다른 점은 딱 하나 — res.json() 이 아니라 return c.json() 입니다.

“그럼 아무 코드나 다 옮겨지나요” — 아닙니다. Hono 는 옮겨지지만 내가 부른 라이브러리는 아닐 수 있습니다. fs·path·crypto(Node 판)·네이티브 모듈을 쓰는 순간 그 코드는 Node 에 묶입니다. 이식성은 Hono 가 아니라 내 의존성이 결정합니다(g08).
Express 를 당장 걷어낼 필요는 없습니다. Hono 는 @hono/node-server 로 Node 위에서도 잘 돌기 때문에 새 엔드포인트만 Hono 로 짜서 기존 Express 앱 옆에 리버스 프록시로 붙여 두는 방식이 가장 안전합니다. 옮길 준비가 되면 그 조각들만 Workers 로 올리면 됩니다.
정리 — Hono 는 Express 의 개념을 그대로 쓰되 문법만 표준으로 바꾼 것입니다. 외울 것은 c.req.param · c.req.query · await c.req.json() · return c.json() 네 개이고, 나머지는 Express 지식이 그대로 통합니다. 다만 return 을 빼면 404 가 나간다는 것만 기억하세요.
EDGE 03

미들웨어 · 타입 — 양파 구조와 c.set

Express 미들웨어는 줄 서서 통과하는 관문이었습니다. Hono 미들웨어는 양파입니다 — await next() 앞이 내려가는 길, 뒤가 올라오는 길입니다. 이 한 줄 덕분에 응답을 만진 뒤의 처리가 훨씬 자연스러워집니다.

Express 의 res.on("finish") 로 하던 일이 await next() 다음 줄이 됩니다.

커스텀 미들웨어 — createMiddleware

import { createMiddleware } from "hono/factory";
import { HTTPException } from "hono/http-exception";

// ① 인증 — 타입이 붙은 미들웨어
export const requireAuth = createMiddleware<{
  Variables: { user: User };
  Bindings: { JWT_SECRET: string };
}>(async (c, next) => {
  const raw = c.req.header("authorization")?.slice(7);
  if (!raw) throw new HTTPException(401, { message: "인증이 필요합니다" });
  try {
    c.set("user", await verifyJwt(raw, c.env.JWT_SECRET));
  } catch {
    throw new HTTPException(401, { message: "토큰이 유효하지 않습니다" });
  }
  await next();                       // ★ 잊지 마세요
});

// ② 권한 — 인자를 받는 미들웨어는 "함수를 반환"
export const requireRole = (...roles: string[]) =>
  createMiddleware<{ Variables: { user: User } }>(async (c, next) => {
    if (!roles.includes(c.get("user").role))
      throw new HTTPException(403, { message: "권한이 없습니다" });
    await next();
  });

// ③ 응답을 만지는 미들웨어 — await next() '뒤'가 진짜 무대
export const serverTiming = createMiddleware(async (c, next) => {
  const t0 = Date.now();
  await next();
  c.res.headers.set("server-timing", `app;dur=${Date.now() - t0}`);
  // ★ c.res 는 여기서 이미 만들어진 Response 입니다
});

app.get("/admin/x", requireAuth, requireRole("admin"), handler);
c.res 를 통째로 갈아 끼울 때는 주의하세요. c.res = new Response(...) 처럼 바꾸면 먼저 붙은 헤더가 전부 날아갑니다. 헤더만 고칠 거라면 c.res.headers.set(...) 을 쓰세요.

EDGE 04

검증 · RPC · OpenAPI — 타입을 프런트까지

Express + Zod 로도 서버 안쪽은 타입이 맞았습니다. 하지만 프런트가 부를 때는 주소 문자열과 as 캐스팅으로 돌아갔습니다. Hono 는 라우트 정의 그 자체를 타입으로 내보내 그 마지막 구멍을 막습니다.

“API 주소를 문자열로 적고 응답을 as 로 캐스팅하던 자리”가 통째로 사라집니다.

Bun — 런타임 하나가 도구 다섯을 대신합니다

Bun 은 “빠른 Node” 가 아니라 Node + 패키지 매니저 + 테스트 러너 + 번들러 + 파일 감시기 를 실행 파일 하나에 합친 물건입니다. 엔진도 V8 이 아니라 JavaScriptCore(사파리의 엔진)입니다. 그래서 “빨라졌다”보다 “설치할 게 없어졌다”가 체감이 큽니다.

Deno 2 — 기본값이 “아무것도 못 함”

Node 는 node a.js 를 치는 순간 그 스크립트가 내 홈 디렉터리를 읽고 어디로든 전송할 수 있었습니다. Deno 는 문을 하나씩 열어 줘야 움직입니다. 그리고 2 부터는 npm: 지정자로 기존 패키지를 거의 그대로 쓸 수 있습니다.

보안 기능이라기보다 “이 프로그램이 무엇을 하는지 실행 명령만 봐도 안다”는 설계입니다.

설치와 권한 플래그

엣지의 제약과 설계 — 잃은 것을 어떻게 메우나

엣지에 올리자마자 겪는 문제는 대개 셋입니다 — 파일이 없다 · DB 에 못 붙는다 · 서버는 가까운데 응답이 더 느리다. 셋 다 원인이 분명하고 해법도 정해져 있습니다.

엣지의 이득은 사용자와의 거리에서 나오고, 손해는 데이터와의 거리에서 납니다.

① 실행 시간 — “CPU 시간”이 기준입니다

흔한 오해 : "10초 제한이면 DB 가 3초 걸리는 쿼리는 못 쓰겠네"
사실       : 제한은 대개 'CPU 를 실제로 쓴 시간' 입니다.
             fetch · DB 응답을 기다리는 동안은 CPU 를 안 씁니다.

  ┌─ 요청 시작
  │  0.4ms   요청 파싱 · 라우팅          ← CPU 사용
  │  3200ms  DB 응답 대기               ← CPU 안 씀 (계산 안 됨)
  │  1.1ms   JSON 만들기                ← CPU 사용
  └─ 응답            CPU 합계 1.5ms

★ 그래서 걸리는 것은 '오래 기다리는 작업'이 아니라
  '오래 계산하는 작업' 입니다.
    · 큰 JSON 파싱 · 정렬 · 암호화 반복
    · 이미지 리사이즈 · PDF 렌더
    · 수만 건 루프 돌며 집계
  → 이런 것은 Queue 로 넘기거나 컨테이너 서비스로 분리하세요.
메모리도 함께 봅니다. 아이솔레이트는 보통 128MB 기준입니다. await res.arrayBuffer() 로 큰 파일을 통째로 올리면 바로 넘칩니다. 스트리밍으로 흘려보내는 습관이 필수입니다(g10).

import { streamSSE } from "hono/streaming";

app.get("/jobs/:id/events", async (c) => {
  return streamSSE(c, async (stream) => {
    // 연결이 끊기면 알려 줍니다 (Express 의 req.on("close") 자리)
    let closed = false;
    stream.onAbort(() => { closed = true; });

    for (let p = 0; p <= 100 && !closed; p += 5) {
      await stream.writeSSE({
        event: "progress",
        id: String(Date.now()),          // 재연결 시 이어받기용
        data: JSON.stringify({ percent: p }),
      });
      await stream.sleep(300);
    }
    await stream.writeSSE({ event: "done", data: "ok" });
  });
});

export class Room implements DurableObject {
  constructor(private state: DurableObjectState, private env: Env) {}

  async fetch(req: Request) {
    const pair = new WebSocketPair();
    const [client, server] = Object.values(pair);

    // ★ 하이버네이션 — 메시지가 없는 동안 메모리에서 내려갑니다 (요금 절약)

    for (const peer of this.state.getWebSockets()) peer.send(msg);   // 방 전체에
  }

}

  if (err instanceof HTTPException) return err.getResponse();

  const sentry = new Toucan({
    dsn: c.env.SENTRY_DSN,

  id:    text("id").primaryKey(),

});

export const links = sqliteTable("links", {
  code:   text("code").primaryKey(),           // abc123
  url:    text("url").notNull(),
  userId: text("user_id").notNull().references(() => users.id),
  clicks: integer("clicks").notNull().default(0),
  createdAt: integer("created_at", { mode: "timestamp" })
             .notNull().default(sql`(unixepoch())`),
}, (t) => [ index("links_user_idx").on(t.userId) ]);

export const events = sqliteTable("events", {
  id:      integer("id").primaryKey({ autoIncrement: true }),
  code:    text("code").notNull(),
  ts:      integer("ts").notNull(),
  country: text("country"),
  colo:    text("colo"),                        // 어느 도시에서 처리했나
  referer: text("referer"),
}, (t) => [ index("events_code_ts").on(t.code, t.ts) ]);

// src/lib/auth.ts
import { sign, verify } from "hono/jwt";            // ★ 라이브러리 설치 불필요
import { createMiddleware } from "hono/factory";
import { HTTPException } from "hono/http-exception";
import type { Ctx } from "../env";

export const issue = (secret: string, u: { id: string; email: string }) =>
  sign({ sub: u.id, email: u.email,
         exp: Math.floor(Date.now() / 1000) + 60 * 60 * 24 * 7 }, secret);

export const requireAuth = createMiddleware<Ctx>(async (c, next) => {
  const raw = c.req.header("authorization")?.replace(/^Bearer /, "");
  if (!raw) throw new HTTPException(401, { message: "인증이 필요합니다" });
  try {
    const p = await verify(raw, c.env.JWT_SECRET);
    c.set("user", { id: String(p.sub), email: String(p.email) });
  } catch {
    throw new HTTPException(401, { message: "토큰이 유효하지 않습니다" });
  }
  await next();
});

// 비밀번호 해시 — bcrypt 없이 WebCrypto 로 (PBKDF2)
export async function hashPw(pw: string, saltHex?: string) {
  const salt = saltHex ? hexToBytes(saltHex) : crypto.getRandomValues(new Uint8Array(16));
  const key = await crypto.subtle.importKey("raw", new TextEncoder().encode(pw),
                                            "PBKDF2", false, ["deriveBits"]);
  const bits = await crypto.subtle.deriveBits(
    { name: "PBKDF2", salt, iterations: 100_000, hash: "SHA-256" }, key, 256);
  return `${toHex(salt)}:${toHex(new Uint8Array(bits))}`;
}
왜 bcrypt 를 안 쓰나 — bcrypt 는 네이티브 모듈이라 아이솔레이트에 안 올라갑니다. 엣지에서는 WebCrypto 의 PBKDF2 를 쓰거나 인증 자체를 외부 서비스(Auth0·Clerk·Supabase Auth)에 맡깁니다. 반복 횟수를 너무 올리면 CPU 시간 상한에 걸리니 주의하세요(g08).

링크 생성 — 검증 + RPC 체이닝

// src/routes/links.ts
import { Hono } from "hono";
import { zValidator } from "@hono/zod-validator";
import { z } from "zod";
import { drizzle } from "drizzle-orm/d1";
import { eq, and, desc } from "drizzle-orm";
import { links } from "../db/schema";
import { requireAuth } from "../lib/auth";
import { newCode } from "../lib/id";
import type { Ctx } from "../env";

const CreateLink = z.object({
  url: z.url("주소 형식이 아닙니다").max(2048),
  code: z.string().regex(/^[a-z0-9_-]{3,32}$/i).optional(),   // 직접 지정도 허용
});

// ★ 체이닝을 끊지 않습니다 — RPC 타입이 여기서 만들어집니다
const route = new Hono<Ctx>()
  .use(requireAuth)
  .post("/", zValidator("json", CreateLink), async (c) => {
    const { url, code } = c.req.valid("json");
    const db = drizzle(c.env.DB);
    const key = code ?? newCode();               // 7자 무작위

    try {
      await db.insert(links)
              .values({ code: key, url, userId: c.get("user").id });
    } catch {
      return c.json({ code: "DUPLICATE", message: "이미 쓰는 코드입니다" }, 409);
    }
    // ★ 만들자마자 캐시에 넣어 둡니다 — 첫 클릭도 빠릅니다
    c.executionCtx.waitUntil(c.env.KV.put(`l:${key}`, url, { expirationTtl: 86400 }));

    return c.json({ code: key, url, short: `https://s.example.com/${key}` }, 201);
  })
  .get("/", async (c) => {
    const db = drizzle(c.env.DB);
    const rows = await db.select().from(links)
      .where(eq(links.userId, c.get("user").id))
      .orderBy(desc(links.createdAt)).limit(50);
    return c.json({ items: rows });
  })
  .delete("/:code", async (c) => {
    const db = drizzle(c.env.DB);
    const key = c.req.param("code");
    const r = await db.delete(links)
      .where(and(eq(links.code, key), eq(links.userId, c.get("user").id)));
    await c.env.KV.delete(`l:${key}`);           // ★ 캐시 무효화를 같은 함수 안에
    return c.body(null, 204);
  });

export default route;

리다이렉트 — 이 파일이 전부의 핵심입니다

// src/routes/go.ts
import { Hono } from "hono";
import { drizzle } from "drizzle-orm/d1";
import { eq, sql } from "drizzle-orm";
import { links, events } from "../db/schema";
import type { Ctx } from "../env";

const go = new Hono<Ctx>().get("/:code", async (c) => {
  const key = c.req.param("code");

  // ① KV 먼저 — 대부분 여기서 끝납니다 (1~5ms)
  let url = await c.env.KV.get(`l:${key}`);

  // ② 없으면 D1 에서 찾고, 찾으면 KV 를 채웁니다
  if (!url) {
    const db = drizzle(c.env.DB);
    const row = await db.select({ url: links.url }).from(links)
                        .where(eq(links.code, key)).get();
    if (!row) return c.notFound();
    url = row.url;
    c.executionCtx.waitUntil(
      c.env.KV.put(`l:${key}`, url, { expirationTtl: 86400 }),
    );
  }

  // ③ 클릭 기록은 응답을 막지 않습니다 ★ 이게 이 프로젝트의 핵심입니다
  const cf = (c.req.raw as any).cf ?? {};
  c.executionCtx.waitUntil(
    c.env.DB.batch([
      c.env.DB.prepare("UPDATE links SET clicks = clicks + 1 WHERE code = ?1")
              .bind(key),
      c.env.DB.prepare(
        `INSERT INTO events (code, ts, country, colo, referer)
         VALUES (?1, ?2, ?3, ?4, ?5)`)
        .bind(key, Date.now(), cf.country ?? null, cf.colo ?? null,
              c.req.header("referer") ?? null),
    ]),
  );

  // ④ 즉시 넘겨줍니다. 캐시는 짧게 (링크가 바뀔 수 있으므로)
  return c.redirect(url, 302);
});

export default go;
waitUntil 을 빼면 통계가 조용히 사라집니다. c.redirect() 를 반환하는 순간 응답이 나가고, 아이솔레이트는 정리 대상이 됩니다. Express 였다면 res.redirect() 뒤의 await insert() 가 그냥 실행됐지만 여기서는 아닙니다.

// src/routes/stats.ts — 날짜별·나라별 집계
const stats = new Hono<Ctx>()
  .use(requireAuth)
  .get("/:code", async (c) => {
    const key = c.req.param("code");
    const since = Date.now() - 7 * 864e5;

    // ★ 왕복을 한 번으로 — 두 집계를 batch 로 함께 보냅니다
    const [byDay, byCountry] = await c.env.DB.batch([
      c.env.DB.prepare(
        `SELECT date(ts/1000,'unixepoch') d, count(*) n FROM events
          WHERE code = ?1 AND ts > ?2 GROUP BY d ORDER BY d`).bind(key, since),
      c.env.DB.prepare(
        `SELECT country, count(*) n FROM events
          WHERE code = ?1 AND ts > ?2 GROUP BY country
          ORDER BY n DESC LIMIT 10`).bind(key, since),
    ]);

    return c.json({ byDay: byDay.results, byCountry: byCountry.results });
  });

이 프로젝트가 엣지에 잘 맞는 이유 — ① 요청 하나에 DB 왕복이 0~1번(대부분 KV 히트), ② 계산이 거의 없음(문자열 조회와 리다이렉트), ③ 사용자가 전 세계에 흩어져 있음. g01 의 세 질문에 전부 “엣지”가 나오는 형태입니다.
반대로 안 맞는 예 — 같은 구조라도 PDF 를 만들어 주는 API 라면 CPU 시간 때문에 엣지가 불리하고, 주문·결제처럼 대화형 트랜잭션이 필요한 서비스라면 DB 옆 컨테이너가 훨씬 단순합니다. “엣지가 낫다”가 아니라 “이 워크로드가 엣지에 맞는다”로 판단하세요.
정리 — 이 프로젝트 하나에 이 탭의 전부가 들어 있습니다. Hono 라우팅 · Zod 검증 · JWT · Drizzle + D1 · KV 캐시 · waitUntil · RPC 타입 공유 · Workers 배포. 특히 기억할 두 줄은 “캐시 무효화는 쓰기와 같은 함수 안에” 와 “응답 뒤 작업은 waitUntil 에” 입니다 — 엣지에서 가장 자주 나는 사고 두 가지입니다.
