Core Web Vitals — 재고 나서 고친다

"느리다"는 제보는 고칠 수 없습니다. 어느 페이지의 어떤 지표가, 몇 번째 백분위에서, 얼마인지가 있어야 고칩니다. 구글이 정한 세 지표 — LCP · INP · CLS — 가 그 공용어이고, 검색 순위에도 반영됩니다.

세 지표 모두 75번째 백분위(p75)로 판정합니다 — 평균은 느린 사용자를 숨깁니다.

세 지표를 한 줄씩

지표무엇을 재나합격선 (p75)
LCP화면에서 가장 큰 이미지·글 덩어리가 그려진 시각. "다 떴다"의 체감≤ 2.5 s
INP클릭·키 입력 후 다음 프레임이 그려지기까지. 방문 중 가장 나쁜 쪽에 가까운 값을 씁니다≤ 200 ms
CLS사용자가 안 건드렸는데 요소가 밀린 정도의 합(가장 나쁜 5초 창)≤ 0.1
TTFB보조 지표 — 서버가 첫 바이트를 줄 때까지. LCP 의 바닥≤ 0.8 s 권장
FID 는 끝났습니다 — 2024년 3월부터 INP 가 FID 를 대체했습니다. FID 는 첫 입력의 대기 시간만 쟀기 때문에 "처음엔 빠른데 쓰다 보면 버벅이는" 화면을 못 잡았습니다. 오래된 블로그 글의 FID 처방은 건너뛰세요.

랩 점수와 필드 값은 다른 물건입니다

랩 (Lighthouse · DevTools)필드 (실사용자)
어디서내 PC, 정해진 조건방문자 기기 전부
INP못 잽니다 (아무도 클릭 안 함) → TBT 로 대신잽니다
쓰임고친 뒤 재현·비교문제가 있는지 판정
출처DevTools Performance · PageSpeedCrUX(구글 수집) · 내 RUM
신입이 가장 많이 하는 실수 — Lighthouse 를 100점으로 만들고 "끝났다"고 보고하는 것. 사용자 대부분은 중저가 안드로이드 + 4G입니다. DevTools 에서 CPU 4배 감속 + Fast 4G 를 켜고 보는 습관을 들이고, 판정은 반드시 필드 p75 로 하세요.

현장 수집 — web-vitals 로 실사용자 값을 모은다 🟡 중급

수집 코드 — 앱 진입점에서 한 번

// src/vitals.ts   npm i web-vitals   (v5 기준)
import type { Metric } from "web-vitals";
import { onCLS, onINP, onLCP, onTTFB } from "web-vitals/attribution";

type Row = {
  name: Metric["name"]; value: number; rating: Metric["rating"];
  id: string; page: string; target?: string;
};
const queue: Row[] = [];
const SAMPLE = Math.random() < 0.2;          // ★ 20% 표본 — 트래픽 많으면 줄이기

function push(m: Metric, target?: string) {
  if (!SAMPLE) return;
  queue.push({
    name: m.name, value: m.value, rating: m.rating, id: m.id,
    page: location.pathname,                   // 쿼리스트링은 빼기(개인정보)
    target,                                    // "어느 요소 때문에"의 단서
  });
}

// attribution 빌드는 원인 정보까지 줍니다 (조금 더 큼)
onLCP((m) => push(m, m.attribution.target));          // v4 까지는 element
onINP((m) => push(m, m.attribution.interactionTarget));
onCLS((m) => push(m, m.attribution.largestShiftTarget));
onTTFB((m) => push(m));

function flush() {
  if (queue.length === 0) return;
  const blob = new Blob([JSON.stringify(queue.splice(0))],
                        { type: "application/json" });
  // 탭을 닫는 순간에도 전송되는 방법
  if (!navigator.sendBeacon("/rum/vitals", blob)) {
    void fetch("/rum/vitals", { method: "POST", body: blob, keepalive: true });
  }
}
// unload 가 아니라 visibilitychange — 모바일은 unload 가 안 올 때가 많습니다
addEventListener("visibilitychange", () => {
  if (document.visibilityState === "hidden") flush();
});
같은 출처로 보내세요 — /rum/vitals 처럼 내 도메인으로 받고 서버가 저장소로 넘깁니다. 다른 도메인에 JSON 비콘을 보내면 CORS 사전 요청이 붙어 닫히는 탭에서 유실됩니다.

모은 값을 읽는 법 — 평균 금지, p75

-- PostgreSQL · 지난 7일, 페이지 × 지표별 p75
SELECT page, name,
       percentile_cont(0.75) WITHIN GROUP (ORDER BY value) AS p75,
       count(*)                                             AS n
FROM   rum_vitals
WHERE  ts > now() - interval '7 days'
GROUP  BY page, name
HAVING count(*) >= 100            -- 표본이 적은 페이지는 판정 보류
ORDER  BY name, p75 DESC;
읽는 순서 (매주 한 번, 10분)
 1. 지표별로 p75 가 '나쁨' 인 페이지부터           ← 우선순위
 2. 그 페이지의 target 상위 3개                     ← 원인 요소
 3. 기기 · 연결 종류로 쪼개 보기 (모바일만 나쁜가?)
 4. 배포일 전후 비교 — 어느 배포에서 꺾였나
 5. 고친 뒤 '필드 값' 이 바뀌는 데 최소 며칠 — 랩으로 먼저 확인
도구를 이미 쓰고 있다면 — Sentry · Datadog RUM · Vercel Speed Insights 같은 서비스가 같은 web-vitals 를 내부에서 씁니다. 둘을 동시에 켜면 값이 두 번 쌓이니 한쪽만 고르세요. 로그 파이프라인 설계는 📝 로깅 탭을 참고하세요.

// 50ms 넘는 작업 하나가 그 사이의 모든 클릭을 막습니다
type Sched = { yield?: () => Promise<void> };
const sched = (globalThis as { scheduler?: Sched }).scheduler;

// Chrome 129+ 는 scheduler.yield, 나머지는 setTimeout 으로 대체
export const yieldToMain = (): Promise<void> =>
  sched?.yield ? sched.yield() : new Promise((r) => setTimeout(r, 0));

export async function applyAll(rows: Row[]) {
  let last = performance.now();
  for (const row of rows) {
    recalc(row);
    if (performance.now() - last > 40) {   // 40ms 마다 한 번 양보
      await yieldToMain();
      last = performance.now();
    }
  }
}

// src/shared/http/error.ts
export type ApiErrorKind = "network" | "timeout" | "aborted" | "http" | "parse";

export class ApiError extends Error {
  readonly kind: ApiErrorKind;
  readonly status?: number;
  readonly code?: string;        // 서버 업무 코드: OUT_OF_STOCK 등
  readonly details?: unknown;    // 필드 에러 등 (PROD 06)

  constructor(kind: ApiErrorKind, message: string,
    init: { status?: number; code?: string; details?: unknown; cause?: unknown } = {}) {
    super(message, { cause: init.cause });
    this.name = "ApiError";
    this.kind = kind;
    this.status = init.status;
    this.code = init.code;
    this.details = init.details;
  }

  get retryable(): boolean {
    if (this.kind === "network" || this.kind === "timeout") return true;
    return this.kind === "http" && (this.status === 429 || (this.status ?? 0) >= 500);
  }
}

export function toApiError(e: unknown): ApiError {
  if (e instanceof ApiError) return e;
  if (e instanceof DOMException && e.name === "TimeoutError")
    return new ApiError("timeout", "응답이 너무 늦습니다", { cause: e });
  if (e instanceof DOMException && e.name === "AbortError")
    return new ApiError("aborted", "요청이 취소되었습니다", { cause: e });
  return new ApiError("network", "네트워크 연결을 확인해 주세요", { cause: e });
}

request() — 타임아웃 · 취소 · 재시도를 한 곳에 🟡 중급

// src/shared/http/request.ts
import { ApiError, toApiError } from "./error";
import { getAccessToken, refreshOnce } from "./auth";

const BASE = import.meta.env.VITE_API_URL ?? "/api";

type SendOpts = Omit<RequestInit, "body" | "signal"> & {
  json?: unknown;            // 객체를 주면 JSON 으로 직렬화
  signal?: AbortSignal;      // 호출한 쪽의 취소 (언마운트 · 새 검색)
  timeoutMs?: number;
};
type Opts = SendOpts & { retries?: number };

export async function request<T>(path: string, opts: Opts = {}): Promise<T> {
  const { retries, ...sendOpts } = opts;
  const method = (opts.method ?? "GET").toUpperCase();
  // ★ 멱등한 요청만 자동 재시도 — POST 를 재시도하면 주문이 두 번 들어갑니다
  const max = retries ?? (method === "GET" ? 2 : 0);

  for (let attempt = 0; ; attempt++) {
    try {
      return await send<T>(path, method, sendOpts, false);
    } catch (e) {
      const err = toApiError(e);
      if (err.kind === "aborted" || !err.retryable || attempt >= max) throw err;
      await sleep(backoff(attempt), opts.signal);
    }
  }
}

async function send<T>(path: string, method: string, opts: SendOpts, afterRefresh: boolean): Promise<T> {
  const { json, signal, timeoutMs = 10_000, headers, ...init } = opts;

  // 타임아웃과 호출자 취소를 하나로 — 어느 쪽이 먼저 와도 fetch 가 멈춥니다
  const signals = [AbortSignal.timeout(timeoutMs)];
  if (signal) signals.push(signal);

  const h = new Headers(headers);
  if (json !== undefined) h.set("Content-Type", "application/json");
  const token = getAccessToken();
  if (token) h.set("Authorization", `Bearer ${token}`);

  const res = await fetch(BASE + path, {
    ...init, method, headers: h,
    body: json === undefined ? undefined : JSON.stringify(json),
    signal: AbortSignal.any(signals),
    credentials: "include",
  });

  if (res.status === 401 && !afterRefresh) {          // 토큰 만료 → 한 번만 재발급 후 재시도
    await refreshOnce();
    return send<T>(path, method, opts, true);
  }
  if (!res.ok) throw await httpError(res);
  if (res.status === 204) return undefined as T;
  try {
    return (await res.json()) as T;
  } catch (e) {
    throw new ApiError("parse", "응답 형식이 올바르지 않습니다", { status: res.status, cause: e });
  }
}

async function httpError(res: Response): Promise<ApiError> {
  // 서버와의 약속: { code, message, details? } — 아니면 상태 코드로 대신합니다
  const body = (await res.json().catch(() => null)) as
    { code?: string; message?: string; details?: unknown } | null;
  return new ApiError("http", body?.message ?? `요청 실패 (${res.status})`,
    { status: res.status, code: body?.code, details: body?.details });
}

// 지수 백오프 + 지터 — 수천 명이 '동시에' 재시도하는 폭주를 흩뜨립니다
const backoff = (n: number) => Math.min(8_000, 500 * 2 ** n) * (0.5 + Math.random() / 2);

function sleep(ms: number, signal?: AbortSignal) {
  return new Promise<void>((resolve, reject) => {
    const t = setTimeout(resolve, ms);
    signal?.addEventListener("abort", () => { clearTimeout(t); reject(signal.reason); }, { once: true });
  });
}
브라우저 지원 — AbortSignal.timeout · AbortSignal.any 는 2024년 이후 주요 브라우저에 모두 들어왔습니다. 아주 오래된 사파리를 지원해야 하면 setTimeout + AbortController 로 직접 묶으세요. 서버가 429 와 함께 Retry-After 를 주면 백오프 대신 그 값을 쓰는 것이 예의입니다.
재발급 큐의 핵심은 진행 중인 Promise 하나를 모두가 공유하는 것 — 변수 하나로 끝납니다.

let refreshing: Promise<void> | null = null;

export function refreshOnce(): Promise<void> {
  // 이미 진행 중이면 그 Promise 를 그대로 돌려줍니다 — 이것이 '큐'
  refreshing ??= (async () => {
    try {
      // refresh 토큰은 HttpOnly 쿠키라 JS 가 볼 수 없고, 볼 필요도 없습니다
      const res = await fetch("/api/auth/refresh", { method: "POST", credentials: "include" });

        setAccessToken(null);
        window.dispatchEvent(new Event("session-expired"));  // 로그인 화면으로 (한 번만)
        throw new ApiError("http", "다시 로그인해 주세요",
          { status: 401, code: "SESSION_EXPIRED" });
      }
      const { accessToken: next } = (await res.json()) as { accessToken: string };
      setAccessToken(next);
    } finally {
      refreshing = null;                        // 다음 만료 때 다시 시작할 수 있게
    }
  })();
  return refreshing;
}

      } catch (e) {
        return { ok: false, message: toApiError(e).message };
      }
    },
    null,
  );

  return (
    <form action={submit}>
      <textarea name="memo" />
      <button disabled={isPending}>{isPending ? "주문 중…" : "주문하기"}</button>
      {state && !state.ok && <p role="alert">{state.message}</p>}
    </form>
  );
}

서버 상태 캐시 — staleTime 을 정하는 법

서버에서 가져온 데이터는 내 것이 아니라 남의 것의 사본입니다. 언제든 낡을 수 있고, 언제 다시 물어볼지를 정해야 합니다. TanStack Query(v5)는 그 결정을 숫자 두 개로 줄여 줍니다. 기본 사용법은 ⚛️ React 탭 a12, 여기서는 값을 정하는 기준입니다.

      retry: (count, err) =>        // 4xx 는 재시도해도 소용없음
        err instanceof ApiError && err.retryable && count < 2,

// src/shared/form/apply-server-errors.ts
import type { FieldValues, Path, UseFormSetError } from "react-hook-form";
import type { ApiError } from "@/shared/http/error";

export function applyServerErrors<T extends FieldValues>(
  err: ApiError,
  setError: UseFormSetError<T>,
  fields: readonly Path<T>[],
) {
  const details = (err.details ?? {}) as Record<string, string[] | undefined>;
  let mapped = 0;
  for (const name of fields) {
    const msg = details[name]?.[0];
    if (!msg) continue;
    // 첫 번째 틀린 칸으로 포커스 — 키보드 · 스크린리더 사용자에게 중요
    setError(name, { type: "server", message: msg }, { shouldFocus: mapped === 0 });
    mapped++;
  }
  // 칸에 붙일 수 없는 에러(500 · 네트워크)는 폼 위 요약으로
  if (mapped === 0) setError("root.server", { type: "server", message: err.message });
}

  const onBeforeUnload = (e: BeforeUnloadEvent) => { e.preventDefault(); };
  addEventListener("beforeunload", onBeforeUnload);
  return () => removeEventListener("beforeunload", onBeforeUnload);
}, [isDirty]);

URL 은 허용 목록으로 · 리다이렉트는 같은 출처로

const ALLOWED = new Set(["http:", "https:", "mailto:", "tel:"]);

export function safeUrl(raw: string): string | undefined {
  try {
    const u = new URL(raw, location.origin);
    return ALLOWED.has(u.protocol) ? u.href : undefined;   // data: · javascript: 탈락
  } catch {
    return undefined;
  }
}
// <a href={safeUrl(user.website)} target="_blank" rel="noopener noreferrer">

// 로그인 후 ?next=… 로 돌려보내기 — '열린 리다이렉트' 방지
export function safeNext(next: string | null): string {
  if (!next) return "/";
  // "/orders" 만 허용. "//evil.com" · "/\evil.com" 은 다른 사이트로 갑니다
  if (!next.startsWith("/") || next.startsWith("//") || next.startsWith("/\\")) return "/";
  return next;
}

// HTML 을 서버가 내려준다면 (Express 예)
import crypto from "node:crypto";

app.use((req, res, next) => {
  const nonce = crypto.randomBytes(16).toString("base64");
  res.locals.nonce = nonce;                  // 템플릿의 <script nonce="…"> 에 사용
  res.setHeader("Content-Security-Policy-Report-Only", [   // ① 먼저 보고만
    "default-src 'self'",
    `script-src 'nonce-${nonce}' 'strict-dynamic'`,  // nonce 붙은 스크립트 + 그것이 부른 것
    "style-src 'self' 'unsafe-inline'",               // 스타일은 나중에 조이기
    "img-src 'self' data: https://cdn.example.com",
    "connect-src 'self' https://api.example.com",
    "object-src 'none'",
    "base-uri 'none'",
    "frame-ancestors 'none'",                         // 클릭재킹 방지
    "report-to csp",
  ].join("; "));
  res.setHeader("Reporting-Endpoints", 'csp="/csp-report"');
  next();
});

② 휴지통 아이콘(Collect garbage) → Heap snapshot #1
③ 동작을 정확히 N번 반복 (예: 10번)
④ 휴지통 → Heap snapshot #2
⑤ 동작 N번 더 → 휴지통 → Heap snapshot #3

읽기  #3 을 선택 → 보기를 Comparison, 기준을 #2 로
      → # Delta 가 N 의 배수인 생성자가 용의자
        (10번 했는데 정확히 +10, +20 이면 거의 확실)
      → 항목 펼쳐 아래 Retainers 창에서 '누가 붙잡고 있나' 추적
필터 창에 Detached 를 치면 DOM 에서 떨어졌는데 아직 살아 있는 요소가 나옵니다. 모달을 닫았는데 Detached HTMLDivElement 가 회차만큼 늘어 있다면 범인을 반쯤 잡은 것입니다.

Retainers 를 읽는 법

Detached HTMLDivElement               ← 살아 있으면 안 되는 것
  ▸ in handler of Function onResize   ← 함수가 그 DOM 을 붙잡음
    ▸ in [[Scope]] … resize listener  ← 리스너 목록에 남아 있음
      ▸ Window                         ← 뿌리(GC root) — 끝

해석: window 에 붙인 resize 리스너를 안 떼서
      → 리스너 함수 → 클로저 → 모달 DOM 이 통째로 남음

체크
 · 경로에 내 코드의 함수 이름이 보이는 가장 아래 칸이 '고칠 곳'
 · (internal) · system / Context 같은 칸은 건너뛰고 읽기
 · Shallow size 는 자기 크기, Retained size 는 '이것만 풀면 같이 풀리는 양'
   → 정렬은 Retained size 로
함수 이름이 안 보이면 — 개발 빌드나 소스맵이 있는 빌드에서 재세요. 압축된 빌드에서는 a · b 만 보입니다. React 개발 모드는 추가 정보를 붙잡아 두므로 최종 확인은 프로덕션 빌드(vite preview)로 합니다.

접근성 실무 체크 — 키보드 하나로 끝까지 가는가

접근성은 장애가 있는 사용자만의 문제가 아닙니다. 마우스가 고장 난 사람, 한 손으로 폰을 든 사람, 햇빛 아래의 화면 — 그리고 공공 · 금융 서비스라면 법적 요구사항입니다. 역할 · 이름 · 상태의 기초는 📄 HTML 탭 h08, 여기서는 배포 전에 무엇을 어떤 순서로 확인하나입니다.

모달 접근성의 세 줄 — 열면 안으로, 안에서는 갇히고, 닫으면 원래 자리로.

모달은 네이티브 <dialog> 로

import { useEffect, useId, useRef, type ReactNode } from "react";

export function Modal({ open, onClose, title, children }: {
  open: boolean; onClose: () => void; title: string; children: ReactNode;
}) {
  const ref = useRef<HTMLDialogElement>(null);
  const titleId = useId();

  useEffect(() => {
    const d = ref.current;
    if (!d) return;
    if (open && !d.open) d.showModal();   // 바깥은 inert · 포커스는 안으로 · Esc 지원
    if (!open && d.open) d.close();       // 닫히면 브라우저가 이전 포커스로 복귀
  }, [open]);

  return (
    <dialog ref={ref} aria-labelledby={titleId} className="modal"
      onClose={onClose}                     // Esc 로 닫혀도 상태를 맞춤
      onClick={(e) => { if (e.target === e.currentTarget) onClose(); }}>
      {/* dialog 의 padding 은 0 으로 — 안쪽 div 가 여백을 가져야 배경 클릭 판정이 맞음 */}
      <div className="modal-body">
        <h2 id={titleId}>{title}</h2>
        {children}
        <button type="button" onClick={onClose}>닫기</button>
      </div>
    </dialog>
  );
}
직접 만든 div 모달이라면 — 열 때 document.activeElement 를 기억해 두고 닫을 때 .focus(), 배경에는 inert 속성, 첫 포커스는 첫 입력칸 또는 제목. 이걸 다 손으로 하느니 <dialog> 나 검증된 라이브러리(Radix · React Aria)를 쓰는 편이 싸게 먹힙니다.
