TAURI 01

Tauri 가 무엇이고 왜 갑자기 다들 쓰나

한 줄로 말하면 “Electron 에서 Chromium 과 Node.js 를 빼고 그 자리에 OS 의 WebView 와 Rust 를 넣은 것” 입니다. 화면을 만드는 방법(HTML·CSS·JS)은 똑같으니 프런트 코드는 거의 그대로 옮겨 옵니다. 바뀌는 것은 배포 크기 · 메모리 · 뒷단 언어 · 보안 모델 네 가지이고, 이 섹션은 그 네 가지가 각각 얼마나 달라지는지를 숫자로 봅니다.

Tauri 가 작은 이유는 최적화가 아니라 브라우저를 안 들고 다니기 때문입니다 — 그 대가가 WebView 파편화입니다.

★ 여기가 핵심 — 화면은 웹, 힘쓰는 일은 네이티브
흔한 오해 — “Tauri 는 Rust 를 잘해야 쓴다”는 말은 절반만 맞습니다. 파일 읽기 · 대화상자 · HTTP · DB 는 전부 공식 플러그인이 JS API 로 제공합니다(u06). Rust 코드를 한 줄도 안 쓰고 앱 하나를 만들 수 있습니다. Rust 는 플러그인으로 안 되는 일을 할 때만 등장합니다.

Electron 의 위험 지점과 Tauri 의 답

Electron 의 구조적 위험
  · nodeIntegration 을 켜면 렌더러에서 require('fs') 가 됩니다
    → XSS 하나가 곧바로 "임의 파일 읽기/쓰기"가 됩니다
  · contextIsolation + preload 로 막지만, 이건 '옵션'입니다
  · preload 에서 실수로 넓은 API 를 노출하면 원점

Tauri 의 구조
  · WebView 안에서는 fs 든 프로세스 실행이든 애초에 없습니다
  · Rust 쪽이 명시적으로 등록한 command 만 부를 수 있습니다
  · 그 command 조차 capabilities 파일이 허용해야 통과합니다 ★
  · 파일 접근은 scope(경로 패턴)까지 걸 수 있습니다 (u06)

즉 Electron 은 "기본 열림 → 잠근다",
   Tauri 는  "기본 닫힘 → 하나씩 연다" 입니다.

그래도 남는 위험 — 착각하지 말 것

Tauri 를 쓴다고 XSS 가 안전해지지 않습니다. 허용된 command 가 run_shell(cmd: String) 처럼 넓으면, XSS 는 그 command 를 통해 무엇이든 실행합니다. command 를 좁게 설계하는 것이 실제 방어선입니다. 
// ❌ 이 하나로 모든 보안 모델이 무너집니다
#[tauri::command]
fn run(cmd: String) -> String { /* 아무거나 실행 */ }

// ✅ 할 수 있는 일을 타입으로 좁힙니다
#[derive(serde::Deserialize)]
enum Task { Thumbnail, Transcode, Probe }   // 정해진 것만

#[tauri::command]
fn run_task(task: Task, id: u32) -> Result<(), String> {
    // 경로도 인자로 받지 않고 id 로 DB 에서 찾습니다 ★
    Ok(())
}
실무 원칙 — command 인자로 경로·명령어·SQL 을 받지 마세요. “무엇을 할지”만 받고 “어디에 할지”는 Rust 쪽이 정합니다. 이 원칙 하나가 u06 의 권한 설정보다 실제로 더 많은 사고를 막습니다.
정리 — Tauri 는 Electron 에서 Chromium·Node 를 빼고 OS WebView + Rust 를 넣은 것입니다. 설치 파일 100 MB → 5 MB, 메모리 3분의 1, 무거운 일은 네이티브 속도. 대가는 WebView 파편화와 Rust입니다. 뒷단에서 실제로 힘쓰는 일이 있는 앱이라면 고민 없이 Tauri, 화면만 보여 주는 앱이라면 이득이 크지 않습니다.
TAURI 02

설치 · 첫 앱 — 한 줄이면 창이 뜹니다

Tauri 의 준비물은 Rust 툴체인 + Node + OS 별 WebView 런타임 세 가지입니다. 리눅스만 조금 성가시고 나머지는 대부분 이미 깔려 있습니다. 이 섹션에서 OS 별 준비 → 프로젝트 생성 → 폴더 구조 이해 → tauri dev 로 창 띄우기까지 끝냅니다.

개발 중엔 웹 개발과 똑같이 돌아가고, 빌드하면 화면 파일이 실행 파일 안으로 들어갑니다.

OS 별 준비물 — 여기만 넘기면 나머진 쉽습니다

TAURI 03

Commands · IPC — JS 에서 Rust 함수를 부르는 법

Tauri 앱의 거의 모든 코드는 결국 이 한 줄로 수렴합니다 — await invoke("함수이름", { 인자 }). Rust 함수 위에 #[tauri::command] 를 붙이고 등록해 두면, 프런트에서 비동기 함수처럼 부를 수 있습니다. 인자와 반환값은 serde 가 JSON 으로 자동 변환합니다. 이 섹션에서 동기·비동기·에러·스트리밍 네 가지 형태를 전부 봅니다.

IPC 는 결국 JSON 왕복입니다 — 그래서 큰 데이터를 자주 넘기면 그 자체가 병목이 됩니다.

가장 기본 — 동기 command

// src-tauri/src/lib.rs
use serde::{Serialize, Deserialize};

// ① 인자와 반환값에 쓸 타입 — derive 두 줄이면 끝
#[derive(Serialize)]
struct FileInfo {
    name: String,
    size: u64,
    is_dir: bool,
}

// ② 함수 위에 매크로 한 줄
#[tauri::command]
fn list_dir(path: String) -> Result<Vec<FileInfo>, String> {
    let mut out = Vec::new();
    // ❗ map_err 로 std 에러를 String 으로 — E 도 Serialize 여야 합니다
    for e in std::fs::read_dir(&path).map_err(|e| e.to_string())? {
        let e = e.map_err(|e| e.to_string())?;
        let m = e.metadata().map_err(|e| e.to_string())?;
        out.push(FileInfo {
            name: e.file_name().to_string_lossy().into_owned(),
            size: m.len(),
            is_dir: m.is_dir(),
        });
    }
    Ok(out)
}

// ③ 등록 — 여기 빠뜨리면 "not found" 가 납니다 ★
pub fn run() {
    tauri::Builder::default()
        .invoke_handler(tauri::generate_handler![list_dir])
        .run(tauri::generate_context!())
        .unwrap();
}

프런트 쪽 — 그냥 async 함수입니다

여기서 제일 많이 헤맵니다 — 인자 이름이 안 맞으면 invalid args `rootPath` for command 가 뜹니다. JS 는 camelCase, Rust 는 snake_case 가 기본 규칙이고, 구조체 필드도 #[serde(rename_all = "camelCase")] 를 붙여야 JS 쪽에서 isDir 로 보입니다(안 붙이면 is_dir).

async fn hash_file(path: String) -> Result<String, String> {

        Ok(format!("{:x}", md5_like(&bytes)))
    })
    .await
    .map_err(|e| e.to_string())?
}

    NotFound(String),
    #[error("권한이 없습니다: {0}")]
    Denied(String),
    #[error("입출력 오류: {0}")]

}

    fn serialize<S: serde::Serializer>(&self, s: S) -> Result<S::Ok, S::Error> {
        s.serialize_str(&self.to_string())
    }
}

use tauri::ipc::Channel;
use serde::Serialize;

#[derive(Clone, Serialize)]
#[serde(rename_all = "camelCase", tag = "event", content = "data")]
enum ScanEvent {
    Started { total: usize },
    Progress { done: usize, current: String },
    Finished { took_ms: u128 },
}

#[tauri::command]
async fn scan(root: String, on_event: Channel<ScanEvent>) -> Result<(), String> {
    let t0 = std::time::Instant::now();
    let files: Vec<_> = walkdir::WalkDir::new(&root)
        .into_iter().filter_map(|e| e.ok()).collect();

    on_event.send(ScanEvent::Started { total: files.len() })
            .map_err(|e| e.to_string())?;

    for (i, f) in files.iter().enumerate() {
        // 무거운 처리…
        if i % 100 == 0 {                       // ★ 매번 보내면 IPC 가 병목
            let _ = on_event.send(ScanEvent::Progress {
                done: i,
                current: f.path().display().to_string(),
            });
        }
    }
    let _ = on_event.send(ScanEvent::Finished { took_ms: t0.elapsed().as_millis() });
    Ok(())
}

프런트 — 콜백 하나만 넘기면 됩니다

import { invoke, Channel } from '@tauri-apps/api/core'

type ScanEvent =
  | { event: 'started';  data: { total: number } }
  | { event: 'progress'; data: { done: number; current: string } }
  | { event: 'finished'; data: { tookMs: number } }

const onEvent = new Channel<ScanEvent>()
onEvent.onmessage = (m) => {
  switch (m.event) {
    case 'started':  total.value = m.data.total; break
    case 'progress': done.value = m.data.done
                     current.value = m.data.current; break
    case 'finished': alert(`끝! ${m.data.tookMs}ms`); break
  }
}

await invoke('scan', { root: 'D:/data', onEvent })   // 키 이름 주의 ★
Channel vs 이벤트(u04) — 둘 다 Rust → JS 단방향 푸시입니다. Channel 은 “이 호출에 딸린 스트림”이라 호출자만 받고 자동으로 정리됩니다. 이벤트는 앱 전역 방송이라 아무나 구독합니다. 진행률·로그 스트림은 Channel, “설정이 바뀌었다” 같은 알림은 이벤트가 맞습니다.
IPC 는 공짜가 아닙니다 — 메시지 하나마다 JSON 직렬화 + WebView 경계 통과가 일어납니다. 초당 수천 건을 보내면 UI 가 오히려 느려집니다. 100건마다 · 또는 50 ms 마다 로 묶어서 보내세요. 큰 바이너리는 JSON 대신 tauri::ipc::Response::new(Vec<u8>) 로 바이트 그대로 보낼 수 있습니다.

command 는 부를 때마다 새로 실행되는 함수입니다. DB 연결 · 설정 · 캐시처럼 앱이 살아 있는 내내 유지할 것은 manage() 로 Tauri 에 맡깁니다. 그리고 Rust 쪽에서 먼저 말을 걸어야 할 때(파일이 바뀌었다, 다운로드가 끝났다)는 이벤트를 씁니다. 이 둘을 알면 “화면이 요청할 때만 도는 앱”에서 “스스로 움직이는 앱”으로 넘어갑니다.

command 는 매번 새로 도는 함수, 상태는 앱이 사는 동안 하나, 이벤트는 전체 방송입니다.

pub fn run() {
    tauri::Builder::default()
        .setup(|app| {
            // ② 앱 시작 시 한 번 만들어 맡깁니다
            let pool = tauri::async_runtime::block_on(async {
                sqlx::SqlitePool::connect("sqlite:app.db").await
            })?;
            app.manage(AppState { db: pool, cache: Default::default() });
            app.manage(Counter::default());   // 타입당 하나씩 ★
            Ok(())
        })
        .invoke_handler(tauri::generate_handler![bump, cached_read])
        .run(tauri::generate_context!())
        .unwrap();
}

// ③ command 인자로 꺼내 씁니다 — 타입으로 찾습니다
#[tauri::command]
fn bump(counter: State<'_, Counter>) -> u32 {
    let mut n = counter.0.lock().unwrap();
    *n += 1;
    *n
}

플러그인 등록 순서 주의 — single-instance 플러그인은 반드시 가장 먼저 등록해야 합니다(공식 문서 명시). 나중에 등록하면 두 번째 프로세스가 이미 다른 초기화를 해 버린 뒤라 파일 잠금·포트 충돌이 생깁니다.
정리 — 창은 WebviewWindowBuilder, 중복 방지는 get_webview_window 로 먼저 확인. 메뉴를 직접 만들 땐 편집 서브메뉴(복사·붙여넣기)를 꼭 포함하세요 — macOS 에서 단축키가 죽습니다. 상주 앱은 트레이 + prevent_close + 전역 단축키 세 조각이면 완성입니다. single-instance 는 가장 먼저 등록합니다.

struct History(Mutex<Vec<String>>);

            Ok(())
        })
        .on_event(|_app, event| {
            if let tauri::RunEvent::Exit = event { /* 정리 */ }
        })
        .build()
}

Sidecar — FFmpeg · 파이썬을 앱에 실어 보냅니다

Rust 로 다시 짜기엔 너무 큰 것들이 있습니다 — FFmpeg · yt-dlp · 파이썬 머신러닝 스크립트 · 사내 CLI 도구. Tauri 는 이런 외부 실행 파일을 설치본에 함께 넣고, 앱에서 실행하고, 출력을 실시간으로 받아오는 기능을 정식으로 제공합니다. 이것을 sidecar 라고 부릅니다. 파일 이름 규칙 하나만 지키면 크로스 플랫폼도 자동으로 처리됩니다.

use tauri_plugin_shell::{ShellExt, process::CommandEvent};
use tauri::ipc::Channel;
use serde::Serialize;

#[derive(Clone, Serialize)]
#[serde(rename_all = "camelCase", tag = "kind", content = "text")]
enum Line { Out(String), Err(String), Done(i32) }

#[tauri::command]
async fn transcode(
    app: tauri::AppHandle,
    input: String,
    on_line: Channel<Line>,
) -> Result<(), String> {
    let (mut rx, mut child) = app
        .shell()
        .sidecar("ffmpeg").map_err(|e| e.to_string())?
        .args(["-hide_banner", "-i", &input,
               "-vf", "scale=1280:-2", "-y", "out.mp4"])
        .spawn().map_err(|e| e.to_string())?;

    while let Some(ev) = rx.recv().await {
        match ev {
            CommandEvent::Stdout(b) => {
                let _ = on_line.send(Line::Out(String::from_utf8_lossy(&b).into()));
            }
            CommandEvent::Stderr(b) => {
                // ★ ffmpeg 은 진행률을 stderr 로 보냅니다
                let _ = on_line.send(Line::Err(String::from_utf8_lossy(&b).into()));
            }
            CommandEvent::Terminated(p) => {
                let _ = on_line.send(Line::Done(p.code.unwrap_or(-1)));
                break;
            }
            _ => {}
        }
    }
    let _ = child.kill();          // ★ 혹시 남아 있으면 정리
    Ok(())
}
stdin 으로 명령을 보낼 수도 있습니다 — child.write(b"command\n") 로 파이썬 REPL 같은 장기 실행 프로세스와 계속 대화할 수 있습니다. 파이썬 모델 서버를 sidecar 로 띄우고 JSON 한 줄씩 주고받는 패턴이 머신러닝 데스크톱 앱에서 흔합니다.

장기 실행 sidecar 관리 — 상태에 담아 둡니다

use std::sync::Mutex;
use tauri_plugin_shell::process::CommandChild;

#[derive(Default)]
struct Worker(Mutex<Option<CommandChild>>);

#[tauri::command]
async fn worker_start(app: tauri::AppHandle, st: tauri::State<'_, Worker>)
    -> Result<(), String>
{
    if st.0.lock().unwrap().is_some() { return Ok(()); }   // 이미 떠 있음
    let (mut rx, child) = app.shell().sidecar("worker")
        .map_err(|e| e.to_string())?
        .spawn().map_err(|e| e.to_string())?;
    *st.0.lock().unwrap() = Some(child);

    let h = app.clone();
    tauri::async_runtime::spawn(async move {
        while let Some(ev) = rx.recv().await {
            if let CommandEvent::Stdout(b) = ev {
                let _ = h.emit("worker-line", String::from_utf8_lossy(&b).to_string());
            }
        }
    });
    Ok(())
}

#[tauri::command]
fn worker_send(st: tauri::State<'_, Worker>, json: String) -> Result<(), String> {
    if let Some(c) = st.0.lock().unwrap().as_mut() {
        c.write(format!("{json}\n").as_bytes()).map_err(|e| e.to_string())?;
    }
    Ok(())
}

// 앱 종료 시 반드시 정리 ★
fn on_exit(app: &tauri::AppHandle) {
    let st: tauri::State<Worker> = app.state();
    if let Some(c) = st.0.lock().unwrap().take() { let _ = c.kill(); }
}

프런트엔드 연결 — 문자열 invoke 를 없앱니다

invoke('scan_dir', { rootPath }) 는 편하지만 전부 문자열입니다. 명령 이름을 오타 내도, 인자를 빠뜨려도, 반환 타입을 잘못 적어도 실행해 봐야 압니다. Rust 쪽 시그니처를 바꿨을 때 프런트가 조용히 깨지는 것이 Tauri 프로젝트에서 가장 흔한 버그입니다. 이 섹션은 수동 래퍼 → tauri-specta 자동 생성까지, 그 구멍을 막는 방법을 다룹니다.

Tauri 프로젝트에서 가장 흔한 버그는 Rust 를 고치고 프런트를 안 고친 것입니다 — 타입 생성이 이걸 막습니다.

// src/composables/useScan.ts
import { ref, onUnmounted } from 'vue'
import { Channel } from '@tauri-apps/api/core'
import { api, type ScanEvent } from '@/api'

export function useScan() {
  const running = ref(false)
  const done    = ref(0)
  const total   = ref(0)
  let ch: Channel<ScanEvent> | null = null

  async function start(root: string) {
    if (running.value) return
    running.value = true; done.value = 0
    ch = new Channel<ScanEvent>()
    ch.onmessage = (m) => {
      if (m.event === 'progress') done.value = m.data.done
      if (m.event === 'finished') running.value = false
    }
    try { await api.scan(root, ch) }
    finally { running.value = false; ch = null }
  }

  onUnmounted(() => { ch = null })       // 화면이 사라지면 참조 해제
  return { running, done, total, start }
}
// 이벤트 구독은 반드시 해제까지 한 쌍으로

}

import { check } from '@tauri-apps/plugin-updater'
import { relaunch } from '@tauri-apps/plugin-process'

export async function checkUpdate(silent = false) {
  const update = await check()
  if (!update) { if (!silent) alert('최신 버전입니다'); return }

  const ok = await confirm(
    `새 버전 ${update.version} 이 있습니다.\n\n${update.body ?? ''}\n\n지금 설치할까요?`)
  if (!ok) return

  let total = 0, got = 0
  await update.downloadAndInstall((e) => {
    switch (e.event) {
      case 'Started':      total = e.data.contentLength ?? 0; break
      case 'Progress':     got += e.data.chunkLength
                           progress.value = total ? got / total : 0; break
      case 'Finished':     progress.value = 1; break
    }
  })
  await relaunch()          // ★ 재시작해야 새 버전이 뜹니다
}

[dependencies]
eframe = "0.31"         # egui + 창 + 렌더러 묶음 (0.3x 대 · 최신 안정 확인)
use eframe::egui;

#[derive(Default)]
struct App { name: String, age: u32, items: Vec<String> }

impl eframe::App for App {
    // ★ 이 함수가 매 프레임 호출됩니다 — 이게 전부입니다
    fn update(&mut self, ctx: &egui::Context, _f: &mut eframe::Frame) {
        egui::TopBottomPanel::top("top").show(ctx, |ui| {
            ui.horizontal(|ui| { ui.heading("주소록"); ui.label(format!("{}명", self.items.len())); });
        });

        egui::CentralPanel::default().show(ctx, |ui| {
            ui.horizontal(|ui| {
                ui.label("이름:");
                ui.text_edit_singleline(&mut self.name);   // 값이 직접 묶입니다 ★
            });
            ui.add(egui::Slider::new(&mut self.age, 0..=120).text("나이"));

            if ui.button("추가").clicked() {               // 콜백이 없습니다 ★
                self.items.push(format!("{} ({})", self.name, self.age));
                self.name.clear();
            }

            ui.separator();
            egui::ScrollArea::vertical().show(ui, |ui| {
                for (i, it) in self.items.clone().iter().enumerate() {
                    ui.horizontal(|ui| {
                        ui.label(it);
                        if ui.small_button("삭제").clicked() { self.items.remove(i); }
                    });
                }
            });
        });
    }
}

    eframe::run_native("주소록", eframe::NativeOptions::default(),
        Box::new(|_cc| Ok(Box::new(App::default()))))

iced — Elm 아키텍처(상태 · 메시지 · 뷰)

use iced::widget::{button, column, row, text, text_input, scrollable};
use iced::{Element, Task};

#[derive(Default)]
struct App { input: String, items: Vec<String> }

// ① 일어날 수 있는 일을 열거형으로 전부 나열합니다 ★
#[derive(Debug, Clone)]
enum Message { InputChanged(String), Add, Remove(usize) }

impl App {
    // ② 메시지를 받아 상태를 바꿉니다 (여기서만 바뀝니다)
    fn update(&mut self, msg: Message) -> Task<Message> {
        match msg {
            Message::InputChanged(s) => self.input = s,
            Message::Add => {
                if !self.input.is_empty() {
                    self.items.push(std::mem::take(&mut self.input));
                }
            }
            Message::Remove(i) => { self.items.remove(i); }
        }
        Task::none()
    }

    // ③ 상태로부터 화면을 만듭니다 (순수 함수)
    fn view(&self) -> Element<Message> {
        let list = self.items.iter().enumerate().fold(
            column![].spacing(4),
            |col, (i, it)| col.push(row![
                text(it), button("삭제").on_press(Message::Remove(i))
            ].spacing(8)),
        );
        column![
            row![
                text_input("할 일", &self.input).on_input(Message::InputChanged),
                button("추가").on_press(Message::Add),
            ].spacing(8),
            scrollable(list),
        ].padding(16).spacing(12).into()
    }
}

fn main() -> iced::Result {
    iced::run("할 일", App::update, App::view)
}
iced 의 장점은 “상태가 바뀌는 곳이 update 하나뿐” 이라는 점입니다. 규모가 커져도 데이터 흐름을 추적하기 쉽습니다. 단점은 API 가 아직 자주 바뀐다는 것 — 버전을 올릴 때마다 코드를 고쳐야 할 각오가 필요합니다. 버전을 Cargo.toml 에 정확히 고정해 두세요.

use leptos::prelude::*;

#[component]
fn TodoApp() -> impl IntoView {
    let (input, set_input) = signal(String::new());
    let (items, set_items) = signal(Vec::<String>::new());

    // 파생 값 — 의존하는 시그널이 바뀔 때만 다시 계산됩니다 ★
    let count = move || items.get().len();

    view! {
        <div class="wrap">
            <input
                prop:value=move || input.get()
                on:input=move |e| set_input.set(event_target_value(&e))
            />
            <button on:click=move |_| {
                let v = input.get();
                if !v.is_empty() { set_items.update(|l| l.push(v)); set_input.set(String::new()); }
            }>"추가"</button>

            <p>{move || format!("{}개", count())}</p>
            <ul>
                <For each=move || items.get() key=|s| s.clone() let:item>
                    <li>{item}</li>
                </For>
            </ul>
        </div>
    }
}

use yew::prelude::*;

#[function_component(App)]
fn app() -> Html {
    let items = use_state(Vec::<String>::new);
    let input = use_state(String::new);

    let on_input = {
        let input = input.clone();
        Callback::from(move |e: InputEvent| {
            let t: web_sys::HtmlInputElement = e.target_unchecked_into();
            input.set(t.value());
        })
    };
    let on_add = {
        let (items, input) = (items.clone(), input.clone());
        Callback::from(move |_| {
            if !input.is_empty() {
                let mut v = (*items).clone();
                v.push((*input).clone());
                items.set(v);
                input.set(String::new());
            }
        })
    };

    html! {
        <div>
            <input value={(*input).clone()} oninput={on_input} />
            <button onclick={on_add}>{"추가"}</button>
            <ul>{ for items.iter().map(|i| html!{ <li>{i}</li> }) }</ul>
        </div>
    }
}

CREATE TABLE IF NOT EXISTS files (
  id        INTEGER PRIMARY KEY,
  path      TEXT NOT NULL UNIQUE,
  name      TEXT NOT NULL,
  ext       TEXT,
  size      INTEGER NOT NULL,
  mtime     INTEGER NOT NULL,
  hash      TEXT,                    -- 큰 파일만 계산 (지연 해시)
  indexed_at INTEGER NOT NULL
);

CREATE INDEX IF NOT EXISTS idx_files_size ON files(size);
CREATE INDEX IF NOT EXISTS idx_files_hash ON files(hash);
CREATE INDEX IF NOT EXISTS idx_files_ext  ON files(ext);

-- 이름 검색용 전문검색 가상 표 ★ LIKE '%x%' 보다 수십 배 빠릅니다
CREATE VIRTUAL TABLE IF NOT EXISTS files_fts
USING fts5(name, path, content='files', content_rowid='id',
           tokenize='trigram');       -- 한글·부분일치에 trigram 이 유리

-- files 가 바뀌면 fts 도 따라오게 트리거로 묶습니다
CREATE TRIGGER IF NOT EXISTS files_ai AFTER INSERT ON files BEGIN
  INSERT INTO files_fts(rowid, name, path) VALUES (new.id, new.name, new.path);
END;
CREATE TRIGGER IF NOT EXISTS files_ad AFTER DELETE ON files BEGIN
  INSERT INTO files_fts(files_fts, rowid, name, path)
  VALUES ('delete', old.id, old.name, old.path);
END;
tokenize='trigram' 을 쓰는 이유 — 기본 토크나이저는 단어 단위라 보고서 로 2026보고서최종.xlsx 를 못 찾습니다. trigram 은 세 글자씩 잘라 색인하므로 부분 일치와 한글에 강합니다. 색인 크기가 2~3배가 되지만, 파일 검색에서는 그 값어치가 확실합니다.

pub enum IndexEvent {
    Scanning { found: usize },
    Hashing  { done: usize, total: usize },
    Finished { total: usize, took_ms: u128 },
    Canceled,
}

struct Row { path: String, name: String, ext: Option<String>,
             size: u64, mtime: i64, hash: Option<String> }

#[tauri::command]
pub async fn start_index(
    app: tauri::AppHandle,
    st: tauri::State<'_, crate::state::AppState>,
    roots: Vec<String>,
    on_event: Channel<IndexEvent>,
) -> Result<(), String> {
    let cancel = st.cancel.clone();
    cancel.store(false, Ordering::Relaxed);
    let db_path = st.db_path.clone();

    // ★ CPU 를 쓰는 일이므로 통째로 블로킹 풀에서 돌립니다 (u03)
    tauri::async_runtime::spawn_blocking(move || {
        let t0 = std::time::Instant::now();

        // ① 수집 — ignore 크레이트가 .gitignore · 숨김 파일을 알아서 걸러 줍니다
        let mut paths = Vec::new();
        for root in &roots {
            for e in ignore::WalkBuilder::new(root).hidden(true).build().flatten() {
                if e.file_type().map(|t| t.is_file()).unwrap_or(false) {
                    paths.push(e.into_path());
                    if paths.len() % 5000 == 0 {
                        let _ = on_event.send(IndexEvent::Scanning { found: paths.len() });
                    }
                }
                if cancel.load(Ordering::Relaxed) {
                    let _ = on_event.send(IndexEvent::Canceled);
                    return;
                }
            }
        }

        // ② 병렬 처리 — 여기서 코어 수만큼 빨라집니다 ★
        let done = Arc::new(AtomicUsize::new(0));
        let total = paths.len();
        let rows: Vec<Row> = paths.par_iter()
            .filter_map(|p| {
                if cancel.load(Ordering::Relaxed) { return None; }
                let m = std::fs::metadata(p).ok()?;
                let size = m.len();
                // 1 MB 이상만 해시 — 전체 해시는 디스크가 병목이 됩니다
                let hash = (size >= 1_048_576)
                    .then(|| std::fs::read(p).ok().map(|b| blake3::hash(&b).to_hex().to_string()))
                    .flatten();
                let n = done.fetch_add(1, Ordering::Relaxed);
                if n % 500 == 0 {
                    let _ = on_event.send(IndexEvent::Hashing { done: n, total });
                }
                Some(Row {
                    path: p.display().to_string(),
                    name: p.file_name()?.to_string_lossy().into_owned(),
                    ext:  p.extension().map(|e| e.to_string_lossy().to_lowercase()),
                    size,
                    mtime: m.modified().ok()
                        .and_then(|t| t.duration_since(std::time::UNIX_EPOCH).ok())
                        .map(|d| d.as_secs() as i64).unwrap_or(0),
                    hash,
                })
            })
            .collect();

        // ③ 배치 삽입 — 한 건씩 넣으면 100배 느립니다 ★
        if let Ok(mut conn) = rusqlite::Connection::open(&db_path) {
            let _ = conn.execute_batch(
                "PRAGMA journal_mode=WAL; PRAGMA synchronous=NORMAL;");
            if let Ok(tx) = conn.transaction() {
                {
                    let mut stmt = tx.prepare(
                        "INSERT INTO files(path,name,ext,size,mtime,hash,indexed_at)
                         VALUES (?1,?2,?3,?4,?5,?6,strftime('%s','now'))
                         ON CONFLICT(path) DO UPDATE SET
                           size=excluded.size, mtime=excluded.mtime, hash=excluded.hash"
                    ).unwrap();
                    for r in &rows {
                        let _ = stmt.execute(rusqlite::params![
                            r.path, r.name, r.ext, r.size as i64, r.mtime, r.hash]);
                    }
                }
                let _ = tx.commit();
            }
        }

        let _ = on_event.send(IndexEvent::Finished {
            total: rows.len(), took_ms: t0.elapsed().as_millis() });
    });
    Ok(())
}

use serde::Serialize;

#[derive(Serialize)]
#[serde(rename_all = "camelCase")]
pub struct Hit { pub id: i64, pub path: String, pub name: String,
                 pub size: i64, pub mtime: i64 }

#[tauri::command]
pub fn search(st: tauri::State<'_, crate::state::AppState>,
              q: String, limit: u32) -> Result<Vec<Hit>, String> {
    if q.trim().len() < 2 { return Ok(vec![]); }     // 너무 짧으면 안 돕니다
    let conn = rusqlite::Connection::open(&st.db_path).map_err(|e| e.to_string())?;

    // FTS5 질의 — 사용자 입력을 그대로 넣지 않고 따옴표로 감쌉니다 ★
    let term = format!("\"{}\"", q.replace('"', ""));
    let mut stmt = conn.prepare(
        "SELECT f.id, f.path, f.name, f.size, f.mtime
           FROM files_fts JOIN files f ON f.id = files_fts.rowid
          WHERE files_fts MATCH ?1
          ORDER BY rank
          LIMIT ?2").map_err(|e| e.to_string())?;

    let rows = stmt.query_map(rusqlite::params![term, limit], |r| Ok(Hit {
        id: r.get(0)?, path: r.get(1)?, name: r.get(2)?,
        size: r.get(3)?, mtime: r.get(4)?,
    })).map_err(|e| e.to_string())?;

    rows.collect::<Result<Vec<_>, _>>().map_err(|e| e.to_string())
}

#[serde(rename_all = "camelCase")]
pub struct DupeGroup { pub hash: String, pub size: i64, pub paths: Vec<String> }

#[tauri::command]
pub fn find_dupes(st: tauri::State<'_, crate::state::AppState>)
    -> Result<Vec<DupeGroup>, String>
{
    let conn = rusqlite::Connection::open(&st.db_path).map_err(|e| e.to_string())?;
    // 같은 해시가 2건 이상 = 내용이 같은 파일 ★
    let mut stmt = conn.prepare(
        "SELECT hash, MAX(size), GROUP_CONCAT(path, char(10))
           FROM files
          WHERE hash IS NOT NULL
          GROUP BY hash HAVING COUNT(*) > 1
          ORDER BY MAX(size) * COUNT(*) DESC
          LIMIT 500").map_err(|e| e.to_string())?;

    let rows = stmt.query_map([], |r| {
        let joined: String = r.get(2)?;
        Ok(DupeGroup { hash: r.get(0)?, size: r.get(1)?,
                       paths: joined.split('\n').map(String::from).collect() })
    }).map_err(|e| e.to_string())?;

    rows.collect::<Result<Vec<_>, _>>().map_err(|e| e.to_string())
}
