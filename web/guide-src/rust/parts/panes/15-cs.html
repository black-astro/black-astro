C# 은 이미 좋은 언어입니다. 그래서 전부 옮기는 이야기가 아닙니다. 이미지 처리·파싱·암호·시뮬레이션처럼 C# 으로는 GC 와 싸워야 하는 층 하나를 Rust 로 만들고, ASP.NET Core·Unity·Godot·MAUI 어디서든 using 한 줄로 부르는 것이 목표입니다. 길은 여러 개지만 2026년의 기본값은 csbindgen 하나로 정리됐습니다 — build.rs 다섯 줄이면 C# 바인딩이 빌드마다 자동으로 갱신됩니다.

C# 01

다섯 가지 길 — 무엇을 고를지부터 정합니다

Rust 를 C# 에서 부르는 방법은 다섯 가지지만 실제로 고민되는 건 두 가지뿐입니다. 함수가 몇 개면 손으로 [LibraryImport] 를 쓰고, 그보다 많거나 계속 늘어난다면 csbindgen 으로 자동 생성합니다. 나머지 셋은 “여러 언어에 동시에 낼 때”라는 조건이 붙습니다.

고민되는 건 사실상 위의 두 줄뿐입니다 — 손으로 쓸까, csbindgen 에 맡길까.

다섯 개가 서로 배타적이지 않습니다 — 전부 바닥은 같은 C ABI(🔗 f01)입니다. Rust 쪽 extern "C" 함수는 그대로 두고 생성기만 갈아 끼울 수 있습니다. 그래서 손 P/Invoke 로 시작해도 나중에 csbindgen 으로 옮기는 데 비용이 거의 없습니다.

2026년의 추천 — csbindgen

csbindgen (Cysharp · MIT)

  · Rust 소스의 #[no_mangle] extern "C" 함수를 읽어
    C# 의 partial 클래스 하나를 생성합니다
  · 생성물은 [DllImport] / [LibraryImport] 선언 + repr(C) 구조체
  · Unity 용 출력 모드가 따로 있습니다 (★ 게임에서 가장 큰 이점)
  · bindgen 이 만든 Rust 바인딩도 입력으로 받습니다
    → C 라이브러리 → Rust → C# 3단 연결도 한 번에

왜 이게 기본값인가
  ① 설정이 build.rs 다섯 줄입니다 (배우는 데 10분)
  ② 생성물이 사람이 읽을 수 있는 평범한 C# 입니다 ★
     (마법이 없어서 문제가 생기면 그 파일을 열어 보면 됩니다)
  ③ Rust 함수를 고치면 빌드할 때 C# 이 따라 바뀝니다
     — 시그니처 불일치로 인한 조용한 메모리 파손이 사라집니다 ★
  ④ 런타임 의존성이 0 입니다 (생성기는 빌드 때만 씁니다)

한계 (미리 알아 두세요)
  · Rust 의 Option · Result · String 은 여전히 못 넘깁니다 (k04)
  · 제네릭 · 트레이트도 안 됩니다 (구체 함수만)
  · 자동 생성은 '타이핑'을 없애 줄 뿐, '설계'는 여전히 사람 몫입니다

이렇게도 쓸 수 있다 — 나머지 넷은 각각 언제 쓰나 🟡 중급

interoptopus · uniffi

// ── interoptopus — 하나의 정의로 C# · 파이썬 · C 헤더를 함께
use interoptopus::{ffi_function, ffi_type, function, Inventory, InventoryBuilder};

#[ffi_type]                      // repr(C) + 메타데이터를 함께 답니다
#[repr(C)]
pub struct Point { pub x: f32, pub y: f32 }

#[ffi_function]                  // ★ 이 한 줄이 시그니처를 '목록'에 등록합니다
#[no_mangle]
pub extern "C" fn distance(a: Point, b: Point) -> f32 {
    ((a.x - b.x).powi(2) + (a.y - b.y).powi(2)).sqrt()
}

// 목록을 모아 두면 생성기가 이걸 읽습니다
pub fn my_inventory() -> Inventory {
    InventoryBuilder::new().register(function!(distance)).build()
}
// → cargo test 나 별도 bin 에서 C#/파이썬/C 파일을 한 번에 뽑습니다
★ interoptopus 를 고르는 조건
  · C# 과 파이썬(또는 C)에 '같은 API' 를 동시에 내야 한다
  · 타입 안전한 생성물을 원한다 (SafeHandle · 예외 변환까지)
  · 어노테이션을 붙이는 수고를 감수할 수 있다

★ uniffi-bindgen-cs (NordSecurity · Mozilla uniffi 의 C# 백엔드)
  · UDL 파일이나 proc-macro 로 '고수준' 인터페이스를 정의
  · String · Option<T> · Result<T,E> · Vec<T> 가 그대로 넘어갑니다 ★
    (내부적으로 직렬화하므로 공짜는 아닙니다)
  · Kotlin · Swift · Python 바인딩이 같이 나옵니다
  · 모바일 SDK(안드로이드+iOS+데스크톱)를 한 벌로 낼 때 최고
  · 성능이 중요한 뜨거운 경로에는 부적합합니다 (직렬화 비용)

cbindgen · 손 P/Invoke ★

★ cbindgen 은 C# 을 만들지 않습니다
  Rust → C 헤더(.h) 만 만듭니다 (🔗 f04)
  C# 쪽은 그 헤더를 '보고' 사람이 선언합니다

  그래도 유용한 경우
   · C/C++ 고객이 이미 있어서 헤더를 어차피 내야 한다
   · 헤더를 리뷰 대상 문서로 삼는다 (경계 변경이 diff 에 남습니다 ★)
   · Unity 의 C++ 플러그인이나 게임 엔진과도 붙인다

★ 손 P/Invoke 가 오히려 나은 경우
   · 함수가 3~5개이고 앞으로도 안 늘 것이 확실하다
   · 경계 함수마다 C# 쪽에서 검증 · 예외 변환을 넣고 싶다
   · 빌드에 도구를 하나라도 더 넣기 싫은 조직이다
   · 이미 있는 남의 Rust 라이브러리(.dll)만 부른다 ★
     (소스가 없으면 csbindgen 이 읽을 게 없습니다)

★ 섞어 써도 됩니다 — 실제로 많이들 이렇게 합니다
   csbindgen 이 만든 NativeMethods.g.cs 를 '저수준'으로 두고,
   그 위에 손으로 쓴 안전한 래퍼 클래스를 얹습니다 (k06)
   생성물을 직접 쓰지 말고 감싸세요 — 공개 API 가 안정됩니다
생성기를 골랐다고 끝이 아닙니다 — 어떤 도구를 써도 Option·Result·String 이 경계를 못 넘는다는 사실은 그대로입니다(uniffi 만 예외이고, 그건 직렬화로 우회한 것입니다). 경계 설계(k04)가 도구 선택보다 훨씬 중요합니다.

실무에선 이렇게 — 고르기 전에 확인할 네 가지 🔴 실무

체크리스트

① 배포 대상 플랫폼이 몇 개인가
   win-x64 하나면 무엇을 써도 됩니다.
   win-x64 + linux-x64 + osx-arm64 + android + ios 라면
   빌드 파이프라인(k11)이 도구 선택보다 훨씬 큰 일입니다 ★

② C# 쪽이 NativeAOT 인가
   NativeAOT 면 정적 링크(staticlib)가 가능해집니다 (k11).
   그러면 "DLL 을 어디에 두나" 문제가 통째로 사라집니다.

③ Unity 인가
   Unity 는 .NET 이 아니라 Mono/IL2CPP 입니다.
   [LibraryImport] 소스 생성기가 안 돕니다 → [DllImport] 를 씁니다 ★
   csbindgen 의 Unity 출력 모드가 이걸 처리해 줍니다 (k03 · k09)

④ 경계를 몇 번 넘는가
   초당 수백만 번이면 '한 번에 배치로' 로 설계를 바꾸세요 (k05).
   초당 수백 번이면 무엇을 써도 오버헤드가 안 보입니다.

★ ①~④ 를 답하고 나면 대개 선택이 하나로 좁혀집니다.

얹지 말아야 할 기대

이런 기대는 어긋납니다
  • “C# 코드를 Rust 가 대신 관리해 준다” — GC 는 여전히 C# 것이고, Rust 힙은 Rust 것입니다. 두 힙은 절대 섞이지 않습니다.
  • “어차피 다 빨라진다” — 경계를 자주 넘으면 오히려 느려집니다(k05).
  • “Rust 니까 안전하다” — 경계 함수 안은 unsafe 투성이입니다. 안전한 건 그 안쪽 순수 Rust뿐입니다.
  • “빌드가 그대로다” — CI 에 Rust 툴체인과 타깃별 빌드가 추가됩니다(k11).
실제로 얻는 것
  • GC 압박이 사라진 뜨거운 경로 — 대용량 버퍼를 Rust 힙에 두면 Gen2·LOH 가 안 자랍니다.
  • 이미 있는 Rust 생태계 — image · regex · ring · rayon · polars 를 그대로 씁니다.
  • 한 벌로 여러 앱 — 서버(ASP.NET)·게임(Unity)·데스크톱(Avalonia)이 같은 코어를 씁니다(k10 · k12).
  • 결정적인 성능 — 지터·GC 일시정지가 없어 p99 가 안정됩니다.

한 단계 더 — 경계 비용을 숫자로 🧬 전문가

한 번 넘는 데 얼마나 드나

실측 감각 (x64 · .NET 10 · 릴리즈 · 반드시 직접 재세요 · k12)

  blittable 인자만 있는 호출 왕복    약 1~5 ns  ★ 거의 공짜
  (DisableRuntimeMarshalling 켰을 때 · k04)

  string 인자 하나(UTF-8 변환 포함)  약 30~120 ns
  구조체 배열 마샬링(요소 1000개)     수 μs (복사 발생)
  Span 을 고정해서 포인터만 넘김      약 3~8 ns   ★ 제로카피 (k05)
  콜백을 통해 C# 으로 되돌아오기      약 5~20 ns

★ 비교 감각
  파이썬 ↔ Rust (PyO3)      약 100~300 ns   (🐍 y01)
  Node  ↔ Rust (napi-rs)    약 30~100 ns    (🟨 j01)
  C#    ↔ Rust (P/Invoke)   약 1~5 ns       ★ 압도적으로 쌉니다

  이유: CLR 은 이미 네이티브 코드이고, blittable 호출은
  JIT 가 '직접 점프하는 스텁' 으로 컴파일합니다.
  파이썬처럼 인터프리터를 빠져나올 필요가 없습니다.
이 숫자가 뜻하는 것 — C# ↔ Rust 경계는 파이썬보다 두 자릿수 쌉니다. 그래서 “배치로 묶어라”라는 조언이 파이썬만큼 절박하지 않습니다. 그래도 초당 수백만 번이면 여전히 보이니, 그때는 k05 를 보세요.

무엇이 비용을 만드나

경계 통과에서 실제로 일어나는 일 (비싼 순서)

  ④ 마샬링 (변환)          ← 가장 비쌉니다
     string · bool · 배열 · 클래스 · 델리게이트
     → 임시 버퍼 할당 + 복사 + 해제

  ③ GC 전이 (transition)
     "지금 관리 코드를 떠납니다" 표시.
     GC 가 이 스레드를 세우지 않고 진행할 수 있게 합니다.
     SuppressGCTransition 으로 뺄 수 있지만 위험합니다 (k04)

  ② 핀 고정 (pinning)
     GC 가 못 옮기게 고정. fixed / GCHandle.Alloc(Pinned)
     짧게 잡으면 거의 공짜, 오래 잡으면 힙이 파편화됩니다 (k05)

  ① 스텁 호출
     JIT 가 만든 점프. blittable 이면 사실상 직접 call 입니다

★ 결론 — 비용의 대부분은 '④ 마샬링' 입니다.
  경계 시그니처를 blittable 로만 짜면(k04) 나머지는 신경 쓸 게 없습니다.
  이것이 이 탭에서 계속 반복될 한 문장입니다. ★
정리 — 방법은 다섯이지만 고민은 둘입니다. 함수가 몇 개면 손 [LibraryImport], 그 이상이면 csbindgen 이 2026년의 기본값입니다. 무엇을 쓰든 바닥은 같은 C ABI라서 나중에 갈아 끼울 수 있고, 도구보다 훨씬 중요한 건 경계를 blittable 로 설계하는 것(k04)입니다.
C# 02

첫 호출 — 10분이면 dotnet run 이 돕니다

Rust 쪽은 속성 두 줄, C# 쪽은 선언 한 줄이면 함수가 불립니다. 초보가 실제로 막히는 곳은 코드가 아니라 만들어진 .dll 을 C# 실행 폴더로 옮기는 설정 하나입니다. 그것까지 포함해 처음부터 끝까지 갑니다.

두 가지 실패만 알면 됩니다 — 파일을 못 찾았나(③), 함수 이름이 틀렸나(④).

① Rust 쪽 — 파일 두 개

# 프로젝트 하나에 Rust 와 C# 을 나란히 둡니다
mkdir demo && cd demo
cargo new --lib native
dotnet new console -o app
# native/Cargo.toml
[package]
name = "mylib"
version = "0.1.0"
edition = "2024"

[lib]
name = "mylib"                 # ★ 만들어질 파일 이름의 뿌리
crate-type = ["cdylib"]        # ★ 동적 라이브러리 (🔗 f02)

[profile.release]
lto = true
codegen-units = 1
// native/src/lib.rs
// 2024 에디션에서는 no_mangle 에 unsafe 표기를 씁니다
#[unsafe(no_mangle)]
pub extern "C" fn rust_add(a: i32, b: i32) -> i32 {
    a + b
}

#[unsafe(no_mangle)]
pub extern "C" fn rust_sum_squares(n: u64) -> u64 {
    (1..=n).map(|x| x * x).sum()
}

// extern "C"  → 그 플랫폼의 C 호출 규약을 쓰라는 뜻 (🔗 f01)
// no_mangle   → 심볼 이름을 그대로 rust_add 로 두라는 뜻
//               안 붙이면 _ZN5mylib8rust_add17h... 가 됩니다
cd native && cargo build --release

# 만들어진 것 확인 ★ 문제가 생기면 항상 여기부터
ls target/release/
#   mylib.dll   + mylib.dll.lib   (윈도우)
#   libmylib.so                   (리눅스)
#   libmylib.dylib                (맥)

# 심볼이 정말 있는지
dumpbin /exports target\release\mylib.dll | findstr rust_    # 윈도우
nm -D target/release/libmylib.so | grep rust_               # 리눅스

② C# 쪽 — 선언과 csproj

// app/Native.cs
using System.Runtime.InteropServices;

internal static partial class Native            // ★ partial 이어야 합니다
{
    // 파일 이름에서 접두사(lib)와 확장자를 뺀 이름만 씁니다
    //   윈도우 mylib.dll · 리눅스 libmylib.so · 맥 libmylib.dylib
    //   → 전부 "mylib" 하나로 통합니다 ★
    [LibraryImport("mylib")]
    internal static partial int rust_add(int a, int b);

    [LibraryImport("mylib")]
    internal static partial ulong rust_sum_squares(ulong n);
}
// app/Program.cs
Console.WriteLine(Native.rust_add(20, 22));          // 42
Console.WriteLine(Native.rust_sum_squares(1000));    // 333833500

</Project>

탐색 순서

[LibraryImport("mylib")] 를 만나면 CLR 은 이 순서로 시도합니다

  1. 이미 로드된 것 중에 있나 (핸들 캐시)
  2. AssemblyLoadContext 의 DllImportResolver (k10 · 직접 개입 지점 ★)
  3. NATIVE_DLL_SEARCH_DIRECTORIES

  4. 어셈블리가 있는 폴더 (= 대부분 여기서 찾힙니다)
  5. OS 기본 규칙
     윈도우: LoadLibraryEx (앱 폴더 · 시스템 · PATH)
     리눅스: dlopen (rpath · LD_LIBRARY_PATH · ldconfig 캐시)

     mylib → libmylib.so / mylib.so   (리눅스)
     mylib → libmylib.dylib / mylib.dylib (맥)

C# 03

csbindgen — 바인딩을 손으로 쓰지 않습니다

k02 의 방식은 함수가 늘면 곧 무너집니다. Rust 시그니처를 고쳤는데 C# 선언을 안 고치면 컴파일은 되고 실행 중에 조용히 메모리가 깨집니다 — FFI 에서 가장 무서운 실패입니다. csbindgen 은 빌드할 때마다 C# 을 다시 만들어 이 불일치를 원천적으로 없앱니다.

얻는 건 타이핑 절약이 아니라 “고치면 따라 바뀐다”는 보장입니다 — 조용한 메모리 파손이 사라집니다.

use crate::core;                 // 순수 Rust 로직은 따로 (테스트 가능)

#[unsafe(no_mangle)]
pub extern "C" fn mylib_add(a: i32, b: i32) -> i32 {
    core::add(a, b)
}

#[unsafe(no_mangle)]
pub extern "C" fn mylib_checksum(ptr: *const u8, len: usize) -> u32 {
    if ptr.is_null() { return 0; }
    let s = unsafe { std::slice::from_raw_parts(ptr, len) };
    core::checksum(s)
}

★ 읽어 두면 좋은 특징 세 가지

  ① usize → nuint 로 정확히 매핑됩니다

  ② 포인터는 IntPtr 이 아니라 byte* 로 나옵니다
     → unsafe 가 필요하지만 타입이 살아 있어 안전합니다
     (원하면 .csharp_use_nint_types(false) 등으로 조절 가능)

  ③ ExactSpelling = true
     → 이름 변형(Ansi/Unicode 접미사) 탐색을 끕니다. 더 빠르고 명확합니다

    Panic = -99,              // catch_unwind 가 잡았을 때 (k08)

// 규약 ① 성공은 0, 실패는 음수 — C 의 오랜 관례입니다
// 규약 ② '값' 은 out 파라미터로 돌려줍니다
// 규약 ③ 자세한 메시지는 별도 함수로 (k08 의 thread_local)
#[unsafe(no_mangle)]
pub extern "C" fn mylib_parse(text: *const u8, len: usize,
                              out: *mut i64) -> i32 {
    if text.is_null() || out.is_null() { return Code::NullPointer as i32; }
    let s = unsafe { std::slice::from_raw_parts(text, len) };
    match std::str::from_utf8(s).ok().and_then(|s| s.parse::<i64>().ok()) {
        Some(v) => { unsafe { *out = v; } Code::Ok as i32 }
        None => Code::InvalidUtf8 as i32,
    }
}

배열과 버퍼 — 복사 없이 주고받기

경계에서 성능이 갈리는 지점은 함수 호출 비용이 아니라 데이터 복사입니다. 1MB 를 넘길 때 복사하면 수십 μs, 포인터만 넘기면 수 ns — 만 배 차이입니다. C# 은 Span·fixed·GCHandle 로 GC 힙을 잠깐 고정할 수 있고, 그 주소를 Rust 가 slice 로 되살려 씁니다.

복사가 사라지는 건 양쪽 다 같은 메모리를 보기 때문입니다 — 대신 수명을 사람이 지켜야 합니다.

① C# 배열을 빌려주기

}

// 결과를 C# 버퍼에 채워 받기 — 할당이 0 이 됩니다 ★
public static int Transform(ReadOnlySpan<byte> src, Span<byte> dst)
{
    unsafe
    {
        fixed (byte* s = src)
        fixed (byte* d = dst)
        {
            nuint written = 0;
            int rc = NativeMethods.mylib_transform(
                s, (nuint)src.Length, d, (nuint)dst.Length, &written);
            Check.Throw(rc);
            return (int)written;
        }
    }

#[unsafe(no_mangle)]
pub extern "C" fn mylib_transform(
    src: *const u8, src_len: usize,
    dst: *mut u8,   dst_cap: usize,
    out_written: *mut usize,
) -> i32 {
    if src.is_null() || dst.is_null() || out_written.is_null() {
        return -1;
    }
    let s = unsafe { std::slice::from_raw_parts(src, src_len) };
    let d = unsafe { std::slice::from_raw_parts_mut(dst, dst_cap) };

    // ★ 반드시 용량을 먼저 확인합니다 — 넘치면 힙이 통째로 깨집니다
    if d.len() < s.len() {
        unsafe { *out_written = s.len(); }   // 필요한 크기를 알려 줍니다
        return -4;                            // BufferTooSmall
    }
    for (i, b) in s.iter().enumerate() { d[i] = b.wrapping_add(1); }
    unsafe { *out_written = s.len(); }
    0
}

    finally { NativeMethods.mylib_buf_free(b); }   // ★ 빠뜨리면 누수
}
Span 을 free 밖으로 내보내지 마세요 — Span<T> 는 ref struct 라 필드에 저장할 수 없어 언어가 어느 정도 막아 주지만, ToArray() 없이 포인터를 들고 나가면 해제된 메모리를 읽게 됩니다. 복사할 것인가, 수명을 관리할 것인가를 API 마다 정하세요.

핀은 짧게 — 왜 그런가 ★

GC 는 살아남은 객체를 한쪽으로 몰아 붙여(compaction) 빈 공간을 만듭니다.
고정된 객체는 못 옮깁니다 → 그 자리가 '말뚝' 이 됩니다.

  Gen0/Gen1 힙에 말뚝이 여럿 박히면
    · 압축이 부분적으로만 되고
    · 빈 조각이 흩어져 할당이 느려지고
    · 결국 Gen2 승격과 전체 GC 가 늘어납니다 ★

★ 실무 규칙
  · fixed 블록 안에서 '호출 한 번' 만 하고 나오세요
  · 몇 밀리초 이상 잡아야 하면 GC 힙이 아니라
    NativeMemory 나 POH(pinned object heap)를 쓰세요
  · 큰 버퍼(85KB 이상)는 어차피 LOH 라 잘 안 움직입니다 —
    그래도 명시적으로 POH 를 쓰는 편이 예측 가능합니다

★ 확인하는 법
  dotnet-counters monitor --counters System.Runtime
    gen-0-gc-count · gen-2-gc-count · loh-size 를 봅니다
  급증하면 핀 시간이 길거나 배열을 매번 새로 만들고 있는 것입니다
가장 좋은 버퍼는 “재사용하는 버퍼”입니다 — ArrayPool<byte>.Shared.Rent() 로 빌려 쓰고 돌려주면 할당도 GC 도 거의 0 이 됩니다. 그 버퍼를 fixed 로 잠깐 고정해 넘기는 조합이 ASP.NET Core 에서 가장 많이 쓰이는 형태입니다(k12).

피해야 할 시그니처

복사가 숨어 있습니다
  • byte[] data 를 그대로 인자로 — 마샬러가 고정할 수도, 복사할 수도 있습니다(런타임 판단).
  • string[] names — 요소마다 변환 + 배열 재구성.
  • [MarshalAs(UnmanagedType.LPArray)] + SizeParamIndex — 편하지만 비용이 보이지 않습니다.
  • Rust 가 Vec 을 만들어 반환하는데 해제 함수가 없음 — 누수.
비용이 보이는 시그니처
  • byte* ptr, nuint len — 복사 여부가 코드에 드러납니다.
  • 출력도 byte* dst, nuint cap, nuint* written — 호출자가 버퍼를 소유.
  • Rust 반환 버퍼는 Buf 구조체 + buf_free 를 한 쌍으로.
  • C# 공개 API 는 Span/ReadOnlySpan 으로 받아 안에서만 fixed.
규칙 하나로 요약하면 — 경계에는 포인터와 길이만 다닙니다. 배열·문자열·컬렉션은 C# 래퍼 안쪽에서만 존재하게 하세요. 그러면 “왜 여기서 복사가 생기지”를 시그니처만 보고 알 수 있습니다.

    debug_assert_eq!(ptr as usize % 32, 0, "32바이트 정렬이 아닙니다");

    s.iter().sum()

use std::ffi::{c_char, c_void, CStr};

pub struct Decoder {          // ★ repr(C) 가 아니어도 됩니다
    inner: core::Decoder,     //   C# 은 안을 절대 안 보니까요
    frames: u64,
}

// ① 만들기 — 실패하면 널을 돌려줍니다
#[unsafe(no_mangle)]
pub extern "C" fn mylib_decoder_open(path: *const c_char) -> *mut c_void {
    if path.is_null() { return std::ptr::null_mut(); }
    let Ok(s) = (unsafe { CStr::from_ptr(path) }).to_str() else {
        return std::ptr::null_mut();
    };
    match core::Decoder::open(s) {
        Ok(inner) => {
            let boxed = Box::new(Decoder { inner, frames: 0 });
            Box::into_raw(boxed) as *mut c_void   // ★ 소유권을 뗍니다
        }
        Err(_) => std::ptr::null_mut(),
    }
}

// ② 쓰기 — 포인터를 참조로 되살립니다
#[unsafe(no_mangle)]
pub extern "C" fn mylib_decoder_next(h: *mut c_void,
                                     dst: *mut u8, cap: usize,
                                     out_len: *mut usize) -> i32 {
    if h.is_null() || dst.is_null() { return -1; }
    let d = unsafe { &mut *(h as *mut Decoder) };   // ★ 유일한 unsafe
    let buf = unsafe { std::slice::from_raw_parts_mut(dst, cap) };
    match d.inner.next_frame(buf) {
        Ok(n) => { d.frames += 1; unsafe { *out_len = n; } 0 }
        Err(_) => -5,
    }
}

// ③ 없애기 — 널 검사를 반드시 넣습니다
#[unsafe(no_mangle)]
pub extern "C" fn mylib_decoder_close(h: *mut c_void) {
    if h.is_null() { return; }
    unsafe { drop(Box::from_raw(h as *mut Decoder)); }   // ★ 여기서 Drop
}

using Microsoft.Win32.SafeHandles;
using System.Runtime.InteropServices;

// 0 또는 -1 이면 무효인 핸들 — 가장 흔한 규약입니다
internal sealed class DecoderHandle : SafeHandleZeroOrMinusOneIsInvalid
{
    public DecoderHandle() : base(ownsHandle: true) { }

    protected override bool ReleaseHandle()
    {
        NativeMethods.mylib_decoder_close(handle);   // ★ 정확히 한 번
        return true;
    }
}
public sealed class Decoder : IDisposable
{
    readonly DecoderHandle _h;

    public Decoder(string path)
    {
        nint p = NativeMethods.mylib_decoder_open(path);
        if (p == 0) throw new MyLibException(MyLibCode.NotFound, path);

        _h = new DecoderHandle();
        Marshal.InitHandle(_h, p);        // .NET 6+ — 핸들을 안전하게 설정
    }

    public int Next(Span<byte> dst)
    {
        ObjectDisposedException.ThrowIf(_h.IsClosed, this);
        bool taken = false;
        try
        {
            _h.DangerousAddRef(ref taken);      // ★ 호출 중 해제되지 않게
            unsafe
            {
                fixed (byte* d = dst)
                {
                    nuint n;
                    Check.Throw(NativeMethods.mylib_decoder_next(
                        _h.DangerousGetHandle(), d, (nuint)dst.Length, &n));
                    return (int)n;
                }
            }
        }
        finally { if (taken) _h.DangerousRelease(); }
    }

    public void Dispose() => _h.Dispose();
}

const MAGIC: u32 = 0x5255_5354;      // "RUST"

fn as_decoder<'a>(h: *mut c_void) -> Option<&'a mut Decoder> {

    if d.magic != MAGIC { return None; }        // ★ 해제 후 접근을 대개 잡습니다
    Some(d)
}

    if d.magic != MAGIC { return; }             // 이중 해제 방지

★ Arc 를 경계에 쓸 때 주의

use std::ffi::c_void;

// ★ user 포인터를 항상 함께 받으세요 — 콜백이 '누구를 위한 것인지' 를 압니다
pub type ProgressFn = extern "C" fn(user: *mut c_void, done: u32, total: u32);

#[unsafe(no_mangle)]
pub extern "C" fn mylib_process(
    ptr: *const u8, len: usize,
    cb: Option<ProgressFn>,      // ★ 널을 허용하려면 Option
    user: *mut c_void,
) -> i32 {
    if ptr.is_null() { return -1; }
    let data = unsafe { std::slice::from_raw_parts(ptr, len) };

    let total = data.len() as u32;
    for (i, chunk) in data.chunks(4096).enumerate() {
        core::step(chunk);
        if let Some(f) = cb {
            f(user, (i as u32 + 1) * 4096, total);   // ★ 콜백 호출
        }
    }
    0
}
// 스레드로 넘길 때는 포인터를 감싸야 합니다
// (*mut c_void 는 Send 가 아닙니다 — 컴파일러가 막습니다)
struct UserPtr(*mut c_void);
unsafe impl Send for UserPtr {}      // ★ "C# 쪽이 스레드 안전을 보장한다" 는 약속

#[unsafe(no_mangle)]
pub extern "C" fn mylib_start(cb: ProgressFn, user: *mut c_void) -> i32 {
    let u = UserPtr(user);
    std::thread::spawn(move || {
        let u = u;                                  // 소유권을 스레드로
        for i in 0..100u32 {
            core::work();
            cb(u.0, i + 1, 100);                    // 워커 스레드에서 호출
        }
    });
    0                                                // 즉시 돌아옵니다
}

using System.Runtime.CompilerServices;
using System.Runtime.InteropServices;

public sealed class Job
{
    public event Action<int>? Progress;

    // ★ static 이어야 하고, 인자는 전부 blittable 이어야 합니다
    [UnmanagedCallersOnly(CallConvs = [typeof(CallConvCdecl)])]
    static void OnProgress(nint user, uint done, uint total)
    {
        // ★ 예외가 여기서 밖으로 나가면 프로세스가 죽습니다 — 반드시 감쌉니다
        try
        {
            var job = (Job?)GCHandle.FromIntPtr(user).Target;
            job?.Progress?.Invoke((int)(done * 100 / Math.Max(total, 1)));
        }
        catch { /* 로깅만 하고 삼킵니다 */ }
    }

    public unsafe void Run(ReadOnlySpan<byte> data)
    {
        // 자기 자신을 콜백에 전달할 수 있게 핸들을 만듭니다
        var h = GCHandle.Alloc(this);          // ★ Pinned 가 아니어도 됩니다
        try
        {
            fixed (byte* p = data)
                Check.Throw(NativeMethods.mylib_process(
                    p, (nuint)data.Length,
                    &OnProgress,                // ★ 함수 주소를 직접 넘깁니다
                    GCHandle.ToIntPtr(h)));
        }
        finally { h.Free(); }                  // ★ 반드시 해제
    }
}
왜 델리게이트가 아니라 함수 포인터인가 — [UnmanagedCallersOnly] 메서드의 주소는 고정된 네이티브 진입점입니다. 델리게이트를 Marshal.GetFunctionPointerForDelegate 로 넘기면 그 델리게이트를 붙잡아 두지 않는 한 GC 가 수거해 버립니다 — FFI 에서 가장 흔한 크래시 원인입니다.

public static class NativeAsync
{
    sealed class Pending
    {
        // ★ RunContinuationsAsynchronously 를 반드시 켜세요
        //   안 켜면 이어지는 코드가 Rust 스레드에서 계속 실행됩니다
        public readonly TaskCompletionSource<int> Tcs =
            new(TaskCreationOptions.RunContinuationsAsynchronously);
    }

    [UnmanagedCallersOnly(CallConvs = [typeof(CallConvCdecl)])]
    static void OnDone(nint user, int result)
    {
        GCHandle h = default;
        try
        {
            h = GCHandle.FromIntPtr(user);
            ((Pending)h.Target!).Tcs.TrySetResult(result);
        }
        catch { }
        finally { if (h.IsAllocated) h.Free(); }   // ★ 여기서 정리
    }

    public static unsafe Task<int> ProcessAsync(ReadOnlyMemory<byte> data,
                                                 CancellationToken ct = default)
    {
        var p = new Pending();
        var gh = GCHandle.Alloc(p);
        var pin = data.Pin();                      // ★ 비동기 동안 고정 유지

        ct.Register(() => NativeMethods.mylib_cancel());

        int rc = NativeMethods.mylib_process_async(
            (byte*)pin.Pointer, (nuint)data.Length,
            &OnDone, GCHandle.ToIntPtr(gh));

        if (rc != 0) { pin.Dispose(); gh.Free(); Check.Throw(rc); }
        return p.Tcs.Task.ContinueWith(t => { pin.Dispose(); return t.Result; });
    }
}

#[unsafe(no_mangle)]
pub extern "C" fn good(h: *mut c_void, cb: ProgressFn, user: *mut c_void) {

C# 08

패닉 — 경계를 넘게 두면 안 됩니다

Rust 의 panic! 은 기본적으로 스택을 되감으며(unwind) 올라갑니다. 그 되감기가 C# 이 만든 스택 프레임을 지나가면 정의되지 않은 동작입니다. 운이 좋으면 즉시 죽고, 나쁘면 한참 뒤에 엉뚱한 곳에서 죽습니다. 경계 함수마다 catch_unwind 로 가둬 에러 코드로 바꾸는 것이 정답입니다.

되감기는 경계에서 반드시 끝나야 합니다 — 넘어가면 진단조차 불가능해집니다.

감싸는 매크로 하나 만들기 ★

use std::panic::{catch_unwind, AssertUnwindSafe};

// 모든 경계 함수에 붙일 매크로 — 한 번 만들어 두면 잊을 일이 없습니다
macro_rules! ffi_guard {
    ($body:expr) => {
        match catch_unwind(AssertUnwindSafe(|| $body)) {
            Ok(v) => v,
            Err(e) => {
                let msg = if let Some(s) = e.downcast_ref::<&str>() {
                    s.to_string()
                } else if let Some(s) = e.downcast_ref::<String>() {
                    s.clone()
                } else {
                    "unknown panic".to_string()
                };
                set_last_error(format!("panic: {msg}"));   // 아래에서 정의
                -99                                        // Code::Panic
            }
        }
    };
}

#[unsafe(no_mangle)]
pub extern "C" fn mylib_parse(p: *const u8, len: usize, out: *mut i64) -> i32 {
    ffi_guard!({
        if p.is_null() || out.is_null() { return -1; }
        let s = unsafe { std::slice::from_raw_parts(p, len) };
        let v = core::parse(s)?;          // 여기서 패닉해도 안전합니다 ★
        unsafe { *out = v; }
        0
    })
}
AssertUnwindSafe 는 무엇인가 — “되감기 도중에 반쯤 고쳐진 상태가 밖에서 보일 수 있다”는 경고를 끄는 표시입니다. 끈다고 안전해지는 게 아니라, 공유 상태를 패닉이 깨뜨리지 않게 설계했다는 약속입니다. Mutex 는 패닉하면 오염(poisoned) 되니 lock() 결과를 항상 확인하세요.

// 스레드마다 하나씩 — 다른 스레드의 에러와 섞이지 않습니다 ★
thread_local! {
    static LAST_ERROR: RefCell<Option<String>> = const { RefCell::new(None) };
}

pub fn set_last_error(msg: String) {
    LAST_ERROR.with(|e| *e.borrow_mut() = Some(msg));
}

/// 마지막 에러를 UTF-8 로 buf 에 채우고 쓴 바이트 수를 돌려줍니다.
/// buf 가 널이면 필요한 크기만 돌려줍니다.
#[unsafe(no_mangle)]
pub extern "C" fn mylib_last_error(buf: *mut u8, cap: usize) -> usize {
    LAST_ERROR.with(|e| {
        let b = e.borrow();
        let Some(s) = b.as_ref() else { return 0 };
        let bytes = s.as_bytes();
        if buf.is_null() { return bytes.len(); }      // 크기 조회 모드
        let n = bytes.len().min(cap);
        unsafe { std::ptr::copy_nonoverlapping(bytes.as_ptr(), buf, n); }
        n
    })
}

// 에러를 만드는 곳마다 이 함수를 부릅니다
fn to_code(e: core::Error) -> i32 {
    set_last_error(e.to_string());       // ★ Display 구현을 그대로 씁니다
    match e {
        core::Error::NotFound(_) => -3,
        core::Error::Io(_) => -5,
        _ => -9,
    }
}
왜 thread_local 인가 — 전역 변수 하나로 두면 여러 스레드가 동시에 실패했을 때 메시지가 섞입니다. C 의 errno 도 같은 이유로 스레드 지역입니다. 버퍼를 호출자가 주는 형태라 문자열 해제 문제도 함께 사라집니다(k04).

internal static class Check
{
    public static void Throw(int rc)
    {
        if (rc == 0) return;
        string msg = LastError();
        throw rc == -99
            ? new NativePanicException(msg)
            : new MyLibException((MyLibCode)rc, msg);
    }

    static unsafe string LastError()
    {
        nuint need = NativeMethods.mylib_last_error(null, 0);   // 크기 조회
        if (need == 0) return "(메시지 없음)";
        Span<byte> buf = need <= 512 ? stackalloc byte[(int)need] : new byte[need];
        fixed (byte* p = buf)
        {
            nuint n = NativeMethods.mylib_last_error(p, (nuint)buf.Length);
            return Encoding.UTF8.GetString(buf[..(int)n]);
        }
    }
}

#if UNITY_EDITOR_WIN
using System;
using System.Runtime.InteropServices;
using UnityEditor;

[InitializeOnLoad]
public static class NativeReloader
{
    [DllImport("kernel32")] static extern nint LoadLibrary(string path);
    [DllImport("kernel32")] static extern bool FreeLibrary(nint h);
    [DllImport("kernel32")] static extern nint GetProcAddress(nint h, string n);

    static nint _lib;
    public static unsafe delegate* unmanaged[Cdecl]<byte*, nuint, uint> Checksum;

    static NativeReloader()
    {
        AssemblyReloadEvents.beforeAssemblyReload += Unload;
        EditorApplication.playModeStateChanged += s =>
        {
            if (s == PlayModeStateChange.ExitingPlayMode) Unload();
            if (s == PlayModeStateChange.EnteredPlayMode) Load();
        };
        Load();
    }

    static unsafe void Load()
    {
        if (_lib != 0) return;
        // ★ 원본이 아니라 '복사본' 을 엽니다 — 원본은 안 잠깁니다
        var src = "Assets/Plugins/x86_64/mylib.dll";
        var tmp = System.IO.Path.GetTempFileName() + ".dll";
        System.IO.File.Copy(src, tmp, true);

        _lib = LoadLibrary(tmp);
        Checksum = (delegate* unmanaged[Cdecl]<byte*, nuint, uint>)
                   GetProcAddress(_lib, "mylib_checksum");
    }

    static void Unload()
    {
        if (_lib == 0) return;
        FreeLibrary(_lib);
        _lib = 0;
    }
}
#endif

크로스 플랫폼 로더 ★

using System.Reflection;
using System.Runtime.InteropServices;

internal static class NativeLoader
{
    static int _done;

    // 어느 진입점에서든 한 번만 부르면 됩니다
    public static void Install()
    {
        if (Interlocked.Exchange(ref _done, 1) != 0) return;
        NativeLibrary.SetDllImportResolver(
            typeof(NativeLoader).Assembly, Resolve);
    }

    static nint Resolve(string name, Assembly asm, DllImportSearchPath? path)
    {
        if (name != "mylib") return 0;          // ★ 모르면 0 — 기본 규칙으로

        foreach (var candidate in Candidates())
            if (File.Exists(candidate) &&
                NativeLibrary.TryLoad(candidate, out var h))
                return h;

        return 0;
    }

    static IEnumerable<string> Candidates()
    {
        string bas = AppContext.BaseDirectory;
        string file = OperatingSystem.IsWindows() ? "mylib.dll"
                    : OperatingSystem.IsMacOS()   ? "libmylib.dylib"
                    : "libmylib.so";

        yield return Path.Combine(bas, file);                        // 옆에
        yield return Path.Combine(bas, "runtimes", Rid(), "native", file);
        yield return Path.Combine(bas, "native", Rid(), file);
        yield return Path.Combine(AppContext.BaseDirectory, "..",
                                  "Frameworks", file);               // 맥 앱 번들
    }

    static string Rid()
    {
        string os = OperatingSystem.IsWindows() ? "win"
                  : OperatingSystem.IsMacOS()   ? "osx" : "linux";
        string arch = RuntimeInformation.ProcessArchitecture switch
        {
            Architecture.X64 => "x64",
            Architecture.Arm64 => "arm64",
            Architecture.X86 => "x86",
            _ => "x64",
        };
        return $"{os}-{arch}";
    }
}

use image::imageops::FilterType;

pub fn resize_to_webp(input: &[u8], w: u32, h: u32, q: f32)
    -> Result<Vec<u8>, image::ImageError>
{
    let img = image::load_from_memory(input)?;
    let out = img.resize(w, h, FilterType::Lanczos3);   // 비율 유지
    let mut buf = Vec::with_capacity(input.len() / 4);
    let enc = image::codecs::webp::WebPEncoder::new_lossless(&mut buf);
    out.write_with_encoder(enc)?;
    let _ = q;
    Ok(buf)
}

// native/src/ffi.rs — 경계만. 얇게.
use crate::core;
use std::panic::{catch_unwind, AssertUnwindSafe};

#[repr(C)]
pub struct Buf { pub ptr: *mut u8, pub len: usize, pub cap: usize }

impl Buf {
    fn empty() -> Self { Buf { ptr: std::ptr::null_mut(), len: 0, cap: 0 } }
}

#[unsafe(no_mangle)]
pub extern "C" fn mylib_resize_webp(
    src: *const u8, src_len: usize,
    w: u32, h: u32, quality: f32,
    out: *mut Buf,
) -> i32 {
    let r = catch_unwind(AssertUnwindSafe(|| {
        if src.is_null() || out.is_null() { return -1; }
        let input = unsafe { std::slice::from_raw_parts(src, src_len) };
        match core::resize_to_webp(input, w, h, quality) {
            Ok(mut v) => {
                let b = Buf { ptr: v.as_mut_ptr(), len: v.len(), cap: v.capacity() };
                std::mem::forget(v);
                unsafe { *out = b; }
                0
            }
            Err(e) => { crate::ffi::set_last_error(e.to_string()); -5 }
        }
    }));
    match r { Ok(c) => c, Err(_) => -99 }
}

#[unsafe(no_mangle)]
pub extern "C" fn mylib_buf_free(b: Buf) {
    if b.ptr.is_null() { return; }
    unsafe { drop(Vec::from_raw_parts(b.ptr, b.len, b.cap)); }
}

// src/MyLib/ImageOps.cs — 사람이 쓰는 얼굴
namespace MyLib;

public static class ImageOps
{
    /// <summary>이미지를 리사이즈해 WebP 로 인코딩합니다.</summary>
    /// <returns>호출자가 소유하는 새 배열.</returns>
    public static byte[] ResizeToWebp(ReadOnlySpan<byte> src,
                                      int width, int height,
                                      float quality = 0.8f)
    {
        NativeMethods.Buf buf = default;
        unsafe
        {
            fixed (byte* p = src)
            {
                Check.Throw(NativeMethods.mylib_resize_webp(
                    p, (nuint)src.Length,
                    (uint)width, (uint)height, quality, &buf));
            }
            try
            {
                return new ReadOnlySpan<byte>(buf.ptr, (int)buf.len).ToArray();
            }
            finally { NativeMethods.mylib_buf_free(buf); }   // ★
        }
    }

    /// 복사 없이 바로 스트림으로 흘려보내는 버전 ★
    public static async Task WriteWebpAsync(ReadOnlyMemory<byte> src,
        int w, int h, Stream dst, CancellationToken ct = default)
    {
        NativeMethods.Buf buf = default;
        using var pin = src.Pin();
        unsafe
        {
            Check.Throw(NativeMethods.mylib_resize_webp(
                (byte*)pin.Pointer, (nuint)src.Length,
                (uint)w, (uint)h, 0.8f, &buf));
        }
        try
        {
            // Rust 힙을 그대로 가리키는 Memory 를 만들어 씁니다
            using var mm = new UnmanagedMemoryManager(buf);
            await dst.WriteAsync(mm.Memory, ct);
        }
        finally { NativeMethods.mylib_buf_free(buf); }
    }
}
