# 시각화 모델 카탈로그 (2026-08-28 신설 · 30종)

> **디자인 규칙**은 [`DIAGRAM-STYLE.md`](DIAGRAM-STYLE.md) 가 정답입니다(색·박스·화살촉·글자·viewBox).
> 이 문서는 그 규칙 **안에서 어떤 모양을 고를 것인가**를 다룹니다.
> 스니펫 원본 `shared/models/*.html` · 갤러리 `npm run diag:lab` → `public/diag-lab/index.html`

## 왜 만들었나

기존 다이어그램 1,340개를 구성 요소로 분류해 봤습니다.

| 모양 | 개수 | 비율 |
|---|---|---|
| 사각 박스 + 직선 화살표 | 835 | 62% |
| 사각 박스 나열 | 458 | 34% |
| 원 노드 | 17 | 1.3% |
| 그 밖(다각형·곡선·축) | 30 | 2% |

`<ellipse>` 6개 · `<polygon>` 1개 · 좌표축과 채워진 영역은 **0개**였습니다.
그림의 종류가 부족한 게 아니라 **어휘가 없어서** 매번 같은 걸 그린 것입니다.
시간 축이 필요한 이야기도 박스로, 수량 비교도 박스로 그렸습니다.

그래서 ① 공통 CSS 에 어휘를 추가하고(`shared/css/06-diag.css` §7)
② 복붙할 수 있는 30종의 본보기를 두고 ③ 고르는 기준을 적었습니다.

## 고르는 순서

1. **이 그림으로 전할 한 문장을 먼저 적습니다.** ("N+1 이 전체 지연의 73%다")
2. 그 문장이 아래 다섯 묶음 중 무엇인지 정합니다.
3. 묶음 안에서 모델을 고릅니다.
4. 다 그린 뒤, ①의 문장이 `.cap` 에 그대로 들어가는지 봅니다.
   **들어가지 않으면 모델 선택이 틀린 것입니다.**

| 묶음 | 묻는 것 | 모델 |
|---|---|---|
| **구조** | 무엇이 무엇과 이어져 있나 | flow · layer · pipe · swim · seq · state · tree · graph |
| **관계·배치** | 두 축으로 어디에 놓이나 | matrix · quad · venn · hub · orbit |
| **시간** | 언제 · 얼마나 걸리나 | timeline · gantt · waterfall · cycle |
| **수량** | 얼마나 되나 | bar · line · stack · sankey · funnel · scatter · gauge · spark |
| **개념** | 이것을 뜯어 보면 | memory · pyramid · decision · compare · anatomy |

## 30종 — 언제 쓰고 언제 피하나

### 구조 (8종)

| id | 이름 | 이럴 때 | 피할 때 |
|---|---|---|---|
| `flow` | 흐름도 | 단계 4~6개가 한 줄로 읽힐 때. 기본형 | 단계 8개 초과 · 되돌아가는 경로가 많으면 |
| `layer` | 레이어 스택 | 아래가 위를 떠받치는 계층 | 층끼리 서로 호출하면 (그건 graph) |
| `pipe` | 셰브론 파이프라인 | 되돌아오지 않는 단방향 가공 | 분기가 있으면 decision |
| `swim` | 스윔레인 | 일이 역할 사이를 오갈 때 | 주체가 하나면 flow |
| `seq` | 시퀀스 | 왕복 호출·프로토콜·인증 절차 | 왕복 3회 이하면 flow |
| `state` | 상태 기계 | 되돌아오는 전이가 있을 때 | 되돌아오지 않으면 flow |
| `tree` | 트리·계층 | 부모-자식으로 갈라지는 구조 | 자식이 부모를 여럿 가지면 graph |
| `graph` | 의존 그래프 | 순환 의존·호출 관계망 | 노드 8개 초과면 matrix |

### 관계·배치 (5종)

| id | 이름 | 이럴 때 | 피할 때 |
|---|---|---|---|
| `matrix` | 매트릭스·히트맵 | 행×열 조합마다 값이 있을 때 | 값이 한 축에만 있으면 bar |
| `quad` | 사분면 | 축 두 개로 판단이 끝날 때 | 기준이 셋 이상이면 표 |
| `venn` | 벤 다이어그램 | 겹친 영역에 **이름을 붙일 수 있을 때** | 이름을 못 붙이면 그리지 않음 |
| `hub` | 허브 앤 스포크 | 중심이 뚜렷할 때 | 중심이 없으면 graph |
| `orbit` | 동심원 | 안과 밖이 뜻을 가질 때(변경 비용) | 순서가 있는 단계면 pipe |

### 시간 (4종)

| id | 이름 | 이럴 때 | 피할 때 |
|---|---|---|---|
| `timeline` | 타임라인 | 시점이 핵심(장애·버전 역사) | 길이가 중요하면 gantt |
| `gantt` | 간트·스케줄 바 | 겹침과 마감이 핵심(배치 창) | 한 줄 소요 분해면 waterfall |
| `waterfall` | 워터폴 트레이스 | 한 요청의 구간별 소요 | 여러 작업 일정이면 gantt |
| `cycle` | 순환·생명주기 | 반복이 본질일 때 | 한 번 끝나면 flow |

### 수량 (8종)

| id | 이름 | 이럴 때 | 피할 때 |
|---|---|---|---|
| `bar` | 막대 | 대상별 값 크기 비교 | 시간 변화면 line |
| `line` | 라인·영역 | 시간에 따른 변화 | **축을 두 개 쓰지 말 것** — 그림을 나눔 |
| `stack` | 100% 비율 바 | 합이 100%인 구성비 | 조각 5개 초과면 '기타'로 묶기 |
| `sankey` | 산키·흐름 밴드 | 양이 갈라지고 합쳐질 때 | 양이 중요하지 않으면 flow |
| `funnel` | 깔때기 | 단계마다 줄어들 때 | 줄지 않으면 pipe |
| `scatter` | 산점도 | 두 값의 상충 관계 | 점 6개 미만이면 표 |

기존 `.bx` · `.fl` · `.ln` · `.lbl` 은 그대로 두고 **추가**된 것들입니다.

열 가이드 `parts/10-body-open.html` 에 모두 들어가 있습니다.

### 계열 색을 쓸 때 지킬 것

- **의미 색과 섞지 않습니다.** `.bx-ok`(정답) · `.bx-warn`(틀림)은 상태, `.s1~.s4`는 구분입니다.
- **색만으로 구분하게 두지 않습니다.** 직접 라벨이나 범례를 반드시 함께 둡니다.
- 4색은 색각 이상 시뮬레이션을 통과한 조합입니다(인접 쌍 최소 ΔE 19.5 deutan / 27.0 정상).
  **5번째 색을 만들지 마세요.** '기타'로 묶거나 그림을 나눕니다.
- 순차 램프(`.h0~.h5`)는 **한 가지 색의 명도**입니다. 무지개로 칠하면 크기 순서가 사라집니다.
- 발산 램프(`.d-n2~.d-p2`)의 가운데(`.d-0`)는 반드시 무채색입니다.

## 다른 프로젝트로 옮기기

이 카탈로그는 이 저장소 밖에서도 씁니다. 필요한 것은 세 가지뿐입니다.

1. **CSS 토큰 12개** — `--line` `--line-soft` `--panel` `--panel-2` `--bg` `--cyan`
   `--ink` `--ink-2` `--dim` `--dim-2` `--mono` `--ease`
   (`shared/css/01-tokens-base-layout.css` 의 `:root` 에서 그대로 복사)
2. **`shared/css/06-diag.css`** — 이 파일 하나가 `.diag` 의 전부입니다. 다른 CSS 에 의존하지 않습니다.
3. **화살촉 마커 `<defs>`** — `parts/10-body-open.html` 의 숨은 SVG 블록(8개 마커).
   `url(#...)` 은 문서 전체에서 해석되므로 페이지에 한 번만 두면 됩니다.

그 다음 `shared/models/*.html` 의 스니펫을 복사해 라벨과 좌표만 바꿉니다.
**런타임 JS 가 필요 없습니다** — 오프라인·인쇄에서도 그대로 나옵니다
(움직이는 흐름선 `.fl` 과 스크롤 리빌 `.rv` 만 각각 CSS 애니메이션·관찰자에 의존합니다.
`.rv` 를 안 쓰는 곳이라면 그 클래스만 빼면 됩니다).

라이브러리(D3·Mermaid·Cytoscape)를 쓰지 않는 이유는 `DIAGRAM-STYLE.md` §7 에 있습니다 —
단일 HTML 배포 크기, 런타임 JS 없음, 한글 라벨 폭 실측 워크플로가 자동 배치와 충돌.
