SECTION 01

데이터베이스란 무엇인가

"엑셀로 하면 되지 않나요?" — 맞습니다. 혼자 쓰면 엑셀로 충분합니다. 데이터베이스가 필요해지는 순간은 혼자가 아닐 때입니다.

데이터베이스의 본질은 저장이 아니라 동시에 들어온 요청을 한 줄로 세우는 것입니다.

엑셀 파일로 버티다 반드시 만나는 네 가지 벽

벽 1
동시에 열면 덮어쓴다 A가 연 파일을 B도 열어 각자 저장하면, 나중에 저장한 쪽만 남고 앞의 작업은 사라집니다.
▼
벽 2
같은 정보를 여러 곳에 적게 된다 주문 시트마다 고객 주소를 적어 두면, 주소가 바뀔 때 수백 줄을 전부 고쳐야 합니다. 하나라도 놓치면 데이터가 서로 다릅니다.
▼
벽 3
잘못된 값이 그냥 들어간다 수량 칸에 "세 개", 금액에 −5000이 적혀도 엑셀은 막지 않습니다. 집계할 때 터집니다.
▼
벽 4
커지면 느려지고, 반쯤 저장되면 복구가 안 된다 수십만 행부터 버벅이고, 저장 중 정전이 나면 파일 자체가 깨집니다.
데이터베이스는 이 네 가지를 구조적으로 해결하는 프로그램입니다. 동시 접근을 정리해 주고(트랜잭션·락), 중복을 없애 한 곳만 고치게 하고(정규화·관계), 잘못된 값을 아예 못 넣게 막고(제약조건), 수억 건에서도 빠르게 찾아 주며(인덱스), 중간에 죽어도 되살립니다(로그·복구).
DB는 문장을 받는 즉시 실행하지 않습니다. "어떻게 읽는 게 가장 싼가"를 먼저 계산하고 움직입니다.

용어 다섯 개면 시작할 수 있습니다

용어엑셀로 치면설명
데이터베이스엑셀 파일 하나서로 관련된 표들을 담는 그릇. 서비스마다 보통 하나씩 만듭니다.
테이블시트 한 장같은 종류의 데이터를 모은 표. member, orders 처럼 이름을 붙입니다.
행(row)가로 한 줄데이터 하나. 회원 한 명, 주문 한 건.
열(column)세로 한 칸속성 하나. 이름·이메일·금액. 타입이 정해져 있습니다.
SQL수식 · 필터 · 피벗데이터를 넣고 꺼내는 공용 언어. 어느 DB에서나 큰 틀은 같습니다.

곧 만나게 될 낯선 말들 — 미리 한 줄씩

아래 용어들은 이 가이드 곳곳에서 계속 나옵니다. 지금 다 외울 필요는 없어요. 읽다가 모르는 말이 나오면 이 표로 돌아와서 확인하면 됩니다.

용어쉽게 말하면
스키마(schema)표들의 설계도이자 폴더. "어떤 표가 있고, 각 표에 어떤 칸이 어떤 타입으로 있는가"라는 구조 전체를 뜻하고, PostgreSQL·Oracle에서는 표들을 담는 폴더 이름으로도 씁니다. "스키마를 만든다" = 표 구조를 정한다.
쿼리(query)DB에 보내는 질문·요청 한 건. SELECT … 한 문장이 쿼리 하나입니다. "쿼리를 날린다" = 요청을 보낸다.
기본키(PK)행마다 붙는 겹치지 않는 번호표(회원번호·주문번호). 이걸로 그 행을 정확히 집어냅니다.
외래키(FK)다른 표의 번호표를 적어 둔 칸. 주문 표의 "회원번호" 칸이 회원 표를 가리키는 식으로, 표와 표를 잇습니다.
인덱스(index)책 뒤의 찾아보기. 미리 만들어 두면 수백만 줄에서도 몇 번 만에 찾습니다. 조회를 빠르게 하는 1순위 도구.
트랜잭션여러 변경을 전부 성공 아니면 전부 취소로 묶는 단위. 계좌 이체가 "출금만 되고 입금은 안 되는" 사고를 막습니다.
커밋 · 롤백트랜잭션의 마무리 두 가지 — 커밋 = 확정 저장, 롤백 = 없던 일로 되돌리기.
CRUD데이터 다루기 4종 세트 — Create(넣기) · Read(읽기) · Update(고치기) · Delete(지우기). 앱이 DB에 하는 일의 전부입니다.
서버 · 클라이언트DB 프로그램이 서버(항상 떠서 요청을 기다림), 접속하는 내 쪽 도구·앱이 클라이언트입니다.
마이그레이션표 구조를 바꾸는 작업(또는 그 기록). 칸 추가·이름 변경 같은 변경을 파일로 남겨 순서대로 적용합니다.

DBMS · RDBMS · NoSQL — 이름 정리

  • DBMS — Database Management System. 데이터베이스를 관리하는 프로그램 자체를 말합니다. "MySQL을 설치한다"는 곧 DBMS를 설치한다는 뜻입니다.
  • RDBMS — 관계형(Relational) DBMS. 표와 표를 키로 연결하는 방식. 이 가이드가 다루는 네 DB가 전부 여기에 속하며, 업무 시스템의 90% 이상이 관계형입니다.
  • NoSQL — 표 구조를 쓰지 않는 DB들(MongoDB·Redis·Cassandra 등)의 통칭. 관계형을 대체하는 게 아니라 옆에 두고 씁니다. 캐시는 Redis, 본체는 관계형이 가장 흔한 구성입니다. 이 가이드의 ⚡ Redis 탭(r01에 상세 비교)과 🍃 MongoDB 탭에서 전용으로 다룹니다.
흔한 오해 — "요즘은 NoSQL이 대세 아닌가요?" 아닙니다. 돈·주문·회원처럼 정확해야 하는 데이터는 여전히 관계형이 기본입니다. NoSQL은 캐시·로그·검색처럼 목적이 분명한 자리에 씁니다. 처음 배운다면 관계형부터가 맞습니다.

고르는 기준, 세 문장

🟢 지금 배우는 중이라면
  • SQLite로 SQL 문법을 익히세요 — 설치가 없어 바로 시작합니다
  • 그다음 PostgreSQL을 도커로 띄워 서버형을 경험합니다
  • 취업 목표가 SI·금융이면 Oracle도 한 번은 만져 보세요
🔵 서비스를 만든다면
  • 회사에 이미 쓰는 DB가 있으면 그것이 정답입니다
  • 새로 정할 수 있다면 PostgreSQL이 무난합니다
  • 워드프레스·커머스 솔루션을 쓴다면 MySQL이 사실상 강제됩니다
🟣 규모가 커지면
  • DB 종류보다 인덱스·쿼리·스키마 설계가 성능을 좌우합니다
  • 앞단에 Redis 캐시를 두는 구성이 사실상 표준입니다
  • 읽기 부하는 복제본으로, 쓰기 한계는 샤딩으로 나눕니다
솔직한 조언 — DB 선택으로 고민하는 시간보다 SQL을 제대로 익히는 시간이 훨씬 값집니다. SELECT·JOIN·인덱스는 네 DB에서 거의 같고, 방언 차이는 이 가이드의 각 탭에서 대조표로 30분이면 따라잡습니다.
표로 안 담기는 데이터가 보이기 시작했다면 — 캐시·세션·순위표는 ⚡ Redis 탭, 구조가 자꾸 바뀌는 JSON 데이터는 🍃 MongoDB 탭에서 다룹니다. NoSQL이 처음이라면 r01 (NoSQL vs RDBMS)부터 읽으세요.
고민이 길어지면 PostgreSQL 로 시작하세요 — 나중에 후회할 일이 가장 적습니다.
SECTION 03

설치 ① Windows

윈도우는 설치 파일을 받아 실행하는 방식이 가장 쉽습니다. 설치 중에 나오는 비밀번호와 포트 번호는 반드시 메모하세요 — 나중에 다시 보기 어렵습니다.

PostgreSQL — 추천 경로

  1. 공식 배포처(EDB)에서 Windows x86-64 인스톨러를 받습니다 — 검색어: postgresql windows installer
  2. 실행 → 설치 경로는 기본값 그대로 → 구성 요소는 전부 체크(pgAdmin·Command Line Tools 포함)
  3. superuser(postgres) 비밀번호 입력 — ★ 메모해 두세요
  4. 포트 5432 그대로 → 로케일 기본값 → 설치 완료
  5. 마지막의 Stack Builder는 체크 해제해도 됩니다 (나중에 필요할 때 설치)
# 설치 확인 — PowerShell 을 새로 열고
psql --version
# psql (PostgreSQL) 18.x

# 접속 (비밀번호를 물어봅니다)
psql -U postgres -h localhost -p 5432
psql 을 못 찾는다고 나오면 — PATH 문제입니다. C:\Program Files\PostgreSQL\18\bin 을 시스템 환경 변수 Path에 추가하고 터미널을 새로 여세요(기존 창은 옛 PATH를 그대로 씁니다).

MySQL

  1. MySQL Installer for Windows를 받습니다 (community 판)
  2. Setup Type은 Developer Default 또는 Server only
  3. Authentication Method — Strong Password Encryption(기본값) 선택. 오래된 클라이언트를 써야 한다면 Legacy를 고르지만, 가급적 기본값을 유지하세요
  4. root 비밀번호 입력 — ★ 메모
  5. Windows Service 로 등록 → 이름 기본값(MySQL80) → 실행
mysql --version
mysql -u root -p            # 비밀번호 입력 후 접속

SQLite — 설치라고 할 것도 없습니다

  1. sqlite.org 다운로드 페이지에서 sqlite-tools-win-x64-*.zip 을 받습니다
  2. 압축을 풀어 C:\sqlite 같은 폴더에 두고, 그 경로를 Path에 추가합니다
  3. 끝입니다. 서비스도 계정도 포트도 없습니다
sqlite3 --version
sqlite3 shop.db             # 파일이 없으면 새로 만들어집니다
# sqlite> .quit  로 빠져나옵니다
파이썬이 설치돼 있다면 SQLite는 이미 들어 있습니다. python -c "import sqlite3; print(sqlite3.sqlite_version)" 로 바로 확인됩니다.

Oracle — 윈도우 직접 설치는 권하지 않습니다

Oracle Database Free 를 윈도우에 직접 설치할 수는 있지만, 설치 용량이 크고 리스너·서비스 설정에서 막히는 일이 많습니다. 학습 목적이라면 다음 섹션의 Docker 방식을 강력히 권합니다. 회사에서 이미 운영 중인 오라클에 접속만 하면 되는 경우라면, Oracle Instant Client + SQL Developer 만 설치하면 충분합니다.

포트가 이미 쓰이고 있다면 — 설치 중 "port in use" 가 나오면 다른 프로그램이 그 포트를 쓰고 있습니다. netstat -ano | findstr :5432 로 점유 프로세스를 찾거나, 설치 시 포트를 5433 처럼 바꾸세요. 바꿨다면 접속할 때도 그 포트를 써야 합니다.
SECTION 04

설치 ② macOS · Linux

맥과 리눅스는 패키지 매니저 명령 한 줄이면 끝납니다. 설치 후 서비스 시작까지가 한 세트라는 것만 기억하세요.

macOS (Homebrew)

# Homebrew 가 없다면 먼저 설치 (brew.sh 참고)

# PostgreSQL
brew install postgresql@18
brew services start postgresql@18      # 백그라운드 자동 실행 등록
psql postgres                          # 내 계정 이름으로 바로 접속됩니다

# MySQL
brew install mysql
brew services start mysql
mysql_secure_installation              # root 비밀번호 설정 (권장)
mysql -u root -p

# SQLite — macOS 에는 이미 들어 있습니다
sqlite3 --version
Homebrew 의 PostgreSQL 은 특이합니다 — postgres 계정이 아니라 내 맥 사용자 이름으로 DB 계정이 만들어집니다. 그래서 psql postgres 만으로 비밀번호 없이 접속됩니다. 리눅스·도커와 다르니 헷갈리지 마세요.

Ubuntu · Debian (apt)

# PostgreSQL
sudo apt update
sudo apt install -y postgresql postgresql-contrib
sudo systemctl enable --now postgresql      # 부팅 시 자동 시작 + 지금 시작
sudo -u postgres psql                       # postgres 계정으로 전환해 접속

# MySQL
sudo apt install -y mysql-server
sudo systemctl enable --now mysql
sudo mysql_secure_installation
sudo mysql -u root                          # 우분투 기본은 소켓 인증이라 sudo 로 접속

# MariaDB (MySQL 대신)
sudo apt install -y mariadb-server
sudo systemctl enable --now mariadb
sudo mariadb

# SQLite
sudo apt install -y sqlite3

RHEL · Rocky · Alma (dnf)

sudo dnf install -y postgresql-server postgresql-contrib
sudo postgresql-setup --initdb              # ★ 이 단계를 빠뜨리면 서비스가 안 뜹니다
sudo systemctl enable --now postgresql

sudo dnf install -y mysql-server
sudo systemctl enable --now mysqld
sudo grep 'temporary password' /var/log/mysqld.log   # 초기 임시 비밀번호 확인

설치 후 반드시 확인하는 세 가지

SECTION 05

설치 ③ Docker — 선택 사항

이 절은 필수가 아닙니다. 앞의 ①(Windows)·②(macOS·Linux) 방식으로 이미 설치했다면 그대로 다음 섹션으로 넘어가세요. 도커는 설치 없이 명령 한 줄로 DB를 띄우는 또 하나의 방법일 뿐입니다 — PC가 지저분해지지 않고 버전 실험이 쉬워, 쓸 줄 알면 편리한 선택지입니다.

도커, 해야 하나요? — 아니요. DB 공부에는 ①·② 직접 설치로 충분합니다. 도커가 빛나는 순간은 ⓐ 여러 DB·여러 버전을 갈아 끼우며 실험할 때, ⓑ 팀 전체가 같은 개발 환경을 맞출 때(compose), ⓒ PC를 깨끗하게 유지하고 싶을 때입니다. 지금 안 써도 되고, 필요해지면 그때 돌아와도 됩니다.
도커에서 기억할 것은 둘입니다 — 포트는 바깥:안쪽, 그리고 남기고 싶은 데이터는 볼륨에.
준비물 — Docker Desktop(Windows·macOS) 또는 Docker Engine(Linux) 하나면 됩니다. 설치 후 docker --version 이 나오면 준비 완료입니다.

한 줄로 띄우기

# PostgreSQL 18
docker run -d --name pg \
  -e POSTGRES_PASSWORD=devpass \
  -e POSTGRES_DB=shop \
  -p 5432:5432 \
  -v pgdata:/var/lib/postgresql/data \
  postgres:18

# MySQL 8.4 LTS
docker run -d --name my \
  -e MYSQL_ROOT_PASSWORD=devpass \
  -e MYSQL_DATABASE=shop \
  -p 3306:3306 \
  -v mydata:/var/lib/mysql \
  mysql:8.4

# MariaDB 11.8 LTS
docker run -d --name maria \
  -e MARIADB_ROOT_PASSWORD=devpass \
  -e MARIADB_DATABASE=shop \
  -p 3307:3306 \
  -v mariadata:/var/lib/mysql \
  mariadb:11.8

# Oracle Database Free 23ai (공식 컨테이너 레지스트리)
docker run -d --name ora \
  -e ORACLE_PWD=devpass \
  -p 1521:1521 \
  container-registry.oracle.com/database/free:latest
-v 를 빼면 데이터가 사라집니다. 컨테이너를 지우면 안의 파일도 같이 지워집니다. -v pgdata:/var/lib/postgresql/data 처럼 볼륨을 붙여야 컨테이너를 지웠다 다시 만들어도 데이터가 남습니다.

접속하기

# 컨테이너 안으로 들어가서 접속
docker exec -it pg psql -U postgres -d shop
docker exec -it my mysql -u root -p shop
docker exec -it ora sqlplus system/devpass@//localhost:1521/FREEPDB1

# 내 PC의 클라이언트로 접속 (포트를 열어 뒀으므로)
psql -h localhost -p 5432 -U postgres -d shop
mysql -h 127.0.0.1 -P 3306 -u root -p shop
MySQL 접속에서 -h localhost 대신 -h 127.0.0.1 을 쓰세요. MySQL 클라이언트는 localhost 를 유닉스 소켓으로 해석해서 도커로 띄운 서버에 안 붙는 일이 자주 있습니다. IP를 직접 적으면 TCP로 붙습니다.

팀이 함께 쓸 때 — docker compose 한 파일

# compose.yaml  ·  docker compose up -d 로 전부 기동
services:
  postgres:
    image: postgres:18
    environment:
      POSTGRES_PASSWORD: devpass
      POSTGRES_DB: shop
      TZ: Asia/Seoul
    ports: ["5432:5432"]
    volumes:
      - pgdata:/var/lib/postgresql/data
      - ./init:/docker-entrypoint-initdb.d   # 최초 1회 실행되는 .sql 넣는 곳
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U postgres"]
      interval: 5s
      retries: 10

  mysql:
    image: mysql:8.4
    environment:
      MYSQL_ROOT_PASSWORD: devpass
      MYSQL_DATABASE: shop
      TZ: Asia/Seoul
    command: --character-set-server=utf8mb4 --collation-server=utf8mb4_0900_ai_ci
    ports: ["3306:3306"]
    volumes:
      - mydata:/var/lib/mysql

volumes:
  pgdata:
  mydata:
/docker-entrypoint-initdb.d 는 아주 유용합니다. 이 폴더에 .sql 파일을 넣어 두면 DB가 처음 만들어질 때 자동 실행됩니다. 다음 섹션의 샘플 스키마를 여기에 넣어 두면, 팀원 누구나 docker compose up 한 번으로 같은 데이터를 갖게 됩니다. (이미 데이터가 있으면 실행되지 않습니다)

SECTION 07

계정 · 데이터베이스 · 권한

관리자 계정으로 모든 것을 하지 마세요. 앱마다 전용 계정을 만들고 필요한 권한만 주는 것이 기본이자, 사고가 났을 때 피해를 줄이는 유일한 방법입니다.

PostgreSQL
-- 관리자(postgres)로 접속한 상태에서
CREATE DATABASE shop;
CREATE USER app WITH PASSWORD 'strong-pass';

-- 접속 허용
GRANT CONNECT ON DATABASE shop TO app;

-- shop 으로 이동한 뒤 (\c shop)
GRANT USAGE ON SCHEMA public TO app;
GRANT SELECT, INSERT, UPDATE, DELETE
  ON ALL TABLES IN SCHEMA public TO app;

-- 앞으로 만들어질 표에도 자동 적용
ALTER DEFAULT PRIVILEGES IN SCHEMA public
  GRANT SELECT, INSERT, UPDATE, DELETE TO app;
MySQL / MariaDB
CREATE DATABASE shop
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_0900_ai_ci;

-- 계정은 '이름'@'접속위치' 가 한 세트
CREATE USER 'app'@'%' IDENTIFIED BY 'strong-pass';

GRANT SELECT, INSERT, UPDATE, DELETE
  ON shop.* TO 'app'@'%';

FLUSH PRIVILEGES;
Oracle (23ai · PDB 안에서)
-- PDB 로 이동
ALTER SESSION SET CONTAINER = FREEPDB1;

CREATE USER app IDENTIFIED BY "strong-pass"
  DEFAULT TABLESPACE users
  QUOTA UNLIMITED ON users;

GRANT CREATE SESSION TO app;
GRANT CREATE TABLE, CREATE SEQUENCE TO app;
-- 남의 스키마 접근은 객체 단위로
GRANT SELECT ON hr.member TO app;
SQLite
# 계정도 권한도 없습니다.
# 접근 통제 = 파일 권한 그 자체입니다.

권한을 주는 세 가지 원칙

  • 필요한 것만 — 앱 계정에 DROP TABLE 권한은 필요 없습니다. SQL 인젝션이 성공해도 테이블을 못 지우게 됩니다.
  • 용도별로 나눈다 — 읽기 전용 계정(분석·리포트), 읽기·쓰기 계정(앱), 스키마 변경 계정(마이그레이션 전용)을 분리합니다.
  • 관리자 계정은 사람만 — postgres·root·SYS 로 애플리케이션을 붙이지 않습니다. 사고 시 원인 추적조차 불가능해집니다.
비밀번호를 코드에 적지 마세요. 소스에 넣으면 깃 기록에 영원히 남습니다. 환경 변수나 시크릿 관리 도구를 쓰고, 실수로 커밋했다면 파일을 지우는 것만으로는 안 되고 비밀번호를 반드시 교체해야 합니다.
접속 오류의 절반은 문법이 아니라 이 네 겹 중 어디가 안 맞는지의 문제입니다.
SECTION 08

실습용 샘플 스키마 만들기

이 가이드의 거의 모든 예제가 아래 작은 쇼핑몰 데이터로 돌아갑니다. 한 번만 만들어 두면 끝까지 복붙해서 따라올 수 있습니다.

표준 SQL 버전 (PostgreSQL · MySQL · SQLite 공통에 가깝게)

-- 회원
CREATE TABLE member (
    id          INTEGER      PRIMARY KEY,
    name        VARCHAR(50)  NOT NULL,
    email       VARCHAR(120) UNIQUE,
    grade       VARCHAR(10)  NOT NULL DEFAULT 'BASIC',   -- BASIC / SILVER / GOLD
    city        VARCHAR(30),
    joined_at   DATE         NOT NULL
);

-- 상품
CREATE TABLE product (
    id          INTEGER       PRIMARY KEY,
    name        VARCHAR(80)   NOT NULL,
    category    VARCHAR(30)   NOT NULL,
    price       DECIMAL(12,2) NOT NULL CHECK (price >= 0),
    stock       INTEGER       NOT NULL DEFAULT 0
);

-- 주문 (회원 1명 : 주문 N건)
CREATE TABLE orders (
    id          INTEGER       PRIMARY KEY,
    member_id   INTEGER       NOT NULL,
    ordered_at  DATE          NOT NULL,
    status      VARCHAR(15)   NOT NULL DEFAULT 'PAID',   -- PAID / SHIPPED / CANCELED
    FOREIGN KEY (member_id) REFERENCES member(id)
);

-- 주문 상세 (주문 1건 : 품목 N개)
CREATE TABLE order_item (
    id          INTEGER       PRIMARY KEY,
    order_id    INTEGER       NOT NULL,
    product_id  INTEGER       NOT NULL,
    qty         INTEGER       NOT NULL CHECK (qty > 0),
    unit_price  DECIMAL(12,2) NOT NULL,
    FOREIGN KEY (order_id)   REFERENCES orders(id),
    FOREIGN KEY (product_id) REFERENCES product(id)
);

-- 첫 조인 — 누가 언제 얼마어치 샀나
SELECT m.name, o.id AS order_no, o.ordered_at,
       SUM(oi.qty * oi.unit_price) AS 금액
FROM   member m
JOIN   orders o     ON o.member_id = m.id
JOIN   order_item oi ON oi.order_id = o.id
GROUP  BY m.name, o.id, o.ordered_at
ORDER  BY o.ordered_at;
name order_no ordered_at 금액 김하늘 1001 2026-01-05 103000 박바다 1002 2026-01-07 289000 …
이 표들이 왜 이렇게 나뉘어 있는지(주문과 주문상세가 왜 따로인지)는 ⚙️ 설계 · 튜닝 탭 t01 정규화에서 다룹니다. 지금은 "이렇게 생겼구나" 정도만 보고 넘어가도 충분합니다.
주문과 상품의 다대다 관계를 order_items 가 풀어 줍니다 — 가장 흔한 모양입니다.
SECTION 09

접속 오류 사전

접속이 안 되는 이유는 거의 정해져 있습니다. ① 서버가 안 떴다 → ② 주소·포트가 다르다 → ③ 계정·비밀번호 → ④ 방화벽 순서로 확인하세요.

메시지원인과 해결
Connection refused 서버가 안 떠 있거나 포트가 다릅니다. systemctl status postgresql · docker ps 로 확인. 도커라면 -p 5432:5432 를 빠뜨리지 않았는지 보세요.
timeout / 무응답 방화벽·보안 그룹에서 막힌 것입니다. refused(거부)와 timeout(무응답)의 차이가 진단의 핵심입니다. 클라우드라면 인바운드 규칙을 확인하세요.
password authentication failed 비밀번호가 틀렸습니다. 도커에서 이미 볼륨이 있으면 POSTGRES_PASSWORD 를 바꿔도 반영되지 않습니다 — 볼륨을 지우고 다시 만들어야 합니다.
no pg_hba.conf entry for host PostgreSQL이 그 IP의 접속을 허용하지 않았습니다. pg_hba.conf 에 host all all <대역> scram-sha-256 을 추가하고 reload.
Access denied for user 'app'@'1.2.3.4' MySQL 계정의 접속 위치가 안 맞습니다. 'app'@'localhost' 만 만들었다면 외부에서는 못 붙습니다. 'app'@'%' 를 추가로 만드세요.
ORA-12541: TNS:no listener 오라클 리스너가 안 떠 있습니다. lsnrctl status 로 확인, lsnrctl start 로 기동합니다.
ORA-12514: service_name not known 리스너는 살아 있지만 서비스명이 틀렸습니다. FREE 인지 FREEPDB1 인지 확인하세요 — 23ai Free 는 보통 FREEPDB1 입니다.
ORA-01017: invalid username/password 계정·비밀번호 오류. 오라클은 따옴표 없이 만든 비밀번호가 대문자로 저장되던 시절의 습관 때문에 헷갈리기 쉽습니다. 큰따옴표로 감싸 만들었다면 대소문자를 그대로 입력해야 합니다.
database is locked (SQLite) 다른 연결이 쓰기 중입니다. WAL 모드 + busy_timeout 으로 대부분 해결됩니다 → ✒️ SQLite3 탭 s11 참고.
한글이 ??? 로 보임 문자셋 문제입니다. MySQL이라면 100% utf8mb4 설정 → 🐬 MySQL 탭 m04 참고.
too many connections 커넥션을 반납하지 않고 계속 만들고 있습니다. 앱의 커넥션 풀 설정을 확인하세요 → ⚙️ 튜닝 탭 t13.

막혔을 때 순서대로 치는 명령

# 1) 서버가 살아 있나
docker ps                       # 도커라면
systemctl status postgresql     # 직접 설치라면

# 2) 포트가 열려 있나 (LISTEN 이 보여야 함)
ss -lntp | grep -E '5432|3306|1521'

# 3) 네트워크가 닿나 (다른 PC에서)
nc -zv 10.0.1.20 5432

# 4) 로그에 뭐라고 나오나  ← 대부분 여기에 답이 있습니다
docker logs --tail 50 pg
sudo tail -50 /var/log/postgresql/postgresql-18-main.log
로그를 먼저 보세요. 접속 문제의 90%는 서버 로그에 원인이 그대로 적혀 있습니다. 추측으로 설정을 이것저것 바꾸는 것보다 훨씬 빠릅니다.
