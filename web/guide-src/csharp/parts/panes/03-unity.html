UNITY 01

설치하고 화면 익히기

Unity Hub 로 버전을 관리하고, 창 다섯 개의 역할만 알면 시작할 수 있습니다.

  • 모듈에서 빌드 대상 체크(Android · iOS · WebGL · Windows)

창 다섯 개

Scene
세상을 배치하는 곳 여기서 물체를 놓고 옮깁니다. 실제 실행 화면이 아닙니다.
Game
플레이어가 볼 화면 카메라가 비추는 결과. ▶ 을 누르면 여기가 돕니다.
Hierarchy
지금 씬에 있는 것들의 목록 부모–자식 관계를 여기서 만듭니다.
Inspector
고른 것의 부품과 설정 스크립트의 public 변수도 여기에 나타납니다.
Project
프로젝트 파일 전체 Assets 폴더. 이미지·소리·스크립트가 전부 여기 있습니다.
플레이(▶) 중에 바꾼 값은 저장되지 않습니다. 멈추면 원래대로 돌아갑니다 — 모르고 한 시간 작업하다 날리는 것이 첫날의 통과의례입니다. 값을 확정하려면 정지 후 다시 입력하세요.

설치 끝났으면 — 5분 만에 첫 실행까지

따라 하기 — 굴러가는 공 하나

1. Hierarchy 우클릭 → 3D Object → Plane   (바닥)
2. Hierarchy 우클릭 → 3D Object → Sphere  (공)
3. Sphere 를 클릭 → Inspector 아래 [Add Component]
   → Rigidbody 추가                        (중력을 받게)
4. Sphere 의 Position Y 를 5 로            (공중에 띄우기)
5. ▶ 재생 → 공이 떨어져 바닥에 멈추면 성공

코드 한 줄 없이 물리가 도는 장면이 만들어졌습니다. Unity 개발은 이 위에 스크립트라는 부품을 얹는 일입니다.

// 6. Project 우클릭 → Create → C# Script → "Roller"
// 7. 이 파일을 Sphere 로 드래그 (= 부품으로 붙이기)
using UnityEngine;

public class Roller : MonoBehaviour
{
    [SerializeField] private float power = 10f;

    void Update()
    {
        float h = Input.GetAxis("Horizontal");   // A·D / ←→
        float v = Input.GetAxis("Vertical");     // W·S / ↑↓
        GetComponent<Rigidbody>()
            .AddForce(new Vector3(h, 0, v) * power);
    }
}

UNITY 02

씬 · 게임오브젝트 · 컴포넌트

Unity 의 전부입니다. 이 세 단어의 관계를 잡으면 나머지는 사용법일 뿐입니다.

게임오브젝트는 빈 상자입니다. 무엇을 할 수 있는지는 붙인 컴포넌트가 정합니다.

코드에서 다루기

using UnityEngine;

public class Player : MonoBehaviour       // ← 컴포넌트가 되려면 상속
{
    // Inspector 에 노출 (public 대신 이걸 권장 — 캡슐화 유지)
    [SerializeField] private float speed = 5f;
    [SerializeField] private Transform muzzle;

    private Rigidbody _rb;

    void Awake()
    {
        // ★ 매 프레임 찾지 말고 한 번만 캐시
        _rb = GetComponent<Rigidbody>();
    }

    void Update()
    {
        var h = Input.GetAxis("Horizontal");
        transform.Translate(Vector3.right * h * speed * Time.deltaTime);
    }
}
GetComponent 는 검색입니다. Update() 안에서 부르면 매 프레임 뒤집니다. Awake·Start 에서 한 번 찾아 변수에 담아 두세요 — Unity 성능 문제의 절반이 여기서 나옵니다.

찾기 · 만들기 · 지우기

// 자신·자식·부모에서 찾기
var col = GetComponent<Collider>();
var gun = GetComponentInChildren<Gun>();
var mgr = GetComponentInParent<RoomManager>();

// 씬 전체에서 찾기 — 느립니다. 시작할 때 한 번만.
var spawner = FindFirstObjectByType<Spawner>();

// 만들기 · 지우기
var go = Instantiate(bulletPrefab, muzzle.position, muzzle.rotation);
Destroy(go, 3f);                 // 3초 뒤 파괴
gameObject.SetActive(false);     // 끄기(파괴보다 훨씬 쌉니다)

// 태그 · 레이어
if (other.CompareTag("Enemy")) { }        // == "Enemy" 보다 빠름
참조는 코드로 찾기보다 Inspector 로 꽂는 편이 낫습니다. [SerializeField] 로 슬롯을 만들고 드래그해 넣으면 실행 전에 빠진 참조를 눈으로 확인할 수 있고 검색 비용도 0입니다.

// Health 는 "체력이 필요한 모든 것"에 그대로 재사용
public class Health : MonoBehaviour
{
    [SerializeField] private int max = 100;
    public int Current { get; private set; }
    public event System.Action<int> OnDamaged;
    public event System.Action OnDied;

    void Awake() => Current = max;

    public void TakeDamage(int dmg)
    {
        Current = Mathf.Max(0, Current - dmg);
        OnDamaged?.Invoke(Current);
        if (Current == 0) OnDied?.Invoke();
    }
}
// Player 도 Enemy 도 상자도 전부 이 한 부품을 씁니다

UNITY 03

MonoBehaviour 생명주기

언제 무엇을 하느냐. 순서를 모르면 "가끔 null 이 뜨는" 버그에 시달립니다.

규칙은 하나 — 자기 초기화는 Awake, 남의 것 참조는 Start. 이 그림의 순서가 그 이유입니다.

호출 순서

Awake()          오브젝트 생성 직후 (자기 초기화 · 캐시)
OnEnable()       활성화될 때마다 (이벤트 구독)
Start()          첫 프레임 직전 (다른 오브젝트 참조 OK)
  ↓ 매 프레임
FixedUpdate()    물리 주기 (기본 0.02초) ← Rigidbody 는 여기서
Update()         화면 주기 (프레임마다) ← 입력·로직
LateUpdate()     Update 끝난 뒤     ← 카메라 추적
  ↓
OnDisable()      비활성화 (이벤트 해지)
OnDestroy()      파괴 직전 (정리)
Awake 에서 남의 컴포넌트를 건드리지 마세요. 그 오브젝트의 Awake 가 아직 안 돌았을 수 있습니다. 자기 것은 Awake, 남의 것은 Start — 이 규칙만 지켜도 초기화 순서 버그가 사라집니다.

void Update()
{
    // ★ 프레임마다 시간이 다르므로 deltaTime 을 곱한다
    transform.position += dir * speed * Time.deltaTime;

    if (Input.GetKeyDown(KeyCode.Space)) _jump = true;   // 입력은 Update
}

void FixedUpdate()
{
    if (_jump) { _rb.AddForce(Vector3.up * power, ForceMode.Impulse); _jump = false; }
    _rb.MovePosition(_rb.position + dir * speed * Time.fixedDeltaTime);
}

void LateUpdate()
{
    cam.position = target.position + offset;   // 대상이 다 움직인 뒤 따라간다
}
Time.deltaTime 을 빼먹으면 기기마다 속도가 달라집니다. 144Hz 모니터에서 두 배 빨리 움직이는 게임이 되는 이유입니다.

코루틴 — "3초 뒤에" · "다 될 때까지"를 코드로

기본 형태

// "기다렸다가 이어서" 를 함수 하나로 씁니다
IEnumerator RespawnRoutine()
{
    ShowDeathEffect();
    yield return new WaitForSeconds(3f);     // 3초 대기
    transform.position = spawnPoint.position;
    yield return null;                       // 한 프레임 대기
    SetInvincible(2f);
}

void Die() => StartCoroutine(RespawnRoutine());

// 자주 쓰는 yield 들
yield return null;                           // 다음 프레임
yield return new WaitForSeconds(1f);         // 초 단위
yield return new WaitForFixedUpdate();       // 다음 물리 틱
yield return new WaitUntil(() => loaded);    // 조건이 참이 될 때까지
yield return StartCoroutine(Other());        // 다른 코루틴이 끝날 때까지

함정과 대안

코루틴은 오브젝트가 꺼지면 함께 죽습니다. SetActive(false) 하는 순간 그 오브젝트의 코루틴은 소리 없이 중단됩니다 — "가끔 리스폰이 안 되는" 버그의 정체입니다. 전역 흐름은 꺼지지 않는 매니저 오브젝트에서 돌리세요. 
// 반복 타이머 — Update 에서 시간 더하기보다 깔끔
IEnumerator SpawnLoop()
{
    var wait = new WaitForSeconds(2f);   // ★ 재사용 (매번 new 는 GC)
    while (enabled)
    {
        Spawn();
        yield return wait;
    }
}

// 중단이 필요하면 핸들을 잡아 두세요
Coroutine _loop;
void OnEnable()  => _loop = StartCoroutine(SpawnLoop());
void OnDisable() { if (_loop != null) StopCoroutine(_loop); }
Unity 6 부터는 Awaitable 로 async/await 도 됩니다 — await Awaitable.WaitForSecondsAsync(3f); C# 비동기에 익숙하다면 이쪽이 예외 처리·취소(CancellationToken)에서 더 낫습니다.
UNITY 04

Transform · 좌표와 회전

위치·회전·크기. 부모 자식 관계와 로컬/월드 구분이 핵심입니다.

헷갈리면 이렇게 — 씬에서의 절대 위치는 월드, 부모에 붙은 상대 위치는 로컬. Inspector 가 보여 주는 것은 로컬입니다.

이동과 회전

// 위치
transform.position      = new Vector3(0, 1, 0);   // 월드 기준
transform.localPosition = Vector3.zero;           // 부모 기준
transform.Translate(Vector3.forward * 2f);        // 자기 방향으로

// 회전 — 각도(Euler)는 보기 편하고, 계산은 Quaternion 으로
transform.rotation = Quaternion.Euler(0, 90, 0);
transform.Rotate(Vector3.up, 90f * Time.deltaTime);
transform.LookAt(target);

// 부드럽게 회전
var want = Quaternion.LookRotation(dir);
transform.rotation = Quaternion.Slerp(transform.rotation, want, 8f * Time.deltaTime);

// 부모 자식
child.SetParent(parent, worldPositionStays: false);
eulerAngles 를 누적해서 더하지 마세요. 내부는 쿼터니언이라 0~360 으로 되돌아오면서 값이 튑니다. 각도를 따로 변수에 들고 매번 통째로 대입하는 편이 안전합니다.

자주 쓰는 벡터 계산

var to    = target.position - transform.position;
var dist  = to.magnitude;              // 거리
var dir   = to.normalized;             // 방향(길이 1)

// ★ 거리 비교는 제곱으로 (제곱근 계산을 피한다)
if (to.sqrMagnitude < range * range) Attack();

var lerp  = Vector3.Lerp(a, b, 0.5f);             // 중간값
var moved = Vector3.MoveTowards(a, b, speed * Time.deltaTime);
var dot   = Vector3.Dot(transform.forward, dir);  // 앞에 있나? (>0)
var cross = Vector3.Cross(a, b);                  // 수직 벡터

// 2D 라면 z 를 무시하고 Vector2 를 쓰세요
"적이 내 앞 60도 안에 있는가" 같은 판정은 Vector3.Dot(forward, dir) > Mathf.Cos(30f * Mathf.Deg2Rad) 로 끝납니다. 각도를 직접 계산하는 것보다 훨씬 빠릅니다.

2D 게임이라면

// 2D 는 z 를 안 쓰고, 회전은 z축 하나만 씁니다
transform.position = new Vector2(3, 1);        // z=0 으로 들어감

// 스프라이트 좌우 반전 — 회전 대신 flipX
GetComponent<SpriteRenderer>().flipX = dir.x < 0;

// 마우스 방향으로 회전 (탑다운 슈터)
Vector2 to = mouseWorld - (Vector2)transform.position;
float deg = Mathf.Atan2(to.y, to.x) * Mathf.Rad2Deg;
transform.rotation = Quaternion.Euler(0, 0, deg - 90f);
2D 에서 앞뒤(그리기 순서)는 z 가 아니라 SpriteRenderer 의 Sorting Layer · Order in Layer 로 정합니다. z 를 만지면 물리·클릭 판정이 꼬입니다.

좌표 변환 — 화면 ↔ 월드

// 마우스 클릭 지점을 월드 좌표로 (2D)
Vector2 world = Camera.main.ScreenToWorldPoint(Input.mousePosition);

// 월드 좌표를 화면 좌표로 — 머리 위 체력바·이름표
Vector3 screen = Camera.main.WorldToScreenPoint(enemy.position);
nameTag.position = screen;
if (screen.z < 0) nameTag.gameObject.SetActive(false);  // 뒤에 있으면 숨김

// 부모 기준 ↔ 월드 기준
Vector3 w = transform.TransformPoint(localOffset);   // 로컬 → 월드
Vector3 l = transform.InverseTransformPoint(worldPos); // 월드 → 로컬
Camera.main 은 내부적으로 검색입니다. Awake 에서 한 번 받아 변수에 두세요 — GetComponent 캐시와 같은 이유입니다.

# Package Manager → Input System 설치 후 재시작
# Project Settings → Player → Active Input Handling: Both
using UnityEngine.InputSystem;

public class PlayerInputHandler : MonoBehaviour
{
    private InputAction _move, _jump;

    void Awake()
    {
        var map = new InputActionMap("Player");
        _move = map.AddAction("Move", binding: "<Gamepad>/leftStick");
        _move.AddCompositeBinding("2DVector")
             .With("Up", "<Keyboard>/w").With("Down", "<Keyboard>/s")
             .With("Left", "<Keyboard>/a").With("Right", "<Keyboard>/d");
        _jump = map.AddAction("Jump", binding: "<Keyboard>/space");
        map.Enable();
    }

    void Update()
    {

IEnumerator PunchScale(Transform t, float dur = 0.25f)
{
    Vector3 baseS = t.localScale;
    for (float e = 0; e < dur; e += Time.deltaTime)
    {
        float k = e / dur;
        // 튀어 올랐다가 돌아오는 곡선
        float s = 1f + Mathf.Sin(k * Mathf.PI) * 0.25f;
        t.localScale = baseS * s;
        yield return null;
    }
    t.localScale = baseS;
}
// 버튼 클릭·아이템 획득·데미지 숫자에 이거 하나면 살아납니다

코루틴과 비동기 — 시간을 다루기

"3초 뒤에" · "끝날 때까지"를 코드로 쓰는 법. 중단 관리까지 알아야 실전에서 안 터집니다.

코루틴 — 시간 흐름을 함수 하나로

using System.Collections;
using UnityEngine;

public class DashSkill : MonoBehaviour
{
    [SerializeField] private float cooldown = 2f;
    private bool _ready = true;

    public void TryDash()
    {
        if (!_ready) return;
        StartCoroutine(DashRoutine());
    }

    IEnumerator DashRoutine()          // ★ 반환형이 IEnumerator
    {
        _ready = false;
        // 0.2초 동안 프레임마다 이동 — 시간 흐름이 for 문처럼 읽힙니다
        for (float e = 0; e < 0.2f; e += Time.deltaTime)
        {
            transform.Translate(Vector3.forward * 30f * Time.deltaTime);
            yield return null;         // 다음 프레임까지 양보
        }
        yield return new WaitForSeconds(cooldown);
        _ready = true;
    }
}

yield return 은 "여기서 멈췄다가, 조건이 되면 이어서" 입니다. 상태 변수·타이머를 Update 에 흩뿌리지 않고 절차를 위에서 아래로 쓸 수 있다는 것이 코루틴의 가치입니다.

    [SerializeField] private Vector3 offset = new(0, 5, -8);
    [SerializeField] private float smooth = 0.2f;

    void LateUpdate()   // ★ Update 에서 하면 안 됩니다

상태 머신 — 순찰 · 추적 · 공격을 enum 으로

복붙해서 시작하는 적 AI

using UnityEngine;
using UnityEngine.AI;

public class EnemyAI : MonoBehaviour
{
    enum State { Patrol, Chase, Attack }        // u10 의 게임 상태와 같은 패턴

    [SerializeField] private Transform[] waypoints;
    [SerializeField] private Transform player;
    [SerializeField] private float sightRange  = 8f;
    [SerializeField] private float attackRange = 1.8f;

    private NavMeshAgent _agent;
    private State _state = State.Patrol;
    private int _wp;

    void Awake() => _agent = GetComponent<NavMeshAgent>();

    void Update()
    {
        float dist = Vector3.Distance(transform.position, player.position);

        // 1) 전환 규칙 — 한 곳에 모아 둡니다
        switch (_state)
        {
            case State.Patrol:
                if (CanSee(dist)) _state = State.Chase;
                break;
            case State.Chase:
                if (dist <= attackRange)          _state = State.Attack;
                else if (dist > sightRange * 1.5f) _state = State.Patrol;  // 놓침
                break;
            case State.Attack:
                if (dist > attackRange) _state = State.Chase;
                break;
        }

        // 2) 상태별 행동
        switch (_state)
        {
            case State.Patrol:
                _agent.isStopped = false;
                if (!_agent.pathPending && _agent.remainingDistance < 0.3f)
                {
                    _wp = (_wp + 1) % waypoints.Length;   // 다음 지점 순환
                    _agent.SetDestination(waypoints[_wp].position);
                }
                break;
            case State.Chase:
                _agent.isStopped = false;
                _agent.SetDestination(player.position);
                break;
            case State.Attack:
                _agent.isStopped = true;                  // 멈춰서
                transform.LookAt(player);                 // 바라보고
                TryAttack();                              // 쿨다운은 내부에서
                break;
        }
    }
}
전환(1)과 행동(2)을 분리한 것이 핵심입니다. 상태가 늘어도 어디를 고칠지 명확하고, 상태별 로직이 커지면 State 패턴 클래스로 승격하면 됩니다(u10 과 같은 길).

시야 판정 — "봤다"를 코드로

bool CanSee(float dist)
{
    if (dist > sightRange) return false;

    var dir = (player.position - transform.position).normalized;

    // 시야각 120도 — 등 뒤는 못 봅니다 (u04 의 Dot 판정)
    if (Vector3.Dot(transform.forward, dir)
        < Mathf.Cos(60f * Mathf.Deg2Rad)) return false;

    // 벽에 가렸나 — 눈높이에서 레이 하나
    var eye = transform.position + Vector3.up * 1.6f;
    if (Physics.Raycast(eye, dir, out var hit, sightRange)
        && !hit.transform.CompareTag("Player"))
        return false;                       // 먼저 맞은 것이 벽

    return true;
}

private static readonly int Flash = Shader.PropertyToID("_FlashAmount");

void OnHit() => _renderer.material.SetFloat(Flash, 1f);
.material 은 부르는 순간 머티리얼을 복제합니다. 개별로 바꿀 게 아니면 .sharedMaterial — 복제본이 쌓이면 메모리와 드로우콜이 같이 늘어납니다. HLSL 을 몰라도 되는 것이 Shader Graph 의 가치지만, 노드 수가 곧 GPU 비용이라는 것은 기억하세요.

4. Vignette : Intensity 0.3
              가장자리를 어둡게 — 화면 집중도가 올라감
5. 안 보이면 → Main Camera 의 Rendering →
              Post Processing 체크 확인

Bloom 으로 빛나게 하려면 재질 쪽도 필요합니다 — 머티리얼의 Emission 을 켜고 HDR 색상 Intensity 를 1 이상으로. Threshold 를 넘는 밝기만 번집니다.

모바일에서 이펙트는 채우기 비용(fill rate) 싸움입니다. 파티클은 개수보다 화면을 덮는 반투명 면적(오버드로우)이 문제 — 크고 겹치는 파티클 몇 장이 작은 것 수백 개보다 무겁습니다. 후처리도 Vignette·Color Adjustments 는 싸지만 Bloom·Depth of Field·Motion Blur 는 비쌉니다 — 저사양 기기에서는 끄는 옵션을 두는 것이 표준입니다.
