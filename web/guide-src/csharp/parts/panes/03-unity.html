Unity 는 "오브젝트에 부품(컴포넌트)을 붙여" 게임을 만드는 엔진입니다. 이 구조 하나만 이해하면 나머지는 부품 사용법입니다. 여기까지 마치면 조작·물리·UI·저장이 들어간 작은 게임 하나를 혼자 완성할 수 있습니다.

UNITY 01

설치하고 화면 익히기

Unity Hub 로 버전을 관리하고, 창 다섯 개의 역할만 알면 시작할 수 있습니다.

설치 순서

  • Unity Hub 설치 → 여기서 에디터 버전을 깝니다
  • LTS 버전을 고르세요 — 최신 베타는 플러그인이 안 붙습니다
  • 모듈에서 빌드 대상 체크(Android · iOS · WebGL · Windows)
  • 에디터는 Rider 또는 VS Code + C# Dev Kit
템플릿 고르기
  2D (Built-in)      가장 단순 · 첫 게임에 좋음
  Universal 3D (URP) 모바일·PC 대부분 ★ 기본값으로 권장
  HDRP               고사양 PC·콘솔 전용
  3D (Built-in)      옛 프로젝트 유지보수용
프로젝트 경로에 한글·공백을 넣지 마세요. 일부 빌드 도구가 깨집니다. 또 OneDrive·클라우드 동기화 폴더 안에 두면 Library 폴더 충돌로 프로젝트가 망가집니다.

창 다섯 개

Scene
세상을 배치하는 곳 여기서 물체를 놓고 옮깁니다. 실제 실행 화면이 아닙니다.
Game
플레이어가 볼 화면 카메라가 비추는 결과. ▶ 을 누르면 여기가 돕니다.
Hierarchy
지금 씬에 있는 것들의 목록 부모–자식 관계를 여기서 만듭니다.
Inspector
고른 것의 부품과 설정 스크립트의 public 변수도 여기에 나타납니다.
Project
프로젝트 파일 전체 Assets 폴더. 이미지·소리·스크립트가 전부 여기 있습니다.
플레이(▶) 중에 바꾼 값은 저장되지 않습니다. 멈추면 원래대로 돌아갑니다 — 모르고 한 시간 작업하다 날리는 것이 첫날의 통과의례입니다. 값을 확정하려면 정지 후 다시 입력하세요.
UNITY 02

씬 · 게임오브젝트 · 컴포넌트

Unity 의 전부입니다. 이 세 단어의 관계를 잡으면 나머지는 사용법일 뿐입니다.

게임오브젝트는 빈 상자입니다. 무엇을 할 수 있는지는 붙인 컴포넌트가 정합니다.

코드에서 다루기

using UnityEngine;

public class Player : MonoBehaviour       // ← 컴포넌트가 되려면 상속
{
    // Inspector 에 노출 (public 대신 이걸 권장 — 캡슐화 유지)
    [SerializeField] private float speed = 5f;
    [SerializeField] private Transform muzzle;

    private Rigidbody _rb;

    void Awake()
    {
        // ★ 매 프레임 찾지 말고 한 번만 캐시
        _rb = GetComponent<Rigidbody>();
    }

    void Update()
    {
        var h = Input.GetAxis("Horizontal");
        transform.Translate(Vector3.right * h * speed * Time.deltaTime);
    }
}
GetComponent 는 검색입니다. Update() 안에서 부르면 매 프레임 뒤집니다. Awake·Start 에서 한 번 찾아 변수에 담아 두세요 — Unity 성능 문제의 절반이 여기서 나옵니다.

찾기 · 만들기 · 지우기

// 자신·자식·부모에서 찾기
var col = GetComponent<Collider>();
var gun = GetComponentInChildren<Gun>();
var mgr = GetComponentInParent<RoomManager>();

// 씬 전체에서 찾기 — 느립니다. 시작할 때 한 번만.
var spawner = FindFirstObjectByType<Spawner>();

// 만들기 · 지우기
var go = Instantiate(bulletPrefab, muzzle.position, muzzle.rotation);
Destroy(go, 3f);                 // 3초 뒤 파괴
gameObject.SetActive(false);     // 끄기(파괴보다 훨씬 쌉니다)

// 태그 · 레이어
if (other.CompareTag("Enemy")) { }        // == "Enemy" 보다 빠름
참조는 코드로 찾기보다 Inspector 로 꽂는 편이 낫습니다. [SerializeField] 로 슬롯을 만들고 드래그해 넣으면 실행 전에 빠진 참조를 눈으로 확인할 수 있고 검색 비용도 0입니다.
UNITY 03

MonoBehaviour 생명주기

언제 무엇을 하느냐. 순서를 모르면 "가끔 null 이 뜨는" 버그에 시달립니다.

호출 순서

Awake()          오브젝트 생성 직후 (자기 초기화 · 캐시)
OnEnable()       활성화될 때마다 (이벤트 구독)
Start()          첫 프레임 직전 (다른 오브젝트 참조 OK)
  ↓ 매 프레임
FixedUpdate()    물리 주기 (기본 0.02초) ← Rigidbody 는 여기서
Update()         화면 주기 (프레임마다) ← 입력·로직
LateUpdate()     Update 끝난 뒤     ← 카메라 추적
  ↓
OnDisable()      비활성화 (이벤트 해지)
OnDestroy()      파괴 직전 (정리)
Awake 에서 남의 컴포넌트를 건드리지 마세요. 그 오브젝트의 Awake 가 아직 안 돌았을 수 있습니다. 자기 것은 Awake, 남의 것은 Start — 이 규칙만 지켜도 초기화 순서 버그가 사라집니다.

void Update()
{
    // ★ 프레임마다 시간이 다르므로 deltaTime 을 곱한다
    transform.position += dir * speed * Time.deltaTime;

    if (Input.GetKeyDown(KeyCode.Space)) _jump = true;   // 입력은 Update
}

void FixedUpdate()
{
    if (_jump) { _rb.AddForce(Vector3.up * power, ForceMode.Impulse); _jump = false; }
    _rb.MovePosition(_rb.position + dir * speed * Time.fixedDeltaTime);
}

void LateUpdate()
{
    cam.position = target.position + offset;   // 대상이 다 움직인 뒤 따라간다
}
Time.deltaTime 을 빼먹으면 기기마다 속도가 달라집니다. 144Hz 모니터에서 두 배 빨리 움직이는 게임이 되는 이유입니다.
UNITY 04

Transform · 좌표와 회전

위치·회전·크기. 부모 자식 관계와 로컬/월드 구분이 핵심입니다.

이동과 회전

// 위치
transform.position      = new Vector3(0, 1, 0);   // 월드 기준
transform.localPosition = Vector3.zero;           // 부모 기준
transform.Translate(Vector3.forward * 2f);        // 자기 방향으로

// 회전 — 각도(Euler)는 보기 편하고, 계산은 Quaternion 으로
transform.rotation = Quaternion.Euler(0, 90, 0);
transform.Rotate(Vector3.up, 90f * Time.deltaTime);
transform.LookAt(target);

// 부드럽게 회전
var want = Quaternion.LookRotation(dir);
transform.rotation = Quaternion.Slerp(transform.rotation, want, 8f * Time.deltaTime);

// 부모 자식
child.SetParent(parent, worldPositionStays: false);
eulerAngles 를 누적해서 더하지 마세요. 내부는 쿼터니언이라 0~360 으로 되돌아오면서 값이 튑니다. 각도를 따로 변수에 들고 매번 통째로 대입하는 편이 안전합니다.

자주 쓰는 벡터 계산

var to    = target.position - transform.position;
var dist  = to.magnitude;              // 거리
var dir   = to.normalized;             // 방향(길이 1)

// ★ 거리 비교는 제곱으로 (제곱근 계산을 피한다)
if (to.sqrMagnitude < range * range) Attack();

var lerp  = Vector3.Lerp(a, b, 0.5f);             // 중간값
var moved = Vector3.MoveTowards(a, b, speed * Time.deltaTime);
var dot   = Vector3.Dot(transform.forward, dir);  // 앞에 있나? (>0)
var cross = Vector3.Cross(a, b);                  // 수직 벡터

// 2D 라면 z 를 무시하고 Vector2 를 쓰세요
"적이 내 앞 60도 안에 있는가" 같은 판정은 Vector3.Dot(forward, dir) > Mathf.Cos(30f * Mathf.Deg2Rad) 로 끝납니다. 각도를 직접 계산하는 것보다 훨씬 빠릅니다.
UNITY 05

입력 — Input System

키보드·패드·터치를 같은 코드로 받습니다. 새 프로젝트는 새 Input System 을 쓰세요.

옛 방식 (Input Manager)

// 배우기 쉽고 예제가 많지만, 패드·터치 대응이 번거롭습니다
float h = Input.GetAxis("Horizontal");        // -1 ~ 1 (부드럽게)
float raw = Input.GetAxisRaw("Horizontal");   // -1 / 0 / 1 (즉시)

if (Input.GetKeyDown(KeyCode.Space)) Jump();  // 누른 순간
if (Input.GetKey(KeyCode.LeftShift)) Run();   // 누르고 있는 동안
if (Input.GetMouseButtonDown(0)) Fire();

// 마우스로 화면 좌표 → 월드
var ray = Camera.main.ScreenPointToRay(Input.mousePosition);
if (Physics.Raycast(ray, out var hit)) Move(hit.point);

새 Input System (권장)

# Package Manager → Input System 설치 후 재시작
# Project Settings → Player → Active Input Handling: Both
using UnityEngine.InputSystem;

public class PlayerInputHandler : MonoBehaviour
{
    private InputAction _move, _jump;

    void Awake()
    {
        var map = new InputActionMap("Player");
        _move = map.AddAction("Move", binding: "<Gamepad>/leftStick");
        _move.AddCompositeBinding("2DVector")
             .With("Up", "<Keyboard>/w").With("Down", "<Keyboard>/s")
             .With("Left", "<Keyboard>/a").With("Right", "<Keyboard>/d");
        _jump = map.AddAction("Jump", binding: "<Keyboard>/space");
        map.Enable();
    }

    void Update()
    {
        var v = _move.ReadValue<Vector2>();
        if (_jump.WasPressedThisFrame()) Jump();
    }
}
실무에서는 Input Actions 에셋(에디터에서 만드는 파일)으로 정의하고 C# 클래스를 자동 생성해 쓰는 방식이 표준입니다. 키 리매핑·패드 대응·터치를 코드 수정 없이 처리할 수 있습니다.

총알·적·아이템처럼 같은 것을 여러 개 만들 때 쓰는 틀입니다.

만들고 쓰기

public class Spawner : MonoBehaviour
{

    [SerializeField] private Transform[] points;

    void Spawn()
    {
        var p = points[Random.Range(0, points.Length)];
        var go = Instantiate(enemyPrefab, p.position, Quaternion.identity);

        // 만든 직후 값 넣기
        go.GetComponent<Enemy>().Init(level: _wave);

}

UNITY 07

물리 — Rigidbody · Collider

부딪히고 떨어지게 만드는 부품. 움직이는 방법을 틀리면 물리가 무너집니다.

두 부품의 역할

Collider
모양 — "어디까지가 몸인가" Box · Sphere · Capsule 이 빠릅니다. Mesh Collider 는 무겁고 움직이는 물체에는 제한이 있습니다.
Rigidbody
물리 — "중력·힘을 받는가" 이게 없으면 충돌은 감지되어도 튕기지 않습니다.
isTrigger
통과시키되 알림만 아이템 획득·구역 진입 판정에 씁니다.
void OnCollisionEnter(Collision c)      // 부딪힘 (둘 다 Collider, 하나는 Rigidbody)
{
    if (c.gameObject.CompareTag("Ground")) _grounded = true;
    var point = c.contacts[0].point;      // 맞은 지점
}

void OnTriggerEnter(Collider other)     // 통과 (isTrigger 체크)
{
    if (other.TryGetComponent<Item>(out var item)) Pickup(item);
}

움직이는 방법 — 이걸 틀립니다

방법쓸 곳
AddForce밀기·점프 — 가장 물리적
linearVelocity일정 속도 이동 (조작감 중시)
MovePosition움직이는 발판 (Kinematic)
transform.positionRigidbody 가 있으면 쓰지 말 것
Rigidbody 가 붙은 물체를 transform.position 으로 옮기면 물리 엔진이 이동을 모릅니다 — 벽을 뚫고 지나가거나 충돌이 씹힙니다. 반드시 FixedUpdate 에서 Rigidbody API 로 옮기세요.

rb.collisionDetectionMode = CollisionDetectionMode.ContinuousDynamic;

// 레이어로 충돌 규칙 정리 (Project Settings → Physics)
// 예: Player 는 PlayerBullet 과 충돌하지 않음 → 자기 총알에 안 맞음

// 레이캐스트로 미리 검사
if (Physics.Raycast(pos, dir, out var hit, dist, groundMask)) { }
UNITY 08

애니메이션 · 사운드

움직임과 소리. 상태 기계로 애니메이션을 관리하는 방식만 잡으면 됩니다.

Animator

구성 요소
  Animation Clip   실제 동작 (Idle · Run · Jump · Attack)
  Animator Controller  상태와 전환 규칙 (.controller 파일)
  Parameter        전환 조건 (float Speed · bool Grounded · trigger Attack)
  Layer            상반신/하반신 분리 등
private Animator _anim;
// ★ 문자열 대신 해시로 (매 프레임 문자열 비교를 피한다)
private static readonly int Speed    = Animator.StringToHash("Speed");
private static readonly int Grounded = Animator.StringToHash("Grounded");
private static readonly int AttackT  = Animator.StringToHash("Attack");

void Update()
{
    _anim.SetFloat(Speed, _rb.linearVelocity.magnitude);
    _anim.SetBool(Grounded, _grounded);
    if (Input.GetMouseButtonDown(0)) _anim.SetTrigger(AttackT);
}

// 애니메이션 중간에 이벤트 호출 (Animation Event 로 등록)
public void OnHitFrame() => DealDamage();
전환이 복잡해지면 Animator 창이 스파게티가 됩니다. 상태가 10개를 넘으면 Any State 남용을 줄이고, Layer 로 나누거나 코드에서 CrossFade 로 직접 제어하는 편이 관리하기 쉽습니다.

오디오

[SerializeField] private AudioClip shootClip;
private AudioSource _src;

void Awake() => _src = GetComponent<AudioSource>();

// 겹쳐 재생 (총소리처럼 빠르게 반복)
_src.PlayOneShot(shootClip, volume: 0.7f);

// 한 지점에서 잠깐 나는 소리 — 오브젝트 없이
AudioSource.PlayClipAtPoint(explodeClip, pos);

// 음량 조절은 AudioMixer 로 (설정 화면과 연결)
mixer.SetFloat("BgmVolume", Mathf.Log10(v) * 20);   // dB 변환
오디오 임포트 설정이 메모리를 좌우합니다. 짧은 효과음은 Decompress On Load, 배경음은 Streaming 으로 두세요. 전부 기본값으로 두면 모바일에서 메모리가 수백 MB 로 뜁니다.
사운드는 게임 완성도의 체감 절반입니다. 타격음·UI 클릭음만 붙여도 완전히 다른 게임처럼 느껴집니다.
UNITY 09

UI — Canvas · uGUI

체력바·버튼·메뉴. 해상도가 달라도 안 깨지게 만드는 것이 핵심입니다.

Canvas 설정

  • Render Mode — 대부분 Screen Space - Overlay
  • Canvas Scaler — Scale With Screen Size 로 두고 기준 해상도(예: 1920×1080) 지정 ★
  • Match — 가로/세로 중 무엇에 맞출지 (모바일 세로 게임은 Width 쪽)
  • Anchor — 화면 모서리에 붙이면 해상도가 바뀌어도 자리가 유지됩니다
using TMPro;

[SerializeField] private TMP_Text hpText;
[SerializeField] private Slider hpBar;
[SerializeField] private Button startBtn;

void Awake()
{
    startBtn.onClick.AddListener(StartGame);      // 코드로 연결
}
void OnDestroy() => startBtn.onClick.RemoveListener(StartGame);

void SetHp(int cur, int max)
{
    hpBar.value = (float)cur / max;
    hpText.SetText("{0}/{1}", cur, max);          // 할당 없는 API
}

느려지는 이유와 대책

Canvas 는 하나만 바뀌어도 전체를 다시 계산합니다. 체력바가 매 프레임 움직이는 캔버스에 정적인 메뉴까지 같이 있으면 메뉴도 매 프레임 다시 그려집니다.
  • 캔버스를 나누세요 — 자주 바뀌는 것(HUD)과 안 바뀌는 것(메뉴)을 분리
  • Raycast Target 끄기 — 클릭이 필요 없는 이미지·텍스트는 전부 해제
  • 텍스트는 TextMeshPro — 기본 Text 는 화질·성능 모두 불리합니다
  • 비활성화보다 캔버스 그룹 — alpha 0 + blocksRaycasts false 가 더 쌉니다
  • 레이아웃 그룹 남용 금지 — 중첩되면 계산 비용이 급증합니다
UI Toolkit(새 UI 시스템)은 에디터 툴과 정적 UI 에 강합니다. 게임 내 HUD 는 아직 uGUI 가 현실적인 선택인 경우가 많습니다.
UNITY 10

씬 전환 · 게임 흐름

타이틀 → 게임 → 결과. 그리고 씬이 바뀌어도 살아남아야 하는 것을 다룹니다.

씬 로딩

using UnityEngine.SceneManagement;

SceneManager.LoadScene("Game");                    // 즉시 (멈칫함)

// 비동기 + 로딩바 (권장)
IEnumerator LoadAsync(string name)
{
    var op = SceneManager.LoadSceneAsync(name);
    op.allowSceneActivation = false;               // 다 될 때까지 대기

    while (op.progress < 0.9f)
    {
        bar.value = op.progress / 0.9f;
        yield return null;
    }
    bar.value = 1f;
    yield return new WaitForSeconds(0.3f);         // 로딩바를 잠깐 보여 주기
    op.allowSceneActivation = true;
}

// 겹쳐 올리기 (UI 씬 · 스테이지 추가)
SceneManager.LoadScene("Pause", LoadSceneMode.Additive);

씬을 넘어 살아남기

public class GameManager : MonoBehaviour
{
    public static GameManager Instance { get; private set; }

    void Awake()
    {
        if (Instance != null && Instance != this) { Destroy(gameObject); return; }
        Instance = this;
        DontDestroyOnLoad(gameObject);      // 씬이 바뀌어도 유지
    }
}
싱글턴을 남발하면 나중에 못 풉니다. GameManager.Instance.어쩌고 가 코드 전역에 퍼지면 테스트도 재사용도 불가능해집니다. 정말 하나만 있어야 하는 것(오디오·세이브·씬 전환)만 두고, 나머지는 참조를 넘겨받게 만드세요.
데이터만 넘기고 싶다면 ScriptableObject 가 더 깔끔합니다 — 씬에 속하지 않는 에셋이라 자동으로 살아남고, 인스펙터에서 값을 확인·수정할 수 있습니다(다음 섹션).
UNITY 11

데이터 — ScriptableObject · 세이브

아이템 표·능력치 같은 게임 데이터와, 진행 상황을 저장하는 법.

ScriptableObject — 데이터를 에셋으로

[CreateAssetMenu(fileName = "Item", menuName = "Game/Item")]
public class ItemData : ScriptableObject
{
    public string displayName;
    public Sprite icon;
    public int    price;
    public int    attack;
    [TextArea] public string description;
}

// 쓰는 쪽
public class Shop : MonoBehaviour
{
    [SerializeField] private ItemData[] stock;   // 인스펙터에서 드래그
}
  • 메모리에 한 벌만 존재합니다 — 프리팹마다 복사되지 않습니다
  • 기획자가 직접 값을 수정할 수 있습니다(코드 수정·재빌드 불필요)
  • 밸런스 표를 엑셀 → SO 자동 생성하는 파이프라인이 흔합니다
ScriptableObject 에 런타임 상태를 저장하지 마세요. 에디터에서는 플레이를 멈춰도 값이 남아 다음 실행에 영향을 줍니다. 정의(원본 데이터)는 SO, 현재 상태는 일반 클래스로 나누세요.

세이브

[Serializable]
public class SaveData
{
    public int level;
    public int gold;
    public List<string> unlocked = new();
}

static string Path => System.IO.Path.Combine(
    Application.persistentDataPath, "save.json");   // ★ 반드시 이 경로

public static void Save(SaveData d)
{
    var json = JsonUtility.ToJson(d, prettyPrint: true);
    var tmp  = Path + ".tmp";
    File.WriteAllText(tmp, json);
    File.Copy(tmp, Path, overwrite: true);          // 쓰다 꺼져도 원본 보존
    File.Delete(tmp);
}

public static SaveData Load() =>
    File.Exists(Path) ? JsonUtility.FromJson<SaveData>(File.ReadAllText(Path))
                      : new SaveData();
PlayerPrefs 는 설정용입니다. 볼륨·해상도 정도만 넣으세요. 재화·진행도를 넣으면 사용자가 쉽게 수정할 수 있고 기기 이전도 안 됩니다. 온라인 게임이라면 서버에 저장이 정답입니다.
