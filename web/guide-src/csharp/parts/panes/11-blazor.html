BLAZOR 01

Blazor 가 무엇인가 — 렌더 모드부터 고릅니다

Blazor 를 배우는 일의 절반은 렌더 모드 네 가지를 구분하는 것입니다. 같은 .razor 파일이 서버에서 도느냐 브라우저에서 도느냐에 따라 할 수 있는 일과 못 하는 일이 완전히 갈리기 때문입니다.

모드를 잘못 고르면 되돌리는 비용이 큽니다 — 특히 WASM 은 서버 코드를 직접 못 부릅니다.

네 모드를 한 문장으로

  • Static SSR — 서버가 HTML 을 만들어 보내고 끝. 버튼을 눌러도 아무 일이 없습니다(폼 제출은 됩니다). 블로그·상품 목록·랜딩 페이지.
  • Interactive Server — 컴포넌트가 서버에서 돌고, 바뀐 화면 조각만 WebSocket 으로 내려옵니다. DB 를 바로 부를 수 있어 사내 관리 도구에 가장 잘 맞습니다.
  • Interactive WebAssembly — .NET 런타임이 브라우저 안에서 돕니다. 첫 방문에 수 MB 를 받아야 하지만 그다음부터는 서버 없이도 반응합니다.
  • Auto — 첫 방문은 Server 로 즉시 시작하고, 배경에서 WASM 을 내려받아 다음 방문부터 브라우저에서 돕니다. 둘의 단점을 서로 덮습니다.
"Blazor Server 냐 Blazor WebAssembly 냐"는 옛 질문입니다. .NET 8 부터는 Blazor Web App 프로젝트 하나 안에서 페이지마다 @rendermode 를 다르게 줍니다. 목록 페이지는 Static SSR, 편집 화면만 Interactive Server — 이렇게 섞는 것이 기본값입니다.

언제 Blazor 를 쓰고 언제 안 쓰나 — 솔직한 기준 🟡 중급

Blazor 가 확실히 유리한 자리
  • 팀이 C# 팀일 때 — 프런트 인력을 따로 안 뽑아도 됩니다. 이게 현실에서 가장 큰 이유입니다
  • 사내 업무 도구 · 관리자 화면 — 첫 로딩 몇 백 ms 는 아무도 신경 안 쓰고, DB 를 바로 다루는 편의가 압도적입니다
  • 서버와 화면이 같은 규칙을 써야 할 때 — 검증 속성, 계산 로직, 열거형을 한 곳에 두고 양쪽에서 씁니다
  • 데스크톱·모바일로도 내보내야 할 때 — 같은 컴포넌트를 MAUI Blazor Hybrid 로 감쌉니다(b12)
  • 오프라인 도구 — WASM + PWA 면 설치 없이 도는 오프라인 앱이 됩니다
Blazor 를 피하는 편이 나은 자리
  • 공개 서비스의 첫 로딩이 매출을 좌우할 때 — WASM 초기 다운로드는 아무리 줄여도 1~2MB 대입니다
  • 특정 JS 라이브러리에 크게 기대는 화면 — 지도·에디터·차트를 깊게 쓰면 상호운용 코드가 앱보다 커집니다
  • 이미 React·Vue 팀이 있고 잘 돌 때 — 언어 통일이 주는 이득보다 재학습 비용이 큽니다
  • SEO 가 핵심인데 상호작용도 많을 때 — 가능은 하지만(Static SSR + 부분 Interactive) React 진영의 도구가 더 성숙합니다
  • 모바일 회선이 나쁜 사용자 대상 — Interactive Server 는 연결이 끊기면 화면이 멈춥니다(b09)
번들 크기 감각 — 아무것도 안 넣은 Blazor WASM 앱을 Release 로 게시하면 브로틀리 압축 기준 대략 1.5MB 안팎이 내려갑니다. 같은 일을 하는 React 앱은 50~150KB 수준입니다. 이 차이는 트리밍·AOT 로 줄여도 사라지지 않습니다(b10) — 대신 두 번째 방문부터는 브라우저 캐시에 남아 체감이 확 달라집니다. 첫 방문이 전부인 서비스인지, 매일 쓰는 도구인지가 판단의 갈림길입니다.
정리 — Blazor 는 C# 으로 화면을 만드는 방법이고, 배우는 일의 절반은 렌더 모드 네 가지를 구분하는 것입니다. Static SSR(정적) · Interactive Server(서버 회로) · Interactive WASM(브라우저 런타임) · Auto(둘을 전환) — 이 넷을 한 앱 안에서 화면마다 섞어 쓰는 것이 .NET 10 의 표준 사용법입니다.
BLAZOR 02

첫 앱 — dotnet new blazor 부터 핫 리로드까지

npm 도, 번들러 설정도 없습니다. 명령 두 줄이면 화면이 뜹니다. 대신 어떤 파일이 무슨 역할인지를 처음에 잡아 두면 뒤가 아주 편해집니다.

만들고 띄우기 — 두 줄

# 상호작용 모드를 Auto 로, 인증까지 포함해서 생성
dotnet new blazor -o Inventory.Web -int Auto -au Individual
cd Inventory.Web
dotnet watch          # 브라우저가 열리고, 저장하면 즉시 반영됩니다

# 주요 옵션
#  -int|--interactivity  None | Server | WebAssembly | Auto
#       None        → 전부 Static SSR (가장 가벼움)
#       Auto        → Server 로 시작해 WASM 으로 넘어감 (프로젝트 2개 생성)
#  -ai |--all-interactive  모든 페이지에 렌더 모드를 한꺼번에 적용
#  -au |--auth           None | Individual  (Identity + 로그인 화면 포함)
#  -e  |--empty          예제 페이지 없이 뼈대만
#  --no-https            사내망 전용일 때

# 어떤 템플릿이 있는지 확인
dotnet new list blazor
-int Auto 를 주면 프로젝트가 두 개 생깁니다 — Inventory.Web(서버) 와 Inventory.Web.Client(브라우저에서 도는 쪽). 브라우저로 내려갈 컴포넌트는 반드시 .Client 프로젝트에 둬야 합니다. 이 규칙 하나를 몰라 "왜 내 컴포넌트가 안 살아나지" 로 몇 시간을 쓰는 사람이 많습니다.

_Imports.razor 를 먼저 열어 보세요. 여기에 @using 을 한 번 적어 두면 모든 .razor 파일에서 그 네임스페이스를 쓸 수 있습니다. "이 컴포넌트를 못 찾는다"는 에러의 90%는 해당 프로젝트의 _Imports.razor 에 using 이 없어서입니다 (서버·클라이언트 프로젝트가 각각 가지고 있습니다).
사전 렌더링은 공짜가 아닙니다 — 컴포넌트 초기화 코드가 서버에서 한 번, 클라이언트에서 또 한 번 돕니다.

Program.cs — 렌더 모드를 켜는 곳

var builder = WebApplication.CreateBuilder(args);

builder.Services.AddRazorComponents()          // ① Razor 컴포넌트 엔진
    .AddInteractiveServerComponents()          // ② Server 모드를 쓰겠다
    .AddInteractiveWebAssemblyComponents();    // ③ WASM 모드도 쓰겠다

var app = builder.Build();

if (!app.Environment.IsDevelopment())
{
    app.UseExceptionHandler("/Error", createScopeForErrors: true);
    app.UseHsts();
}
app.UseHttpsRedirection();
app.UseAntiforgery();                          // ★ 폼 위조 방지 — 반드시 필요
app.MapStaticAssets();                         // .NET 9+ : 지문·압축 자동

app.MapRazorComponents<App>()
   .AddInteractiveServerRenderMode()
   .AddInteractiveWebAssemblyRenderMode()
   .AddAdditionalAssemblies(typeof(Client._Imports).Assembly);  // ★ 클라 프로젝트

app.Run();
AddAdditionalAssemblies 를 빠뜨리면 .Client 프로젝트에 있는 페이지의 URL 이 404 가 납니다. 라우터가 그 어셈블리를 뒤지지 않기 때문입니다. 템플릿으로 만들면 자동으로 들어가 있으니, 손으로 프로젝트를 나눌 때만 신경 쓰면 됩니다.

BLAZOR 03

Razor 컴포넌트 문법 — 화면을 조각으로 나눕니다

.razor 파일 하나가 컴포넌트 하나입니다. HTML 을 쓰다가 @ 를 만나면 C# 으로 넘어가고, 다시 태그를 만나면 HTML 로 돌아옵니다. 규칙은 이 한 줄이 전부입니다.

파일 하나의 구조

@* Components/Pages/Counter.razor *@
@page "/counter"                 @* 이 컴포넌트의 URL *@
@rendermode InteractiveServer    @* 살아 있게 만들기 *@
@using Inventory.Shared.Models   @* 이 파일에만 필요한 using *@
@inject ILogger<Counter> Log     @* DI — 생성자 주입 대신 이렇게 *@

<PageTitle>카운터</PageTitle>    @* <title> 을 바꿉니다 *@

<h1>현재 @count</h1>              @* @변수 = 값을 출력 *@

@if (count > 10)                 @* @if / @foreach = 제어문 *@
{
    <p class="warn">10 을 넘었습니다</p>
}

<button class="btn" @onclick="Increment">+1</button>

@code {                          @* 이 컴포넌트의 C# 코드 *@
    private int count;

    private void Increment()
    {
        count++;
        Log.LogInformation("count={Count}", count);
    }   // ← 이벤트 처리기가 끝나면 자동으로 다시 그려집니다
}
@ 는 "여기부터 C#" 이라는 표시입니다. @count 처럼 한 낱말이면 그대로 쓰고, 식이 길면 @(a + b) 처럼 괄호로 묶습니다. 이메일 주소처럼 진짜 @ 문자를 쓰고 싶으면 @@ 로 두 번 씁니다.

파라미터 — React 의 props 자리

@* Components/ProductCard.razor *@
<div class="card @(Selected ? "on" : "")">
    <h4>@Product.Name</h4>
    <p>@Product.Price.ToString("N0") 원</p>
    <button @onclick="() => OnPick.InvokeAsync(Product)">담기</button>
</div>

@code {
    [Parameter, EditorRequired]              // ★ 빠뜨리면 빌드 경고
    public Product Product { get; set; } = default!;

    [Parameter] public bool Selected { get; set; }

    [Parameter] public EventCallback<Product> OnPick { get; set; }

    // 나머지 속성을 통째로 받아 <div> 에 넘기기 (class, data-* …)
    [Parameter(CaptureUnmatchedValues = true)]

StateHasChanged — 언제 부르나

@implements IDisposable
@inject NotificationService Notices

@code {
    private Timer? timer;
    private int remain = 60;

    protected override void OnInitialized()
    {
        // ❌ 타이머 콜백은 '이벤트 처리기'가 아닙니다 — 자동 렌더가 안 됩니다
        timer = new Timer(_ =>
        {
            remain--;
            InvokeAsync(StateHasChanged);   // ★ 이 한 줄이 필요합니다
        }, null, 1000, 1000);

        Notices.OnChange += Refresh;        // 다른 서비스가 알려 줄 때도 마찬가지
    }

    private void Refresh() => InvokeAsync(StateHasChanged);

    public void Dispose()
    {
        timer?.Dispose();
        Notices.OnChange -= Refresh;        // ★ 안 빼면 회로가 안 죽습니다
    }
}
InvokeAsync 로 감싸는 이유 — Blazor 는 렌더 전용 스레드에서만 화면을 건드릴 수 있습니다. 타이머·백그라운드 작업·SignalR 콜백은 다른 스레드에서 옵니다. 그냥 StateHasChanged() 를 부르면 "The current thread is not associated with the Dispatcher" 예외가 납니다. WPF 의 Dispatcher.Invoke 와 정확히 같은 이야기입니다.

// Client/PersistentAuthenticationStateProvider.cs (템플릿 생성물)
// 서버가 렌더할 때 사용자 정보를 실어 보내고,
// 브라우저 쪽은 그걸 받아 상태를 만듭니다 — 다시 물어보지 않습니다
internal sealed class PersistentAuthenticationStateProvider
    : AuthenticationStateProvider
{
    private static readonly Task<AuthenticationState> Anonymous =
        Task.FromResult(new AuthenticationState(new ClaimsPrincipal(
            new ClaimsIdentity())));

    private readonly Task<AuthenticationState> state = Anonymous;

    public PersistentAuthenticationStateProvider(PersistentComponentState s)
    {
        if (!s.TryTakeFromJson<UserInfo>(nameof(UserInfo), out var u) || u is null)
            return;

        Claim[] claims = [
            new(ClaimTypes.NameIdentifier, u.UserId),
            new(ClaimTypes.Name, u.Email),
            new(ClaimTypes.Email, u.Email)];

        state = Task.FromResult(new AuthenticationState(new ClaimsPrincipal(
            new ClaimsIdentity(claims, "PersistentAuth"))));
    }

    public override Task<AuthenticationState> GetAuthenticationStateAsync() => state;
}

// ServiceDefaults/Extensions.cs 가 해 주는 일 (템플릿 생성물)
public static TBuilder AddServiceDefaults<TBuilder>(this TBuilder builder)
    where TBuilder : IHostApplicationBuilder
{
    builder.ConfigureOpenTelemetry();          // 로그 · 트레이스 · 메트릭
    builder.AddDefaultHealthChecks();          // /health · /alive
    builder.Services.AddServiceDiscovery();    // 이름 → 주소
    builder.Services.ConfigureHttpClientDefaults(http =>
    {
        http.AddStandardResilienceHandler();   // 재시도 · 타임아웃 · 회로 차단
        http.AddServiceDiscovery();
    });
    return builder;
}

public static class ProductEndpoints
{
    public static void MapProducts(this WebApplication app)
    {
        var g = app.MapGroup("/products").RequireAuthorization();

        // 표가 구간 단위로 부르는 조회 — 총 개수를 헤더로 같이 줍니다
        g.MapGet("/", async (InventoryDb db, HttpContext ctx,
                             string? q, int skip = 0, int take = 50) =>
        {
            var query = db.Products.AsNoTracking()
                .Where(p => q == null || p.Name.Contains(q) || p.Sku.Contains(q));

            ctx.Response.Headers["X-Total-Count"] =
                (await query.CountAsync()).ToString();

            return await query.OrderBy(p => p.Sku)
                              .Skip(skip).Take(take).ToListAsync();
        });

        g.MapPost("/adjust", AdjustAsync)
         .RequireAuthorization("CanAdjustStock");      // ★ 여기가 진짜 방어선
    }

    static async Task<IResult> AdjustAsync(
        AdjustStockRequest req, InventoryDb db,
        IHubContext<StockHub> hub, ClaimsPrincipal user)
    {
        // ① 같은 요청이 두 번 오면 원래 결과를 그대로 돌려줍니다
        if (await db.Moves.AnyAsync(m => m.RequestId == req.RequestId))
            return Results.Ok(new { duplicated = true });

        await using var tx = await db.Database.BeginTransactionAsync();

        var p = await db.Products.FirstOrDefaultAsync(x => x.Sku == req.Sku);
        if (p is null) return Results.NotFound();

        // ② 음수 재고 금지 — 서버에서만 판단합니다
        if (p.Stock + req.Delta < 0)
            return Results.Problem("재고가 부족합니다", statusCode: 409);

        p.Stock     += req.Delta;
        p.UpdatedAt  = DateTimeOffset.UtcNow;

        db.Moves.Add(new StockMove {                    // ③ 감사 로그
            RequestId = req.RequestId, Sku = req.Sku, Delta = req.Delta,
            Reason = req.Reason, ActorId = user.FindFirst("sub")!.Value,
            At = DateTimeOffset.UtcNow });

        await db.SaveChangesAsync();
        await tx.CommitAsync();

        // ④ 보고 있는 사람 모두에게 알립니다
        await hub.Clients.Group($"sku:{p.Sku}")
                 .SendAsync("StockChanged", p.Sku, p.Stock);

        return Results.Ok(new { stock = p.Stock });
    }
}
RequestId 로 중복을 막는 것이 실시간 화면에서 특히 중요합니다. 네트워크가 끊겼다 붙는 순간 사용자가 저장을 두 번 누르는 일이 흔하고, 재고는 두 번 빠지면 되돌리기 어려운 값입니다.

public sealed class InventoryApiClient(HttpClient http)
{
    public async Task<(IReadOnlyList<Product> Rows, int Total)> GetPageAsync(
        string? q, int skip, int take, CancellationToken ct)
    {
        var url = $"products?q={Uri.EscapeDataString(q ?? "")}&skip={skip}&take={take}";
        using var res = await http.GetAsync(url, ct);
        res.EnsureSuccessStatusCode();

        var total = res.Headers.TryGetValues("X-Total-Count", out var v)
                    && int.TryParse(v.FirstOrDefault(), out var n) ? n : 0;
        var rows = await res.Content
                            .ReadFromJsonAsync<List<Product>>(ct) ?? [];
        return (rows, total);
    }

    public async Task<AdjustResult> AdjustAsync(AdjustStockRequest req)
    {
        using var res = await http.PostAsJsonAsync("products/adjust", req);

        if (res.StatusCode == HttpStatusCode.Conflict)
            return AdjustResult.Fail("재고가 부족합니다");

        if (res.StatusCode == HttpStatusCode.BadRequest)
        {
            var pd = await res.Content
                        .ReadFromJsonAsync<ValidationProblemDetails>();
            return AdjustResult.Invalid(pd!.Errors);      // 폼에 붙일 오류들
        }
        res.EnsureSuccessStatusCode();
        return AdjustResult.Ok();
    }
}

@code {
    [Parameter] public string Sku { get; set; } = "";
    private AdjustStockRequest form = new();
    private EditContext? ctx;
    private ValidationMessageStore? store;
    private bool busy;

    protected override void OnInitialized()
    {
        form.Sku = Sku;
        ctx   = new EditContext(form);
        store = new ValidationMessageStore(ctx);
    }

    private async Task SubmitAsync()
    {
        busy = true; store!.Clear();
        try
        {
            var r = await Api.AdjustAsync(form);
            if (r.Success) { Nav.NavigateTo("/"); return; }

            foreach (var (field, msgs) in r.Errors)
                foreach (var m in msgs) store.Add(ctx!.Field(field), m);

            if (r.Message is not null)
                store.Add(ctx!.Field(nameof(form.Delta)), r.Message);

            ctx!.NotifyValidationStateChanged();
        }
        finally { busy = false; }
    }
}
