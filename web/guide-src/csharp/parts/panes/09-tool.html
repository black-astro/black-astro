TOOL 02

로깅 — Serilog

장애가 났을 때 로그만 보고 재현할 수 있어야 합니다.

설정

builder.Host.UseSerilog((ctx, cfg) => cfg
    .ReadFrom.Configuration(ctx.Configuration)
    .Enrich.FromLogContext()
    .Enrich.WithProperty("app", "game-api")
    .WriteTo.Console(outputTemplate:
        "[{Timestamp:HH:mm:ss} {Level:u3}] {Message:lj} {Properties:j}{NewLine}{Exception}")
    .WriteTo.File("logs/log-.txt",
        rollingInterval: RollingInterval.Day,
        retainedFileCountLimit: 14,          // ★ 오래된 것은 지운다
        fileSizeLimitBytes: 100L * 1024 * 1024));
// 값을 넘기면 검색·집계가 됩니다
log.LogInformation("구매 완료 {PlayerId} {ItemId} {Cost}", pid, iid, cost);

// 요청 단위 공통 값
using (LogContext.PushProperty("TraceId", Activity.Current?.Id))
{
    await HandleAsync();
}

운영 규칙

  • 레벨 — Error 는 사람이 조치할 것만. 나머지는 Warning 이하
  • 보관 기간을 반드시 설정 — 디스크가 차서 서버가 죽는 사고가 흔합니다
  • 민감정보 금지 — 비밀번호·토큰·카드번호·주민번호
  • 운영에서 Debug 를 켜 두지 마세요 — I/O 가 응답을 느리게 합니다
  • 수집기(Seq·Loki·CloudWatch)로 보내면 검색이 됩니다
로그에 개인정보가 들어가면 삭제가 어렵습니다. 여러 곳에 복제되고 백업에도 남습니다. 애초에 남기지 않는 것이 유일한 방법입니다.
TOOL 03

HTTP 클라이언트 · Refit · Polly

외부 API 를 부르는 코드는 실패를 전제로 써야 합니다.

Refit — 인터페이스만

public interface IPayApi
{
    [Post("/v1/payments/{key}/confirm")]
    Task<PayResult> ConfirmAsync(string key, [Body] ConfirmReq req, CancellationToken ct);

    [Get("/v1/payments/{key}")]
    Task<PayResult> GetAsync(string key, CancellationToken ct);
}

builder.Services.AddRefitClient<IPayApi>()
    .ConfigureHttpClient(c =>
    {
        c.BaseAddress = new Uri(cfg["Pay:BaseUrl"]!);
        c.Timeout = TimeSpan.FromSeconds(10);
    })
    .AddStandardResilienceHandler();      // 재시도·서킷·타임아웃 한 줄
new HttpClient() 를 매번 만들지 마세요. 소켓이 고갈됩니다(TIME_WAIT). 반드시 IHttpClientFactory 를 통해 받으세요 — 위 등록 방식이 그것입니다.

복원력 정책

.AddResilienceHandler("pay", b => b
    .AddTimeout(TimeSpan.FromSeconds(3))
    .AddRetry(new HttpRetryStrategyOptions
    {
        MaxRetryAttempts = 2,
        BackoffType = DelayBackoffType.Exponential,
        UseJitter = true,                       // ★ 동시 재시도 방지
        ShouldHandle = args => ValueTask.FromResult(
            args.Outcome.Result?.StatusCode is HttpStatusCode.ServiceUnavailable
              or HttpStatusCode.RequestTimeout),
    })
    .AddCircuitBreaker(new HttpCircuitBreakerStrategyOptions
    {
        FailureRatio = 0.5, MinimumThroughput = 20,
        BreakDuration = TimeSpan.FromSeconds(15),
    }));
재시도해서는 안 되는 요청을 구분하세요. 결제 승인처럼 두 번 실행되면 안 되는 것은 멱등 키를 함께 보내거나 재시도를 끄고, 조회로 결과를 확인하는 방식이 안전합니다.
TOOL 04

테스트 — xUnit 기본기

밸런스와 규칙은 계속 바뀝니다. 바꿔도 안 깨진다는 확신이 속도를 만듭니다.

쓰는 법

public class InventoryTests
{
    [Fact]
    public void 아이템을_넣으면_수량이_는다()
    {
        var inv = new Inventory(capacity: 10);
        inv.Add(itemId: 1, count: 3);
        Assert.Equal(3, inv.CountOf(1));
    }

    [Theory]
    [InlineData(0)]
    [InlineData(-1)]
    public void 잘못된_수량은_거부한다(int count)
    {
        var inv = new Inventory(10);
        Assert.Throws<ArgumentOutOfRangeException>(() => inv.Add(1, count));
    }

    [Fact]
    public async Task 동시에_사도_골드가_음수가_되지_않는다()
    {
        var shop = new Shop(gold: 100);
        var tasks = Enumerable.Range(0, 10).Select(_ => shop.BuyAsync(cost: 30));
        var results = await Task.WhenAll(tasks);
        Assert.Equal(3, results.Count(r => r.Ok));    // 100 / 30 = 3회만 성공
    }
}

가짜 객체

var pay = Substitute.For<IPayApi>();
pay.ConfirmAsync(Arg.Any<string>(), Arg.Any<ConfirmReq>(), Arg.Any<CancellationToken>())
   .Returns(Task.FromResult(new PayResult(Ok: false, Code: "LIMIT")));

var sut = new OrderService(pay, repo);
var r = await sut.PlaceAsync(userId: 1, amount: 50_000);

Assert.False(r.Ok);
await pay.Received(1).ConfirmAsync(Arg.Any<string>(), Arg.Any<ConfirmReq>(), default);
무엇을 테스트할지 고르는 기준 — "틀리면 돈이나 데이터가 잘못되는 곳" 부터. 게임이라면 재화 계산·확률·인벤토리 한도·멱등성 입니다. UI 나 단순 전달 코드는 우선순위가 낮습니다.
목을 너무 많이 쓰면 "통과하는데 안 돌아가는" 테스트가 됩니다. DB 는 진짜로, 외부 결제·메일은 가짜로 가 실무에서 가장 잘 통하는 경계입니다.
TOOL 05

통합 테스트 — Testcontainers

인메모리 DB 로 통과한 코드가 운영 DB 에서 깨집니다. 진짜를 띄워 테스트합니다.

진짜 DB 로

public sealed class DbFixture : IAsyncLifetime
{
    private readonly PostgreSqlContainer _pg =
        new PostgreSqlBuilder()
            .WithImage("postgres:17-alpine")
            .WithCleanUp(true)
            .Build();

    public string ConnectionString => _pg.GetConnectionString();

    public async Task InitializeAsync()
    {
        await _pg.StartAsync();
        await using var db = new GameDb(Options());
        await db.Database.MigrateAsync();       // 실제 마이그레이션을 돌린다
    }
    public Task DisposeAsync() => _pg.DisposeAsync().AsTask();
}
인메모리 프로바이더(UseInMemoryDatabase)를 믿지 마세요. 제약·트랜잭션·SQL 함수가 실제와 다릅니다. "테스트는 통과했는데 배포하면 깨짐"의 단골 원인입니다.

API 전체 테스트

public class ShopApiTests(ApiFixture f) : IClassFixture<ApiFixture>
{
    [Fact]
    public async Task 멱등키가_같으면_한_번만_처리된다()
    {
        var c = f.CreateAuthedClient(playerId: 1);
        var body = new { itemId = 1, count = 1 };
        var key = Guid.NewGuid().ToString();

        c.DefaultRequestHeaders.Add("Idempotency-Key", key);
        var a = await c.PostAsJsonAsync("/shop/buy", body);
        var b = await c.PostAsJsonAsync("/shop/buy", body);   // 재시도

        Assert.Equal(HttpStatusCode.OK, a.StatusCode);
        Assert.Equal(HttpStatusCode.OK, b.StatusCode);
        Assert.Equal(1, await f.CountInventoryAsync(playerId: 1, itemId: 1));
    }
}
느린 테스트는 마커로 분리하세요. [Trait("Category","Slow")] 를 붙이고 CI 에서 빠른 것 먼저 → 통과하면 느린 것 순으로 돌리면 피드백이 훨씬 빨라집니다.

  • 취약점 점검 — dotnet list package --vulnerable --include-transitive
  • 구식 패키지 점검 — dotnet list package --outdated

TOOL 07

CI / CD — GitHub Actions

사람이 손으로 빌드하는 순간 사고가 납니다. 같은 명령이 항상 같은 결과를 내게 만듭니다.

서버 · 라이브러리

name: ci
on: [push, pull_request]

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v5
      - uses: actions/setup-dotnet@v4
        with: { dotnet-version: '10.0.x' }
      - run: dotnet restore
      - run: dotnet build -c Release --no-restore
      - run: dotnet format --verify-no-changes        # 포맷 검사
      - run: dotnet test -c Release --no-build \
               --filter "Category!=Slow" \
               --collect:"XPlat Code Coverage"
      - run: dotnet list package --vulnerable --include-transitive

  docker:
    needs: build
    if: github.ref == 'refs/heads/main'
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v5
      - uses: docker/build-push-action@v6
        with:
          push: true
          tags: ghcr.io/${{ github.repository }}:${{ github.sha }}

Unity 빌드

jobs:
  unity:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v5
        with: { lfs: true }                 # ★ 에셋은 Git LFS
      - uses: actions/cache@v4
        with:
          path: Library                     # ★ 캐시하면 빌드가 몇 배 빨라집니다
          key: Library-${{ hashFiles('Assets/**','Packages/**') }}
      - uses: game-ci/unity-builder@v4
        with:
          targetPlatform: Android
          buildMethod: BuildScript.BuildAndroid
        env:
          UNITY_LICENSE: ${{ secrets.UNITY_LICENSE }}
Unity 프로젝트는 Git LFS 가 사실상 필수입니다. 텍스처·오디오·모델을 그냥 커밋하면 저장소가 수 GB가 되고 클론이 몇십 분 걸립니다. .gitattributes 를 처음부터 설정하세요.

TOOL 09

NuGet 패키지 만들기

여러 프로젝트가 같은 코드를 복사하고 있다면 패키지로 만들 때입니다.

만들고 올리기

<PropertyGroup>
  <PackageId>Acme.Game.Protocol</PackageId>
  <Version>1.2.0</Version>
  <Authors>Acme</Authors>
  <Description>게임 클라이언트·서버 공용 패킷 정의</Description>
  <GeneratePackageOnBuild>true</GeneratePackageOnBuild>
  <IncludeSymbols>true</IncludeSymbols>
  <SymbolPackageFormat>snupkg</SymbolPackageFormat>
</PropertyGroup>
dotnet pack -c Release
dotnet nuget push bin/Release/*.nupkg \
  --source https://nuget.pkg.github.com/acme/index.json \
  --api-key $TOKEN

사내 공용 패키지의 규칙

  • 버전 규칙(SemVer) — 깨지는 변경은 메이저를 올리세요
  • 변경 이력을 패키지와 함께 (무엇이 바뀌었는지)
  • 의존성을 최소로 — 공용 패키지가 무거우면 모두가 무거워집니다
  • 심볼 포함 — 디버깅 시 소스로 들어갈 수 있습니다
  • 게임이라면 클라이언트·서버 공용 프로토콜이 가장 좋은 후보입니다
Unity 에서 쓸 패키지는 제약이 있습니다. Unity 는 NuGet 을 기본 지원하지 않아 DLL 을 직접 넣거나 NuGetForUnity 를 씁니다. .NET Standard 2.1 을 타깃으로 만들어야 호환됩니다.

async UniTaskVoid StartGameAsync(CancellationToken ct)
{
    await UniTask.Delay(500, cancellationToken: ct);
    var prefab = await Addressables.LoadAssetAsync<GameObject>("Boss")
                                   .ToUniTask(cancellationToken: ct);
    Instantiate(prefab);
}
