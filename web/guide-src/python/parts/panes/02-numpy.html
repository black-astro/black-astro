NUMPY 01

ndarray — 한 덩어리로 붙어 있는 배열

파이썬 리스트와 NumPy 배열의 결정적 차이는 메모리에 어떻게 놓여 있느냐입니다. 이 하나가 속도 차이의 전부를 설명합니다.

메모리 구조 비교

리스트가 느린 이유

  • 각 원소가 독립된 파이썬 객체(PyObject)라 메모리에 흩어져 있음
  • 리스트는 그 객체들의 주소(포인터)만 들고 있음
  • 값 하나 읽으려면 포인터를 따라 점프해야 함 → CPU 캐시 미스
  • 더할 때마다 “이게 int인가 str인가” 타입 검사를 반복

배열이 빠른 이유

  • 값들이 연속된 메모리 블록에 나란히 놓임
  • 모든 원소가 같은 타입·같은 크기 → 주소 계산만으로 접근
  • 연산 루프가 C로 컴파일되어 돌아감 (파이썬 인터프리터 밖)
  • CPU의 SIMD(한 번에 여러 값 계산) 명령까지 활용

첫 코드

import numpy as np      # 관례적 별칭

a = np.array([1, 2, 3, 4])
a * 2                   # array([2, 4, 6, 8])  <- 반복문 없음!

lst = [1, 2, 3, 4]
lst * 2                 # [1,2,3,4,1,2,3,4]    <- 리스트는 '반복'!
가장 헷갈리는 지점 — 같은 * 2인데 리스트는 길이가 2배가 되고 배열은 값이 2배가 됩니다. +도 마찬가지로 리스트는 이어붙이기, 배열은 덧셈입니다.
Java 비유 — 파이썬 list는 ArrayList<Object>, ndarray는 double[] 원시 배열입니다. Integer 박싱 객체들의 리스트와 int[]의 성능 차이를 떠올리면 정확히 같은 이야기입니다.
넘파이가 빠른 이유는 알고리즘이 아니라 값이 붙어 있다는 사실 하나입니다.
NUMPY 02

배열 만들기 — 목적별 생성 함수

버튼을 눌러 각 함수가 만들어내는 모양을 확인하세요.

생성 함수 미리보기

기본 생성

np.array([1,2,3])              # 리스트 -> 배열
np.array([[1,2],[3,4]])        # 2차원
np.array([1,2,3], dtype=float) # 타입 지정

np.zeros(5)          # [0. 0. 0. 0. 0.]
np.zeros((2,3))      # 2행 3열 0 행렬
np.ones((3,3))       # 전부 1
np.full((2,2), 7)    # 전부 7
np.eye(3)            # 단위행렬 (대각선만 1)
np.empty(3)          # 초기화 안 함 (쓰레기값, 가장 빠름)

# 기존 배열과 같은 모양으로
np.zeros_like(a)
np.ones_like(a)

수열 · 난수

np.arange(5)            # [0 1 2 3 4]
np.arange(2, 10, 2)     # [2 4 6 8]  (시작, 끝, 간격)
np.linspace(0, 1, 5)    # [0. 0.25 0.5 0.75 1.] (개수 지정)

# 난수 (신형 API 권장)
rng = np.random.default_rng(42)   # seed 고정 -> 재현 가능
rng.random(5)              # 0~1 균등분포
rng.integers(1, 7, 10)     # 주사위 10번
rng.normal(0, 1, 1000)     # 정규분포 (평균0, 표준편차1)
rng.choice([1,2,3], 5)     # 임의 추출
rng.shuffle(a)             # 섞기
arange vs linspace — 간격을 알면 arange, 개수를 알면 linspace. 실수 간격일 때 arange는 부동소수점 오차로 원소 개수가 들쭉날쭉해질 수 있어 linspace가 안전합니다.
NUMPY 03

shape · dtype · 차원(axis)

NumPy에서 에러의 90%는 shape이 안 맞아서 납니다. 이 세 가지만 정확히 읽을 줄 알면 됩니다.

차원별 모양

필수 속성

a = np.array([[1,2,3],[4,5,6]])

a.shape      # (2, 3)   행 2, 열 3
a.ndim       # 2        차원 수
a.size       # 6        전체 원소 개수
a.dtype      # int64    데이터 타입
a.itemsize   # 8        원소 하나의 바이트
a.nbytes     # 48       전체 바이트
a.T          # 전치 (행<->열)
shape 읽는 법 — (2,3)은 “바깥쪽에 2개, 각각 안에 3개”. (10, 28, 28, 3)이면 “이미지 10장 × 세로28 × 가로28 × RGB3채널”처럼 바깥에서 안으로 읽습니다.
Windows 에서도 int64 입니다 — 예전 NumPy 1.x 는 Windows 만 기본 정수가 int32 라 21억을 넘기면 조용히 뒤집혔는데, NumPy 2.0 에서 다른 OS 와 int64 로 통일되었습니다.

dtype — 타입이 곧 메모리

dtype크기범위 / 용도
int81B-128 ~ 127
int324B±21억
int648B기본 정수형
float324B딥러닝 기본
float648B기본 실수형
bool1BTrue/False 마스크
object-파이썬 객체 (느림, 피하세요)
a.astype(np.float32)     # 타입 변환 (복사본 생성)
np.array([1,2], dtype=np.int8)

# 정수 오버플로 주의!
np.array([127], dtype=np.int8) + 1   # -128 로 뒤집힘
암묵적 승격 — int 배열에 실수를 넣으면 잘립니다. a = np.array([1,2,3]); a[0] = 1.9 → 1이 저장됩니다. 배열은 타입이 고정이라 판다스처럼 알아서 float로 바뀌지 않습니다.
shape 를 소리 내어 읽는 습관 하나로 차원 에러의 절반이 사라집니다.
NUMPY 04

인덱싱 · 슬라이싱 — 그리고 view의 함정

NumPy 슬라이싱은 리스트와 달리 복사본이 아니라 원본을 들여다보는 창(view)입니다. 이걸 모르면 원본이 왜 바뀌었는지 영원히 못 찾습니다.

2D 슬라이싱 시뮬레이터 — 코드를 클릭

인덱싱 문법

a = np.arange(12).reshape(3,4)

a[0]         # 0행 전체 -> [0 1 2 3]
a[0, 2]      # 0행 2열 -> 2   (a[0][2] 보다 빠름)
a[:, 1]      # 1열 전체 -> [1 5 9]
a[1:, 2:]    # 1행부터 x 2열부터
a[::2]       # 2칸씩 건너뛰기
a[::-1]      # 뒤집기
a[-1, -1]    # 마지막 원소

# 리스트와 다른 점: 콤마로 차원을 구분!
# 리스트라면 a[0][2], 배열은 a[0, 2]

view vs copy

a = np.arange(5)          # [0 1 2 3 4]

b = a[1:4]                # view (원본 공유!)
b[0] = 99
print(a)                  # [0 99 2 3 4]  <- 원본이 바뀜!

c = a[1:4].copy()         # 명시적 복사
c[0] = 0
print(a)                  # 원본 그대로

# view 여부 확인
b.base is a               # True -> view
c.base is None            # True -> 독립 배열

# 팬시 인덱싱은 항상 copy
d = a[[0,2,4]]            # copy
왜 view인가 — 100만 행 배열의 절반을 슬라이스할 때마다 복사하면 메모리가 터집니다. NumPy는 기본을 무복사로 두고, 필요할 때만 .copy()를 부르게 설계했습니다. 판다스에서 보던 SettingWithCopyWarning도 뿌리가 여기입니다.
리스트와 정반대로 동작한다는 점만 기억하면 사고가 사라집니다.

NUMPY 05

reshape · 전치 — 데이터는 그대로, 모양만 바꾸기

12개의 값은 그대로 두고 shape만 바꿉니다. 버튼을 누르면 같은 셀이 실제로 재배치됩니다.

reshape 애니메이션 — 원소 12개 고정

모양 바꾸기

a = np.arange(12)

a.reshape(3, 4)      # 3행 4열
a.reshape(4, -1)     # -1 = 알아서 계산 -> (4,3)
a.reshape(2, 2, 3)   # 3차원으로

a.ravel()            # 1차원으로 펴기 (가능하면 view)
a.flatten()          # 1차원으로 펴기 (항상 copy)

a.T                  # 전치
np.transpose(a, (1,0,2))   # 축 순서 직접 지정

# 차원 추가/제거 — 브로드캐스팅에서 자주 씀
a[:, np.newaxis]     # (12,) -> (12,1)
a[np.newaxis, :]     # (12,) -> (1,12)
np.expand_dims(a, 0)
np.squeeze(b)        # 크기 1인 축 제거

reshape의 규칙

  • 원소 개수(size)가 반드시 같아야 합니다. 12 → (5,3)은 에러
  • 채우는 순서는 기본이 C 순서(행 우선). 마지막 축부터 채웁니다
  • -1은 “나머지 하나는 알아서” — 한 번만 쓸 수 있습니다
  • reshape은 대개 view라 값을 바꾸면 원본도 바뀝니다
전치(.T)는 값을 옮기지 않습니다 — 메모리는 그대로 두고 “읽는 순서(stride)”만 바꿉니다. 그래서 거의 공짜로 빠릅니다. 다만 이후 연산이 메모리 순서와 어긋나 느려질 수 있어, 반복 연산 전이라면 np.ascontiguousarray()를 고려하세요.
Java 비유 — int[12] 하나를 두고 arr[i*4+j]로 읽으면 3×4 행렬, arr[i*3+j]로 읽으면 4×3 행렬이 되는 것과 같습니다. reshape은 인덱스 계산식만 갈아끼우는 작업입니다.
NUMPY 06

결합 · 분할 — 배열 붙이고 자르기

판다스의 concat에 해당하는 기능입니다. axis 방향만 정확히 잡으면 됩니다.

concatenate 방향
a = np.array([[1,2],[3,4]])
b = np.array([[5,6],[7,8]])

np.concatenate([a, b], axis=0)   # 세로로 (4,2)
np.concatenate([a, b], axis=1)   # 가로로 (2,4)

np.vstack([a, b])    # = axis=0 (vertical)
np.hstack([a, b])    # = axis=1 (horizontal)
np.stack([a, b])     # 새 축 추가 -> (2,2,2)

# 분할
np.split(x, 3)              # 3등분
np.split(x, [2, 5])         # 2, 5 위치에서 자르기
np.vsplit(a, 2)             # 세로로 분할
np.hsplit(a, 2)             # 가로로 분할

# 원소 추가/삭제 (매번 전체 복사 — 반복문 안에서 쓰지 마세요)
np.append(a, [9, 10])
np.insert(a, 1, 99)
np.delete(a, 0, axis=0)
안티패턴 — 반복문에서 arr = np.append(arr, x)를 돌리면 매번 전체를 새로 복사해 O(n²)이 됩니다. 파이썬 리스트에 모았다가 마지막에 np.array(lst) 하거나, 크기를 미리 아는 경우 np.empty(n)으로 잡아놓고 채우세요.

vstack? hstack? — axis 하나로 통일해 기억하세요

a = np.array([[1, 2], [3, 4]])     # (2, 2)
b = np.array([[5, 6], [7, 8]])     # (2, 2)

np.concatenate([a, b], axis=0)     # 아래로 쌓기 → (4, 2)
# = np.vstack([a, b])              #   "행(axis 0)이 늘어난다"

np.concatenate([a, b], axis=1)     # 옆으로 붙이기 → (2, 4)
# = np.hstack([a, b])              #   "열(axis 1)이 늘어난다"

np.stack([a, b], axis=0)           # ★ 새 차원을 만들며 쌓기 → (2, 2, 2)
# concatenate 는 기존 축에 이어 붙이고,
# stack 은 한 차원을 '추가'합니다 — 이미지 100장 → (100, H, W)
이미지 배치가 대표 사례 — 같은 크기 사진 100장을 np.stack(imgs) 하면 (100, H, W, 3) 배열 하나가 되고, 정규화·평균 계산이 반복문 없이 한 줄이 됩니다.

분할 — 훈련/검증 나누기까지

arr = np.arange(12).reshape(6, 2)

top, bottom  = np.vsplit(arr, 2)      # 위아래 반반
left, right  = np.hsplit(arr.T, [1])  # 1열 기준으로 쪼개기
chunks = np.array_split(arr, 4)       # ★ 안 나눠떨어져도 OK

# 실전 — 데이터를 8:2 로 나누기 (섞어서)
idx = np.random.default_rng(42).permutation(len(arr))
cut = int(len(arr) * 0.8)
train, valid = arr[idx[:cut]], arr[idx[cut:]]
split 이 돌려주는 것은 view 입니다 — 쪼갠 조각을 고치면 원본도 바뀝니다(04번의 view 함정과 같은 것). 독립된 조각이 필요하면 .copy() 를 붙이세요.
NUMPY 07

브로드캐스팅 — 모양이 달라도 계산되는 마법

NumPy의 가장 강력하면서 가장 헷갈리는 기능입니다. 작은 배열이 실제로 복사되지는 않으면서 큰 배열 모양으로 “늘어난 것처럼” 계산됩니다. 버튼을 눌러 늘어나는 과정을 보세요.

브로드캐스팅 시뮬레이터

브로드캐스팅 규칙 3줄

  • ① 뒤에서부터 차원을 하나씩 비교합니다
  • ② 크기가 같거나, 둘 중 하나가 1이면 통과
  • ③ 1인 쪽이 상대 크기만큼 늘어난 것처럼 동작 (실제 복사 없음)
# 뒤에서부터 맞춰보기
(3, 4) + (4,)      -> (3, 4)   ✅  4==4, 3은 그대로
(3, 4) + (3, 1)    -> (3, 4)   ✅  1이 4로 확장
(3, 1) + (1, 4)    -> (3, 4)   ✅  양쪽 다 확장
(3, 4) + (3,)      -> ❌ ERROR  4 != 3
(2, 3, 4) + (3, 1) -> (2, 3, 4) ✅
가장 흔한 에러 메시지
operands could not be broadcast together with shapes (3,4) (3,)
→ b[:, None] 또는 b.reshape(-1,1)로 축을 명시해 주면 대부분 해결됩니다.

실전 활용

a = np.arange(12).reshape(3,4)

# 전체에 상수 연산
a * 2 + 1

# 열마다 다른 가중치 적용 (shape (4,))
가중치 = np.array([1, 2, 3, 4])
a * 가중치

# 행마다 다른 값 더하기 -> 축을 세워줘야 함
행보정 = np.array([10, 20, 30])
a + 행보정[:, None]        # (3,1) 로 만들어 브로드캐스팅

# 표준화 (열 기준) — 머신러닝 전처리의 정석
(a - a.mean(axis=0)) / a.std(axis=0)

# 구구단 표 한 줄로 (외적)
np.arange(1,10)[:, None] * np.arange(1,10)[None, :]
메모리를 안 쓰는 게 핵심 — (10000, 1) + (1, 10000)은 1억 개짜리 결과를 만들지만, 입력 두 개는 각각 1만 개만 차지합니다. “늘어난 것처럼”은 어디까지나 계산할 때만입니다.
차원 에러가 나면 두 shape 를 오른쪽 정렬해서 적어 보세요 — 대개 그 자리에서 보입니다.
NUMPY 08

유니버설 함수(ufunc) — 배열 전체에 한 번에

원소 하나하나에 적용되지만 내부는 C 루프로 도는 함수들입니다.

수학 함수

np.sqrt(a)      np.exp(a)      np.log(a)
np.log10(a)     np.abs(a)      np.sign(a)
np.sin(a)       np.cos(a)      np.tan(a)
np.power(a, 2)  np.mod(a, 3)

# 반올림
np.round(a, 2)   np.floor(a)   np.ceil(a)   np.trunc(a)

# 비교 -> bool 배열 반환
np.greater(a, 5)      # a > 5 와 동일
np.isnan(a)   np.isinf(a)   np.isfinite(a)

# 두 배열 원소별 비교
np.maximum(a, b)   # 원소별 큰 값
np.minimum(a, b)
np.clip(a, 0, 100) # 범위 밖 값을 자르기 (이상치 처리)

조건 연산

axis 완전정복 — “축이 사라진다”

axis=0인데 왜 열 평균이 나오지? 여기서 대부분 헷갈립니다. 핵심은 하나입니다 — 지정한 축이 계산되어 없어진다. 버튼을 눌러 어느 방향으로 뭉개지는지 보세요.

axis 시각화 — a.sum(axis=?)

집계 함수

a = np.arange(12).reshape(3,4)

a.sum()            # 66      전체
a.sum(axis=0)      # (4,)    열별 합  <- 행이 사라짐
a.sum(axis=1)      # (3,)    행별 합  <- 열이 사라짐
a.sum(axis=0, keepdims=True)   # (1,4) 축 유지

a.mean()   a.std()   a.var()
np.median(a)          # median 은 메서드가 아니라 np. 함수
a.min()    a.max()    # np.ptp(a) = max-min
a.argmin() a.argmax()          # 최소/최대 '위치'
a.cumsum() a.prod()

np.percentile(a, [25, 50, 75])
np.unique(a, return_counts=True)

axis 외우는 법

  • shape의 몇 번째 숫자를 없앨 것인가가 axis입니다
  • (3,4)에서 axis=0 → 3이 사라져 (4,) = 열마다 하나씩
  • (3,4)에서 axis=1 → 4가 사라져 (3,) = 행마다 하나씩
  • 화살표 방향으로 훑으면서 뭉갠다고 상상하면 헷갈리지 않습니다
  • keepdims=True를 쓰면 축이 1로 남아 브로드캐스팅에 바로 쓸 수 있습니다
# keepdims의 진가 — 행별 비율 구하기
행합 = a.sum(axis=1, keepdims=True)   # (3,1)
비율 = a / 행합                        # 브로드캐스팅 성공!

# keepdims 없으면
행합 = a.sum(axis=1)     # (3,)
a / 행합                 # ❌ (3,4) vs (3,) 에러
판다스와 같은 규칙 — df.sum(axis=0)도 열별 합계입니다. 판다스의 axis는 NumPy에서 그대로 물려받은 개념이라 한 번만 익히면 둘 다 해결됩니다.
"axis=0 은 세로" 로 외우면 3차원에서 무너집니다 — 그 축이 없어진다로 외우세요.
