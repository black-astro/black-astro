DL 01

딥러닝은 무엇이 다른가

차이는 단 하나 — 특징(피처)을 누가 만드느냐입니다.

피처를 사람이 vs 기계가

머신러닝 (🤖 탭)
  사람: "면적, 역거리, 층수가 중요할 거야" → 피처 설계
  모델: 그 피처로 규칙 학습
  → 표 데이터에 강함. 사람의 도메인 지식이 핵심

딥러닝 (이 탭)
  사람: 원본(픽셀·파형·문자)을 그대로 넣는다
  모델: 낮은 층 = 선·모서리 → 중간 층 = 눈·바퀴
        → 높은 층 = 얼굴·자동차  ← 특징을 스스로 조립
  → 이미지·음성·언어처럼 피처를 사람이 못 만드는 영역 정복
이것을 표현 학습(representation learning)이라 부릅니다. 층(layer)을 깊게(deep) 쌓아 표현을 단계적으로 올리는 것이 "딥"러닝입니다.

딥러닝을 쓰는 기준

상황선택
이미지 · 음성 · 영상 · 자연어딥러닝 확정
표 데이터 수천~수십만 행부스팅이 보통 승리 (🤖 탭)
데이터가 아주 적음 (수백 건)고전 ML 또는 전이학습(l10)
글 이해·생성·요약직접 학습보다 LLM API 먼저 (✨ 탭)
2026년의 현실적인 조언 — 처음부터 학습(from scratch)하는 일은 실무에서 드뭅니다. 대부분 사전학습 모델 + 미세조정(l10, l14)입니다. 그래도 원리(l02~l08)를 모르면 미세조정도 감으로 하게 되니, 기초부터 갑니다.
DL 02

뉴런 · 층 · 활성화 함수

뉴런 하나는 곱하고 더하고 구부리기가 전부입니다. 이게 수백만 개 모인 것이 신경망입니다.

활성화 함수가 없으면 층을 아무리 쌓아도 직선 하나와 같습니다. 구부림이 있어야 복잡한 패턴을 표현합니다.

활성화 함수 — 무엇을 언제

함수모양쓰는 곳
ReLU음수는 0, 양수는 그대로은닉층 기본값
GELUReLU의 부드러운 버전Transformer 계열
Sigmoid0~1로 눌러 담기이진 분류 출력층
Softmax합이 1인 확률로다중 분류 출력층
고민되면 은닉층은 ReLU, 출력층은 문제에 맞게가 정답입니다. 회귀는 출력층에 활성화를 안 씁니다(숫자를 그대로 내보내야 하니까).

신경망 = 층 쌓기, 코드로는

import torch.nn as nn

model = nn.Sequential(
    nn.Linear(4, 64),    # 입력 4 → 뉴런 64개 층
    nn.ReLU(),           # 구부리기
    nn.Linear(64, 32),   # 64 → 32
    nn.ReLU(),
    nn.Linear(32, 3),    # 32 → 클래스 3개 점수
)
# nn.Linear(in, out)이 "완전연결층" —
# in×out 개의 가중치 + out 개의 편향을 가진다

sum(p.numel() for p in model.parameters())
# 2,467개 파라미터 — GPT류는 이것이 수십억~수조 개

DL 04

autograd — 미분을 기계가 대신한다

"어느 방향으로 고치면 오차가 줄까?"의 답이 기울기(gradient)이고, PyTorch가 자동으로 구해 줍니다.

경사하강법 — 산 내려가기

오차(loss)를 산의 높이라고 생각하면:

1. 지금 위치에서 경사(기울기)를 잰다   ← 미분
2. 내리막 방향으로 한 걸음            ← 가중치 갱신
3. 반복하면 골짜기(오차 최소)에 도달

가중치_새값 = 가중치 - 학습률 × 기울기
              ^^^^^^   ^^^^^^
              보폭을 정하는 게 학습률(learning rate)

학습률이 크면 → 골짜기를 건너뛰며 발산
학습률이 작으면 → 너무 느림
(그래서 l07에서 옵티마이저·스케줄러가 등장합니다)

PyTorch의 자동 미분

import torch

w = torch.tensor(3.0, requires_grad=True)  # 추적 대상 선언
x = torch.tensor(2.0)

loss = (w * x - 10) ** 2   # 오차 = (3×2-10)² = 16
loss.backward()            # ★ 역전파 — 기울기 자동 계산
print(w.grad)              # -16.0 (w를 키우면 오차가 줄어든다)

# 여기서 "역전파(backpropagation)"란:
# 출력에서 입력 방향으로 연쇄법칙을 거꾸로 적용해
# 모든 가중치의 기울기를 한 번에 구하는 알고리즘.
# 수백만 파라미터도 backward() 한 줄이면 끝 —
# 이것이 딥러닝을 가능하게 만든 단 하나의 트릭입니다
기울기는 누적됩니다. 매 스텝 optimizer.zero_grad()로 지우지 않으면 이전 기울기가 계속 더해져 학습이 엉망이 됩니다 — 초심자 사고 1위.
딥러닝 코드에서 사람이 직접 미분을 쓰는 일은 없습니다 — 기록과 역추적이 전부입니다.
DL 05

학습 루프 해부 — 다섯 줄의 심장

모든 딥러닝 코드의 중심에는 같은 다섯 줄이 있습니다. 이것만 외우면 됩니다.

순전파 → 오차 → 역전파 → 갱신. 어떤 최신 모델도 이 사이클 위에서 돕니다.

전체 학습 루프 — 이 형태를 통째로 기억하세요

import torch.nn as nn

loss_fn = nn.CrossEntropyLoss()
optimizer = torch.optim.AdamW(model.parameters(), lr=1e-3)

for epoch in range(10):                    # 데이터 전체 10바퀴
    model.train()                          # 학습 모드 (드롭아웃 ON)
    for x, y in train_loader:              # 배치 단위로
        x, y = x.to(device), y.to(device)

        pred = model(x)                    # 1. 순전파
        loss = loss_fn(pred, y)            # 2. 오차 측정

        optimizer.zero_grad()              # 기울기 초기화 (필수!)
        loss.backward()                    # 3. 역전파
        optimizer.step()                   # 4. 가중치 갱신

    model.eval()                           # 평가 모드 (드롭아웃 OFF)
    with torch.no_grad():                  # 기울기 계산 끄기 → 빠르고 가볍게
        acc = evaluate(model, val_loader)
    print(f"epoch {epoch}: loss={loss.item():.4f} val_acc={acc:.3f}")
model.train() / model.eval() / no_grad() 세 짝을 빼먹는 것이 loss는 주는데 검증 점수가 이상한 사고의 단골 원인입니다. 평가 블록은 항상 이 형태로 쓰세요.

첫 신경망 — 손글씨 숫자 인식

MNIST(28×28 손글씨)로 데이터 준비 → 모델 → 학습 전 과정을 완주합니다.

데이터 — Dataset과 DataLoader

from torchvision import datasets, transforms
from torch.utils.data import DataLoader

tf = transforms.Compose([
    transforms.ToTensor(),                  # 픽셀 0~255 → 0~1 텐서
    transforms.Normalize((0.1307,), (0.3081,)),  # 평균0 부근으로
])

train_ds = datasets.MNIST("data", train=True,  download=True, transform=tf)
test_ds  = datasets.MNIST("data", train=False, download=True, transform=tf)

train_loader = DataLoader(train_ds, batch_size=64, shuffle=True)
test_loader  = DataLoader(test_ds,  batch_size=256)
# DataLoader = 섞고, 배치로 묶고, 병렬로 읽어 주는 컨베이어

모델 — nn.Module 상속 (표준 형태)

class MLP(nn.Module):
    def __init__(self):
        super().__init__()
        self.net = nn.Sequential(
            nn.Flatten(),           # 28×28 이미지 → 784 벡터
            nn.Linear(784, 256), nn.ReLU(),
            nn.Linear(256, 128), nn.ReLU(),
            nn.Linear(128, 10),     # 숫자 0~9의 점수 10개
        )

    def forward(self, x):           # 순전파 정의
        return self.net(x)

model = MLP().to(device)
# l05의 학습 루프를 그대로 돌리면 → 5 에포크에 정확도 ~97%
출력이 확률이 아니라 점수(logit)인 것에 주목하세요. CrossEntropyLoss가 내부에서 softmax를 처리하므로 모델 끝에 softmax를 붙이지 않는 것이 PyTorch 관례입니다.

무엇이 부족한가 — 이 모델의 한계가 다음 섹션들의 이유

  • 픽셀을 일렬로 펴서(Flatten) 위치 정보를 버렸다 → 합성곱 CNN(l09)이 해결
  • 학습이 불안정하거나 과적합 → 정규화·드롭아웃(l08), 옵티마이저 선택(l07)
  • 내 데이터는 몇천 장뿐 → 사전학습 + 전이학습(l10)

드롭아웃 · 배치 정규화

nn.Sequential(
    nn.Linear(784, 256),

DL 09

CNN — 이미지를 보는 눈

작은 필터가 이미지를 훑으며 위치와 무관하게 패턴을 찾는 구조입니다. 🖼️ 이미지 탭의 커널(i08)과 같은 원리입니다.

합성곱의 아이디어

완전연결층의 문제 (l06)
  픽셀을 일렬로 펴면 "옆 픽셀"이라는 정보가 사라진다
  고양이가 왼쪽에 있든 오른쪽에 있든 같은 고양이인데
  완전연결층에겐 전혀 다른 입력이 된다

합성곱(Convolution)의 해법
  3×3 같은 작은 필터가 이미지 전체를 미끄러지며
  같은 가중치로 반복 검사 → "어디에 있든" 같은 패턴 감지
  필터 1개 = 특징 탐지기 1개 (모서리·질감·눈...)
  필터의 값들도 역전파로 학습된다 ★

풀링(Pooling)
  2×2 구역에서 최댓값만 남겨 크기 절반으로
  → 계산량 감소 + 위치 변화에 둔감해짐

작은 CNN — MNIST 정확도 99%대

class SmallCNN(nn.Module):
    def __init__(self):
        super().__init__()
        self.features = nn.Sequential(
            nn.Conv2d(1, 32, kernel_size=3, padding=1),
            nn.ReLU(),
            nn.MaxPool2d(2),          # 28×28 → 14×14
            nn.Conv2d(32, 64, 3, padding=1),
            nn.ReLU(),
            nn.MaxPool2d(2),          # 14×14 → 7×7
        )
        self.head = nn.Sequential(
            nn.Flatten(),
            nn.Linear(64 * 7 * 7, 128), nn.ReLU(),
            nn.Dropout(0.3),
            nn.Linear(128, 10),
        )

    def forward(self, x):
        return self.head(self.features(x))
# 앞부분(features) = 특징 추출 / 뒷부분(head) = 분류
# 이 2단 구조가 전이학습(l10)의 열쇠가 됩니다
CNN 이 이미지에 잘 맞는 이유는 층이 깊어서가 아니라 이미지의 성질을 구조에 넣었기 때문입니다.
DL 10

전이학습 — 거인의 어깨 위에서

남이 1,400만 장으로 학습한 모델을 가져와 내 데이터 수백 장으로 마무리합니다. 실무 표준입니다.

사전학습 모델 가져다 쓰기

from torchvision import models

# ImageNet으로 학습된 ResNet-18
model = models.resnet18(weights="IMAGENET1K_V1")

# 1. 특징 추출부는 얼린다 (가중치 고정)
for p in model.parameters():
    p.requires_grad = False

# 2. 마지막 분류층만 내 문제로 교체 (예: 불량/정상 2클래스)
model.fc = nn.Linear(model.fc.in_features, 2)

# 3. 교체한 층만 학습 → CPU로도 몇 분이면 끝
optimizer = torch.optim.AdamW(model.fc.parameters(), lr=1e-3)
모서리·질감·형태 같은 낮은 수준의 시각 특징은 어떤 문제든 공통이라 재사용이 됩니다. 이것이 전이(transfer)라는 이름의 이유입니다.

단계별 전략과 미세조정

내 데이터전략
수백 장몸통 얼리고 머리만 교체·학습
수천~수만 장머리 학습 후 전체를 아주 작은 lr로 미세조정
수십만 장 + 도메인 특수처음부터 학습도 검토
# 2단계 미세조정(fine-tuning) — 전부 녹이되 lr을 낮게
for p in model.parameters():
    p.requires_grad = True
optimizer = torch.optim.AdamW(model.parameters(), lr=1e-5)
# 사전학습된 지식을 "살짝만" 내 데이터 쪽으로 옮긴다
# lr이 크면 애써 배운 지식이 파괴됩니다 (파국적 망각)
언어 모델의 미세조정(LoRA 등)은 ✨ LLM 탭 c13에서 다룹니다. 원리는 여기와 같습니다.
밑바닥부터 학습할 이유는 거의 없습니다 — 대부분 전이학습이 정답입니다.
DL 11

순서가 있는 데이터 — RNN과 그 한계

문장·시계열은 순서가 정보입니다. RNN의 아이디어와 한계를 알아야 Transformer가 왜 나왔는지 이해됩니다.

RNN — 기억을 들고 순서대로 읽기

"나는 어제 극장에서 영화를 ___"

RNN의 방식: 단어를 하나씩 읽으며 "기억(은닉 상태)"을 갱신
  읽기: 나는 → 어제 → 극장에서 → 영화를
  기억: h1  →  h2  →  h3     →  h4  → "봤다" 예측

한계 1 — 긴 문장에서 앞 내용의 기억이 흐려진다
         (LSTM·GRU가 게이트로 완화했지만 근본 해결은 아님)
한계 2 — 순서대로만 처리 가능 → GPU 병렬화가 안 됨
         → 모델을 키울 수 없다

이 두 한계를 동시에 깬 것이 Attention (l12)

코드 맛보기 + 2026년의 위치

rnn = nn.LSTM(input_size=64, hidden_size=128,
              num_layers=2, batch_first=True)
out, (h, c) = rnn(x)   # x: (배치, 시간, 특징)
# out[:, -1]  → 마지막 시점의 표현으로 분류 등 수행
용도현재 권장
자연어 전반Transformer로 대체됨
가벼운 시계열·센서LSTM·GRU 여전히 실용적
수요 예측 (표+시간)부스팅+시차 피처가 강력 (🤖 탭)
RNN을 깊게 팔 필요는 없습니다. "순서 처리의 한계 → Attention의 등장"이라는 맥락을 잡는 것이 이 섹션의 목적입니다.
DL 12

Attention과 Transformer — 현대 AI의 골격

GPT·Claude·번역기·이미지 생성까지 전부 이 구조 위에 서 있습니다. 핵심은 놀랄 만큼 단순합니다.

Attention — 서로를 얼마나 참고할까

"그 배우는 감독에게 상을 받았다. 그는 기뻐했다."
                                    ^^
"그는"을 이해하려면 어느 단어를 봐야 할까?

Attention의 답: 모든 단어 쌍의 "관련도"를 계산해
관련 높은 단어의 정보를 많이 섞는다
  그는 → 배우(0.6) 감독(0.2) 상(0.1) ...

구현은 세 벡터의 곱:
  Q(질문) · K(색인) → 관련도 점수 → softmax로 비율화
  → V(내용)를 그 비율로 가중합

RNN과 결정적 차이:
  · 거리와 무관 — 문장 처음↔끝도 직통으로 연결
  · 모든 쌍을 동시에 계산 → GPU 병렬화 → 거대화 가능

Transformer 블록 — 레고처럼 쌓는다

Transformer 블록 1개 =
  ① Multi-Head Attention   ← 관계 파악 (여러 관점으로)
  ② LayerNorm + 잔차 연결   ← 학습 안정화
  ③ FFN (완전연결 2층)      ← 각 위치에서 정보 가공
  ④ LayerNorm + 잔차 연결

이 블록을 N번 쌓으면:
  N=12  → BERT-base, GPT-2 급
  N=32+ → 현대 LLM (수십억~수조 파라미터)

+ 위치 인코딩: Attention은 순서 개념이 없어서
  "몇 번째 단어인지"를 벡터로 따로 주입한다
GPT류의 학습 목표는 단 하나 — "다음 토큰 맞히기"입니다. 이 단순한 목표 + Transformer + 인터넷 규모 데이터가 LLM의 전부입니다. 그 활용법은 ✨ LLM 탭에서 이어집니다.

PyTorch로 Attention 한 번 돌려보기

import torch.nn as nn

attn = nn.MultiheadAttention(embed_dim=64, num_heads=8, batch_first=True)
x = torch.randn(2, 10, 64)          # (배치2, 단어10, 차원64)
out, weights = attn(x, x, x)        # self-attention: Q=K=V=x
print(out.shape)                    # (2, 10, 64) — 문맥이 섞인 표현
print(weights.shape)                # (2, 10, 10) — 단어 간 관련도 행렬

# 블록 통째로는 nn.TransformerEncoderLayer가 제공됩니다
# 실무에선 이마저 직접 안 쌓고 사전학습 모델(l14)을 씁니다
"Attention is all you need" 의 뜻은 순서 처리 없이 이것만으로 된다는 주장이었습니다.

학습 실전 — GPU · 체크포인트 · 디버깅

토이 예제와 실전의 간격을 메우는 운영 기술들입니다.

저장·재개와 혼합 정밀도

# 저장은 state_dict로 — 모델 통째 저장은 버전에 취약
torch.save({
    "model": model.state_dict(),
    "optimizer": optimizer.state_dict(),
    "epoch": epoch,
}, "ckpt.pt")

ckpt = torch.load("ckpt.pt", map_location=device)
model.load_state_dict(ckpt["model"])       # 재개

# 혼합 정밀도(AMP) — float16 연산으로 속도·메모리 개선
scaler = torch.amp.GradScaler()
with torch.amp.autocast(device_type="cuda"):
    pred = model(x)
    loss = loss_fn(pred, y)
scaler.scale(loss).backward()
scaler.step(optimizer)
scaler.update()
# 최신 GPU에서 2배 가까운 속도 · 메모리 절반

GPU 메모리 · 디버깅 처방전

CUDA out of memory
  → batch_size 절반으로 / AMP 켜기 / 모델 축소
  → 기울기 누적: 작은 배치 N번의 grad를 모아 1번 step
    (큰 배치와 같은 효과를 작은 메모리로)

loss가 안 떨어진다
  → lr 10배 올려보고 / 10배 내려보고
  → 데이터·라벨이 맞게 짝지어졌는지 눈으로 5개 확인
  → 아주 작은 데이터(배치 1개)에 과적합시켜 보기
    : 그것도 안 되면 모델/loss 코드가 잘못된 것 ★

loss가 nan
  → lr 과대 / 입력에 nan / log(0) — 순서대로 의심

train만 좋고 val이 나쁘다 → 과적합 (l08)
둘 다 나쁘다             → 과소적합 (모델·피처·lr)
"배치 1개 과적합 테스트"는 최고의 디버깅 도구입니다. 정상 코드라면 몇 십 스텝 안에 loss가 0 근처로 가야 합니다.

    "klue/bert-base", num_labels=2)   # 머리만 내 문제로 교체

    return tok(batch["text"], truncation=True, padding=True)

trainer = Trainer(
    model=model,
    args=TrainingArguments("out", num_train_epochs=3,
                           per_device_train_batch_size=16,

    eval_dataset=val_ds.map(encode, batched=True),
