왜 이렇게 갈리나 — 자료구조와 통신 도구는 다른 물건 🟡 중급

자바는 ArrayDeque(자료구조)와 LinkedBlockingQueue(통신 도구)가 같은 Queue 인터페이스를 공유하지만, 파이썬은 이름부터 다릅니다. deque 는 append/popleft, queue.Queue 는 put/get 입니다. queue.Queue 내부도 사실 deque 하나에 락과 조건 변수 세 개를 두른 것이라(SQ 06), 혼자 쓸 때 queue.Queue 를 고르면 아무도 기다리지 않는데 락만 잡았다 놓는 셈이 됩니다.

Python 2 시절 이름 — 옛 코드의 import Queue(대문자)는 Python 3 에서 queue 로 바뀌었습니다. asyncio.Queue(loop=...) 의 loop 인자는 3.10 에서 사라졌습니다. 2026 년 코드에서 보이면 고칠 대상입니다.
정리 — 혼자 쓰면 list(스택) · deque(큐·덱) · heapq(우선순위), 같이 쓰면 경계에 맞는 queue · asyncio.Queue · multiprocessing.Queue.
SQ 02

스택 — list 하나면 끝, 대신 끝에서만

파이썬에는 Stack 클래스가 없고, 만들 필요도 없습니다. list 의 오른쪽 끝이 top 입니다. 자바의 Stack extends Vector 처럼 버려진 과거가 없는 대신, 앞쪽에 쌓는 실수와 빈 스택 처리가 함정입니다.

list 를 스택으로 — 전부 실행 결과

타입으로 드러내고 싶을 때 — 얇은 래퍼 3.12+ 문법

class Stack[T]:                     # PEP 695 제네릭
    __slots__ = ("_items",)

    def __init__(self) -> None:
        self._items: list[T] = []

    def push(self, x: T) -> None:
        self._items.append(x)

    def pop(self) -> T:
        if not self._items:
            raise IndexError("pop from empty Stack")
        return self._items.pop()

    def peek(self) -> T | None:
        return self._items[-1] if self._items else None

    def __len__(self) -> int:
        return len(self._items)

    def __bool__(self) -> bool:
        return bool(self._items)


st = Stack[int]()
st.push(10); st.push(20)
print(st.peek(), len(st))            # 20 2
print(st.pop(), st.pop(), bool(st))  # 20 10 False
래퍼는 “중간 삽입 금지”를 타입으로 강제하고 싶을 때만 씁니다. 메서드 호출 한 단계가 더 붙으므로 핫 루프(알고리즘 풀이)에서는 맨 list 가 낫습니다.
스택 연산은 오른쪽 끝 한 칸만 바꿉니다. 그래서 list 가 스택으로 완벽합니다.

“분할 상환 O(1)” 의 실체 — 용량은 계단처럼 늘어난다 🟡 중급

CPython 의 list 는 포인터의 연속 배열(ob_item)과 할당된 칸 수(allocated)를 들고 있습니다. 칸이 모자라면 약 12.5% + 6 칸을 더 얹어 새로 잡고 옮깁니다. 옮기는 순간은 O(n) 이지만 드물게 일어나므로, n 번 append 의 총비용이 O(n) — 한 번당 평균 O(1) 이라는 뜻이 “분할 상환(amortized) O(1)”입니다. 아래 계단은 이 PC 에서 sys.getsizeof 로 실제로 잰 값입니다.

재할당은 가끔, 그러나 한 번에 O(n) — 평균을 내면 append 한 번이 O(1) 입니다.

SQ 03

큐(FIFO) — list.pop(0) 은 왜 느린가, 그래서 deque

list 의 앞을 빼는 코드는 짧은 데이터에서는 티가 안 나다가 데이터가 커지는 날 갑자기 시스템을 멈춥니다. 원인은 CPython list 가 연속 배열이라는 한 가지 사실입니다. 실제로 재 보면 n=10만에서 221배입니다.

list.pop(0) 은 뒤의 n−1 개를 한 칸씩 당깁니다. deque 는 왼쪽 끝 표시만 옮깁니다.
n=10만에서 1.2초 vs 5ms. deque 막대는 너무 짧아 거의 보이지 않습니다 — 그게 결론입니다.

deque 로 만드는 큐

from collections import deque

q: deque[str] = deque()
q.append("A")              # enqueue (뒤)
q.append("B")
q.append("C")
print(q[0])                # peek (앞) -> A
print(q.popleft())         # dequeue -> A
print(q)                   # deque(['B', 'C'])

try:
    deque().popleft()
except IndexError as e:
    print("IndexError:", e)      # pop from an empty deque

def poll(dq: deque):             # '특수값' 버전을 직접 만든다
    return dq.popleft() if dq else None
print(poll(q), poll(q), poll(q)) # B C None

q2 = deque([1, 2, 3])
q2.extend([4, 5])
while q2:                  # 비우면서 처리 — for 가 아니라 while
    x = q2.popleft()
    if x == 2:
        q2.append(20)      # 처리 중 일을 더 넣는 건 OK (BFS 와 같은 모양)
    print(x, end=" ")
print()                    # 1 2 3 4 5 20

SQ 04

덱의 속 — 64칸 블록을 이은 이중 연결 리스트

자바 ArrayDeque 는 원형 배열이고 C++ std::deque 는 청크 맵입니다. CPython 의 collections.deque 는 또 다릅니다 — 칸 64개짜리 블록을 앞뒤로 이은 사슬입니다(Modules/_collectionsmodule.c 의 BLOCKLEN 64). 이 구조 하나로 “양끝은 O(1), 가운데 인덱싱은 O(n)”이 전부 설명됩니다.

원소를 옮기지 않는 구조라서 list 의 “가끔 O(n) 재할당”조차 없습니다. 대신 i 번째 칸을 찾으려면 블록을 따라 걸어야 합니다.

블록 크기를 직접 확인

import sys
from collections import deque

for n in (1, 63, 64, 65, 128, 200):
    print(n, sys.getsizeof(deque(range(n))))
# 1 760      <- 빈 deque 도 블록 하나를 들고 시작
# 63 760
# 64 1288    <- +528 = 64칸 x 8바이트 + 링크 2 x 8바이트
# 65 1288
# 128 1816
# 200 2344

print(sys.getsizeof(deque(range(64)))
      - sys.getsizeof(deque(range(1))))   # 528
블록 하나가 528 바이트이므로 원소당 오버헤드는 약 8.25 바이트 — list(8 바이트 + 여유분)와 거의 같습니다. “연결 리스트라 메모리를 많이 먹는다”는 걱정은 원소마다 노드를 만드는 연결 리스트 얘기입니다.

우선순위 큐 — heapq 는 클래스가 아니라 함수 모음

힙의 원리(트리 ↔ 배열, sift-up)는 알고리즘 탭 g11 에 있습니다. 여기서는 실무에서 heapq 를 쓸 때 부딪히는 것을 다룹니다 — 최소 힙밖에 없다는 것, 같은 우선순위에서 TypeError 가 나는 것, 우선순위를 바꿀 방법이 없다는 것.

함수비용언제
heappush(h, x) / heappop(h)O(log n)기본. h 는 그냥 list — 직접 정렬하거나 고치면 힙이 깨짐
h[0]O(1)꺼내지 않고 최솟값 보기
heapify(h)O(n)이미 있는 리스트를 한 번에 힙으로. n 번 push(O(n log n))보다 빠름
heappushpop(h, x)O(log n)넣고 바로 최솟값 빼기 — 크기 k 유지(top-k)에 최적

가운데에 순번을 끼워 넣으면 TypeError 도 사라지고 같은 우선순위의 순서도 보장됩니다.

우선순위를 바꾸고 싶다 — 지연 삭제(lazy deletion) 🔴 고급

힙 안의 원소를 찾아 고치는 것은 O(n) 이고, 고친 뒤 힙 성질도 깨집니다(SQ 10). 표준 문서의 해법은 옛 항목에 “죽음” 표시만 하고 새 항목을 하나 더 넣는 것입니다. 죽은 항목은 꺼낼 때 버립니다.

우선순위 변경 = 옛 것에 표시 + 새 것 push. 다익스트라의 if d > dist[u]: continue 도 같은 생각입니다.
import heapq, itertools

class PQ:
    REMOVED = object()

    def __init__(self):
        self._h: list[list] = []
        self._entry: dict[str, list] = {}
        self._seq = itertools.count()

    def push(self, item: str, prio: int) -> None:
        if item in self._entry:                 # 이미 있으면 옛 항목을 '죽은 표시'
            self._entry.pop(item)[-1] = PQ.REMOVED
        entry = [prio, next(self._seq), item]
        self._entry[item] = entry
        heapq.heappush(self._h, entry)

    def pop(self) -> tuple[str, int]:
        while self._h:
            prio, _, item = heapq.heappop(self._h)
            if item is not PQ.REMOVED:          # 죽은 항목은 꺼낼 때 버린다
                del self._entry[item]
                return item, prio
        raise KeyError("pop from empty PQ")

pq2 = PQ()
pq2.push("a", 5); pq2.push("b", 3); pq2.push("a", 1)    # a 의 우선순위 5 -> 1
print(pq2.pop(), pq2.pop(), len(pq2._h))                # ('a', 1) ('b', 3) 1  <- 죽은 a 가 남음
힙은 FIFO 를 보장하지 않습니다 — 같은 우선순위끼리 나오는 순서는 넣은 순서와 무관합니다. “같은 우선순위면 먼저 온 것부터”가 요구사항이면 반드시 순번을 넣으세요. 스레드 간이면 queue.PriorityQueue 도 같은 규칙입니다.
정리 — heapq 는 list 를 힙처럼 다루는 함수 모음. (우선순위, 순번, 항목) 으로 넣고, 변경은 지연 삭제, 최대 힙은 3.14+ *_max 또는 부호 뒤집기.

스레드 안전 큐 — queue.Queue, 배압과 종료까지

스레드끼리 일을 주고받을 때 필요한 것은 넣고 빼기만이 아닙니다 — 비었으면 기다리기, 가득 차면 생산자 늦추기(배압), 다 끝났는지 알기, 깔끔하게 끝내기. queue.Queue 는 이 네 가지를 다 갖춘 유일한 표준 도구입니다.

queue.Queue = deque + 락 1 + 조건 변수 3 + 카운터. LifoQueue · PriorityQueue 는 저장소만 바꾼 하위 클래스입니다.
maxsize 가 배압, task_done/join 이 완료 추적, shutdown 이 종료입니다. 셋 다 직접 만들 필요가 없습니다.

생산자 1 · 소비자 3 · 유한 큐 · poison pill — 완전한 예제

import queue
import threading
import time

q: queue.Queue[int | None] = queue.Queue(maxsize=4)
results: list[int] = []
lock = threading.Lock()
STOP = None                            # poison pill (sentinel)
N_WORKERS = 3


def producer() -> None:
    for i in range(10):
        q.put(i)                       # 가득 차면 여기서 대기 = 배압
    for _ in range(N_WORKERS):         # 소비자 수만큼 알약
        q.put(STOP)


def consumer() -> None:
    while True:
        item = q.get()                 # 비어 있으면 대기
        try:
            if item is STOP:
                return                 # return 해도 finally 의 task_done 은 불림
            time.sleep(0.01)           # 일하는 척
            with lock:
                results.append(item * item)
        finally:
            q.task_done()              # get 1번 = task_done 1번 (예외가 나도)


threads = [threading.Thread(target=consumer) for _ in range(N_WORKERS)]
for t in threads:
    t.start()
producer()
q.join()                               # put 된 것 전부가 task_done 될 때까지
for t in threads:
    t.join()
print(sorted(results))                 # [0, 1, 4, 9, 16, 25, 36, 49, 64, 81]

import time

STOP = None

def worker(inq, outq) -> None:
    while True:
        item = inq.get()
        if item is STOP:                 # sentinel 로 종료
            break
        outq.put((item, item * item))

def main() -> None:
    inq: mp.Queue = mp.Queue(maxsize=100)
    outq: mp.Queue = mp.Queue()
    procs = [mp.Process(target=worker, args=(inq, outq)) for _ in range(2)]
    for p in procs: p.start()
    for i in range(8): inq.put(i)        # 객체는 pickle 되어 파이프로 건너감

PAIRS = {")": "(", "]": "[", "}": "{"}

def balanced(s: str) -> bool:
    st: list[str] = []
    for ch in s:
        if ch in "([{":
            st.append(ch)
        elif ch in PAIRS:              # 괄호가 아닌 글자는 무시
            if not st or st.pop() != PAIRS[ch]:
                return False
    return not st                      # 남은 여는 괄호가 있으면 실패

② 다음 큰 수 — 단조 감소 스택 O(n)

from collections.abc import Sequence

def next_greater(a: Sequence[int]) -> list[int]:
    ans = [-1] * len(a)
    st: list[int] = []                 # 값이 아니라 인덱스를 쌓는다
    for i, x in enumerate(a):
        while st and a[st[-1]] < x:   # 나보다 작은 대기자는 답을 찾음
            ans[st.pop()] = x
        st.append(i)
    return ans

print(next_greater([2, 1, 2, 4, 3]))   # [4, 2, 4, -1, -1]
인덱스를 쌓는 이유 — 답을 써 넣을 자리(ans[i])와 거리(i - j, “며칠 뒤 더 따뜻해지나”)를 함께 알 수 있습니다.

③ BFS — deque, 넣을 때 방문 표시

from collections import deque

def bfs(graph: dict[str, list[str]], start: str) -> dict[str, int]:
    dist = {start: 0}                  # dist 가 곧 visited
    q = deque([start])
    while q:
        u = q.popleft()
        for v in graph[u]:
            if v not in dist:          # 넣을 때 표시 — 중복 삽입 방지
                dist[v] = dist[u] + 1
                q.append(v)
    return dist

g = {"A": ["B", "C"], "B": ["D"], "C": ["D", "E"],
     "D": ["F"], "E": ["F"], "F": []}
print(bfs(g, "A"))
# {'A': 0, 'B': 1, 'C': 1, 'D': 2, 'E': 2, 'F': 3}

④ 0-1 BFS — 덱의 양끝을 다 쓴다

from collections import deque
from collections.abc import Iterable

def zero_one_bfs(n: int, edges: Iterable[tuple[int, int, int]],
                 s: int) -> list[float]:
    adj: list[list[tuple[int, int]]] = [[] for _ in range(n)]
    for u, v, w in edges:
        adj[u].append((v, w))
    dist = [float("inf")] * n
    dist[s] = 0
    dq = deque([s])
    while dq:
        u = dq.popleft()
        for v, w in adj[u]:
            if dist[u] + w < dist[v]:
                dist[v] = dist[u] + w
                # 가중치 0 은 앞에(지금 거리 그대로), 1 은 뒤에
                (dq.appendleft if w == 0 else dq.append)(v)
    return dist

print(zero_one_bfs(4, [(0, 1, 1), (0, 2, 0), (2, 1, 0), (1, 3, 1)], 0))
# [0, 0, 0, 1]

⑤ 슬라이딩 윈도우 최댓값 — 단조 덱 🟡 중급

창 크기 k 마다 max() 를 부르면 O(nk) 입니다. 덱에 “앞으로 최댓값이 될 가능성이 있는 인덱스”만 감소 순서로 남기면 각 원소는 한 번 들어가고 한 번 나가므로 O(n) 입니다. 뒤에서는 작은 것을 버리고(pop), 앞에서는 창 밖으로 나간 것을 버립니다(popleft) — 덱의 양끝이 모두 필요한 대표 예입니다.

“나보다 늦게 왔는데 더 큰 값”이 들어오면 나는 다시는 최댓값이 될 수 없으므로 버립니다.

⑤ 코드

from collections import deque
from collections.abc import Sequence

def window_max(a: Sequence[int], k: int) -> list[int]:
    dq: deque[int] = deque()           # 인덱스. a[dq] 는 감소
    out: list[int] = []
    for i, x in enumerate(a):
        while dq and a[dq[-1]] <= x:  # 뒤: 나보다 작은 건 쓸모없음
            dq.pop()
        dq.append(i)
        if dq[0] <= i - k:            # 앞: 창 밖으로 나감
            dq.popleft()
        if i >= k - 1:
            out.append(a[dq[0]])
    return out

print(window_max([1, 3, -1, -3, 5, 3, 6, 7], 3))
# [3, 3, 5, 5, 6, 7]

⑥ undo / redo — 스택 두 개

class Editor:
    def __init__(self) -> None:
        self.text = ""
        self._undo: list[str] = []
        self._redo: list[str] = []

    def type(self, s: str) -> None:
        self._undo.append(self.text)
        self._redo.clear()             # ★ 새 동작이면 redo 는 무효
        self.text += s

    def undo(self) -> None:
        if self._undo:
            self._redo.append(self.text)
            self.text = self._undo.pop()

    def redo(self) -> None:
        if self._redo:
            self._undo.append(self.text)
            self.text = self._redo.pop()

ed = Editor()
ed.type("안녕"); ed.type("하세요"); ed.undo()
print(ed.text)               # 안녕
ed.redo(); print(ed.text)    # 안녕하세요
ed.undo(); ed.type("!")
ed.redo(); print(ed.text)    # 안녕!  <- 새 입력 뒤라 redo 없음

import threading, time
from collections import deque
from collections.abc import Callable

class SlidingWindowLimiter:
    def __init__(self, limit: int, window: float,
                 clock: Callable[[], float] = time.monotonic) -> None:
        self.limit, self.window, self.clock = limit, window, clock
        self.hits: deque[float] = deque()
        self.lock = threading.Lock()   # 확인 후 추가 = 두 연산 -> 락

    def allow(self) -> bool:
        with self.lock:
            now = self.clock()
            while self.hits and self.hits[0] <= now - self.window:
                self.hits.popleft()    # 창 밖 기록 제거
            if len(self.hits) < self.limit:
                self.hits.append(now)
                return True
            return False

import asyncio
import random

async def retry_demo() -> None:
    random.seed(7)                                  # 실행 결과를 고정하려고
    q: asyncio.Queue[tuple[str, int]] = asyncio.Queue()
    log: list[str] = []
    jobs = ("a", "b", "c")
    for job in jobs:
        q.put_nowait((job, 0))

    async def call(job: str) -> None:              # 절반 확률로 실패하는 외부 호출
        await asyncio.sleep(0)
        if random.random() < 0.5:
            raise ConnectionError(job)

        await asyncio.sleep(0.01 * 2 ** attempt)    # 10ms, 20ms, 40ms ... (실무는 jitter 추가)
        await q.put((job, attempt))

    async def worker() -> None:
        while True:
            try:
                job, attempt = await q.get()
            except asyncio.QueueShutDown:
                return
            try:
                await call(job)
                log.append(f"{job} ok@{attempt}")
            except ConnectionError:
                if attempt < 3:
                    tg.create_task(requeue_later(job, attempt + 1))   # 워커를 막지 않음
                else:
                    log.append(f"{job} dead")       # 데드레터
            finally:
                q.task_done()

        for _ in range(2):

import heapq, itertools
from collections.abc import Callable

class Scheduler:
    def __init__(self) -> None:
        self._h: list[tuple[float, int, Callable[[], None]]] = []
        self._seq = itertools.count()

    def call_at(self, when: float, fn: Callable[[], None]) -> None:
        heapq.heappush(self._h, (when, next(self._seq), fn))

    def run_due(self, now: float) -> int:
        n = 0
        while self._h and self._h[0][0] <= now:   # 맨 위만 보면 됨
            _, _, fn = heapq.heappop(self._h)
            fn()
            n += 1
        return n

import time
from collections.abc import Callable

class Batcher:
    def __init__(self, size: int, max_wait: float,
                 sink: Callable[[list[str]], None],
                 clock: Callable[[], float] = time.monotonic) -> None:
        self.size, self.max_wait = size, max_wait
        self.sink, self.clock = sink, clock
        self.buf: list[str] = []
        self.first_at = 0.0

    def add(self, ev: str) -> None:
        if not self.buf:
            self.first_at = self.clock()
        self.buf.append(ev)
        if (len(self.buf) >= self.size
                or self.clock() - self.first_at >= self.max_wait):
            self.flush()

    def flush(self) -> None:
        if self.buf:
            batch, self.buf = self.buf, []   # 통째로 바꿔 끼움 — 복사 없음
            self.sink(batch)

import sys

N = 200_000                      # 부모 -> 자식 하나씩 이어진 사슬
children: dict[int, list[int]] = {i: [i + 1] for i in range(N - 1)}
children[N - 1] = []

def depth_recursive(u: int) -> int:
    return 1 + max((depth_recursive(v) for v in children[u]), default=0)

try:
    depth_recursive(0)
except RecursionError as e:
    print("RecursionError:", str(e)[:40])
    # RecursionError: maximum recursion depth exceeded
print(sys.getrecursionlimit())   # 1000

def depth_iterative(root: int) -> int:
    best = 0
    stack: list[tuple[int, int]] = [(root, 1)]   # (노드, 깊이)
    while stack:
        u, d = stack.pop()
        best = max(best, d)
        for v in children[u]:
            stack.append((v, d + 1))
    return best

print(depth_iterative(0))        # 200000

def postorder(tree: dict[str, list[str]], root: str) -> list[str]:
    out: list[str] = []
    stack: list[tuple[str, bool]] = [(root, False)]
    while stack:
        u, expanded = stack.pop()
        if expanded:
            out.append(u)                 # 두 번째 방문 = 자식 처리 끝
        else:
            stack.append((u, True))       # 나를 다시 쌓고
            for v in reversed(tree.get(u, [])):
                stack.append((v, False))  # 왼쪽 자식이 먼저 나오게 뒤집어
    return out

t = {"root": ["a", "b"], "a": ["a1", "a2"], "b": ["b1"]}
