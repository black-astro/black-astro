AUTO 01

두 갈래 — 좌표 기반 vs 컨트롤 기반

이 선택을 잘못하면 자동화 스크립트가 매주 깨집니다.

좌표는 화면이 그대로일 때만 맞습니다. 자동화가 매주 깨진다면 대개 이 선택이 원인입니다.

PyAutoGUI — 사람 흉내

마우스를 특정 좌표로 옮기고 클릭합니다. 화면에 보이는 것이면 무엇이든 조작할 수 있습니다.

  • ✅ 웹, 게임, 그림판, 원격 데스크톱까지 전부 가능
  • ✅ 배우기 쉽고 코드가 짧음
  • ❌ 창 위치·해상도·배율이 바뀌면 즉시 실패
  • ❌ 실행 중 사람이 마우스를 건드리면 망가짐
  • ❌ 창이 가려지면 안 됨 (항상 최상단이어야 함)

PyWinAuto — 창 내부 직접 제어

Windows가 관리하는 컨트롤 객체(버튼·입력창)를 이름으로 찾아 직접 명령합니다. 좌표가 필요 없습니다.

  • ✅ 창이 움직여도 가려져도 동작
  • ✅ 텍스트를 읽어올 수 있음 (검증 가능)
  • ✅ 해상도·배율에 영향 없음
  • ❌ Windows 네이티브 앱만 (웹·전자문서 뷰어 등은 한계)
  • ❌ 컨트롤 구조 파악에 학습 시간이 필요

한눈 시각화 — 창이 움직이면 무슨 일이 벌어지나

PyAutoGUI 는 3년 넘게 유지보수가 멈춰 있습니다 — 마지막 릴리스가 0.9.54 (2023-05-24) 이고 그 뒤로 새 버전이 없습니다. ★ 지금 동작 자체에는 문제가 없지만, 새 파이썬 버전 대응이 늦거나 아예 안 될 수 있습니다. 게다가 좌표 기반이라 화면 해상도·배율·창 위치가 바뀌면 바로 깨집니다. 그러니 좌표 기반(PyAutoGUI)보다 컨트롤 기반(PyWinAuto)을 먼저 쓰고, 대상이 웹이면 Playwright(🧰 도구상자 탭)로 내려가세요. PyAutoGUI 는 다른 방법이 없을 때의 최후 수단으로 남겨 두는 편이 좋습니다.
실무 판단 기준 — 대상이 Windows 프로그램(사내 ERP, 메모장, 엑셀 창 등)이면 PyWinAuto를 먼저 시도하고, 안 잡히는 부분만 PyAutoGUI로 보완하세요. 엑셀·아웃룩만 다룬다면 화면 조작 없이 pywin32(COM)가 더 견고하고, 웹이 대상이면 Playwright가 훨씬 안정적입니다.
먼저 확인할 것 — 자동화 대상 프로그램에 API·CSV 내보내기·DB 접근이 있다면 화면 자동화보다 그쪽이 100배 안정적입니다. GUI 자동화는 다른 방법이 없을 때의 최후 수단입니다.
AUTO 02

안전장치부터 걸고 시작하세요

자동화 스크립트는 마우스를 빼앗습니다. 무한 루프에 빠지면 멈출 방법이 없어 재부팅해야 할 수도 있습니다. 이건 선택이 아니라 필수입니다. 

import pyautogui

# ① 페일세이프 — 마우스를 화면 좌측 상단(0,0)으로 확 밀면 즉시 중단
pyautogui.FAILSAFE = True          # 기본값 True. 절대 끄지 마세요

# ② 모든 동작 사이에 지연 — 프로그램이 반응할 시간을 줍니다
pyautogui.PAUSE = 0.3

# ③ 비상 탈출 핫키 (별도 스레드로 감시)
import os, keyboard      # uv add keyboard
keyboard.add_hotkey("esc", lambda: os._exit(1))

# ④ 시작 전 카운트다운 — 창을 띄울 시간 확보
import time
for i in range(3, 0, -1):
    print(f"{i}초 후 시작…"); time.sleep(1)

개발 중 지켜야 할 습관

  • 처음 테스트는 메모장 같은 무해한 앱에서
  • 반복 횟수를 3회로 제한해 두고 검증 후 늘리기
  • 클릭 전에 화면을 캡처해 로그로 남기기
  • 실제 데이터가 아니라 테스트 데이터로 먼저 돌리기
  • 모니터 두 대라면 보조 모니터에서 실행
절대 하지 말 것 — 삭제·전송·결제 버튼을 누르는 자동화를 검증 없이 전체 루프로 돌리는 것. 반드시 dry-run 모드 (실제 클릭 대신 로그만 남기는 플래그)를 만들어 두세요.

dry-run 패턴

DRY_RUN = True      # 실전 전환 시에만 False

def click(x, y, label=""):
    if DRY_RUN:
        print(f"[DRY] click({x},{y}) {label}")
        return
    pyautogui.click(x, y)
    logger.info(f"click({x},{y}) {label}")

# 화면 상태를 남기는 습관
def snap(name):
    pyautogui.screenshot(f"logs/{name}_{time.time():.0f}.png")
왜 로그가 중요한가 — 자동화는 새벽에 혼자 돌다가 실패합니다. 어느 화면에서 멈췄는지 스크린샷이 없으면 원인 파악이 불가능합니다.

AUTO 04

키보드 입력과 한글 문제

PyAutoGUI의 typewrite는 한글을 입력하지 못합니다. 우회법이 정해져 있습니다.

키보드 기본

import pyautogui as pg

pg.write("Hello World", interval=0.05)   # 영문/숫자만!
pg.press("enter")
pg.press(["a","b","c"])
pg.keyDown("shift"); pg.press("left"); pg.keyUp("shift")

# 조합키
pg.hotkey("ctrl", "c")
pg.hotkey("ctrl", "shift", "esc")
pg.hotkey("alt", "tab")
pg.hotkey("win", "d")

# 주요 키 이름
# enter tab esc space backspace delete
# up down left right home end pageup pagedown
# f1~f12  ctrl alt shift win

한글 입력 — 클립보드 우회 ★

import pyperclip, pyautogui as pg   # uv add pyperclip

def type_korean(text):
    """한글 포함 텍스트를 안전하게 입력"""
    old = pyperclip.paste()          # 기존 클립보드 백업
    pyperclip.copy(text)
    pg.hotkey("ctrl", "v")
    time.sleep(0.1)
    pyperclip.copy(old)              # 원복 (예의)

type_korean("김민준 대리 보고서")
이 방식이 표준입니다 — 빠르고, IME(한/영 전환) 상태와 무관하게 동작합니다. 긴 영문 텍스트도 write보다 클립보드가 훨씬 빠릅니다.
주의 — 붙여넣기를 막아둔 입력창(보안 프로그램, 일부 ERP)에서는 동작하지 않습니다. 그럴 땐 PyWinAuto의 set_text()를 쓰거나, 한/영 전환 후 pg.write()로 자모를 보내야 합니다.

한글 입력 3단 폴백 — 이 순서로 시도하세요

import pyperclip, pyautogui as pg
from pywinauto.keyboard import send_keys

def type_korean(text: str, ctrl=None) -> None:
    # ① 컨트롤을 아는 경우 — 가장 확실 (입력기 우회)
    if ctrl is not None:
        ctrl.set_edit_text(text)          # pywinauto
        return

    # ② 클립보드 붙여넣기 — 빠르고 대부분 통함
    old = pyperclip.paste()               # 원래 내용 보존
    try:
        pyperclip.copy(text)
        pg.hotkey("ctrl", "v")
        pg.sleep(0.1)
    finally:
        pyperclip.copy(old)               # 사용자 클립보드 복원

# ③ 그래도 안 되면 — IME 를 영문으로 두고 유니코드 전송
#    send_keys 는 한글을 유니코드로 직접 보냅니다
send_keys("안녕하세요", with_spaces=True, pause=0.02)

한/영 상태 — 자동화가 깨지는 진짜 이유

  • pg.write() 는 영문 자판 기준입니다 — 한글 IME 가 켜져 있으면 "hello" 가 "ㅗ디ㅣㅐ" 로 들어갑니다
  • 반대로 아이디·명령어를 넣을 때 IME 가 켜져 있어도 같은 사고 — 입력 전에 IME 상태를 확정하는 것이 원칙입니다
# 현재 IME 상태 확인 · 강제 영문 전환 (Windows)
import ctypes
imm32, user32 = ctypes.windll.imm32, ctypes.windll.user32

def ime_off():
    hwnd = user32.GetForegroundWindow()
    ime  = imm32.ImmGetDefaultIMEWnd(hwnd)
    # 0x283 = WM_IME_CONTROL, 0x006 = SET_OPENSTATUS
    user32.SendMessageW(ime, 0x283, 0x006, 0)   # 0=영문, 1=한글

ime_off()
pg.write("admin123")     # 이제 안전
규칙으로 외우세요 — 영문·숫자는 ime_off 후 write, 한글은 클립보드나 set_text. 이 구분만 지켜도 "가끔 이상한 글자가 들어가는" 증상이 사라집니다.
AUTO 05

스크린샷과 이미지로 찾기

버튼 이미지를 저장해 두고 화면에서 찾아 클릭하는 방식입니다.

캡처 & 탐색

import pyautogui as pg

shot = pg.screenshot()                  # 전체 (PIL Image)
shot = pg.screenshot(region=(0,0,800,600))
pg.screenshot("logs/step1.png")

# 이미지 찾기 — 최신 pyautogui 는 못 찾으면 예외를 던집니다
try:
    loc = pg.locateOnScreen("button.png", confidence=0.9)
    # confidence 옵션은 opencv-python 이 설치돼 있어야 동작합니다
    center = pg.center(loc)             # Box -> 중심 좌표
    pg.click(center)
except pg.ImageNotFoundException:
    raise RuntimeError("버튼을 찾지 못함")

# 한 번에 (못 찾으면 역시 ImageNotFoundException)
pg.click(pg.locateCenterOnScreen("btn.png", confidence=0.85))

# 여러 개 찾기
for box in pg.locateAllOnScreen("row.png", confidence=0.9):
    print(box)

# 특정 색 픽셀 확인 (가장 빠른 상태 판별)
pg.pixel(100, 200)                      # (R,G,B)
pg.pixelMatchesColor(100, 200, (255,0,0), tolerance=10)

안정적으로 쓰는 요령

  • region을 지정하세요 — 전체 화면 검색은 느립니다(수백 ms)
  • confidence는 0.8~0.9 — 1.0은 거의 안 맞습니다
  • 템플릿 이미지는 변하지 않는 부분만 잘라 저장 (텍스트·숫자 제외)
  • 같은 배율(DPI)에서 캡처한 이미지를 쓰세요
  • 못 찾으면 즉시 실패시키지 말고 재시도 루프로 감싸기
def wait_image(path, timeout=10, conf=0.85, region=None):
    """이미지가 나타날 때까지 대기 후 좌표 반환"""
    end = time.time() + timeout
    while time.time() < end:
        try:
            return pg.locateCenterOnScreen(path, confidence=conf,
                                           region=region)
        except pg.ImageNotFoundException:
            time.sleep(0.4)
    raise TimeoutError(f"{path} 를 {timeout}초 안에 못 찾음")

pg.click(wait_image("확인버튼.png", region=(600,400,600,400)))
이 wait_image 함수 하나가 이미지 자동화의 90%를 커버합니다. time.sleep(5)로 무작정 기다리는 코드를 전부 이걸로 바꾸세요.
AUTO 06

PyWinAuto — 앱 연결과 backend

첫 단추는 backend 선택입니다. 여기서 잘못 고르면 컨트롤이 아예 안 보입니다.

앱 시작 / 연결

from pywinauto.application import Application

# 새로 실행
app = Application(backend="uia").start("notepad.exe")

# 이미 떠 있는 앱에 붙기
app = Application(backend="uia").connect(title="제목 없음 - Windows 메모장")
app = Application(backend="uia").connect(path="notepad.exe")
app = Application(backend="uia").connect(process=12345)

# 창 잡기
win = app.window(title_re=".*메모장.*")
win = app.window(class_name="Notepad")
win = app.top_window()

win.wait("ready", timeout=10)     # 준비될 때까지 대기 ★
win.set_focus()
win.maximize()
win.print_control_identifiers()   # 컨트롤 트리 출력 ★★★

자동화의 신뢰도는 성공 경로가 아니라 실패했을 때 무엇을 남기고 어디로 가느냐가 결정합니다.
import logging, time, functools
from pathlib import Path
import pyautogui as pg

# ── 로깅 설정 ──────────────────────────────────────────
Path("logs").mkdir(exist_ok=True)
logging.basicConfig(
    level=logging.INFO,
    format="%(asctime)s [%(levelname)s] %(message)s",
    handlers=[
        logging.FileHandler("logs/auto.log", encoding="utf-8"),
        logging.StreamHandler(),
    ],
)
log = logging.getLogger(__name__)

# ── 재시도 데코레이터 ──────────────────────────────────
def retry(times=3, delay=1.0, shot=True):
    def deco(fn):
        @functools.wraps(fn)
        def wrapper(*a, **kw):
            last = None
            for i in range(1, times + 1):
                try:
                    return fn(*a, **kw)
                except Exception as e:
                    last = e
                    log.warning(f"{fn.__name__} 실패 {i}/{times}: {e}")
                    if shot:
                        pg.screenshot(f"logs/fail_{fn.__name__}_{i}.png")
                    time.sleep(delay * i)      # 점점 길게 대기
            log.error(f"{fn.__name__} 최종 실패")
            raise last
        return wrapper
    return deco

# ── 사용 ───────────────────────────────────────────────
@retry(times=3, delay=1.5)
def 로그인(app, user, pw):
    win = app.window(title_re=".*로그인.*")
    win.wait("ready", timeout=15)
    win.child_window(auto_id="txtUser").set_text(user)
    win.child_window(auto_id="txtPw").set_text(pw)
    win.child_window(auto_id="btnLogin").click()
    win.wait_not("visible", timeout=20)      # 로그인 창이 닫히면 성공
    log.info("로그인 성공")

import logging, sys, traceback
from datetime import datetime
from pathlib import Path

LOG = Path.home() / "automation" / "logs"
LOG.mkdir(parents=True, exist_ok=True)

logging.basicConfig(
    level=logging.INFO,
    format="%(asctime)s %(levelname)s %(message)s",
    handlers=[
        logging.FileHandler(LOG / f"{datetime.now():%Y%m%d}.log", encoding="utf-8"),
        logging.StreamHandler(sys.stdout),
    ],
)

def guarded(step_name: str):
    """단계마다 스크린샷 + 알림. 실패해도 다음 작업은 계속 간다."""
    def deco(fn):
        def wrap(*a, **kw):
            t0 = datetime.now()
            try:
                r = fn(*a, **kw)
                logging.info("✓ %s (%.1fs)", step_name,
                             (datetime.now() - t0).total_seconds())
                return r
            except Exception:
                shot = LOG / f"fail_{step_name}_{datetime.now():%H%M%S}.png"
                pyautogui.screenshot(str(shot))          # ★ 증거를 남긴다
                logging.error("✗ %s\n%s", step_name, traceback.format_exc())
                notify(f"매크로 실패: {step_name}", shot)  # 슬랙·메일
                raise
        return wrap
    return deco

def with_retry(fn, tries=3, wait=2.0):
    for i in range(tries):
        try:
            return fn()
        except Exception:
            if i == tries - 1: raise
            logging.warning("재시도 %d/%d", i + 1, tries)
            ensure_clean_state()          # ★ 재시도 전에 상태를 되돌린다
            time.sleep(wait * (i + 1))
