타입 힌트는
실행을 바꾸지 않고
실수를 미리 보여 줍니다

파이썬은 동적 타입 언어라 def add(a, b) 에 무엇이든 넣을 수 있습니다. 코드가 작을 땐 이게 장점이지만, 파일이 수십 개를 넘으면 “이 함수가 None 을 돌려줄 수 있었나?”를 기억에 의존하게 됩니다. 타입 힌트는 그 기억을 코드에 적어 두고, mypy · pyright 같은 검사기가 실행 전에 대조하게 하는 장치입니다. 이 탭은 기본 표기부터 제네릭 · 변성 · Protocol · overload 까지 순서대로 쌓고, 마지막에 검사기 설정과 에러 메시지 사전으로 마무리합니다. 본문의 에러 메시지는 전부 이 PC 에서 mypy 2.4 · pyright 1.1.414 로 실제로 돌려 받은 문구입니다.

TYPE 01

타입 힌트는 누가 읽는가 — 런타임 · 검사기 · 에디터

가장 먼저 알아야 할 사실: 파이썬 실행기는 타입 힌트를 검사하지 않습니다. def f(x: int) 에 문자열을 넣어도 그대로 실행됩니다. 힌트를 읽는 것은 별도 프로그램(검사기)과 에디터, 그리고 pydantic · FastAPI 처럼 일부러 힌트를 읽도록 만든 라이브러리입니다.

힌트를 적기만 해서는 아무 일도 안 일어납니다. 검사기를 돌리거나(CI) 에디터가 보여 줄 때 비로소 쓸모가 생깁니다.

실행기는 힌트를 무시한다 — 직접 확인

def add(a: int, b: int) -> int:
    return a + b

add("1", "2")          # '12' — 에러 없이 실행됨
add.__annotations__    # {'a': int, 'b': int, 'return': int}
                       # ↑ 저장만 해 둠

# 검사기를 돌리면
#   $ uv run mypy app.py
#   app.py:4: error: Argument 1 to "add" has incompatible type "str";
#             expected "int"  [arg-type]
그래서 타입 힌트는 비용이 0입니다. 성능에 영향이 없고, 틀려도 프로그램은 돌아갑니다. 대신 검사기를 CI 에 걸지 않으면 힌트가 거짓말이 돼도 아무도 모릅니다.

왜 쓰나 — 세 가지 이득

이득예

TYPE 02

기본 표기 — 변수 · 함수 · 컬렉션 · None

3.9 이후로는 list[int] 처럼 내장 타입에 대괄호를 붙이고, 3.10 이후로는 int | None 처럼 세로 막대로 합집합을 씁니다. 옛 코드에 보이는 List · Dict · Optional · Union 은 같은 뜻의 이전 표기입니다.

한 장 정리 (3.10+ 표기)

# 변수
age: int = 31
name: str = "민준"
ratio: float = 0.5           # int 도 넣을 수 있음 (숫자 승격)
ok: bool = True
raw: bytes = b"\x00"

# 컬렉션 — 대괄호 안이 '원소 타입'
ids: list[int] = [1, 2]
tags: set[str] = {"a"}
score: dict[str, float] = {"국어": 90.5}

row: tuple[str, ...] = ("a", "b", "c")   # 길이 자유, 전부 str

# 없을 수도 있음
nick: str | None = None

# 여러 타입 중 하나
key: int | str = 3

# 함수
def greet(name: str, times: int = 1) -> str:
    return name * times

def log(msg: str) -> None:       # 반환값 없음
    print(msg)

None 을 돌려줄까, 예외를 던질까

정리 — list[int] · dict[str, int] · tuple[int, ...] · X | None. 옛 List · Optional 은 ruff UP 규칙으로 자동 변환. None 가능성을 반환 타입에 적는 것이 가장 큰 이득입니다.
TYPE 03

인자는 넓게 · 반환은 좁게 — collections.abc 추상 타입

def total(xs: list[int]) 라고 쓰면 튜플 · 집합 · 제너레이터를 넣을 때 검사기가 막습니다. 함수가 실제로 하는 일이 “돌면서 읽기”뿐이면 Iterable[int] 로 받아야 합니다. 필요한 능력만 요구하고, 돌려줄 땐 구체 타입을 약속하는 것이 원칙입니다.

함수가 for 로 돌기만 하면 Iterable, len · 인덱스가 필요하면 Sequence, 키 조회만 하면 Mapping. 노란 글씨가 실제로 넣을 수 있는 구체 타입입니다.

받을 때는 능력으로

from collections.abc import Iterable, Sequence, Mapping, Iterator

def total(xs: Iterable[int]) -> int:          # 돌기만 함
    return sum(xs)

total([1, 2]); total((1, 2)); total({1, 2})
total(x for x in range(3))                    # ✅ 전부 통과

def middle(xs: Sequence[str]) -> str:          # 인덱스 필요
    return xs[len(xs) // 2]

middle(["a", "b", "c"]); middle("abc")         # ✅ str 도 Sequence

def render(ctx: Mapping[str, object]) -> str:  # 읽기만 함
    return ", ".join(f"{k}={v}" for k, v in ctx.items())

# Mapping/Sequence 로 받으면 '수정하지 않는다'는 약속도 됩니다
def bad(ctx: Mapping[str, int]) -> None:
    ctx["x"] = 1
# error: Unsupported target for indexed assignment ("Mapping[str, int]")

돌려줄 때는 구체적으로

# ✅ 호출자가 list 의 모든 기능(append · sort)을 쓸 수 있음
def load_ids(path: str) -> list[int]: ...

# ❌ 반환을 Iterable 로 하면 호출자가 len() 도 못 씀
def load_ids(path: str) -> Iterable[int]: ...

# 제너레이터의 반환 타입
def read_lines(path: str) -> Iterator[str]:     # 보통은 이것으로 충분
    with open(path) as f:
        yield from f

from collections.abc import Generator
def avg() -> Generator[float, float, None]:     # send 까지 쓸 때
    #               yield ↑ send ↑ return ↑
    ...
하는 일인자 타입
for 로 한 번 돈다Iterable[T]
len · in · 여러 번 돈다Collection[T]
인덱스 · 슬라이스Sequence[T]
append · 수정MutableSequence[T] 또는 list[T]
키로 읽기Mapping[K, V]
정리 — 인자는 collections.abc 의 필요한 최소 능력(Iterable · Sequence · Mapping)으로, 반환은 list · dict 처럼 구체 타입으로. Mapping · Sequence 로 받으면 “수정 안 함” 약속까지 덤으로 생깁니다.
TYPE 04

타입 좁히기 — if 한 줄이 타입을 바꾼다

x: int | None 인 변수도 if x is not None: 안에서는 int 입니다. 검사기는 코드의 흐름을 따라가며 가능한 타입을 줄여 나가는데, 이것을 좁히기(narrowing)라고 합니다. 어떤 조건이 좁히기로 인정되는지 알면 cast 나 # type: ignore 없이 깔끔하게 통과시킬 수 있습니다.

검사기는 is None · isinstance · ==리터럴 · 조기 return 을 보고 갈래마다 타입을 줄입니다. 마지막 갈래에 남은 타입이 없으면 모든 경우를 처리한 것입니다.

좁히기로 인정되는 조건

def show(v: int | str | None) -> str:
    if v is None:                 # ① is None / is not None
        return "-"
    if isinstance(v, str):        # ② isinstance (튜플도 됨)
        return v.upper()          #    여기선 str
    return f"{v:,}"               #    여기선 int

def size(x: list[int] | dict[str, int]) -> int:
    if isinstance(x, list):
        return len(x)
    return sum(x.values())        # dict 로 좁혀짐

# ③ 진릿값 — 단, 0 · "" 도 걸러지니 주의
def first(name: str | None) -> str:
    if not name:
        return "익명"             # None 과 "" 둘 다 여기로
    return name

# ④ 리터럴 비교 · in
def go(d: Literal["up", "down"]) -> int:
    if d == "up": return 1
    return -1                     # 여기선 Literal["down"]

# ⑤ callable() · hasattr() (pyright · mypy 최신 지원)

assert_never — 빠진 경우를 검사기가 찾게

from typing import Literal, assert_never

Status = Literal["pending", "paid", "shipped"]

def label(s: Status) -> str:
    match s:
        case "pending": return "대기"
        case "paid":    return "결제됨"
        case _:
            assert_never(s)
# 나중에 누가 Status 에 "shipped" 를 추가했는데 case 를 안 썼다면:
# error: Argument 1 to "assert_never" has incompatible type
#        "Literal['shipped']"; expected "Never"  [arg-type]

# Enum 에도 똑같이 동작합니다 (case Color.RED: ...)
assert_never 는 실행 중에 닿으면 AssertionError 를 던지고, 검사기에게는 “여기까지 오는 타입은 없어야 한다”를 알립니다. 상태값 · 이벤트 종류를 다루는 모든 분기에 붙여 두세요.

내 함수로 좁히기 — TypeIs · TypeGuard 🔴 실무

from typing import TypeIs      # 3.13+ (이전: typing_extensions)

def is_str_list(v: list[object]) -> TypeIs[list[str]]:
    return all(isinstance(x, str) for x in v)
# mypy: Narrowed type "list[str]" is not a subtype of
#       input type "list[object]"   ← list 가 불변이라서 (TYPE 08)

# ✅ 입력 타입의 '부분 타입'으로 좁혀야 함
def is_str(v: object) -> TypeIs[str]:
    return isinstance(v, str)

def is_user_row(v: dict[str, object]) -> TypeIs[UserRow]: ...

def handle(x: int | str) -> None:
    if is_str(x):
        x.upper()        # str
    else:
        x + 1            # int ← TypeIs 는 else 쪽도 좁혀 줌

TypeIs vs TypeGuard vs cast

도구if 쪽else 쪽언제
TypeIs 3.13좁힘나머지로 좁힘기본 선택
TypeGuard 3.10좁힘그대로입력과 무관한 타입으로 바꿀 때
cast(T, x)검사 없이 “믿어라”최후의 수단 · 런타임 비용 0
assert isinstance실행 중에도 검사 + 좁힘테스트 · 내부 불변식
cast 는 거짓말을 허락합니다 — cast(int, "abc") 도 통과합니다. 쓸 때마다 “왜 검사기가 모르는지” 주석을 남기세요. 대부분은 isinstance 나 TypeIs 로 대체됩니다.
정리 — is None · isinstance · 리터럴 비교 · 조기 return 이 타입을 좁힙니다. 모든 경우를 처리했는지는 assert_never, 내 검사 함수는 TypeIs, cast 는 최후의 수단.
TYPE 05

값까지 정하는 타입 — Literal · Final · ClassVar · Annotated

str 은 “아무 문자열”이지만 Literal["r", "w"] 는 “이 두 문자열 중 하나”입니다. 옵션 문자열 · 상수 · 클래스 공유 값처럼 값의 범위나 변경 가능성까지 약속하고 싶을 때 쓰는 도구들입니다.

Literal — 허용 값 목록

from typing import Literal

type Mode = Literal["r", "w", "a"]     # 3.12+ type 문

def open_log(path: str, mode: Mode = "r") -> None: ...

open_log("x.log", "w")     # ✅
open_log("x.log", "x")
# error: Argument 2 to "open_log" has incompatible type
#        "Literal['x']"; expected "Literal['r', 'w', 'a']"

# 변수에 담아 넘기면 str 로 넓혀질 수 있음
m = "w"                    # 추론: str
open_log("x.log", m)
# mypy:    incompatible type "str"; expected "Literal['r', 'w', 'a']"
# pyright: 통과 (대입된 값 "w" 를 기억)
M: Mode = "w"              # ✅ 명시하면 확실

# Literal 에 쓸 수 있는 것: str · int · bool · bytes · Enum 멤버 · None
값이 3~4개이고 다른 동작이 붙지 않으면 Literal, 값마다 메서드 · 설명 · 순회가 필요하면 StrEnum(🚀 중고급 탭 ADV 10). 둘 다 assert_never 와 함께 쓸 수 있습니다.

Final · ClassVar

from typing import Final, ClassVar

MAX_RETRY: Final = 3          # 타입은 추론 (Literal[3])
MAX_RETRY = 4
# error: Cannot assign to final name "MAX_RETRY"

class Config:
    VERSION: Final = "1.0"            # 자식에서 재정의 금지
    instances: ClassVar[int] = 0      # 클래스 공유 값 (인스턴스 필드 아님)
    name: str                         # 인스턴스 필드

    def __init__(self, name: str) -> None:
        self.name = name
        Config.instances += 1

# dataclass 에서 ClassVar 는 '필드에서 제외'라는 뜻
@dataclass
class Item:
    registry: ClassVar[dict[str, "Item"]] = {}   # __init__ 인자 아님
    name: str

# @final — 상속 · 재정의 금지
from typing import final
@final
class Token: ...
class MyToken(Token): ...   # error: Cannot inherit from final class "Token"

Annotated — 타입에 메타데이터 붙이기 🟡 중급

쉽게 말하면 — Annotated[int, 무엇이든] 은 검사기에게는 그냥 int 이고, 뒤에 붙은 정보는 pydantic · FastAPI 같은 라이브러리가 실행 중에 꺼내 쓰는 메모입니다.
from typing import Annotated
from pydantic import BaseModel, Field

# 검사기 눈에는 int, pydantic 눈에는 '1~150 사이 int'
Age = Annotated[int, Field(ge=1, le=150)]
Email = Annotated[str, Field(pattern=r".+@.+")]

class SignUp(BaseModel):
    email: Email
    age: Age

SignUp(email="a@b.c", age=200)
# ValidationError: age — Input should be less than or equal to 150
# FastAPI — 같은 원리로 '어디서 받는지'를 붙임
from fastapi import FastAPI, Query, Depends

app = FastAPI()

def list_items(

TYPE 06

함수를 타입으로 — Callable · 콜백 Protocol · ParamSpec

파이썬에서 함수는 값이라 인자로 넘기고 반환합니다(🚀 ADV 05·06). 그 함수의 모양 — 무엇을 받고 무엇을 돌려주는지를 적는 방법이 Callable 입니다. 데코레이터처럼 “받은 함수의 시그니처를 그대로 보존”해야 할 때는 ParamSpec 이 필요합니다.

Callable[[인자들], 반환]

from collections.abc import Callable, Awaitable

def apply(fn: Callable[[int], int], xs: list[int]) -> list[int]:
    return [fn(x) for x in xs]

apply(lambda x: x * 2, [1, 2])      # ✅
apply(str, [1, 2])
# error: Argument 1 to "apply" has incompatible type
#        "type[str]"; expected "Callable[[int], int]"

# 인자 상관없음
Handler = Callable[..., None]

# 인자 없음
Factory = Callable[[], "Connection"]

# async 함수 — 호출하면 Awaitable 을 돌려주는 함수
AsyncHandler = Callable[[Request], Awaitable[Response]]

# 콜백 등록 API
class Button:
    def __init__(self) -> None:
        self._handlers: list[Callable[[str], None]] = []
    def on_click(self, h: Callable[[str], None]) -> None:
        self._handlers.append(h)

Callable 로 표현 못 할 때 — __call__ Protocol

from typing import Protocol

# 키워드 인자 · 기본값 · 오버로드가 있는 콜백은 Callable 로 못 적음
class Fetcher(Protocol):
    def __call__(self, url: str, *, timeout: float = 10.0) -> bytes: ...

def crawl(fetch: Fetcher, urls: list[str]) -> None:
    for u in urls:
        fetch(u, timeout=3)          # ✅ 키워드 인자까지 검사

def my_fetch(url: str, *, timeout: float = 10.0) -> bytes: ...
crawl(my_fetch, [...])               # ✅ 모양이 맞으면 통과

def wrong(url: str) -> bytes: ...
crawl(wrong, [...])                  # ❌ timeout 키워드를 못 받음
기준 — 위치 인자만 있으면 Callable, 키워드 인자 이름이 중요하면 __call__ 을 가진 Protocol(TYPE 09).

데코레이터 타입 — ParamSpec · Concatenate 🔴 실무

쉽게 말하면 — Callable[..., R] 로 감싸면 데코레이터를 붙인 순간 원래 함수의 인자 정보가 사라집니다. ParamSpec 은 “인자 목록 전체”를 하나의 변수로 받아 그대로 옮겨 주는 장치입니다.
import functools, time
from collections.abc import Callable

# 3.12+ 문법 — [**P, R] 를 함수 이름 뒤에
def timer[**P, R](fn: Callable[P, R]) -> Callable[P, R]:
    @functools.wraps(fn)
    def wrapper(*args: P.args, **kwargs: P.kwargs) -> R:
        t0 = time.perf_counter()
        try:
            return fn(*args, **kwargs)
        finally:
            print(fn.__name__, time.perf_counter() - t0)
    return wrapper

@timer
def greet(name: str, times: int = 1) -> str:
    return name * times

greet("a", times=2)     # ✅ str
greet(3)                # ❌ 검사기가 원래 시그니처로 검사
# error: Argument 1 to "greet" has incompatible type "int"; expected "str"

# 3.11 이하 문법
from typing import ParamSpec, TypeVar
P = ParamSpec("P"); R = TypeVar("R")

인자를 하나 '주입'하는 데코레이터

from typing import Concatenate

# 원래 함수: (conn, *나머지) → 데코레이터 후: (*나머지)
def with_conn[**P, R](
    fn: Callable[Concatenate[Connection, P], R],
) -> Callable[P, R]:
    @functools.wraps(fn)
    def wrapper(*args: P.args, **kwargs: P.kwargs) -> R:
        with pool.connect() as conn:
            return fn(conn, *args, **kwargs)
    return wrapper

@with_conn
def get_user(conn: Connection, uid: int) -> User: ...

get_user(3)          # ✅ conn 은 데코레이터가 넣어 줌
get_user(conn, 3)    # ❌ 인자가 너무 많음

# async 버전은 반환을 Awaitable/Coroutine 으로:
# Callable[P, Awaitable[R]] -> Callable[P, Awaitable[R]]
정리 — 단순 콜백은 Callable[[A, B], R], 키워드 인자가 중요하면 __call__ Protocol, 데코레이터는 [**P, R] + P.args/P.kwargs, 인자 주입은 Concatenate.
TYPE 07

제네릭 — 타입을 인자로 받는 함수와 클래스

def first(xs: list) -> ??? 의 반환 타입은 무엇일까요? list[int] 를 넣으면 int, list[str] 을 넣으면 str 입니다. 이렇게 들어온 타입에 따라 나가는 타입이 정해지는 관계를 적는 것이 제네릭이고, 3.12 부터는 def first[T] 처럼 이름 뒤에 대괄호로 씁니다.

제네릭의 핵심은 입력과 출력의 타입을 같은 변수 T 로 묶는 것입니다. Any 는 이 연결을 끊어 버립니다.

제네릭 함수 · 클래스 (3.12+)

def first[T](xs: list[T]) -> T | None:
    return xs[0] if xs else None

def pair[K, V](k: K, v: V) -> tuple[K, V]:
    return k, v

class Stack[T]:
    def __init__(self) -> None:
        self._items: list[T] = []
    def push(self, x: T) -> None:
        self._items.append(x)
    def pop(self) -> T:
        return self._items.pop()

s = Stack[int]()
s.push(1)
s.push("a")
# error: Argument 1 to "push" of "Stack" has incompatible type
#        "str"; expected "int"

# 타입 별칭도 제네릭으로
type Pair[T] = tuple[T, T]
type Tree[T] = T | list[Tree[T]]       # 재귀 별칭도 됨

제약 — bound · 제한 목록 · 기본값

# bound — T 는 이 타입의 '하위 타입'이어야 함
from typing import Protocol
class HasId(Protocol):
    id: int

def by_id[T: HasId](items: list[T]) -> dict[int, T]:
    return {it.id: it for it in items}    # .id 사용 가능
# 반환은 dict[int, User] — HasId 로 뭉개지지 않음 ★

# 제한 목록 — 정확히 이 중 하나
def concat[S: (str, bytes)](a: S, b: S) -> S:
    return a + b
concat("a", "b")      # str
concat(b"a", b"b")    # bytes
concat("a", b"b")     # ❌ 섞을 수 없음

# 3.13+ 기본값
class Box[T = int]:
    ...
Box()                 # Box[int]
옛 문법으로 된 라이브러리 코드: T = TypeVar("T", bound=HasId) · class Stack(Generic[T]). 뜻은 같고, 3.12 문법은 TypeVar 를 모듈 전역에 만들 필요가 없을 뿐입니다.

Self — 메서드 체이닝 · 대체 생성자 🔴 실무

from typing import Self       # 3.11+

class Query:
    def where(self, cond: str) -> Self:     # ★ -> "Query" 가 아니라 Self
        self._conds.append(cond)
        return self

    @classmethod
    def from_dict(cls, d: dict) -> Self:
        return cls(**d)

class UserQuery(Query):
    def active(self) -> Self: ...

UserQuery().where("x").active()   # ✅ where 의 반환이 UserQuery 로 유지
# -> "Query" 로 적었다면 .active() 에서 에러

언제 제네릭을 쓰나

TYPE 08

변성 — 왜 list[Dog] 는 list[Animal] 이 아닌가

Dog 가 Animal 의 자식이어도 list[Dog] 를 list[Animal] 자리에 넣으면 검사기가 거부합니다. 처음 보면 버그 같지만 이유가 분명합니다 — 받은 쪽이 그 리스트에 Cat 을 넣을 수 있기 때문입니다. 이 규칙을 변성(variance)이라고 부릅니다.

읽기만 하면 자식 → 부모 방향으로 허용(공변), 받기만 하면 반대 방향(반공변), 둘 다 하면 정확히 같아야(불변) 합니다.

실제 에러와 해결

class Animal: ...
class Dog(Animal): ...

def feed(xs: list[Animal]) -> None: ...
dogs: list[Dog] = [Dog()]
feed(dogs)
# mypy:
# error: Argument 1 to "feed" has incompatible type "list[Dog]";
#        expected "list[Animal]"  [arg-type]
# note: "list" is invariant -- see .../common_issues.html#variance
# note: Consider using "Sequence" instead, which is covariant

# ✅ feed 가 리스트를 수정하지 않는다면 — 읽기 전용 타입으로
from collections.abc import Sequence
def feed(xs: Sequence[Animal]) -> None: ...
feed(dogs)          # 통과

# dict 도 마찬가지 → Mapping[str, Animal]
TYPE 03 의 “인자는 넓게(Sequence · Mapping)” 원칙을 지키면 변성 에러는 거의 만나지 않습니다. 검사기 메시지도 똑같이 Sequence 를 쓰라고 권합니다.

내 제네릭 클래스의 변성

# 3.12+ 문법은 변성을 '자동 추론'합니다
class Box[T]:                     # 읽기만 하면 공변으로 추론
    def __init__(self, v: T) -> None:
        self._v = v
    def get(self) -> T:
        return self._v

class Sink[T]:                    # 받기만 하면 반공변
    def send(self, v: T) -> None: ...

class Cell[T]:                    # 둘 다 → 불변
    def get(self) -> T: ...
    def set(self, v: T) -> None: ...

def show(b: Box[Animal]) -> None: ...
show(Box(Dog()))                  # ✅ Box 는 공변

# 옛 문법은 직접 선언
from typing import TypeVar
T_co = TypeVar("T_co", covariant=True)
T_contra = TypeVar("T_contra", contravariant=True)
공개 가변 속성은 불변으로 만듭니다 — Box 에 self.v: T 를 밖에서 대입 가능한 속성으로 두면 “쓰기”가 생겨 불변이 됩니다. 공변을 원하면 _v + 읽기 메서드나 @property 로 두세요.
정리 — list · dict 는 불변이라 list[Dog] ≠ list[Animal]. 수정하지 않는다면 Sequence · Mapping 으로 받으면 해결됩니다. 3.12 제네릭은 변성을 자동 추론합니다.
TYPE 09

Protocol — 덕 타이핑에 타입 붙이기

파이썬다운 코드는 “이 클래스를 상속했나”가 아니라 “이 메서드가 있나”로 판단합니다. Protocol 은 그 판단을 타입으로 적는 방법입니다. 상속하지 않아도 모양(메서드 · 속성)이 맞으면 통과하므로, 남이 만든 클래스나 테스트용 가짜 객체도 그대로 받을 수 있습니다.

모양만 맞으면 통과

from typing import Protocol

class Notifier(Protocol):
    def send(self, to: str, msg: str) -> bool: ...

class Slack:                          # Notifier 를 상속하지 않음
    def send(self, to: str, msg: str) -> bool: ...

class FakeNotifier:                   # 테스트용 가짜
    def __init__(self) -> None:
        self.sent: list[tuple[str, str]] = []
    def send(self, to: str, msg: str) -> bool:
        self.sent.append((to, msg)); return True

def alert(n: Notifier, msg: str) -> None:
    n.send("#ops", msg)

alert(Slack(), "x")          # ✅
alert(FakeNotifier(), "x")   # ✅ — mock 라이브러리 없이 테스트

class Wrong:
    def send(self, to: str) -> bool: ...
alert(Wrong(), "x")          # ❌ 인자 모양이 다름
# error: Argument 1 to "alert" has incompatible type "Wrong";
#        expected "Notifier"
# note: Following member(s) of "Wrong" have conflicts: ...

class HasId(Protocol):

    def id(self) -> int: ...

# 제네릭 Protocol
class Repo[T](Protocol):
    def get(self, id: int) -> T | None: ...
    def add(self, item: T) -> None: ...

def sync[T](src: Repo[T], dst: Repo[T], ids: list[int]) -> None:
    for i in ids:
        if (x := src.get(i)) is not None:
            dst.add(x)

runtime_checkable — isinstance 로도 쓰기 🔴 실무

from typing import Protocol, runtime_checkable

@runtime_checkable
class Closeable(Protocol):
    def close(self) -> None: ...

def cleanup(objs: list[object]) -> None:
    for o in objs:
        if isinstance(o, Closeable):     # ✅ 런타임 검사 가능
            o.close()                    #    + 검사기도 좁혀 줌
runtime_checkable 의 한계 — isinstance 는 메서드 이름이 있는지만 봅니다. 인자 개수 · 타입 · 반환 타입은 확인하지 않으므로 def close(self, force) 인 객체도 True 가 됩니다. 또 매번 속성을 훑어 일반 isinstance 보다 수십 배 느립니다. 뜨거운 루프에서는 피하세요.
정리 — “이 메서드만 있으면 된다”는 Protocol, 쓰는 쪽 모듈에 정의하고 테스트 가짜 객체도 그대로 넘깁니다. 런타임 isinstance 가 필요하면 @runtime_checkable — 단 이름만 봅니다.
TYPE 10

데이터의 모양 — TypedDict · NamedTuple · dataclass · **kwargs

JSON 을 dict[str, Any] 로 다루면 키 오타 · 누락이 실행할 때까지 숨어 있습니다. TypedDict 는 런타임엔 그냥 dict 이면서 검사기에게는 “이 키들이 이 타입으로 있다”를 알려 줍니다. 변환 비용 없이 JSON 에 타입을 입히는 가장 가벼운 방법입니다.

TypedDict — 키와 값 타입

from typing import TypedDict, NotRequired, Required, ReadOnly

class Event(TypedDict):

from typing import TypedDict, Unpack, NotRequired

class FetchOpts(TypedDict):
    timeout: NotRequired[float]
    retries: NotRequired[int]
    headers: NotRequired[dict[str, str]]

def fetch(url: str, **opts: Unpack[FetchOpts]) -> bytes:
    t = opts.get("timeout", 10.0)

# 래퍼 함수가 옵션을 그대로 넘길 때 특히 유용:
def get(url: str, **opts: Unpack[FetchOpts]) -> bytes:
    return fetch(url, **opts)

정리 — JSON 은 TypedDict(NotRequired · ReadOnly), 옵션 키워드는 **kw: Unpack[Opts], 외부 입력은 pydantic 으로 검증한 뒤 타입을 믿습니다.
TYPE 11

고급 도구 — overload · NewType · Never · Any vs object

여기까지로 실무 코드의 대부분을 적을 수 있습니다. 남은 것은 “인자에 따라 반환 타입이 달라지는 함수”, “같은 int 인데 섞이면 안 되는 값”, “절대 돌아오지 않는 함수”, 그리고 Any 를 언제 써도 되는가입니다.

@overload — 인자에 따라 반환이 다를 때

from typing import overload, Literal
import json

@overload
def load(raw: str, *, as_text: Literal[True]) -> str: ...
@overload
def load(raw: str, *, as_text: Literal[False] = False) -> dict: ...
def load(raw: str, *, as_text: bool = False) -> str | dict:   # 실제 구현
    return raw if as_text else json.loads(raw)

reveal_type(load("{}"))                 # dict
reveal_type(load("{}", as_text=True))   # str

# overload 가 없으면 반환이 늘 str | dict 라서
# 호출할 때마다 isinstance 로 좁혀야 합니다.

# 표준 라이브러리 예: open(mode="rb") → BinaryIO, open(mode="r") → TextIO
#                   re.match(str) → Match[str], re.match(bytes) → Match[bytes]
@overload 선언들은 검사기 전용이고, 실행되는 것은 마지막 데코레이터 없는 구현 하나입니다. 구현의 시그니처는 모든 overload 를 받아들일 만큼 넓어야 합니다.

NewType — 같은 int, 다른 의미

from typing import NewType

UserId = NewType("UserId", int)
OrderId = NewType("OrderId", int)

def get_user(uid: UserId) -> User: ...

oid = OrderId(42)
get_user(oid)
# error: Argument 1 to "get_user" has incompatible type
#        "OrderId"; expected "UserId"
get_user(42)          # ❌ 그냥 int 도 거부
get_user(UserId(42))  # ✅ 명시적으로 만든 값만

# 런타임 비용 0 — UserId(42) 는 그냥 42 를 돌려줌
type(UserId(42))      # <class 'int'>

# type 별칭과의 차이
type Meters = float   # 별칭 — float 와 완전히 같은 타입 (구분 안 됨)
Km = NewType("Km", float)   # 새 타입 — 섞으면 에러

Any · object · Never — 세 개의 특수 타입 🟡 중급

타입뜻검사기 동작
Any“검사하지 마”무엇이든 받고, 무엇으로든 쓸 수 있음 — 오류가 전부 사라짐
object“무엇이든 될 수 있음”무엇이든 받지만, 쓰려면 좁혀야 함
Never“값이 존재할 수 없음”돌아오지 않는 함수 · 도달 불가 분기
from typing import Any, Never, NoReturn

def a(x: Any) -> None:
    x.whatever()           # 통과 — 아무것도 안 잡음
def b(x: object) -> None:
    x.whatever()           # error: "object" has no attribute "whatever"
    if isinstance(x, str):
        x.upper()          # ✅ 좁힌 뒤에만

def fail(msg: str) -> Never:      # NoReturn 과 같은 뜻
    raise SystemExit(msg)

Any 는 전염됩니다

import json
data = json.loads(raw)          # 반환 타입이 Any
user = data["user"]             # Any
name = user["nmae"].upper()     # Any — 오타도 통과
send(name)                      # send 의 인자 타입도 검사 안 됨

# ✅ 경계에서 Any 를 끊기
data: object = json.loads(raw)            # 쓰려면 좁혀야 함
rows = TypeAdapter(list[UserRow]).validate_python(json.loads(raw))

# 어디서 Any 가 새는지 찾기
#   mypy --disallow-any-expr (매우 엄격) / --warn-return-any
#   pyright: reportUnknown* 진단 (strict 모드)
“모르겠으면 Any”는 검사기를 끄는 것과 같습니다. 정말 무엇이든 받는 함수(print 같은)는 object 로, 아직 정리 못 한 레거시는 Any 로 두되 경계에서 끊으세요.

정리 — 반환이 인자에 따라 다르면 @overload, 같은 int 를 구분하려면 NewType, “아무거나”는 Any 가 아니라 object. 재정의는 @override 로 오타를 막습니다.
TYPE 12

런타임에서 타입 쓰기 — 어노테이션 지연 평가 · TYPE_CHECKING

3.14 부터 어노테이션은 정의할 때가 아니라 처음 읽을 때 계산됩니다(PEP 649). 그래서 아직 정의되지 않은 클래스를 따옴표 없이 적을 수 있고, 타입 때문에 생기던 순환 import 문제가 크게 줄었습니다. 하지만 pydantic · FastAPI 처럼 실행 중에 힌트를 읽는 코드는 이 차이를 알아야 합니다.

3.14 에서는 정의 순서와 상관없이 따옴표 없이 적을 수 있습니다. 차이가 나는 곳은 실행 중에 __annotations__ 를 읽는 라이브러리뿐입니다.

3.14 — 지연 평가 직접 확인

class Node:
    def add(self, child: Node) -> Node: ...   # 3.14: 따옴표 없이 OK
                                             # 3.13: NameError → "Node"

def g(x: Undefined) -> int: ...   # 정의 시점엔 에러 없음
g.__annotations__
# NameError: name 'Undefined' is not defined  ← 읽을 때 계산

import annotationlib
annotationlib.get_annotations(g, format=annotationlib.Format.FORWARDREF)
# {'x': ForwardRef('Undefined', ...), 'return': <class 'int'>}
annotationlib.get_annotations(g, format=annotationlib.Format.STRING)
# {'x': 'Undefined', 'return': 'int'}
from __future__ import annotations 는 3.14 에서도 동작하지만, 새 코드에서는 필요 없습니다. 3.13 이하를 지원해야 하는 라이브러리만 유지하세요.

TYPE_CHECKING — 타입 때문에 생긴 순환 import 끊기

    from users import User                # ← 실행 중엔 import 안 함

def assign(order_id: int, user: User) -> None:
    ...

# users.py 가 orders.py 를 import 해도 순환이 생기지 않습니다.
# 단, 실행 중에 User 를 '값'으로 쓰면(isinstance 등) NameError.

# ruff 규칙 TC001~TC003 이 '타입에만 쓰이는 import' 를
# TYPE_CHECKING 블록으로 옮기라고 알려 줍니다.

힌트를 읽는 라이브러리를 만들 때 🔴 실무

import typing
from typing import get_type_hints, get_origin, get_args, Annotated

def describe(fn) -> dict[str, str]:
    hints = get_type_hints(fn, include_extras=True)   # 문자열·지연 평가 해석
    out = {}
    for name, tp in hints.items():
        origin = get_origin(tp)           # list[int] → list
        args = get_args(tp)               # list[int] → (int,)
        if origin is Annotated:
            base, *meta = args
            out[name] = f"{base} + {meta}"
        else:
            out[name] = str(tp)
    return out

def f(a: list[int], b: int | None, c: Annotated[str, "메모"]) -> None: ...
describe(f)
# {'a': 'list[int]', 'b': 'int | None', 'c': "<class 'str'> + ['메모']", ...}
