시간 복잡도 — 입력이 10배가 되면 얼마나 느려지나

알고리즘 공부의 출발점은 “빠른 코드”가 아니라 “얼마나 빨리 느려지는가”입니다. 막대를 눌러 입력 크기 n을 키워 보세요 — 계단이 무너지는 게 보입니다.

복잡도 성장 비교
n = 10 막대 높이는 연산 횟수를 로그 스케일로 그린 것입니다. n이 작을 땐 차이가 없어 보이지만…

코딩테스트 기준선 — “1초에 약 1억 번”

파이썬은 1초에 대략 2,000만~5,000만 번의 단순 연산을 처리합니다(C++의 1/5~1/10). 문제에서 N ≤ 100,000이라고 주면, 그건 사실상 “O(N log N) 이하로 풀어라”는 힌트입니다.

N 범위허용 복잡도대표 풀이파이썬 체감
N ≤ 10O(N!) · O(2ⁿ)순열 전수조사, 백트래킹여유
N ≤ 20O(2ⁿ)부분집합 비트마스크여유
N ≤ 500O(N³)플로이드–워셜아슬아슬
N ≤ 5,000O(N²)이중 반복문 DP가능
N ≤ 100,000O(N log N)정렬, 이분탐색, 힙, 세그먼트 트리가장 흔한 구간
N ≤ 10,000,000O(N)투 포인터, 누적합, 그리디입력 읽기부터 최적화 필요
파이썬 반복문은 비쌉니다 — 같은 O(N)이라도 순수 for문보다 sum()·sorted()·collections 같은 C로 구현된 내장이 5~50배 빠릅니다. 시간초과가 나면 알고리즘을 바꾸기 전에 “내장 함수로 대체할 수 있나”부터 확인하세요.

for x in data:          # 느림: 파이썬 인터프리터가 매 반복마다 개입
    total += x

total = sum(data)       # 빠름: C 루프 한 번

# 리스트에서 "있는지" 확인 — 이건 복잡도 자체가 다르다
if x in my_list:        # O(N)  — 처음부터 끝까지 훑음
    ...
if x in my_set:         # O(1)  — 해시로 즉시 판정  ★ 시간초과 1순위 원인

# 문자열 이어붙이기
s = ""
for w in words:
    s += w              # O(N²) — 매번 새 문자열을 통째로 복사
s = "".join(words)      # O(N)  — 정답

“배열은 조회가 빠르고 삽입이 느리다”는 문장을 외우지 마세요. 맨 앞에 값을 하나 넣어 보면 이유가 한눈에 보입니다.

배열(파이썬 list)

  • 인덱스 접근 O(1) — 주소 계산 한 번
  • 맨 뒤 추가 append O(1)
  • 맨 앞 삽입·삭제 O(N) — 전부 밀림

연결 리스트(파이썬 deque)

  • 양쪽 끝 삽입·삭제 O(1)
  • k번째 접근 O(N) — 처음부터 따라감
  • 노드마다 포인터를 저장해 메모리를 더 씀
  • 파이썬에선 직접 구현할 일 거의 없음 → deque를 쓰세요
from collections import deque

# ❌ 리스트 맨 앞 조작 — O(N), 10만 번이면 시간초과
q = []
q.insert(0, x)     # 전부 한 칸씩 밀림
q.pop(0)           # 역시 전부 당겨짐

# ✅ deque — 양쪽 끝 O(1)
q = deque()
q.appendleft(x)    # 앞에 추가
q.popleft()        # 앞에서 꺼내기   ★ BFS 큐의 정석
q.append(x); q.pop()

# 회전도 O(k)
d = deque([1,2,3,4,5])
d.rotate(2)        # deque([4, 5, 1, 2, 3])
실전 규칙 — “앞에서 빼는” 코드가 보이면 즉시 deque. BFS·슬라이딩 윈도우·큐 시뮬레이션 문제의 시간초과 절반은 list.pop(0) 때문입니다.

    return not st

def two_sum(nums, target):
    pos = {}                       # 값 -> 인덱스
    for i, v in enumerate(nums):
        if target - v in pos:      # 짝이 이미 지나갔나?
            return [pos[target - v], i]
        pos[v] = i

이진 탐색 — 한 번 볼 때마다 절반을 버린다

100만 개에서 값을 찾는 데 20번이면 충분합니다. L(왼쪽)·M(가운데)·R(오른쪽) 포인터가 어떻게 좁혀지는지 한 단계씩 보세요.

정렬된 배열에서 값 찾기
속도
0확인한 칸 수
0순차 탐색이면 필요한 횟수
M — 지금 보는 가운데 남은 후보 구간 버려진 구간 찾음 
def binary_search(arr, target):
    lo, hi = 0, len(arr) - 1
    while lo <= hi:
        mid = (lo + hi) // 2        # 가운데
        if arr[mid] == target:
            return mid              # 찾음
        if arr[mid] < target:
            lo = mid + 1            # 왼쪽 절반을 통째로 버림
        else:
            hi = mid - 1            # 오른쪽 절반을 통째로 버림
    return -1                       # 없음

# 실전에서는 직접 구현하지 않는다 — bisect 사용
import bisect
i = bisect.bisect_left(arr, x)      # x 가 들어갈 가장 왼쪽 자리
j = bisect.bisect_right(arr, x)     # 가장 오른쪽 자리
cnt = j - i                         # 정렬된 배열에서 x 의 개수 O(log N)

found = i < len(arr) and arr[i] == x   # 존재 여부
전제 조건 — 이진 탐색은 정렬되어 있을 때만 성립합니다. 정렬이 안 된 배열에 쓰면 틀린 답이 조용히 나옵니다(에러가 안 나서 더 위험).

한 단계 위 — “매개 변수 탐색(Parametric Search)”

“최댓값을 구하라”는 문제를 “이 값이 가능한가? (예/아니오)”로 바꾸면 답 자체를 이진 탐색할 수 있습니다. 랜선 자르기·나무 자르기·예산 배분이 전부 이 유형입니다. 

# "길이 x 로 잘랐을 때 K개 이상 나오는가?" 를 판정 함수로
def possible(x, lines, k):
    # x > 0 를 먼저 검사한다 — 뒤에 두면 x == 0 일 때 sum() 이 먼저 돌아 ZeroDivisionError
    return x > 0 and sum(L // x for L in lines) >= k

lo, hi, ans = 1, max(lines), 0
while lo <= hi:
    mid = (lo + hi) // 2
    if possible(mid, lines, k):             # 가능하면 더 길게 시도
        ans = mid
        lo = mid + 1
    else:                                   # 불가능하면 짧게
        hi = mid - 1
print(ans)

투 포인터 — 양 끝에서 좁혀 오면 이중 반복문이 사라진다

정렬된 배열에서 합이 목표값인 두 수 찾기. 이중 for문이면 O(N²), 양 끝 포인터를 좁히면 O(N). 왜 답을 놓치지 않는지 눈으로 확인하세요.

합이 26 인 두 수 찾기
속도
L · R 포인터 현재 합 비교 중 정답 제외된 구간 
# 합이 target 인 두 수 (배열이 정렬되어 있을 때) — O(N)
def two_sum_sorted(arr, target):
    lo, hi = 0, len(arr) - 1
    while lo < hi:
        s = arr[lo] + arr[hi]
        if s == target:
            return (arr[lo], arr[hi])
        if s < target:
            lo += 1        # 더 큰 수가 필요 -> 왼쪽을 오른쪽으로
        else:
            hi -= 1        # 더 작은 수가 필요 -> 오른쪽을 왼쪽으로
    return None

# 왜 답을 놓치지 않나?
#   s < target 인데 hi 를 줄이면 합이 더 작아지므로 절대 답이 될 수 없다.
#   즉 "버리는 후보는 전부 오답임이 증명된" 상태 -> 안전하게 O(N).
투 포인터가 보이는 신호 — “정렬된 배열”, “연속 구간”, “두 수/세 수의 합”, “회문(팰린드롬) 판별”. 세 수의 합은 바깥 for 1개 + 안쪽 투 포인터로 O(N²)에 풉니다.

슬라이딩 윈도우 — 창을 밀면서 더하고 빼기

“연속한 K개의 합 중 최대”를 구할 때, 매번 K개를 다시 더하면 O(N·K). 들어온 값 하나 더하고 나간 값 하나 빼면 O(N)입니다.

크기 3 창을 밀며 최대 구간합 찾기
속도
0현재 창의 합
0지금까지 최대
0덧셈 횟수 (전부 다시 더했다면 0회)
# 고정 크기 K 슬라이딩 윈도우 — O(N)
def max_window_sum(arr, k):
    cur = sum(arr[:k])          # 첫 창만 직접 계산
    best = cur
    for i in range(k, len(arr)):
        cur += arr[i] - arr[i - k]   # 들어온 것 + , 나간 것 -
        best = max(best, cur)
    return best

# 가변 크기 윈도우 — "합이 S 이상인 가장 짧은 구간"
def min_len(arr, S):
    lo = cur = 0
    best = float("inf")
    for hi, v in enumerate(arr):
        cur += v
        while cur >= S:              # 조건을 만족하면 왼쪽을 당겨 줄인다
            best = min(best, hi - lo + 1)
            cur -= arr[lo]
            lo += 1
    return 0 if best == float("inf") else best

# 누적합(prefix sum) — 구간 합을 O(1) 로
import itertools

코드

def factorial(n):
    if n <= 1:          # ① 종료 조건 (base case)
        return 1
    return n * factorial(n - 1)   # ② 자기 자신 호출
재귀 함수 작성 3단계
① 종료 조건을 먼저 쓴다 → ② 문제를 한 단계 작게 만들어 호출한다 → ③ 돌아온 값으로 내 답을 만든다.
파이썬 재귀 한계 — 기본 재귀 깊이가 1000입니다. DFS를 재귀로 짜면 노드가 10만 개일 때 RecursionError가 납니다. 코딩테스트에선 아래 두 줄을 습관적으로 넣거나, 스택을 직접 쓰는 반복 DFS로 바꾸세요.

from functools import lru_cache

@lru_cache(maxsize=None)

def preorder(n):
    if not n: return
    print(n.v)            # ★ 먼저 나
    preorder(n.left); preorder(n.right)

def inorder(n):
    if not n: return
    inorder(n.left)
    print(n.v)            # ★ 왼쪽 다 끝나고 나
    inorder(n.right)

def postorder(n):
    if not n: return
    postorder(n.left); postorder(n.right)
    print(n.v)            # ★ 자식 다 끝나고 나

# K번째 큰 수 — 크기 K 힙만 유지하면 O(N log K)
def kth_largest(nums, k):
    h = []
    for x in nums:
        heapq.heappush(h, x)
        if len(h) > k:
            heapq.heappop(h)   # 가장 작은 걸 버림
    return h[0]
힙이 답인 신호 — “가장 작은/큰 것을 반복해서 꺼낸다”, “실시간으로 값이 추가되는데 매번 최솟값이 필요하다”, “상위 K개”. 한 번만 필요하면 min()이 낫습니다(정렬·힙 불필요).

BFS vs DFS — 왜 BFS만 최단 경로를 보장하나

같은 미로를 두 방식으로 탐색합니다. BFS는 물결처럼 동심원으로 퍼지고, DFS는 한 방향으로 끝까지 파고듭니다. 이 차이가 전부입니다.

미로 탐색 — S 출발 → G 도착
속도
0방문한 칸
-찾은 경로 길이
0대기열 크기
지금 꺼낸 칸 방문 완료 최종 경로 벽 
from collections import deque

# BFS — 격자 최단 경로의 표준 템플릿
def bfs(grid, start, goal):
    R, C = len(grid), len(grid[0])
    dq = deque([start])
    dist = {start: 0}                      # 방문 표시 + 거리 동시에
    while dq:
        r, c = dq.popleft()                # ★ 큐: 먼저 넣은 것부터
        if (r, c) == goal:
            return dist[(r, c)]
        for dr, dc in ((-1,0),(1,0),(0,-1),(0,1)):
            nr, nc = r + dr, c + dc
            if 0 <= nr < R and 0 <= nc < C \
               and grid[nr][nc] != 1 and (nr, nc) not in dist:
                dist[(nr, nc)] = dist[(r, c)] + 1
                dq.append((nr, nc))
    return -1

# DFS — 스택(또는 재귀). "갈 수 있나?"에는 되지만 "몇 걸음?"에는 부적합
def dfs(grid, start, goal):
    st = [start]
    seen = {start}
    while st:
        r, c = st.pop()                    # ★ 스택: 마지막에 넣은 것부터
        if (r, c) == goal:
            return True
        for dr, dc in ((-1,0),(1,0),(0,-1),(0,1)):
            nr, nc = r + dr, c + dc
            if 0 <= nr < len(grid) and 0 <= nc < len(grid[0]) \
               and grid[nr][nc] != 1 and (nr, nc) not in seen:
                seen.add((nr, nc))
                st.append((nr, nc))
    return False
가장 흔한 버그 — 방문 표시를 꺼낼 때(pop) 하면 같은 칸이 큐에 여러 번 들어가 시간초과가 납니다. 반드시 넣을 때(push) 즉시 방문 처리하세요.
문제 유형선택이유
최단 거리·최소 이동 횟수BFS가중치가 모두 1이면 먼저 도달 = 최단
연결 요소 개수·섬 세기둘 다 가능전부 방문만 하면 되므로 아무거나
모든 경로 탐색·조합DFS되돌아가며(백트래킹) 경우의 수를 만듦
가중치가 다른 최단 경로다익스트라BFS + 힙 (§11의 우선순위 큐)

# 예: 계단 오르기 (1칸 또는 2칸)
def stairs(n):
    if n <= 2: return n     # 가드가 없으면 n < 2 일 때 dp[2] 대입에서 IndexError
    dp = [0] * (n + 1)
    dp[1], dp[2] = 1, 2
    for i in range(3, n + 1):
        dp[i] = dp[i-1] + dp[i-2]
    return dp[n]

# 예: 0-1 배낭 (2차원)
dp = [[0] * (W + 1) for _ in range(N + 1)]
for i in range(1, N + 1):
    w, v = items[i-1]
    for c in range(W + 1):
        dp[i][c] = dp[i-1][c]                       # 안 담는다
        if c >= w:
            dp[i][c] = max(dp[i][c], dp[i-1][c-w] + v)   # 담는다

# 하향식(메모이제이션)이 더 편할 때도 많다
from functools import lru_cache
@lru_cache(None)
def go(i, c):
    if i == N: return 0
    best = go(i + 1, c)
    if c >= items[i][0]:
        best = max(best, go(i + 1, c - items[i][0]) + items[i][1])
    return best
