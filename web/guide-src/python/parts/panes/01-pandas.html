Series — 이름표가 붙은 1차원 배열

판다스의 최소 단위입니다. 리스트에 인덱스(이름표)가 붙으면 Series가 됩니다. DataFrame의 컬럼 하나 = Series 하나입니다.

리스트가 Series가 되는 과정
list

Java 비유 — Series는 LinkedHashMap<Object, T> + double[]을 합친 물건입니다. 키로도 찾고(s["김민준"]), 위치로도 찾고(s[0]), 배열 전체 연산(s * 1.1)도 됩니다. Java였다면 list.stream().map(x -> x*1.1).toList()가 필요한 일이 곱셈 기호 하나로 끝납니다.

Series 필수 속성

이렇게도 쓸 수 있다 — 인덱스가 계산을 지배합니다

Series 연산에서 가장 많이 당황하는 순간이 있습니다. 두 Series를 더했는데 결과가 NaN 투성이인 경우죠. 원인은 하나입니다 — 판다스는 위치가 아니라 인덱스(이름표)를 맞춰서 계산합니다. 이것만 알면 “결과가 이상해요”의 절반이 해결됩니다.

자동 정렬 — 편리하지만 함정

a = pd.Series([10, 20, 30], index=["가","나","다"])
b = pd.Series([ 1,  2,  3], index=["나","다","라"])

a + b
# 가    NaN   <- b 에 '가'가 없음
# 나   21.0
# 다   32.0
# 라    NaN   <- a 에 '라'가 없음

# 없는 쪽을 0으로 보고 더하기
a.add(b, fill_value=0)      # 가 10, 나 21, 다 32, 라 3

# 인덱스를 무시하고 '위치'로 계산하고 싶다면 값만 꺼내기
a.values + b.values         # 넘파이 배열 연산 (길이가 같아야 함)
a.reset_index(drop=True) + b.reset_index(drop=True)  # 또는 양쪽 인덱스를 다시 매기고
실무 최다 사고 — df.sort_values()나 필터를 거친 뒤 인덱스가 0,3,7,...처럼 뒤섞인 상태에서 다른 컬럼을 대입하면 NaN이 생깁니다. 필터·정렬 직후엔 .reset_index(drop=True)를 습관처럼 붙이세요.

버튼을 눌러 DataFrame의 각 구성 요소를 확인하세요.

직접 만들어 보기

import pandas as pd

# 방법 1: 딕셔너리 (가장 흔함) — 키가 컬럼명
df = pd.DataFrame({
    "이름":   ["김민준","이서연","박지훈","최유진","정하늘","강도윤"],
    "팀":     ["A","B","A","C","B","C"],
    "지역":   ["서울","부산","서울","대구","부산","대구"],
    "매출":   [320, 210, 450, 180, 390, 275],
    "만족도": [4.5, 4.1, 4.8, 3.9, None, 4.2],
})

# 방법 2: 리스트의 리스트 + 컬럼명 지정
df2 = pd.DataFrame([[1,"a"],[2,"b"]], columns=["no","val"])

# 방법 3: 딕셔너리의 리스트 (JSON/API 응답과 동일한 모양)
df3 = pd.DataFrame([{"no":1,"val":"a"}, {"no":2,"val":"b"}])

df.describe() # 숫자 컬럼 통계 요약
df.dtypes     # 컬럼별 데이터 타입

실무 습관 — 새 데이터를 받으면 무조건 이 순서로 봅니다: df.shape → df.head() → df.info() → df.describe() → df.isna().sum(). 이 5줄이면 데이터의 성격이 거의 파악됩니다.
DataFrame = 같은 인덱스를 공유하는 Series 묶음 — 그래서 컬럼 하나를 꺼내면 인덱스가 그대로 따라옵니다.

컬럼 다루기 — 실무에서 실제로 하는 것들

① 고르기 · ② 이름 바꾸기 · ③ 순서

# ── ① 여러 컬럼 고르기 (대괄호 두 번 = 리스트를 넘기는 것)
df[["이름", "매출"]]              # ✅ 두 컬럼 → DataFrame
df["매출"]                        # Series (1차원)
df[["매출"]]                      # DataFrame (2차원) ← 대괄호 개수 차이

cols = ["이름", "팀", "매출"]      # 변수로 빼 두면 재사용이 쉽습니다
df[cols]

# 없는 컬럼이 섞여 있으면 KeyError → 있는 것만 고르기
df[[c for c in cols if c in df.columns]]

# ── 조건으로 고르기 (컬럼이 수십 개일 때 진가가 나옵니다)
df.select_dtypes(include="number")          # 숫자 컬럼만
df.select_dtypes(include=["object","string"])  # 문자 컬럼만
df.select_dtypes(exclude="number")

df.filter(like="매출")             # 이름에 '매출'이 든 컬럼
df.filter(regex=r"_(합계|평균)$")   # 정규식으로
df.loc[:, df.columns.str.startswith("q_")]  # 접두사

# ── ② 이름 바꾸기
df = df.rename(columns={"매출": "sales", "만족도": "score"})
df.columns = df.columns.str.strip()          # 앞뒤 공백 제거 (엑셀 파일의 단골 문제)
df.columns = (df.columns.str.replace(" ", "_", regex=False)
                        .str.lower())        # 공백 → _, 소문자로 통일

# ── ③ 순서 바꾸기 / 특정 컬럼을 맨 앞으로
front = ["이름", "팀"]
df = df[front + [c for c in df.columns if c not in front]]
엑셀에서 읽은 컬럼명에는 눈에 안 보이는 공백이 자주 섞여 있습니다. df["매출"] 이 KeyError 를 내는데 df.columns 를 보면 멀쩡해 보이는 상황이 그것입니다. list(df.columns) 로 찍어 보면 '매출 ' 처럼 보입니다. 읽자마자 .str.strip() 을 거는 것이 실무 습관입니다.

④ 추가·계산 · ⑤ 타입 일괄 · ⑥ 삭제

# ── ④ 컬럼 추가 — assign 을 쓰면 원본을 안 건드립니다
df = df.assign(
    단가   = lambda d: d["매출"] / d["수량"],
    등급   = lambda d: pd.cut(d["매출"], [0, 200, 400, 9999],
                             labels=["하", "중", "상"]),
    월     = lambda d: d["날짜"].dt.to_period("M").astype(str),
    is_vip = lambda d: d["매출"].ge(400) & d["팀"].eq("A"),
)
# assign 안에서 방금 만든 컬럼을 다시 쓸 수 있습니다 (위에서 아래로 평가)

# 여러 컬럼을 한 번에 만들기
df[["세전", "세후"]] = df[["매출"]].to_numpy() * [1.0, 0.9]

# ── ⑤ 타입 일괄 변경 — 메모리와 정확성 양쪽에 영향을 줍니다
df = df.astype({
    "코드":   "string",     # ★ 앞자리 0 보존 (int 면 00123 → 123)
    "수량":   "int32",
    "매출":   "float32",
    "팀":     "category",   # 값 종류가 적으면 메모리가 크게 줍니다
})

# 숫자여야 하는데 문자가 섞여 있을 때 — 실패한 값만 NaN 으로
df["매출"] = pd.to_numeric(df["매출"], errors="coerce")
df["날짜"] = pd.to_datetime(df["날짜"], errors="coerce", format="%Y-%m-%d")

# 결측을 담을 수 있는 정수 타입 (Int64 — 대문자 I)
df["수량"] = df["수량"].astype("Int64")   # NaN 이 있어도 정수 유지

# ── ⑥ 삭제
df = df.drop(columns=["임시", "메모"])          # 여러 개
df = df.drop(columns=[c for c in df.columns if c.startswith("_")])
df = df.loc[:, df.notna().any()]                # 전부 빈 컬럼 제거
errors="coerce" 를 기억하세요. 실무 CSV 에는 숫자 컬럼에 "-"·"미입력"·"1,200" 같은 값이 섞여 있습니다. 기본 동작은 예외를 던지며 전체가 멈추는 것인데, coerce 를 주면 변환 실패한 값만 NaN 이 되어 df["매출"].isna().sum() 으로 몇 건이 이상한지 세어 볼 수 있습니다.

조건 조합

# and -> &   or -> |   not -> ~
# 각 조건은 반드시 괄호로 감쌀 것!
df[(df["매출"] > 300) & (df["팀"] == "A")]
df[(df["지역"] == "서울") | (df["지역"] == "부산")]
df[~(df["팀"] == "C")]              # C팀 제외

# 목록 포함 여부 (SQL의 IN)
df[df["지역"].isin(["서울","부산"])]

# 범위 (SQL의 BETWEEN)
df[df["매출"].between(200, 400)]

# 문자열 조건 (SQL의 LIKE)
df[df["이름"].str.contains("김")]

NaN의 성질 — NaN == NaN은 False입니다. 그래서 df[df["x"] == None]은 절대 안 되고 반드시 .isna()를 써야 합니다. 또 NaN이 섞이면 정수 컬럼이 자동으로 float64로 바뀝니다 (320 → 320.0). 이걸 막으려면 dtype="Int64"(대문자 I) 를 쓰세요.
어떤 전략을 고를까
· 결측 비율 5% 미만 + 데이터 충분 → dropna
· 수치형이고 분포가 중요 → 중앙값 (평균은 이상치에 흔들림)
· 시계열(센서·주가) → ffill / interpolate
· “없음”이 의미 있는 정보 → fillna("미입력") 후 별도 범주로 취급

# transform: 집계값을 '원본 행 수 그대로' 되돌려줌

# 그룹 내 순위

agg vs transform — 결과 행 수가 다릅니다. agg는 그룹 수만큼(3행), transform은 원본 행 수만큼(6행) 나옵니다. “각 행에 자기 팀 평균을 붙이고 싶다”면 transform입니다.
Java 비유 — groupby("팀")["매출"].mean()은 list.stream().collect(groupingBy(E::getTeam, averagingInt(E::getSales)))와 같습니다. transform에 딱 맞는 Java 대응물은 없고, 그룹 평균을 구한 뒤 원본을 다시 순회하며 붙이는 작업을 한 줄로 만든 것이라고 보면 됩니다.
고민의 기준은 하나입니다 — 결과가 "요약"이면 agg, "원본에 붙일 값"이면 transform.

import pandas as pd
import logging

log = logging.getLogger(__name__)

def safe_merge(left, right, on, how="left", validate="m:1", **kw):
    """행 수 변화와 매칭 실패를 눈에 보이게 만드는 merge"""
    before = len(left)

    out = left.merge(
        right, on=on, how=how,
        validate=validate,          # ★ 관계가 어긋나면 여기서 예외
        indicator=True,             # ★ 어느 쪽에서 왔는지 표시 컬럼 추가
        **kw,
    )

    after = len(out)
    matched = (out["_merge"] == "both").sum()
    only_left = (out["_merge"] == "left_only").sum()

    log.info("merge on=%s %d행 → %d행 (매칭 %d, 미매칭 %d)",
             on, before, after, matched, only_left)

    if after != before and how == "left":
        raise ValueError(f"left 조인인데 행 수가 바뀌었습니다: {before} → {after}")

    if only_left:
        # 매칭 안 된 키를 실제로 보여 줍니다 — 원인 파악에 결정적입니다
        keys = out.loc[out["_merge"] == "left_only", on].drop_duplicates().head(10)
        log.warning("매칭 실패 키 예시:\n%s", keys.to_string())

    return out.drop(columns="_merge")

import logging
import pandas as pd
from pathlib import Path
from datetime import datetime, timezone

log = logging.getLogger(__name__)

SCHEMA = {                      # 기대하는 컬럼과 타입을 코드로 못 박습니다
    "주문일":   "datetime64[ns]",
    "지점코드": "string",
    "수량":     "int32",
    "단가":     "int32",
}

def load(path: Path) -> pd.DataFrame:
    df = pd.read_csv(path, usecols=list(SCHEMA), dtype={
        k: v for k, v in SCHEMA.items() if v != "datetime64[ns]"
    }, parse_dates=["주문일"], encoding="utf-8-sig", thousands=",")
    df.columns = df.columns.str.strip()
    return df

def validate(df: pd.DataFrame) -> pd.DataFrame:
    """기대와 다르면 여기서 멈춥니다 — 조용히 틀린 리포트보다 낫습니다"""
    문제 = []
    if df.empty:
        문제.append("데이터가 비어 있습니다")
    if (미상 := df["주문일"].isna().sum()):
        문제.append(f"날짜 파싱 실패 {미상}건")
    if (음수 := (df["수량"] <= 0).sum()):
        문제.append(f"수량이 0 이하 {음수}건")
    if (중복 := df.duplicated(["주문번호"]).sum()):
        문제.append(f"주문번호 중복 {중복}건")

    if 문제:
        raise ValueError("입력 데이터 검증 실패: " + " / ".join(문제))

    log.info("검증 통과 %d행 (%s ~ %s)", len(df),
             df["주문일"].min().date(), df["주문일"].max().date())
    return df

def transform(df: pd.DataFrame) -> pd.DataFrame:
    return (df
        .assign(매출=lambda d: d["수량"] * d["단가"])
        .pipe(lambda d: d[d["매출"] > 0])
        .groupby(["지점코드", df["주문일"].dt.to_period("M").astype(str)],
                 as_index=False, observed=True)
        .agg(건수=("주문번호", "size"), 매출=("매출", "sum"))
    )

def save(df: pd.DataFrame, out: Path) -> None:
    tmp = out.with_suffix(out.suffix + ".tmp")     # ★ 임시 파일 → 바꿔치기
    df.to_parquet(tmp, index=False)
    tmp.replace(out)
    log.info("저장 완료 %s (%d행)", out, len(df))

def main(src: Path, out: Path) -> int:
    t0 = datetime.now(timezone.utc)
    try:
        result = load(src).pipe(validate).pipe(transform)
        save(result, out)
        log.info("완료 %.1fs", (datetime.now(timezone.utc) - t0).total_seconds())
        return 0
    except Exception:
        log.exception("배치 실패 src=%s", src)
        return 1

왜 .str를 거쳐야 하나요? — Series는 “값들의 묶음”이지 문자열이 아닙니다. 그래서 s.upper()는 없습니다. .str는 “이 묶음 안의 각 값에 파이썬 문자열 메서드를 적용해 달라”는 뜻의 문패입니다. Java로 치면 list.stream().map(String::toUpperCase).toList()가 s.str.upper() 한 줄로 줄어든 것이고, 보너스로 빈칸(NaN)은 알아서 건너뜁니다.
