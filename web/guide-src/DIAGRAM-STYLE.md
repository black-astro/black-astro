# 시각화 모델 디자인 기준 (2026-08-10 확정)

> **기준 원본은 파이썬 가이드입니다.**
> `.diag` 카드의 배경·투명도·색, `.bx` 박스의 채움과 테두리는
> **`python/parts/css/06-scale.css` 의 값이 정답**입니다.
> 다른 가이드는 여기에 맞춥니다. 임의로 그라디언트·그림자·굵은 테두리를 넣지 마세요.
> (실제로 cs 에 그라디언트 + 1.2px 테두리 + drop-shadow 를 넣었다가
>  "박스가 너무 큼직하다"는 지적을 받고 되돌렸습니다.)

## 1. 절대 바꾸지 말 것 — 카드와 박스

```css
/* 그림 카드 */
.diag{
  margin:18px 0; padding:16px 12px 12px; overflow-x:auto;
  border:1px solid var(--line); border-radius:var(--r-m);
  background:linear-gradient(160deg,var(--panel-2),var(--panel))}

/* 그림 폭 — 이 상한이 글씨 크기를 정합니다 */
.diag svg{display:block;width:100%;max-width:1000px;margin:0 auto;
          height:auto;min-width:440px}

/* 박스 — 평면 채움. 그라디언트 금지 */
.diag .bx{fill:rgba(15,26,46,.72);stroke:var(--line);stroke-width:1;rx:10}
```

- **`fill` 은 `rgba(15,26,46,.72)` 평면**입니다. `url(#...)` 그라디언트를 쓰면
  박스가 무겁고 커 보입니다.
- **`stroke-width` 는 1** 입니다. 1.2 만 되어도 눈에 띄게 굵어집니다.
- **`filter: drop-shadow` 를 박스에 걸지 마세요.** 카드가 붕 뜬 것처럼 보입니다.
  (`.pk` 흐름 점의 glow 는 예외 — 원래 있던 것입니다)

## 2. 색의 뜻 — 고정입니다

| 클래스 | 색 | 뜻 |
|---|---|---|
| `.bx` | 남색 평면 | 기본 · 아직 아무 일도 없음 |
| `.bx-ok` | 초록 `rgba(52,211,153,.07)` | 확정 · 정답 · 채택 |
| `.bx-warn` | 붉은 점선 `rgba(251,113,133,.06)` | 버림 · 틀림 · 잘려 나간 가지 |
| `.bx-fw` | 붉은 채움 `rgba(251,113,133,.14)` | **지금 보고 있는 대상** |
| `.bx-hi` | 호박 `rgba(251,191,36,.10)` | 강조 (드물게) |
| `.bx-mut` | 흐린 남색 | 처리 끝나 비활성 |

## 3. 화살촉 — `.ar` 로 켭니다 (2026-08-10 추가)

전에는 화살표가 **선만 있고 화살촉이 없었습니다**(알고리즘 탭 37개 전부).
공용 마커를 `parts/10-body-open.html` 의 숨은 `<svg><defs>` 에 두고
`url(#...)` 로 참조합니다. `url()` 은 문서 전체에서 해석되므로 한 번만 두면 됩니다.

```css
.diag .ar{marker-end:url(#ar-cy)}      /* .fl 흐름선 — 청록 */
.diag .ln.ar{marker-end:url(#ar-ln)}   /* .ln 구조선 — 회청 */
.diag .ar2{marker-start:…;marker-end:…} /* 양방향 */
```

- 마커는 **7 user unit**(화면 약 10px). 9 로 키우면 뭉툭해 보입니다.
- `markerUnits="userSpaceOnUse"` — 선 굵기와 무관하게 크기가 일정합니다.
- **숨길 때 `display:none` 을 쓰면 안 됩니다.** 마커가 안 그려집니다.
  `width=0 height=0 + overflow:hidden` 을 쓰세요.

### 어디에 붙이나
| 붙인다 | 안 붙인다 |
|---|---|
| 방향 그래프 간선 (다익스트라 · 위상 정렬 · 유량 · SCC · 함의 그래프) | 무방향 그래프 (BFS/DFS 예제) |
| 단계 사이 흐름 (`.fl`) | 트리 간선 (위→아래로 이미 읽힘) |
| 실패 링크 · 점프 · 완화 | 구간 막대 · 괄호 · 축 · 장식용 구분선 |
| 시간축 화살표 | 닫힌 도형(`Z` 로 끝나는 path) |

### 선 끝은 반드시 도형 경계에서 끊습니다
중심에서 중심으로 그으면 **화살촉이 노드 밑에 깔려 안 보입니다.**
`guide-src` 루트에서 보정 스크립트를 돌리면 `.ar` 이 붙은 직선 경로의
양 끝을 자동으로 4px 바깥까지 물립니다(원·사각형 모두 처리).

## 4. 글씨 크기 — `max-width:1000px` 기준

확대율이 **1.47배** 로 고정입니다. 화면 실측:

| 소스 | 화면 | 쓰는 곳 |
|---|---|---|
| `font-size="9"` | 13.2px | 곁주석 · 셀 안 작은 라벨 |
| `font-size="10"` | 14.7px | 묶음 제목 · 하단 설명줄 |
| `.lbl` (10.5) | 15.4px | 기본 라벨 |
| `font-size="11"` | 16.2px | 셀 값 · 노드 이름 |
| (본문) | 17.5px | — |

- **9 미만은 쓰지 마세요.** 13px 아래로 내려갑니다.
- 그림 글씨가 본문(17.5px)보다 커지면 안 됩니다.

## 5. viewBox 규칙

- 폭은 **680 고정**.
- 높이는 **마지막 텍스트 baseline + 8 이상**. 같게 두면 1~3px 잘립니다.
- 가로 한계: 한글 `.lbl` 이 x=16 시작 시 약 60자, x=366 시작 시 약 28자.

## 6. 검사

`npm run verify:guide` 는 넘침을 못 잡습니다. 브라우저에서 재야 합니다.
**`content-visibility` 를 먼저 풀지 않으면 `getBBox()` 가 0 을 돌려주고
검사가 조용히 건너뜁니다** — 실제로 이것 때문에 넘침 6건을 놓쳤습니다.

```js
document.querySelectorAll('.pane, .sec').forEach(e=>e.style.contentVisibility='visible')
// 그 다음 HANDOFF.md 의 실측 스크립트 실행
```

## 7. 라이브러리를 쓰지 않는 이유

D3 · Mermaid · Cytoscape · Graphviz(WASM) · JointJS 는 전부 순수 HTML 에서 됩니다
(리액트 전용은 react-flow · visx 정도). 그래도 안 씁니다 —

- 가이드가 **단일 HTML 파일**입니다(cs 1.7MB). 1MB 라이브러리면 배포 크기가 2배.
- 지금은 **런타임 JS 없이** 그려집니다 (오프라인 · 인쇄 정상).
- 한글 라벨 폭을 실측해 맞추는 워크플로가 있는데, **자동 배치가 그걸 깨뜨립니다.**

참고 사이트(algomaster.io)가 좋아 보이는 이유도 라이브러리가 아니라
**색 의미 고정 · 화살촉 · 여백 · 타이포 계층** 같은 규칙입니다. 위 1~5 가 그 규칙입니다.
