벡터 — 배열에 방향을 붙이면 생기는 일

벡터는 [0.2, -0.7, 1.3] 같은 숫자 배열입니다. 다른 점은 이 배열들끼리 더하고 재고 비교할 수 있다는 것뿐인데, 그 하나로 검색·추천·이미지 처리가 전부 돌아갑니다.

기본 연산

import numpy as np

a = np.array([3, 4])
b = np.array([1, 2])

a + b          # [4, 6]     방향을 이어 붙임
a - b          # [2, 2]     b 에서 a 로 가는 방향
3 * a          # [9, 12]    크기만 3배 (방향 유지)

np.linalg.norm(a)      # 5.0   길이(노름) = √(3² + 4²)
a / np.linalg.norm(a)  # [0.6, 0.8]  단위벡터 — 방향만 남김
정규화가 중요한 이유 — 문서 임베딩에서 긴 문서일수록 벡터가 길어집니다. 길이를 1로 맞춰 두면 “내용이 비슷한가”만 남고 “얼마나 긴가”는 빠집니다.

곱셈의 규칙과 의미

(m×n) · (n×p) = (m×p) 가운데 n 이 맞아야 하고, 결과는 바깥 두 개입니다. 
A = np.array([[1, 2],
              [3, 4]])
v = np.array([5, 6])

A @ v          # [17, 39]   ← 벡터를 변환
A @ A          # 변환을 두 번 적용한 것과 같은 하나의 변환

# 결과의 [i][j] = A 의 i 행과 B 의 j 열의 내적
# "i 번째 출력은 입력 전체에 가중치를 곱해 더한 것"

A.T            # 전치 — 행과 열을 바꿈
np.eye(2)      # 항등행렬 — 곱해도 그대로 (숫자의 1 에 해당)
교환법칙이 성립하지 않습니다 — A @ B ≠ B @ A. “회전한 뒤 확대”와 “확대한 뒤 회전”은 다른 결과입니다. 3D 변환에서 순서를 틀리는 버그가 여기서 나옵니다.

선형변환 · 기저 — “좌표계를 바꾼다”의 뜻

회전 · 확대 · 전단은 전부 같은 종류의 연산입니다. 그리고 차원 축소도 사실 “좋은 좌표계로 옮긴 뒤 뒤쪽을 버리는 것”입니다.

import numpy as np

def rotate(deg):
    t = np.radians(deg)
    return np.array([[np.cos(t), -np.sin(t)],
                     [np.sin(t),  np.cos(t)]])

scale = np.array([[2, 0],
                  [0, 3]])          # x 2배, y 3배

shear = np.array([[1, 0.5],
                  [0, 1  ]])        # 기울이기

# 합성 — 오른쪽부터 적용된다
M = rotate(30) @ scale              # 확대한 뒤 회전
p = np.array([1, 0])
M @ p
행렬의 각 열이 “기저 벡터가 어디로 가는가”입니다. [[2,0],[0,3]] 은 “x축 단위벡터가 (2,0)으로, y축이 (0,3)으로 간다”는 뜻이고, 그게 확대의 전부입니다.

# 그래서 차원을 하나 늘려 3×3 으로 만든다 (2D 그래픽스의 표준)

LA 04

행렬식 · 역행렬 — 되돌릴 수 있는가

역행렬은 “변환을 되돌리는 변환”입니다. 그리고 되돌릴 수 없는 경우가 언제인지를 알려 주는 값이 행렬식입니다.

행렬식이 뜻하는 것

det(A) = 면적(부피)이 몇 배가 되는가 det = 0 이면 납작하게 눌려 차원이 줄었다 → 되돌릴 수 없음 
np.linalg.det([[2, 0], [0, 3]])    # 6.0   면적 6배
np.linalg.det([[1, 2], [2, 4]])    # 0.0   2행이 1행의 2배 → 직선으로 눌림
np.linalg.det([[0,-1], [1, 0]])    # 1.0   회전 — 면적 그대로

# det < 0 이면 뒤집힘(거울상)이 포함된 것
직관 — 3차원 물체를 종이에 그림자로 눌러 버리면(det=0) 그림자만 보고 원래 모양을 복원할 수 없습니다. 그게 “역행렬이 없다”입니다.

def solve_naive(A, b):
    A = A.astype(float).copy(); b = b.astype(float).copy()
    n = len(b)
    for i in range(n):
        # ★ 부분 피벗: 남은 행 중 절댓값이 가장 큰 것을 위로
        p = max(range(i, n), key=lambda r: abs(A[r][i]))
        A[[i, p]] = A[[p, i]]; b[i], b[p] = b[p], b[i]

        for r in range(i + 1, n):
            f = A[r][i] / A[i][i]
            A[r, i:] -= f * A[i, i:]
            b[r] -= f * b[i]

    x = np.zeros(n)                     # 후진 대입
    for i in reversed(range(n)):
        x[i] = (b[i] - A[i, i+1:] @ x[i+1:]) / A[i][i]
    return x
피벗팅을 빼면 아주 작은 수로 나누게 되어 오차가 폭발합니다. 실제로 [[1e-20, 1], [1, 1]] 같은 행렬에서 답이 완전히 틀어집니다. 수학적으로는 필요 없지만 부동소수점에서는 필수인 단계이고, 그 이유는 12 · 13 절에서 이어집니다.

def pagerank(M, d=0.85, iters=100):
    n = M.shape[0]
    r = np.ones(n) / n
    for _ in range(iters):
        r = (1 - d) / n + d * (M @ r)     # 계속 곱하면 수렴
    return r

# M[i][j] = j 가 i 를 링크할 확률
# 반복해서 곱하면 '가장 큰 고윳값의 고유벡터'로 수렴한다 (거듭제곱법)
# d = 감쇠 계수 — 링크가 없는 페이지에서 무작위 점프

def power_iteration(A, iters=1000, tol=1e-10):
    v = np.random.rand(A.shape[0])
    v /= np.linalg.norm(v)
    for _ in range(iters):
        w = A @ v
        w_norm = np.linalg.norm(w)
        if w_norm == 0: break
        w /= w_norm
        if np.linalg.norm(w - v) < tol:      # 수렴
            break
        v = w
    lam = v @ (A @ v)                        # 레일리 몫
    return lam, v

#  · 거듭제곱법은 곱셈만 반복 — 희소 행렬에서 O(간선 수)

def power_iteration(A, iters=100, tol=1e-10):
    x = np.random.rand(A.shape[0])
    x /= np.linalg.norm(x)
    for k in range(iters):

        y /= np.linalg.norm(y)          # ★ 정규화 안 하면 발산·언더플로

확률의 기초 — 조건이 붙으면 직관이 무너집니다

확률 계산에서 사람이 틀리는 지점은 거의 정해져 있습니다 — 조건부확률과 독립성 착각. 이 둘만 잡으면 대부분의 오류가 사라집니다.

기본 규칙

P(A∪B) = P(A) + P(B) − P(A∩B)
P(A|B) = P(A∩B) / P(B)
독립 ⟺ P(A∩B) = P(A)·P(B) 세 번째가 정의입니다 — “관계없어 보인다”가 아니라 이 식이 성립해야 독립입니다.

import random
def monty(switch, n=100_000):
    win = 0
    for _ in range(n):
        car = random.randrange(3)
        pick = random.randrange(3)
        # 사회자는 자동차도 내 선택도 아닌 문을 연다
        opened = next(d for d in range(3) if d != car and d != pick)
        if switch:
            pick = next(d for d in range(3) if d != pick and d != opened)
        win += (pick == car)
    return win / n

monty(True)    # 0.667   ← 바꾸는 게 두 배 유리

베이즈 정리 — 증거를 보고 믿음을 갱신하는 공식

“정확도 99% 인 검사가 양성이면 정말 99% 인가?” 답은 아니오이고, 그 이유가 베이즈 정리입니다. 스팸 필터 · 이상 탐지 · 알림 설계가 전부 이 계산 위에 있습니다.

공식과 이름

P(A|B) = P(B|A) · P(A) / P(B) P(A) 사전확률 · P(B|A) 우도 · P(A|B) 사후확률 
# 실제 침입이 0.1% 인 환경에서
# 탐지율 99%, 오탐률 1% 인 시스템이 경보를 울렸다.
# 진짜 침입일 확률은?

p_attack = 0.001
p_alert_given_attack = 0.99
p_alert_given_normal = 0.01

p_alert = (p_alert_given_attack * p_attack +
           p_alert_given_normal * (1 - p_attack))

posterior = p_alert_given_attack * p_attack / p_alert
print(posterior)      # 0.090  ← 겨우 9%!
기저율 무시 오류입니다 — 원래 드문 일이면 정확한 검사도 대부분 오탐이 됩니다. 보안 경보 · 이상 탐지 알림이 무시당하는 수학적 이유입니다.

# 증거가 여러 개면 곱해서 갱신한다 (독립 가정 = 나이브 베이즈)
def update(prior, likelihood_ratios):
    odds = prior / (1 - prior)
    for lr in likelihood_ratios:
        odds *= lr                  # 우도비를 곱하기만 하면 된다
    return odds / (1 + odds)

update(0.001, [99, 50, 20])   # 세 신호가 겹치면 0.99

import math
from collections import Counter, defaultdict

class NaiveBayes:
    def __init__(self, alpha=1.0):
        self.alpha = alpha                   # 라플라스 평활
        self.counts = defaultdict(Counter)
        self.totals = Counter()
        self.docs = Counter()
        self.vocab = set()

    def fit(self, docs):                     # docs: [(tokens, label)]
        for tokens, label in docs:
            self.docs[label] += 1
            for t in tokens:
                self.counts[label][t] += 1
                self.totals[label] += 1
                self.vocab.add(t)

    def predict(self, tokens):
        n = sum(self.docs.values())
        best, best_score = None, -math.inf
        V = len(self.vocab)
        for label in self.docs:
            # 로그로 더한다 — 곱하면 0 으로 언더플로 (13절 참고)
            score = math.log(self.docs[label] / n)
            for t in tokens:
                c = self.counts[label][t] + self.alpha
                score += math.log(c / (self.totals[label] + self.alpha * V))
            if score > best_score:
                best, best_score = label, score
        return best

공식으로 다시 — 그리고 로그로 계산하는 이유

베이즈 정리 유도

P(A∩B) = P(A|B)·P(B) = P(B|A)·P(A) 양변을 P(B) 로 나누면
P(A|B) = P(B|A) · P(A) / P(B)

P(A)  사전확률 — 증거를 보기 전의 믿음
P(B|A)  가능도 — 그 원인이면 이 증거가 나올 확률
P(A|B)  사후확률 — 증거를 본 뒤의 믿음
P(B)  정규화 상수 = Σi P(B|Ai)P(Ai)
오즈(odds) 형태가 실무에서 더 편합니다 사후 오즈 = 사전 오즈 × 우도비
P(A|B)/P(¬A|B) = [P(A)/P(¬A)] × [P(B|A)/P(B|¬A)]

위 예: 사전 오즈 = 1/99, 우도비 = 0.99/0.01 = 99
→ 사후 오즈 = (1/99)×99 = 1 → 확률 1/(1+1) = 0.5 ✓

증거가 여러 개면 우도비를 곱하기만 하면 됩니다 — 분모 P(B) 를 계산할 필요가 없어져 나이브 베이즈 분류기가 이 형태로 구현됩니다.

나이브 베이즈 — 스팸 필터를 직접

import math
from collections import Counter

class NaiveBayes:
    def fit(self, docs, labels):
        self.prior, self.wc, self.total = Counter(), {}, {}
        for d, y in zip(docs, labels):
            self.prior[y] += 1
            self.wc.setdefault(y, Counter()).update(d)
        self.vocab = {w for c in self.wc.values() for w in c}
        self.total = {y: sum(c.values()) for y, c in self.wc.items()}
        self.n = len(docs)
        return self

    def predict(self, doc):
        best, best_score = None, -math.inf
        for y in self.prior:
            # ★ 확률을 곱하면 언더플로 → 로그로 바꿔 더합니다
            score = math.log(self.prior[y] / self.n)
            for w in doc:
                if w not in self.vocab:      # 처음 보는 단어는 무시
                    continue
                # ★ 라플라스 평활 — 한 번도 안 나온 단어가 확률을 0 으로 만드는 것 방지
                p = (self.wc[y][w] + 1) / (self.total[y] + len(self.vocab))
                score += math.log(p)
            if score > best_score:
                best, best_score = y, score
        return best

nb = NaiveBayes().fit(
    [["무료","쿠폰","지금"], ["회의","자료","첨부"], ["당첨","클릭","무료"]],
    ["스팸", "정상", "스팸"])
print(nb.predict(["무료","클릭"]))    # 스팸
두 가지가 없으면 반드시 망가집니다.
① 로그 변환 — 단어 100개면 확률을 100번 곱해 1e-300 이하로 내려가 전부 0 이 됩니다(언더플로). 곱셈을 로그의 덧셈으로 바꾸면 사라집니다.
② 평활(smoothing) — 학습 데이터에 없던 단어 하나가 확률을 0 으로 만들어 문서 전체를 무효화합니다. 분자·분모에 1 을 더하는 라플라스 평활 한 줄이면 됩니다.

def expected_latency(p_fail, base_ms, retries, backoff=2.0):
    """실패 확률 p 로 재시도할 때 기대 지연"""
    total, prob_reach = 0.0, 1.0
    delay = base_ms
    for i in range(retries + 1):
        total += prob_reach * base_ms            # 이번 시도의 소요
        if i < retries:
            total += prob_reach * p_fail * delay # 실패 시 대기
            delay *= backoff
        prob_reach *= p_fail
    return total

expected_latency(0.05, 100, 0)   # 100.0  재시도 없음
expected_latency(0.05, 100, 2)   # 111.3  거의 안 늘어난다
expected_latency(0.30, 100, 2)   # 175.0  실패율이 높으면 비싸진다

# 성공률
1 - 0.05 ** 3    # 0.999875
1 - 0.30 ** 3    # 0.973

# 비슷한 크기의 두 수를 빼면 유효 자릿수가 날아간다

# 실제 사고 예: 분산을 이렇게 계산하면 안 된다
def var_bad(xs):
    n = len(xs)
    return sum(x*x for x in xs)/n - (sum(xs)/n)**2   # E[X²] - E[X]²

xs = [1e8 + i for i in range(5)]
var_bad(xs)     # 음수가 나올 수도 있다 (분산이 음수?!)

# ✓ 웰포드 알고리즘 — 한 번 훑으면서 안정적으로
def var_good(xs):
    n = 0; mean = 0.0; m2 = 0.0
    for x in xs:
        n += 1
        d = x - mean
        mean += d / n
        m2 += d * (x - mean)
    return m2 / n
교과서 공식을 그대로 옮기면 위험합니다 — E[X²]−E[X]² 는 수학적으로 맞지만 수치적으로는 최악입니다. numpy·pandas 는 이미 안정적인 방법을 씁니다.

def kahan_sum(xs):
    total = 0.0; c = 0.0        # c = 잃어버린 아랫자리

        y = x - c
        t = total + y
        c = (t - total) - y     # 방금 잃은 부분을 되찾는다
        total = t
    return total

def logsumexp(xs):

마르코프 체인과 엔트로피 — “다음에 무엇이 올까”를 재는 법

마르코프 체인은 “바로 직전 상태만 보면 다음이 정해지는” 확률 모형입니다. PageRank · 캐시 적중률 · 대기열 · 언어 모델이 전부 이 틀 위에 있습니다. 엔트로피는 “얼마나 예측하기 어려운가”를 숫자 하나로 잰 것이고, 압축률의 하한과 비밀번호의 강도가 같은 식에서 나옵니다.

마르코프 성질 — 미래는 현재에만 의존하고 과거 경로에는 의존하지 않습니다. P(Xn+1 | Xn, Xn−1, …) = P(Xn+1 | Xn). “기억이 없다”는 이 가정 덕분에 전이 행렬 하나로 시스템 전체를 다룰 수 있습니다.
“기억이 없다”는 가정 하나로, 복잡한 시스템의 장기 행동을 행렬 곱셈으로 계산할 수 있게 됩니다.

정상 분포를 두 가지 방법으로

import numpy as np

# 행이 '현재 상태', 열이 '다음 상태' — 각 행의 합은 1
P = np.array([
    [0.0, 0.7, 0.3],   # 대기 → 처리중 0.7, 실패 0.3
    [0.5, 0.3, 0.2],   # 처리중 → 대기 0.5, 유지 0.3, 실패 0.2
    [0.6, 0.0, 0.4],   # 실패 → 대기 0.6, 유지 0.4
])

# ① 반복해서 곱하기 (직관적)
pi = np.array([1.0, 0.0, 0.0])       # 대기에서 출발
for k in range(1, 60):
    new = pi @ P
    if np.abs(new - pi).max() < 1e-12:
        print(f"{k}회에 수렴"); break
    pi = new
print("정상 분포:", pi.round(4))       # [0.3673 0.4184 0.2143]

# ② 고유벡터로 한 번에 (πP = π → P^T 의 고윳값 1 고유벡터)
w, v = np.linalg.eig(P.T)
pi2 = np.real(v[:, np.argmin(np.abs(w - 1))])
pi2 = pi2 / pi2.sum()
print("고유벡터로:", pi2.round(4))     # 같은 값

# 수렴 속도 — 두 번째로 큰 고윳값의 크기
lam = np.sort(np.abs(w))[::-1]
print(f"λ2 = {lam[1]:.3f} → 오차가 매 단계 이 비율로 줄어듭니다")
수렴 조건 — 기약(irreducible)이고 비주기적(aperiodic) 기약: 어느 상태에서든 모든 상태로 갈 수 있다
비주기적: 돌아오는 주기가 딱 떨어지지 않는다

둘 다 만족하면 유일한 정상 분포로 수렴합니다 (에르고딕 정리)
PageRank 가 댐핑 팩터 0.85 를 쓰는 이유가 이것입니다 — 15% 확률로 아무 페이지나 가게 해서 기약성을 강제로 만듭니다

# 가용성을 마르코프로 계산 — SLA 협의에 쓰는 숫자
MTBF, MTTR = 720.0, 2.0        # 평균 무장애 720시간, 평균 복구 2시간

# 상태: 0 정상, 1 다운
P = np.array([
    [1 - 1/MTBF,  1/MTBF],
    [1/MTTR,      1 - 1/MTTR],
])

pi = np.real(v[:, np.argmin(np.abs(w - 1))]); pi /= pi.sum()

print(f"가용성 {pi[0]*100:.4f}%")               # 99.7230%
print(f"연간 다운타임 {pi[1]*365*24:.1f}시간")   # 24.3시간

가용성을 올리는 두 길 중 MTTR 이 훨씬 싸다는 결론이 이 계산에서 바로 나옵니다. “장애가 안 나게 만들기”(MTBF ↑)는 어렵지만, “빨리 복구하기”(MTTR ↓)는 자동 재시작 · 롤백 · 헬스체크로 비교적 쉽게 줄일 수 있습니다. 🏛️ 소프트웨어 공학 12 의 관측 가능성이 여기에 직접 연결됩니다.

엔트로피 — 예측 불가능성을 비트로 재기

압축과 보안이 같은 공식을 씁니다 — 한쪽은 값을 줄이려 하고, 다른 쪽은 늘리려 할 뿐입니다.

공식과 직접 계산

H(X) = − Σ p(x) log2 p(x)  [비트] 균등분포일 때 최대: H = log2 n
한 값이 확실하면 최소: H = 0

교차 엔트로피 H(p, q) = − Σ p(x) log2 q(x)
— 실제 분포 p 를 내 모델 q 로 설명할 때 드는 비용
→ 분류 모델의 손실 함수가 바로 이것입니다

KL 발산 D(p‖q) = H(p,q) − H(p) ≥ 0
— 모델이 실제와 얼마나 다른가 (0 이면 같음) 
import math
from collections import Counter

def entropy(data) -> float:
    n = len(data)
    return -sum((c/n) * math.log2(c/n) for c in Counter(data).values())

print(entropy("aaaaaaaa"))          # 0.0    — 전부 같음
print(entropy("abababab"))          # 1.0    — 두 글자가 반반
print(entropy("abcdefgh"))          # 3.0    — 8가지 균등 = log2(8)
print(entropy(open("a.jpg","rb").read()))   # 7.9 근처 — 이미 압축됨

# 압축 하한 확인 — 이론값보다 작게는 못 줄입니다
data = b"aaaabbbbccccdddd" * 1000
lower = entropy(data) * len(data) / 8
print(f"이론 하한 {lower:.0f}B, 실제 gzip {len(__import__('gzip').compress(data))}B")
