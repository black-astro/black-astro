# 예제 코드 정확성 검토 지침 (code-audit 에이전트용)

저장소 `D:/gibis/workTool/astro/black-astro`, 명령은 `web/` 에서. 대상: 담당 pane 파일의 `<pre class="code">` 예제 + 인라인 코드 + 그 코드를 설명하는 본문.

## 왜 하나 — 사용자가 찾은 실제 예
코틀린 가이드의 예제:
```kotlin
class Order(val id: Long, val amount: Long, val status: String = "NEW") {
    init { require(amount > 0) { "금액은 0보다 커야 합니다: $amount" } }
    constructor(id: Long) : this(id, 0L, "DRAFT")   // ← amount=0 을 넘긴다
}
```
`Order(10)` 은 `require(0 > 0)` 에서 **반드시 실패**합니다 — 보조 생성자를 보여 주려던 예제가 init 검증과 잘못 조합된 것.
이런 오류는 문법 검사로는 안 잡히고 **코드를 직접 따라가 봐야** 보입니다. 담당 범위에서 이런 것을 전부 찾아 고칩니다.

## 무엇을 찾나 (우선순위 순)
1. **실행하면 설명과 다르게 동작하는 코드** — 위 예처럼 서로 모순되는 조합, 주석의 출력값(`// 출력: 3`)이 실제와 다름,
   "이렇게 하면 된다"인데 실제론 예외/무한 루프/데드락/레이스, off-by-one, 빈 컬렉션·null 경로 누락
2. **컴파일·실행 오류** — 없는 메서드/잘못된 시그니처, 타입 불일치, import 누락이 설명을 깨는 경우, 문법 오류, 잘못된 들여쓰기(파이썬)
3. **본문과 코드의 불일치** — 본문은 A 라는데 코드는 B, 표의 값과 코드의 값이 다름, 변수명이 중간에 바뀜
4. **틀렸거나 낡은 API·사실** — 사라진/바뀐 API, 잘못된 기본값 주장(예: 기본 격리 수준, 기본 타임아웃), 버전 표기 오류
5. **나쁜 실무 습관을 "좋은 예"로 보여 주는 것** — 예외 삼키기, 자원 미해제, 하드코딩된 비밀번호를 정답처럼 등. (`.bad`/❌ 처럼 일부러 나쁜 예로 표시된 것은 의도이니 그대로)

일부러 단순화한 코드(… 생략, 의사코드라고 밝힌 것)는 문제 삼지 않습니다. **"설명하려는 요점이 그 코드로 실제로 성립하는가"**가 기준입니다.

## 확인 방법
- 코드를 머릿속으로 따라가되, 짧고 독립적인 예제는 **가능하면 실제로 돌려 보세요**: `python`, `node` 는 이 PC 에 있습니다
  (`python -c` 대신 스크래치패드에 파일로 써서 실행). java/kotlin 은 컴파일러가 없으면 정밀하게 손으로 추적.
- 표현식 결과·출력 주석은 반드시 계산해서 맞춰 보세요.

## 고치는 법
- **최소 수정**으로 요점을 살립니다. 위 예라면 보조 생성자가 유효한 값을 넘기게 바꾸거나(`this(id, 1L, "DRAFT")` 보다는
  설명이 자연스러운 쪽 — 예: 초안 주문은 금액 검증을 다르게 한다는 걸 보여 주거나, 보조 생성자가 amount 를 받게), 주석으로 함정을 설명.
  고친 뒤 주변 본문·주석·출력 주석이 여전히 맞는지 같이 확인.
- 코드 블록 안 `<` `>` `&` 는 반드시 `&lt;` `&gt;` `&amp;` 로. 기존 하이라이트 span 이 있으면 구조를 깨지 말 것.
- 큰 수정은 node 스크립트(파일로 작성 → readFile → 함수형 replace → writeFile) 또는 Edit 도구. bash heredoc 으로 HTML 쓰기 금지,
  `node -e '...'` 로 정규식 수정 금지(셸이 `\b` 를 백스페이스로 바꿈). perl 금지.
- 섹션 추가·삭제·이동 금지, 다이어그램 수정 금지(이번 범위 아님), 담당 외 파일 수정 금지, 빌드 금지, `web/public` 수정 금지.
