왜 C++ 로 앱을 만드나 — 툴킷 일곱 개 중에 고르기

2026년에 데스크톱 앱을 만드는 가장 쉬운 길은 사실 Electron 이나 Tauri 입니다. 그래도 C++ 를 고르는 이유가 분명히 있고, 그 이유가 어떤 툴킷을 고를지까지 결정합니다. 먼저 그 지도를 그린 다음에 설치로 넘어갑니다.

순서는 “정말 C++ 여야 하나” → “무엇을 만드나” → 툴킷 입니다.

툴킷 일곱 개 한눈에 ★

툴킷강점약점

그래서 C++ 를 고르는 진짜 이유 — 네 가지 🟢 기초

숫자로 보는 이유

① 시작 속도 — 사용자가 가장 먼저 느끼는 것
   Electron  창이 뜰 때까지  0.8 ~ 3.0초  (크로뮴 부팅)
   PySide6                   0.5 ~ 2.0초  (파이썬 + Qt import)
   Qt C++                    0.05 ~ 0.2초  ★ 클릭하면 이미 떠 있음

② 메모리 — 백그라운드에 늘 떠 있는 앱일수록 중요
   Electron  빈 창          150 ~ 400MB
   Qt C++    빈 창           25 ~ 60MB

③ 큰 데이터 — 앱이 죽느냐 마느냐가 갈립니다
   1,000만 행 테이블을 JS 배열로  →  수 GB, 사실상 불가
   1,000만 행을 C++ 구조체 배열로 →  200~400MB, 스크롤 부드러움

④ 기존 C++ 자산 — 이게 실무에서 제일 흔한 이유입니다
   이미 있는 엔진·SDK·영상 처리 코드에 화면만 붙일 때
   FFI 로 넘기는 것보다 같은 프로세스가 압도적으로 단순합니다
반대로 C++ 를 고르면 안 되는 신호 — 화면이 폼과 목록뿐이다 · 디자이너가 CSS 로 시안을 준다 · 2주 안에 시연해야 한다 · 팀에 C++ 를 읽는 사람이 없다. 이 중 둘 이상이면 Tauri 2 나 Electron 이 정답입니다.

한 앱 안에 두 툴킷

실제 제품에서 자주 보는 조합

① Qt Widgets  +  Dear ImGui
   사용자가 보는 화면은 Qt, 개발자용 디버그 오버레이는 ImGui
   → QOpenGLWidget 안에 ImGui 를 그려 F12 로 토글

② Qt Widgets  +  Qt Quick(QML)
   메뉴·툴바·도킹은 Widgets, 그래프·애니메이션 패널만 QML
   → QQuickWidget 으로 QML 화면을 위젯처럼 끼워 넣습니다

③ SDL3(창·입력)  +  Dear ImGui(UI)
   게임 엔진 툴체인의 표준 조합. 에디터가 이 구조입니다

④ 네이티브 셸  +  웹뷰
   Qt WebEngine 이나 WebView2 로 일부 화면만 웹으로
   → 결제·약관·리포트처럼 자주 바뀌는 화면에 유용

⑤ C++ 코어  +  파이썬/Electron 프런트
   계산은 C++ 라이브러리, 화면은 다른 언어 — 🔗 FFI 탭 참고
   → 프로세스가 나뉘면 크래시 격리가 되는 장점도 있습니다
①~③ 은 전부 “보여 줄 사람이 다르다”가 이유입니다 — 사용자용 화면과 개발자용 화면의 요구가 완전히 다르기 때문입니다. 개발자용을 예쁘게 만드느라 시간을 쓰는 건 대부분 낭비고, 그래서 ImGui 가 사랑받습니다(g07).

Qt 6 설치 — 설치기냐 vcpkg 냐, 그리고 첫 CMake

pip install pyside6 한 줄이던 것이 C++ 에서는 계정 만들기 · 컴포넌트 고르기 · 30GB 디스크가 됩니다. 여기서 막히는 사람이 정말 많아서, 무엇을 왜 고르는지를 화면 순서대로 적어 둡니다. 그리고 이 모든 걸 건너뛰는 vcpkg 경로도 같이 봅니다.

설치가 어렵게 느껴지는 이유는 “CMake 에게 Qt 위치를 알려 주는 한 줄”이 안 보여서입니다.

경로 A — 온라인 설치기, 화면 순서대로 ★

① qt.io/download-open-source  →  Qt Online Installer 내려받기
   (윈도우 .exe / macOS .dmg / 리눅스 .run — chmod +x 필요)

② Qt 계정 로그인 — 계정이 없으면 여기서 만듭니다
   "I'm an individual and do not use Qt for commercial..." 체크
   → 회사에서 쓸 거면 여기서 멈추고 법무·구매 확인이 먼저입니다

③ 설치 방식: "Custom installation" 을 고르세요
   기본값(Qt 전체)을 그대로 두면 30GB 를 받습니다

④ 컴포넌트 선택 — 윈도우 기준 최소 조합
   Qt 6.8.x
     [v] MSVC 2022 64-bit          ★ 이거 하나가 본체
     [ ] MinGW 13.1.0 64-bit        (g++ 를 쓸 거면 이것도)
     [v] Qt 5 Compatibility Module  (예제·구버전 코드용, 작음)
     [ ] Sources                     ★ 끄세요 (3GB, 디버깅할 때만)
     Additional Libraries
       [v] Qt Multimedia            (동영상·오디오 재생이 필요하면)
       [ ] Qt WebEngine             ★ 2GB+ — 정말 필요할 때만
       [v] Qt Charts                (그래프)

     [v] CMake · Ninja              (이미 있으면 꺼도 됨)

⑤ 설치 경로는 기본값 C:\Qt 를 권합니다
   공백·한글이 든 경로는 나중에 반드시 문제를 냅니다
MSVC 냐 MinGW 냐 — 둘을 섞으면 링크가 안 됩니다. 윈도우에서 Visual Studio Build Tools 가 이미 깔려 있다면 MSVC 2022 64-bit 하나만 고르세요. vcpkg 로 받는 다른 라이브러리들도 기본이 MSVC 라 섞일 일이 없습니다. MinGW 는 “g++ 명령이 익숙하다”는 이유 하나로 고르기엔 나중에 치를 값이 큽니다.

최소 프로젝트 — 파일 세 개면 창이 뜹니다 🟢 기초

CMakeLists.txt — 실무에서도 이 모양입니다 ★

cmake_minimum_required(VERSION 3.21)
project(qtfirst LANGUAGES CXX)

set(CMAKE_CXX_STANDARD 20)
set(CMAKE_CXX_STANDARD_REQUIRED ON)

# Qt 가 만들어 내는 코드를 자동으로 처리합니다 ★ 세 줄 다 필요
set(CMAKE_AUTOMOC ON)   # Q_OBJECT 가 붙은 클래스 → moc 실행
set(CMAKE_AUTOUIC ON)   # .ui 파일 → ui_*.h 생성
set(CMAKE_AUTORCC ON)   # .qrc 리소스 → 코드로 embed

find_package(Qt6 6.5 REQUIRED COMPONENTS Widgets)

qt_standard_project_setup()      # Qt 6.3+ — 관례를 한 번에 켜 줍니다

qt_add_executable(qtfirst
    main.cpp
    mainwindow.cpp mainwindow.h
)

target_link_libraries(qtfirst PRIVATE Qt6::Widgets)

# 윈도우에서 콘솔 창이 같이 뜨지 않게 (배포용)
set_target_properties(qtfirst PROPERTIES
    WIN32_EXECUTABLE ON       # 윈도우: 콘솔 없음
    MACOSX_BUNDLE ON          # macOS: .app 번들로
)
qt_add_executable vs add_executable — Qt 6 전용 버전은 배포 도구 연동 · 안드로이드/WASM 대응 · 리소스 처리가 붙어 있습니다. Qt 프로젝트라면 항상 qt_ 접두사 버전을 쓰세요. qt_standard_project_setup() 은 AUTOMOC 같은 것들을 알아서 켜 주므로 위의 세 줄은 사실 생략해도 됩니다(설명을 위해 남겨 뒀습니다).

Qt Widgets 첫 앱 — 이벤트 루프와 시그널/슬롯

Qt 앱의 main() 은 딱 세 줄입니다. 그 세 줄이 무슨 일을 하는지 알면 “왜 창이 바로 닫히지”, “왜 UI 가 멈추지” 같은 질문이 한꺼번에 풀립니다. PySide6 코드와 나란히 놓고 보겠습니다.

Qt 의 모든 이상 현상은 대개 “이 루프가 지금 무엇을 하느라 못 도는가”로 설명됩니다.

첫 창 — PySide6 와 나란히 ★

// main.cpp
#include <QApplication>
#include <QPushButton>

int main(int argc, char *argv[]) {
    QApplication app(argc, argv);   // ① 반드시 첫 줄. 스타일·폰트·이벤트 큐를 세웁니다

    QPushButton button("눌러 보세요");
    button.resize(240, 80);
    button.show();                  // ② show() 를 빠뜨리면 창이 안 보입니다

    QObject::connect(&button, &QPushButton::clicked, [] {
        qDebug() << "눌렸습니다";   // ③ 람다가 그대로 슬롯이 됩니다
    });

    return app.exec();              // ④ 여기서 이벤트 루프가 돕니다
}                                   //    창을 닫으면 exec() 이 반환됩니다

// rowmodel.h — 데이터가 어디 있든 "표처럼 보이게" 하는 어댑터입니다
#include <QAbstractTableModel>

struct Row { QString name; int size; QString when; };

class RowModel : public QAbstractTableModel {
    Q_OBJECT
public:
    using QAbstractTableModel::QAbstractTableModel;

    void setRows(std::vector<Row> rows) {
        beginResetModel();          // ★ 뷰에게 "지금부터 바뀐다"
        m_rows = std::move(rows);
        endResetModel();            // ★ "끝났다" — 이 사이에서만 고칩니다
    }

    int rowCount(const QModelIndex& = {}) const override
        { return static_cast<int>(m_rows.size()); }
    int columnCount(const QModelIndex& = {}) const override { return 3; }

    QVariant data(const QModelIndex &ix, int role) const override {
        if (!ix.isValid()) return {};
        const Row &r = m_rows[ix.row()];
        if (role == Qt::DisplayRole) {
            switch (ix.column()) {
                case 0: return r.name;
                case 1: return QLocale().formattedDataSize(r.size);
                case 2: return r.when;
            }
        }
        if (role == Qt::TextAlignmentRole && ix.column() == 1)
            return int(Qt::AlignRight | Qt::AlignVCenter);
        return {};
    }

    QVariant headerData(int s, Qt::Orientation o, int role) const override {
        if (o != Qt::Horizontal || role != Qt::DisplayRole) return {};
        static const char *h[] = {"이름", "크기", "수정 시각"};
        return QString::fromUtf8(h[s]);
    }
private:
    std::vector<Row> m_rows;
};

Qt Quick · QML — 선언형 UI와 C++ 백엔드 잇기

Widgets 가 “버튼을 만들어 레이아웃에 넣어라”라면, QML 은 “여기에 버튼이 있다”고 적는 방식입니다. React 나 SwiftUI 를 써 봤다면 익숙한 감각이고, 애니메이션·터치·커스텀 디자인에서 압도적으로 유리합니다. 대신 C++ 데이터를 QML 로 넘기는 다리를 놓는 법을 알아야 합니다.

경계를 지키면 C++ 로직은 화면을 모르고, 나중에 Widgets 로 갈아끼워도 그대로 삽니다.

class Backend : public QObject {
    Q_OBJECT
    QML_ELEMENT                        // ★ 이 한 줄로 QML 에 Backend 로 등록됩니다

    // ① 읽기 전용 프로퍼티 — QML 이 backend.busy 로 읽습니다
    Q_PROPERTY(bool busy READ busy NOTIFY busyChanged)
    Q_PROPERTY(QStringList results READ results NOTIFY resultsChanged)

    // 읽고 쓰는 프로퍼티라면 WRITE 도 붙입니다
    Q_PROPERTY(QString keyword READ keyword WRITE setKeyword NOTIFY keywordChanged)

public:
    explicit Backend(QObject *parent = nullptr) : QObject(parent) {}

    bool busy() const { return m_busy; }
    QStringList results() const { return m_results; }
    QString keyword() const { return m_keyword; }

    void setKeyword(const QString &k) {
        if (k == m_keyword) return;      // ★ 같으면 즉시 반환 — 무한 루프 방지
        m_keyword = k;
        emit keywordChanged();
    }

    // ② QML 이 부를 수 있는 함수
    Q_INVOKABLE void search(const QString &q);
    Q_INVOKABLE void open(const QString &item);

signals:
    void busyChanged();
    void resultsChanged();
    void keywordChanged();
    void failed(const QString &message);   // ③ QML 이 onFailed 로 받습니다

private:
    void setBusy(bool b) { if (b != m_busy) { m_busy = b; emit busyChanged(); } }

    bool        m_busy = false;
    QStringList m_results;
    QString     m_keyword;
};

창을 띄우는 것과 쓸 만한 앱 사이의 거리는 대부분 이 다섯 가지입니다. 특히 “UI 가 멈춘다”는 문제는 신입이든 경력이든 한 번은 겪는데, Qt 의 해법은 놀랄 만큼 단정합니다 — 워커는 시그널만 쏘고 화면은 건드리지 않습니다.

방법 A — QtConcurrent, 단발성이면 이걸로 ★

#include <QtConcurrent>
#include <QFutureWatcher>
// CMake: find_package(Qt6 COMPONENTS Concurrent) / Qt6::Concurrent

struct Result { int lines; qint64 bytes; };

void MainWindow::loadFile(const QString &path) {
    ui->loadButton->setEnabled(false);       // 중복 실행 방지

    // ① 스레드풀에서 실행 — 반환값이 QFuture 로 옵니다
    QFuture<Result> future = QtConcurrent::run([path] {
        QFile f(path);
        f.open(QIODevice::ReadOnly);
        int n = 0;
        while (!f.atEnd()) { f.readLine(); ++n; }
        return Result{ n, f.size() };        // 여기서는 위젯을 절대 안 만짐
    });

    // ② 끝나면 UI 스레드에서 이어받기 — Qt 6 의 then() 이 제일 깔끔합니다
    future.then(this, [this](Result r) {     // this 를 주면 UI 스레드에서 실행 ★
        ui->statusLabel->setText(QString("%1줄 / %2").arg(r.lines)
                                  .arg(QLocale().formattedDataSize(r.bytes)));
        ui->loadButton->setEnabled(true);
    }).onFailed(this, [this](const std::exception &e) {
        QMessageBox::warning(this, "실패", QString::fromUtf8(e.what()));
        ui->loadButton->setEnabled(true);
    });
}

// worker.h — QThread 를 상속하지 마세요. 객체를 옮기는 방식이 정석입니다
class Worker : public QObject {
    Q_OBJECT
public slots:
    void scan(const QString &dir) {
        QDirIterator it(dir, QDirIterator::Subdirectories);
        int n = 0;
        while (it.hasNext()) {
            if (m_stop.loadRelaxed()) { emit canceled(); return; }
            it.next();
            if (++n % 500 == 0) emit progress(n);      // 너무 자주 쏘면 UI 가 밀립니다
        }
        emit finished(n);
    }
    void requestStop() { m_stop.storeRelaxed(1); }     // 다른 스레드에서 불러도 안전
signals:
    void progress(int count);
    void finished(int total);
    void canceled();
private:
    QAtomicInt m_stop{0};
};
// mainwindow.cpp — 조립은 여섯 줄입니다
auto *thread = new QThread(this);

worker->moveToThread(thread);              // 이 객체의 슬롯은 이제 저 스레드에서 돕니다

connect(this, &MainWindow::startScan, worker, &Worker::scan);       // 큐 연결

});
thread->start();
emit startScan("C:/data");                 // 직접 worker->scan() 을 부르면 안 됩니다 ★

    q.prepare("INSERT INTO notes(title, body, created) VALUES(?, ?, ?)");
    q.addBindValue(title);
    q.addBindValue(body);
    q.addBindValue(QDateTime::currentSecsSinceEpoch());
    if (!q.exec()) qWarning() << q.lastError().text();
}

Qt 배포 — exe 하나를 건네도 안 도는 이유

빌드가 끝나면 app.exe 가 생기지만, 그걸 다른 컴퓨터에 복사하면 거의 확실히 안 돕니다. Qt DLL 이 없기 때문입니다. 여기서는 필요한 파일을 자동으로 모으고 → 설치 파일로 묶고 → 서명하는 한 바퀴를 OS 별로 끝냅니다. 이 섹션을 마치면 남에게 건넬 수 있는 결과물이 나옵니다.

“내 PC 에선 되는데”의 정체는 대부분 Qt 설치 폴더가 PATH 에 있어서입니다.

윈도우 — windeployqt ★

      COMMAND "${CMAKE_COMMAND}" -E copy "$<TARGET_FILE:app>" "$<TARGET_FILE_DIR:app>/dist"
      COMMAND "${WINDEPLOYQT}" --release "$<TARGET_FILE_DIR:app>/dist/app.exe")
endif()

# Qt 6.5+ 에는 표준 설치 스크립트 생성기도 있습니다

Dear ImGui — 즉시 모드가 도구를 만드는 방식

Qt 로 디버그 창 하나를 만들려면 클래스 · 헤더 · 시그널 · 모델이 줄줄이 붙습니다. ImGui 는 그 자리에서 if (ImGui::Button("리셋")) reset(); 한 줄이면 끝입니다. 게임 엔진과 그래픽스 도구가 전부 이걸 쓰는 이유, 그리고 왜 사용자용 앱에는 안 쓰는지를 봅니다.

즉시 모드의 본질은 “UI 상태를 따로 보관하지 않는다” — 그래서 동기화 버그가 사라집니다.

Qt 와 ImGui 는 “위젯”이라는 개념 위에 있습니다. SDL3 와 raylib 에는 그런 게 없습니다 — 창을 열고, 입력을 받고, 픽셀을 그리는 딱 그만큼만 줍니다. 게임뿐 아니라 영상 플레이어 · 시뮬레이터 · 시각화 도구처럼 화면 전체를 직접 그리는 프로그램의 바닥입니다.

델타 타임만 써도 대부분 충분하고, 충돌이 중요한 게임이면 ③ 누산기로 갑니다.

SDL3 — 전체 예제 (움직이는 사각형) ★

// vcpkg install sdl3   /   CMake: find_package(SDL3 CONFIG REQUIRED)
//                            target_link_libraries(app PRIVATE SDL3::SDL3)
#include <SDL3/SDL.h>
#include <cstdio>

int main(int, char**) {
    if (!SDL_Init(SDL_INIT_VIDEO)) {          // ★ SDL3 는 bool 을 돌려줍니다
        SDL_Log("init 실패: %s", SDL_GetError());
        return 1;
    }

    // SDL3 의 CreateWindow 에는 x, y 가 없습니다 (SDL2 와 다른 점)
    SDL_Window *win = SDL_CreateWindow("SDL3 첫 창", 960, 640,
                                       SDL_WINDOW_RESIZABLE);
    SDL_Renderer *ren = SDL_CreateRenderer(win, nullptr);   // nullptr = 자동 선택
    SDL_SetRenderVSync(ren, 1);               // 화면 주사율에 맞춰 제한

    SDL_FRect player{ 100.f, 100.f, 48.f, 48.f };   // SDL3 는 float 좌표가 기본
    float speed = 320.f;                             // 초당 320픽셀

    Uint64 prev = SDL_GetTicksNS();
    bool running = true;

    while (running) {
        // ── ① 입력 ────────────────────────────────
        SDL_Event e;
        while (SDL_PollEvent(&e)) {
            switch (e.type) {
                case SDL_EVENT_QUIT: running = false; break;
                case SDL_EVENT_KEY_DOWN:
                    if (e.key.key == SDLK_ESCAPE) running = false;
                    break;
                case SDL_EVENT_WINDOW_RESIZED:
                    SDL_Log("크기 %dx%d", e.window.data1, e.window.data2);
                    break;
            }
        }

        // ── ② 갱신 (델타 타임) ────────────────────
        Uint64 now = SDL_GetTicksNS();
        float dt = float(now - prev) / 1'000'000'000.0f;   // 초 단위
        prev = now;
        if (dt > 0.25f) dt = 0.25f;           // ★ 디버거로 멈췄다 재개했을 때 대비

        const bool *key = SDL_GetKeyboardState(nullptr);   // SDL3 는 bool 배열
        float dx = 0, dy = 0;
        if (key[SDL_SCANCODE_LEFT])  dx -= 1;
        if (key[SDL_SCANCODE_RIGHT]) dx += 1;
        if (key[SDL_SCANCODE_UP])    dy -= 1;
        if (key[SDL_SCANCODE_DOWN])  dy += 1;
        if (dx && dy) { dx *= 0.7071f; dy *= 0.7071f; }   // 대각선 보정
        player.x += dx * speed * dt;
        player.y += dy * speed * dt;

        // ── ③ 그리기 ──────────────────────────────
        SDL_SetRenderDrawColor(ren, 24, 28, 36, 255);
        SDL_RenderClear(ren);

        SDL_SetRenderDrawColor(ren, 96, 220, 160, 255);
        SDL_RenderFillRect(ren, &player);

        SDL_SetRenderDrawColor(ren, 200, 200, 210, 255);
        SDL_RenderDebugText(ren, 12, 12, "화살표로 이동 / ESC 종료");  // 디버그용

        SDL_RenderPresent(ren);               // 화면에 내보내기
    }

    SDL_DestroyRenderer(ren);
    SDL_DestroyWindow(win);
    SDL_Quit();
    return 0;
}
SDL2 를 알던 사람이 놓치는 SDL3 변경점 — ① 성공하면 true(SDL2 는 0) · ② 이벤트 이름이 SDL_EVENT_* 로 통일 · ③ e.key.keysym.sym → e.key.key · ④ 좌표가 float 기본(SDL_FRect) · ⑤ SDL_RenderCopy → SDL_RenderTexture. 인터넷의 SDL2 예제를 그대로 쓰면 컴파일이 안 됩니다.

#define SDL_MAIN_USE_CALLBACKS 1

#include <SDL3/SDL_main.h>

struct App { SDL_Window *win; SDL_Renderer *ren; SDL_FRect p; Uint64 prev; };

SDL_AppResult SDL_AppInit(void **state, int, char**) {
    SDL_Init(SDL_INIT_VIDEO);
    auto *a = new App{};
    SDL_CreateWindowAndRenderer("app", 960, 640, 0, &a->win, &a->ren);
    a->p = {100, 100, 48, 48};
    a->prev = SDL_GetTicksNS();

SDL_AppResult SDL_AppEvent(void *state, SDL_Event *e) {
    if (e->type == SDL_EVENT_QUIT) return SDL_APP_SUCCESS;   // 정상 종료

SDL_AppResult SDL_AppIterate(void *state) {     // 한 프레임 ★

    SDL_RenderClear(a->ren);

    SDL_RenderFillRect(a->ren, &a->p);

}

            DrawCircleV(player, 18, dead ? GRAY : LIME);
            DrawText(TextFormat("SCORE %04i", (int)score), 16, 16, 24, RAYWHITE);
            if (dead) DrawText("GAME OVER - SPACE", W/2 - 190, H/2 - 20, 34, RED);
        EndDrawing();
    }

    CloseWindow();
    return 0;
}

// 물리가 중요한 게임이라면 이 형태로 바꿉니다
constexpr double STEP = 1.0 / 120.0;      // 물리는 초당 120회 고정

double accumulator = 0.0;
Uint64 prev = SDL_GetTicksNS();

while (running) {
    Uint64 now = SDL_GetTicksNS();
    double frame = double(now - prev) / 1e9;
    prev = now;
    if (frame > 0.25) frame = 0.25;       // 스파이럴 오브 데스 방지 ★
    accumulator += frame;

    pollInput();

    while (accumulator >= STEP) {         // 밀린 만큼 여러 번 돕니다
        previousState = currentState;     // 보간용으로 직전 상태 보관
        physicsStep(currentState, STEP);  // 항상 같은 dt — 결과가 결정적입니다
        accumulator -= STEP;
    }

    const double alpha = accumulator / STEP;          // 0.0 ~ 1.0
    auto view = lerp(previousState, currentState, alpha);   // 부드럽게
    render(view);
}
왜 고정 스텝이 필요한가 — 세 가지 이유

  ① 터널링   dt 가 크면 총알이 벽을 그냥 통과합니다
             (한 프레임에 벽 두께보다 많이 이동)
  ② 결정성   같은 입력 → 항상 같은 결과. 리플레이·네트워크 동기화의 전제
             (게임 서버 얘기는 🎮 게임 서버 탭에서 이어집니다)
  ③ 안정성   스프링·마찰 같은 수치 적분은 dt 가 흔들리면 발산합니다

  "스파이럴 오브 데스" — 프레임이 느려지면 물리를 더 많이 돌리고,
  그래서 더 느려지고, 다시 더 많이 돌리는 악순환.
  frame 을 0.25초로 자르는 한 줄이 이걸 끊습니다 ★
이 루프는 게임만의 것이 아닙니다 — 로봇 제어, 시뮬레이션, 신호 처리, 실시간 차트 렌더링이 전부 같은 구조를 씁니다. “일정한 간격으로 계산하고, 화면은 남는 시간에 그린다”는 패턴 자체가 자산입니다.
정리 — SDL3 는 OS 를 감싸는 얇은 층이고 raylib 은 배우기 쉬운 포장입니다. 둘 다 UI 위젯을 주지 않으므로, 도구를 만든다면 SDL3 + Dear ImGui 조합으로 가세요.

void MyFrame::OnKey(wxKeyEvent &e) {
    if (e.GetKeyCode() == WXK_ESCAPE) { Close(); return; }
    e.Skip();      // ★ 처리 안 했으면 반드시 Skip() — 부모로 넘깁니다

        L"Software\\Microsoft\\Windows\\CurrentVersion\\Run",

struct LogStore {
    std::vector<qint64>  ts;        // 타임스탬프
    std::vector<quint8>  level;     // 0=DEBUG 1=INFO 2=WARN 3=ERROR
    std::vector<quint32> msgOffset; // 큰 문자열 버퍼 안의 위치
    QByteArray           blob;      // 메시지 원문을 한 덩어리로 (mmap 도 가능)
    size_t size() const { return ts.size(); }
};
// 행마다 QString 3개를 들고 있는 구조체 배열보다 메모리가 5~10배 적습니다

class LogModel : public QAbstractTableModel {
    Q_OBJECT
public:
    int rowCount(const QModelIndex& = {}) const override
        { return int(m_visible.size()); }        // 필터 결과 인덱스만 보관
    int columnCount(const QModelIndex& = {}) const override { return 3; }

    QVariant data(const QModelIndex &ix, int role) const override {
        if (!ix.isValid()) return {};
        const quint32 row = m_visible[ix.row()];   // 필터 → 원본 인덱스

        switch (role) {
        case Qt::DisplayRole:
            switch (ix.column()) {
            case 0: return m_fmtCache.timeString(m_s.ts[row]);  // ★ 캐시 사용
            case 1: return levelName(m_s.level[row]);           // ★ 정적 문자열
            case 2: return QString::fromUtf8(m_s.blob.constData()
                              + m_s.msgOffset[row]);
            }
            break;
        case Qt::ForegroundRole:
            if (m_s.level[row] >= 3) return QColor(0xff, 0x6b, 0x6b);
            break;
        case Qt::UserRole:                      // 정렬용 원시 값
            return qulonglong(m_s.ts[row]);
        }
        return {};
    }
private:
    const LogStore   &m_s;
    std::vector<quint32> m_visible;
    mutable TimeCache m_fmtCache;   // 같은 초는 문자열을 재사용합니다 ★
};
data() 는 “가장 자주 불리는 함수”라고 생각하세요 — 스크롤 한 번에 수백 번, 마우스를 움직이기만 해도 툴팁 role 로 또 불립니다. 여기서 파일을 읽거나 · 정규식을 돌리거나 · 로그를 찍으면 앱이 즉시 끈적해집니다. 무거운 계산은 미리 해서 캐시해 두고, data() 는 꺼내 주기만 해야 합니다.

// src/core/LogStore.h — 파일 전체를 메모리에 올리지 않습니다
#pragma once
#include <QFile>
#include <QString>
#include <vector>

struct LineRef { quint64 offset; quint32 len; quint8 level; qint64 ts; };

class LogStore {
public:
    bool open(const QString &path, QString *err);
    size_t size() const { return m_lines.size(); }

    // 메시지는 물어볼 때만 문자열로 만듭니다 (data() 에서 호출) ★
    QString text(size_t i) const {
        const auto &r = m_lines[i];
        return QString::fromUtf8(
            reinterpret_cast<const char*>(m_map) + r.offset, int(r.len));
    }
    const LineRef& ref(size_t i) const { return m_lines[i]; }

    // 워커에서 호출 — 진행률 콜백과 취소 플래그를 받습니다
    template <class Fn>
    bool index(Fn onProgress, const std::atomic_bool &cancel);

private:
    QFile                 m_file;
    const uchar          *m_map = nullptr;   // ★ mmap
    qint64                m_size = 0;
    std::vector<LineRef>  m_lines;
};
// src/core/LogStore.cpp
bool LogStore::open(const QString &path, QString *err) {
    m_file.setFileName(path);
    if (!m_file.open(QIODevice::ReadOnly)) { *err = m_file.errorString(); return false; }
    m_size = m_file.size();
    m_map  = m_file.map(0, m_size);          // ★ OS 가 필요한 페이지만 읽어 옵니다
    if (!m_map) { *err = "메모리 매핑 실패"; return false; }
    return true;
}

template <class Fn>
bool LogStore::index(Fn onProgress, const std::atomic_bool &cancel) {
    m_lines.clear();
    m_lines.reserve(size_t(m_size / 120));   // 평균 줄 길이로 미리 확보 ★
    const char *p = reinterpret_cast<const char*>(m_map);
    quint64 start = 0;

    for (qint64 i = 0; i < m_size; ++i) {
        if (p[i] != '\n') continue;
        LineRef r;
        r.offset = start;
        r.len    = quint32(i - start);
        r.level  = detectLevel(p + start, r.len);    // "ERROR" 등을 앞부분에서만 찾음
        r.ts     = parseTimestamp(p + start, r.len); // 실패하면 -1
        m_lines.push_back(r);
        start = quint64(i + 1);

        if ((m_lines.size() & 0xFFFF) == 0) {        // 6.5만 줄마다 ★
            if (cancel.load(std::memory_order_relaxed)) return false;
            onProgress(int(i * 100 / m_size));
        }
    }
    return true;
}
왜 mmap 인가 — 3GB 파일을 readAll() 하면 메모리 3GB 를 씁니다. mmap 은 주소만 잡아 두고 실제로 읽는 페이지만 물리 메모리에 올립니다. 화면에 보이는 40줄만 만지면 그 40줄이 있는 페이지만 읽힙니다. 인덱싱은 전체를 한 번 훑지만 순차 읽기라 디스크가 가장 빠른 방식으로 돕니다.

// src/core/Filter.h
struct FilterSpec {
    QString  needle;          // 부분 문자열 (대소문자 무시)
    quint8   minLevel = 0;    // 0=전체 2=WARN 이상 3=ERROR 만
    qint64   fromTs = -1, toTs = -1;
    bool     regex = false;
};

std::vector<quint32> runFilter(const LogStore &s, const FilterSpec &f,
                               const std::atomic_bool &cancel);
// src/viewmodel/LogViewModel.cpp
void LogViewModel::applyFilter(const QString &text) {
    m_spec.needle = text;

    // ① 이전 작업 취소 — 사용자가 계속 타이핑하면 앞의 것은 버립니다 ★
    if (m_filterCancel) m_filterCancel->store(true);
    auto cancel = std::make_shared<std::atomic_bool>(false);
    m_filterCancel = cancel;

    setBusy(true);
    const LogStore *store = &m_store;
    FilterSpec spec = m_spec;
    const quint64 token = ++m_filterToken;      // ② 순서 보장용 표 ★

    QtConcurrent::run([store, spec, cancel] {
        return runFilter(*store, spec, *cancel);
    }).then(this, [this, token, cancel](std::vector<quint32> visible) {
        if (cancel->load()) return;              // 취소된 결과는 버립니다
        if (token != m_filterToken) return;      // ③ 늦게 온 옛 결과도 버립니다
        setBusy(false);
        emit filterReady(std::move(visible));
    });
}
“늦게 온 옛 결과”가 실무의 진짜 버그입니다 — 사용자가 err 를 치다가 error 까지 쳤는데, err 작업이 더 오래 걸려 나중에 도착하면 화면이 옛 결과로 덮입니다. 토큰(순번) 비교 한 줄이 이걸 막습니다. 취소 플래그만으로는 부족합니다.

    initStyleOption(&o, ix);

    // 선택 배경 · 교대 행 색은 기본 스타일에 맡깁니다
    o.widget->style()->drawPrimitive(QStyle::PE_PanelItemViewItem, &o, p, o.widget);

    const int level = ix.data(Qt::UserRole + 1).toInt();
    p->setPen(level >= 3 ? QColor(0xff, 0x6b, 0x6b)
             : level == 2 ? QColor(0xfb, 0xbf, 0x24)
                          : o.palette.text().color());

    const QString text = ix.data(Qt::DisplayRole).toString();
    QRect r = o.rect.adjusted(6, 0, -6, 0);

    // 검색어 강조 — 매칭 구간에만 배경을 칠합니다
    if (!m_needle.isEmpty()) {
        const int at = text.indexOf(m_needle, 0, Qt::CaseInsensitive);
        if (at >= 0) {
            const QFontMetrics fm(o.font);
            const int x1 = fm.horizontalAdvance(text.left(at));
            const int w  = fm.horizontalAdvance(text.mid(at, m_needle.size()));
            p->fillRect(QRect(r.x() + x1, r.y(), w, r.height()),
                        QColor(0x22, 0xc5, 0x5e, 0x55));
        }
    }
    p->drawText(r, Qt::AlignVCenter | Qt::TextSingleLine,
                o.fontMetrics.elidedText(text, Qt::ElideRight, r.width()));
}

// ★ sizeHint 는 고정값을 돌려주세요 — 계산하면 100만 행에서 멈춥니다
QSize LogDelegate::sizeHint(const QStyleOptionViewItem&, const QModelIndex&) const {
    return QSize(10, m_rowHeight);
}
