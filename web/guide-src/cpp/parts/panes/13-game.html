게임 서버는 웹 서버와 목표가 다릅니다. 웹은 요청 하나에 응답 하나를 잘 돌려주면 되지만, 게임은 아무도 요청하지 않아도 1초에 30~60번 세계를 굴려야 하고, 그 결과를 접속한 전원에게 수십 밀리초 안에 뿌려야 합니다. 그래서 스레드 모델도, 네트워크 모델도, 데이터 저장 방식도 전부 달라집니다. 이 탭은 틱 루프 · 신뢰 UDP · 패킷 설계 · IOCP/epoll · 넷코드(예측·보간·지연 보상) 를 거쳐 마지막에 실제로 도는 2D 실시간 대전 서버 한 벌을 끝까지 만듭니다. 국내 게임사 서버 팀에서 실제로 쓰는 용어와 구조를 기준으로 씁니다.

GAME 01

게임 서버의 종류와 구조 — 무엇을 만들 것인지부터

"게임 서버를 만들자"는 말은 너무 넓습니다. 방 하나에 8명이 들어가는 대전 게임과 한 세계에 수천 명이 돌아다니는 MMO 는 부품이 겹치는 게 거의 없습니다. 먼저 어떤 종류를 만드는지 정하고, 그다음 서버를 몇 개로 쪼갤지 정합니다.

서버를 역할별로 쪼개는 이유는 부하 특성이 완전히 다르기 때문입니다 — 게이트웨이는 연결 수, 게임 룸은 CPU.

GAME 02

틱 루프 — 아무도 부르지 않아도 돌아가는 심장

웹 서버는 요청이 없으면 아무 일도 하지 않습니다. 게임 서버는 반대입니다. 1초에 30~60번, 아무 입력이 없어도 세계를 한 칸씩 굴립니다. 이 루프의 정확도가 곧 게임의 체감 품질이 되므로, 처음부터 제대로 짜 두어야 합니다.

틱 예산은 33.3ms 가 아니라 그 절반으로 잡으세요 — 나머지는 GC 없는 언어에도 반드시 생기는 변동분입니다.

고정 틱 루프 — 이 40줄이 서버의 전부입니다

#include <chrono>
#include <thread>
using namespace std::chrono;

class GameLoop {
    // ★ steady_clock 을 씁니다. system_clock 은 NTP 보정으로 '뒤로 갈' 수 있습니다
    using Clock = steady_clock;

    static constexpr int      TICK_HZ  = 30;
    static constexpr nanoseconds DT     = nanoseconds(1'000'000'000 / TICK_HZ); // 33.33ms
    static constexpr int      MAX_CATCHUP = 5;   // 한 번에 따라잡을 최대 틱 수

    World       world_;
    std::atomic<bool> running_{true};
    std::uint64_t tick_ = 0;

public:
    void run() {
        auto next = Clock::now();            // 다음 틱이 시작돼야 할 '이상적인' 시각

        while (running_.load(std::memory_order_relaxed)) {
            auto now = Clock::now();

            int catchup = 0;
            while (now >= next && catchup < MAX_CATCHUP) {
                auto t0 = Clock::now();

                pump_network();                       // ① 들어온 패킷을 큐에서 꺼내 적용
                world_.update(1.0 / TICK_HZ);         // ② 세계를 dt 만큼 굴림
                broadcast_snapshot(tick_);            // ③ 결과를 뿌림

                auto used = duration_cast<microseconds>(Clock::now() - t0);
                stats_.record(used);                  // ④ 틱당 처리 시간 기록 ★ n12
                if (used > duration_cast<microseconds>(DT))
                    log_warn("tick {} overrun: {}us", tick_, used.count());

                ++tick_;
                next += DT;                           // ★ now 가 아니라 next 에 더합니다
                ++catchup;
            }

            if (catchup == MAX_CATCHUP) {             // 너무 밀렸으면 기준을 다시 잡음
                log_error("loop far behind, resync");
                next = Clock::now() + DT;
            }

            // 남는 시간은 자야 합니다 — 안 자면 코어 하나를 100% 태웁니다
            auto sleep_for = next - Clock::now();
            if (sleep_for > 1ms)  std::this_thread::sleep_for(sleep_for - 1ms);
            while (Clock::now() < next) std::this_thread::yield();  // 마지막 1ms 는 스핀
        }
    }
};
next += DT 가 핵심입니다 — next = now + DT 로 쓰면 매 틱마다 처리 시간만큼 오차가 누적되어 30틱이 27틱쯤으로 조용히 내려앉습니다. “이상적인 시각”을 기준으로 더해야 장시간 돌려도 틱 수가 정확합니다.
sleep_for 를 그대로 믿으면 안 됩니다 — 윈도우 기본 타이머 해상도는 약 15.6ms 라 1ms 를 재워 달라고 해도 15ms 를 잡니다. 그래서 마지막 1ms 는 스핀으로 채웁니다. 윈도우에서는 timeBeginPeriod(1) 또는 최신 API 인 SetProcessInformation 의 타이머 해상도 설정을 함께 씁니다.

한 단계 더 — 시뮬레이션 틱과 전송 틱을 분리합니다 🟡 중급

60틱 시뮬 · 20틱 전송

static constexpr int SIM_HZ  = 60;   // 판정 정확도를 위해 촘촘히
static constexpr int SEND_HZ = 20;   // 대역폭을 위해 드물게
static constexpr int SEND_EVERY = SIM_HZ / SEND_HZ;   // 3틱마다 한 번

void tick_once() {
    pump_network();
    world_.update(1.0 / SIM_HZ);

    if (tick_ % SEND_EVERY == 0)
        broadcast_snapshot(tick_);       // ★ 3틱에 한 번만 전송
}
왜 나누나 — 히트 판정은 촘촘할수록 정확하지만, 클라이언트는 어차피 화면을 보간해서 그립니다(n07). 대역폭은 정확히 전송 틱에 비례하므로, 60 → 20 으로 내리면 서버 트래픽 비용이 1/3 이 됩니다. 오버워치·발로란트류가 “틱레이트 128”을 말할 때도 전송 틱을 가리키는 경우가 많습니다.

한 프로세스에 방이 여러 개일 때

// 방마다 스레드를 하나씩? → 방 500개면 스레드 500개. 안 됩니다.
// 워커 스레드 N개가 방 목록을 나눠 갖습니다 (N = 코어 수)

struct RoomWorker {
    std::vector<std::unique_ptr<Room>> rooms;   // 이 워커 전용 — 락 필요 없음 ★
    void tick(double dt) {
        for (auto& r : rooms) {
            if (!r->alive()) continue;
            r->update(dt);          // 방끼리는 서로 안 건드립니다
        }
        std::erase_if(rooms, [](auto& r){ return !r->alive(); });
    }
};

// 방을 새로 만들 때는 가장 한가한 워커에 붙입니다
RoomWorker& pick_worker() {
    return *std::ranges::min_element(workers_, {},
        [](const auto& w){ return w.load_score(); });
}

struct TickStats {
    std::array<std::uint32_t, 8> bucket{};   // <1,2,4,8,16,33,66,그 이상 ms
    std::uint64_t total = 0, over = 0;

    void record(std::chrono::microseconds us) {
        double ms = us.count() / 1000.0;
        std::size_t i = ms < 1 ? 0 : ms < 2 ? 1 : ms < 4 ? 2 : ms < 8 ? 3
                      : ms < 16 ? 4 : ms < 33 ? 5 : ms < 66 ? 6 : 7;
        ++bucket[i]; ++total;
        if (ms > 33.3) ++over;               // 오버런 비율 ★ 가장 중요한 지표
    }
    double p99_estimate() const;             // 버킷 누적으로 근사
};
평균은 거짓말을 합니다 — 평균 5ms 여도 100틱 중 1번 80ms 가 나오면 플레이어는 그 순간 끊김으로 느낍니다. p99 와 오버런 비율만 대시보드에 띄워도 문제의 90%가 보입니다(n12에서 지표로 다시 다룹니다).
정리 — 틱 루프는 next += DT 로 이상 시각을 누적하고, 따라잡기에 상한을 두고, 남는 시간은 자야 합니다. 시뮬 틱과 전송 틱을 분리하면 정확도는 지키면서 대역폭만 줄일 수 있습니다. 틱 안에서는 절대 블로킹하지 않습니다 — 이 원칙 하나가 이후 모든 장의 전제입니다.
GAME 03

TCP 냐 UDP 냐 — 신뢰성을 직접 얹는 이유

TCP 는 “빠짐없이 순서대로” 를 보장합니다. 좋아 보이지만 실시간 게임에서는 그게 독이 됩니다. 패킷 하나가 늦으면 뒤에 도착한 최신 정보까지 전부 붙잡아 두기 때문입니다. 그래서 게임은 UDP 위에 필요한 만큼만 신뢰성을 얹습니다.

위치 정보는 다시 보내는 순간 이미 낡았습니다 — 재전송이 항상 이득이 아닌 이유입니다.

TCP 의 진짜 문제 — 머리 막힘(HOL blocking)

TCP 로 위치를 60Hz 로 보낸다고 합시다.

  보낸 순서 :  P100  P101  P102  P103  P104  P105
  P101 이 유실 →  재전송에 RTT(예: 80ms) 가 걸립니다

  그동안 P102~P105 는 이미 도착해 있지만
  커널 수신 버퍼에 갇혀 앱으로 올라오지 못합니다 ★
  "순서대로" 를 지켜야 하기 때문입니다

  결과 : 80ms 뒤에 P101~P105 가 한꺼번에 올라옵니다
        → 화면에서는 '멈췄다가 순간이동' 으로 보입니다

UDP + 최신값 우선이라면 :
  P101 은 그냥 버립니다. P102 가 도착한 순간 그걸 씁니다
  → 16ms 뒤 정상 진행. 한 프레임 튄 것으로 끝납니다
“TCP 는 느리다”는 말은 부정확합니다 — 대역폭·처리량은 오히려 TCP 가 좋습니다. 문제는 지연의 분포입니다. 손실이 1%만 있어도 TCP 는 가끔 RTT 만큼 통째로 멈추고, 게임에서는 그 “가끔”이 곧 렉으로 체감됩니다.

// 헤더 12바이트로 "내가 받은 최근 33개" 를 전부 알려 줍니다
struct RelHeader {
    std::uint16_t seq;        // 이 패킷의 번호
    std::uint16_t ack;        // 내가 받은 것 중 가장 최신 번호
    std::uint32_t ack_bits;   // ack-1 ~ ack-32 를 비트 1개씩 ★
    std::uint32_t sent_at_ms; // RTT 계산용
};

// 받았을 때 — 내 수신 기록을 갱신
void on_recv(std::uint16_t s) {
    if (seq_greater(s, recv_ack_)) {          // 더 최신이면 창을 민다
        std::uint16_t shift = s - recv_ack_;
        recv_bits_ = (shift >= 32) ? 0 : (recv_bits_ << shift) | (1u << (shift-1));
        recv_ack_  = s;
    } else {                                   // 늦게 도착한 옛 패킷
        std::uint16_t diff = recv_ack_ - s;
        if (diff <= 32) recv_bits_ |= (1u << (diff-1));
    }
}

// ★ 순환 비교 — 65535 다음이 0 이므로 그냥 < 로 비교하면 틀립니다
inline bool seq_greater(std::uint16_t a, std::uint16_t b) {
    return (a > b && a - b <= 32768) || (a < b && b - a > 32768);
}

보낸 쪽 — 확인 안 된 것만 다시

struct SentInfo { std::uint32_t at_ms; bool acked; std::vector<std::byte> body; };
std::array<SentInfo, 1024> sent_;          // seq % 1024 로 원형 저장

void on_ack(const RelHeader& h, std::uint32_t now_ms) {
    auto confirm = [&](std::uint16_t s) {
        auto& e = sent_[s % 1024];
        if (e.acked) return;
        e.acked = true;
        rtt_ = rtt_ * 0.9 + (now_ms - e.at_ms) * 0.1;   // 지수 이동 평균
    };
    confirm(h.ack);
    for (int i = 0; i < 32; ++i)
        if (h.ack_bits & (1u << i)) confirm(h.ack - (i + 1));
}

void update(std::uint32_t now_ms) {
    // RTT 의 1.5배가 지나도 확인이 없으면 유실로 간주하고 재전송
    const std::uint32_t timeout = static_cast<std::uint32_t>(rtt_ * 1.5) + 10;
    for (auto& e : sent_)
        if (!e.acked && e.body.size() && now_ms - e.at_ms > timeout)
            { resend(e); e.at_ms = now_ms; }
}
ack 는 따로 보내지 않습니다 — 어차피 매 틱 패킷이 오가므로 헤더에 얹어 보냅니다(piggyback). ack 전용 패킷을 만들면 트래픽이 두 배가 됩니다. 보낼 게 없을 때만 200ms 주기로 빈 keep-alive 를 보내 NAT 매핑을 유지합니다.

패킷 크기 — MTU 를 넘기면 조각납니다

이더넷 MTU 1500 바이트에서 실제로 쓸 수 있는 크기는

  1500 - IP 헤더 20 - UDP 헤더 8 = 1472 바이트
  VPN·PPPoE·모바일 터널을 감안하면 실무 안전선은 ★ 1200 바이트

이 선을 넘으면 IP 단편화가 일어납니다
  · 조각 중 하나만 잃어도 패킷 전체가 무효가 됩니다
  · 손실률 1% 짜리 회선에서 3조각 패킷의 손실률은 약 3%
  · 일부 방화벽·NAT 는 조각난 UDP 를 아예 버립니다

그래서 게임 패킷은 항상 1200 바이트 안에 넣습니다
  · 스냅샷이 크면 '중요한 것부터' 잘라 담고 나머지는 다음 틱에
  · 그래도 커야 하는 것(맵 데이터·리소스)은 TCP/HTTP 로 따로 받습니다
1200 바이트라는 숫자를 외워 두세요 — QUIC 표준이 초기 패킷에 요구하는 최소값도 이 근처(1200)입니다. 신뢰 UDP 라이브러리들도 대부분 기본 MTU 를 1200 안팎으로 잡습니다. 직접 만든다면 접속 시 MTU 탐색을 한 번 돌리는 것이 정석입니다.

class SendPacer {
    double budget_bytes_ = 0;
    double rate_bps_     = 256'000;   // 초당 32KB 에서 시작
public:
    void update(double dt, double loss_ratio) {
        // ★ 손실이 보이면 줄이고, 깨끗하면 천천히 늘립니다 (AIMD)
        if (loss_ratio > 0.05)      rate_bps_ *= 0.75;          // 곱셈 감소
        else if (loss_ratio < 0.01) rate_bps_ += 8'000 * dt;    // 덧셈 증가
        rate_bps_ = std::clamp(rate_bps_, 64'000.0, 4'000'000.0);
        budget_bytes_ = std::min(budget_bytes_ + rate_bps_ / 8 * dt, 4096.0);
    }
    bool allow(std::size_t n) {                 // 예산 안에서만 보냅니다
        if (budget_bytes_ < double(n)) return false;
        budget_bytes_ -= double(n); return true;
    }
};

//   ① 신뢰 채널(아이템·스킬)          → 절대 버리지 않음
//   ② 가까운 적의 위치                 → 우선

TCP 에는 “메시지”라는 개념이 없습니다. send 를 세 번 했다고 recv 가 세 번 나오지 않습니다. 신입 서버 개발자가 가장 많이 만드는 버그가 여기서 나옵니다. 길이를 앞에 붙이고, 다 모일 때까지 기다리는 것 — 이 규칙 하나가 프로토콜의 절반입니다.

한 번의 recv 로 0개, 1개, 혹은 3.5개의 메시지가 올 수 있습니다 — 파서는 항상 while 루프여야 합니다.

헤더와 파서 — 복붙해서 바로 쓰는 형태

#include <bit>        // std::byteswap (C++23), std::endian
#include <cstdint>
#include <span>
#include <vector>

// ── 헤더 4바이트 : 길이(본문만) + 메시지 id ──────────────────
#pragma pack(push, 1)
struct PacketHeader {
    std::uint16_t size;   // 본문 길이 (헤더 제외) — 최대 65535
    std::uint16_t id;     // 메시지 종류
};
#pragma pack(pop)
static_assert(sizeof(PacketHeader) == 4);

// ── 엔디안 : 네트워크는 빅엔디안이 관례입니다 ─────────────────
constexpr std::uint16_t hton16(std::uint16_t v) {
    if constexpr (std::endian::native == std::endian::little) return std::byteswap(v);
    else return v;
}
constexpr std::uint16_t ntoh16(std::uint16_t v) { return hton16(v); }

// ── 수신 버퍼 : 받은 것을 쌓고, 완성된 메시지만 꺼냅니다 ───────
class RecvBuffer {
    std::vector<std::byte> buf_;
    std::size_t            read_ = 0;   // 다음에 읽을 위치

public:
    void append(std::span<const std::byte> in) {
        buf_.insert(buf_.end(), in.begin(), in.end());
    }

    // 완성된 메시지가 있으면 꺼내 true. 없으면 false — ★ while 로 돌리세요
    bool next(PacketHeader& out_hdr, std::span<const std::byte>& out_body) {
        const std::size_t avail = buf_.size() - read_;
        if (avail < sizeof(PacketHeader)) return false;          // ① 헤더도 안 왔다

        PacketHeader h;
        std::memcpy(&h, buf_.data() + read_, sizeof h);
        h.size = ntoh16(h.size);
        h.id   = ntoh16(h.id);

        if (h.size > MAX_BODY) throw ProtocolError{"body too large"};   // ★ 반드시 상한
        if (avail < sizeof(PacketHeader) + h.size) return false;  // ② 본문이 덜 왔다

        out_hdr  = h;
        out_body = {buf_.data() + read_ + sizeof h, h.size};
        read_   += sizeof h + h.size;                             // ③ 소비
        return true;
    }

    void compact() {                       // 처리 후 앞부분을 버립니다
        if (read_ == 0) return;
        buf_.erase(buf_.begin(), buf_.begin() + read_);
        read_ = 0;
    }
    static constexpr std::uint16_t MAX_BODY = 8192;
};

// ── 사용 : 소켓에서 읽은 뒤 ────────────────────────────────
void on_bytes(Session& s, std::span<const std::byte> in) {
    s.rb.append(in);
    PacketHeader h; std::span<const std::byte> body;
    while (s.rb.next(h, body))        // ★ 한 번에 여러 개가 나올 수 있습니다
        dispatch(s, h.id, body);
    s.rb.compact();
}

// Windows. 실제로 도는 최소 형태입니다
struct IoCtx : OVERLAPPED {          // ★ OVERLAPPED 를 '상속' 하는 것이 관례
    enum class Op { Recv, Send } op;
    WSABUF   wsabuf;
    char     buf[8192];
    Session* sess;
};

HANDLE g_cp = CreateIoCompletionPort(INVALID_HANDLE_VALUE, nullptr, 0, 0);

void attach(SOCKET s, Session* sess) {
    CreateIoCompletionPort((HANDLE)s, g_cp, (ULONG_PTR)sess, 0);
    post_recv(sess);                 // 첫 수신 요청을 걸어 둡니다
}

void post_recv(Session* s) {
    auto* ctx = s->recv_ctx();
    ZeroMemory(static_cast<OVERLAPPED*>(ctx), sizeof(OVERLAPPED));
    ctx->op = IoCtx::Op::Recv;
    ctx->wsabuf = { sizeof ctx->buf, ctx->buf };
    DWORD flags = 0;
    int r = WSARecv(s->sock, &ctx->wsabuf, 1, nullptr, &flags, ctx, nullptr);
    if (r == SOCKET_ERROR && WSAGetLastError() != WSA_IO_PENDING)
        s->close();                  // 진짜 에러
}

void worker() {                      // 코어 수만큼 띄웁니다
    DWORD bytes; ULONG_PTR key; OVERLAPPED* ov;
    for (;;) {
        BOOL ok = GetQueuedCompletionStatus(g_cp, &bytes, &key, &ov, INFINITE);
        if (!ov) break;                            // 종료 신호(PostQueued…)
        auto* ctx  = static_cast<IoCtx*>(ov);
        auto* sess = reinterpret_cast<Session*>(key);

        if (!ok || bytes == 0) { sess->close(); continue; }   // ★ 0 = 정상 종료

        if (ctx->op == IoCtx::Op::Recv) {
            sess->on_bytes({reinterpret_cast<std::byte*>(ctx->buf), bytes});
            post_recv(sess);                        // ★ 다시 걸어야 계속 받습니다
        } else {
            sess->on_sent(bytes);
        }
    }
}
가장 흔한 IOCP 버그 두 가지 — ① post_recv 재등록을 잊어 첫 패킷만 받고 조용해지는 것, ② OVERLAPPED 를 스택에 두어 함수가 끝난 뒤 커널이 죽은 메모리에 쓰는 것. 비동기 I/O 의 버퍼와 컨텍스트는 완료 통지를 받을 때까지 반드시 살아 있어야 합니다.

// ★ enable_shared_from_this : 비동기 콜백이 끝날 때까지 객체를 살려 둡니다
class Session : public std::enable_shared_from_this<Session> {
    tcp::socket                 sock_;
    asio::strand<asio::any_io_executor> strand_;   // ★ 이 세션의 콜백 직렬화
    std::array<std::byte, 8192> rbuf_{};
    RecvBuffer                  parser_;
    std::deque<std::vector<std::byte>> wq_;        // 쓰기 대기 큐
    bool                        writing_ = false;

public:
    explicit Session(tcp::socket s)
        : sock_(std::move(s)), strand_(asio::make_strand(sock_.get_executor())) {}

    void start() {
        sock_.set_option(tcp::no_delay(true));     // ★ Nagle 끄기 — 게임에서는 필수
        do_read();
    }

    // 어느 스레드에서 불러도 안전합니다 (strand 로 넘김)
    void send(std::vector<std::byte> msg) {
        asio::post(strand_, [self = shared_from_this(), m = std::move(msg)]() mutable {
            self->wq_.push_back(std::move(m));
            if (!self->writing_) self->do_write();
        });
    }

private:
    void do_read() {
        auto self = shared_from_this();
        sock_.async_read_some(asio::buffer(rbuf_),
            asio::bind_executor(strand_, [self](auto ec, std::size_t n) {
                if (ec) { self->on_close(ec); return; }
                self->parser_.append({self->rbuf_.data(), n});
                PacketHeader h; std::span<const std::byte> body;
                while (self->parser_.next(h, body))
                    self->enqueue_to_room(h.id, body);   // ★ 여기서 게임 로직을 부르지 않습니다
                self->parser_.compact();
                self->do_read();                          // 다시 읽기
            }));
    }

    void do_write() {
        writing_ = true;
        auto self = shared_from_this();
        asio::async_write(sock_, asio::buffer(wq_.front()),
            asio::bind_executor(strand_, [self](auto ec, std::size_t) {
                if (ec) { self->on_close(ec); return; }
                self->wq_.pop_front();
                if (!self->wq_.empty()) self->do_write();
                else                    self->writing_ = false;
            }));
    }

    void on_close(boost::system::error_code ec) {
        if (closed_) return; closed_ = true;
        boost::system::error_code ign;
        sock_.shutdown(tcp::socket::shutdown_both, ign);
        room_->post_leave(id_);        // 방에 "나갔다" 를 알립니다
    }
    bool closed_ = false;
};

int main() {
    asio::io_context io;                        // 윈도우면 내부적으로 IOCP,
    tcp::acceptor acc(io, {tcp::v4(), 7777});   // 리눅스면 epoll/io_uring 을 씁니다

    std::function<void()> accept_one = [&] {
        acc.async_accept([&](auto ec, tcp::socket s) {
            if (!ec) std::make_shared<Session>(std::move(s))->start();
            accept_one();                        // 계속 받습니다
        });
    };
    accept_one();

    std::vector<std::jthread> pool;              // 코어 수만큼
    for (unsigned i = 1; i < std::thread::hardware_concurrency(); ++i)
        pool.emplace_back([&]{ io.run(); });
    io.run();
}

스레드 모델 — 락을 줄이는 가장 확실한 방법

멀티스레드 게임 로직은 “되긴 되는데 가끔 이상한” 버그의 온상입니다. 그래서 실무의 정답은 대개 스레드를 잘 쓰는 것이 아니라 공유를 없애서 락 자체를 지우는 것입니다.

게임 서버에서 가장 큰 성능 개선은 대개 락을 잘 쓰는 게 아니라 없애는 것입니다.

잡 큐 — 액터의 실제 구현

#include <functional>
#include <mutex>
#include <vector>

// 방 하나 = 액터 하나. 외부에서는 오직 post() 로만 접근합니다
class Room {
    std::mutex                            qmx_;      // ★ 큐에만 걸리는 짧은 락
    std::vector<std::function<void()>>    q_, swap_;
    WorldState                            state_;    // 락 없이 씁니다 ★

public:
    // 어느 스레드에서든 호출 가능 (I/O 스레드가 부릅니다)
    void post(std::function<void()> job) {
        std::lock_guard lk(qmx_);
        q_.push_back(std::move(job));
    }

    // 이 방을 소유한 워커 스레드에서만 호출됩니다
    void tick(double dt) {
        { std::lock_guard lk(qmx_); swap_.swap(q_); }   // ★ 통째로 훔쳐 옵니다
        for (auto& job : swap_) job();                  // 락 밖에서 실행
        swap_.clear();

        state_.step(dt);
        broadcast_snapshot();
    }
};

// I/O 스레드에서 패킷이 왔을 때 — 게임 로직을 직접 부르지 않습니다
void Session::enqueue_to_room(std::uint16_t id, std::span<const std::byte> body) {
    auto copy = std::vector<std::byte>(body.begin(), body.end());   // 소유권 이전
    room_->post([r = room_, pid = player_id_, id, b = std::move(copy)] {
        r->handle(pid, id, b);          // ★ 룸 스레드에서 안전하게 실행됩니다
    });
}
swap 트릭 — 큐를 통째로 바꿔치기하면 락을 잡는 시간이 포인터 교환 한 번으로 끝납니다. 잡 실행은 락 밖에서 하므로, 잡 안에서 다시 post 를 불러도 교착이 없습니다. 이 패턴 하나로 게임 서버 동시성의 8할이 해결됩니다.

// 100명 방에서 전원에게 전원을 보내면 초당 100×100×30 = 30만 건입니다
// 시야 안(예: 40m)의 대상만 보내면 보통 10분의 1 이하로 줄어듭니다

class Grid {                       // 셀 크기 = 시야 반경
    static constexpr float CELL = 40.f;
    std::unordered_map<std::uint64_t, std::vector<EntityId>> cells_;

    static std::uint64_t key(int cx, int cy) {
        return (std::uint64_t)(std::uint32_t)cx << 32 | (std::uint32_t)cy;
    }
public:
    void move(EntityId id, Vec2 from, Vec2 to) {
        auto a = key(int(from.x/CELL), int(from.y/CELL));
        auto b = key(int(to.x  /CELL), int(to.y  /CELL));
        if (a == b) return;                       // 같은 셀이면 할 일 없음
        std::erase(cells_[a], id);
        cells_[b].push_back(id);
    }
    // 내 셀 + 인접 8칸만 보면 됩니다 — 3×3 = 최대 9칸
    template <class F> void for_near(Vec2 p, F&& f) const {
        int cx = int(p.x/CELL), cy = int(p.y/CELL);
        for (int dy = -1; dy <= 1; ++dy)
          for (int dx = -1; dx <= 1; ++dx)
            if (auto it = cells_.find(key(cx+dx, cy+dy)); it != cells_.end())
                for (auto id : it->second) f(id);
    }
};

// 서버와 '완전히 같은' 이동 함수를 클라도 갖고 있어야 합니다 ★
// 공용 라이브러리로 빼서 서버·클라가 같은 .cpp 를 씁니다
Vec2 step_move(Vec2 pos, const Input& in, double dt, const Map& map);

struct Prediction {
    std::uint32_t         next_seq = 1;
    std::deque<Input>     pending;      // 아직 서버가 확인 안 한 입력들
    Vec2                  shown;        // 화면에 그리는 위치

    void on_local_input(Input in, const Map& map, double dt) {
        in.seq = next_seq++;
        net::send(in);                  // ① 서버로 보내고
        shown = step_move(shown, in, dt, map);   // ② 기다리지 않고 바로 움직임
        pending.push_back(in);          // ③ 나중에 다시 쓰려고 보관
    }

    void on_snapshot(Vec2 server_pos, std::uint32_t ack, const Map& map, double dt) {
        // ④ 서버가 처리한 것까지는 버립니다
        while (!pending.empty() && pending.front().seq <= ack) pending.pop_front();

        // ⑤ 서버 위치에서 시작해, 남은 입력을 다시 적용 (re-simulation)
        Vec2 p = server_pos;
        for (const auto& in : pending) p = step_move(p, in, dt, map);

        // ⑥ 예측이 맞았으면 p == shown 이라 아무 일도 안 일어납니다
        if (dist(p, shown) > 0.01f) {
            if (dist(p, shown) > 2.0f) shown = p;          // 크게 틀렸으면 즉시 점프
            else shown = lerp(shown, p, 0.25f);            // 작게 틀렸으면 부드럽게
        }
    }
};

보간(interpolation) — 남의 캐릭터는 과거를 그립니다

// 스냅샷은 20Hz(50ms 간격)로 옵니다. 화면은 60Hz 입니다
// 받은 즉시 그리면 초당 20번만 움직이는 뚝뚝 끊긴 화면이 됩니다

struct RemoteEntity {
    struct Sample { double t; Vec2 pos; float rot; };
    std::deque<Sample> hist;                 // 최근 1초치 보관
    static constexpr double DELAY = 0.10;    // ★ 100ms 뒤처져서 그립니다

    void on_snapshot(double server_t, Vec2 p, float r) {
        hist.push_back({server_t, p, r});
        while (hist.size() > 2 && hist[1].t < server_t - 1.0) hist.pop_front();
    }

    Vec2 render_pos(double now_t) const {
        const double target = now_t - DELAY;      // 과거 시점을 그립니다
        for (std::size_t i = 1; i < hist.size(); ++i) {
            if (hist[i].t >= target) {
                const auto& a = hist[i-1]; const auto& b = hist[i];
                double u = (target - a.t) / std::max(1e-6, b.t - a.t);
                return lerp(a.pos, b.pos, float(u));   // ★ 두 스냅샷 사이를 채움
            }
        }
        return hist.empty() ? Vec2{} : hist.back().pos;   // 데이터가 끊기면 마지막 값
    }
};
DELAY 는 “스냅샷 간격 × 2” 정도가 안전합니다(20Hz → 100ms). 이보다 짧으면 패킷이 하나만 늦어도 그릴 데이터가 없어 외삽(extrapolation) 으로 넘어가고, 외삽은 벽을 뚫고 미끄러지는 현상을 만듭니다. 내 캐릭터는 예측(미래), 남의 캐릭터는 보간(과거) — 이 비대칭이 넷코드의 핵심입니다.

    for (const auto& e : w.entities) {
        if (!cv.visible(e)) continue;               // ★ AoI 로 먼저 거릅니다
        const State* prev = cv.find(e.id);
        std::uint8_t mask = 0;
        if (!prev || prev->pos != e.pos) mask |= 1;
        if (!prev || prev->hp  != e.hp ) mask |= 2;
        if (!prev || prev->ani != e.ani) mask |= 4;
        if (mask == 0) continue;                    // 안 바뀌었으면 아예 생략
        out.u32(e.id); out.u8(mask);
        if (mask & 1) out.pos_q(e.pos);             // 양자화 ★
        if (mask & 2) out.u16(e.hp);
        if (mask & 4) out.u8(e.ani);
    }
}

struct Waiting { PlayerId id; int mmr; std::uint64_t since_ms; int party_size; };

// 대기 시간에 따라 넓어지는 밴드
int band_for(std::uint64_t waited_ms) {
    if (waited_ms <  5'000) return 50;
    if (waited_ms < 15'000) return 150;
    if (waited_ms < 30'000) return 250;
    return std::min(400 + int((waited_ms - 30'000) / 1000) * 20, 900);
}

void Matcher::tick() {                     // 0.5초마다 돕니다
    auto now = now_ms();
    auto pool = redis_.zrange_all("queue:solo");     // MMR 순으로 정렬돼 옵니다

    // 오래 기다린 사람부터 처리해야 공평합니다 ★
    std::ranges::sort(pool, {}, &Waiting::since_ms);

    for (auto& anchor : pool) {
        if (taken_.contains(anchor.id)) continue;
        const int band = band_for(now - anchor.since_ms);

        std::vector<PlayerId> team;
        for (auto& c : pool) {                        // 정렬돼 있어 근처만 보면 됩니다
            if (taken_.contains(c.id)) continue;
            if (std::abs(c.mmr - anchor.mmr) > band) continue;
            team.push_back(c.id);
            if (team.size() == TEAM_TOTAL) break;
        }
        if (team.size() < TEAM_TOTAL) continue;

        if (!redis_.atomic_take("queue:solo", team)) continue;   // ★ 원자적 확보
        auto srv = alloc_.pick_game_server();                    // 가장 한가한 서버
        auto room = srv.create_room(balance_teams(team));
        for (auto id : team) notify_match(id, srv.addr, room.token);
        for (auto id : team) taken_.insert(id);
    }
}

// 기대 승률 : 점수 차 400 이면 약 91% 승리 기대
double expected(double ra, double rb) {
    return 1.0 / (1.0 + std::pow(10.0, (rb - ra) / 400.0));
}

// K 값이 클수록 한 판의 영향이 큽니다
int k_factor(int games_played, int rating) {
    if (games_played < 10)  return 60;   // 배치 고사 — 빨리 제자리 찾게
    if (rating > 2200)      return 16;   // 고랭크는 천천히
    return 32;
}

void apply_result(Player& a, Player& b, double score_a /*1 승, 0.5 무, 0 패*/) {
    double ea = expected(a.mmr, b.mmr);
    int k = k_factor(a.games, a.mmr);
    int delta = int(std::lround(k * (score_a - ea)));
    a.mmr += delta;  b.mmr -= delta;      // 제로섬
    ++a.games; ++b.games;
}

// MySQL/PostgreSQL C 클라이언트는 기본이 '블로킹' 입니다.
// 그래서 게임 서버는 대개 전용 스레드 풀로 감쌉니다 (진짜 비동기 API 는 까다롭습니다)

class DbPool {
    struct Worker { std::jthread th; MYSQL* conn; };
    std::vector<Worker>                 workers_;
    moodycamel::BlockingConcurrentQueue<std::vector<SaveJob>> q_;

public:
    explicit DbPool(int n, const DbCfg& cfg) {
        for (int i = 0; i < n; ++i) {
            auto* c = mysql_init(nullptr);
            mysql_real_connect(c, cfg.host, cfg.user, cfg.pw, cfg.db, cfg.port, nullptr, 0);
            workers_.push_back({std::jthread{[this, c](std::stop_token st){ loop(c, st); }}, c});
        }
    }
    void post(std::vector<SaveJob> batch) { q_.enqueue(std::move(batch)); }

private:
    void loop(MYSQL* c, std::stop_token st) {
        std::vector<SaveJob> batch;
        while (!st.stop_requested()) {
            if (!q_.wait_dequeue_timed(batch, std::chrono::milliseconds(200))) continue;
            // ★ 한 트랜잭션에 묶어야 왕복이 1회로 끝납니다
            mysql_query(c, "START TRANSACTION");
            for (const auto& j : batch) write_one(c, j);
            mysql_query(c, "COMMIT");
        }
    }
};
배치가 성능의 전부입니다 — 개별 UPDATE 를 1000번 보내면 왕복 1000번이지만, 한 트랜잭션에 묶으면 왕복이 사실상 1번입니다. 실측으로 10~50배 차이가 납니다. INSERT ... ON DUPLICATE KEY UPDATE(MySQL) 또는 INSERT ... ON CONFLICT DO UPDATE(PostgreSQL) 로 여러 행을 한 문장에 넣으면 더 좋습니다.

// 로그인할 때 — 이 캐릭터를 이 서버가 소유한다고 선언
bool acquire_char_lock(Redis& r, PlayerId pid, std::string_view server_id) {
    // NX = 없을 때만 성공, PX = 60초 뒤 자동 해제(서버가 죽어도 풀립니다)
    return r.set("lock:char:" + std::to_string(pid), server_id,
                 Redis::NX, std::chrono::seconds(60));
}

// 살아 있는 동안 20초마다 갱신 (lease 연장)
void renew_char_lock(Redis& r, PlayerId pid, std::string_view server_id) {
    // ★ 내 것일 때만 연장 — Lua 로 원자 실행
    static constexpr char LUA[] =
      "if redis.call('GET', KEYS[1]) == ARGV[1] then "
      "  return redis.call('PEXPIRE', KEYS[1], ARGV[2]) else return 0 end";
    r.eval(LUA, {"lock:char:" + std::to_string(pid)}, {server_id, "60000"});
}

// 로그아웃 — 저장이 '끝난 뒤' 에 풉니다 ★ 순서가 중요합니다
void release_char(Redis& r, PlayerId pid, std::string_view server_id) {
    save_now_and_wait(pid);                       // 동기 저장
    r.eval(DEL_IF_MINE, {"lock:char:" + std::to_string(pid)}, {server_id});
}

bool Room::validate_move(Player& p, const Input& in, double dt) {
    // ① 입력 폭탄 — 초당 개수 제한
    if (++p.input_count_this_sec > limits_.max_inputs_per_sec) {
        flag(p, Cheat::InputFlood); return false;
    }
    // ② dt 조작 — 클라가 보낸 dt 를 믿지 않습니다 ★
    dt = std::clamp(dt, 0.0, 1.0 / 20.0);

    // ③ 속도 상한 — 텔레포트·스피드핵의 1차 방어선
    Vec2 want = step_move(p.pos, in, dt, map_);
    float moved = dist(want, p.pos);
    if (moved > limits_.max_speed * dt * 1.15f) {   // 15% 여유(부동소수·지연)
        // 즉시 밴이 아니라 '보정' 이 정답입니다 ★
        send_correction(p);                          // 서버 위치를 강제로 알림
        flag(p, Cheat::SpeedSuspect);                // 누적 카운트만 올림
        return false;
    }
    // ④ 지형 통과 — 벽 뚫기
    if (!map_.is_walkable(want) || map_.crosses_wall(p.pos, want)) {
        send_correction(p); return false;
    }
    p.pos = want;
    return true;
}

// 상호작용은 '거리 + 소유권 + 상태' 세 가지를 항상 봅니다
bool Room::validate_loot(Player& p, EntityId chest_id) {
    auto* c = world_.find_chest(chest_id);
    if (!c)                                   return false;   // 존재하나
    if (dist(p.pos, c->pos) > limits_.interact_range) return false;   // 가까운가
    if (c->opened)                            return false;   // 이미 열렸나
    if (c->owner && c->owner != p.id)         return false;   // 내 것인가
    return true;

// ── 메시지 종류별 토큰 버킷 ──────────────────────────────
struct TokenBucket {
    double tokens, rate, cap;
    bool take(double now, double n = 1) {
        tokens = std::min(cap, tokens + (now - last) * rate); last = now;
        if (tokens < n) return false;
        tokens -= n; return true;
    }
    double last = 0;
};

// 종류마다 다른 상한 — 채팅은 초당 2회, 입력은 90회

bool Session::allow(std::uint16_t id, double now) {
    if (!buckets_[id].take(now)) {
        if (++violations_ > 20) { close("rate limit"); }
        return false;
    }
    return true;
}

// ── 재생 공격(replay) 방어 ──────────────────────────────
// 공격자가 예전에 캡처한 '스킬 사용' 패킷을 그대로 다시 보내는 공격입니다
bool Session::check_nonce(std::uint32_t seq) {
    if (seq <= last_seq_ - 64) return false;         // 너무 오래된 것
    if (seq <= last_seq_ && (seen_bits_ >> (last_seq_ - seq)) & 1)
        return false;                                 // ★ 이미 본 번호
    if (seq > last_seq_) { seen_bits_ <<= (seq - last_seq_); last_seq_ = seq; }
    seen_bits_ |= 1ull << (last_seq_ - seq);
    return true;
}

    asio::steady_timer tick_;
    std::mt19937      rng_;
    std::uint32_t     seq_ = 0;

public:
    void start(std::string_view host, std::uint16_t port) {
        asio::async_connect(sock_, resolve(host, port), [this](auto ec, auto) {
            if (ec) { ++g_stats.connect_fail; return; }
            send_login();
            schedule_input();
        });
    }
private:
    void schedule_input() {
        tick_.expires_after(std::chrono::milliseconds(33));    // 30Hz 입력
        tick_.async_wait([this](auto ec) {
            if (ec) return;
            Input in{.seq = ++seq_,
                     .dx = jitter(), .dy = jitter(),          // 랜덤 워크
                     .buttons = (rng_() % 40 == 0) ? FIRE : 0};
            send_framed(sock_, encode(in));
            ++g_stats.sent;
            schedule_input();
        });
    }
};

#pragma once
#include "shared/sim.h"
#include "room/history.h"
#include <chrono>
#include <functional>
#include <memory>
#include <mutex>
#include <unordered_map>

struct PlayerSlot {
    PlayerId                 id{};
    std::weak_ptr<Session>   sess;
    Vec2                     pos{}, vel{};
    std::uint16_t            hp = 100;
    std::uint32_t            last_input_seq = 0;   // ★ ack_input 으로 돌려줄 값
    std::uint64_t            last_packet_ms = 0;
    ClientView               view;                 // 델타 기준 (n07)
    BehaviorProfile          prof;                 // 이상 탐지 (n11)
    std::uint32_t            dirty = 0;            // 저장 대상 (n09)
};

class Room : public std::enable_shared_from_this<Room> {
public:
    static constexpr int SIM_HZ    = 60;
    static constexpr int SEND_EVERY = 3;                     // 20Hz 전송
    static constexpr double DT     = 1.0 / SIM_HZ;

    explicit Room(std::string id, const Map& map) : id_(std::move(id)), map_(map) {}

    // 어느 스레드에서든 호출 가능 — I/O 스레드가 부릅니다
    void post(std::function<void()> job) {
        std::lock_guard lk(qmx_);
        q_.push_back(std::move(job));
    }

    // 이 방을 소유한 워커 스레드에서만 호출
    void tick() {
        drain_jobs();                                        // ① 입력 반영
        for (auto& [id, p] : players_) integrate(p);         // ② 이동
        resolve_combat();                                    // ③ 전투 판정
        hist_.snapshot(tick_, players_);                     // ④ 되감기용 기록
        if (tick_ % SEND_EVERY == 0) broadcast_delta();      // ⑤ 전송
        check_timeouts();                                    // ⑥ 끊김 정리
        flush_dirty();                                       // ⑦ 저장은 비동기로
        ++tick_;
    }

    bool alive() const { return !finished_ && !players_.empty(); }

private:
    void drain_jobs() {
        { std::lock_guard lk(qmx_); swap_.swap(q_); }
        for (auto& j : swap_) j();
        swap_.clear();
    }

    void integrate(PlayerSlot& p) {
        // 입력은 이미 on_input 에서 검증되어 p.vel 에 반영돼 있습니다
        Vec2 want = step_move(p.pos, p.vel, DT, map_);       // ★ shared/ 의 함수
        if (map_.is_walkable(want)) p.pos = want;
        p.dirty |= Dirty::Pos;
    }

public:
    // ── 입력 처리 (잡으로 들어옵니다) ─────────────────────
    void on_input(PlayerId who, const pk::Input& in) {
        auto it = players_.find(who);
        if (it == players_.end()) return;
        auto& p = it->second;
        p.last_packet_ms = now_ms();

        if (in.seq() <= p.last_input_seq) return;            // 재생·중복 무시 ★
        p.last_input_seq = in.seq();

        Vec2 dir{in.dx(), in.dy()};
        if (float l = len(dir); l > 1.0f) dir = dir / l;     // 대각선 가속 방지 ★
        p.vel = dir * MOVE_SPEED;                            // 속도는 서버가 정합니다
    }

    void on_fire(PlayerId who, std::uint32_t view_tick, Vec2 dir) {
        auto& p = players_.at(who);
        if (now_ms() - p.last_fire_ms < FIRE_COOLDOWN_MS) return;   // 쿨다운 ★
        p.last_fire_ms = now_ms();

        const std::uint32_t v = std::clamp(view_tick,
            tick_ > MAX_REWIND ? tick_ - MAX_REWIND : 0u, tick_);   // 되감기 상한
        if (const auto* f = hist_.at(v))
            if (auto hit = raycast(p.pos, normalize(dir), *f, WEAPON_RANGE))
                apply_damage(hit->target, WEAPON_DAMAGE, who);
    }

private:
    std::string                          id_;
    const Map&                           map_;
    std::unordered_map<PlayerId, PlayerSlot> players_;
    HitboxHistory                        hist_;
    std::uint32_t                        tick_ = 0;
    bool                                 finished_ = false;
    std::mutex                           qmx_;
    std::vector<std::function<void()>>   q_, swap_;
};
대각선 정규화를 빼먹는 실수가 굉장히 흔합니다 — dx=1, dy=1 을 그대로 쓰면 대각선 이동이 1.414배 빨라집니다. 클라가 이걸 알아채면 그대로 스피드핵이 됩니다. 서버가 방향을 정규화하고 속도는 서버 상수를 쓰는 것이 정답입니다.

main.cpp — 구동 전체

int main(int argc, char** argv) {
    install_crash_handler();                       // n12
    auto cfg = Config::load("config/server.json");
    spdlog::set_level(spdlog::level::info);

    asio::io_context io;
    RoomManager  rooms(cfg->max_rooms);
    Redis        redis(cfg->redis_url);
    DbPool       db(4, cfg->db);
    Metrics      metrics;

    Listener listener(io, cfg->port, [&](tcp::socket s) {
        std::make_shared<Session>(std::move(s), rooms, redis, metrics)->start();
    });
    listener.run();

    // ── 룸 워커 : 코어 수만큼. 각 워커가 방들을 고정 소유합니다 (n06) ──
    std::vector<std::jthread> room_workers;
    const unsigned nw = std::max(1u, std::thread::hardware_concurrency() / 2);
    for (unsigned i = 0; i < nw; ++i)
        room_workers.emplace_back([&, i](std::stop_token st) {
            auto next = std::chrono::steady_clock::now();
            const auto dt = std::chrono::nanoseconds(1'000'000'000 / Room::SIM_HZ);
            while (!st.stop_requested()) {
                auto t0 = std::chrono::steady_clock::now();
                rooms.tick_shard(i, nw);                   // 이 워커가 맡은 방만
                metrics.tick.record(elapsed_us(t0));
                next += dt;
                sleep_until_precise(next);                 // n02
            }
        });

    // ── I/O 스레드 ──────────────────────────────────────
    std::vector<std::jthread> io_threads;
    for (unsigned i = 1; i < std::thread::hardware_concurrency(); ++i)
        io_threads.emplace_back([&]{ io.run(); });

    // ── 드레인 종료 (n12) ───────────────────────────────
    asio::signal_set sig(io, SIGINT, SIGTERM);
    sig.async_wait([&](auto, int){ rooms.begin_drain(); });

    metrics.serve(io, cfg->metrics_port);          // /metrics
    io.run();
    return 0;
}
