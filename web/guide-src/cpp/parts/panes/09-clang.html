C 01

C 는 왜 아직도 여기 있나

1972년에 나온 언어가 2020년대에도 리눅스 커널 · 파이썬 인터프리터 · SQLite · 모든 운영체제의 바닥을 차지하고 있습니다. 낡아서 남아 있는 게 아니라 대체할 자리가 없어서 남아 있습니다.

C 가 지금도 쓰이는 네 자리

자리이유
운영체제 · 드라이버하드웨어 주소를 있는 그대로 다뤄야 합니다
언어 런타임파이썬 · 루비 · PHP 가 전부 C 로 구현돼 있습니다
임베디드 · 펌웨어램이 수십 KB 인 칩에서는 C 밖에 안 돕니다
언어 사이의 다리C ABI 가 모든 언어의 공용어입니다 — FFI 탭의 주제
이 탭을 읽어야 하는 실질적인 이유 — 다른 언어로 부를 라이브러리를 만들려면 결국 C 인터페이스를 설계하게 됩니다. 안은 C++ 로 쓰더라도 경계는 C 입니다.

C 와 C++ 는 얼마나 다른가

C 코드는 대부분 C++ 컴파일러로도 컴파일됩니다. 하지만 "C++ 는 C 의 상위 집합"이라는 말은 정확하지 않습니다 — void* 암묵 변환, 구조체 초기화, bool, new 같은 이름 등에서 실제로 어긋납니다.

더 중요한 차이는 문법이 아니라 사고방식입니다. C 에는 소멸자도, RAII 도, 템플릿도 없습니다. 모든 자원 관리를 사람이 직접 합니다. 그래서 규율이 필요하고, 그 규율이 무너진 자리에서 세상의 보안 취약점 절반이 나왔습니다.

int main() 와 int main(void) 는 C 에서 의미가 다릅니다. 앞의 것은 "인자 정보를 모른다"이고, 뒤의 것이 "인자가 없다"입니다. C++ 에서는 둘이 같아서 헷갈리기 쉽습니다.

C 는 기본 설정이 아무것도 안 알려 줍니다. 경고를 안 켜면 if (x = 1) 같은 오타가 조용히 컴파일됩니다. 경고 플래그는 선택이 아니라 필수입니다.
표준 버전 — 무엇을 고를까. 실무 기본값은 C11 또는 C17입니다(둘은 거의 같습니다). C99 는 오래된 임베디드 툴체인 때문에 아직 쓰이고, C23 은 true/false 내장, nullptr, typeof 같은 편한 것들이 들어왔지만 컴파일러 지원이 아직 고르지 않습니다.
C 02

정수 — 크기가 정해져 있지 않습니다

파이썬 정수는 무한대까지 커지고, 자바 int 는 항상 32비트입니다. C 의 int 는 "최소 16비트, 나머지는 구현에 따라"입니다. 이 한 문장에서 나오는 버그가 아주 많습니다.

표준이 보장하는 것은 최소 크기뿐

타입표준 보장보통(64비트 리눅스)
char1바이트1 · 부호는 구현 정의
short≥ 16비트2
int≥ 16비트4
long≥ 32비트8 (윈도우는 4)
long long≥ 64비트8
size_t크기 표현용8 · 부호 없음
long 은 리눅스에서 8, 윈도우에서 4바이트입니다. 플랫폼 사이를 오가는 구조체에 long 을 쓰면 그 자체가 버그입니다.

그래서 실무에서는 stdint.h

#include <stdint.h>
#include <inttypes.h>   // 출력 형식 매크로

int32_t  a = -5;         // 정확히 32비트, 부호 있음
uint64_t b = 1ULL << 40; // 정확히 64비트, 부호 없음
size_t   n = 100;        // 길이 · 인덱스는 항상 size_t

// 출력할 때도 타입에 맞는 형식을 써야 합니다
printf("%" PRId32 " %" PRIu64 " %zu\n", a, b, n);

// ❌ printf("%d", n);   // size_t 를 %d 로 → UB

파일 형식 · 네트워크 프로토콜 · 다른 언어와 주고받는 구조체에는 반드시 고정 크기 타입을 쓰세요.

부호 있는 오버플로는 UB, 부호 없는 것은 순환

❌ 무엇이 일어날지 알 수 없다
int x = INT_MAX;
x = x + 1;          // 부호 있는 오버플로 = 미정의 동작

// 컴파일러는 "오버플로는 일어나지 않는다"고 가정하고
// 최적화하므로, 아래 검사가 통째로 삭제될 수 있습니다
if (x + 1 < x) { /* 여기는 영영 실행되지 않을 수 있음 */ }
✅ 넘치기 전에 검사한다
#include <limits.h>
if (a > 0 && b > INT_MAX - a) { /* 넘칠 것이다 */ }
else                            { int c = a + b; }

// GCC · Clang 내장 함수를 쓰면 더 간단합니다
int c;
if (__builtin_add_overflow(a, b, &c)) { /* 넘침 처리 */ }

// 부호 없는 타입은 넘침이 UB 가 아니라 '2^n 으로 나눈 나머지'
unsigned u = UINT_MAX; u++;   // 정의된 동작: 0 이 됩니다
부호 있는 값과 없는 값을 비교하면 조용히 뒤집힙니다. int i = -1; size_t n = 3; if (i < n) 는 거짓입니다 — i 가 거대한 부호 없는 수로 변환되기 때문입니다. -Wsign-compare(-Wextra 에 포함)를 켜 두세요.

char 의 부호는 정해져 있지 않다

x86 에서는 부호 있음, ARM 에서는 부호 없음인 경우가 많습니다. 바이트를 다룰 때는 unsigned char 나 uint8_t 를 명시하세요.

정수 승격이 먼저 일어난다

uint8_t a=200, b=100; a+b 는 uint8_t 가 아니라 int 로 계산돼 300 이 됩니다. 다시 담을 때 잘리므로 중간 타입을 항상 의식해야 합니다.

나눗셈과 시프트

음수를 오른쪽으로 시프트하는 것은 구현 정의이고, 시프트 폭이 타입 비트 수 이상이면 UB 입니다. x >> 32 (32비트 int) 는 쓰면 안 됩니다.

C 03

배열과 포인터 — 같아 보이지만 다릅니다

"C 에서 배열은 포인터다"라는 말은 절반만 맞습니다. 배열은 배열이고, 대부분의 자리에서 포인터로 변할 뿐입니다. 이 '변한다'가 어디서 일어나는지 아는 것이 C 를 다루는 핵심입니다.

이 규칙 하나가 버퍼 오버플로가 C 에서 흔한 이유이기도 합니다 — 언어가 길이를 안 들고 다닙니다.

배열이 포인터로 변하지 않는 자리

int a[10];

sizeof(a);      // 40  — 여기서는 배열 그대로
&a;             // int(*)[10] — 배열 전체의 주소 (타입이 다릅니다!)
_Alignof(a);    // 정렬도 배열 기준

// 나머지는 전부 첫 원소의 주소로 변합니다
int* p = a;     // == &a[0]
f(a);           // f 는 int* 를 받습니다

// &a 와 a 는 값은 같지만 타입이 다릅니다
a + 1;          // 4바이트 앞
&a + 1;         // 40바이트 앞 (!)

포인터 산술의 단위는 '타입 크기'

int  a[5] = {10,20,30,40,50};
int* p = a;

*(p + 2);       // 30 — 2 는 '8바이트'가 아니라 '원소 2개'
p[2];           // 정확히 같은 뜻 (a[i] == *(a+i))
2[a];           // 놀랍게도 이것도 합법입니다 (쓰지 마세요)

// 두 포인터의 차이는 '원소 개수'
ptrdiff_t d = &a[4] - &a[1];    // 3

// ⚠ 배열 범위를 넘은 포인터 연산 자체가 UB 입니다
int* q = a + 5;   // 끝 바로 뒤까지는 합법 (역참조는 불가)
int* r = a + 6;   // ❌ UB

2차원 배열 — 진짜 2차원과 포인터 배열은 다릅니다

연속된 진짜 2차원

int m[3][4];            // 12개가 한 덩어리로 연속

m[1][2];                // == *(*(m+1)+2)
sizeof(m);              // 48
sizeof(m[0]);           // 16 (한 행)

// 함수로 넘길 때 열 수는 반드시 알려야 합니다
void f(int m[][4], int rows);
void g(int (*m)[4], int rows);   // 같은 뜻
메모리가 연속이라 캐시에 유리합니다. 크기를 컴파일 때 아는 경우 이쪽이 정답입니다.

포인터 배열 (흩어진 행)

int** m = malloc(3 * sizeof(int*));
for (int i = 0; i < 3; i++)
    m[i] = malloc(4 * sizeof(int));   // 행마다 따로 할당

m[1][2];                // 두 번 역참조 — 캐시 미스가 늘어납니다

// 해제도 역순으로 전부
for (int i = 0; i < 3; i++) free(m[i]);
free(m);
int** 와 int[3][4] 는 호환되지 않습니다. 서로 넘기면 컴파일은 경고만 내고 실행에서 죽습니다.
실무에서 가장 편한 절충 — 1차원 배열 하나를 잡고 idx = row * cols + col 로 직접 계산하는 방식입니다. 연속성도 지키고, 함수 인자로 넘기기도 쉽고, 해제도 한 번이면 끝납니다. 수치 계산 코드가 대부분 이 방식을 씁니다.
C 04

문자열 — 널 하나로 끝을 표시합니다

C 문자열은 타입이 아니라 약속입니다 — "'\0' 을 만날 때까지가 문자열이다". 길이를 들고 다니지 않는 이 설계에서 지난 50년 보안 취약점의 상당수가 나왔습니다.

그래서 C 에서 문자열을 다룰 때는 길이를 언제나 손에 쥐고 있어야 합니다.

쓰면 안 되는 함수와 대안

쓰지 말 것대신
getsC11 에서 표준에서 삭제됨 — fgets
strcpysnprintf(dst, cap, "%s", src)
strcat길이를 세어 snprintf 로 한 번에
sprintfsnprintf — 상한을 반드시 지정
strncpy널을 안 붙일 수 있습니다 — 이름과 달리 안전하지 않음
strncpy 는 안전한 strcpy 가 아닙니다. 원본이 상한보다 길면 널 종료를 붙이지 않고 끝냅니다. 그 뒤 strlen 을 부르면 버퍼 밖으로 달려 나갑니다.

실무에서 쓰는 패턴

#include <stdio.h>
#include <string.h>

char buf[64];

// ① 만들기 — snprintf 하나면 충분합니다
int n = snprintf(buf, sizeof buf, "%s-%d", name, id);
if (n < 0 || (size_t)n >= sizeof buf) {
    /* 잘렸습니다. n 은 '필요했던 길이'를 알려 줍니다 */
}

// ② 읽기 — fgets 는 개행까지 함께 담습니다
if (fgets(buf, sizeof buf, stdin)) {
    buf[strcspn(buf, "\n")] = '\0';   // 개행 제거 관용구
}

// ③ 비교 — == 는 주소 비교입니다!
if (strcmp(a, b) == 0) { /* 같다 */ }

문자열 리터럴은 읽기 전용입니다

❌ 리터럴을 고치려 하면 죽습니다
char* s = "hello";   // 읽기 전용 영역을 가리킴
s[0] = 'H';          // 💥 세그멘테이션 폴트 (UB)

// C++ 에서는 이 대입 자체가 컴파일 에러입니다
// C 에서는 경고만 나거나 아예 안 납니다
✅ 고칠 것은 배열로 복사해 둡니다
char s[] = "hello";  // 6바이트를 스택에 복사
s[0] = 'H';          // ✅ 괜찮습니다

// 고치지 않을 것은 const 를 붙여 의도를 밝힙니다
const char* msg = "hello";   // 컴파일러가 막아 줍니다

한글은 한 글자가 아닙니다

UTF-8 에서 한글 한 글자는 3바이트입니다. strlen("한글") 은 6 을 돌려줍니다. 바이트 수와 글자 수를 구분하세요 — 자르다가 깨지는 사고의 원인입니다.

POSIX · BSD 확장

strdup(복사본 할당) 은 POSIX, strlcpy/strlcat(항상 널 종료) 은 BSD·macOS 계열입니다. 이식성이 필요하면 snprintf 로 통일하세요.

길이를 들고 다니는 습관

큰 프로젝트는 대부분 { char* p; size_t len; } 같은 자체 문자열 구조체를 만들어 씁니다. 길이를 잃지 않는 것만으로 버그가 크게 줄어듭니다.

C 05

메모리 — malloc 과 그 다섯 가지 함정

C 에는 가비지 컬렉터도, 소멸자도, unique_ptr 도 없습니다. 내가 잡은 것은 내가 놓아야 하고, 놓은 뒤에는 다시 쳐다보지 말아야 합니다. 규칙은 두 줄이지만, 지키는 일이 어렵습니다.

기본 네 함수

#include <stdlib.h>

int* p = malloc(n * sizeof *p);   // 쓰레기 값으로 채워져 있음
if (!p) { /* 실패 처리 — 반드시 검사 */ }

int* q = calloc(n, sizeof *q);    // 0 으로 초기화 + 곱셈 넘침 검사

int* r = realloc(p, m * sizeof *p);
if (!r) { free(p); return -1; }   // ⚠ 실패해도 p 는 살아 있습니다
p = r;                            //   바로 대입하면 p 를 잃습니다

free(p);
p = NULL;                         // 해제 후 NULL — 습관으로 만드세요
sizeof *p 를 쓰세요. sizeof(int) 라고 쓰면 나중에 타입을 바꿀 때 여기를 같이 고쳐야 합니다. *p 로 쓰면 타입이 바뀌어도 자동으로 따라옵니다.

이중 해제같은 것을 두 번 free — 힙 구조가 깨집니다
버퍼 넘침잡은 크기 밖에 쓰기 — 옆 데이터가 조용히 바뀝니다
미초기화 읽기malloc 직후의 값을 그냥 씀 — 실행마다 결과가 달라집니다
다섯 개 전부 ASan 이 잡아 줍니다. 개발과 CI 에서 -fsanitize=address 를 켜는 것이 이 절의 결론입니다.
"크래시가 난 자리"와 "버그가 있는 자리"가 완전히 다른 것이 힙 버그의 특징입니다.

소유권을 코드로 표현하는 방법

함수 이름과 주석으로 규약을 밝힌다

/* 반환값의 소유권은 호출자에게 넘어갑니다.
   다 쓴 뒤 buffer_free() 로 해제하세요. */
Buffer* buffer_create(size_t cap);
void    buffer_free(Buffer* b);

/* 반환값은 내부 버퍼를 가리킵니다.
   해제하지 마세요. b 가 살아 있는 동안만 유효합니다. */
const char* buffer_data(const Buffer* b);

C 에는 소유권을 표현할 문법이 없습니다. 이름 규칙(create/free 짝)과 const 가 유일한 도구입니다.

에러 처리 — goto 가 정답인 드문 자리

int load(const char* path, Result* out) {
    FILE*  f   = NULL;
    char*  buf = NULL;
    int    rc  = -1;

    f = fopen(path, "rb");
    if (!f)   goto done;

    buf = malloc(SIZE);
    if (!buf) goto done;

    if (fread(buf, 1, SIZE, f) != SIZE) goto done;

    out->data = buf;  buf = NULL;   // 소유권을 넘겼으니 여기서 비웁니다
    rc = 0;

done:
    free(buf);                     // NULL 이면 아무 일도 안 합니다
    if (f) fclose(f);
    return rc;
}
C 에는 finally 도 소멸자도 없습니다. 정리 지점을 한 곳으로 모으는 goto 가 커널을 포함한 대형 C 코드베이스의 표준 관용구입니다.

malloc 반환값 캐스팅

C 에서는 (int*)malloc(...) 처럼 캐스팅하지 않는 것이 권장됩니다. 캐스팅이 stdlib.h 를 빠뜨린 실수를 가려 버리기 때문입니다. (C++ 에서는 반대로 캐스팅이 필수입니다.)

스택에 잡는 것이 더 낫다

크기가 작고 함수 안에서만 쓴다면 지역 배열이 훨씬 빠르고 안전합니다. 스택은 보통 1~8MB 이므로, 수 KB 까지는 고민하지 말고 스택에 두세요.

아레나 · 풀 할당

수명이 같은 객체가 많다면 큰 덩어리를 한 번 잡고 잘라 쓰다가 한 번에 버리는 방식이 빠르고 누수도 없습니다. 게임·컴파일러에서 널리 쓰는 기법입니다.

C 06

구조체 · 정렬과 패딩

구조체 크기는 필드 크기의 합이 아닙니다. CPU 가 좋아하는 위치에 맞추려고 컴파일러가 빈칸을 끼워 넣기 때문입니다. 파일 형식이나 네트워크 프로토콜을 구조체로 다루려면 이 규칙을 알아야 합니다.

멤버를 크기가 큰 것부터 선언하는 것만으로 메모리가 줄어듭니다 — 공짜 최적화입니다.

확인하는 법

#include <stddef.h>
#include <stdio.h>

struct A { char a; int n; char b; };

printf("%zu\n", sizeof(struct A));          // 12
printf("%zu\n", offsetof(struct A, n));     // 4  ← 빈칸 3 뒤
printf("%zu\n", _Alignof(struct A));        // 4

// 컴파일 때 못 박아 두는 방법 (C11)
_Static_assert(sizeof(struct A) == 12, "레이아웃이 바뀌었습니다");

_Static_assert 를 걸어 두면, 누군가 필드를 추가해 레이아웃을 바꿨을 때 빌드가 막아 줍니다. 파일 형식·프로토콜 구조체에는 꼭 넣으세요.

빈칸을 없애는 packed — 그리고 대가

// GCC · Clang
struct __attribute__((packed)) Header {
    uint8_t  type;
    uint32_t length;      // 1바이트 위치에서 시작 — 정렬이 깨집니다
};

// MSVC
#pragma pack(push, 1)
struct Header { uint8_t type; uint32_t length; };
#pragma pack(pop)
packed 는 마지막 수단입니다. 정렬되지 않은 접근은 x86 에서는 느려지기만 하지만 일부 ARM 에서는 크래시합니다. 파일에서 읽을 때는 바이트를 하나씩 읽어 조립하는 편이 이식성과 안전성 모두에서 낫습니다.

공용체와 비트필드

union — 같은 자리를 여러 타입으로

// 크기는 '가장 큰 멤버' 하나 — 동시에 하나만 유효합니다
typedef struct {
    enum { INT, STR, DBL } tag;    // 무엇이 들었는지 표시
    union { int i; char* s; double d; } v;
} Value;

Value x = { .tag = INT, .v.i = 42 };

switch (x.tag) {
    case INT: printf("%d\n", x.v.i); break;
    /* ... */
}
넣은 것과 다른 멤버를 읽는 것은 C 에서 허용되지만(타입 펀), C++ 에서는 UB 입니다. 태그를 같이 두는 습관이 안전합니다.

비트필드 — 플래그를 촘촘히

struct Flags {
    unsigned enabled  : 1;
    unsigned mode     : 3;   // 0~7
    unsigned reserved : 4;
};   // 1바이트 안에 들어갑니다

읽기 쉽지만 비트 배치 순서가 구현 정의입니다. 하드웨어 레지스터나 통신 프로토콜에는 직접 시프트와 마스크를 쓰는 편이 이식성이 높습니다.

구조체를 그대로 파일에 쓰거나 소켓으로 보내지 마세요. 패딩 · 엔디안 · 타입 크기가 기계마다 다릅니다. 필드마다 명시적으로 직렬화하는 코드를 쓰는 것이 결국 가장 빠른 길입니다.
C 07

함수 포인터 — C 가 다형성을 흉내 내는 법

C 에는 인터페이스도 가상 함수도 없습니다. 그 자리를 함수 포인터가 채웁니다. 리눅스 커널의 파일 시스템, qsort, 이벤트 콜백이 전부 이 하나로 돌아갑니다.

문법 — 읽는 순서만 익히면 됩니다

int add(int a, int b) { return a + b; }

// 이름부터 안쪽으로 읽습니다: f 는 → 포인터 → 함수 → int 반환
int (*f)(int, int) = add;      // &add 라고 써도 같습니다
int r = f(2, 3);               // (*f)(2,3) 과 동일

// typedef 로 감싸면 훨씬 읽힙니다
typedef int (*BinOp)(int, int);
BinOp ops[] = { add, sub, mul };
int r2 = ops[0](2, 3);

// 괄호를 빼면 뜻이 완전히 달라집니다
int* g(int, int);              // int* 를 반환하는 함수 (포인터 아님)

qsort — 표준 라이브러리의 예

#include <stdlib.h>

int cmp_int(const void* a, const void* b) {
    int x = *(const int*)a, y = *(const int*)b;
    return (x > y) - (x < y);      // 뺄셈은 오버플로 위험이 있습니다
}

int a[5] = {3,1,4,1,5};
qsort(a, 5, sizeof a[0], cmp_int);
return x - y; 로 쓰면 안 됩니다. 큰 값들에서 정수 오버플로가 나서 정렬이 조용히 틀어집니다. 위처럼 비교 결과의 차로 쓰세요.
C++ 의 virtual 은 컴파일러가 이 표를 대신 만들어 주는 것일 뿐입니다.

인터페이스 흉내 — 전체 모습

typedef struct Stream Stream;

typedef struct {
    ssize_t (*read )(Stream*, void*, size_t);
    ssize_t (*write)(Stream*, const void*, size_t);
    void    (*close)(Stream*);
} StreamOps;

struct Stream {
    const StreamOps* ops;   // 첫 필드에 두는 것이 관례
    /* 구현마다 다른 상태가 뒤에 옵니다 */
};

// 부르는 쪽은 구현을 전혀 모릅니다
ssize_t n = s->ops->read(s, buf, sizeof buf);

쓸 때 주의할 것

  • NULL 검사 — 표의 함수가 비어 있을 수 있습니다
  • 시그니처 불일치 — 잘못된 타입으로 부르면 UB. typedef 로 고정하세요
  • 수명 — 콜백에 넘긴 void* 가 콜백이 불릴 때까지 살아 있어야 합니다
  • C ABI 경계 — 다른 언어에서 넘어온 콜백은 호출 규약이 맞아야 합니다
  • 등록 해제 — 콜백을 등록했으면 해제하는 함수도 함께 제공하세요
C 08

파일 입출력과 에러 처리

C 의 에러 처리는 반환값과 errno 뿐입니다. 예외가 없으니 모든 호출의 반환값을 확인해야 하고, 확인하지 않은 한 줄이 나중에 사고가 됩니다.

텍스트 읽기 — 한 줄씩

#include <stdio.h>
#include <errno.h>
#include <string.h>

FILE* f = fopen("data.txt", "r");
if (!f) {
    fprintf(stderr, "열기 실패: %s\n", strerror(errno));
    return -1;
}

char line[256];
while (fgets(line, sizeof line, f)) {
    line[strcspn(line, "\n")] = '\0';
    /* 처리 */
}
if (ferror(f)) { /* 읽기 도중 오류 */ }

fclose(f);
feof(f) 를 루프 조건으로 쓰면 마지막 줄이 두 번 처리됩니다. feof 는 "읽기를 시도해서 실패한 뒤"에 참이 되기 때문입니다. 위처럼 읽기 함수의 반환값을 조건으로 쓰세요.

바이너리 읽기 — 통째로

FILE* f = fopen("blob.bin", "rb");   // ⚠ 윈도우에서 "b" 는 필수
if (!f) return -1;

fseek(f, 0, SEEK_END);
long size = ftell(f);                // 2GB 넘으면 부족합니다
fseek(f, 0, SEEK_SET);

unsigned char* buf = malloc((size_t)size);
size_t got = fread(buf, 1, (size_t)size, f);
if (got != (size_t)size) { /* 짧게 읽힘 */ }

fclose(f);
free(buf);

큰 파일에는 fseeko/ftello(POSIX) 또는 메모리 매핑(mmap·CreateFileMapping)을 씁니다.

규칙이유
errno 는 즉시 읽는다다음 라이브러리 호출이 덮어씁니다. 실패 직후에 저장하세요
성공 시 errno 는 의미 없다성공해도 값이 바뀔 수 있습니다 — 반환값으로 먼저 판단하세요
fclose 도 실패할 수 있다버퍼를 비우다 디스크가 꽉 차면 여기서 실패합니다. 쓰기 파일은 반환값을 보세요
바이너리는 "b" 모드윈도우에서 텍스트 모드는 \n 을 \r\n 으로 바꿉니다
stdout 은 줄 단위 버퍼파이프로 넘기면 블록 버퍼가 됩니다 — 크래시하면 로그가 통째로 사라집니다
에러는 stderr 로버퍼링이 없고, 리다이렉트로 분리할 수 있습니다

반환값 규약을 하나로

프로젝트 안에서 "0 성공 · 음수 에러" 처럼 한 가지로 통일하세요. 어떤 함수는 0 이 성공이고 어떤 함수는 0 이 실패면 호출부에서 반드시 헷갈립니다.

부분 읽기 · 부분 쓰기

read/write(POSIX)는 요청한 만큼 다 처리하지 않을 수 있습니다. 소켓과 파이프에서 특히 그렇습니다 — 루프로 감싸는 것이 기본입니다.

경로와 인코딩

윈도우에서 한글 경로는 fopen 으로 안 열릴 수 있습니다. _wfopen 을 쓰거나 UTF-8 매니페스트를 켜야 합니다 — 크로스 플랫폼 코드에서 자주 만나는 함정입니다.

C 09

전처리기 — 강력하고 위험합니다

#define 은 문법을 아는 도구가 아니라 텍스트 치환기입니다. 컴파일러가 보기 전에 소스를 갈아엎기 때문에, 잘 쓰면 유용하고 잘못 쓰면 디버거로도 안 보이는 버그를 만듭니다.

매크로가 무는 세 가지

// ① 괄호 누락
#define SQ(x) x * x
SQ(1 + 2)        // → 1 + 2 * 1 + 2  = 5  (9 가 아닙니다)
#define SQ(x) ((x) * (x))            // ✅ 전부 괄호로

// ② 인자를 두 번 평가
#define MAX(a,b) ((a) > (b) ? (a) : (b))
MAX(i++, j)      // i 가 두 번 증가할 수 있습니다

// ③ 여러 문장을 한 덩어리로
#define LOG(m) printf("%s", m); fflush(stdout)
if (x) LOG("hi");    // fflush 는 if 밖에서 항상 실행됩니다!

#define LOG(m) do { printf("%s", m); fflush(stdout); } while (0)
상수는 매크로 대신 enum 이나 static const 를 쓰세요. 타입이 있고, 디버거에 이름이 보이고, 스코프도 지켜집니다.

그래도 매크로가 필요한 자리

// 파일 · 줄 번호가 필요한 로깅 — 함수로는 불가능합니다
#define LOG_ERR(fmt, ...) \
    fprintf(stderr, "[%s:%d] " fmt "\n", __FILE__, __LINE__, __VA_ARGS__)

// 배열 길이 (배열에만 써야 합니다 — 포인터에 쓰면 틀립니다)
#define COUNT_OF(a) (sizeof(a) / sizeof((a)[0]))

// 조건부 컴파일
#ifdef NDEBUG
#  define DBG(...) ((void)0)
#else
#  define DBG(...) LOG_ERR(__VA_ARGS__)
#endif

// 인클루드 가드 — 모든 헤더의 첫 줄
#ifndef MYLIB_BUFFER_H
#define MYLIB_BUFFER_H
/* ... */
#endif

플랫폼 · 컴파일러 분기

자주 쓰는 미리 정의된 매크로

매크로참이 되는 곳
_WIN32윈도우 (64비트에서도 정의됩니다)
__linux__리눅스
__APPLE__macOS · iOS
__GNUC__GCC 와 Clang 둘 다
_MSC_VERMSVC — 값이 버전
__cplusplusC++ 컴파일러로 컴파일 중
__STDC_VERSION__C 표준 버전 (C17 은 201710L)

C++ 에서도 부를 수 있는 헤더 만들기

#ifndef MYLIB_H
#define MYLIB_H

#ifdef __cplusplus
extern "C" {
#endif

int mylib_add(int a, int b);
void mylib_free(char* p);

#ifdef __cplusplus
}
#endif

#endif  /* MYLIB_H */
C 라이브러리 헤더의 표준 형태입니다. 이 여섯 줄이 없으면 C++ 에서 포함할 때 이름 맹글링 때문에 링크가 실패합니다. (FFI 탭에서 자세히 다룹니다)
#pragma once 는 표준이 아닙니다 — 다만 GCC · Clang · MSVC 가 전부 지원해서 실무에서는 널리 쓰입니다. 심볼릭 링크나 같은 파일이 두 경로로 보이는 환경에서 드물게 오작동하므로, 배포용 공개 헤더에는 전통적인 인클루드 가드를 권합니다.
C 10

여러 파일로 나누기 · 빌드

파일이 두 개가 되는 순간 선언과 정의, 내부와 외부를 구분해야 합니다. C 에는 모듈이 없어서 헤더와 링커의 규칙이 그 역할을 대신합니다.

C 의 "모듈"은 결국 헤더 + static + 이름 접두사 세 가지로 흉내 내는 것입니다.

전역 변수를 여러 파일에서 쓰기

/* config.h — 선언만 */
extern int g_verbose;          // "어딘가에 있다"

/* config.c — 정의는 딱 한 번 */
int g_verbose = 0;

/* main.c */
#include "config.h"
int main(void) { g_verbose = 1; }
헤더에 int g_verbose; 라고 쓰면 포함하는 파일마다 정의가 생겨 multiple definition 이 납니다. (일부 컴파일러는 관대하게 넘어가지만 표준은 아닙니다)

가장 단순한 Makefile

CC      = gcc
CFLAGS  = -std=c17 -Wall -Wextra -g -O2
OBJS    = main.o buffer.o config.o

app: $(OBJS)
	$(CC) $(CFLAGS) -o $@ $(OBJS)

%.o: %.c
	$(CC) $(CFLAGS) -c $< -o $@

clean:
	rm -f $(OBJS) app

들여쓰기는 반드시 탭이어야 합니다 — 스페이스를 쓰면 "missing separator" 에러가 납니다. Make 의 대표적인 첫 관문입니다.

헤더 의존성 — 안 잡으면 반드시 물립니다

# 헤더를 고쳤는데 다시 빌드가 안 되는 문제를 막습니다
CFLAGS += -MMD -MP
-include $(OBJS:.o=.d)

이 두 줄이 없으면 헤더를 고쳐도 .o 가 그대로 남아 "고쳤는데 왜 안 바뀌지"가 반복됩니다. 실무에서는 이런 것을 알아서 처리하는 CMake 를 쓰는 편이 낫습니다(빌드 탭 참고).

공개 API 를 설계하는 규칙

미정의 동작 — C 를 위험하게 만드는 것

UB 는 "이상한 값이 나온다"가 아니라 "표준이 아무 약속도 하지 않는다"입니다. 컴파일러는 UB 가 절대 일어나지 않는다고 가정하고 최적화합니다 — 그래서 내가 쓴 검사 코드가 통째로 사라지는 일이 벌어집니다.

"내 컴퓨터에서는 잘 돌던데"가 UB 에서는 아무 근거가 되지 않습니다.

나머지 두 가지 — 덜 알려졌지만 자주 밟습니다

// ⑤ 엄격한 앨리어싱 — 다른 타입 포인터로 같은 메모리 읽기
float f = 1.0f;
int   i = *(int*)&f;          // ❌ UB (-O2 에서 이상해집니다)

uint32_t bits;
memcpy(&bits, &f, sizeof bits);   // ✅ memcpy 는 항상 안전합니다

// ⑥ 한 식 안에서 같은 변수를 두 번 바꾸기
i = i++ + 1;                  // ❌ UB
arr[i] = i++;                 // ❌ UB
printf("%d %d", i++, i++);    // ❌ 인자 평가 순서도 정해져 있지 않습니다

memcpy 는 최적화 단계에서 대개 사라집니다. "느릴 것 같아서" 포인터 캐스팅을 쓸 이유가 없습니다.

#include <stdlib.h>     // malloc, strtol, qsort
#include <string.h>     // strlen, memcpy
#include <ctype.h>      // isspace
#include <math.h>       // sqrt   (링크에 -lm)
#include <time.h>       // clock
#include <errno.h>      // errno
#include <limits.h>     // INT_MAX
#include <stdint.h>     // int64_t
#include <stdbool.h>    // bool, true, false

static int cmp_int(const void *a, const void *b) {
    int x = *(const int *)a, y = *(const int *)b;
    return (x > y) - (x < y);      // 뺄셈은 넘침 위험 — 이 관용구가 안전
}

int main(void) {
    // ① 문자열 → 수 : 에러를 확인할 수 있는 방법
    errno = 0;
    char *end;
    long v = strtol("  42abc", &end, 10);
    printf("v=%ld, 남은 문자='%s', errno=%d\n", v, end, errno);

    // ② 정렬
    int a[] = {5, 2, 9, 1};
    qsort(a, 4, sizeof a[0], cmp_int);
    for (int i = 0; i < 4; i++) printf("%d ", a[i]);
    putchar('\n');

    // ③ 시간 재기 (CPU 시간)
    clock_t t0 = clock();
    double s = 0;
    for (int i = 1; i < 5000000; i++) s += sqrt((double)i);
    printf("합=%.2f, %.3f초\n", s, (double)(clock() - t0) / CLOCKS_PER_SEC);

    printf("INT_MAX=%d, int64 최대=%lld\n", INT_MAX, (long long)INT64_MAX);
    return 0;
}

표준에 없는 것들 — C 표준 라이브러리에는 네트워크·스레드 풀·정규식·JSON·디렉터리 순회·동적 배열이 없습니다. C11 의 <threads.h> 조차 선택 기능이라 MSVC 는 오랫동안 지원하지 않았습니다. 그래서 실무 C 는 POSIX(리눅스·맥) + Win32(윈도우) + 외부 라이브러리를 섞어 씁니다 — c17 · c18 · c26 에서 그 지형을 차례로 봅니다.
정리 — C 표준 라이브러리는 아홉 묶음이면 거의 다 커버됩니다. stdio(입출력) · stdlib(메모리·변환) · string(메모리 복사) 셋이 8할이고, atoi 대신 strtol, sprintf 대신 snprintf, strcpy 대신 snprintf 이 세 가지 교체만 몸에 붙여도 C 에서 나는 사고의 절반이 사라집니다.
C 14

동적 배열 · 연결 리스트를 직접 만듭니다

파이썬의 list, C++ 의 std::vector 에 해당하는 것이 C 에는 없습니다. 그래서 C 프로젝트는 거의 예외 없이 자기 동적 배열을 하나 가지고 있습니다. 직접 만들어 보면 “왜 vector 는 push 가 평균 O(1) 인가”, “왜 포인터를 보관하면 위험한가”가 한 번에 이해됩니다. 여기서 만든 코드는 그대로 복사해 쓸 수 있는 수준으로 씁니다.

배열은 커질 때 통째로 옮겨 다니고, 리스트는 영영 제자리입니다 — 이 한 줄이 둘의 모든 차이를 만듭니다.

동적 배열 — 복붙해서 바로 쓰는 전체 코드

// vec.h  — int 전용 동적 배열 (제네릭은 아래에서)
#ifndef VEC_H
#define VEC_H
#include <stddef.h>

typedef struct {
    int   *data;     // 힙에 있는 연속 버퍼
    size_t len;      // 지금 들어 있는 개수
    size_t cap;      // 버퍼가 담을 수 있는 개수
} Vec;

void vec_init(Vec *v);
int  vec_push(Vec *v, int value);          // 0 성공 / -1 메모리 부족
int  vec_get(const Vec *v, size_t i);
void vec_free(Vec *v);
#endif
// vec.c
#include "vec.h"
#include <stdlib.h>
#include <string.h>

void vec_init(Vec *v) { v->data = NULL; v->len = 0; v->cap = 0; }

static int vec_grow(Vec *v, size_t need) {
    if (need <= v->cap) return 0;

    size_t cap = v->cap ? v->cap * 2 : 8;   // ★ 2배 성장 — 평균 O(1) 의 이유
    while (cap < need) cap *= 2;

    // 곱셈이 넘치면 malloc 이 '작은' 크기를 성공시켜 버립니다 — 반드시 검사
    if (cap > (size_t)-1 / sizeof(int)) return -1;

    int *p = realloc(v->data, cap * sizeof(int));
    if (!p) return -1;        // ★ 실패해도 v->data 는 그대로 살아 있습니다
    v->data = p;
    v->cap  = cap;
    return 0;
}

int vec_push(Vec *v, int value) {
    if (vec_grow(v, v->len + 1) != 0) return -1;
    v->data[v->len++] = value;
    return 0;
}

int vec_get(const Vec *v, size_t i) {
    return v->data[i];        // 범위 검사는 호출자 책임 — C 의 기본 태도
}

void vec_free(Vec *v) {
    free(v->data);
    v->data = NULL; v->len = v->cap = 0;   // ★ dangling 방지
}
절대 하면 안 되는 realloc — v->data = realloc(v->data, n) 처럼 같은 변수에 바로 대입하면, 실패해서 NULL 이 돌아왔을 때 원래 버퍼의 주소를 잃어버려 통째로 샙니다. 위 코드처럼 임시 포인터에 받고 검사한 뒤에 대입하세요. 이건 C 코드 리뷰에서 가장 자주 지적되는 항목입니다.

}

static int gvec_push(GVec *v, const void *item) {
    if (v->len == v->cap) {
        size_t cap = v->cap ? v->cap * 2 : 8;
        void *p = realloc(v->data, cap * v->esz);
        if (!p) return -1;
        v->data = p; v->cap = cap;

    // 바이트 단위로 계산해야 하므로 char* 로 캐스트합니다
    memcpy((char *)v->data + v->len * v->esz, item, v->esz);
    v->len++;
    return 0;
}

단일 연결 리스트 — 전체 코드와 흔한 실수

typedef struct Node {
    int          value;
    struct Node *next;      // ★ 자기 타입을 가리키려면 struct 태그가 필요
} Node;

typedef struct { Node *head; size_t len; } List;

void list_init(List *l) { l->head = NULL; l->len = 0; }

// 맨 앞에 넣기 — O(1)
int list_push_front(List *l, int v) {
    Node *n = malloc(sizeof *n);       // ★ sizeof(Node) 대신 sizeof *n
    if (!n) return -1;
    n->value = v;
    n->next  = l->head;
    l->head  = n;
    l->len++;
    return 0;
}

// 전부 해제 — next 를 먼저 저장해 두는 것이 핵심
void list_free(List *l) {
    Node *cur = l->head;
    while (cur) {
        Node *nx = cur->next;   // ★ free 뒤에는 cur->next 를 못 읽습니다
        free(cur);
        cur = nx;
    }
    l->head = NULL; l->len = 0;
}
// 값으로 찾아 지우기 — 이중 포인터 관용구 ★
// head 를 지우는 경우와 중간을 지우는 경우가
// 하나의 코드로 합쳐집니다
int list_remove(List *l, int v) {
    Node **pp = &l->head;          // '나를 가리키는 포인터'의 주소
    while (*pp) {
        Node *cur = *pp;
        if (cur->value == v) {
            *pp = cur->next;       // 앞사람의 next 를 바로 고침
            free(cur);
            l->len--;
            return 1;
        }
        pp = &cur->next;
    }
    return 0;
}

// 순회
for (Node *p = l.head; p; p = p->next)
    printf("%d ", p->value);

// 뒤집기 — 면접 단골
Node *prev = NULL, *cur = l.head;
while (cur) {
    Node *nx = cur->next;
    cur->next = prev;
    prev = cur;
    cur  = nx;
}
l.head = prev;
이중 포인터(Node **)가 어렵게 느껴진다면 — “다음 노드”가 아니라 “그 노드를 가리키고 있는 칸 자체”를 들고 다닌다고 생각하세요. 그 칸이 list->head 일 수도 있고 어떤 노드의 next 일 수도 있는데, 고쳐야 할 대상은 언제나 그 칸이기 때문에 특수 케이스가 사라집니다. 리눅스 커널 코드에 이 관용구가 도처에 나옵니다.
정리 — C 에는 vector 가 없으니 동적 배열 하나는 직접 갖고 시작합니다. 핵심은 2배 성장(평균 O(1))과 realloc 을 임시 포인터로 받기, 그리고 재할당하면 원소 주소가 바뀐다는 사실입니다. 연결 리스트는 “중간 삽입이 잦거나 주소가 고정돼야 할 때”만 꺼내면 되고, 그때는 이중 포인터 관용구가 코드를 절반으로 줄여 줍니다.

해시 테이블과 정렬 · 탐색 — 딕셔너리도 직접 만듭니다

파이썬의 dict 도 C 에는 없습니다. 다행히 해시 테이블은 100줄이면 만들 수 있고, 정렬과 이진 탐색은 표준 qsort·bsearch 가 이미 줍니다. 이 절에서는 오픈 어드레싱 해시 테이블 전체 코드와, 비교 함수를 넘기는 C 특유의 정렬 방식을 봅니다.

충돌은 피하는 게 아니라 다루는 것입니다 — 옆 칸으로 미는 방식이 가장 단순하고 캐시에 가장 좋습니다.

문자열 → 값 해시 테이블 — 전체 코드

#include <stdint.h>
#include <stdlib.h>
#include <string.h>

// FNV-1a — 짧고 빠르고 분포가 괜찮습니다
static uint64_t fnv1a(const char *s) {
    uint64_t h = 1469598103934665603ULL;   // offset basis
    while (*s) {
        h ^= (unsigned char)*s++;
        h *= 1099511628211ULL;             // FNV prime
    }
    return h;
}

typedef struct {
    char *key;      // NULL = 빈 칸, TOMB = 삭제됨
    int   val;
} Slot;

typedef struct {
    Slot  *slots;
    size_t cap;     // 항상 2의 거듭제곱
    size_t used;    // 살아 있는 항목 수
} Map;

static char TOMB_MARK;                    // 주소만 쓰는 묘비 표식
#define TOMB (&TOMB_MARK)

int map_init(Map *m, size_t cap) {
    m->slots = calloc(cap, sizeof(Slot)); // 전부 NULL 로
    if (!m->slots) return -1;
    m->cap = cap; m->used = 0;
    return 0;
}
static int map_grow(Map *m);   // 아래에 정의

int map_put(Map *m, const char *key, int val) {
    if ((m->used + 1) * 10 >= m->cap * 7)  // 적재율 0.7
        if (map_grow(m) != 0) return -1;

    size_t i = fnv1a(key) & (m->cap - 1);  // ★ % 대신 비트 AND (2의 거듭제곱)
    size_t first_tomb = (size_t)-1;

    for (;;) {
        Slot *s = &m->slots[i];
        if (s->key == NULL) {              // 빈 칸 = 없다는 뜻
            size_t at = (first_tomb != (size_t)-1) ? first_tomb : i;
            char *dup = strdup(key);
            if (!dup) return -1;
            m->slots[at].key = dup;
            m->slots[at].val = val;
            m->used++;
            return 0;
        }
        if (s->key == TOMB) {
            if (first_tomb == (size_t)-1) first_tomb = i;
        } else if (strcmp(s->key, key) == 0) {
            s->val = val;                  // 덮어쓰기
            return 0;
        }
        i = (i + 1) & (m->cap - 1);        // 옆 칸으로
    }
}

int *map_get(Map *m, const char *key) {
    size_t i = fnv1a(key) & (m->cap - 1);
    for (;;) {
        Slot *s = &m->slots[i];
        if (s->key == NULL) return NULL;    // 빈 칸 = 없음
        if (s->key != TOMB && strcmp(s->key, key) == 0)
            return &s->val;
        i = (i + 1) & (m->cap - 1);
    }
}
int map_del(Map *m, const char *key) {
    size_t i = fnv1a(key) & (m->cap - 1);
    for (;;) {
        Slot *s = &m->slots[i];
        if (s->key == NULL) return 0;                       // 없음
        if (s->key != TOMB && strcmp(s->key, key) == 0) {
            free(s->key);
            s->key = TOMB;                                  // ★ NULL 이 아니라 묘비
            m->used--;
            return 1;
        }
        i = (i + 1) & (m->cap - 1);
    }
}

static int map_grow(Map *m) {
    Map bigger;
    if (map_init(&bigger, m->cap * 2) != 0) return -1;
    for (size_t i = 0; i < m->cap; i++) {
        Slot *s = &m->slots[i];
        if (s->key && s->key != TOMB) {
            map_put(&bigger, s->key, s->val);   // 해시가 같아도 슬롯 번호는 달라집니다
            free(s->key);
        }
    }
    free(m->slots);
    *m = bigger;
    return 0;
}

// 사용
Map m; map_init(&m, 16);
map_put(&m, "apple", 3);
map_put(&m, "grape", 7);
int *p = map_get(&m, "grape");
if (p) printf("grape=%d\n", *p);
묘비를 빠뜨리면 생기는 버그 — apple 을 지우고 NULL 로 만들면, 4번에 밀려 있던 grape 를 찾을 때 3번이 빈 칸이라 즉시 “없음”으로 끝나 버립니다. 데이터가 있는데도 못 찾는, 재현이 어려운 종류의 버그입니다. 묘비가 너무 쌓이면 used 가 그대로여도 rehash 로 청소해야 합니다.

표준이 주는 것 — qsort 와 bsearch 🟢 기초

비교 함수를 넘기는 방식

#include <stdlib.h>

typedef struct { char name[32]; int age; } Person;

// 인자는 항상 const void* 두 개입니다
static int by_age(const void *a, const void *b) {
    const Person *x = a, *y = b;
    // ★ return x->age - y->age;  ← 넘침 가능. 쓰지 마세요
    return (x->age > y->age) - (x->age < y->age);
}

static int by_name(const void *a, const void *b) {
    return strcmp(((const Person *)a)->name,
                  ((const Person *)b)->name);
}

Person ps[] = {{"kim",31},{"lee",24},{"park",45}};
size_t n = sizeof ps / sizeof ps[0];

}

void parse_line(char *line) {
    // ① 끝의 개행 제거 — fgets 는 '\n' 을 남깁니다
    line[strcspn(line, "\r\n")] = '\0';   // ★ 관용구. 개행이 없어도 안전

    // ② strtok_r — 상태를 saveptr 에 두므로 스레드 안전
    char *save = NULL;
    char *name = strtok_r(line, ",", &save);
    char *ages = strtok_r(NULL, ",", &save);   // ★ 두 번째부터는 NULL
    char *city = strtok_r(NULL, ",", &save);
    if (!name || !ages || !city) {            // 필드가 모자라면
        fprintf(stderr, "형식 오류\n");
        return;

    char *end;

        fprintf(stderr, "나이가 숫자가 아닙니다: %s\n", ages);
        return;
    }
    printf("%s / %ld / %s\n", name, age, city);
}

#include <stdarg.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

typedef struct { char *p; size_t len, cap; } Str;

static void str_init(Str *s) { s->p = NULL; s->len = s->cap = 0; }

static int str_reserve(Str *s, size_t need) {
    if (need + 1 <= s->cap) return 0;        // +1 은 널 자리
    size_t cap = s->cap ? s->cap : 32;
    while (cap < need + 1) cap *= 2;
    char *q = realloc(s->p, cap);
    if (!q) return -1;
    s->p = q; s->cap = cap;
    return 0;
}

int str_append(Str *s, const char *t) {
    size_t n = strlen(t);
    if (str_reserve(s, s->len + n) != 0) return -1;
    memcpy(s->p + s->len, t, n + 1);          // 널까지 복사
    s->len += n;
    return 0;
}

void str_free(Str *s) { free(s->p); str_init(s); }
// 서식 붙이기 — vsnprintf 로 필요 길이를 먼저 잽니다 ★
int str_appendf(Str *s, const char *fmt, ...) {
    va_list ap, ap2;
    va_start(ap, fmt);
    va_copy(ap2, ap);                       // ★ 두 번 쓰려면 복사 필수
    int need = vsnprintf(NULL, 0, fmt, ap); // 길이만 계산
    va_end(ap);
    if (need < 0) { va_end(ap2); return -1; }

    if (str_reserve(s, s->len + (size_t)need) != 0) {
        va_end(ap2); return -1;
    }
    vsnprintf(s->p + s->len, (size_t)need + 1, fmt, ap2);
    va_end(ap2);
    s->len += (size_t)need;
    return 0;
}

// 사용

str_append(&out, "결과: ");
for (int i = 0; i < 3; i++)
    str_appendf(&out, "[%d:%s] ", i, i % 2 ? "홀" : "짝");

#include <stddef.h>
#include <stdbool.h>

// 뒤따르는 바이트는 상위 두 비트가 10 입니다 (0x80~0xBF)
static bool is_cont(unsigned char c) { return (c & 0xC0) == 0x80; }

// 글자 수 = 뒤따르지 않는 바이트의 개수
size_t utf8_len(const char *s) {
    size_t n = 0;
    for (const unsigned char *p = (const unsigned char *)s; *p; p++)
        if (!is_cont(*p)) n++;
    return n;
}

// 글자 단위로 안전하게 자르기 — 최대 max 바이트 안에서
// 글자 중간이 잘리지 않는 위치를 돌려줍니다
size_t utf8_trunc(const char *s, size_t max) {
    size_t n = strlen(s);
    if (n <= max) return n;
    size_t cut = max;
    while (cut > 0 && is_cont((unsigned char)s[cut])) cut--;
    return cut;
}

// 코드포인트 하나를 읽고 다음 위치로 이동
const char *utf8_next(const char *s, unsigned *out) {
    unsigned char c = (unsigned char)*s;
    int extra = c < 0x80 ? 0 : c < 0xE0 ? 1 : c < 0xF0 ? 2 : 3;
    unsigned cp = c & (0xFF >> (extra + 2));
    if (extra == 0) cp = c;
    for (int i = 0; i < extra; i++)
        cp = (cp << 6) | (*++s & 0x3F);
    *out = cp;
    return s + 1;
}

open · read · write — 시스템 콜 직접 쓰기

#include <fcntl.h>      // open, O_RDONLY
#include <unistd.h>     // read, write, close
#include <errno.h>
#include <string.h>

int copy_file(const char *src, const char *dst) {
    int in = open(src, O_RDONLY);
    if (in < 0) return -1;                      // ★ 실패는 -1, errno 에 이유

    int out = open(dst, O_WRONLY | O_CREAT | O_TRUNC, 0644);
    if (out < 0) { close(in); return -1; }

    char buf[65536];
    ssize_t n;
    while ((n = read(in, buf, sizeof buf)) > 0) {
        ssize_t off = 0;
        while (off < n) {
            // ★ write 는 요청한 만큼 다 안 쓸 수 있습니다 (부분 쓰기)
            ssize_t w = write(out, buf + off, (size_t)(n - off));
            if (w < 0) {
                if (errno == EINTR) continue;   // ★ 시그널에 끊긴 것뿐
                close(in); close(out); return -1;
            }
            off += w;
        }
    }
    int rc = (n < 0) ? -1 : 0;
    close(in);
    if (close(out) < 0) rc = -1;   // ★ close 실패도 데이터 유실입니다
    return rc;
}

        printf("%c %10lld  %s  %s\n",
               S_ISDIR(st.st_mode) ? 'd' : '-',   // 종류
               (long long)st.st_size,             // 크기
               when, e->d_name);
    }
    closedir(d);
}

long count_lines(const char *path) {
    int fd = open(path, O_RDONLY);
    if (fd < 0) return -1;

    struct stat st;
    if (fstat(fd, &st) != 0) { close(fd); return -1; }
    if (st.st_size == 0) { close(fd); return 0; }

    // 파일 전체를 주소 공간에 붙입니다 — 실제로 읽지는 않습니다
    char *p = mmap(NULL, (size_t)st.st_size,
                   PROT_READ, MAP_PRIVATE, fd, 0);
    close(fd);                       // ★ 매핑 후에는 fd 를 닫아도 됩니다
    if (p == MAP_FAILED) return -1;

    // 커널에 접근 패턴을 알려 주면 미리 읽어 줍니다
    madvise(p, (size_t)st.st_size, MADV_SEQUENTIAL);

    long lines = 0;
    const char *cur = p, *end = p + st.st_size;
    while ((cur = memchr(cur, '\n', (size_t)(end - cur))) != NULL) {
        lines++; cur++;              // memchr 은 SIMD 로 최적화돼 매우 빠릅니다
    }
    munmap(p, (size_t)st.st_size);
    return lines;
}

네트워크 라이브러리를 한 겹만 걷어 내면 전부 이 여섯 개의 C 함수가 나옵니다 — socket · bind · listen · accept · connect · close. 파이썬 socket 모듈도 이름까지 똑같습니다. 여기서는 복사해서 바로 도는 에코 서버와 클라이언트를 만들고, 접속이 늘어날 때 select · poll · epoll 로 어떻게 넘어가는지까지 봅니다.

서버가 fd 를 두 개 갖는다는 점이 핵심입니다 — 듣는 소켓과 손님별 소켓은 완전히 다릅니다.

TCP 에코 서버 — 윈도우·리눅스·맥에서 그대로 도는 전체 코드

// echo_server.c
//   리눅스/맥 : gcc -std=c17 -O2 -Wall echo_server.c -o echo_server
//   윈도우    : gcc echo_server.c -o echo_server.exe -lws2_32
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

#ifdef _WIN32
  #include <winsock2.h>
  #include <ws2tcpip.h>
  #pragma comment(lib, "ws2_32.lib")      // MSVC 용. gcc 는 -lws2_32
  typedef SOCKET sock_t;
  #define CLOSESOCK closesocket
  #define SOCK_ERR  WSAGetLastError()
  static int net_init(void) {
      WSADATA w; return WSAStartup(MAKEWORD(2,2), &w);   // ★ 윈도우만 필요
  }
  static void net_quit(void) { WSACleanup(); }
#else
  #include <sys/socket.h>
  #include <netinet/in.h>
  #include <arpa/inet.h>
  #include <unistd.h>
  #include <errno.h>
  typedef int sock_t;
  #define INVALID_SOCKET (-1)
  #define CLOSESOCK close
  #define SOCK_ERR  errno
  static int  net_init(void) { return 0; }
  static void net_quit(void) { }
#endif

#define PORT 9000

int main(void) {
    if (net_init() != 0) { fprintf(stderr, "네트워크 초기화 실패\n"); return 1; }

    sock_t srv = socket(AF_INET, SOCK_STREAM, 0);
    if (srv == INVALID_SOCKET) { perror("socket"); return 1; }

    // ★ 서버를 껐다 켤 때 "Address already in use" 를 막습니다
    int yes = 1;
    setsockopt(srv, SOL_SOCKET, SO_REUSEADDR, (const char *)&yes, sizeof yes);

    struct sockaddr_in addr;
    memset(&addr, 0, sizeof addr);
    addr.sin_family      = AF_INET;
    addr.sin_addr.s_addr = htonl(INADDR_ANY);   // 모든 인터페이스
    addr.sin_port        = htons(PORT);         // ★ 네트워크 바이트 순서

    if (bind(srv, (struct sockaddr *)&addr, sizeof addr) != 0) {
        fprintf(stderr, "bind 실패 (%d)\n", SOCK_ERR); return 1;
    }
    if (listen(srv, 128) != 0) {
        fprintf(stderr, "listen 실패 (%d)\n", SOCK_ERR); return 1;
    }
    printf("포트 %d 에서 대기 중\n", PORT);

    for (;;) {
        struct sockaddr_in peer;
        socklen_t plen = sizeof peer;
        sock_t cli = accept(srv, (struct sockaddr *)&peer, &plen);
        if (cli == INVALID_SOCKET) continue;

        char ip[INET_ADDRSTRLEN];
        inet_ntop(AF_INET, &peer.sin_addr, ip, sizeof ip);
        printf("접속: %s:%d\n", ip, ntohs(peer.sin_port));

        char buf[4096];
        for (;;) {
            int n = recv(cli, buf, sizeof buf, 0);
            if (n == 0)  { printf("상대가 닫음\n"); break; }   // ★ 정상 종료
            if (n < 0)   { printf("오류 %d\n", SOCK_ERR); break; }

            // ★ send 도 부분 전송이 있습니다 — 다 보낼 때까지 루프
            int off = 0;
            while (off < n) {
                int w = send(cli, buf + off, n - off, 0);
                if (w <= 0) goto done;
                off += w;
            }
        }
    done:
        CLOSESOCK(cli);
    }
    CLOSESOCK(srv);
    net_quit();
    return 0;
}
가장 많이 틀리는 세 가지 — ① htons/htonl 을 빠뜨려 포트가 엉뚱한 값이 됩니다. ② recv 가 0 을 돌려주면 에러가 아니라 상대가 정상적으로 닫은 것입니다. ③ SO_REUSEADDR 없이 서버를 재시작하면 TIME_WAIT 때문에 1~2분 동안 bind 가 실패합니다.

// "EAGAIN 이 날 때까지 전부 읽어야" 하는 규칙이 생깁니다
실무에서는 직접 안 씁니다 — libuv(Node.js 의 심장) 나 libevent 가 epoll·kqueue·IOCP 를 하나의 API 로 덮어 줍니다. 그래도 이 절을 아는 것이 중요한 이유는, 장애가 났을 때 로그에 나오는 것이 결국 이 층의 용어이기 때문입니다.
실서비스로 가기 전 최소 체크리스트 — ① SIGPIPE 무시(signal(SIGPIPE, SIG_IGN))하지 않으면 끊긴 연결에 send 하는 순간 프로세스가 죽습니다. ② 읽기·쓰기 타임아웃(SO_RCVTIMEO) 설정. ③ 길이 필드는 반드시 상한 검증. ④ TLS 가 필요하면 직접 만들지 말고 mbedTLS·OpenSSL 를 얹습니다. ⑤ 작은 메시지를 자주 보낸다면 TCP_NODELAY(Nagle 끄기)를 검토합니다.
정리 — TCP 서버는 socket → bind → listen → accept 네 줄이 전부이고, 클라이언트는 socket → connect 두 줄입니다. 가장 중요한 사실은 TCP 에 메시지 경계가 없다는 것 — 길이 접두사를 붙이는 습관 하나가 실전 버그의 절반을 막습니다. 접속이 많아지면 poll → epoll 로 올라가되, 실무에서는 대개 libuv 같은 래퍼를 씁니다.

스레드와 동기화 — pthreads · C11 threads · atomics

파이썬에는 GIL 이 있어서 스레드를 써도 CPU 가 하나뿐이지만, C 는 진짜로 코어를 다 씁니다. 그 대가로 데이터 레이스라는, 재현도 안 되고 디버거로도 안 잡히는 종류의 버그가 생깁니다. 이 절은 왜 counter++ 하나가 깨지는지부터 시작해서 뮤텍스·조건 변수·원자 연산과 TSan 으로 실제로 잡아내는 법까지 갑니다.

데이터 레이스는 “가끔 값이 이상하다”로 나타납니다 — 디버거를 붙이면 느려져서 재현이 안 되는 것이 특징입니다.

pthreads — 리눅스·맥의 사실상 표준

#include <pthread.h>
#include <stdio.h>
#include <stdlib.h>

typedef struct { int from, to; long sum; } Job;

// 스레드 함수의 모양은 고정입니다: void* (*)(void*)
static void *worker(void *arg) {
    Job *j = arg;
    long s = 0;
    for (int i = j->from; i < j->to; i++) s += i;
    j->sum = s;                 // ★ 각자 다른 Job 을 쓰므로 레이스 없음
    return NULL;
}

int main(void) {
    enum { N = 4 };
    pthread_t th[N];
    Job jobs[N];

    for (int i = 0; i < N; i++) {
        jobs[i] = (Job){ i * 250000, (i + 1) * 250000, 0 };
        if (pthread_create(&th[i], NULL, worker, &jobs[i]) != 0) {
            perror("pthread_create"); return 1;
        }
    }
    long total = 0;
    for (int i = 0; i < N; i++) {
        pthread_join(th[i], NULL);   // ★ 끝날 때까지 기다립니다
        total += jobs[i].sum;
    }
    printf("합계 %ld\n", total);
}
// 컴파일: gcc -std=c17 -O2 -pthread sum.c -o sum
-pthread 를 빼먹으면 링크는 되는데 런타임에 이상하게 동작할 수 있습니다 (일부 환경에서 스레드 지원 코드가 비활성화됩니다). -lpthread 가 아니라 -pthread 를 컴파일·링크 양쪽에 주는 것이 정확한 방법입니다.

스레드 안전 큐 — 실무에서 가장 자주 쓰는 형태

#include <pthread.h>
#include <stdbool.h>

#define CAP 256

typedef struct {
    int   buf[CAP];
    size_t head, tail, count;
    bool  closed;
    pthread_mutex_t m;
    pthread_cond_t  not_empty;   // "넣었다" 알림
    pthread_cond_t  not_full;    // "뺐다" 알림
} Queue;

void q_init(Queue *q) {
    q->head = q->tail = q->count = 0;
    q->closed = false;
    pthread_mutex_init(&q->m, NULL);
    pthread_cond_init(&q->not_empty, NULL);
    pthread_cond_init(&q->not_full,  NULL);
}

void q_push(Queue *q, int v) {
    pthread_mutex_lock(&q->m);
    while (q->count == CAP)                    // ★ if 가 아니라 while
        pthread_cond_wait(&q->not_full, &q->m);
    q->buf[q->tail] = v;
    q->tail = (q->tail + 1) % CAP;
    q->count++;
    pthread_cond_signal(&q->not_empty);
    pthread_mutex_unlock(&q->m);
}
bool q_pop(Queue *q, int *out) {
    pthread_mutex_lock(&q->m);
    while (q->count == 0 && !q->closed)
        pthread_cond_wait(&q->not_empty, &q->m);

    if (q->count == 0) {                       // 닫혔고 비었다
        pthread_mutex_unlock(&q->m);
        return false;
    }
    *out = q->buf[q->head];
    q->head = (q->head + 1) % CAP;
    q->count--;
    pthread_cond_signal(&q->not_full);
    pthread_mutex_unlock(&q->m);
    return true;
}

// 더 이상 안 넣는다고 알리기 — 소비자들이 빠져나옵니다
void q_close(Queue *q) {
    pthread_mutex_lock(&q->m);
    q->closed = true;
    pthread_cond_broadcast(&q->not_empty);     // ★ 전원 깨우기
    pthread_mutex_unlock(&q->m);
}
while 이지 if 가 아닙니다 — cond_wait 는 아무도 신호를 안 보냈는데 깨어날 수 있습니다(가짜 깨어남). 조건을 다시 확인하지 않으면 빈 큐에서 꺼내는 버그가 납니다. 이건 자바 wait/notify, 파이썬 Condition 도 완전히 동일합니다.
왜 조건 변수가 필요한가 — 큐가 비었을 때 while(count==0){} 로 도는 것은 CPU 코어 하나를 통째로 태우는 짓입니다. 조건 변수는 커널에 재워 두었다가 신호가 왔을 때만 깨워 줍니다. cond_wait 는 뮤텍스를 자동으로 풀고 잠들었다가, 깨어날 때 다시 잠급니다 — 이 원자성이 조건 변수의 존재 이유입니다.

// 뮤텍스보다 훨씬 빠릅니다 — 커널에 들어가지 않으니까요

// 플래그 하나로 스레드 멈추기 (가장 흔한 용도)
atomic_bool stop = false;

void *loop(void *_) {
    while (!atomic_load_explicit(&stop, memory_order_relaxed)) {
        /* 일 */
    }
    return NULL;
}

atomic_store(&stop, true);

// 락 없는 스택 push — CAS(compare-and-swap) 관용구
void push(_Atomic(Node *) *head, Node *n) {
    Node *old = atomic_load(head);
    do {
        n->next = old;
    } while (!atomic_compare_exchange_weak(head, &old, n));
    // ★ 실패하면 old 가 '현재 값'으로 갱신되어 다시 시도합니다
}

프로세스 · 시그널 · 파이프 — 셸이 하는 일을 직접

ls | grep c 를 치면 셸이 무슨 일을 하는지 아십니까? fork 로 자기를 복제하고, pipe 로 둘을 잇고, exec 로 다른 프로그램이 되고, wait 으로 기다립니다 — 전부 이 절의 함수입니다. 파이썬 subprocess, Node child_process 도 안에서 정확히 이 일을 합니다. Ctrl+C 를 눌렀을 때 프로그램이 깨끗하게 끝나게 만드는 법도 여기서 배웁니다.

반환값이 0 이면 내가 자식, 0보다 크면 내가 부모 — 이 한 줄이 프로세스 프로그래밍의 출발점입니다.

fork + exec + wait — 외부 명령 실행하기

#include <unistd.h>
#include <sys/wait.h>
#include <stdio.h>
#include <errno.h>

int run(char *const argv[]) {
    pid_t pid = fork();
    if (pid < 0) { perror("fork"); return -1; }

    if (pid == 0) {                       // ── 자식 ──
        execvp(argv[0], argv);            // 성공하면 여기로 안 돌아옵니다
        perror("execvp");                 // 여기 왔다는 건 실패했다는 뜻
        _exit(127);                       // ★ exit 이 아니라 _exit
    }

    // ── 부모 ──
    int status;
    while (waitpid(pid, &status, 0) < 0)
        if (errno != EINTR) return -1;

    if (WIFEXITED(status))   return WEXITSTATUS(status);   // 정상 종료 코드
    if (WIFSIGNALED(status)) return 128 + WTERMSIG(status); // 시그널로 죽음
    return -1;
}

int main(void) {
    char *cmd[] = { "ls", "-l", NULL };   // ★ 마지막은 반드시 NULL
    printf("종료 코드 %d\n", run(cmd));
}
자식에서는 exit 대신 _exit 를 쓰세요. exit 은 atexit 훅을 돌리고 stdio 버퍼를 flush 하는데, 그 버퍼는 부모에게서 복사된 것이라 같은 출력이 두 번 찍힙니다. 실제로 로그가 중복되는 사고의 단골 원인입니다.

시그널 — Ctrl+C 를 우아하게 처리하기 🟡 중급

sigaction — signal() 보다 이쪽을 쓰세요

#include <signal.h>
#include <stdio.h>
#include <unistd.h>

// ★ 핸들러에서 건드릴 수 있는 유일한 전역 타입
static volatile sig_atomic_t g_stop = 0;

static void on_sigint(int sig) {
    (void)sig;
    g_stop = 1;          // 플래그만 세웁니다. 그 이상은 하지 않습니다
}

int main(void) {
    struct sigaction sa;
    memset(&sa, 0, sizeof sa);
    sa.sa_handler = on_sigint;
    sigemptyset(&sa.sa_mask);
    sa.sa_flags = SA_RESTART;      // 끊긴 시스템 콜을 자동 재시작

    sigaction(SIGINT,  &sa, NULL);  // Ctrl+C
    sigaction(SIGTERM, &sa, NULL);  // kill 기본 시그널
    signal(SIGPIPE, SIG_IGN);       // ★ 소켓 서버에는 거의 필수

    while (!g_stop) {
        /* 일을 합니다 */
        sleep(1);
    }
    printf("정리하고 종료합니다\n");   // 여기서 파일 닫기·플러시
    return 0;
}
핸들러 안에서 하면 안 되는 것 — printf·malloc·free는 모두 비동기 시그널 안전이 아닙니다. 락을 잡고 있는 중에 시그널이 오면 데드락이 납니다. 핸들러에서 허용되는 것은 volatile sig_atomic_t 플래그 설정과 write(2) 정도입니다. 나머지는 전부 메인 루프에서 하세요.

#include <stdio.h>

int run_win(const char *cmdline) {
    STARTUPINFOA si;  PROCESS_INFORMATION pi;
    ZeroMemory(&si, sizeof si);  si.cb = sizeof si;
    ZeroMemory(&pi, sizeof pi);

    // ★ cmdline 은 쓰기 가능한 버퍼여야 합니다 (API 가 수정합니다)
    char buf[1024];
    snprintf(buf, sizeof buf, "%s", cmdline);

    if (!CreateProcessA(NULL, buf, NULL, NULL, FALSE,
                        0, NULL, NULL, &si, &pi)) {
        fprintf(stderr, "CreateProcess 실패 %lu\n", GetLastError());
        return -1;
    }
    WaitForSingleObject(pi.hProcess, INFINITE);   // wait() 에 해당

    DWORD code = 0;
    GetExitCodeProcess(pi.hProcess, &code);
    CloseHandle(pi.hProcess);                     // ★ 핸들 누수 주의
    CloseHandle(pi.hThread);
    return (int)code;
}
왜 윈도우에 fork 가 없나 — 윈도우의 프로세스는 생성 시점에 실행할 이미지를 정하는 구조라 “현재 프로세스를 복제한다”는 개념 자체가 없습니다. 그래서 이식성 있는 코드는 “외부 프로그램 실행”이라는 한 가지 기능으로 추상화해 두고 그 안에서 분기합니다.

#include <stdint.h>
#include <stdbool.h>

#define RB_SIZE 256                      // ★ 반드시 2의 거듭제곱
#define RB_MASK (RB_SIZE - 1)

typedef struct {
    uint8_t  buf[RB_SIZE];
    volatile uint16_t head;              // 쓰는 쪽(ISR)만 고칩니다
    volatile uint16_t tail;              // 읽는 쪽(메인)만 고칩니다
} Ring;

// ── 인터럽트 안에서 호출 (생산자) ──
bool rb_push(Ring *r, uint8_t v) {
    uint16_t next = (uint16_t)((r->head + 1) & RB_MASK);
    if (next == r->tail) return false;    // 가득 참 — 버립니다
    r->buf[r->head] = v;
    __atomic_thread_fence(__ATOMIC_RELEASE);   // 데이터가 먼저 보이도록
    r->head = next;                       // ★ 마지막에 head 갱신
    return true;
}

// ── 메인 루프에서 호출 (소비자) ──
bool rb_pop(Ring *r, uint8_t *out) {
    if (r->tail == r->head) return false; // 비었음
    __atomic_thread_fence(__ATOMIC_ACQUIRE);
    *out = r->buf[r->tail];
    r->tail = (uint16_t)((r->tail + 1) & RB_MASK);
    return true;
}

// UART 수신 인터럽트에서
void USART1_IRQHandler(void) {
    if (UART_SR & SR_RXNE)
        rb_push(&g_rx, (uint8_t)UART_DR);   // ★ 짧게 끝냅니다
}

// 메인 루프에서
int main(void) {
    hw_init();
    for (;;) {
        uint8_t c;
        while (rb_pop(&g_rx, &c))
            handle_byte(c);                 // 무거운 처리는 여기서
        idle_sleep();
    }
}
인터럽트 핸들러의 철칙 — ① 짧게. 수 마이크로초 안에 끝내고, 처리는 메인 루프로 넘깁니다. ② malloc·printf·블로킹 대기 금지. ③ 공유 변수는 volatile + 가능하면 한쪽만 쓰는 구조로 설계합니다. ④ 부득이하게 여러 변수를 함께 고쳐야 하면 인터럽트를 잠깐 끄고(critical section) 최소한만 감쌉니다.

라이브러리 만들기 — 남이 쓸 수 있는 형태로 내보내기

C 가 지금도 중심에 있는 진짜 이유는 C ABI 가 모든 언어의 공통 언어이기 때문입니다. 파이썬·자바·C#·Go·러스트·자바스크립트가 전부 C 로 만든 .so·.dll 을 부를 수 있습니다. 이 절에서는 정적·동적 라이브러리를 빌드하고, 심볼을 골라 내보내고, 헤더를 설계하고, 다른 언어에서 한 줄로 불러 보는 것까지 한 번에 해 봅니다.

파이썬·자바가 부르는 것은 거의 항상 동적 라이브러리입니다 — 런타임에 붙일 수 있어야 하니까요.

#ifndef MATHLIB_H
#define MATHLIB_H

// ── 내보내기 매크로 (윈도우 때문에 필요합니다) ──

  #else

  #endif

#endif

// mathlib.c
#define MATHLIB_BUILD      // ★ 라이브러리를 '만드는' 쪽임을 표시
#include "mathlib.h"

// 내부 전용 함수는 static — 밖에서 안 보입니다
static double sum(const double *xs, size_t n) {
    double s = 0;
    for (size_t i = 0; i < n; i++) s += xs[i];
    return s;
}

int ml_add(int a, int b) { return a + b; }

double ml_mean(const double *xs, size_t n) {
    return n ? sum(xs, n) / (double)n : 0.0;
}

const char *ml_version(void) { return "1.2.0"; }

최적화 빌드와 디버그 빌드의 차이 🔴 고급

-O0 과 -O2 는 다른 프로그램입니다

플래그쓰는 곳주의
-O0 -g디버깅느림. 하지만 변수가 다 보입니다
-O1 -g새니타이저속도와 가시성의 균형 — 권장
-O2배포 기본인라인·루프 변형으로 스택이 뭉갬
-O3수치 계산항상 빠르진 않습니다. 재 보고 결정
-Og디버깅용 최적화GCC 전용. -O0 보다 빠르고 볼 만함
-O2 -g배포 + 심볼★ 성능은 그대로, 크래시 분석 가능
# 배포 바이너리에서 심볼만 따로 떼어 보관하는 정석
gcc -O2 -g app.c -o app
objcopy --only-keep-debug app app.debug     # 심볼 파일 분리
objcopy --strip-debug app                   # 배포용은 가볍게
objcopy --add-gnu-debuglink=app.debug app   # 연결 정보만 남김

# 나중에 코어 덤프가 오면
gdb -s app.debug -e app core
“-O0 에선 되는데 -O2 에선 깨져요” — 컴파일러 버그가 아니라 거의 항상 미정의 동작(UB)입니다. 부호 있는 오버플로, 초기화 안 한 변수, 엄격한 앨리어싱 위반 등이 최적화가 켜지면 다르게 해석되기 때문입니다. 이때야말로 -fsanitize=undefined 를 켤 자리입니다(c11 참고).

실전 프로젝트 구조 · 빌드 — Makefile 과 CMake 완전판

파일이 세 개를 넘어가는 순간 gcc *.c 로는 감당이 안 됩니다. 무엇이 무엇에 의존하는지를 적어 두면 도구가 바뀐 것만 다시 빌드해 줍니다. 이 절은 복사해서 바로 쓰는 Makefile 완전판과 CMake 표준 구성, 그리고 디렉터리 배치 · .clang-format · GitHub Actions까지 “새 C 프로젝트를 시작하는 한 세트”를 통째로 만듭니다.

빌드 도구가 하는 일은 하나입니다 — 이 그래프를 따라가며 낡은 것만 다시 만드는 것.

Makefile 완전판 — 새 프로젝트에 그대로 복사

# ── 설정 ─────────────────────────────────────────────
TARGET   := app
SRCDIR   := src
INCDIR   := include
BUILDDIR := build

CC       := gcc
CSTD     := -std=c17
WARN     := -Wall -Wextra -Wpedantic -Wshadow -Wconversion \
            -Wstrict-prototypes -Wmissing-prototypes
CPPFLAGS := -I$(INCDIR) -MMD -MP        # ★ -MMD -MP 가 의존성 자동 생성
LDFLAGS  :=
LDLIBS   := -lm

# make DEBUG=1 로 디버그 빌드
ifdef DEBUG
  OPT := -O0 -g -fsanitize=address,undefined
  LDFLAGS += -fsanitize=address,undefined
else
  OPT := -O2 -DNDEBUG
endif
CFLAGS := $(CSTD) $(WARN) $(OPT)

# ── 파일 목록 (자동 수집) ────────────────────────────
SRCS := $(wildcard $(SRCDIR)/*.c)
OBJS := $(patsubst $(SRCDIR)/%.c,$(BUILDDIR)/%.o,$(SRCS))
DEPS := $(OBJS:.o=.d)

# ── 규칙 ─────────────────────────────────────────────
.PHONY: all clean run test format
all: $(TARGET)

$(TARGET): $(OBJS)
	$(CC) $(LDFLAGS) $^ $(LDLIBS) -o $@

$(BUILDDIR)/%.o: $(SRCDIR)/%.c | $(BUILDDIR)
	$(CC) $(CPPFLAGS) $(CFLAGS) -c $< -o $@

$(BUILDDIR):
	mkdir -p $@

run: $(TARGET)
	./$(TARGET)

test: DEBUG=1
test: $(TARGET)
	./$(TARGET) --self-test

format:
	clang-format -i $(SRCDIR)/*.c $(INCDIR)/*.h

clean:
	rm -rf $(BUILDDIR) $(TARGET)

-include $(DEPS)      # ★ 헤더 의존성을 여기서 읽어 들입니다
Makefile 의 규칙 줄은 반드시 탭(Tab) 으로 들여씁니다 — 스페이스면 missing separator 에러가 납니다. 그리고 -MMD -MP 가 이 파일의 핵심입니다. 이게 없으면 헤더를 고쳐도 다시 빌드되지 않아, “왜 수정이 반영이 안 되지?”로 몇 시간을 날립니다. -MMD 는 .d 파일에 의존 목록을 적고, 마지막 줄의 -include 가 그걸 읽어 옵니다.

// sqlite3.c(약 25만 줄 한 파일) + sqlite3.h 를 받아 함께 컴파일하면 끝입니다
#include "sqlite3.h"
#include <stdio.h>

int main(void) {
    sqlite3 *db;
    if (sqlite3_open("app.db", &db) != SQLITE_OK) return 1;

    sqlite3_exec(db,
        "CREATE TABLE IF NOT EXISTS log(id INTEGER PRIMARY KEY, msg TEXT)",
        NULL, NULL, NULL);

    // ★ 항상 준비된 문장(prepared statement) — SQL 주입을 막습니다
    sqlite3_stmt *st;
    sqlite3_prepare_v2(db, "INSERT INTO log(msg) VALUES(?)", -1, &st, NULL);
    sqlite3_bind_text(st, 1, "첫 기록", -1, SQLITE_STATIC);
    sqlite3_step(st);
    sqlite3_finalize(st);

    sqlite3_prepare_v2(db, "SELECT id, msg FROM log", -1, &st, NULL);
    while (sqlite3_step(st) == SQLITE_ROW)
        printf("%d: %s\n", sqlite3_column_int(st, 0),
                           sqlite3_column_text(st, 1));
    sqlite3_finalize(st);
    sqlite3_close(db);
}
// gcc main.c sqlite3.c -o app -lpthread -ldl

libcurl + cJSON — API 를 부르고 파싱하기

#include <curl/curl.h>
#include <cjson/cJSON.h>
#include <stdlib.h>
#include <string.h>

typedef struct { char *p; size_t n; } Buf;

static size_t on_data(void *src, size_t sz, size_t nm, void *ud) {
    size_t total = sz * nm;
    Buf *b = ud;
    char *q = realloc(b->p, b->n + total + 1);
    if (!q) return 0;                       // 0 을 반환하면 전송이 중단됩니다
    b->p = q;
    memcpy(b->p + b->n, src, total);
    b->n += total;
    b->p[b->n] = '\0';
    return total;
}

int main(void) {
    curl_global_init(CURL_GLOBAL_DEFAULT);
    CURL *c = curl_easy_init();
    Buf buf = {0};

    curl_easy_setopt(c, CURLOPT_URL, "https://api.example.com/items");
    curl_easy_setopt(c, CURLOPT_WRITEFUNCTION, on_data);
    curl_easy_setopt(c, CURLOPT_WRITEDATA, &buf);
    curl_easy_setopt(c, CURLOPT_TIMEOUT, 10L);          // ★ 타임아웃 필수
    curl_easy_setopt(c, CURLOPT_FOLLOWLOCATION, 1L);

    if (curl_easy_perform(c) == CURLE_OK) {
        cJSON *root = cJSON_Parse(buf.p);
        cJSON *name = cJSON_GetObjectItemCaseSensitive(root, "name");
        if (cJSON_IsString(name)) printf("이름: %s\n", name->valuestring);
        cJSON_Delete(root);                             // ★ 해제는 내 책임
    }
    free(buf.p);
    curl_easy_cleanup(c);
    curl_global_cleanup();
}
// gcc main.c -o app -lcurl -lcjson
