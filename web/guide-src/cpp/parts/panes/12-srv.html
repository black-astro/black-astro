첫 판단을 도와주는 계산 한 번

지금 서버가 감당해야 하는 것을 숫자로 적어 봅니다.

  · 피크 RPS                     예) 1,200
  · 요청당 순수 CPU 시간          예) 0.4 ms
  · 요청당 대기(DB·외부 API)      예) 35 ms
  · 목표 p99                     예) 200 ms

CPU 만으로 필요한 코어 =  RPS × CPU시간
                       = 1200 × 0.0004 s = 0.48 코어

→ CPU 는 거의 안 씁니다. 병목은 35ms 의 '대기'입니다.
→ 언어를 바꿔도 35ms 는 그대로입니다.
→ 이 서비스는 C++ 로 옮길 이유가 없습니다.
   (커넥션 풀·인덱스·캐시를 먼저 손대야 합니다)

반대로 CPU시간이 8ms 였다면
   1200 × 0.008 = 9.6 코어  ← 여기서부터 언어가 돈입니다
이 계산을 안 하고 시작한 프로젝트가 정말 많습니다 — “C++ 로 바꿨는데 왜 안 빨라지죠?” 의 90%가 대기 시간이 병목인 경우입니다. 언어가 줄여 주는 건 CPU 시간뿐이고, 나머지는 구조·쿼리·캐시의 몫입니다.
정리 — C++ 서버는 CPU 가 실제로 병목이거나, p99 지연이 계약이거나, C++ 자산이 이미 있을 때의 선택입니다. 넘어왔다면 Drogon 을 기본값으로 잡고, 배우는 단계에서는 cpp-httplib, 소켓 중심이면 uWebSockets·Beast 로 갈라집니다.
SRV 02

첫 서버 — 10줄로 JSON 을 돌려줍니다

설명보다 먼저 뜨는 걸 봅니다. cpp-httplib 은 헤더 파일 하나라 vcpkg 없이도 되고, curl 로 확인까지 5분이면 끝납니다. 이 단계에서 C++ 서버가 요청을 받는 모양이 손에 붙습니다.

이 그림의 5번만 이해하면 됩니다 — 블로킹 모델은 스레드 수가 곧 동시 처리 수입니다.

첫 서버 — 이게 전부입니다

// main.cpp
#include <httplib.h>
#include <nlohmann/json.hpp>
using json = nlohmann::json;

int main() {
    httplib::Server svr;                       // FastAPI 의 app = FastAPI()

    svr.Get("/health", [](const httplib::Request&, httplib::Response& res) {
        res.set_content("ok", "text/plain");
    });

    // GET /users/42  → 경로에 정규식을 씁니다 (애너테이션이 없으니까요)
    svr.Get(R"(/users/(\d+))", [](const httplib::Request& req, httplib::Response& res) {
        int id = std::stoi(req.matches[1]);    // 캡처 그룹 1번
        json body = {{"id", id}, {"name", "김개발"}, {"active", true}};
        res.set_content(body.dump(), "application/json");
    });

    // POST /users  → 본문 파싱
    svr.Post("/users", [](const httplib::Request& req, httplib::Response& res) {
        auto in = json::parse(req.body, nullptr, false);   // false = 예외 대신 discarded
        if (in.is_discarded() || !in.contains("name")) {
            res.status = 400;
            res.set_content(R"({"error":"name is required"})", "application/json");
            return;
        }
        json out = {{"id", 7}, {"name", in["name"]}};
        res.status = 201;
        res.set_content(out.dump(), "application/json");
    });

    svr.set_exception_handler([](const auto&, auto& res, std::exception_ptr) {
        res.status = 500;                       // 안 잡으면 서버가 죽습니다 ★
        res.set_content(R"({"error":"internal"})", "application/json");
    });

    std::cout << "listening on :8080\n";
    svr.listen("0.0.0.0", 8080);                // 여기서 블록됩니다
}
FastAPI 와 나란히 보면 — @app.get("/users/{id}") 가 svr.Get(R"(/users/(\d+))", ...) 입니다. 데코레이터가 없으니 경로 패턴을 정규식으로 쓰고, 타입 변환(int id)도 내가 합니다. R"(...)" 는 원시 문자열이라 백슬래시를 두 번 쓰지 않아도 됩니다.

바로 필요해지는 옵션 다섯 개

httplib::Server svr;

// ① 스레드 풀 크기 — 이게 동시 처리 수의 천장입니다 ★
svr.new_task_queue = [] { return new httplib::ThreadPool(32); };

// ② 타임아웃 — 안 주면 느린 클라이언트 하나가 스레드를 오래 잡습니다
svr.set_read_timeout(5, 0);        // 5초
svr.set_write_timeout(5, 0);
svr.set_keep_alive_max_count(100); // keep-alive 로 처리할 요청 수
svr.set_payload_max_length(1024 * 1024);   // 1MB 넘는 본문 거부

// ③ 공통 처리(미들웨어 자리) — 전/후 훅
svr.set_pre_routing_handler([](const auto& req, auto& res) {
    res.set_header("X-Req-Id", make_uuid());
    return httplib::Server::HandlerResponse::Unhandled;  // 계속 진행
});
svr.set_logger([](const auto& req, const auto& res) {
    std::printf("%s %s -> %d\n", req.method.c_str(), req.path.c_str(), res.status);
});

// ④ CORS (브라우저에서 부를 거라면 필수 — w09 에서 제대로)
svr.Options(".*", [](const auto&, auto& res) {
    res.set_header("Access-Control-Allow-Origin", "*");
    res.set_header("Access-Control-Allow-Headers", "Content-Type, Authorization");
});

// ⑤ 정적 파일 — 프런트 빌드 결과를 같이 서빙
svr.set_mount_point("/", "./public");
이 라이브러리를 실서비스에 두려면 알아야 할 한계 — HTTP/2 가 없고, 스레드 하나가 요청 하나라 느린 외부 호출이 많으면 금방 막힙니다. 사내 도구·테스트 목 서버·관리 API 까지가 편안한 영역이고, 그 위로는 Drogon 으로 넘어가는 게 맞습니다.

Drogon 완전 입문 — C++ 의 Spring Boot 자리

void UserController::create(const HttpRequestPtr& req,

#pragma once
#include <drogon/HttpFilter.h>

class AuthFilter : public drogon::HttpFilter<AuthFilter> {
public:
    void doFilter(const drogon::HttpRequestPtr& req,
                  drogon::FilterCallback&& fail,        // 여기서 끊을 때
                  drogon::FilterChainCallback&& next) override
    {
        auto h = req->getHeader("Authorization");
        if (h.starts_with("Bearer ") && verify_jwt(h.substr(7))) {
            // 뒤 단계에서 쓸 값을 요청에 붙여 둡니다 (ThreadLocal 자리)

            next();                                     // 통과 ★
            return;
        }
        auto res = drogon::HttpResponse::newHttpResponse();
        res->setStatusCode(drogon::k401Unauthorized);
        fail(res);                                      // 여기서 끝 ★
    }
};

co_await 로 DB 를 부릅니다

using namespace drogon;
using namespace drogon::orm;

Task<> UserController::one(HttpRequestPtr req,
                           std::function<void(const HttpResponsePtr&)> cb,
                           int64_t id)
{
    auto db = app().getDbClient();             // config.json 의 "default"
    try {
        // ★ 여기서 스레드가 멈추지 않습니다. 루프는 다른 요청을 처리합니다
        auto rows = co_await db->execSqlCoro(
            "select id, name, created_at from users where id = $1", id);

        if (rows.empty()) {
            cb(HttpResponse::newNotFoundResponse());
            co_return;
        }
        Json::Value j;
        j["id"]   = rows[0]["id"].as<int64_t>();
        j["name"] = rows[0]["name"].as<std::string>();
        cb(HttpResponse::newHttpJsonResponse(j));
    }
    catch (const DrogonDbException& e) {
        LOG_ERROR << "db: " << e.base().what();
        auto r = HttpResponse::newHttpResponse();
        r->setStatusCode(k503ServiceUnavailable);
        cb(r);
    }
    co_return;
}
이 코드가 이 절의 결론입니다 — await 를 쓰는 FastAPI 코드와 모양이 거의 같은데, 스레드 8개로 동시 연결 수만 개를 처리합니다. $1 자리표시자를 쓰므로 SQL 인젝션이 원천 차단됩니다(w07).

SRV 04

Boost.Asio 와 C++20 코루틴 — 그 밑에서 벌어지는 일

Drogon·Crow·Beast 는 전부 이 위에 얹혀 있습니다. io_context·strand·co_await 세 단어만 잡으면 프레임워크가 왜 그렇게 생겼는지가 보이고, 필요할 때 직접 서버를 조립할 수도 있습니다.

스레드 수는 코어 수면 충분합니다 — 더 늘려도 대기 중인 I/O 는 스레드를 쓰지 않기 때문입니다.

코루틴 에코 서버 — 이게 전체 코드입니다

#include <boost/asio.hpp>
#include <boost/asio/co_spawn.hpp>
#include <boost/asio/detached.hpp>
#include <cstdio>

namespace asio = boost::asio;
using asio::ip::tcp;
using asio::awaitable;
using asio::use_awaitable;

// 연결 하나를 담당하는 코루틴 — 동기 코드처럼 읽힙니다 ★
awaitable<void> session(tcp::socket sock) {
    char buf[4096];
    try {
        for (;;) {
            std::size_t n = co_await sock.async_read_some(
                asio::buffer(buf), use_awaitable);        // 여기서 '양보'
            co_await asio::async_write(
                sock, asio::buffer(buf, n), use_awaitable);
        }
    } catch (const std::exception& e) {
        // 상대가 끊으면 예외로 옵니다 — 정상 흐름입니다
    }
}

awaitable<void> listener(unsigned short port) {
    auto ex = co_await asio::this_coro::executor;
    tcp::acceptor acc(ex, {tcp::v4(), port});
    acc.set_option(asio::socket_base::reuse_address(true));
    for (;;) {
        tcp::socket sock = co_await acc.async_accept(use_awaitable);
        // 연결마다 코루틴 하나 — 스레드가 아니라 '코루틴'입니다
        asio::co_spawn(ex, session(std::move(sock)), asio::detached);
    }
}

int main() {
    asio::io_context io(1);
    asio::signal_set sig(io, SIGINT, SIGTERM);
    sig.async_wait([&](auto, auto) { io.stop(); });   // Ctrl+C 로 정상 종료

    asio::co_spawn(io, listener(9000), asio::detached);
    io.run();
}
co_await 가 하는 일 — “여기서 멈추고, 결과가 오면 이 줄부터 다시”. 멈춘 동안 스레드는 다른 코루틴을 실행합니다. 파이썬 asyncio, 자바스크립트 await 와 개념이 정확히 같고, 차이는 스택 프레임이 힙에 저장되어 코루틴 하나가 수백 바이트밖에 안 든다는 점입니다.

스레드 풀 — 코어 수만큼 run() 을 부릅니다

int main() {
    const unsigned n = std::max(1u, std::thread::hardware_concurrency());
    asio::io_context io(n);                    // 힌트: 동시 실행 스레드 수

    asio::co_spawn(io, listener(9000), asio::detached);

    std::vector<std::thread> pool;
    pool.reserve(n - 1);
    for (unsigned i = 0; i + 1 < n; ++i)
        pool.emplace_back([&] { io.run(); });  // 같은 io_context 를 함께 돌립니다
    io.run();                                  // 메인 스레드도 일꾼으로
    for (auto& t : pool) t.join();
}

// 모델 비교
//   ① io_context 1개 + 스레드 N개   ← 기본. 부하가 자동으로 고르게 퍼집니다
//   ② io_context N개 + 스레드 1개씩 ← 연결을 루프에 고정. 캐시 지역성이 좋습니다

class Room {
    asio::strand<asio::io_context::executor_type> strand_;
    std::vector<std::shared_ptr<Session>> members_;   // 락 필요 없음
public:
    explicit Room(asio::io_context& io) : strand_(asio::make_strand(io)) {}

    void join(std::shared_ptr<Session> s) {
        asio::post(strand_, [this, s = std::move(s)] {
            members_.push_back(s);      // 이 람다들은 절대 겹치지 않습니다
        });
    }
    void broadcast(std::string msg) {
        asio::post(strand_, [this, msg = std::move(msg)] {
            for (auto& m : members_) m->send(msg);
        });
    }
};

awaitable<void> ws_session(tcp::socket sock) {
    ws::stream<tcp::socket> s(std::move(sock));

    // ① 권장 타임아웃 한 벌 — 핸드셰이크·유휴·핑 자동 처리까지 포함됩니다 ★
    s.set_option(ws::stream_base::timeout::suggested(beast::role_type::server));

    // ② 응답 헤더 손보기
    s.set_option(ws::stream_base::decorator([](ws::response_type& res) {
        res.set(http::field::server, "beast-echo");
    }));

    co_await s.async_accept(use_awaitable);      // 101 까지 처리해 줍니다

    beast::flat_buffer buf;
    for (;;) {
        buf.clear();
        co_await s.async_read(buf, use_awaitable);   // 프레임 하나
        s.text(s.got_text());                        // 받은 그대로 되돌리기
        co_await s.async_write(buf.data(), use_awaitable);
    }
}

awaitable<void> listener(unsigned short port) {
    auto ex = co_await asio::this_coro::executor;
    tcp::acceptor acc(ex, {tcp::v4(), port});
    for (;;) {
        auto sock = co_await acc.async_accept(use_awaitable);
        asio::co_spawn(ex, [s = std::move(sock)]() mutable -> awaitable<void> {
            try { co_await ws_session(std::move(s)); }
            catch (const std::exception& e) { /* 끊김은 정상 흐름 */ }
        }, asio::detached);
    }
}

class Session;   // 아래에서 정의

class Room {
    asio::strand<asio::any_io_executor> strand_;
    std::unordered_set<std::shared_ptr<Session>> members_;
public:
    explicit Room(asio::any_io_executor ex) : strand_(asio::make_strand(ex)) {}
    auto executor() { return strand_; }

    void join (std::shared_ptr<Session> s) {
        asio::post(strand_, [this, s] { members_.insert(s); });
    }
    void leave(std::shared_ptr<Session> s) {
        asio::post(strand_, [this, s] { members_.erase(s); });
    }
    void publish(std::string msg) {
        // strand 덕분에 members_ 를 락 없이 순회합니다 ★
        asio::post(strand_, [this, m = std::make_shared<std::string>(std::move(msg))] {
            for (auto& s : members_) s->enqueue(m);
        });
    }
};

// 각 세션은 '보낼 것 큐'를 하나 갖습니다 — 동시에 async_write 를 두 번 부르면
// 프레임이 섞여 프로토콜이 깨집니다. 반드시 한 번에 하나씩 ★
class Session : public std::enable_shared_from_this<Session> {
    ws::stream<tcp::socket> ws_;
    std::deque<std::shared_ptr<const std::string>> out_;
    bool writing_ = false;
public:
    void enqueue(std::shared_ptr<const std::string> m) {
        asio::post(ws_.get_executor(), [self = shared_from_this(), m] {
            self->out_.push_back(m);
            if (!self->writing_) self->do_write();
        });
    }
    void do_write() { /* out_.front() 를 async_write, 완료 콜백에서 다음 것 */ }
};
이 절에서 진짜 배워야 할 규칙 — 하나의 WebSocket 스트림에 동시에 async_write 를 두 번 걸면 안 됩니다. 프레임이 섞여 “가끔 이상한 메시지가 온다”는 재현 안 되는 버그가 됩니다. 해법은 언제나 세션마다 송신 큐 하나입니다.

// 라이브러리를 더 못 들일 때 — 이 정도면 실무에서 버팁니다
struct Err { std::string field, msg; };

template <class T>
std::optional<T> pick(const Json::Value& j, const char* k,
                      std::vector<Err>& errs);

template <>
std::optional<std::string> pick<std::string>(const Json::Value& j, const char* k,
                                             std::vector<Err>& errs) {
    if (!j.isMember(k))      { errs.push_back({k, "required"});    return {}; }
    if (!j[k].isString())    { errs.push_back({k, "must be text"}); return {}; }
    return j[k].asString();
}

// 사용
std::vector<Err> errs;
auto name = pick<std::string>(body, "name", errs);
auto age  = pick<int>(body, "age", errs);
if (!errs.empty()) {
    Json::Value out, arr(Json::arrayValue);
    for (auto& e : errs) {
        Json::Value one;
        one["field"] = e.field; one["message"] = e.msg;
        arr.append(one);
    }
    out["errors"] = arr;                    // 422 로 한 번에 돌려줍니다 ★
    auto res = HttpResponse::newHttpJsonResponse(out);
    res->setStatusCode(k422UnprocessableEntity);
    return cb(res);
}

숫자를 정하는 법

① 풀 크기 (connection_number)
   시작값 = 코어 수 × 2
   · 8코어 → 16. 여기서 부하를 걸고 p99 를 보면서 조정합니다
   · 늘렸는데 처리량이 안 늘면 병목은 DB 안입니다 (인덱스·잠금)

② 전체 커넥션 상한
   앱 인스턴스 수 × 풀 크기 ≤ DB max_connections × 0.8
   · 10대 × 16 = 160  → PostgreSQL 기본 100 이면 초과 ★

gRPC · Protobuf — 내부 통신의 표준

외부에는 REST, 내부에는 gRPC — 이게 요즘의 기본 구성입니다. .proto 파일 하나로 C++ 서버와 파이썬·자바 클라이언트가 같은 계약을 공유하고, HTTP/2 위에서 스트리밍까지 공짜로 얻습니다.

gRPC 의 진짜 값어치는 속도가 아니라 여러 언어가 하나의 계약을 공유한다는 점입니다.

#include <grpcpp/grpcpp.h>
#include <grpcpp/ext/proto_server_reflection_plugin.h>
#include "links.grpc.pb.h"

using namespace shortener::v1;

class LinksImpl final : public Links::CallbackService {
public:
    // 단항 — 리액터를 돌려주는 방식입니다
    grpc::ServerUnaryReactor* Resolve(grpc::CallbackServerContext* ctx,
                                      const ResolveRequest* req,
                                      ResolveReply* rep) override {
        auto* reactor = ctx->DefaultReactor();
        auto url = lookup(req->code());
        if (!url) {
            reactor->Finish(grpc::Status(grpc::StatusCode::NOT_FOUND, "no code"));
            return reactor;
        }
        rep->set_url(*url);
        rep->set_hits(hits_of(req->code()));
        reactor->Finish(grpc::Status::OK);
        return reactor;
    }
};

int main() {
    grpc::reflection::InitProtoReflectionServerBuilderPlugin();  // grpcurl 용
    LinksImpl svc;
    grpc::ServerBuilder b;
    b.AddListeningPort("0.0.0.0:50051", grpc::InsecureServerCredentials());
    b.RegisterService(&svc);
    b.SetMaxReceiveMessageSize(16 * 1024 * 1024);
    auto server = b.BuildAndStart();
    server->Wait();
}
동기 API 도 있습니다 — Links::Service 를 상속해 grpc::Status Resolve(...) 를 그냥 구현하면 됩니다. 훨씬 읽기 쉽지만 요청 1건 = 스레드 1개 모델이라 동시성이 스레드 수에 묶입니다. 처음엔 동기로, 부하가 보이면 콜백으로 가는 순서가 실용적입니다.

서버 스트리밍 구현

// 이벤트가 생길 때마다 클라이언트로 밀어 보냅니다
class HitWatcher : public grpc::ServerWriteReactor<HitEvent> {
    std::deque<HitEvent> queue_;
    std::mutex          m_;
    bool                writing_ = false;
public:
    void push(HitEvent e) {                    // 다른 스레드에서 부릅니다
        std::lock_guard lk(m_);
        queue_.push_back(std::move(e));
        if (!writing_) next();
    }
    void OnWriteDone(bool ok) override {       // 한 건 전송 완료
        std::lock_guard lk(m_);
        writing_ = false;
        if (!ok) { Finish(grpc::Status::OK); return; }
        if (!queue_.empty()) next();
    }
    void OnDone() override { delete this; }    // 정리 ★
private:
    void next() {                              // m_ 을 잡은 상태에서 부릅니다
        writing_ = true;
        StartWrite(&queue_.front());
    }
};

grpc::ServerWriteReactor<HitEvent>* LinksImpl::WatchHits(
        grpc::CallbackServerContext* ctx, const WatchRequest* req) {
    auto* w = new HitWatcher();
    registry().subscribe(req->code(), w);      // 어딘가에 등록해 둡니다
    return w;
}
StartWrite 를 겹쳐 부르면 즉시 죽습니다 — 한 번에 하나가 규칙이고, 다음 쓰기는 OnWriteDone 에서 시작합니다. WebSocket 의 “세션마다 송신 큐 하나”와 똑같은 규칙입니다(w05).

인증과 보안 — 스타터가 없는 자리를 직접 채우기

Spring Security 도, fastapi-users 도 없습니다. 대신 필요한 조각은 다 있습니다 — jwt-cpp, Argon2, 그리고 Nginx. 중요한 건 라이브러리가 아니라 어디까지를 앱이 하고 어디부터를 앞단이 하느냐의 경계입니다.

보안의 절반은 앱이 하지 않는 일을 정하는 것입니다 — TLS·레이트 리밋은 앞단의 몫.

비밀번호 — Argon2id 로 저장합니다

#include <argon2.h>
#include <random>

// 저장할 때 — 솔트는 매번 새로 만듭니다
std::string hash_password(std::string_view pwd) {
    uint8_t salt[16];
    std::random_device rd;
    for (auto& b : salt) b = static_cast<uint8_t>(rd());

    char encoded[128];
    int rc = argon2id_hash_encoded(
        /*t_cost=*/3,             // 반복 횟수
        /*m_cost=*/1 << 16,       // 메모리 64MB — GPU 공격을 비싸게 만듭니다 ★
        /*parallelism=*/1,
        pwd.data(), pwd.size(),
        salt, sizeof salt,
        /*hashlen=*/32,
        encoded, sizeof encoded);
    if (rc != ARGON2_OK) throw std::runtime_error(argon2_error_message(rc));
    return encoded;   // "$argon2id$v=19$m=65536,t=3,p=1$...$..." 통째로 저장
}

// 검증할 때 — 파라미터는 문자열 안에 들어 있습니다
bool verify_password(const std::string& encoded, std::string_view pwd) {
    return argon2id_verify(encoded.c_str(), pwd.data(), pwd.size()) == ARGON2_OK;
}

JWT — jwt-cpp 로 만들고 검증하기

#include <jwt-cpp/jwt.h>

std::string issue_token(int64_t uid, std::string_view role) {
    const auto now = std::chrono::system_clock::now();
    return jwt::create()
        .set_type("JWT")
        .set_issuer("shortener")
        .set_audience("web")
        .set_subject(std::to_string(uid))
        .set_issued_at(now)
        .set_expires_at(now + std::chrono::minutes(15))    // 짧게 ★
        .set_id(make_uuid())                               // jti — 블랙리스트 키
        .set_payload_claim("role", jwt::claim(std::string(role)))
        .sign(jwt::algorithm::hs256{secret_from_env()});
}

struct Claims { int64_t uid; std::string role, jti; };

std::optional<Claims> verify_token(const std::string& token) {
    static const auto verifier = jwt::verify()
        .allow_algorithm(jwt::algorithm::hs256{secret_from_env()})
        .with_issuer("shortener")
        .with_audience("web")
        .leeway(30);                       // 서버 시계 오차 허용(초)
    try {
        auto d = jwt::decode(token);
        verifier.verify(d);                // 서명·만료·발급자 전부 확인
        return Claims{
            std::stoll(d.get_subject()),
            d.get_payload_claim("role").as_string(),
            d.get_id()
        };
    } catch (const std::exception&) {
        return std::nullopt;               // 이유를 클라이언트에 알리지 마세요 ★
    }
}
HS256 이냐 RS256 이냐 — 토큰을 발급하는 곳과 검증하는 곳이 같으면 HS256(대칭키)로 충분합니다. 서비스 여러 개가 검증만 한다면 RS256/ES256 을 써서 공개키만 나눠 주세요. 대칭키를 여러 서비스에 뿌리면 어느 하나만 털려도 전부 위조됩니다.

static const std::set<std::string> kAllowed = {
    "https://app.example.com", "https://admin.example.com"
};

drogon::app().registerSyncAdvice(
  [](const HttpRequestPtr& req) -> HttpResponsePtr {
    auto origin = req->getHeader("Origin");
    if (origin.empty() || !kAllowed.contains(origin)) return {};

    if (req->method() == drogon::Options) {          // 프리플라이트
        auto r = HttpResponse::newHttpResponse();
        r->setStatusCode(drogon::k204NoContent);
        r->addHeader("Access-Control-Allow-Origin",      origin);
        r->addHeader("Access-Control-Allow-Methods",     "GET,POST,PATCH,DELETE");
        r->addHeader("Access-Control-Allow-Headers",     "Content-Type,Authorization");
        r->addHeader("Access-Control-Allow-Credentials", "true");
        r->addHeader("Access-Control-Max-Age",           "600");
        return r;
    }
    return {};
  });

//    config.json: "client_max_body_size": "2M"
// ② 경로 조작 방지 — 사용자 입력으로 파일 경로를 만들지 않습니다
//    "../../etc/passwd" 를 걸러야 합니다
// ③ 상수 시간 비교 — API 키·서명 비교에 == 를 쓰지 않습니다
bool ct_equal(std::string_view a, std::string_view b) {
    if (a.size() != b.size()) return false;
    unsigned char diff = 0;
    for (size_t i = 0; i < a.size(); ++i) diff |= a[i] ^ b[i];
    return diff == 0;                       // 길이 정보만 새어 나갑니다
}

// src/core/base62.h — drogon 을 include 하지 않습니다 ★
#pragma once
#include <string>
#include <string_view>
#include <algorithm>
#include <stdexcept>

inline constexpr std::string_view kB62 =
    "0123456789abcdefghijklmnopqrstuvwxyz"
    "ABCDEFGHIJKLMNOPQRSTUVWXYZ";

inline std::string base62_encode(int64_t n) {
    if (n < 0) throw std::invalid_argument("negative");
    if (n == 0) return "0";
    std::string s;
    while (n > 0) { s.push_back(kB62[n % 62]); n /= 62; }
    std::reverse(s.begin(), s.end());
    return s;
}

inline int64_t base62_decode(std::string_view s) {
    if (s.empty()) throw std::invalid_argument("empty");
    int64_t n = 0;
    for (char c : s) {
        auto p = kB62.find(c);
        if (p == std::string_view::npos) throw std::invalid_argument("bad char");
        n = n * 62 + static_cast<int64_t>(p);
    }
    return n;
}

struct Link { int64_t id; std::string code, url; int64_t hits; };

class LinkRepo {
    drogon::orm::DbClientPtr db_;
public:
    explicit LinkRepo(drogon::orm::DbClientPtr db) : db_(std::move(db)) {}

    // 코드로 찾기
    drogon::Task<std::optional<std::string>> url_of(std::string code) {
        auto r = co_await db_->execSqlCoro(
            "select url from links "
            " where code = $1 and (expires_at is null or expires_at > now())",
            code);
        if (r.empty()) co_return std::nullopt;
        co_return r[0]["url"].as<std::string>();

        throw std::runtime_error("code space exhausted");
    }

    // 조회 수는 나중에 몰아서 반영합니다 (요청 경로에서 update 하지 않습니다)
    drogon::Task<> flush_hits(std::vector<std::pair<std::string,int64_t>> batch) {
        auto tx = co_await db_->newTransactionCoro();
        for (auto& [code, n] : batch)
            co_await tx->execSqlCoro(
                "update links set hits = hits + $1 where code = $2", n, code);
        co_return;
    }
};
요청마다 update links set hits = hits + 1 을 하면 안 됩니다 — 인기 링크 한 줄에 쓰기 경합이 몰려 초당 수백 건에서 무너집니다. Redis 에서 세고 10초마다 한 번씩 몰아서 반영하세요. 읽기 전용 서비스에서 쓰기를 만들어 내는 게 가장 흔한 설계 실수입니다.

using namespace drogon;

Task<> LinkController::resolve(HttpRequestPtr req, Cb cb, std::string code) {
    // ① 캐시 — 실패해도 서비스는 계속돼야 합니다
    if (auto hit = co_await cache().get(code)) {
        cb(redirect(*hit));
        cache().bump(code);                    // 조회 수는 Redis 에서만 셉니다
        co_return;
    }
    // ② DB
    auto url = co_await repo().url_of(code);
    if (!url) {
        auto r = HttpResponse::newHttpJsonResponse(err("not found"));
        r->setStatusCode(k404NotFound);
        cb(r);
        co_return;
    }
    // ③ 캐시에 채우고 응답
    co_await cache().set(code, *url, 300);
    cb(redirect(*url));
    cache().bump(code);
    co_return;
}

Task<> LinkController::create(HttpRequestPtr req, Cb cb) {
    auto body = req->getJsonObject();
    if (!body || !(*body)["url"].isString())
        co_return cb(bad_request("url is required"));

    std::string url = (*body)["url"].asString();
    if (!is_valid_url(url))                    // core/url.h — 순수 함수
        co_return cb(bad_request("only http/https, max 2048 chars"));

    auto code = co_await repo().create(url, uid_of(req));
    Json::Value out;
    out["code"]      = code;
    out["short_url"] = base_url() + "/" + code;
    auto res = HttpResponse::newHttpJsonResponse(out);
    res->setStatusCode(k201Created);
    cb(res);
    co_return;
}

    auto r = HttpResponse::newHttpResponse();
    r->setStatusCode(k302Found);
    r->addHeader("Location", url);
    r->addHeader("Cache-Control", "no-store");
    return r;

// src/cache/link_cache.cc
class LinkCache {
    drogon::nosql::RedisClientPtr rc_;
public:
    // 캐시는 '있으면 좋은 것'입니다 — 실패를 예외로 올리지 않습니다 ★
    drogon::Task<std::optional<std::string>> get(std::string code) {
        try {
            auto r = co_await rc_->execCommandCoro("get l:%s", code.c_str());
            if (r.type() == drogon::nosql::RedisResultType::kNil) co_return std::nullopt;
            co_return std::string(r.asString());
        } catch (const std::exception& e) {
            SPDLOG_WARN(R"({{"event":"cache_down","err":"{}"}})", e.what());
            co_return std::nullopt;            // DB 로 그냥 갑니다
        }
    }

    drogon::Task<> set(std::string code, std::string url, int ttl) {
        try {
            co_await rc_->execCommandCoro("set l:%s %s EX %d",
                                          code.c_str(), url.c_str(), ttl);
        } catch (...) {}
        co_return;
    }

    void bump(const std::string& code) {        // 기다리지 않습니다
        rc_->execCommandAsync([](auto&&) {}, [](auto&&) {},
                              "hincrby hits %s 1", code.c_str());
    }
};

// main.cc — 10초마다 조회 수를 DB 로 옮깁니다
drogon::app().getLoop()->runEvery(10.0, [] {
    drogon::async_run([]() -> drogon::Task<> {
        auto r = co_await redis()->execCommandCoro("hgetall hits");
        auto batch = parse_pairs(r);
        if (batch.empty()) co_return;
        co_await redis()->execCommandCoro("del hits");
        co_await repo().flush_hits(std::move(batch));   // 한 트랜잭션으로
        co_return;
    });
});
