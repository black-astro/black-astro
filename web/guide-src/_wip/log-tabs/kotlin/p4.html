LOG 09

안드로이드 — Log · Timber · R8 셋이 각각 다른 층에서 일합니다

안드로이드에는 SLF4J 가 없습니다. 바닥에 android.util.Log 가 있고, 그 위에 Timber 를 얹고, 릴리스 빌드에서는 R8 이 호출 자체를 지웁니다. 세 층이 하는 일이 다르기 때문에 “Timber 를 썼으니 릴리스에서 로그가 안 나가겠지”라는 생각이 가장 흔한 오해입니다 — 문자열은 이미 만들어졌고, 호출은 여전히 APK 안에 있습니다.

릴리스 빌드에서 로그를 정말 없애는 것은 Tree 가 아니라 R8 규칙입니다 — Tree 는 출력만 막습니다.

바닥 — android.util.Log 의 제약 네 가지

import android.util.Log

private const val TAG = "OrderScreen"

// ① 태그 길이 — API 25 이하에서 24자 이상이면 예외로 죽습니다
//    (API 26+ 는 제한이 풀렸지만 옛 기기를 지원하면 여전히 문제)
Log.d(TAG, "주문 목록 갱신")

// ② 한 줄 4KB 정도에서 잘립니다 — 긴 JSON 은 끝이 사라집니다
Log.d(TAG, hugeJson)          // ...뒷부분이 조용히 없어짐

// ③ 지연 평가가 없습니다 — 문자열은 항상 먼저 만들어집니다
Log.d(TAG, "items=${items.joinToString()}")   // 릴리스에서도 결합됨

// ④ 레벨 제어가 시스템 속성입니다 — 코드에서 켜고 끌 수 없습니다
if (Log.isLoggable(TAG, Log.DEBUG)) { ... }
//   adb shell setprop log.tag.OrderScreen DEBUG  ← 기기에서 이렇게 켬
Log 는 파사드가 아니라 최종 출력입니다 — 서버의 Logback 자리에 해당합니다. 레벨을 설정 파일로 바꾸거나 파일로 보내는 기능이 없습니다. 그래서 그 위에 Timber(껍데기)를 얹어 “어디로 보낼지”를 코드로 정합니다.

껍데기 — Timber 5 와 CrashReportingTree

// Timber 는 람다 API 가 없습니다 — String.format 스타일입니다
Timber.d("주문 %d 항목 %d개", order.id, order.items.size)   // ✅ 포맷은 Tree 가 있을 때만
Timber.d("주문 ${order.id}")                               // ⚠ 템플릿은 먼저 결합됨
Timber.tag("Payment").w(e, "결제 재시도 %d", attempt)       // 태그를 한 번만 바꿔 씀

// 릴리스용 Tree — WARN 이상만 Crashlytics 로
class CrashReportingTree : Timber.Tree() {
    override fun isLoggable(tag: String?, priority: Int) =
        priority >= Log.WARN                     // ★ 여기서 걸러야 문자열 포맷을 안 함

    override fun log(priority: Int, tag: String?, message: String, t: Throwable?) {
        val cl = FirebaseCrashlytics.getInstance()
        cl.log("[$tag] $message")                // 크래시 직전 문맥으로 남음
        if (t != null && priority >= Log.ERROR) cl.recordException(t)
    }
}
isLoggable 을 재정의하세요 — Timber 는 isLoggable 이 true 일 때만 String.format 을 돌립니다. log() 안에서 레벨을 검사하면 이미 포맷이 끝난 뒤라 비용을 못 줄입니다. 단, 코틀린 템플릿 "$x" 는 어느 쪽이든 먼저 결합됩니다(LOG 02).

인자의 부작용은 R8 이 보존합니다 — -assumenosideeffects 는 “이 호출은 부작용이 없다”는 뜻이지 인자를 계산하는 코드까지 없애 준다는 약속이 아닙니다. 부작용이 없다고 판단되는 문자열 결합은 보통 함께 사라지지만, 메서드 호출이 들어간 인자는 그대로 실행됩니다. LOG 02 의 규칙(로그 인자에 I/O 금지)은 안드로이드에서도 같습니다.
확인하는 법 — 릴리스 APK 를 Android Studio 의 Analyze APK 로 열어 classes.dex 에서 Log.d 참조가 사라졌는지 봅니다. 또는 app/build/outputs/mapping/release/usage.txt 에 제거된 메서드 목록이 남습니다.

Logcat 은 “내 것”이 아닙니다

로그가 어디까지 가나

  · 같은 기기의 다른 앱은 (Android 4.1 이후) 내 로그를 못 읽습니다.
    → 그래서 "괜찮다"고 생각하기 쉽습니다. 하지만
  · 사용자가 보내는 버그 리포트(bugreport.zip) 에 logcat 이 통째로 들어갑니다.
  · Play Console 의 ANR · 크래시 리포트에 최근 logcat 이 첨부됩니다.
  · Crashlytics 의 cl.log() 는 서드파티 서버로 갑니다.
  · 개발자 옵션 켠 사용자는 adb 로 전부 읽습니다.

즉 릴리스 빌드의 로그 한 줄은 '외부로 나가는 데이터'입니다.

정리 — 안드로이드 로깅은 Log(출력) · Timber(껍데기) · R8(제거) 세 층입니다. Timber.plant 는 디버그에서만 DebugTree, 릴리스는 WARN 이상만 Crashlytics 로 보내는 Tree, 그리고 -assumenosideeffects 로 d/v 호출을 APK 에서 지웁니다. Logcat 은 버그 리포트로 외부에 나가므로 토큰·개인정보는 처음부터 넣지 않습니다.
LOG 10

KMP — expect / actual 로 직접 만들거나 Kermit 을 쓰거나

공통 코드(commonMain)에는 SLF4J 도 android.util.Log 도 없습니다. 플랫폼마다 출력 수단이 다르니 “공통에서 부르고 플랫폼에서 구현한다”는 KMP 의 기본 문법 — expect/actual — 이 로깅에서도 그대로 쓰입니다. 직접 만들면 20줄이고, Kermit 은 그 20줄에 태그·레벨·Writer 교체·Crashlytics 연동을 얹은 것입니다.

expect/actual 트리의 잎 하나가 플랫폼 하나입니다 — Kermit 은 이 잎들을 LogWriter 라는 이름으로 미리 채워 둡니다.

직접 만들기 — 20줄이면 됩니다

// commonMain/kotlin/Log.kt
enum class LogLevel { DEBUG, INFO, WARN, ERROR }

expect fun platformLog(level: LogLevel, tag: String, msg: String)

// 공통에서 쓰는 얼굴 — 람다로 지연 평가를 직접 넣습니다
object Log {
    var minLevel = LogLevel.DEBUG
    inline fun d(tag: String, msg: () -> String) = log(LogLevel.DEBUG, tag, msg)
    inline fun w(tag: String, msg: () -> String) = log(LogLevel.WARN, tag, msg)
    inline fun log(level: LogLevel, tag: String, msg: () -> String) {
        if (level >= minLevel) platformLog(level, tag, msg())
    }
}

// androidMain
actual fun platformLog(level: LogLevel, tag: String, msg: String) {
    val p = when (level) {
        LogLevel.DEBUG -> android.util.Log.DEBUG
        LogLevel.INFO  -> android.util.Log.INFO
        LogLevel.WARN  -> android.util.Log.WARN
        LogLevel.ERROR -> android.util.Log.ERROR
    }
    android.util.Log.println(p, tag, msg)
}

// iosMain — NSLog 는 Foundation 에 있습니다
actual fun platformLog(level: LogLevel, tag: String, msg: String) {
    platform.Foundation.NSLog("[%s] %s: %s", level.name, tag, msg)
}

// jvmMain
actual fun platformLog(level: LogLevel, tag: String, msg: String) {
    val l = org.slf4j.LoggerFactory.getLogger(tag)
    when (level) {
        LogLevel.DEBUG -> l.debug(msg); LogLevel.INFO -> l.info(msg)
        LogLevel.WARN  -> l.warn(msg);  LogLevel.ERROR -> l.error(msg)
    }
}

    suspend fun sync() {

Kermit 이 직접 만든 것보다 나은 지점 — 태그 상속(withTag), Severity 6단계, Writer 교체·복수 등록(Logcat + Crashlytics 동시), 그리고 Swift 에서 같은 로거를 부를 수 있게 해 두었다는 점입니다. 직접 만든 것은 마지막 항목을 흉내 내기가 특히 번거롭습니다.

이렇게도 쓸 수 있다 — Writer 갈아 끼우기 · Crashlytics · Swift 쪽 🟡 중급

LogWriter — 플랫폼 잎을 직접 만드는 자리

import co.touchlab.kermit.LogWriter
import co.touchlab.kermit.Severity

// 공통 — 메모리에 최근 N 줄을 남겨 '버그 리포트 보내기'에 붙이는 Writer
class RingBufferWriter(private val size: Int = 200) : LogWriter() {
    private val buf = ArrayDeque<String>(size)
    override fun log(severity: Severity, message: String, tag: String, throwable: Throwable?) {
        if (buf.size == size) buf.removeFirst()
        buf.addLast("${severity.name[0]}/$tag: $message")
    }
    fun dump(): String = buf.joinToString("\n")
}

// 등록 — 여러 개를 동시에
val ring = RingBufferWriter()
Logger.setLogWriters(platformLogWriter(), ring)

// Crashlytics — 공식 모듈이 있습니다 (kermit-crashlytics)
// implementation("co.touchlab:kermit-crashlytics:2.0.6")
Logger.setLogWriters(platformLogWriter(), CrashlyticsLogWriter(minSeverity = Severity.Warn))

한 프로젝트에 둘을 섞지 마세요 — 공유 모듈은 Kermit, 서버는 kotlin-logging 이면 공유 모듈의 로그가 서버에서 Logback 설정을 안 탑니다(Kermit 의 JVM Writer 는 println). 서버까지 공유한다면 처음부터 kotlin-logging 으로 통일하거나, JVM 에서만 Kermit 에 SLF4J 로 넘기는 커스텀 LogWriter 를 끼웁니다.
정리 — KMP 로깅은 expect 선언 하나 + 플랫폼별 actual 구조이고, Kermit 은 그 구조를 Logger + LogWriter 로 미리 만들어 둔 라이브러리입니다. 앱은 Kermit, 서버와 공유하는 코드는 kotlin-logging, 의존성 0 인 라이브러리는 직접 만듭니다. 어느 쪽이든 Android 릴리스에서는 R8 규칙을, iOS 는 setMinSeverity 를 잊지 마세요.
