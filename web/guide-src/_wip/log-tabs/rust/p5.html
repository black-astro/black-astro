LOG 12

임베디드 · no_std — defmt 는 포맷을 호스트로 미룹니다

MCU 에는 파일도 stdout 도 없고, 플래시 64KB 에 core::fmt 를 넣을 자리도 없습니다. defmt(deferred formatting) 는 발상을 뒤집습니다 — 장치는 “몇 번 문장인지”와 원시 값만 보내고, 문자열로 만드는 일은 PC 가 합니다. 그래서 빠르고, 작고, 그 대가로 호스트에 같은 ELF 가 있어야 읽힙니다.

포맷은 장치가 아니라 호스트에서 — 장치가 보내는 것은 문장 번호와 원시 값뿐입니다.

세 조각 — 매크로 · 전송 · 패닉 핸들러

# Cargo.toml (Cortex-M 예 · 2026년 8월 기준 defmt 1.x)
[dependencies]
defmt = "1.0"
defmt-rtt = "1.0"                # 전송 계층 — RTT(SRAM 링 버퍼)
panic-probe = { version = "1.0", features = ["print-defmt"] }
cortex-m = { version = "0.7", features = ["critical-section-single-core"] }
cortex-m-rt = "0.7"

[profile.release]
debug = 2          # ★ 릴리즈에도 디버그 정보를 — .defmt 테이블이 여기 삽니다
                   #   (플래시에는 안 들어갑니다. ELF 파일에만 있습니다)
# .cargo/config.toml
[target.thumbv7em-none-eabihf]
runner = "probe-rs run --chip STM32F411CEUx"   # cargo run 이 곧 플래시 + 로그
rustflags = ["-C", "link-arg=-Tlink.x",
             "-C", "link-arg=-Tdefmt.x"]       # ★ 이 링커 스크립트가 없으면 링크 에러

[env]
DEFMT_LOG = "info"     # 컴파일 타임 필터 — RUST_LOG 와 같은 문법
# DEFMT_LOG = "debug,my_fw::i2c=trace"
DEFMT_LOG 는 실행이 아니라 빌드 때 읽습니다 — 꺼진 레벨은 기계어에서 사라집니다(LOG 09 의 release_max_level 과 같은 원리). 바꾸면 다시 빌드해야 하고, defmt 의 빌드 스크립트가 이 변수를 감시하니 cargo build 만 다시 하면 됩니다.

펌웨어 코드 — log 와 거의 같은 얼굴

#![no_std]
#![no_main]

use defmt::{info, warn, unwrap, Format};
use defmt_rtt as _;       // ★ 링크만 하면 전역 로거가 됩니다 (use 만으로 충분)
use panic_probe as _;     // 패닉을 defmt 로 찍고 프로브를 멈춥니다

#[derive(Format)]         // Debug 대신 Format — 호스트에서 포맷됩니다
struct Reading { temp_c: f32, ok: bool }

#[cortex_m_rt::entry]
fn main() -> ! {
    let r = Reading { temp_c: 23.5, ok: true };

    info!("측정값 {:?}", r);                 // Format 구현으로 통째로
    info!("temp = {=f32} C", r.temp_c);      // ★ 타입 힌트 — 값 4바이트만 보냅니다
    warn!("배터리 {=u8}%", 12u8);
    info!("버퍼 {=[u8]:#x}", &[0xde, 0xad]); // 슬라이스 · 16진수 지정

    let v = unwrap!(sensor.read());          // Err 면 defmt 로 남기고 패닉
    //      ↑ core 의 .unwrap() 은 Debug 포맷 코드를 플래시에 끌어옵니다
    loop { cortex_m::asm::wfi(); }
}
{=u8} 같은 타입 힌트가 핵심입니다 — 힌트가 있으면 컴파일러가 정확히 그 바이트 수만 전송합니다. {:?} 는 Format 구현을 따라가므로 조금 더 큽니다. {=str} 은 문자열을 통째로 보내니 동적 문자열은 되도록 피하세요.

속을 열어 보기 — 인터닝과 프레임 🟡 중급

문자열은 심볼이 되고, 심볼 값이 번호가 됩니다

# 매크로가 펼쳐질 때 (개념적으로)
info!("temp = {=f32} C", t)
  → 링커 섹션 .defmt 에 심볼 하나가 생깁니다
      이름 : {"package":"my_fw","tag":"defmt_info","data":"temp = {=f32} C", ...}
      값   : 17                           ← 링커가 매긴 고유 번호
  → 장치는 이렇게만 보냅니다 (LEB128 로 압축된 번호 + 원시 인자)
      [0x11] [0x00 0x00 0xbc 0x41]        ← 5바이트 (번호 1 + f32 4)
  → 타임스탬프를 켰다면 앞에 하나 더
      defmt::timestamp!("{=u64:us}", now_us());

# 호스트(probe-rs · defmt-print) 는 ELF 를 열어
#   17 → "temp = {=f32} C" 를 찾고, 4바이트를 f32 로 읽어 "temp = 23.5 C" 를 만듭니다

# 확인해 보기
$ nm target/thumbv7em-none-eabihf/release/my_fw | grep defmt_info | head
$ probe-rs run --chip STM32F411CEUx target/.../my_fw   # 러너가 자동으로 디코딩
플래시에 문자열이 없다는 뜻 — 로그 문구를 100개 늘려도 펌웨어 크기는 거의 그대로입니다. 디버그 정보(debug = 2)는 ELF 에만 있고 플래시로 안 올라갑니다. ELF 를 잃어버리면 그 펌웨어의 로그는 영영 못 읽습니다 — 릴리즈마다 ELF 를 보관하세요.

#[derive(Debug)]
pub struct Frame { pub id: u16, pub len: u8 }

// Cargo.toml

Embassy 와 함께 쓰면 — 비동기 임베디드 프레임워크 Embassy 는 defmt 피처가 기본 예제에 들어 있고, HAL 크레이트들도 위의 cfg_attr 관례를 따릅니다. ESP32 는 espflash 가 defmt 디코딩을 지원하고, 프로브 없이 쓰려면 esp-println 이 대안입니다.

현장에서 겪는 것들 🔴 실무

깨진 출력 · 안 나오는 출력

증상원인 → 처방
글자가 깨져 나옴ELF 와 펌웨어 불일치 → 다시 플래시
링크 에러 _defmt_*-Tdefmt.x 누락 → rustflags 확인
아무것도 안 나옴use defmt_rtt as _; 빠짐 · DEFMT_LOG 가 off
앞부분이 잘림RTT 버퍼가 차기 전에 호스트가 못 붙음 → 버퍼 키우기
절전 모드에서 멈춤SWD 클록이 꺼짐 → 디버그 중엔 절전 끄기
패닉 뒤 재부팅 안 함panic-probe 는 프로브를 멈추는 것 — 운영에는 다른 핸들러
운영 펌웨어의 패닉 핸들러는 따로 — panic-probe 는 개발용입니다(브레이크포인트에서 멈춤). 현장 장비라면 원인을 플래시 한 구석에 적고 리셋하는 핸들러를 직접 두어야 하고, 그 “한 구석”이 임베디드의 로그 파일입니다.

프로브 없이 · 현장에서 로그 남기기

// ① 링 버퍼를 직접 두고 RTT 대신 UART 로 흘리기 — defmt-serial
//    (호스트에서 defmt-print 로 디코딩: 같은 ELF 필요)
use defmt_serial as _;
defmt_serial::defmt_serial(uart_tx);   // 전송 계층만 바뀌고 매크로는 그대로

// ② 현장 장비 — 플래시의 마지막 섹터를 '블랙박스'로
//    · 패닉 핸들러에서 번호 + 인자만 기록 (defmt 프레임 그대로)
//    · 다음 부팅 때 그 섹터를 RTT/UART 로 뱉고 지웁니다
//    · 회수한 프레임을 그 펌웨어의 ELF 로 디코딩 ★ ELF 보관이 그래서 중요

// ③ 시각 붙이기 — 틱 카운터를 타임스탬프로
defmt::timestamp!("{=u64:ms}", {
    TICKS.load(core::sync::atomic::Ordering::Relaxed)
});
서버 로그와 같은 원칙이 여기서도 통합니다 — 구조(필드 = 타입 힌트) · 레벨(DEFMT_LOG) · 비동기 쓰기(RTT 링 버퍼 = non_blocking) · 보관(ELF = 스키마). 이 탭에서 배운 것이 도구만 바뀌어 그대로 적용됩니다.
정리 — defmt 는 포맷을 호스트로 미룹니다 — 장치는 문장 번호와 원시 바이트만 보내고, 플래시에는 문자열이 없습니다. 대가는 같은 ELF 가 있어야 읽힌다는 것이니 릴리즈마다 ELF 를 보관하세요. {=u8} 타입 힌트 · DEFMT_LOG 컴파일 타임 필터 · -Tdefmt.x 링커 스크립트 세 가지만 기억하면 나머지는 log 와 같습니다.
