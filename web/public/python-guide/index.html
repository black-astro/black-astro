Series — 이름표가 붙은 1차원 배열

판다스의 최소 단위입니다. 리스트에 인덱스(이름표)가 붙으면 Series가 됩니다. DataFrame의 컬럼 하나 = Series 하나입니다.

리스트가 Series가 되는 과정
list

Java 비유 — Series는 LinkedHashMap<Object, T> + double[]을 합친 물건입니다. 키로도 찾고(s["김민준"]), 위치로도 찾고(s[0]), 배열 전체 연산(s * 1.1)도 됩니다. Java였다면 list.stream().map(x -> x*1.1).toList()가 필요한 일이 곱셈 기호 하나로 끝납니다.

Series 필수 속성

코드의미
s.values값만 numpy 배열로 (인덱스 제외)
s.index이름표 목록
s.dtype데이터 타입 (int64 / float64 / object / category …)
s.shape(길이,) 형태 튜플
s.nameSeries 이름 = DataFrame에 들어갔을 때의 컬럼명
s.head(3) / s.tail(3)앞·뒤 3개
s.describe()개수·평균·표준편차·사분위 요약
s.value_counts()값별 빈도수 (범주형 데이터의 필살기)
s.unique() / s.nunique()고유값 배열 / 고유값 개수

SECTION 05

loc / iloc — 원하는 부분만 잘라내기

판다스 초보가 가장 많이 헷갈리는 지점입니다. 규칙은 딱 하나: loc = 이름(라벨)로, iloc = 번호(위치)로. 아래 코드를 클릭하면 표에서 선택 영역이 실시간으로 칠해집니다.

인덱싱 시뮬레이터 — 코드를 클릭하세요
이름팀지역매출만족도
 
df["매출"]

loc — 라벨 기준

df.loc[2]                  # 인덱스 라벨 2 인 행
df.loc[1:3]                # 1,2,3 -> 끝 포함! (파이썬과 다름)
df.loc[:, "이름":"지역"]    # 이름~지역 컬럼 전체
df.loc[2, "매출"]           # 특정 한 칸
df.loc[df["매출"] > 300, ["이름","매출"]]  # 조건 + 컬럼
주의 — loc의 슬라이스는 끝을 포함합니다. df.loc[1:3] 은 3행까지 나옵니다. 반면 iloc[1:3]은 파이썬 규칙대로 2행까지만 나옵니다.

iloc — 위치(정수) 기준

df.iloc[0]        # 첫 번째 행
df.iloc[0:3]      # 0,1,2 -> 끝 제외 (파이썬 그대로)
df.iloc[:, 0:2]   # 앞 두 컬럼
df.iloc[-1]       # 마지막 행
df.iloc[[0,2,4], [0,3]]  # 0,2,4행 x 0,3열
구분법 — iloc의 i는 integer(정수). 정수가 보이면 iloc, 문자열이 보이면 loc. 인덱스를 날짜나 이름으로 바꿔 놓으면 loc이 훨씬 강력해집니다.

헷갈리는 3형제 정리

표현결과타입
df["매출"]매출 컬럼 하나Series
df[["매출"]]매출 컬럼 하나 (표 형태 유지)DataFrame
df[["이름","매출"]]두 컬럼DataFrame
df[0:2]대괄호에 슬라이스면 행이 잘림 (혼란의 원인)DataFrame
df.매출점 접근. 컬럼명에 공백·한글 이슈 있으면 실패Series
SECTION 06

불리언 필터링 — True/False 마스크로 걸러내기

판다스의 필터링은 SQL의 WHERE와 같지만 내부 동작이 독특합니다. 조건식이 먼저 True/False 배열을 만들고, 그 배열이 True인 행만 남습니다. 슬라이더를 움직여 마스크가 바뀌고 행이 사라지는 과정을 보세요.

필터링 3단계 — 조건 → 마스크 → 결과
df["매출"] >= 300
① 원본 + 계산된 마스크
이름매출mask
② 마스크 적용 결과 (행이 실제로 이동합니다)
이름매출

조건 조합

# and -> &   or -> |   not -> ~
# 각 조건은 반드시 괄호로 감쌀 것!
df[(df["매출"] > 300) & (df["팀"] == "A")]
df[(df["지역"] == "서울") | (df["지역"] == "부산")]
df[~(df["팀"] == "C")]              # C팀 제외

# 목록 포함 여부 (SQL의 IN)
df[df["지역"].isin(["서울","부산"])]

# 범위 (SQL의 BETWEEN)
df[df["매출"].between(200, 400)]

# 문자열 조건 (SQL의 LIKE)
df[df["이름"].str.contains("김")]
df[df["이름"].str.startswith("이")]
가장 흔한 에러 — df[df.매출>300 and df.팀=="A"] 처럼 파이썬 and를 쓰면 "truth value of a Series is ambiguous" 에러가 납니다. Series는 값이 여러 개라 하나의 참/거짓으로 못 줄이기 때문입니다. 반드시 &, | 와 괄호를 쓰세요.

query() — SQL처럼 쓰기

# 문자열로 조건을 쓰면 훨씬 읽기 쉽습니다
df.query("매출 > 300 and 팀 == 'A'")

버튼을 눌러 3단계를 확인하세요.

기본 사용법

# 한 컬럼 집계
df.groupby("팀")["매출"].mean()

# 여러 집계를 한 번에
df.groupby("팀")["매출"].agg(["sum","mean","count","max"])

# 컬럼별로 다른 집계
df.groupby("팀").agg({
    "매출": ["sum","mean"],
    "만족도": "mean",
})

# 결과 컬럼 이름 지정 (실무 필수)
df.groupby("팀").agg(
    총매출=("매출","sum"),
    평균매출=("매출","mean"),
    인원=("이름","count"),
).reset_index()

# 다중 키 그룹 (SQL: GROUP BY 팀, 지역)
df.groupby(["팀","지역"])["매출"].sum()

고급 — transform / filter

# transform: 집계값을 '원본 행 수 그대로' 되돌려줌
df["팀평균"] = df.groupby("팀")["매출"].transform("mean")
df["팀내비중"] = df["매출"] / df.groupby("팀")["매출"].transform("sum")

# filter: 그룹 단위로 통째 남기기/버리기 (SQL의 HAVING)
df.groupby("팀").filter(lambda g: g["매출"].sum() > 500)

# apply: 그룹마다 임의 처리 (가장 자유롭지만 가장 느림)
df.groupby("팀").apply(lambda g: g.nlargest(2, "매출"))

# 그룹 내 순위
df["팀내순위"] = df.groupby("팀")["매출"].rank(ascending=False)
agg vs transform — 결과 행 수가 다릅니다. agg는 그룹 수만큼(3행), transform은 원본 행 수만큼(6행) 나옵니다. “각 행에 자기 팀 평균을 붙이고 싶다”면 transform입니다.
Java 비유 — groupby("팀")["매출"].mean()은 list.stream().collect(groupingBy(E::getTeam, averagingInt(E::getSales)))와 같습니다. transform에 딱 맞는 Java 대응물은 없고, 그룹 평균을 구한 뒤 원본을 다시 순회하며 붙이는 작업을 한 줄로 만든 것이라고 보면 됩니다.

df.resample("W").mean()   # 주별
df.resample("ME").sum()   # 월말 기준 월별
df.resample("QE").sum()   # 분기

# rolling: 이동 윈도우
df["MA7"]  = df["매출"].rolling(7).mean()          # 7일 이동평균
df["MA7"]  = df["매출"].rolling(7, min_periods=1).mean()  # 앞부분도 계산
df["표준편차"] = df["매출"].rolling(7).std()
df["최대"]  = df["매출"].rolling(7).max()

# expanding: 처음부터 현재까지 누적
df["누적평균"] = df["매출"].expanding().mean()
df["누적합"]   = df["매출"].cumsum()

# shift: 시점 이동 -> 전일 대비 증감
df["전일"]     = df["매출"].shift(1)
df["증감률"]   = df["매출"].pct_change() * 100
df["차이"]     = df["매출"].diff()
Java 비유 — resample("ME")는 GROUP BY DATE_FORMAT(dt,'%Y-%m'), rolling(7)은 SQL 윈도우 함수 AVG(x) OVER (ORDER BY dt ROWS BETWEEN 6 PRECEDING AND CURRENT ROW)와 같습니다.

NUMPY 01

ndarray — 한 덩어리로 붙어 있는 배열

파이썬 리스트와 NumPy 배열의 결정적 차이는 메모리에 어떻게 놓여 있느냐입니다. 이 하나가 속도 차이의 전부를 설명합니다.

메모리 구조 비교

리스트가 느린 이유

  • 각 원소가 독립된 파이썬 객체(PyObject)라 메모리에 흩어져 있음
  • 리스트는 그 객체들의 주소(포인터)만 들고 있음
  • 값 하나 읽으려면 포인터를 따라 점프해야 함 → CPU 캐시 미스
  • 더할 때마다 “이게 int인가 str인가” 타입 검사를 반복

배열이 빠른 이유

  • 값들이 연속된 메모리 블록에 나란히 놓임
  • 모든 원소가 같은 타입·같은 크기 → 주소 계산만으로 접근
  • 연산 루프가 C로 컴파일되어 돌아감 (파이썬 인터프리터 밖)
  • CPU의 SIMD(한 번에 여러 값 계산) 명령까지 활용

첫 코드

import numpy as np      # 관례적 별칭

a = np.array([1, 2, 3, 4])
a * 2                   # array([2, 4, 6, 8])  <- 반복문 없음!

lst = [1, 2, 3, 4]

가장 헷갈리는 지점 — 같은 * 2인데 리스트는 길이가 2배가 되고 배열은 값이 2배가 됩니다. +도 마찬가지로 리스트는 이어붙이기, 배열은 덧셈입니다.
Java 비유 — 파이썬 list는 ArrayList<Object>, ndarray는 double[] 원시 배열입니다. Integer 박싱 객체들의 리스트와 int[]의 성능 차이를 떠올리면 정확히 같은 이야기입니다.

arange vs linspace — 간격을 알면 arange, 개수를 알면 linspace. 실수 간격일 때 arange는 부동소수점 오차로 원소 개수가 들쭉날쭉해질 수 있어 linspace가 안전합니다.
NUMPY 03

shape · dtype · 차원(axis)

NumPy에서 에러의 90%는 shape이 안 맞아서 납니다. 이 세 가지만 정확히 읽을 줄 알면 됩니다.

차원별 모양

필수 속성

a = np.array([[1,2,3],[4,5,6]])

a.ndim       # 2        차원 수
a.size       # 6        전체 원소 개수

a.nbytes     # 48       전체 바이트
a.T          # 전치 (행<->열)
shape 읽는 법 — (2,3)은 “바깥쪽에 2개, 각각 안에 3개”. (10, 28, 28, 3)이면 “이미지 10장 × 세로28 × 가로28 × RGB3채널”처럼 바깥에서 안으로 읽습니다.

NUMPY 04

인덱싱 · 슬라이싱 — 그리고 view의 함정

NumPy 슬라이싱은 리스트와 달리 복사본이 아니라 원본을 들여다보는 창(view)입니다. 이걸 모르면 원본이 왜 바뀌었는지 영원히 못 찾습니다.

2D 슬라이싱 시뮬레이터 — 코드를 클릭

인덱싱 문법

a = np.arange(12).reshape(3,4)

a[0]         # 0행 전체 -> [0 1 2 3]
a[0, 2]      # 0행 2열 -> 2   (a[0][2] 보다 빠름)
a[:, 1]      # 1열 전체 -> [1 5 9]
a[1:, 2:]    # 1행부터 x 2열부터
a[::2]       # 2칸씩 건너뛰기
a[::-1]      # 뒤집기
a[-1, -1]    # 마지막 원소

# 리스트와 다른 점: 콤마로 차원을 구분!
# 리스트라면 a[0][2], 배열은 a[0, 2]

view vs copy

a = np.arange(5)          # [0 1 2 3 4]

b = a[1:4]                # view (원본 공유!)
b[0] = 99
print(a)                  # [0 99 2 3 4]  <- 원본이 바뀜!

c = a[1:4].copy()         # 명시적 복사
c[0] = 0
print(a)                  # 원본 그대로

# view 여부 확인
b.base is a               # True -> view
c.base is None            # True -> 독립 배열

# 팬시 인덱싱은 항상 copy
d = a[[0,2,4]]            # copy
왜 view인가 — 100만 행 배열의 절반을 슬라이스할 때마다 복사하면 메모리가 터집니다. NumPy는 기본을 무복사로 두고, 필요할 때만 .copy()를 부르게 설계했습니다. 판다스에서 보던 SettingWithCopyWarning도 뿌리가 여기입니다.
NUMPY 05

reshape · 전치 — 데이터는 그대로, 모양만 바꾸기

12개의 값은 그대로 두고 shape만 바꿉니다. 버튼을 누르면 같은 셀이 실제로 재배치됩니다.

reshape 애니메이션 — 원소 12개 고정

모양 바꾸기

a = np.arange(12)

a.reshape(3, 4)      # 3행 4열
a.reshape(4, -1)     # -1 = 알아서 계산 -> (4,3)
a.reshape(2, 2, 3)   # 3차원으로

a.ravel()            # 1차원으로 펴기 (가능하면 view)
a.flatten()          # 1차원으로 펴기 (항상 copy)

a.T                  # 전치
np.transpose(a, (1,0,2))   # 축 순서 직접 지정

# 차원 추가/제거 — 브로드캐스팅에서 자주 씀
a[:, np.newaxis]     # (12,) -> (12,1)
a[np.newaxis, :]     # (12,) -> (1,12)
np.expand_dims(a, 0)
np.squeeze(b)        # 크기 1인 축 제거

reshape의 규칙

  • 원소 개수(size)가 반드시 같아야 합니다. 12 → (5,3)은 에러
  • 채우는 순서는 기본이 C 순서(행 우선). 마지막 축부터 채웁니다
  • -1은 “나머지 하나는 알아서” — 한 번만 쓸 수 있습니다
  • reshape은 대개 view라 값을 바꾸면 원본도 바뀝니다
전치(.T)는 값을 옮기지 않습니다 — 메모리는 그대로 두고 “읽는 순서(stride)”만 바꿉니다. 그래서 거의 공짜로 빠릅니다. 다만 이후 연산이 메모리 순서와 어긋나 느려질 수 있어, 반복 연산 전이라면 np.ascontiguousarray()를 고려하세요.
Java 비유 — int[12] 하나를 두고 arr[i*4+j]로 읽으면 3×4 행렬, arr[i*3+j]로 읽으면 4×3 행렬이 되는 것과 같습니다. reshape은 인덱스 계산식만 갈아끼우는 작업입니다.
NUMPY 06

결합 · 분할 — 배열 붙이고 자르기

판다스의 concat에 해당하는 기능입니다. axis 방향만 정확히 잡으면 됩니다.

concatenate 방향

b = np.array([[5,6],[7,8]])

np.concatenate([a, b], axis=1)   # 가로로 (2,4)

np.vstack([a, b])    # = axis=0 (vertical)
np.hstack([a, b])    # = axis=1 (horizontal)
np.stack([a, b])     # 새 축 추가 -> (2,2,2)

# 분할
np.split(x, 3)              # 3등분

np.vsplit(a, 2)             # 세로로 분할
np.hsplit(a, 2)             # 가로로 분할

# 원소 추가/삭제 (매번 전체 복사 — 반복문 안에서 쓰지 마세요)

NUMPY 07

브로드캐스팅 — 모양이 달라도 계산되는 마법

NumPy의 가장 강력하면서 가장 헷갈리는 기능입니다. 작은 배열이 실제로 복사되지는 않으면서 큰 배열 모양으로 “늘어난 것처럼” 계산됩니다. 버튼을 눌러 늘어나는 과정을 보세요.

브로드캐스팅 시뮬레이터

브로드캐스팅 규칙 3줄

  • ① 뒤에서부터 차원을 하나씩 비교합니다
  • ② 크기가 같거나, 둘 중 하나가 1이면 통과
  • ③ 1인 쪽이 상대 크기만큼 늘어난 것처럼 동작 (실제 복사 없음)
# 뒤에서부터 맞춰보기
(3, 4) + (4,)      -> (3, 4)   ✅  4==4, 3은 그대로
(3, 4) + (3, 1)    -> (3, 4)   ✅  1이 4로 확장
(3, 1) + (1, 4)    -> (3, 4)   ✅  양쪽 다 확장
(3, 4) + (3,)      -> ❌ ERROR  4 != 3
(2, 3, 4) + (3, 1) -> (2, 3, 4) ✅
가장 흔한 에러 메시지
operands could not be broadcast together with shapes (3,4) (3,)
→ b[:, None] 또는 b.reshape(-1,1)로 축을 명시해 주면 대부분 해결됩니다.

실전 활용

a = np.arange(12).reshape(3,4)

# 전체에 상수 연산
a * 2 + 1

# 열마다 다른 가중치 적용 (shape (4,))
가중치 = np.array([1, 2, 3, 4])
a * 가중치

# 행마다 다른 값 더하기 -> 축을 세워줘야 함
행보정 = np.array([10, 20, 30])
a + 행보정[:, None]        # (3,1) 로 만들어 브로드캐스팅

# 표준화 (열 기준) — 머신러닝 전처리의 정석
(a - a.mean(axis=0)) / a.std(axis=0)

# 구구단 표 한 줄로 (외적)
np.arange(1,10)[:, None] * np.arange(1,10)[None, :]
메모리를 안 쓰는 게 핵심 — (10000, 1) + (1, 10000)은 1억 개짜리 결과를 만들지만, 입력 두 개는 각각 1만 개만 차지합니다. “늘어난 것처럼”은 어디까지나 계산할 때만입니다.

NUMPY 09

axis 완전정복 — “축이 사라진다”

axis=0인데 왜 열 평균이 나오지? 여기서 대부분 헷갈립니다. 핵심은 하나입니다 — 지정한 축이 계산되어 없어진다. 버튼을 눌러 어느 방향으로 뭉개지는지 보세요.

axis 시각화 — a.sum(axis=?)

집계 함수

a = np.arange(12).reshape(3,4)

a.sum()            # 66      전체
a.sum(axis=0)      # (4,)    열별 합  <- 행이 사라짐
a.sum(axis=1)      # (3,)    행별 합  <- 열이 사라짐
a.sum(axis=0, keepdims=True)   # (1,4) 축 유지

a.mean()   a.std()   a.var()
np.median(a)          # median 은 메서드가 아니라 np. 함수
a.min()    a.max()    # np.ptp(a) = max-min
a.argmin() a.argmax()          # 최소/최대 '위치'
a.cumsum() a.prod()

np.percentile(a, [25, 50, 75])
np.unique(a, return_counts=True)

axis 외우는 법

  • shape의 몇 번째 숫자를 없앨 것인가가 axis입니다
  • (3,4)에서 axis=0 → 3이 사라져 (4,) = 열마다 하나씩
  • (3,4)에서 axis=1 → 4가 사라져 (3,) = 행마다 하나씩
  • 화살표 방향으로 훑으면서 뭉갠다고 상상하면 헷갈리지 않습니다
  • keepdims=True를 쓰면 축이 1로 남아 브로드캐스팅에 바로 쓸 수 있습니다
# keepdims의 진가 — 행별 비율 구하기
행합 = a.sum(axis=1, keepdims=True)   # (3,1)
비율 = a / 행합                        # 브로드캐스팅 성공!

# keepdims 없으면
행합 = a.sum(axis=1)     # (3,)
a / 행합                 # ❌ (3,4) vs (3,) 에러
판다스와 같은 규칙 — df.sum(axis=0)도 열별 합계입니다. 판다스의 axis는 NumPy에서 그대로 물려받은 개념이라 한 번만 익히면 둘 다 해결됩니다.
NUMPY 10

불리언 마스킹 · 팬시 인덱싱

판다스 필터링의 원형입니다. 슬라이더를 움직여 마스크가 바뀌는 걸 보세요.

불리언 마스크 → 추출
a > 5

불리언 마스킹

a = np.arange(12)

mask = a > 5           # bool 배열
a[mask]                # True인 것만 -> 1차원으로 평탄화
a[a % 2 == 0]          # 짝수만

# 조건 조합 — 반드시 & | ~ 와 괄호!
a[(a > 3) & (a < 8)]
a[(a < 2) | (a > 9)]
a[~(a > 5)]

# 값 대입도 가능
a[a > 5] = 0           # 조건에 맞는 곳만 0으로

# 개수/존재 확인
(a > 5).sum()          # 조건 만족 개수 (True=1)
(a > 5).any()          # 하나라도 있나
(a > 5).all()          # 전부 그런가
np.count_nonzero(a > 5)

팬시 인덱싱 · 위치 찾기

# 원하는 위치를 리스트로 지정 (결과는 항상 copy)
a[[0, 3, 7]]           # 0,3,7번째
a[[0,3], [1,2]]        # (0,1), (3,2) 원소 두 개

# 순서 바꾸기/반복도 가능
a[[2, 2, 0]]

# 조건을 만족하는 '위치' 찾기
np.where(a > 5)              # 인덱스 튜플
np.argwhere(a > 5)           # (n, ndim) 좌표 배열
np.flatnonzero(a > 5)        # 평탄화된 인덱스

# 정렬
np.sort(a)              # 정렬된 복사본
a.sort()                # 제자리 정렬
np.argsort(a)           # 정렬 순서의 인덱스
a[np.argsort(a)[::-1]]  # 내림차순 정렬

# 상위 3개 (전체 정렬보다 빠름)
np.partition(a, -3)[-3:]
2D에서 행 골라내기 — a[a[:,0] > 5] 처럼 조건을 1차원 마스크로 만들면 해당 행 전체가 뽑힙니다. 판다스의 df[df["x"]>5]가 정확히 이 동작입니다.
NUMPY 11

난수 · 선형대수 — 실전 수치 계산

머신러닝·통계 시뮬레이션에서 실제로 쓰이는 부분입니다.

난수 (신형 Generator API)

rng = np.random.default_rng(42)   # seed -> 항상 같은 결과

rng.uniform(-1, 1, 5)        # 균등분포 범위 지정
rng.choice(a, 3, replace=False)   # 비복원 추출
rng.permutation(a)           # 섞은 복사본
rng.shuffle(a)               # 제자리 섞기

# 몬테카를로 예시: 주사위 2개 합의 분포

행렬 연산

A = np.array([[1,2],[3,4]])
B = np.array([[5,6],[7,8]])

A * B          # 원소별 곱 (아다마르 곱)
A @ B          # 행렬곱  ★ 이게 진짜 행렬 곱셈

def timer(func):

        return result

UV 01

왜 uv인가

기존 방식의 고통을 먼저 정리하면 uv가 무엇을 해결했는지 명확해집니다.

패키지 설치 속도 (pandas + numpy + opencv + pyside6 기준)
pip install
poetry install
uv sync

캐시가 있으면 uv는 하드링크로 파일을 연결해 사실상 즉시 끝납니다. 실제 값은 환경에 따라 다릅니다.

기존 방식 (도구가 4개)

pyenv install 3.12.0        # 파이썬 버전 관리
python -m venv .venv        # 가상환경 생성
.venv\Scripts\activate      # 활성화 (까먹기 쉬움)
pip install pandas          # 설치
pip freeze > requirements.txt   # 수동 기록 (부정확!)
  • activate를 잊으면 전역에 설치되어 환경이 오염됨
  • requirements.txt는 직접 설치한 것과 딸려온 것이 구분 안 됨
  • 의존성 재현이 불완전 — “내 PC에선 되는데요”
  • 파이썬 버전 관리는 또 다른 도구(pyenv)가 필요

uv 방식 (도구가 1개)

uv init myapp               # 프로젝트 + pyproject.toml 생성
cd myapp
uv add pandas               # 설치 + 기록 + 락파일 갱신 (한 번에)
uv run main.py              # 가상환경 자동 인식 후 실행
  • activate 불필요 — uv run이 알아서 .venv를 씁니다
  • pyproject.toml = 내가 선언한 의존성 (사람이 관리)
  • uv.lock = 실제 설치된 전체 트리 (기계가 관리, 커밋 대상)
  • 파이썬 버전까지 uv python install로 해결
Spring 비유 — pyproject.toml은 pom.xml / build.gradle, uv.lock은 정확한 버전이 고정된 의존성 트리 (Gradle의 lockfile)입니다. uv sync는 mvn install에 해당합니다.

UV 03

파이썬 버전 관리

pyenv 없이 uv 하나로 여러 파이썬 버전을 깔고 프로젝트별로 고정합니다.

# 설치 가능한 버전 목록
uv python list

# 특정 버전 설치 (시스템 파이썬을 건드리지 않음)
uv python install 3.12
uv python install 3.11 3.12 3.13     # 여러 개 동시에

# 현재 프로젝트가 쓸 버전 고정 -> .python-version 파일 생성
uv python pin 3.12

# 설치된 파이썬 위치 확인
uv python find

# 특정 버전으로 가상환경 만들기
uv venv --python 3.12
왜 프로젝트마다 버전을 고정하나 — PyWinAuto·OpenCV 같은 라이브러리는 특정 파이썬 버전에서만 휠(wheel)이 제공되는 경우가 있습니다. .python-version을 커밋해 두면 팀원 모두 같은 버전에서 돌아갑니다.
PySide6 주의 — 최신 파이썬이 나온 직후에는 PySide6 휠이 아직 없을 수 있습니다. GUI 프로젝트라면 3.11~3.12 같은 안정 버전으로 pin 해 두는 편이 안전합니다.
UV 04

패키지 add · sync · lock

이 세 명령의 관계만 이해하면 uv는 끝입니다.

3단계 흐름
1. 선언
uv add pandas
pyproject.toml 에
"pandas>=2.2" 기록
→
2. 해결
uv lock
의존성 트리 전체를
uv.lock 에 고정
→
3. 반영
uv sync
.venv 를 lock 과
정확히 일치시킴

uv add는 이 3단계를 자동으로 다 수행합니다. lock/sync를 따로 칠 일은 드뭅니다.

패키지 다루기

uv add pandas                    # 최신 버전
uv add "pandas>=2.2,<3"          # 범위 지정
uv add pandas numpy matplotlib   # 여러 개
uv add --dev pytest ruff         # 개발 전용 (배포엔 미포함)
uv add git+https://github.com/user/repo
uv add ./local_package           # 로컬 경로

uv remove pandas                 # 삭제

uv sync                          # lock 대로 환경 맞추기 (팀원 최초 1회)
uv sync --frozen                 # lock 갱신 없이 (CI 권장)
uv lock --upgrade                # 전체 최신으로 갱신
uv lock --upgrade-package pandas # 특정 패키지만 갱신

uv tree                          # 의존성 트리 보기
uv pip list                      # 설치 목록

커밋 규칙 (.gitignore)

# 반드시 커밋
pyproject.toml      # 무엇을 원하는지
uv.lock             # 정확히 무엇이 깔렸는지
.python-version     # 어떤 파이썬으로

# 커밋 금지 (.gitignore)
.venv/
__pycache__/
*.pyc
.env
uv.lock을 꼭 커밋하세요 — 이게 없으면 팀원마다 다른 버전이 깔려 “제 컴퓨터에선 되는데요” 문제가 그대로 재발합니다. Gradle lockfile을 커밋하는 것과 같은 이유입니다.
새 팀원 온보딩 — git clone 후 uv sync 한 번이면 파이썬 설치부터 패키지까지 끝납니다.
UV 05

uv run — activate를 잊어도 되는 이유

uv run은 실행 직전에 환경을 자동으로 맞춰줍니다.

실행하기

uv run main.py                 # 스크립트 실행
uv run python                  # REPL 진입
uv run python -m pytest        # 모듈 실행
uv run pytest                  # 설치된 명령 실행
uv run --with rich python      # 임시로 패키지 추가해 실행

# 매번 uv run 이 귀찮다면 (기존 방식도 가능)
.venv\Scripts\activate         # Windows
source .venv/bin/activate      # Mac/Linux
uv run이 하는 일 — ① lock 확인 → ② 환경이 다르면 자동 동기화 → ③ .venv의 파이썬으로 실행. 즉 항상 최신 상태에서 실행되는 것이 보장됩니다.

단일 파일 스크립트 (PEP 723)

# analyze.py — 파일 안에 의존성을 직접 적습니다
# /// script
# requires-python = ">=3.12"
# dependencies = ["pandas", "matplotlib"]
# ///

import pandas as pd
df = pd.read_csv("sales.csv")
print(df.describe())
# 프로젝트 없이 바로 실행 — uv가 임시 환경을 만들어 줌
uv run analyze.py

# 의존성 블록을 명령으로 추가
uv add --script analyze.py pandas matplotlib
실무에서 아주 유용 — 동료에게 .py 파일 하나만 보내도 uv run 한 줄로 돌아갑니다. 설치 안내 문서가 필요 없습니다.
UV 06

pyproject.toml 해부

프로젝트의 모든 설정이 이 파일 하나에 모입니다.

[project]
name = "myapp"
version = "0.1.0"
description = "업무 자동화 도구"
requires-python = ">=3.12"
dependencies = [                 # ← uv add 가 여기에 씁니다
    "pandas>=2.2.0",
    "numpy>=2.0",
    "opencv-python>=4.10",
    "pyside6>=6.7",
]

[project.scripts]                # 실행 명령 등록
myapp = "myapp.main:run"         # -> uv run myapp

[dependency-groups]              # uv add --dev 가 여기에
dev = ["pytest>=8.0", "ruff>=0.6"]

[tool.uv]
package = false                  # 앱이면 false, 라이브러리면 true

[tool.ruff]                      # 린터 설정도 같은 파일에
line-length = 100
target-version = "py312"

[build-system]
requires = ["hatchling"]
build-backend = "hatchling.build"

표기의미

PyAutoGUI — 사람 흉내

마우스를 특정 좌표로 옮기고 클릭합니다. 화면에 보이는 것이면 무엇이든 조작할 수 있습니다.

  • ✅ 웹, 게임, 그림판, 원격 데스크톱까지 전부 가능
  • ✅ 배우기 쉽고 코드가 짧음
  • ❌ 창 위치·해상도·배율이 바뀌면 즉시 실패
  • ❌ 실행 중 사람이 마우스를 건드리면 망가짐
  • ❌ 창이 가려지면 안 됨 (항상 최상단이어야 함)

  • ✅ 텍스트를 읽어올 수 있음 (검증 가능)

def wait_image(path, timeout=10, conf=0.85, region=None):
    """이미지가 나타날 때까지 대기 후 좌표 반환"""
    end = time.time() + timeout
    while time.time() < end:
        loc = pg.locateCenterOnScreen(path, confidence=conf,
                                      region=region)
        if loc:
            return loc
        time.sleep(0.4)
    raise TimeoutError(f"{path} 를 {timeout}초 안에 못 찾음")

from pathlib import Path
import pyautogui as pg

Path("logs").mkdir(exist_ok=True)
logging.basicConfig(
    level=logging.INFO,
    format="%(asctime)s [%(levelname)s] %(message)s",
    handlers=[
        logging.FileHandler("logs/auto.log", encoding="utf-8"),
        logging.StreamHandler(),
    ],
)
log = logging.getLogger(__name__)

# ── 재시도 데코레이터 ──────────────────────────────────
def retry(times=3, delay=1.0, shot=True):
    def deco(fn):
        @functools.wraps(fn)
        def wrapper(*a, **kw):
            last = None
            for i in range(1, times + 1):
                try:
                    return fn(*a, **kw)
                except Exception as e:
                    last = e
                    log.warning(f"{fn.__name__} 실패 {i}/{times}: {e}")
                    if shot:
                        pg.screenshot(f"logs/fail_{fn.__name__}_{i}.png")
                    time.sleep(delay * i)      # 점점 길게 대기
            log.error(f"{fn.__name__} 최종 실패")
            raise last
        return wrapper
    return deco

# ── 사용 ───────────────────────────────────────────────
@retry(times=3, delay=1.5)
def 로그인(app, user, pw):
    win = app.window(title_re=".*로그인.*")
    win.wait("ready", timeout=15)
    win.child_window(auto_id="txtUser").set_text(user)
    win.child_window(auto_id="txtPw").set_text(pw)
    win.child_window(auto_id="btnLogin").click()
    win.wait_not("visible", timeout=20)      # 로그인 창이 닫히면 성공
    log.info("로그인 성공")

from PySide6.QtCore import QThread, QObject, Signal, Slot

# ── ① 작업 클래스 (QObject) ───────────────────────────
class Worker(QObject):
    progress = Signal(int)
    finished = Signal(object)
    error    = Signal(str)

    def __init__(self, path):
        super().__init__()
        self.path = path
        self._stop = False

    @Slot()
    def run(self):
        try:
            import pandas as pd
            df = pd.read_csv(self.path)
            results = []
            total = len(df)
            for i, row in df.iterrows():
                if self._stop:            # 중단 요청 확인
                    break
                results.append(heavy_work(row))
                self.progress.emit(int((i+1) / total * 100))
            self.finished.emit(results)
        except Exception as e:
            self.error.emit(str(e))

    def stop(self):
        self._stop = True

# ── ② 메인 창에서 스레드 띄우기 ───────────────────────
def start_job(self, path):
    self.thread = QThread()                       # ★ self. 로 보관!
    self.worker = Worker(path)
    self.worker.moveToThread(self.thread)         # 작업을 스레드로 이사

    self.thread.started.connect(self.worker.run)
    self.worker.progress.connect(self.bar.setValue)
    self.worker.finished.connect(self.on_done)
    self.worker.error.connect(self.on_error)

    # 정리 (누수 방지)
    self.worker.finished.connect(self.thread.quit)
    self.worker.finished.connect(self.worker.deleteLater)
    self.thread.finished.connect(self.thread.deleteLater)

    self.run_btn.setEnabled(False)                # 중복 실행 방지
    self.thread.start()

@Slot(object)
def on_done(self, results):
    self.run_btn.setEnabled(True)
    self.table.setModel(PandasModel(pd.DataFrame(results)))

절대 규칙

  • UI는 오직 메인 스레드에서만 건드립니다. 워커에서 label.setText()를 직접 호출하면 크래시합니다
  • 워커 → UI 전달은 반드시 시그널로
  • QThread와 워커는 self.에 보관하세요. 지역변수면 함수 종료 시 파괴되어 조용히 멈춥니다
  • 스레드 안에서 time.sleep 대신 QThread.msleep()을 쓰면 중단 대응이 쉬워집니다

더 간단한 방법 — QThreadPool

from PySide6.QtCore import QRunnable, QThreadPool, Slot

class Task(QRunnable):
    def __init__(self, fn, *a):
        super().__init__()
        self.fn, self.a = fn, a
    @Slot()
    def run(self):
        self.fn(*self.a)

QThreadPool.globalInstance().start(Task(heavy_work, path))
선택 기준 — 진행률·중단이 필요하면 QThread + Worker, “그냥 백그라운드에서 한 번 돌리기”면 QRunnable이 간편합니다.

자동화와 결합할 때 — PyAutoGUI 루프를 워커에 넣고 진행률을 시그널로 보내면, 사용자는 진행 상황을 보면서 “중단” 버튼도 누를 수 있는 도구가 됩니다.

import pandas as pd
from PySide6.QtCore import QAbstractTableModel, Qt, QModelIndex

class PandasModel(QAbstractTableModel):
    """DataFrame 을 QTableView 에 연결하는 어댑터"""

    def __init__(self, df: pd.DataFrame):
        super().__init__()
        self._df = df

    def rowCount(self, parent=QModelIndex()):
        return len(self._df)

    def columnCount(self, parent=QModelIndex()):
        return len(self._df.columns)

    def data(self, index, role=Qt.DisplayRole):
        if not index.isValid():
            return None
        value = self._df.iat[index.row(), index.column()]

        if role == Qt.DisplayRole:
            if pd.isna(value):
                return ""
            if isinstance(value, float):
                return f"{value:,.2f}"
            return str(value)

        if role == Qt.TextAlignmentRole:
            if isinstance(value, (int, float)):
                return int(Qt.AlignRight | Qt.AlignVCenter)

        if role == Qt.ForegroundRole:
            from PySide6.QtGui import QColor
            if isinstance(value, (int, float)) and value < 0:
                return QColor("#fb7185")           # 음수는 빨강
        return None

    def headerData(self, section, orientation, role=Qt.DisplayRole):
        if role != Qt.DisplayRole:
            return None
        if orientation == Qt.Horizontal:
            return str(self._df.columns[section])
        return str(self._df.index[section])

    def sort(self, column, order=Qt.AscendingOrder):   # 헤더 클릭 정렬
        self.layoutAboutToBeChanged.emit()
        self._df = self._df.sort_values(
            self._df.columns[column],
            ascending=(order == Qt.AscendingOrder))
        self.layoutChanged.emit()

from pathlib import Path
from PySide6.QtCore import QStandardPaths
from PySide6.QtSql import (QSqlDatabase, QSqlQuery,
                           QSqlTableModel)

def db_path():
    """쓰기 가능한 표준 위치에 DB 파일 준비"""
    base = Path(QStandardPaths.writableLocation(
        QStandardPaths.AppDataLocation))   # ...\AppData\Roaming\업무도구
    base.mkdir(parents=True, exist_ok=True)
    return base / "app.db"

def init_db():
    db = QSqlDatabase.addDatabase("QSQLITE")
    db.setDatabaseName(str(db_path()))
    if not db.open():
        raise RuntimeError(db.lastError().text())
    QSqlQuery("""CREATE TABLE IF NOT EXISTS 거래처 (
        id   INTEGER PRIMARY KEY AUTOINCREMENT,
        이름  TEXT NOT NULL,
        담당자 TEXT,
        메모  TEXT)""")
    return db

# ── 메인 창에서: 표 ↔ DB 직결 ─────────────────
self.db = init_db()
self.model = QSqlTableModel(self)
self.model.setTable("거래처")
self.model.setEditStrategy(QSqlTableModel.OnFieldChange)
#      ^ 셀 수정 즉시 DB 반영 (OnManualSubmit 이면 저장버튼식)
self.model.select()                    # SELECT * 실행

self.table.setModel(self.model)        # 끝! 편집=저장
self.table.hideColumn(0)               # id 숨기기

# 행 추가/삭제 버튼
def add_row(self):
    r = self.model.rowCount()
    self.model.insertRow(r)
    self.table.edit(self.model.index(r, 1))   # 바로 입력 모드

def del_row(self):
    for idx in self.table.selectionModel().selectedRows():
        self.model.removeRow(idx.row())
    self.model.select()

self.search.textChanged.connect(self.apply_filter)

def apply_filter(self, text):
    safe = text.replace("'", "")       # 따옴표 제거로 안전하게
    self.model.setFilter(f"이름 LIKE '%{safe}%'" if safe else "")

import sqlite3
import pandas as pd

class Store:
    """DB 접근을 한 클래스로 모아두면 관리가 쉽다"""
    def __init__(self, path):
        self.conn = sqlite3.connect(path)
        self.conn.execute("""CREATE TABLE IF NOT EXISTS 이력 (
            id 	INTEGER PRIMARY KEY AUTOINCREMENT,
            파일명 TEXT, 상태 TEXT,
            시각  TEXT DEFAULT CURRENT_TIMESTAMP)""")

    def add(self, 파일명, 상태):
        with self.conn:
            self.conn.execute(
                "INSERT INTO 이력(파일명, 상태) VALUES (?, ?)",
                (파일명, 상태))

    def to_df(self):
        return pd.read_sql(
            "SELECT * FROM 이력 ORDER BY id DESC", self.conn)

# 화면 갱신: 처리 후 df 를 다시 읽어 모델 교체
self.store.add("매출_0731.xlsx", "완료")
self.table.setModel(PandasModel(self.store.to_df()))

방식장점단점이럴 때

서버 없이 파일 하나가 DB입니다. “처리한 목록 기억하기”, “수집 데이터 쌓기”에 CSV보다 훨씬 안전합니다.

기본 사용

import sqlite3

conn = sqlite3.connect("app.db")     # 파일이 없으면 생성
conn.row_factory = sqlite3.Row       # 컬럼명으로 접근 가능하게
cur = conn.cursor()

cur.execute("""
    CREATE TABLE IF NOT EXISTS 처리내역 (
        id     INTEGER PRIMARY KEY AUTOINCREMENT,
        파일명  TEXT UNIQUE,
        상태    TEXT,
        시각    TEXT DEFAULT CURRENT_TIMESTAMP
    )
""")

# 넣기 — 반드시 ? 플레이스홀더! (SQL 인젝션 방지)
cur.execute("INSERT INTO 처리내역(파일명, 상태) VALUES (?, ?)",
            ("매출_0731.xlsx", "완료"))
cur.executemany("INSERT INTO 처리내역(파일명, 상태) VALUES (?, ?)",
                [("a.csv", "완료"), ("b.csv", "실패")])
conn.commit()                        # ★ 잊으면 저장 안 됨

# 조회
for row in cur.execute("SELECT * FROM 처리내역 WHERE 상태 = ?", ("완료",)):
    print(row["파일명"], row["시각"])

conn.close()

실전 패턴 — 중복 처리 방지

# 자동화의 단골 요구: "이미 처리한 파일은 건너뛰기"
def 이미_처리했나(conn, 파일명):
    r = conn.execute("SELECT 1 FROM 처리내역 WHERE 파일명 = ?",
                     (파일명,)).fetchone()
    return r is not None

def 처리_기록(conn, 파일명, 상태="완료"):
    with conn:                    # with = 자동 commit/rollback
        conn.execute(
            "INSERT OR REPLACE INTO 처리내역(파일명, 상태) VALUES (?, ?)",
            (파일명, 상태))

# pandas 와도 바로 연결됩니다
import pandas as pd
df = pd.read_sql("SELECT * FROM 처리내역", conn)
df.to_sql("백업", conn, if_exists="replace", index=False)
f-string으로 SQL 만들지 마세요 — f"WHERE 이름='{name}'"은 따옴표 하나에 깨지고 보안 구멍입니다. 값은 항상 ?로 넘기세요.
어디까지 sqlite로 버틸까 — 단일 PC, 수백만 행, 동시 쓰기가 적다면 충분합니다. 여러 사람이 동시에 쓰는 시스템이 되면 그때 MariaDB/PostgreSQL로 넘어가면 됩니다.

from email.message import EmailMessage
from pathlib import Path

def 리포트_발송(받는사람, 제목, 본문, 첨부경로=None):
    msg = EmailMessage()
    msg["From"] = "bot@company.com"
    msg["To"] = ", ".join(받는사람)
    msg["Subject"] = 제목                    # 한글 제목 그대로 OK
    msg.set_content(본문)                    # 텍스트 본문

    # HTML 본문을 쓰고 싶으면
    msg.add_alternative(f"""
      <h2>{제목}</h2>
      <p>{본문}</p>
      <p style="color:#888">자동 발송 메일입니다.</p>
    """, subtype="html")

    # 엑셀 첨부
    if 첨부경로:
        p = Path(첨부경로)
        msg.add_attachment(
            p.read_bytes(),
            maintype="application", subtype="octet-stream",
            filename=p.name)                 # 한글 파일명 OK

    # 발송 — 587(STARTTLS) 또는 465(SSL)
    with smtplib.SMTP("smtp.company.com", 587) as s:
        s.starttls()
        s.login("bot@company.com", os.environ["MAIL_PW"])
        s.send_message(msg)

# uv add tenacity
import requests
from tenacity import (retry, stop_after_attempt,
                      wait_exponential, retry_if_exception_type)

@retry(
    stop=stop_after_attempt(4),               # 최대 4회
    wait=wait_exponential(min=1, max=30),     # 1s→2s→4s→8s… 점점 길게
    retry=retry_if_exception_type(            # 이 예외들만 재시도
        (requests.ConnectionError, requests.Timeout)),
)
def api_호출(url):
    r = requests.get(url, timeout=10)
    r.raise_for_status()
    return r.json()

import logging

       before_sleep=before_sleep_log(log, logging.WARNING))

왜 대기 시간을 점점 늘리나(지수 백오프) — 상대 서버가 과부하일 때 즉시 재시도하면 부하를 더 얹어 상황을 악화시킵니다. 1초→2초→4초로 물러나며 기다리는 것이 서로에게 최선이라 업계 표준이 됐습니다.

concurrent.futures — 먼저 이걸로

from concurrent.futures import (ThreadPoolExecutor,
                                ProcessPoolExecutor, as_completed)

# I/O 작업: 스레드 8개로 동시에 다운로드
def 다운로드(url):
    r = requests.get(url, timeout=30)
    return url, len(r.content)

with ThreadPoolExecutor(max_workers=8) as ex:
    results = list(ex.map(다운로드, url목록))

# 끝나는 순서대로 처리 + 개별 실패 처리
with ThreadPoolExecutor(max_workers=8) as ex:
    futs = {ex.submit(다운로드, u): u for u in url목록}
    for f in as_completed(futs):
        try:
            url, size = f.result()
            print(f"완료 {url} ({size:,}B)")
        except Exception as e:
            print(f"실패 {futs[f]}: {e}")

# CPU 작업: 프로세스로 (반드시 main 가드 안에서!)
if __name__ == "__main__":
    with ProcessPoolExecutor() as ex:
        results = list(ex.map(이미지_변환, 파일목록))

asyncio — 수백 개 동시 I/O

import asyncio, httpx

async def fetch(client, url, sem):
    async with sem:                      # 동시 10개로 제한
        r = await client.get(url, timeout=10)
        return url, r.status_code

async def main():
    sem = asyncio.Semaphore(10)
    async with httpx.AsyncClient() as client:
        tasks = [fetch(client, u, sem) for u in url목록]
        return await asyncio.gather(*tasks,
                                    return_exceptions=True)

results = asyncio.run(main())
GIL 한 줄 요약 — 파이썬 스레드는 계산을 동시에 못 합니다 (한 번에 한 스레드만 실행). 그래서 CPU 작업은 스레드를 늘려도 안 빨라지고 프로세스를 써야 합니다. I/O 대기는 GIL을 놓고 기다리므로 스레드로 충분합니다.
초보자 경로 — ① 일단 순차로 완성 → ② 느리면 ThreadPoolExecutor.map 한 줄 → ③ 수백 개 이상 동시가 필요할 때만 asyncio. asyncio는 코드 전체가 async로 물들기 때문에 마지막 카드입니다.
